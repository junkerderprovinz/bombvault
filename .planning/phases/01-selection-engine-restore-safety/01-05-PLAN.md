<objective>
Close verification gap WR-01 (review finding; user decision 2026-09-09 "Encode — gap closure"): a mixed folder selection (include + exclude branches) is stored and advertised via the `!`-prefix flat encoding in `backupPaths`, but the backup engine compiled selection → restic positional targets ONLY, so the excluded branch was backed up anyway while the UI advertised it as excluded. This plan encodes stored exclusion branches as restic `--exclude` patterns appended to the backup argv, making the advertised selection and the actual snapshot content agree.

**The Excludes-metadata tradeoff (explicit, per the recorded remediation):** restic records every `--exclude` pattern in the snapshot's `Excludes` metadata, which is the user-owned surface the exclusions editor previews. After this change, snapshots of mixed selections carry machine-derived patterns the user did not write there. The user decision accepts this consequence in exchange for content correctness — a backup that silently includes the "excluded" branch is the worse failure (silent non-consent is the cardinal sin of backup tools in reverse: silently backing up what the user deselected). This tradeoff supersedes the tail of the L14 rationale recorded in `includesOnly`'s comment and in PROJECT.md.

**Deliberate revision of plan 01-01's prohibition:** the original prohibition "No restic `--exclude` ever derived from the folder selection" and its enforcement test `TestBackupNarrowedSelectionUsesMaximalIncludes` (asserting an unchanged fake-engine exclude capture) are REVISED by this gap closure per the user decision. The revised contract: positionals remain the maximal-root includes (unchanged); excludes are now derived from stored exclusion branches. The revised prohibition set lives in this plan's must_haves.

Purpose: the snapshot must contain what the user was told it would contain — the content half of Phase 1 SC2, the one must-have the original verification could only score as a user-approved override.
Output: `internal/api/selection.go` + `internal/api/service.go` enforcement, revised and new tests, a real-restic contract test, and the four documentation-drift fixes from 01-VERIFICATION.md human item 4 (a–d).
