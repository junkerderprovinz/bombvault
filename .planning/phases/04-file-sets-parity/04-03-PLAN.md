<objective>
**As a** BombVault user, **I want to** unfold a file set on the Files page and tick exactly which sub-folders it covers in the same tree I already use for containers, **so that** I learn the selection model once and multi-gigabyte sets stop backing up branches I never wanted.

This plan mounts the Phase 2 `SelectionTree` on the Files page per the UI-SPEC reuse contract: row-level "Choose folders" disclosure on the set card (never inside FileSetDialog — dialog PATCHes are full-set saves and would race the live queue), one synthetic root (the set's resolved Path, D-02), `hostMountRoot` as the browse prefix, per-set expansion memory, and the Phase 3 preview-count rule on the root. The genuinely new UI decision is the NULL mirror seed (UI-SPEC item 9): a never-tree-edited set renders its root CHECKED at "1 path" — honest about what the legacy argv covers — and no write happens until the first toggle.

Purpose: this is the user-visible capability (INTEG-02 criterion 1) and the client half of the D-06 refusal and the concurrency edge.
Output: optional-props tweak, the Files-page editor, 4 i18n keys x 42 locales, the page's first dom harness.
</objective>
