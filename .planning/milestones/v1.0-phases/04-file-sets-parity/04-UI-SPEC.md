# Phase 4 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Phase shape:** brownfield parity. INTEG-02 mounts the existing `SelectionTree` (Phase 2) on the Files page with a single root (the set's resolved `Path`, D-02). The contract below is therefore mostly a *reuse contract*: match the container panel's tree exactly — same tokens, same states, same copy keys — and add only what the files domain forces (no CACHEDIR row, no Reset, no custom-path rows, DELETE-orienting empty-selection refusal per D-06).

**Focal point (Dimension 2):** the expanded set card's tree is the primary visual anchor of the Files page; the set cards themselves are secondary, the page heading tertiary.

## Spacing Scale

The app is on Tailwind's 4-point grid. Declared values for this phase (multiples of 4 only):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | `py-1` notice/disclosure sub-rows, icon-to-label micro gaps |
| sm | 8px | `gap-2` inside tree rows (chevron / checkbox / label) |
| md | 12px | `gap-3` between blocks inside the set card |
| lg | 16px | card padding (`p-4`), tree depth indent step (16px per level — pinned in `SelectionTree.tsx`), `gap-4` in the card actions row |
| xl | 20px | dialog padding (`p-5`, unchanged) |
| 2xl | 24px | section breathing room inside the expansion block |
| 3xl | 40px | page card rhythm — `PAGE_SHELL` `gap-10` (Files page already on it) |

Exceptions (all measured, all existing — reproduce, do not invent new ones; 12/20/40 are existing house values, 4-pt aligned — not precedents for inventing further off-scale values):

- Tree row heights: `min-h-8` (32px) root rows, `min-h-7` (28px) child rows — 12px text register.
- Chevron/exclusion glyph box: 10px SVG (a glyph box, not spacing).
- Tree viewport: `h-[clamp(12rem,55vh,32rem)] overflow-y-auto` — verbatim from `SelectionTree.tsx`.

## Placement and Component Reuse Contract

Locked by CONTEXT D-02/D-07 and RESEARCH (Pitfall 6, Open Question 3). The planner may adjust mechanics but may NOT add a second implementation of selection semantics.

1. **Placement: row-level expansion on the set card.** The disclosure button renders after the actions row inside each `FileSetRow` card (below the Backups/Restore disclosure, separated by `border-t border-carbon-border pt-3`). NOT inside `FileSetDialog` — dialog PATCHes are full-set saves and would race the live-selection queue; the create flow is unchanged (D-02). Tree appears only when the set has a Path.
2. **One root.** `SelectionTree` receives `mounts = [one synthetic mount-like row]` (source = the set's resolved host path; `reachable: true` always), `customPaths = []`. Root label: the resolved path (mono, ltr, break-all) + the preview count line. NO `dest ← source` arrow, NO appdata line, NO remove chip.
3. **Browse prefix.** `hostSourceRoot` prop = `hostMountRoot` (`Files.tsx` already holds it) — NOT `hostSourceRoot`/`/mnt`. Zero backend change; `GET /api/browse` serves the listings.
4. **Expansion memory.** `containerName` prop = `fileset-${set.id}` so the localStorage key scopes per set (`bv-tree-expanded-fileset-{id}`). Comfort state only; selection never goes to localStorage.
5. **No CACHEDIR row.** The Files tree renders NO CACHEDIR.TAG switch (RESTIC-01 is container-scoped; D-07 deferred). Passing an empty map + no-op handler would render a dead switch — a silent lie. Contract: make `excludeCaches`/`onToggleCaches` optional on `SelectionTreeProps` and skip the sub-row when absent. Additive, non-semantic, no fork.
6. **Audit-only exclusions list.** The per-root exclusions disclosure renders exactly as in Phase 3 (`folders.exclusions`, relative mono paths, muted, not focusable, collapsed on every reopen). Mutations flow ONLY through the tree's one toggle pipeline.
7. **Live-save queue.** One-deep serialized queue over a ref mirror (`Containers.tsx` Pattern 4, single owed class). Toggle → `applyToggle` on the mirror → PATCH `{ selectedPaths: toFlatList(includes, exclusions) }`. In-flight node's checkbox disables (`busyPaths`). Zero-includes toggle: client refuses BEFORE PATCH — inline warn line (`files.emptySelectionBlocked`) + `glim-shake`, no request. Server refusal (`code:"empty-selection"`) routes to the same warn line + fail toast.
8. **No narrowing note.** The Phase 3 "narrowed" note is container-scope; D-07's parity surfaces are the preview count and the exclusions list only.
9. **Tree state mirror (the one genuinely new UI decision).** A set with NULL `selected_paths` is rendered honestly: the client mirror is seeded with a synthetic include of the set root, so the root renders CHECKED and the preview reads "1 path" — exactly what the legacy argv `[SourceDir]` covers (Phase 3 rule: the visible number equals the positionals the next backup hands restic). Rendering it unchecked/"0 paths" would contradict the trust posture and D-06's own logic. The synthetic seed participates in `applyToggle` math (untick a child → `[root, !child]`; untick the root → zero includes → refusal), and no write happens until the first toggle. NULL stays NULL in storage until then (legacy argv pinned).

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| empty | list-collection (tree) | ✅ covered | No-Path sets render no tree (D-02; card hint `files.noPathHint`); an expanded empty directory renders the `folder.none` notice row, honestly `aria-expanded=true` with zero children |

| populated | list-collection | ✅ covered | Tri-state rows derive from `classifyNode` over (I, E) host-path sets — correct for collapsed and never-loaded subtrees (TREE-04); the preview count line renders on the root at every volume, including zero |
| partial | list-collection | 🧪 backstop | A file set whose `selected_paths` is NULL renders its root CHECKED with preview "1 path", byte-mirroring the legacy `[SourceDir]` argv (Reuse Contract item 9) — pinned by a dom/unit test (Files tree harness), not by prose alone |

| zero-one-many | list-collection | ✅ covered | Exactly one level-1 treeitem (the set root, `aria-setsize=1`); counts ride "{n} paths" / "{n} exclusions" (existing accepted "{n} phrasing", byte-identical reuse) |
| long-text | static-content, interactive-control | ✅ covered | Paths: `font-mono break-all` + `title`; set name: `truncate`; button labels: `.glim-btn-label` ellipsis — all existing house patterns, none new |
