<objective>
**As a** BombVault user, **I want to** see exactly what a container's selection will back up and what it will skip, **so that** I can trust the tree without running a backup to find out.

This plan lands the read-only trust layer over the Phase 2 tree (D-01, D-03, D-04): a per-root effective-selection preview line ("{n} paths") derived client-side from the live mirror, and a per-root reviewable exclusions list (relative paths, muted, non-interactive, collapsible). Zero new endpoints and zero new state sources: both surfaces are pure functions of the (includes, exclusions) sets the editor already holds (SELECT-03 first half, INTEG-03, INTEG-04 D-04 rendering).

Purpose: The visible count must equal what the next backup hands restic (Phase 1 flat-set contract) and deselected branches must stay visible as remembered memory.
Output: Two pure helpers with table tests, two new sub-row surfaces in SelectionTree, 2 i18n keys across 42 locales, rebuilt web/dist.
</objective>
