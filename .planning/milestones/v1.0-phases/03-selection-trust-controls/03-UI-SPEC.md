# Phase 3 — UI Design Contract

> Visual and interaction contract for the selection-trust layer over the Phase 2
> tree: per-root effective-selection preview, narrowing note, reviewable
> exclusions, full-deselect semantics with an explicit reset, and the per-root
> CACHEDIR.TAG toggle. Generated by gsd-ui-researcher, verified by
> gsd-ui-checker. Mode note: every decision below marked **[auto]** was
> selected without user input from locked CONTEXT decisions (D-01..D-07),
> RESEARCH patterns, and codebase precedent — each carries a one-line rationale.
> Remaining discretion is listed under "Open Questions (advisory)".

## Interaction & Accessibility Contract (SELECT-03, INTEG-03, INTEG-04, RESTIC-01)

### 1. Effective-selection preview (D-01 — pure derivation)

- One muted line per root (mounts AND standalone custom rows), rendered INSIDE
  the root treeitem's existing `flex flex-col` label column — the exact
  placement precedent of `folders.appdataDefault`/`folders.notReachable`
  sub-lines, so the count is announced with the row's accessible name. **[auto]**
- `n = |{ p ∈ includes : isAtOrUnder(p, root) }|` — computed ONLY from the
  editor's live `(includes, exclusions)` mirror via a new pure helper in
  `selectionTree.ts` (`rootIncludeCount`), table-tested beside
  `rootExclusions`. Stored maximal includes ARE the positionals (Phase 1
  contract), so n matches what `toFlatList` serializes — never a count of
  checked nodes on screen (D-01's explicit anti-pattern; correct for collapsed
  and never-loaded subtrees).
- The count is existence-UNfiltered by design (RESEARCH Pitfall 5 / A3):
  stale/missing paths stay counted; those cases are already row-level-warned
  (`folders.notReachable`, `folders.customMissing`). Planner pins this reading
  in a test comment.
- The line ALWAYS renders, including "0 paths" on fully-deselected roots — a
  zero is information (INTEG-04), not an empty state to hide.

### 2. Narrowing note (D-02 — event-driven, not state-derived)

- Trigger: on every SUCCESSFUL backupPaths save, if the attempted (drained live
  list) include count is LOWER than `lastSavedCount` AND
  `container.lastBackup != null`. `lastSavedCount` is a ref initialized from
  the load-time mirror size, updated on every ok, and re-initialized after the
  reset's refetch. Comparing against last-SAVED (not pre-mutation) is what makes
  queue-collapsed bursts net correctly (RESEARCH Pitfall 3).
- `lastBackup` arrives as a new FoldersEditor prop threaded from ContainerRow
  (which already holds `container`); `lastBackup !== null` is the "≥1 prior
  snapshot" signal (handlers.go:531 precedent, orphan fallback included).
- Render: one `text-xs text-statusWarn` line directly UNDER the tree scroll
  region (always visible without scrolling), above the Add row, `role="status"`
  (it appears asynchronously after a PATCH resolves — screen readers must hear
  it). **[auto]**
- Transient by design (D-02/RESEARCH Pattern 2): editor-session component
  state, cleared on section close/reopen; underivable on reopen (no server-side
  include-count history) — that is correct, not a gap. No dismissal control.
- No comparison against existing snapshots' CONTENT ever (that is the deferred
  SELECT-06 coverage diff — out of scope).

### 3. Reviewable exclusions (D-03 — audit view, non-interactive)

- Under every root with ≥1 exclusion STRICTLY under it (`isStrictlyUnder`,
  `rootExclusions` helper, root prefix stripped to a relative path): a
  collapsible section. Collapsed by default; expansion state is component
  state, deliberately NOT persisted (audit view, not navigation comfort —
  unlike tree expansion). **[auto]**
- Structure (all inside the tree container, sibling of the root treeitem,
  `role="presentation"`-wrapped like every Phase 2 notice row so the tree's
  treeitem/group structural contract is preserved):
  - Header: plain `<button aria-expanded aria-controls>` — chevron triangle +
    `t("folders.exclusions")`, `text-xs text-carbon-textMuted`, indent 16,
    `py-1`. NOT a treeitem; excluded from `aria-setsize`/`posinset` counts;
    normally tabbable (retry-Button precedent for controls inside the tree).
  - Expanded body: a plain `<ul>` of `font-mono dir="ltr" break-all` muted
    `<li>` relative paths, indent 16, sorted lexically (deterministic; matches
    server sort).
- NON-INTERACTIVE by contract (D-03): no checkbox, no re-check, no remove, no
  link into the ExcludesEditor — mutation flows ONLY through the tree's single
  toggle pipeline (Phase 2 T-02-10). Rows are not focusable.
- Renders regardless of the root's include state: active (root included) and
  dormant (root unchecked — D-04's remembered-partial memory) use the SAME
  section; the root's own checkbox state above it distinguishes them. No
  second variant, no extra key. **[auto]**
- No display cap: realistic hand-toggled exclusion counts are small, and the
  tree's existing scroll region bounds the panel's height.

### 4. Full-deselect semantics and the reset (D-04 + D-05)

- **D-04 rendering invariant**: a root with zero relevant includes and ≥1
  stored exclusion renders ALL THREE signals — unchecked checkbox, "0 paths"
  preview, "{n} exclusions" section — never hidden, never filtered. The root
  row itself stays in the tree (Phase 2 already classifies it "unchecked";
  nothing new needed beyond the two derived signals above).
- **D-05 reset control**: neutral `Button` (label `folders.resetSelection`, no
  glyph, no tone) at the section foot, below the Add row, start-aligned, `pt-1`.
  Click → `useConfirm` dialog (`folders.resetConfirm`, default fail tone) → on
  confirm, enqueues a reset descriptor through the SAME serialized one-deep
  queue as toggles, carrying per-attempt selection source (Pattern 3):
  the drain sends `setBackupPaths(name, [])` with NO `selectionSource` field —
  the Phase 1 guard is strictly tree-source-gated, so this passes by design
  (dom test must pin the body carries no `selectionSource` — Pitfall 2).
- The reset is NOT optimistic **[auto]**: the button busy-disables, the PATCH
  sends, and only on ok does the editor reset `loaded` and re-run the mounts
  load (the served auto-detected state — appdata default reselected — becomes
  the visible, documented outcome; `lastSavedCount` re-initializes from the
  refetch). Avoids the custom-rows revert problem entirely: `custom` state is
  only ever replaced by the refetch, never locally emptied and restored.
  On failure: verbatim toast + `.glim-shake` on the button; nothing else
  changes. (Planner may switch to optimistic-with-revert; the pinned contract
  is the PATCH body shape, serialization, and refetch-on-ok.)
- Edge cases resolve through the queue exactly as RESEARCH Pattern 3 documents
  (toggle stacked behind a reset drains the live non-empty list with tree
  source; reset stacked behind a toggle drains `[]` with the reset source).
- The Phase 2 client-side zero-include block (pre-PATCH guard) stays exactly as
  is — the reset is now its documented companion exit, referenced from the
  enriched `folders.emptySelectionBlocked` line.

### 5. CACHEDIR.TAG toggle (D-06 + D-07)

- Placement: one sub-row under EVERY root (mounts and standalone custom rows —
  RESEARCH Q5 recommendation followed **[auto]**: same map, same union, the
  tooltip already discloses item-wide scope), between the root treeitem and its
  children group: `role="presentation"` wrapper, indent 16, `py-1`,
  `flex items-center gap-2`: `Toggle` (`hideLabel`, caller-drawn
  `text-xs text-carbon-textSub` label) + `InfoBubble(t("folders.cachedirScope"))`.
  Renders regardless of the root's expand state. **[auto]**
  Sibling order under a root: treeitem → CACHEDIR toggle row → exclusions
  section → `role="group"` children (controls before content; the children
  group stays last-adjacent, matching the Phase 2 blocked-line precedent for
  presentation rows between a treeitem and its group).
- Unreachable mounts: the toggle renders DISABLED (same disabled rule as their
  checkbox — an unreachable mount is never backed up, so the flag is moot
  there). **[auto]**
- State source: the additive `excludeCaches` map on the mounts response
  (`{}` when unset); on = `map[root] === true`.
- Save: optimistic local flip → PATCH `/api/containers/{name}` with the FULL
  map (whole-map replace — RESEARCH Q2 recommendation **[auto]**: one
  translation layer fewer, keys identical to rendered roots; wire field
  `excludeCaches: map[string]bool`, nil = untouched, `DisallowUnknownFields`
  declared in the same change — Pitfall 8).
- Serialization (Pitfall 6 contract, mechanism is planner's per RESEARCH A2):
  the CACHEDIR PATCH must NEVER run concurrently with a backupPaths PATCH from
  this editor — either generalize the one-deep queue to a per-attempt PATCH
  descriptor or give the toggle its own serialized path. Dom test pins: no two
  overlapping `/api/containers/{name}` fetches in one editor timeline.
- Failure: revert to stored value + verbatim fail toast + `.glim-shake` keyed
  by a nonce on the Toggle (UpdateAfterBackupRow's toast-AND-shake standing
  rule). Success: quiet — the switch state is the feedback (no toast, matching
  every other settings toggle).
- While in flight: `disabled` on the Toggle (component contract).
- Scope honesty is requirement-level (D-06): the InfoBubble tooltip disclosing
  the item-wide union effect is part of the contract, not polish — never ship
  the toggle without it.

### 6. Keyboard and AT

- The tree's roving-tabindex and APG key map are UNTOUCHED. The tree's keydown
  target guard (`role="treeitem"` or tree root) already preserves inner
  controls' own key semantics — the disclosure button, the switch, and Space on
  the focused switch keep native behavior.
- New tabbables inside the tree container (disclosure header, switch) follow
  the retry-Button precedent: regular DOM tab order, outside the roving set.
- Narrowing note: `role="status"` (polite live region).
- Confirm dialog: the `useConfirm` machinery (portal, Escape, Tab trap, focus
  restore) — nothing new to build.
- No new focus treatments: base `:focus-visible` rule and Toggle/InfoBubble/
  Button's own rings cover every new control.
