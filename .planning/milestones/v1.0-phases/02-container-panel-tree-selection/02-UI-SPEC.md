# Phase 2 — UI Design Contract

> Visual and interaction contract for the lazy tri-state folder tree inside the
> container panel (FoldersEditor). Generated by gsd-ui-researcher in `--auto`
> mode, verified by gsd-ui-checker. Mode note: every decision below marked
> **[auto]** was selected without user input by codebase precedent — each carries
> a one-line rationale. Genuinely user-facing leftovers are listed under
> "Open Questions (advisory)".

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none — shadcn deliberately NOT initialized. Locked project constraint (CLAUDE.md: "SPA with no state library, no UI kit — the tree UI must be hand-rolled in line with existing components"); RESEARCH.md marks all tree libraries BANNED. **[auto]** |
| Preset | not applicable |
| Component library | none — hand-rolled components over shared `glim-*` engine classes (`.glim-btn`, `.glim-shake`, `.glim-field-focus`, base `:focus-visible` rule) |
| Icon library | house-generated glyphs (`web/src/components/glyphs.tsx`, 16px SVG box). The expansion chevron reuses the SnapshotFileTree chevron shape (10×10 triangle in a `w-4` box, `transition-transform`, `rotate-90` open / `rtl:rotate-180` closed) — it is the app's only existing tree chevron |
| Font | `system-ui, -apple-system, "Segoe UI", Roboto, sans-serif`; paths and node names in `font-mono` (`ui-monospace, "Cascadia Code", Menlo, Consolas`), always `dir="ltr"` |

No `components.json` exists and none may be created: Tailwind v4 token config lives
in `web/src/index.css` (`@theme` block). Registry safety gate: not applicable.

## Spacing Scale

Declared values (multiples of 4 only), as Tailwind utilities on semantic tokens:

| Token | Value | Usage in this phase |
|-------|-------|---------------------|
| xs | 4px | `gap-1` chevron→checkbox→label inside a row; `gap-1` between sibling rows; `py-1` vertical padding on child rows |
| sm | 8px | `gap-2` checkbox→path text (today's mount-row gap, preserved); `p-2` notice-row inset |
| md | 16px | Tree indent per level: `paddingInlineStart: level * 16` (logical property, RTL-correct — see rule below); `p-4` unchanged card padding |
| lg | 24px | unchanged page spacing (not introduced this phase) |
| xl | 32px | `min-h-8` row height for level-1 mount/custom root rows — "32px is this app's control height" (FolderBrowser measured rule, index.css `--btn-h`) |

Exceptions (both multiples of 4, stated because they are new constants):

- **Child-row height 28px (`min-h-7`)** for expanded sub-folder rows below level 1 —
  denser than the 32px root rows so a 500-entry sibling list stays scannable; still a
  4-multiple. **[auto]** (Root rows keep 32px so today's panel rhythm is unchanged.)
- **Tree scroll region** `h-[clamp(12rem,55vh,32rem)] overflow-y-auto` around the whole
  tree — the exact FolderBrowser precedent ([497]): one fixed height per viewport so
  expansion never reflows the panel below it. **[auto]**

Rules:

- Indent MUST use `paddingInlineStart` (logical), never `paddingLeft` — RTL sweep rule
  (SnapshotFileTree:104-118 documents the physical-property trap it had to fix).
- Do NOT copy SnapshotFileTree's `depth * 14` indent — 14 is not a 4-multiple; this tree
  uses 16. SnapshotFileTree itself is untouched this phase.
- No new spacing tokens; no values outside the scale above.

## Color

Dual-theme app; every value below is the semantic token, with dark / light hexes for
reference only. NEVER raw hex, never hard-coded radii, status hues never on interactive
controls (lint `bombvault/no-status-color-on-control`).

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `carbon-background` (#161616 / #f4f4f4) | Page ground; the FoldersEditor panel itself is `bg-carbon-background` inside the container card (unchanged) |
| Secondary (30%) | `carbon-surface` (#262626 / #ffffff), nested `carbon-surface2` (#393939 / #e8e8e8) | Container cards (`.glim-hue` rows), nested fields/wells |
| Accent (10%) | `accent` (#FCC419 default, user-selectable) | See reserved list below |
| Destructive | `statusFail` (#ff8389 / #da1e28) | TEXT ONLY, existing rows unchanged ("not reachable", "custom missing"). No destructive action is added this phase |

Accent reserved for (exhaustive list — nothing else in the tree may take accent):

1. The native checkbox fill: `accentColor: var(--accent)` on every tree checkbox
   (checked tick AND the indeterminate dash) — the existing mount-checkbox treatment
   (`accent-(--accent)`), now also on the mixed state.
2. The keyboard focus ring on the focused treeitem (base
   `:focus-visible { outline: 2px solid var(--focus-ring) }` rule — no per-node work,
   but the tree must not suppress it).
3. The per-node loading spinner border (`border-accentText`, FolderBrowser spinner
   precedent).
4. Pre-existing controls in the panel (Add button `tone="accent"`, folder-browse
   badge) — unchanged.

Status tokens in this phase: `statusOk` text stays on the existing "appdata (default)"
line; `statusFail` text stays on existing not-reachable/missing lines; the D-04 guard
message uses `statusWarn` TEXT (see Copywriting); the "no access" and truncated rows use
`carbon-textMuted` TEXT — no status color ever lands on a checkbox, chevron, or row
background. Excluded vs plain-unchecked is distinguished by TEXT TONE only:

| Node state | Checkbox | Path/name text |
|------------|----------|----------------|
| checked (all below included) | checked, accent tick | `text-carbon-text` |
| mixed (remembered partial / whitelist) | indeterminate (accent dash) | `text-carbon-text` |
| unchecked (nothing selected at/under it) | unchecked | `text-carbon-textSub` |
| excluded (explicit `!` carve-out below an included ancestor) | unchecked | `text-carbon-textMuted` |

**[auto]** muted-vs-sub is the token-only distinguisher TREE-04 needs; a red/excluded
control would violate the house rule and a strikethrough would read as "deleted".
Four states, two unchecked checkboxes, two text tones — checker-verifiable.

## Interaction & Accessibility Contract (TREE-05, D-01, D-03, D-04)

### Structure

- ONE `role="tree"` per FoldersEditor, `aria-label={t("folders.treeLabel")}`. Level-1
  `role="treeitem"` entries are the existing mount rows followed by custom-path rows
  (D-02: the list BECOMES the tree; no modal, no second presentation). Children of an
  expanded node wrap in `role="group"`.
- Roving tabindex: exactly one treeitem carries `tabIndex={0}` (the last-focused node,
  first root initially), all others `tabIndex={-1}`. Selection is expressed ONLY via
  `aria-checked` on the treeitem ("true" / "mixed" / "false") — never also
  `aria-selected` (APG: never mix).
- `aria-expanded` on EVERY treeitem (all directories are potential parents — Phase 1
  rejected emptiness probes; an expanded empty dir honestly reports `true` with zero
  children). `aria-level`, `aria-setsize`, `aria-posinset` on every treeitem, computed
  from the flat model (uniformly, not only post-load). Notice rows (truncated, no
  access, empty, loading) are NOT treeitems and are excluded from setsize/posinset
  counts (RESEARCH Pitfall 7).
- Native `<input type="checkbox">` per row with `accentColor: var(--accent)"`; the
  mixed state is set via the DOM `indeterminate` property in a callback ref/effect
  (React has no prop for it — first tri-state checkbox in the app, RESEARCH Pattern 5).
  Checkbox semantics live on the treeitem's aria-checked; the input is the visible
  control and carries `aria-hidden` OR its own label omitted — do NOT duplicate
  state on both elements.

### Keyboard map (APG TreeView, checkbox variant)

| Key | Action |
|-----|--------|
| Right Arrow | closed → expand (focus STAYS on parent; async children may still be loading); open → focus first child; second Right while loading → no-op |
| Left Arrow | open → collapse; closed child → focus parent; closed root → nothing |
| Down / Up | focus next/previous focusable treeitem, never expands/collapses |
| Home / End | first / last focusable treeitem |
| Enter | toggle expansion on any node (default action); no extra action on leaves |
| Space | toggle the focused node's checkbox (the ONLY selection toggler) |

Type-ahead deliberately deferred (APG optional; keeps scope tight — RESEARCH Pattern 4).
Test file follows the house precedent: `SelectionTree.keyboard.dom.test.tsx`, modeled on
`DropdownListbox.keyboard.dom.test.tsx` (jsdom `// @vitest-environment jsdom` pragma,
`document.activeElement` assertions, `scrollIntoView` stub).

### Pointer model

- Click on the chevron OR the row body → expand/collapse that node.
- Click on the checkbox → selection toggle only (`stopPropagation`).
- Hover: no special tree treatment (no per-row accent — accent stays reserved).

### Selection state machine (D-01, verbatim)

Cycle is remembered-partial, realized by the flat `!`-encoding (dormant exclusions):

1. unchecked → click → **fill**: node becomes an include; everything below is included
   (existing dormant exclusions below it wake and immediately apply — restoring a
   remembered partial exactly, with zero UI-side memory).
2. checked (no exclusions below) → click → **uncheck all**: remove the include;
   exclusions strictly below go dormant (stay stored, never deleted — deleting them
   destroys the remembered partial).
3. mixed → click → **uncheck all below, remembering the partial**: remove the include;
   the exclusion set below is preserved dormant.
4. Never silently overwrite a mixed state: fill applies ONLY to the unchecked→checked
   transition.

Per-node display state is PURE list arithmetic over includes `I` and exclusions `E`
(prefix tests, segment-aligned, mirroring `selection.go`): excluded ⇔ at/under an `E`
entry; checked ⇔ at/under an `I` entry with no `E` strictly below; mixed ⇔ include
applies with an `E` strictly below, OR an `I` strictly below (whitelist start-state);
unchecked otherwise. Laziness affects only which rows render, never what state they
show (TREE-04 without expanding anything).

### Save flow (D-03) and the D-04 guard

- Every toggle: optimistic mirror update → `PATCH /api/containers/{name}` with the full
  flat list (`backupPaths`: bare host-path includes + `"!"`-prefixed host-path
  exclusions) and `selectionSource:"tree"` → on failure revert re-derived from the
  LATEST mirror (not a captured snapshot) + `.glim-shake` keyed by node path
  (row `key` includes the shake nonce so the animation replays — house technique).
- PATCH queue is serialized one-deep: while a save is in flight a further toggle just
  marks dirty; on resolve the latest full list is sent once (Pitfall 5 — a slow save
  must never revert a newer toggle).
- **D-04 pre-PATCH block**: before building any request, count includes across the
  WHOLE item (all mounts + custom). If the toggle would leave zero includes, do NOT
  PATCH — render the `folders.emptySelectionBlocked` inline line + shake the row. The
  server's `code:"empty-selection"` envelope is an unreachable backstop, handled
  defensively (toast the error verbatim + revert) if it ever fires.
- Success feedback stays the existing quiet toast (`folders.saved`) — no per-row flash.

### Expansion persistence (D-05)

- localStorage key `bv-tree-expanded-{containerName}`, value a JSON array of expanded
  HOST paths, hard-capped at 64 entries (oldest-expanded evicted — write order = recency
  order). **[auto]** cap 64: bounds growth per container while covering real appdata
  browsing; exact number is planner-tunable. Selection is NEVER stored here — TREE-04
  reconstruction always re-reads the server (`GET /api/containers/{name}/mounts`).
- (I, E) mirror, listings cache (plain `Map`, editor lifetime), and translation roots
  live in FoldersEditor-level state so closing/reopening the section restores expansion
  and cached listings without refetch (Pitfall 3).

### Lazy loading states per node (TREE-01, TREE-06)

| Browse outcome | Render under the row |
|----------------|----------------------|
| in flight | spinner (`h-3 w-3 rounded-full border-2 border-accentText border-t-transparent animate-spin`) + `folder.loading`, muted |
| ok, dirs[] non-empty | child treeitem rows (sorted as served — server sorts lexically) |
| ok, truncated:true | children, then the `folders.truncatedList` muted non-interactive notice row (D-06) — never a treeitem, never paginated |
| ok, zero dirs | one muted `folder.none` child row (plain text, not a treeitem) |
| ok:false (restricted/missing/error) | muted row: scrubbed server error text verbatim (fallback `folder.couldNotRead`) + compact neutral "Try again" Button (`folders.retry`) — selection state untouched; a vanished/unreadable folder never blocks saving |

No infinite spinners: every fetch resolves the per-node state in a `finally`; no path
where `dirs ?? []` swallows an `ok:false`. `hidden=1` is NEVER passed (BROWSE-04
consistency with FolderBrowser).

|----------|------------|--------|------------------------------|

| zero-one-many | E1 tree | ✅ resolved (explicit) | Zero → `folders.empty`; one/many mounts render identically to today (same rows, now expandable); no singular/plural copy added |
| long-text | E1 tree; E2 node row; E3 guard line; E4 error row | ✅ resolved (explicit) | Node names/paths: `truncate` + `title={path}` on every node span (`min-w-0 flex-1`), `dir="ltr"`, `break-all` preserved on root rows showing `dest ← source`; deep nesting shrinks the name area, never the indent.
