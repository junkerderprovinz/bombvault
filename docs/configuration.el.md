# Διαμόρφωση

Αυτή η σελίδα καλύπτει τις μεταβλητές περιβάλλοντος του κοντέινερ, τις προσαρτήσεις που παρέχει το template, το μοντέλο ασφαλείας, το αντίγραφο VM μέσω SSH και τη ρύθμιση εκτός τόπου. Το πού πηγαίνουν τα αντίγραφα ρυθμίζεται μέσα στην εφαρμογή ως **προορισμοί αποθήκευσης**, όχι με μεταβλητές περιβάλλοντος.

## Μεταβλητές περιβάλλοντος {#environment-variables}

| Μεταβλητή | Απαιτείται | Περιγραφή |
|---|---|---|
| `APP_KEY` | **Ναι** | Μυστικό hex 32 byte (64 χαρακτήρες hex) που χρησιμοποιείται για την παραγωγή του κωδικού του αποθετηρίου restic. Δημιουργήστε το με `openssl rand -hex 32`. Κρατήστε το ασφαλές: η απώλειά του καθιστά τα κρυπτογραφημένα αντίγραφα μη ανακτήσιμα. |
| `LIBVIRT_HOST` | Για VMs και σύνολα δεδομένων ZFS | Ο host Unraid που προσεγγίζεται μέσω SSH για αντίγραφα VM και συνόλων δεδομένων ZFS (πεδίο του template **Host SSH: Address**, προεπιλογή `host.docker.internal`). Το template προσυμπληρώνει το placeholder `192.168.x.x`, που θεωρείται μη ορισμένο. Χρησιμοποιήστε τη LAN IP του Unraid σας, απαιτείται σε προσαρμοσμένο δίκτυο `br0.x`. Όταν το `host.docker.internal` δεν επιλύεται, όπως σε μια εφαρμογή TrueNAS, και ούτε το `LIBVIRT_URI` ορίζει host, το BombVault χρησιμοποιεί την προεπιλεγμένη πύλη του κοντέινερ και το αρχείο καταγραφής εκκίνησης την αναφέρει. |
| `LIBVIRT_SSH_PORT` | Όχι | Η θύρα SSH του host για αντίγραφα VM και συνόλων δεδομένων ZFS (πεδίο του template **Host SSH: Port**, προεπιλογή `22`). |
| `LIBVIRT_SSH_USER` | Όχι | Ο χρήστης SSH στον host για αντίγραφα VM και συνόλων δεδομένων ZFS (πεδίο του template **Host SSH: User**, προεπιλογή `root`). |
| `LIBVIRT_URI` | Όχι | Πλήρες URI σύνδεσης libvirt, που χρησιμοποιείται **αυτούσιο** αντί να φτιαχτεί από τις τρεις παραπάνω μεταβλητές `LIBVIRT_*` (που τότε αγνοούνται για τη συμβολοσειρά σύνδεσης). Προεπιλογή: μη ορισμένο. Χρειάζεται στο TrueNAS Scale, του οποίου το libvirtd ακούει σε μη τυπικό socket που η μορφή της φτιαγμένης συμβολοσειράς δεν μπορεί να εκφράσει: `qemu+ssh://<user>@<truenas-host>/system?socket=/run/truenas_libvirt/libvirt-sock`. Δείτε τον [οδηγό αντιγράφων VM](vm-backup-ssh-setup.md#truenas-scale). Όταν είναι URI `qemu+ssh://`, καθεμία από τις `LIBVIRT_HOST`, `LIBVIRT_SSH_USER` και `LIBVIRT_SSH_PORT` που δεν έχει οριστεί λαμβάνεται από αυτό, και για τις δικές εντολές SSH του BombVault (μεταφορά NVRAM, σύνολα δεδομένων ZFS). |
| `PORT` | Όχι | Θύρα HTTP (προεπιλογή `3000`. Χρησιμοποιείται μόνο με `HTTP_ONLY=true`). |
| `HTTPS_PORT` | Όχι | Θύρα HTTPS (προεπιλογή `3443`. Το template τη δημοσιεύει 1:1, οπότε το WebUI απαντά στο `https://<ip>:3443`). |
| `HTTP_ONLY` | Όχι | Ορίστε `true` για να απενεργοποιήσετε τον αυτο-υπογεγραμμένο ακροατή HTTPS και να σερβίρετε μόνο απλό HTTP (για χρήση πίσω από reverse proxy που τερματίζει το TLS). |
| `BIND_HOST` | Όχι | Η διεύθυνση στην οποία ακούει το WebUI (προεπιλογή `0.0.0.0`, κάθε διεπαφή). Αφήστε το μη ορισμένο στο κοντέινερ, του οποίου οι δημοσιευμένες θύρες χρειάζονται κάθε διεπαφή. Το `127.0.0.1` ταιριάζει σε εκτέλεση εκτός Docker. Ο έλεγχος υγείας ρωτά την ίδια διεύθυνση. |
| `TRUSTED_PROXY` | Όχι | Διευθύνσεις ή περιοχές CIDR, χωρισμένες με κόμμα, του reverse proxy μπροστά από το BombVault (για παράδειγμα `192.168.20.11` ή `10.0.0.0/8`). Μόνο από αυτά τα βήματα πιστεύεται το `X-Forwarded-For`, και ο περιορισμός σύνδεσης μετρά τότε τις αποτυχίες ανά πραγματικό πελάτη αντί να βάζει όλους πίσω από τον proxy σε ένα καλάθι. Μη ορισμένο (η προεπιλογή) δεν εμπιστεύεται κανέναν: μια κεφαλίδα που θα πιστευόταν άνευ όρων θα άφηνε οποιονδήποτε να διαλέξει το δικό του καλάθι. |
| `HOST_SOURCE_ROOT` | Όχι | Η διαδρομή του host που προσαρτάται ως **Host Data** (προεπιλογή `/mnt`). Το BombVault μεταφράζει τις πηγές bind mount που αναφέρει το Docker σε διαδρομές κάτω από αυτό το mount. Αλλάξτε το μόνο αν προσαρτήσατε διαφορετική ρίζα του host. |
| `HOST_MOUNT_ROOT` | Όχι | Πού προσαρτάται το Host Data μέσα στο κοντέινερ (προεπιλογή `/host/user`). Στο TrueNAS το Host Data προσαρτάται στη δική του διαδρομή host, οπότε αυτό και το `HOST_SOURCE_ROOT` ονομάζουν και τα δύο αυτή τη διαδρομή, για παράδειγμα `/mnt/tank` (δείτε [TrueNAS SCALE](getting-started.md#truenas)). |
| `DATA_ROOT_SEGMENTS` | Όχι | Ονόματα τμημάτων διαδρομής, χωρισμένα με κόμμα, που σημαδεύουν την πηγή ενός bind mount ως δεδομένα αντιγράφου (προεπιλογή `appdata`, που ταιριάζει με τη σύμβαση `/mnt/user/appdata/<container>` του Unraid). Ένα bind mount κοντέινερ επιλέγεται αυτόματα για αντίγραφο όταν ΟΠΟΙΟΔΗΠΟΤΕ από τα τμήματα της λίστας εμφανίζεται ως πλήρες τμήμα διαδρομής της πηγής του στον host. Για παράδειγμα το `DATA_ROOT_SEGMENTS=appdata,config` πιάνει και ένα bind `.../config`. Η αντιστοίχιση αγνοεί πεζά και κεφαλαία, οπότε η προεπιλογή καλύπτει και το `/DATA/AppData/<container>` του ZimaOS. Δείτε [Εντοπισμός πηγής αντιγράφου](#backup-source-detection) για τους άλλους, πάντα ενεργούς τρόπους με τους οποίους βρίσκεται ο φάκελος δεδομένων ενός κοντέινερ. |
| `PLATFORM` | Όχι | Επιβάλλει σε ποια πλατφόρμα θεωρεί το BombVault ότι τρέχει, αντί για αυτόματο εντοπισμό: `unraid`, `generic` ή `truenas` (προεπιλογή μη ορισμένο: εντοπίζει αυτόματα το Unraid ψάχνοντας τον δείκτη `dockerMan` κάτω από το mount του flash, αλλιώς `generic`. Μια άγνωστη τιμή πέφτει επίσης σε `generic`, με καταγραφή). Ορίστε το ρητά σε generic host Docker ή TrueNAS Scale αντί να βασιστείτε στον εντοπισμό μόνο για Unraid. Το generic αρχείο compose το κάνει. Αλλάζει τη σύμβαση εφεδρείας του appdata, τις προεπιλογές προορισμού επαναφοράς ανάμεσα σε στιγμιότυπα και το αν δοκιμάζονται καθόλου τα βήματα ειδοποίησης/συνοδού πρόσθετου μόνο για Unraid (δείτε `internal/platform`). |
| `BOMBVAULT_SELF_CONTAINER` | Όχι | Το όνομα του ίδιου του κοντέινερ του BombVault, ώστε να μην αντιγράφει (και άρα να μη σταματά) τον εαυτό του. |
| `BACKUP_MAX_HOURS` | Όχι | Το μέγιστο πλήθος ωρών πραγματικού χρόνου που μπορεί μια εκτέλεση αντιγράφου να κρατά το κλείδωμα του τομέα της πριν ακυρωθεί διά της βίας (μια δικλίδα ώστε μια κολλημένη εκτέλεση να μη μπλοκάρει τον τομέα για πάντα). Κενό (η προεπιλογή) χρησιμοποιεί `48`. Αυξήστε το για πολύ μεγάλα ή αργά αντίγραφα cloud (μια εκτέλεση που ακυρώνεται στο όριο αποτυγχάνει με `context deadline exceeded`). Ορίστε `0` για να καταργήσετε εντελώς το όριο. Μια εκκαθάριση (prune) υπόκειται στο ίδιο όριο, και ένας έλεγχος ή μια εκκαθάριση τρέχει όσο το restic συνεχίζει να αναφέρει πρόοδο. |
| `BACKUP_STALL_HOURS` | Όχι | Ώρες που μπορεί ένα αντίγραφο να μην κάνει **καμία πρόοδο** πριν ακυρωθεί. Κενό (η προεπιλογή) χρησιμοποιεί `2`. Ορίστε `0` για να μη ακυρώνεται ποτέ λόγω στασιμότητας. Αυτή είναι η λεπτότερη από τις δύο δικλίδες και συνήθως αυτή που ενεργοποιείται: παρακολουθεί αν κάτι συμβαίνει ακόμα και όχι πόσο έχει διαρκέσει η εκτέλεση, οπότε ένα αργό αλλά υγιές αντίγραφο πολλών terabyte αφήνεται ήσυχο, ενώ ένα κολλημένο σε έναν μη αποκρινόμενο κοινόχρηστο πόρο σταματά σε ώρες αντί για ημέρες. Μια προειδοποίηση καταγράφεται μετά από 30 λεπτά σιωπής, πριν ακυρωθεί οτιδήποτε. Η σάρωση μετρά ως πρόοδος: το restic δεν γράφει byte όσο διασχίζει ένα μεγάλο δέντρο, και αυτή η φάση παρακολουθείται μέσω των συνόλων αρχείων και byte και όχι των byte που γράφτηκαν. Οι δύο μεταβλητές είναι ανεξάρτητες, και το `BACKUP_MAX_HOURS` εξακολουθεί να οριοθετεί τις φάσεις μετά το ίδιο το αντίγραφο (διατήρηση, στατιστικά, αντίγραφο εκτός τόπου), όπου δεν υπάρχουν μετρητές να παρακολουθηθούν. |
| `DB_DUMP_MAX_HOURS` | Όχι | Ώρες που μπορεί να τρέχει ένα αυτόματο dump βάσης δεδομένων πριν σταματήσει. Κενό (η προεπιλογή) χρησιμοποιεί `6`. Επιτρεπόμενες τιμές είναι από `1` έως `48`, και το όριο κρατιέται μία ώρα κάτω από το `BACKUP_MAX_HOURS` (στο μισό του όταν αυτό είναι κάτω από δύο ώρες), ώστε ένα μακρύ dump να κόβεται από το δικό του όριο και να αναφέρεται ως τέτοιο αντί να ρίξει μαζί του το αντίγραφο. Ένα dump που δεν κάνει πρόοδο σταματά νωρίτερα, μετά από `BACKUP_STALL_HOURS`. Ένα σταματημένο dump αποτυγχάνει μόνο του και το αντίγραφο του κοντέινερ συνεχίζει. Στο Unraid, προσθέστε το στο κοντέινερ BombVault με **Add another Path, Port, Variable**. |
| `TZ` | Όχι | Ζώνη ώρας του χρονοπρογραμματιστή (για παράδειγμα `Europe/Berlin`). **Αν το αφήσετε μη ορισμένο, κάθε χρονοδιάγραμμα τρέχει σε UTC**: ένα ορισμένο στις 02:30 ενεργοποιείται τότε στις 02:30 UTC και όχι στο δικό σας ρολόι. Στο Unraid δεν το ορίζετε ποτέ μόνοι σας: το σύστημα περνά τη δική του ζώνη ώρας σε κάθε κοντέινερ. Το αρχείο καταγραφής εκκίνησης λέει σε ποια ζώνη κατέληξε. Μια ζώνη με θερινή ώρα χάνει μία εκτέλεση την άνοιξη και τρέχει μία δύο φορές το φθινόπωρο, ενώ το UTC δεν κάνει κανένα από τα δύο, αλλά ξεφεύγει μια ώρα από το ρολόι σας δύο φορές τον χρόνο. |
| `DATA_DIR` | Όχι | Πού κρατά το BombVault τη βάση δεδομένων, τα κλειδιά και τις caches του (προεπιλογή `/config`). Αφήστε το ήσυχο στο κοντέινερ. Έχει σημασία όταν τρέχετε το δυαδικό εκτός Docker. |
| `FLASH_DIR`, `FLASH_TEMPLATES_DIR` | Όχι | Πού προσαρτώνται η μονάδα flash και τα templates Docker της μέσα στο κοντέινερ (προεπιλογές `/host/boot` και `/host/boot/config/plugins/dockerMan/templates-user`). Ακολουθούν το mount `/boot` του template, οπότε αφήστε τα μη ορισμένα. |

## Προσαρτήσεις {#mounts}

Προσαρτήστε το Docker socket, το flash (`/boot`) και τη ρίζα του **Host Data** (`/mnt`) όπως φαίνεται στο template του CA. Οι *πηγές* και οι *προορισμοί* των αντιγράφων βρίσκονται και οι δύο κάτω από το Host Data, και προσαρτάται ως **slave** ώστε ένας απομακρυσμένος κοινόχρηστος πόρος που προσαρτάται μετά την εκκίνηση του κοντέινερ (για παράδειγμα κάτω από το `/mnt/remotes`) να γίνεται ορατός χωρίς επανεκκίνηση.

Στο TrueNAS, το Host Data είναι μια διαδρομή συνόλου δεδομένων όπως το `/mnt/tank`, ποτέ ixVolume. Δεδομένα που μια εφαρμογή κρατά σε ixVolume βρίσκονται έξω από αυτό και δεν αντιγράφονται. Δείτε [TrueNAS SCALE](getting-started.md#truenas).

Και τα αντίγραφα συνόλων δεδομένων ZFS χρειάζονται αυτή τη λειτουργία: ο host προσαρτά το στιγμιότυπο ενός συνόλου δεδομένων μόνο αφού έχει ξεκινήσει το κοντέινερ. Δείτε [Σύνολα δεδομένων ZFS](zfs-datasets.md).

Τα τοπικά αποθετήρια έχουν ως προεπιλογή το `/mnt/user/bombvault/{container,vms,flash,config,files,zfs}`, που δημιουργείται στο πρώτο αντίγραφο. Είναι οι **δικοί φάκελοι** των τομέων και σχηματίζουν τον προορισμό αποθήκευσης **Τοπικό**. Στη σελίδα του κάτω από τους **Προορισμούς**, η κάρτα **Σύνδεση** αλλάζει τον φάκελο κάθε τομέα.

Ο δικός φάκελος ενός τομέα μπορεί επίσης να βρίσκεται σε έναν προορισμό αποθήκευσης που έχετε ήδη, όπως ένα NAS ή ένας κάδος S3: η **Χρήση ως δικού φακέλου** στη σελίδα εκείνου του προορισμού τον μετακινεί εκεί και λέει πρώτα τι γίνεται με τα αντίγραφα που έχουν ήδη γίνει. Δείτε [Ο δικός φάκελος ενός τομέα](offsite-recovery.md#own-folder).

Οι φάκελοι των τοπικών αποθετηρίων μένουν στα δικαιώματα `0755` και `0644`, ώστε ένας χρήστης συγχρονισμού χωρίς root μέσω SMB να μη κλειδώνεται έξω, και τα αποθετήρια είναι κρυπτογραφημένα, οπότε αυτό δεν εκθέτει τίποτα. Οι ορισμοί ανάκτησης ζουν μέσα σε κάθε αποθετήριο, οπότε ένας αντιγραμμένος φάκελος είναι πλήρης από μόνος του. Το αποθετήριο του αυτο-αντιγράφου μένει αναγνώσιμο μόνο από το root.

!!! note "Έλεγχος ενσωμάτωσης host"
    Η κάρτα **Ενσωμάτωση host** στην επισκόπηση (προσθέστε την κάτω από την **Προσαρμογή**) ελέγχει κάθε mount και CLI (Docker socket, libvirt, restic, qemu-img, rclone) και αναφέρει ό,τι λείπει.

## Εντοπισμός πηγής αντιγράφου {#backup-source-detection}

Για κάθε κοντέινερ, το BombVault επιλέγει αυτόματα ποια bind mounts και ονομασμένους τόμους θα αντιγράψει. Μια διαδρομή πιάνεται όταν ισχύει οτιδήποτε από τα παρακάτω (μπορείτε πάντα να παρακάμψετε το αποτέλεσμα στην κάρτα **Φάκελοι αντιγράφων** στην καρτέλα Ρυθμίσεις του κοντέινερ):

- **Αντιστοίχιση τμήματος ρίζας δεδομένων:** η πηγή του bind στον host περιέχει ένα από τα τμήματα του `DATA_ROOT_SEGMENTS` ως πλήρες συστατικό διαδρομής (προεπιλογή μόνο `appdata`).
- Οι **ονομασμένοι τόμοι Docker** περιλαμβάνονται πάντα, αφού δεν έχουν ισοδύναμο προς πέταμα και δεν υπάρχει τίποτα να φιλτραριστεί, **αλλά μόνο όταν η πραγματική διαδρομή αποθήκευσης του τόμου στον host είναι η ίδια προσβάσιμη μέσω του mount του Host Data**, ακριβώς όπως κάθε άλλη διαδρομή του host που αντιγράφει το BombVault. Ο προεπιλεγμένος οδηγός τοπικών τόμων του Docker αποθηκεύει έναν τόμο κάτω από τη ρίζα δεδομένων του ίδιου του daemon (`/var/lib/docker/volumes/<name>/_data`, εκτός αν την έχετε προσαρμόσει. Ελέγξτε με `docker info -f '{{.DockerRootDir}}'`), η οποία δεν καλύπτεται από το στενό mount του Host Data ενός μόνο φακέλου που χρησιμοποιεί από προεπιλογή το generic `docker-compose.yml`. Ένας τόμος που δεν προσεγγίζεται παραλείπεται σιωπηλά, δεν είναι σφάλμα. Για να αντιγράψετε πραγματικά ονομασμένους τόμους σε generic host, στρέψτε το Host Data (και το `HOST_SOURCE_ROOT`) σε έναν κοινό πρόγονο που καλύπτει και τη ρίζα δεδομένων του Docker. Το σχόλιο για το Host Data στο αρχείο compose εξηγεί τον συμβιβασμό (το Unraid τον παρακάμπτει προσαρτώντας ολόκληρο το `/mnt`, τη δική του καθολική σύμβαση ανώτατου επιπέδου, για τον ίδιο λόγο).
- **Φάκελος έργου Docker Compose:** αν το κοντέινερ φέρει την τυπική ετικέτα `com.docker.compose.project.working_dir` (που ορίζεται αυτόματα από το `docker compose up`), αυτός ο φάκελος προστίθεται επίσης, ανεξάρτητα από το αν κάποιο bind ταίριαξε με τμήμα ρίζας δεδομένων.
- **Παράκαμψη με την ετικέτα `bombvault.data`:** ορίστε την ετικέτα `bombvault.data=true` σε ένα κοντέινερ για να περιλάβετε όλα τα bind mounts του, για μια διάταξη που καμία από τις παραπάνω συμβάσεις δεν πιάνει (για παράδειγμα ένα μοναδικό bind `/srv/plex/config` χωρίς έργο Compose). Κάθε μη κενή τιμή εκτός του `false` θεωρείται αληθής. Μια απούσα ετικέτα ή το `bombvault.data=false` δεν αλλάζει τίποτα.
- **Ετικέτα `bombvault.dbdump`:** ορίστε `bombvault.dbdump=false` σε ένα κοντέινερ για να απενεργοποιήσετε το αυτόματο dump βάσης δεδομένων του (το ίδιο κάνουν τα `0`, `no` και `off`), ή ονομάστε τη μηχανή (`postgres`, `mysql`, `mariadb`) για να γίνει dump σε ένα κοντέινερ που το BombVault δεν αναγνωρίζει μόνο του. Η ετικέτα υπερισχύει του διακόπτη στην κάρτα **Βάση δεδομένων** στην καρτέλα Ρυθμίσεις του κοντέινερ, που είναι ο τρόπος να το κάνετε στο Unraid.

## Μοντέλο ασφαλείας {#security-model}

!!! warning "Έλεγχος ισοδύναμος με root στον host"
    Μέσω του Docker socket το BombVault μπορεί να σταματά, να αφαιρεί και να ξαναδημιουργεί κοντέινερ και να διαβάζει/γράφει το appdata, και για το αντίγραφο VM συνδέεται στον host μέσω SSH (`qemu+ssh://`, από προεπιλογή ως root) για να τρέξει `virsh`. Όποιος φτάνει στο web UI του έχει ουσιαστικά root στον host.

### Σύνδεση {#login}

- **Προαιρετική προστασία με κωδικό** (κάρτα **Κωδικός πρόσβασης** στις **Ρυθμίσεις, Ασφάλεια**): ορίστε κωδικό για να απαιτείται σύνδεση, διαγράψτε τον για να την απενεργοποιήσετε. Ανενεργή από προεπιλογή για χρήση σε αξιόπιστο LAN. Ο κωδικός αποθηκεύεται με Argon2id πάνω από ένα pepper που εξαρτάται από το `APP_KEY`, οπότε ένα αντιγραμμένο `/config` είναι άχρηστο χωρίς το κλειδί και αργό στην επίθεση ακόμα και με αυτό. Ένας νέος κωδικός χρειάζεται τουλάχιστον 12 χαρακτήρες. Ένας υπάρχων μικρότερος συνεχίζει να λειτουργεί μέχρι να αλλάξει. Οι συνεδρίες υπογράφονται (HMAC που παράγεται από το `APP_KEY`) και η αλλαγή του κωδικού τις ακυρώνει. Οι συνδέσεις περιορίζονται σε πέντε αποτυχίες το λεπτό ανά πελάτη. Η αλλαγή ή η διαγραφή του κωδικού ζητά τον **Τρέχων κωδικός πρόσβασης** και, με ενεργή την ταυτοποίηση δύο παραγόντων, τον κωδικό.
- **Κάποια πράγματα χρειάζονται κωδικό.** Η λήψη του κιτ ανάκτησης και της αναφοράς σφάλματος, η κατάθεση του κλειδιού σε έναν φύλακα κλειδιού, η άδεια παράδοσης μιας κατάθεσης, η δημιουργία νέου κωδικού ανάκτησης, η διαγραφή των αντιγράφων σε έναν προορισμό αποθήκευσης, η εξαγωγή ρυθμίσεων με διαπιστευτήρια, η ταυτοποίηση δύο παραγόντων και τα κλειδιά πρόσβασης απορρίπτονται μέχρι να οριστεί κωδικός εισόδου, και χρειάζονται σύνδεση στην ίδια την εγκατάσταση.
- **Ταυτοποίηση δύο παραγόντων** (**Ρυθμίσεις, Ασφάλεια**): ένας χρονικός κωδικός από μια εφαρμογή ταυτοποίησης επιπλέον του κωδικού πρόσβασης, μαζί με οκτώ κωδικούς ανάκτησης μίας χρήσης που δίνονται μία φορά όταν ενεργοποιείται. Το κοινό μυστικό αποθηκεύεται κρυπτογραφημένο με το `APP_KEY`, και η απενεργοποίηση του παράγοντα απαιτεί έναν τρέχοντα κωδικό.
- Τα **Κλειδιά πρόσβασης** (WebAuthn) έχουν δική τους κάρτα μόλις οριστεί κωδικός, δίπλα στον κωδικό και ποτέ αντί γι' αυτόν, οπότε η αφαίρεση κάθε κλειδιού πρόσβασης δεν κλειδώνει κανέναν έξω. Χρειάζονται πραγματικό όνομα domain και πιστοποιητικό που εμπιστεύεται ο browser. Το προεπιλεγμένο `https://<ip>:3443` είναι ακριβώς αυτό που το WebAuthn αρνείται, και η κάρτα το λέει αντί να προσφέρει ένα κουμπί που αποτυγχάνει. Με ενεργή την ταυτοποίηση δύο παραγόντων, ένα κλειδί πρόσβασης πρέπει να ελέγξει το PIN, το δαχτυλικό αποτύπωμα ή το πρόσωπό σας, αλλιώς η σύνδεση ζητά και τον κωδικό.
- **Μια επαναφορά διαμόρφωσης** (**Επαναφορά ρυθμίσεων** στον Οδηγό έκτακτης ανάγκης) τερματίζει κάθε συνεδρία, αφαιρεί κάθε κλειδί πρόσβασης και ανακαλεί κάθε token API και κλειδί MCP, γιατί οι επαναφερμένες ρυθμίσεις θα μπορούσαν να φέρουν πίσω κάποια που αφαιρέθηκαν αφού αποθηκεύτηκαν. Συνδεθείτε με τον κωδικό και ρυθμίστε ξανά τα κλειδιά πρόσβασής σας στις **Ρυθμίσεις, Ασφάλεια**.
- **Ένας ξεχασμένος κωδικός** επαναφέρεται στη σελίδα σύνδεσης. Το **Ξεχάσατε τον κωδικό πρόσβασης;** κάνει το BombVault να γράψει έναν κωδικό 12 χαρακτήρων, σε τρεις ομάδες των τεσσάρων, στο αρχείο καταγραφής του κοντέινερ του (στο Unraid: καρτέλα Docker, εικονίδιο BombVault, **Logs**). Αυτός ο κωδικός και ένας νέος κωδικός πρόσβασης σας συνδέουν. Η επαναφορά απενεργοποιεί επίσης την ταυτοποίηση δύο παραγόντων, αφαιρεί κάθε κλειδί πρόσβασης, ανακαλεί κάθε token API, κλειδί MCP και σύνδεση OAuth, τερματίζει κάθε άλλη συνεδρία, αποσυνδέει κάθε συζευγμένο τηλέφωνο και απενεργοποιεί τη σύζευξη τηλεφώνων. Η σελίδα μετά απαριθμεί τι χάθηκε. Ένας κωδικός ισχύει για 10 λεπτά, και οι λάθος προσπάθειες δεν τον εξαντλούν. Τα tokens του widget και των metrics μένουν, αφού μόνο διαβάζουν.
- **Όποιος μπορεί να διαβάσει το αρχείο καταγραφής του κοντέινερ μπορεί να επαναφέρει τον κωδικό.** Αυτό είναι root στον host, αλλά και ένα πρόγραμμα προβολής αρχείων καταγραφής όπως το Dozzle, κάθε κοντέινερ που έχει το Docker socket (αρκεί μόνο για ανάγνωση) και ένας log shipper που προωθεί την έξοδο των κοντέινερ. Δώστε τα μόνο σε ανθρώπους που θα εμπιστευόσασταν με τον κωδικό. Κάποιος που φτάνει μόνο στη διεπαφή web δεν βλέπει ποτέ τον κωδικό.

### Τηλέφωνα και μέλη της ομάδας {#phones-and-members}

- **Τα συζευγμένα τηλέφωνα φτάνουν σε μια λίστα επιτρεπόμενων.** Ένα τηλέφωνο που ξέρει τις δώδεκα λέξεις της ομάδας συνδέεται χωρίς τον κωδικό, αρκεί να είναι ενεργό το **Τα τηλέφωνα μπορούν να συζευχθούν με τις δώδεκα λέξεις της ομάδας** στην κάρτα **Εφαρμογή Android** κάτω από τις **Ρυθμίσεις, Ασφάλεια**. Η συνεδρία του φτάνει μόνο σε ό,τι δείχνει η εφαρμογή: την επισκόπηση, τις εκτελέσεις, τα αντίγραφα για προβολή, εκκίνηση και επαναφορά, τις ανωμαλίες για ανάγνωση και τη σελίδα Στιγμιότυπα για προβολή. Οι προορισμοί αποθήκευσης και οι εντολές τού φτάνουν με αφαιρεμένες τις διευθύνσεις και τα μυστικά τους, και μια επαναφορά που αντικαθιστά το πρωτότυπο κρατά πρώτα αντίγραφο της τρέχουσας κατάστασης. Όλα τα άλλα απαντούν ότι χρειάζονται σύνδεση στην ίδια την εγκατάσταση: κλειδιά, το κιτ ανάκτησης, καταθέσεις κλειδιών, ρυθμίσεις, διαγραφή αντιγράφων. Μια επαναφορά κωδικού απενεργοποιεί τη σύζευξη τηλεφώνων μέχρι να την ξαναενεργοποιήσετε. Ένα τηλέφωνο που αφαιρείται από τη σελίδα Στιγμιότυπα, ή με απενεργοποιημένο το **Ερώτημα σε αυτή την εγκατάσταση** στις λεπτομέρειές του, χάνει αμέσως τη συνεδρία του, και ένα αφαιρεμένο τηλέφωνο που ανοίγει ξανά την εφαρμογή του επανέρχεται απενεργοποιημένο.
- **Μακριά από το σπίτι ένα τηλέφωνο ανοίγει σελίδες μέσω του αναμεταδότη.** Κάθε αίτημα της σελίδας σφραγίζεται με το κλειδί της ομάδας, που ο αναμεταδότης δεν μπορεί να διαβάσει ή να αλλάξει, και υπογράφεται με ένα δικό του κλειδί του τηλεφώνου που ο διακομιστής καρφίτσωσε την πρώτη φορά που ρώτησε το τηλέφωνο. Ο διακομιστής εκτελεί ένα αίτημα μία φορά και μόνο όσο είναι πρόσφατο. Απαντά μόνο σε ένα τηλέφωνο που απαριθμείται στη σελίδα Στιγμιότυπα όσο η σύζευξη τηλεφώνων είναι ενεργή, και μόνο με μια συνεδρία που έδωσε σε εκείνο το τηλέφωνο, οπότε η αποσύνδεση παντού και η επαναφορά κωδικού τερματίζουν και αυτές τις σελίδες. Ο διακομιστής υπογράφει κάθε απάντηση, και η εφαρμογή ελέγχει την υπογραφή με το κλειδί που καρφίτσωσε για αυτόν τον διακομιστή και προειδοποιεί όταν το κλειδί αλλάζει. Μια τέτοια σελίδα φτάνει στην ίδια λίστα επιτρεπόμενων με ένα συζευγμένο τηλέφωνο, με ή χωρίς κωδικό εισόδου, συν την κατάσταση σύνδεσης που διαβάζει πρώτα η σελίδα. Η σύνδεση και η αποσύνδεση, η επαναφορά κωδικού και οι λήψεις μένουν στη δική του διεύθυνση του διακομιστή, και μία απάντηση περιορίζεται στα 16 MB.
- **Τα μέλη υπογράφουν ό,τι ζητούν.** Τα αιτήματα ρόλων και οι απαντήσεις τους, η παράδοση ενός κωδικού restic σε δέκτη ή αντλητή, οι συνδέσεις δεκτών και οι καταθέσεις κλειδιών υπογράφονται με ένα κλειδί κάθε μέλους, που ένα στιγμιότυπο καρφιτσώνει την πρώτη φορά που βλέπει αυτό το μέλος. Μια κλήση υπογεγραμμένη με άλλο κλειδί απορρίπτεται. Το **Λήθη κλειδιού** στις λεπτομέρειες ενός στιγμιοτύπου πετά το καρφιτσωμένο κλειδί, για την περίπτωση που το κλειδί που είναι γνωστό εδώ δεν είναι του ίδιου του μέλους. Το μέλος ρωτιέται ξανά για το κλειδί του στην επόμενη υπογεγραμμένη κλήση του. Τα μέλη σε BombVault 9.x δεν υπογράφουν και μπορούν να πλαστοπροσωπηθούν από οποιονδήποτε έχει τις λέξεις, όπως στην 9.9.
- **Οι δώδεκα λέξεις είναι κωδικός.** Όποιος τις έχει μπαίνει στην ομάδα, βλέπει την κατάσταση προστασίας των μελών και μπορεί να ζητήσει ρόλους, τους οποίους ένας άνθρωπος στο άλλο στιγμιότυπο πρέπει ακόμα να επιτρέψει. Χωρίς κωδικό εισόδου, όποιος μπορεί να ανοίξει τη διεπαφή web μπορεί να τις διαβάσει, και η κάρτα σύζευξης το λέει μέχρι να οριστεί κωδικός.

### Κλειδιά {#keys}

- **Το APP_KEY κάνει δύο πράγματα.** Σφραγίζει ό,τι αποθηκεύει αυτή η εγκατάσταση (κωδικούς, διαπιστευτήρια, tokens) και είναι το κλειδί των αντιγράφων: ο κωδικός του restic παράγεται από αυτό, και οι ορισμοί κοντέινερ και VM σφραγίζονται με αυτό.
- **Ένα κλειδί που παραλήφθηκε κρατιέται χωριστά.** Όταν ο Οδηγός έκτακτης ανάγκης αναλαμβάνει τα αντίγραφα ενός άλλου διακομιστή, αυτή η εγκατάσταση συνεχίζει να σφραγίζει με το δικό της APP_KEY και αποθηκεύει το κλειδί του άλλου διακομιστή ως **κλειδί αντιγράφων** της, σφραγισμένο όπως κάθε άλλο μυστικό. Το κιτ ανάκτησης τυπώνει τότε και τα δύο. Αν το APP_KEY αλλάξει μετά, το κλειδί αντιγράφων δεν μπορεί πια να ανοίξει: το BombVault σταματά να αντιγράφει και το λέει στο **Χρειάζεται προσοχή**, αντί να γράφει με λάθος κλειδί. Ανεβάστε ξανά το κιτ ανάκτησης στην **Επαναφορά, Έκτακτη ανάγκη**, ή επαναφέρετε το APP_KEY. Δείτε [Οδηγός έκτακτης ανάγκης](offsite-recovery.md#emergency).
- Η **Κρυπτογράφηση** είναι ενεργή από προεπιλογή (**Κρυπτογράφηση αντιγράφων** στην κάρτα **Κρυπτογράφηση** κάτω από τις **Ρυθμίσεις, Ασφάλεια**). Τα αντίγραφα κρυπτογραφούνται από το restic με τον κωδικό που παράγεται από το κλειδί αντιγράφων.
- **Καταθέσεις κλειδιών.** Ένας φύλακας κλειδιού στην ομάδα σας κρατά ένα σφραγισμένο αντίγραφο του κιτ ανάκτησης αυτού του διακομιστή, που ο ίδιος δεν μπορεί να ανοίξει. Μόνο ο κωδικός ανάκτησης των 20 χαρακτήρων το ανοίγει, και ο φύλακας το παραδίδει μόνο αφού κάποιος εκεί πατήσει **Να επιτραπεί**. Δείτε [Φύλακας κλειδιού](offsite-recovery.md#key-keeper).

### Δίκτυο {#network}

- **Οι αλλαγές θέλουν JSON.** Ένα αίτημα που αλλάζει κάτι πρέπει να στείλει `Content-Type: application/json` και να μην σημαδεύεται από τον browser ως cross-site, ώστε μια σελίδα σε άλλο site να μη μπορεί να κάνει τον browser σας να αλλάξει ρυθμίσεις σε μια διεύθυνση LAN. Ένα script που οδηγεί το API στέλνει αυτή την κεφαλίδα. Οτιδήποτε άλλο απορρίπτεται με `415`.
- Επειδή η πύλη είναι προαιρετική, όταν δεν έχει οριστεί ολόκληρο το UI και το API (συμπεριλαμβανομένων των προορισμών αποθήκευσης, των διαδρομών δοκιμής παραβίασης και των διαδρομών επαναφοράς) είναι προσβάσιμα σε οποιονδήποτε φτάνει τη θύρα. Ορίστε κωδικό εισόδου μόλις χρησιμοποιηθούν αντίγραφα εκτός τόπου, append-only ή κρυπτογράφηση.
- Τρέχετε το BombVault μόνο σε αξιόπιστο, μη εκτεθειμένο δίκτυο. Για απομακρυσμένη πρόσβαση βάλτε το πίσω από reverse proxy που προσθέτει ταυτοποίηση και TLS. Οι απαντήσεις φέρουν βασικές κεφαλίδες ασφαλείας (CSP, `nosniff`, `X-Frame-Options`, `Referrer-Policy`).
- Πίσω από reverse proxy κάθε αίτημα φέρει τη διεύθυνση του proxy, οπότε χωρίς το `TRUSTED_PROXY` ο περιορισμός σύνδεσης μετρά κάθε πελάτη σε ένα καλάθι και οι αποτυχίες ενός επιτιθέμενου σας κλειδώνουν κι εσάς έξω. Ονομάστε τον proxy στο `TRUSTED_PROXY` για να επανέλθει η μέτρηση ανά πελάτη.
- Ένας reverse proxy μπροστά από το BombVault πρέπει να περνά την κεφαλίδα `Authorization` ή `X-API-Key` προς το `/mcp` και δεν πρέπει να αποθηκεύει προσωρινά τις απαντήσεις του, αλλιώς οι βοηθοί δεν μπορούν να συνδεθούν. Δείτε [Διακομιστής MCP](mcp.md#tls).
- Το endpoint MCP `/mcp` απαντά `404` μέχρι να υπάρξει κλειδί ή να ενεργοποιηθεί η σύνδεση μέσω OAuth, και ζητά από κάθε πελάτη το κλειδί ή το token του ακόμα και με απενεργοποιημένο τον κωδικό εισόδου. Καμία διεύθυνση δεν εξαιρείται, ούτε το `localhost`. Δεν έχει εργαλεία επαναφοράς ή διαγραφής, και η επαναφορά ενός αντιγράφου διαμόρφωσης ανακαλεί κάθε κλειδί. Δείτε [Διακομιστής MCP](mcp.md#security).
- Με `HTTP_ONLY=true` το cookie συνεδρίας χάνει τη σημαία `Secure` (πρέπει, για να λειτουργεί μέσω απλού HTTP), οπότε ενεργοποιήστε τον κωδικό πίσω από proxy που τερματίζει το TLS μόνο αν σας νοιάζει η εμπιστευτικότητα.
- Η σύνδεση SSH του αντιγράφου VM εμπιστεύεται το κλειδί του host στην πρώτη σύνδεση (TOFU) και το καρφιτσώνει από εκεί και πέρα. Επαληθεύστε το κλειδί του host εκτός δικτύου αν η διαδρομή από το κοντέινερ προς τον host δεν είναι αξιόπιστη.

## Διακομιστής MCP {#mcp-server}

Ο διακομιστής MCP δεν χρειάζεται καμία μεταβλητή περιβάλλοντος. Τον ενεργοποιείτε δημιουργώντας ένα κλειδί στις **Ρυθμίσεις, Ενσωματώσεις, Διακομιστής MCP**, και απαντά στο `/mcp` στην ίδια θύρα με τη διεπαφή web (για παράδειγμα `https://192.168.1.10:3443/mcp`). Χωρίς ενεργό κλειδί αυτή η διαδρομή απαντά `404`. Οι πελάτες, τα πιστοποιητικά και τα όρια περιγράφονται στη σελίδα [Διακομιστής MCP](mcp.md).

## Αντίγραφο VM μέσω SSH {#vm-backup-over-ssh}

Το BombVault αντιγράφει VMs KVM/libvirt **χωρίς να προσαρτά καμία διαδρομή libvirt**. Τρέχει το `virsh` στον host μέσω SSH (`qemu+ssh://`), οπότε δεν μπορεί ποτέ να επηρεάσει τον VM Manager του host σας.

Η προσάρτηση του socket libvirt του host σε ένα κοντέινερ είναι εύθραυστη στο Unraid: ο VM Manager κατέχει αυτές τις διαδρομές, και η εναλλαγή του «Enable VMs» μπορεί να αφήσει το libvirt ανίκανο να ξεκινήσει. Το κλειδί SSH δίνει root στον host, το ίδιο επίπεδο εμπιστοσύνης με το Docker socket που ήδη χρησιμοποιεί το BombVault.

Γρήγορη ρύθμιση:

1. **Ρυθμίσεις, Ενσωματώσεις, SSH κεντρικού συστήματος:** αντιγράψτε το δημόσιο κλειδί που εμφανίζεται.
2. Προσθέστε το στο τέλος του `/root/.ssh/authorized_keys` του Unraid (αποθηκεύεται επίσης στο flash ώστε να επιβιώνει των επανεκκινήσεων).
3. Κάντε κλικ στο **Δοκιμή σύνδεσης**.

Το template προσθέτει `--add-host=host.docker.internal:host-gateway` ώστε το κοντέινερ να φτάνει τον host. Ορίστε το `LIBVIRT_HOST` στη LAN IP του Unraid σας αν αυτό το όνομα δεν επιλύεται (για παράδειγμα όταν το κοντέινερ τρέχει σε προσαρμοσμένο δίκτυο `br0.x`). Αν αλλάξατε τη θύρα SSH του Unraid, ορίστε το `LIBVIRT_SSH_PORT` ώστε να ταιριάζει. Τα **Ζωντανά στιγμιότυπα** χρειάζονται επίσης τον qemu guest agent στη VM και τον δίσκο στο `/mnt/cache` (όχι στο `/mnt/user`).

!!! important "Πλήρης οδηγός ρύθμισης και δικτύωσης VM"
    Ο πλήρης οδηγός βήμα προς βήμα (ενεργοποίηση SSH, μόνιμη εξουσιοδότηση κλειδιού, δρομολόγηση σε προσαρμοσμένα δίκτυα και VLAN, μέθοδος ανά VM και αντιμετώπιση προβλημάτων στο μέρος του host) είναι ο [οδηγός αντιγράφων VM](vm-backup-ssh-setup.md).

## Ρύθμιση εκτός τόπου {#off-site-setup}

Τα αντίγραφα εκτός τόπου πηγαίνουν σε **προορισμούς αποθήκευσης**. Ανοίξτε τους **Προορισμούς** από το πλακίδιο ρυθμίσεών τους (ή καρφιτσώστε τους στην πλαϊνή μπάρα) και επιλέξτε **Προσθήκη προορισμού**. Δείτε [Εκτός τόπου και ανάκτηση](offsite-recovery.md) για την πλήρη ροή (προστασία από διαγραφή, δοκιμές παραβίασης και ασκήσεις DR). Με δύο λόγια:

- **Backends:** SMB/CIFS και WebDAV μέσω rclone χωρίς mount στον host, NFS (προσαρτήστε την εξαγωγή στον host και χρησιμοποιήστε την ως τοπικό φάκελο), εγγενή backends του restic χωρίς rclone (`s3:...`, `rest:http://host:8000/repo`, `sftp:user@host:/repo`), ή οποιοδήποτε remote του rclone (`rclone:<remote>:<bucket>/path`). Το Backblaze B2 δεν έχει εγγενές backend εδώ: φτάστε το μέσω του endpoint S3 (`s3:https://s3.<region>.backblazeb2.com/<bucket>/<path>`) με το key ID και το application key ως διαπιστευτήρια S3.
- Τα **Διαπιστευτήρια** αποθηκεύονται κρυπτογραφημένα, ως μία λίστα αποθηκευμένων διαπιστευτηρίων στην κάρτα **Διαπιστευτήρια** κάτω από τις **Ρυθμίσεις, Προορισμοί**. Ένα αστέρι σημαδεύει την προεπιλογή, που χρησιμοποιείται όπου δεν έχει επιλεγεί διαπιστευτήριο. Η σελίδα ενός προορισμού διαλέγει εκείνο που χρησιμοποιεί στην κάρτα **Διαπιστευτήρια**. Δείτε [Διαπιστευτήρια](offsite-recovery.md#sign-ins).
- **Οι προορισμοί SSH δεν χρειάζονται τίποτα εγκατεστημένο στην άλλη πλευρά.** Το `sftp:` χρειάζεται μόνο έναν διακομιστή SSH. Προσθέστε το δημόσιο κλειδί από τις **Ρυθμίσεις, Ενσωματώσεις, SSH κεντρικού συστήματος** (επίσης στο `/config/ssh/id_ed25519.pub`) στο `~/.ssh/authorized_keys` του χρήστη προορισμού, ή αφήστε την **Προσθήκη κλειδιού** στην **Προσθήκη προορισμού** να το βάλει εκεί με τον κωδικό του λογαριασμού.
- **rest-server με αυτο-υπογεγραμμένο πιστοποιητικό:** βάλτε το πιστοποιητικό του, ή εκείνο της αρχής που το υπέγραψε, ως αρχείο PEM στον φάκελο `certs` του φακέλου δεδομένων του BombVault (`/config/certs` μέσα στο κοντέινερ, `appdata/bombvault/certs` στο Unraid). Τα αντίγραφα, τα αντίγραφα εκτός τόπου και η δοκιμή προστασίας από διαγραφή το εμπιστεύονται χωρίς επανεκκίνηση.
- **Αντίγραφο εκτός τόπου:** το BombVault αντιγράφει νέα στιγμιότυπα με `restic copy` με βάση την καλύτερη προσπάθεια, πάνω από ένα (συνήθως τοπικό) πρωτεύον. Η κάρτα **Αντιγραφή** ενός προορισμού ορίζει αν αντιγράφει **Μετά από κάθε αντίγραφο ασφαλείας** ή με δικό του χρονοδιάγραμμα, και τα **Αντίγραφα εκτός τόπου ανά τομέα** στις **Ρυθμίσεις, Προγραμματισμοί** δίνουν σε έναν τομέα δικό του χρονοδιάγραμμα αντιγραφής. Η **Αναπαραγωγή τώρα** βρίσκεται στη γραμμή του τομέα στην κάρτα **Αντίγραφα εκτός τόπου** κάτω από τις **Ρυθμίσεις, Προορισμοί**.
- **Πολλοί προορισμοί αποθήκευσης ανά τομέα:** η κάρτα **Προορισμοί ανά τομέα** στη σελίδα Προορισμοί ενεργοποιεί ή απενεργοποιεί με ένα κλικ κάθε γραμμή από έναν τομέα σε έναν προορισμό, και το **Τοπικό** μαζί. Ένας τομέας μόνο με προορισμούς εκτός τόπου αντιγράφει κατευθείαν σε αυτούς, και ένας με κάθε γραμμή απενεργοποιημένη δεν αντιγράφεται. Οι **Κανόνες ανά τομέα** ενός προορισμού δίνουν σε έναν τομέα δικό του αποθετήριο, δική του διατήρηση ή συμπίεση εκεί.
- **Τοποθέτηση ανά στοιχείο:** κάθε κοντέινερ, VM και σύνολο φακέλων ανάβει το **Τοπικό** και τους προορισμούς που παίρνουν τα αντίγραφά του, στην κάρτα **Χρονοδιάγραμμα και προορισμός** στην καρτέλα Ρυθμίσεων. Τα στοιχεία χωρίς δική τους επιλογή ακολουθούν τον τομέα τους. Δείτε [Τοποθέτηση ανά στοιχείο](offsite-recovery.md#placement).
- **Διατήρηση:** κάθε προορισμός αποθήκευσης κρατά τα αντίγραφα σύμφωνα με την κάρτα **Πόσο διατηρείται**, και ένας τομέας μπορεί να κρατά εκεί δικές του τιμές στους **Κανόνες ανά τομέα**. Αυτό περιλαμβάνει το αντίγραφο στο πεδίο εκτός τόπου ενός τομέα. Όλα στο μηδέν δεν κλαδεύει ποτέ τα στιγμιότυπα ενός προορισμού.
- **Όρια εύρους ζώνης:** περιορίστε τον ρυθμό αποστολής/λήψης του restic στην κάρτα **Εύρος ζώνης εκτός τόπου** κάτω από τις **Ρυθμίσεις, Προορισμοί**, ή ανά προορισμό στην κάρτα **Αντιγραφή** του. Εισάγετε KiB/s, και το πεδίο δείχνει τον ίδιο ρυθμό σε MB/s και Mbit/s.
- **Πρώτα το streaming:** στην κάρτα **Streaming** στη σελίδα Προορισμοί, διαλέξτε τους media servers (το Plex, το Jellyfin και το Emby είναι προεπιλεγμένα με βάση το όνομα του image), τον ρυθμό αποστολής από τον οποίο μετράει ως streaming, το όριο αποστολής όσο γίνεται streaming και πόσο μετά από ένα stream επιστρέφει το κανονικό όριο.
- **Ψυχρή κλάση αποθήκευσης και αρχειοθέτησης (S3):** για έναν προορισμό S3, διαλέξτε μια βαθμίδα από την οποία μπορεί να γίνει επαναφορά (Standard, Standard-IA, One Zone-IA, Intelligent-Tiering, Glacier Instant Retrieval) στη σελίδα του. Τα remotes του rclone ορίζουν την κλάση τους στη διαμόρφωση του rclone.
- **Δικός φάκελος σε προορισμό αποθήκευσης αντί για τοπικό:** ο δικός φάκελος ενός τομέα μπορεί να βρίσκεται σε έναν από τους παραπάνω προορισμούς αποθήκευσης, χωρίς τοπικό αντίγραφο και χωρίς βήμα αντιγραφής. Δείτε [Ο δικός φάκελος ενός τομέα](offsite-recovery.md#own-folder).

## Ανωμαλίες {#anomalies}

Ο εντοπισμός ανωμαλιών δεν χρειάζεται καμία μεταβλητή περιβάλλοντος. Ρυθμίζεται στην κάρτα **Ανωμαλίες** κάτω από τις **Ρυθμίσεις, Επαλήθευση**, όπως περιγράφεται στις [Ανωμαλίες](anomalies.md#settings).

## Φορητές ρυθμίσεις (εξαγωγή και εισαγωγή) {#portable-settings-export-and-import}

Η κάρτα **Εξαγωγή / εισαγωγή ρυθμίσεων** κάτω από τις **Ρυθμίσεις, Σύστημα** γράφει ολόκληρη τη διαμόρφωση του BombVault (ρυθμίσεις τομέων, προορισμούς αποθήκευσης, χρονοδιαγράμματα, διατήρηση, ειδοποιήσεις) σε ένα φορητό αρχείο JSON που μπορείτε να εισαγάγετε σε άλλο στιγμιότυπο, ώστε η μετακόμιση σε νέο μηχάνημα ή η κλωνοποίηση μιας εγκατάστασης να μη σημαίνει ξαναπληκτρολόγηση των πάντων. Η εισαγωγή δείχνει προεπισκόπηση και ζητά επιβεβαίωση, και δεν αγγίζει ποτέ τα δεδομένα ή το ιστορικό των αντιγράφων σας. Οι σύνδεσμοι στο αρχείο προς προορισμούς αποθήκευσης ή αποθετήρια που δεν υπάρχουν πια παραλείπονται, και η προεπισκόπηση τους ονομάζει. Όσο τρέχει μια ρεπλίκα ZFS, μια εισαγωγή απορρίπτεται πριν γραφτεί οτιδήποτε.

!!! warning "Η εξαγωγή μπορεί να περιέχει διαπιστευτήρια"
    Εσείς επιλέγετε αν θα συμπεριλάβετε στο αρχείο τα διαπιστευτήρια εκτός τόπου, ειδοποιήσεων και του broker MQTT. Με συμπεριλαμβανόμενα διαπιστευτήρια, η εξαγωγή είναι εξίσου ευαίσθητη με το κιτ ανάκτησης, οπότε φυλάξτε την κάπου ασφαλές. Χωρίς αυτά, το αρχείο κρατά μόνο μη μυστικές ρυθμίσεις.
