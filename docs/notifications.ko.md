# 알림

BombVault는 백업이 실패했을 때, 성공했을 때, 기한을 넘겼을 때, 그리고 일주일에 한 번 전체 현황을 알려 줄 수 있습니다. 모든 설정은 **설정, 알림**에 있습니다. 개별 백업 말고 BombVault가 무엇을 더 보낼지는 **알림** 카드, 메시지를 어디로 보낼지는 **채널** 카드에서 정합니다. 언제 알릴지는 채널마다 따로 정하며, Healthchecks 체크도 채널 중 하나입니다.

![설정, 알림 화면에 Gotify 채널을 입력한 모습.](assets/screenshots/notifications/gotify-dark.png#only-dark)
![설정, 알림 화면에 Gotify 채널을 입력한 모습.](assets/screenshots/notifications/gotify-light.png#only-light)

## 메시지를 보내는 조건 {#what}

**알림** 카드의 스위치는 모든 채널에 적용됩니다.

- **예약 실행 요약**: 컨테이너나 VM마다 메시지를 하나씩 보내는 대신, 예약 실행 한 번에 메시지 하나를 보냅니다. 예를 들어 *45개 중 42개 성공*처럼요. 직접 시작한 백업은 여전히 자기 메시지를 따로 보냅니다. 멈춘 게스트, 실패한 보존 정리, 넘어선 증가 예산은 요약을 켜 두어도 바로 전달됩니다.
- **컨테이너 업데이트 시 알림**: **백업 성공 후 컨테이너 업데이트**로 더 새로운 이미지로 올라간 컨테이너마다 메시지를 하나씩 보내서, 여전히 잘 동작하는지 확인할 수 있게 합니다.
- **지연된 백업 보고**: 매일 09:00에 BombVault가 켜져 있는 백업 중 기한을 넘긴 것이 있는지 확인합니다. 일정 주기의 두 배보다 오래되면 기한을 넘긴 것이며, 해당하는 건마다 뒤처진 항목의 이름을 담아 메시지를 하나씩 보냅니다. 다음 백업이 성공하면 해소됩니다.
- **주간 요약**: 일주일에 한 번, 실행 횟수, 새로 생긴 백업 데이터, 기한을 넘긴 섹션, 오프사이트 사본이 최신인지, 가장 많이 실패한 항목을 요약해서 보냅니다. 이 계획도 다른 계획처럼 버튼으로 고르며, **끄기**를 고르면 꺼집니다. [일정](schedules.md#plans)을 참고하세요.

성공도 알릴지는 채널마다 **알림**에서 정합니다. 어떤 이상 징후가 메시지를 보낼지는 **설정, 검증**에서 정합니다. [이상 징후](anomalies.md)를 참고하세요. 미뤄진 백업은 기다리기 시작할 때 한 번, 기다림이 끝날 때 한 번 메시지를 보내며, 재시도할 때마다 보내지는 않습니다.

## 채널 {#channels}

**채널** 카드 아래쪽의 **채널 추가**에서 **Unraid 알림**, **ntfy**, **Gotify**, **Discord**, **Slack**, **Matrix**, **이메일 (SMTP)**, **Apprise**, **Webhook**, **Healthchecks**를 고를 수 있습니다. 원하는 만큼 추가할 수 있고, 같은 종류를 두 개 둘 수도 있습니다. 예를 들어 실패용 ntfy 토픽과 모든 알림용 토픽을 따로 둘 수 있습니다. 새 채널은 꺼진 채로 시작하므로, 입력란을 채우기 전에도 저장됩니다.

모든 채널에는 다음이 있습니다.

- 자기 스위치. 꺼도 입력해 둔 값은 그대로 남습니다.
- **알림**: **안 함**, **실패 시에만**, **성공 및 실패 시** 중에서 고릅니다. 새 채널은 **실패 시에만**으로 시작합니다. 성공했지만 일부를 빠뜨린 백업도 실패만 받는 채널로 전달됩니다.
- **이름**: 선택 사항이며, 종류 대신 표시됩니다. 같은 종류가 두 개 있을 때 편리합니다.
- **테스트 보내기**: 저장했든 안 했든 양식에 지금 들어 있는 값 그대로, 이 채널로 테스트 메시지를 보냅니다. 채널 아래의 줄에 서비스가 받았는지, 받지 않았다면 왜인지 표시됩니다.
- **채널 삭제**: 옆에 있는 휴지통입니다.

채널마다 따로, 각자의 제한 시간으로 보내므로 응답하지 않는 호스트 하나가 다른 채널을 붙잡지 않습니다. 다시 시도하면 해결될 수 있는 오류라면 채널이 최대 세 번까지 시도합니다. 어느 채널도 받지 못한 기한 초과, 예산, 이상 징후 알림은 나중에 다시 시도하며, 주간 요약도 마찬가지입니다.

| 채널 | 입력란 | 참고 |
|---|---|---|
| **Unraid 알림** | 없음 | Unraid 자체 알림 시스템으로 보내며, 거기서 Pushover, 이메일, Discord 등으로 전달할 수 있습니다. **설정, 연동, 호스트 SSH**의 SSH 연결을 통해 실행되므로 그 키가 승인되어 있어야 합니다. TrueNAS나 다른 호스트에서는 아무것도 보내지 않으며, 채널에 그 이유가 표시됩니다. |
| **ntfy** | **토픽 URL**, **액세스 토큰(선택)** | 주소는 토픽 이름으로 끝납니다. 토큰은 보호된 토픽에만 필요합니다. |
| **Gotify** | **서버 URL**, **앱 토큰**, **실패 시 우선순위**, **성공 시 우선순위** | 우선순위는 0부터 10까지이며, 기본값은 실패 8, 성공 5입니다. |
| **Discord** | **Webhook URL** | Discord 채널 설정에서 만든 webhook의 주소입니다. |
| **Slack** | **Webhook URL** | Slack 앱의 수신 webhook 주소입니다. |
| **Matrix** | **Homeserver URL**, **액세스 토큰**, **방 ID** | 토큰의 계정이 그 방에 들어가 있어야 합니다. |
| **이메일 (SMTP)** | **SMTP 호스트**, **포트**, **암호화**, **사용자 이름**, **비밀번호**, **보내는 주소**, **받는 주소** | **암호화**는 **STARTTLS**, **TLS (implicit)**, **None** 중에서 고릅니다. |
| **Apprise** | **Apprise API URL**, **태그(선택 사항)**, **Apprise 주소(선택)** | Apprise API 컨테이너의 `/notify/<key>` 엔드포인트를 지정하면 100개가 넘는 서비스로 보낼 수 있으며, 태그로 그 키 대상 중 일부만 고를 수 있습니다. 아니면 Apprise 주소를 한 줄에 하나씩 적고, API URL은 키 없이 `/notify`로 끝냅니다. 예를 들어 Telegram은 `tgram://`, Pushover는 `pover://`입니다. |
| **Webhook** | **Webhook URL**, **메서드**, **헤더**, **본문** | 직접 구성하는 요청입니다. [Webhook](#webhook)을 참고하세요. |
| **Healthchecks** | **ping URL** | [Healthchecks](#healthchecks)를 참고하세요. |

토큰, SMTP 비밀번호, webhook 헤더 값 같은 비밀 값은 암호화되어 저장되며, 서버는 이 값을 페이지로 돌려주지 않습니다. 저장된 비밀 값 아래에는 **저장됨. 그대로 두려면 칸을 비워 두세요.**라고 표시됩니다. 채널이 보내는 곳을 바꾸면 BombVault는 예전 비밀 값을 새 주소로 보내지 않습니다. 입력란에 **이 항목을 다시 입력하면 새 주소가 저장됩니다.**라고 표시됩니다.

채널 목록 이전 버전의 설정은 처음 시작할 때 그대로 넘어오며, 잃는 것은 없습니다. 채워 두었던 채널은 각각 별도의 항목이 되고, 예전에 고른 **알림** 값도 그대로 유지됩니다. Discord, Slack, Gotify, ntfy 형식의 webhook은 해당 종류의 채널이 되고, Generic JSON webhook은 **본문**을 통해 계속 `title`, `message`, `ok`를 보냅니다. Unraid 스위치는 Unraid 채널이, Healthchecks URL과 그 예외는 Healthchecks 채널이 됩니다.

### Webhook {#webhook}

**Webhook** 채널은 원하는 주소로 HTTP 요청을 하나 보냅니다. **메서드**는 GET, POST, PUT 중 하나입니다. **헤더 추가**를 누르면 **헤더**에 줄이 하나 생기며, 헤더 값은 비밀 값으로 보관되므로 `Authorization` 헤더를 넣어도 안전합니다. **본문**은 적은 그대로 보내며, 다음 자리표시자는 값으로 바뀝니다.

| 자리표시자 | 바뀌는 값 |
|---|---|
| `%%title%%` | 메시지 제목 |
| `%%body%%` | 메시지 내용 |
| `%%ok%%` | `true`, 실패면 `false` |
| `%%event%%` | 무슨 일이 있었는지, 예를 들어 `container.failed` |
| `%%severity%%` | `info`, `success`, `warning`, `failure`, `critical` |
| `%%importance%%` | 이에 해당하는 Unraid 수준: `normal`, `warning`, `alert` |
| `%%link%%` | 메시지와 관련된 링크, 없으면 빈 값 |
| `%%key%%` | 섹션, 예를 들어 `container`나 `VM` |
| `%%time%%` | UTC 시각, 예를 들어 `2026-11-09T03:00:00Z` |
| `%%source%%` | `BombVault` |

자리표시자는 주소와 헤더 값에서도 쓸 수 있으며, 각 값은 놓인 자리에 맞게 이스케이프됩니다. `Content-Type` 헤더가 JSON이면 JSON으로, 주소 안에서는 쿼리 값으로 처리됩니다. 새 webhook은 이 헤더를 갖춘 채로 시작하며 `{"title":"%%title%%","message":"%%body%%","ok":%%ok%%}`를 보냅니다. BombVault가 모르는 이름은 적은 그대로 남으므로, 오타는 메시지에서 바로 보입니다. 아무것도 보내지 않으려면 **본문**을 비워 두세요.

## Healthchecks {#healthchecks}

[Healthchecks.io](https://healthchecks.io) 같은 서비스는 BombVault가 신호를 보내지 않으면 알람을 울립니다. **Healthchecks** 채널을 추가하고 체크의 **ping URL**을 붙여 넣으면 BombVault는 모든 백업의 수명 주기 동안, 즉 시작할 때와 성공할 때, 또는 `/fail`로 실패할 때 그 주소에 ping을 보냅니다. 이 채널에는 **알림** 선택이 없습니다. 체크가 녹색으로 남으려면 성공 ping이 꼭 필요하기 때문입니다. 백업할 곳이 없는 섹션은 실패로 치므로, 그 체크는 성공 신호 대신 빨간색이 됩니다.

같은 URL을 쓰는 섹션은 체크 하나를 함께 씁니다. 그중 하나의 백업이 실패하면 다른 섹션의 정상 백업도 `/fail`로 ping을 보내며 실패한 섹션의 이름을 알리므로, 그 항목에 다시 정상 백업이 생기거나 **조치 필요**에서 실패를 확인할 때까지 체크는 빨간색으로 남습니다.

섹션마다 고유한 주소로 ping을 보낼 수도 있습니다. Healthchecks 채널에서 **예외**를 누르면 하나가 추가되며, 그 줄에는 **나머지 모든 섹션이 이 URL로 ping을 보냅니다.**라고 표시됩니다. **테스트 보내기**는 각 체크의 로그에 항목을 하나 남기며, 상태는 그대로입니다.

## 예제: 휴대폰의 Gotify {#example-gotify}

`https://gotify.example.com`에서 Gotify를 운영하고 있고, 실패는 휴대폰에서 소리로 알리고 성공은 조용히 받고 싶다고 해 봅시다.

1. Gotify에서 **Apps**를 열고 `BombVault`라는 애플리케이션을 만든 다음 토큰을 복사합니다.
2. BombVault에서 **설정, 알림**을 열고 **예약 실행 요약**을 켭니다. 그러면 백업 45개가 도는 밤에도 메시지가 45개가 아니라 하나만 옵니다.
3. **채널**에서 **채널 추가**를 누르고 **Gotify**를 고릅니다.
4. **서버 URL**에 `https://gotify.example.com`을 입력합니다. `/message`는 BombVault가 알아서 붙입니다.
5. **앱 토큰**에 토큰을 붙여 넣습니다.
6. **알림**을 **성공 및 실패 시**로 둡니다. **실패 시 우선순위**는 8, **성공 시 우선순위**는 5로 그대로 둡니다. Gotify의 Android 앱은 8 이상을 높음으로 처리하므로 실패만 소리가 납니다.
7. 채널을 켜고 **테스트 보내기**를 누릅니다. 채널 아래의 줄에 Gotify가 받았는지 표시되며, 토큰이 거부되면 그렇게 알려 줍니다.

다음 예약 실행부터는 요약 메시지 하나가 우선순위 5로 오고, 그 안에 실패가 있으면 우선순위 8로 옵니다.

## 예제: 계정 없이 쓰는 ntfy {#example-ntfy}

공개 토픽에는 ntfy 계정이 필요 없습니다. 토픽 이름을 알면 누구나 읽을 수 있으니, 추측하기 어려운 이름을 고르세요.

1. **채널**에서 **채널 추가**를 누르고 **ntfy**를 고릅니다.
2. **토픽 URL**에 토픽 주소를 입력합니다. 예를 들면 `https://ntfy.sh/bombvault-tower-7f3k`이며, 직접 운영하는 ntfy 서버의 토픽이어도 됩니다. 공개 토픽이라면 **액세스 토큰(선택)** 칸은 비워 둡니다.
3. ntfy 앱에서 같은 토픽을 구독하고, 채널을 켠 다음 **테스트 보내기**를 누릅니다.

BombVault는 메시지를 본문으로 보내고 제목은 `Title` 헤더에 넣습니다. 실패는 우선순위 높음과 `warning` 태그로 나가서 앱에서 눈에 띄며, 멈춘 채로 남은 VM은 긴급으로 나갑니다.
