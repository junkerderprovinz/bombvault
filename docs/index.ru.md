# BombVault

**Ваши данные Unraid, запечатанные в хранилище. Сделайте копию. Взорвите восстановление.**

![Обзор: строка состояния, то, что требует внимания, защита каждого раздела, места назначения и история.](assets/screenshots/overview/home-dark.png#only-dark)
![Обзор: строка состояния, то, что требует внимания, защита каждого раздела, места назначения и история.](assets/screenshots/overview/home-light.png#only-light)

BombVault — самостоятельно размещаемое веб-приложение для **резервного копирования и полного аварийного восстановления** на Unraid и других хостах Docker, таких как TrueNAS SCALE, ZimaOS или обычный Linux. Оно копирует контейнеры Docker, виртуальные машины KVM/libvirt, папки, наборы данных ZFS и флешку Unraid. Оно работает как один многоархитектурный контейнер Docker, даёт веб-интерфейс в тёмной, светлой или системной теме и ведёт весь жизненный цикл: копирование, расписание, проверка и восстановление.

Восстановление автоматическое. В Unraid контейнеры снова появляются на вкладке Docker в точности как раньше, а виртуальные машины заново определяются в VM Manager с подключёнными дисками и UEFI NVRAM. Без ручной переустановки, без перенастройки, без драмы. В TrueNAS контейнер, восстановленный рядом с оригиналом, работает как обычный контейнер Docker, которого экран Apps не показывает.

Работает на [restic](https://restic.net), поэтому каждая копия дедуплицирована, инкрементна и по умолчанию зашифрована.

!!! note "Берегите свой APP_KEY"
    BombVault выводит пароль репозитория restic из 32-байтового секрета `APP_KEY`. Если потерять его вместе с набором для восстановления, зашифрованные копии нельзя будет восстановить. Сгенерируйте ключ командой `openssl rand -hex 32` и сохраните его в надёжном месте. См. [Конфигурация](configuration.md).

## Что защищает BombVault {#what-bombvault-protects}

Каждый контейнер, каждая виртуальная машина, набор папок, флешка, каждый набор данных ZFS и собственные настройки BombVault — это **запись** со своей страницей. Записи одного вида образуют **раздел**, который включается в **Настройки, Общие**.

| Раздел | Что сохраняется |
|---|---|
| **Контейнеры** | Каталог appdata и определение контейнера (образ, переменные окружения, порты, метки, тома). |
| **Виртуальные машины** | Образ(ы) диска, определение XML и UEFI NVRAM, копируются по SSH (без монтирования libvirt). |
| **Flash** | Вся USB-флешка (`/boot`): ОС, лицензия, конфигурация массива, общие ресурсы, сеть и конфигурация плагинов. |
| **Автобэкап** | Собственный `/config` BombVault: база данных настроек, учётные данные мест назначения и пара SSH-ключей libvirt. |
| **Папки** | Любая папка на сервере как набор папок, у каждого необязательные шаблоны исключений. |
| **Наборы данных ZFS** | Набор данных вместе с каждым набором под ним, прочитанный из одного снимка ZFS и сохранённый как папка. См. [Наборы данных ZFS](zfs-datasets.md). |

## Восстановление — главное {#restore-is-the-star}

После копирования данных обратно из снимка restic BombVault воспроизводит сохранённое определение контейнера через API Docker, так что контейнер появляется на вкладке Docker в Unraid так, будто был там всегда (тот же образ, те же настройки, те же сопоставления портов). Виртуальные машины получают XML заново по SSH, а их диски и UEFI NVRAM подключаются снова, даже если виртуальную машину удалили.

Одно окно восстанавливает любой вид. По умолчанию оно выбирает **Рядом с оригиналом**, что возвращает копию как отдельный экземпляр и оставляет оригинал как есть. **Заменить оригинал** сначала копирует текущее состояние, так что восстановление можно отменить. Другие цели — папка или новый набор данных ZFS.

Когда копия останавливает зависимые контейнеры, они возвращаются в правильном порядке: BombVault запускает их в порядке `depends_on` из Compose и ждёт, пока каждый сообщит, что здоров, прежде чем запускать зависящие от него, так что ничто не забегает вперёд базы данных или шлюза, которые ещё не работают. См. [Восстановление](restore.md) и [Команды и другие контейнеры](backups.md#commands).

## Как это работает {#how-it-works}

```
Browser --HTTPS--> BombVault container
                   |- Go binary: JSON API + embedded React UI
                   |- Background worker (per-section scheduler + job executor)
                   |
                   |- /var/run/docker.sock  -> Docker API (container stop/inspect/recreate)
                   |- qemu+ssh://host       -> libvirt / KVM on the HOST over SSH (no mount)
                   |- /mnt/ -> /host/user   -> appdata, VM disks + restic repos (read/write)
                   |- /boot/ -> /host/boot  -> Unraid flash backup (whole USB)
                   |- /config               -> BombVault's own settings + sign-ins (self-backup)
                   '- <repo path>           -> restic repository (local or remote: rclone/s3/rest/sftp)
```

BombVault использует сокет Docker, чтобы останавливать контейнеры перед копией и пересоздавать их после восстановления. Для виртуальных машин он запускает `virsh` на хосте по SSH (`qemu+ssh://`), чтобы корректно выключить домен или сделать живой снимок. Он никогда не монтирует путь libvirt, поэтому не может помешать VM Manager на хосте.

BombVault — слой оркестрации и интерфейса, а не движок хранения. Всё реальное перемещение данных идёт через restic.

## Быстрый старт {#quick-start}

Вы здесь впервые? Перейдите к **[Начало работы](getting-started.md)**, чтобы установить BombVault и сделать первую копию, а затем настройте **[Внешние копии и восстановление](offsite-recovery.md)**. **[Примеры по шагам](guides.md)** проводят через частые задачи от начала до конца, страница **[Настройки](settings.md)** перечисляет каждую плитку, а **[Возможности](features.md)** — краткий каталог всего, что умеет BombVault.

Каждый раздел может копировать в несколько мест назначения сразу, сопряжённый BombVault может хранить ваши внешние копии на сервере, который отказывает в удалении, а **Аварийный мастер** возвращает утраченный сервер из набора для восстановления, через вашу группу или с введённым ключом. Чтобы перенести конфигурацию на новый сервер, воспользуйтесь карточкой **Экспорт / импорт настроек**. См. [Внешние копии и восстановление](offsite-recovery.md) и [Конфигурация](configuration.md#portable-settings-export-and-import).

**[Приложение для Android](android.md)** собирает все серверы вашей группы на телефоне с журналом активности всех сразу на одном экране.

Документация доступна на 26 языках, а интерфейс на 42. Страницы, у которых ещё нет перевода, показываются на английском.

## Слова, которые здесь используются {#glossary}

У нескольких слов в BombVault и на этих страницах закреплённое значение.

| Слово | Значение |
|---|---|
| **Запись** | Одна вещь, которую копирует BombVault: контейнер, виртуальная машина, набор папок, флешка, набор данных ZFS с теми, что под ним, или его собственные настройки. У каждой своя страница. |
| **Раздел** | Все записи одного вида, например «Контейнеры». Разделы включаются в **Настройки, Общие**. |
| **Место назначения** | Место, куда идут копии: папка на этом сервере, общий ресурс, ваш собственный сервер или облачная служба. См. [Места назначения](offsite-recovery.md#destinations). |
| **Локально** | Место назначения на этом сервере, где лежат папки разделов. |
| **Собственная папка** | Репозиторий, в который раздел пишет свои копии в первую очередь. По умолчанию он на этом сервере и может лежать в месте назначения. См. [Собственная папка раздела](offsite-recovery.md#own-folder). |
| **Копия** | Резервная копия, скопированная из собственной папки в другое место назначения через `restic copy`. |
| **Прямой репозиторий** | Репозиторий во внешнем месте, в который записи копируют напрямую, без локальной копии между ними. См. [Прямые репозитории](offsite-recovery.md#direct-repositories). |
| **Учётные данные** | Сохранённый ключ или пароль для службы S3 или rest-server. Одни из них — по умолчанию. См. [Учётные данные](offsite-recovery.md#sign-ins). |
| **Размещение** | В какие места назначения идут копии записи, задаётся на самой записи или как значение по умолчанию её раздела. См. [Размещение для отдельной записи](offsite-recovery.md#placement). |
| **Реплика** | Точная до блоков копия записи ZFS на втором сервере ZFS, сделанная через `zfs send`. Она стоит рядом с копией и не заменяет её. См. [Реплика](zfs-datasets.md#replica). |
| **Роль** | То, что один экземпляр вашей группы делает для другого: Приёмник, Подтягивающий, Сервер ZFS или Хранитель ключа. См. [Экземпляры и роли](offsite-recovery.md#roles). |

!!! warning "Управление хостом на уровне root"
    Через сокет Docker BombVault может останавливать, удалять и пересоздавать контейнеры и читать и записывать appdata, а для копий виртуальных машин он входит на хост по SSH, чтобы запускать `virsh`. Любой, кто может достучаться до его веб-интерфейса, фактически получает root на хосте. Запускайте BombVault только в доверенной сети, недоступной снаружи, и задайте пароль для входа в **Настройки, Безопасность**. Для набора для восстановления, передачи ключей на хранение и удаления копий в месте назначения он обязателен. Полную модель безопасности см. в разделе [Конфигурация](configuration.md#security-model).
