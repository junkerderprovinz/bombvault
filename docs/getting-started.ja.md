# はじめに

このページでは、まっさらな Unraid マシンから最初のバックアップまでを案内します。

## 要件

| 要件 | 備考 |
|---|---|
| **Unraid 6.12 以上** | それより古いバージョンはテストされていません。Unraid が主な対象ですが、BombVault は通常の Docker ホストや TrueNAS Scale でも動きます（[一般的な Docker ホスト](#generic-docker-host)と [TrueNAS SCALE](#truenas) を参照）。 |
| **restic リポジトリの場所** | ローカルパス（推奨: アレイまたはキャッシュ）、SMB、NFS、または任意の rclone バックエンド。 |
| **Docker ソケット** | テンプレートによって自動的にマウントされます（`/var/run/docker.sock`）。 |
| **Unraid フラッシュ**（`/boot`） | テンプレートによって全体が自動的にマウントされます（`/boot` を `/host/boot` へ）。フラッシュバックアップを支え、復元されたコンテナが通常の編集可能な Unraid アプリとして再び現れるようにします。 |
| **KVM VM**（オプトイン） | VM バックアップは SSH 経由で libvirt と通信し、libvirt のマウントは不要です。**設定、連携、ホスト SSH** で構成します（[設定](configuration.md)を参照）。 |
| **ZFS データセット**（オプトイン） | VM バックアップと同じ SSH 接続、ホスト上の `zfs`、そしてアクセスモード Read/Write - Slave で `/mnt` にマッピングした Host Data（テンプレートの既定値）が必要です。[ZFS データセット](zfs-datasets.md)を参照してください。 |
| **Android アプリ**（任意） | Android 10 以降で、ペアリングするサーバーはバージョン 9.7.0 以降が必要です。[Android アプリ](android.md)を参照してください。 |

## Unraid へのインストール

最も簡単な方法は **Community Applications** です。

1. Unraid の **Apps** タブを開きます。
2. **BombVault** を検索します。
3. **Install** をクリックし、必要な変数（下記）を設定して適用します。

!!! tip "テンプレートの手動インストール"
    テンプレートを手動で追加したい場合は:

    1. **Docker, Add Container, Template repositories** に移動して、以下を追加します:
       ```
       https://github.com/junkerderprovinz/unraid-apps
       ```
    2. Templates で **BombVault** を検索します。
    3. 必要な変数を設定して **Apply** をクリックします。

## 一般的な Docker ホスト {#generic-docker-host}

Unraid ではない場合。BombVault はどの Docker ホストでも通常のコンテナとして動きます。TrueNAS SCALE には [TrueNAS SCALE](#truenas) に専用の手順があります。

1. リポジトリからそのまま編集できる [`deploy/docker-compose.generic.yml`](https://github.com/junkerderprovinz/bombvault/blob/main/deploy/docker-compose.generic.yml) を取得します。
2. `APP_KEY`（下記参照）を設定し、Host Data ボリュームを実際のデータルートに向けます。どちらもファイル内のコメントが案内します。
3. `docker compose up -d` を実行し、`https://<host-ip>:3443/` を開きます。

Unraid との違い:

- **フラッシュセクションがありません。** 取り込んだり復元したりする起動 USB が存在しないため、フラッシュセクションはここでは出番がありません。代わりに、Host Data がホストの `/etc` まで届く場合、バックアップページの **追加** が **システム構成** をフォルダーの候補として提示します。保存前に確認して編集する `/etc` のフォルダーセットの初期案です。
- **Unraid 独自の通知がありません。** BombVault 自身の通知チャネル（Webhook、オフサイト失敗の警告など）は通常どおり動きます。省かれるのは Unraid 固有の通知システムへの送信だけで、ここにはその仕組みがないからです。
- **VM のバックアップは任意で、SSH で届く別の libvirtd ホストが必要です。** compose ファイル内のコメントアウトされたブロックを参照してください。一般的な Docker ホスト自体には VM 管理機能はありません。
- **ダッシュボードウィジェットがありません。** BombVault Widget は Unraid のプラグインなので、その手順も省かれます。
- **コンテナのデータの見つけ方。** Unraid の `appdata` の慣習がないため、コンテナのデータフォルダーは `DATA_ROOT_SEGMENTS` の区切り、Docker の名前付きボリューム、Compose プロジェクトの作業ディレクトリ、`bombvault.data` ラベルから見つけます（[バックアップ元の自動判定](configuration.md#backup-source-detection)を参照）。名前付きボリュームと `/etc` プリセットが届くのは Host Data マウント内のパスだけなので、Host Data は Docker のデータルートも含む共通の上位ディレクトリに向けてください。
- **`PLATFORM`。** `generic` または `truenas` に設定します。未設定の場合、BombVault はフラッシュのマウントにある Unraid 独自の目印で Unraid を判別し、それ以外はすべて汎用として扱います。Unraid 専用の手順は、試して失敗する代わりに省かれます。

### TrueNAS SCALE {#truenas}

BombVault はまだ TrueNAS のアプリカタログにないため、カスタムアプリとしてインストールします。**Apps, Discover Apps** を開き、**Custom App** の横のメニューから **Install via YAML** を選びます。以下の YAML は、リポジトリの `truenas-apps` フォルダーにあるカタログエントリと同じ内容を設定します。`tank` を自分のプールに置き換え、`APP_KEY` は次の節の説明どおりに入力してください。

```yaml
services:
  bombvault:
    image: junkerderprovinz/bombvault:latest
    hostname: bombvault
    restart: unless-stopped
    cap_drop: [ALL]
    cap_add: [CHOWN, DAC_OVERRIDE, FOWNER, SETGID, SETPCAP, SETUID]
    environment:
      APP_KEY: ""
      PLATFORM: truenas
      HOST_SOURCE_ROOT: /mnt/tank
      HOST_MOUNT_ROOT: /mnt/tank
      # VM バックアップ用:
      # LIBVIRT_URI: qemu+ssh://root@<truenas-ip>/system?socket=/run/truenas_libvirt/libvirt-sock
    volumes:
      - /mnt/tank/apps/bombvault:/config
      - /var/run/docker.sock:/var/run/docker.sock
      - type: bind
        source: /mnt/tank
        target: /mnt/tank
        bind:
          propagation: rslave
    ports:
      - "30528:3443"
```

その後 `https://<truenas-ip>:30528/` を開きます。[Unraid との違い](#generic-docker-host)に挙げた点はここでも当てはまり、TrueNAS ではさらに次の点があります:

- **ケーパビリティ。** BombVault には上の 6 つが必要です。`SETPCAP` がないと VM バックアップは失敗します。
- **Host Data** はデータセット上のホストパス（ここでは `/mnt/tank`）で、アプリ内でも同じパスにマウントされます。そのため `HOST_SOURCE_ROOT` と `HOST_MOUNT_ROOT` の両方にこのパスを指定します。`rslave` はホストが後から行うマウントを渡し、ZFS データセットのバックアップにはこれが必要です。
- **ixVolume 内のデータはバックアップされません。** ストレージが ixVolume のアプリは、データを Host Data の外にある `/mnt/.ix-apps` の下に置きます。BombVault が保存するのはアプリの定義だけで、実行は対象外にしたフォルダーを示します。データをバックアップしたいアプリにはすべて、Host Data 配下のデータセット上の **Host Path** ストレージを選んでください。
- **VM と ZFS データセットのバックアップ** は、root として SSH で TrueNAS に接続します。**System, Services** で SSH サービスをオンにし、**設定、連携、ホスト SSH** の公開鍵を **Credentials, Users** で root ユーザーに追加してください。TrueNAS の libvirtd は独自のソケットで待ち受けるため、VM バックアップには上記の `LIBVIRT_URI` も必要です。`LIBVIRT_URI` も `LIBVIRT_HOST` も設定されていない場合、TrueNAS アプリでは `host.docker.internal` が名前解決できないため、BombVault はアプリのデフォルトゲートウェイをホストとして使います。zvol 上の VM も含めた詳細は [VM バックアップガイド](https://github.com/junkerderprovinz/bombvault/blob/main/docs/vm-backup-ssh-setup.md#truenas-scale)にあります。
- **ZFS レプリカは別の鍵を使います。** 2 台目の ZFS サーバー上のレプリカは、ホスト SSH の鍵ではなく、レプリカのダイアログに表示される鍵でログインします。その鍵を受け取り側のサーバーに追加してください。
- **削除したアプリは 2 段階で戻します。** まず TrueNAS で同じ名前のアプリを再インストールします。これでネットワークが再び作成されます。その後 BombVault でデータを復元します。それまでは復元前の確認がネットワークの欠落を報告し、復元は何かを変更する前に拒否されます。
- **元の隣に** は通常の Docker コンテナを作成します。動作はしますが、TrueNAS の Apps 画面には表示されません。
- **データベースダンプ** はデータセットのマウント上でも動きます。それ自体がデータセットであるデータフォルダーへの取り込みでは、古い内容が隣のフォルダーに移されるため、上位のデータセットにその分の空きが必要です。

## 必須設定はひとつだけ

設定が必須の変数は `APP_KEY` だけです。これは restic リポジトリのパスワードを導出するために使われる 32 バイトの 16 進シークレット（16 進数 64 文字）です。

任意のマシンで生成します:

```bash
openssl rand -hex 32
```

生成された結果をテンプレートの `APP_KEY` フィールド（Unraid）、または `docker-compose.yml` の環境変数 `APP_KEY`（汎用の Docker ホスト）に貼り付けます。

!!! danger "APP_KEY をなくさないでください"
    `APP_KEY` を失うと、暗号化されたバックアップは復元不能になります。サーバーとは別の安全な場所に保管してください。BombVault が起動したら、ログインパスワードを設定し、**設定、復元** で**リカバリーキット**をダウンロードしてください（[オフサイトと復旧](offsite-recovery.md#recovery-kit)を参照）。キー、すべての保存先、restic のコマンドが入っています。

テンプレートは Docker ソケット、フラッシュ（`/boot`）、そして **Host Data** ルート（`/mnt`）もマウントしてくれます。バックアップの*ソース*と*デスティネーション*はどちらも Host Data の配下に存在します。変数の完全なリファレンスとオフサイトのセットアップについては、[設定](configuration.md)を参照してください。

## 初回起動

![最初のバックアップ後の概要。対応が必要なこと、各セクションの保護状況、保存先、履歴。](assets/screenshots/dashboard.png)

*最初のバックアップ後の概要。対応が必要なこと、各セクションの保護状況、保存先、履歴。*

1. Web UI を `https://<your-unraid-ip>:3443` で開きます（デフォルトで自己署名証明書）。新規インストールは **BombVault へようこそ** が開き、BombVault がサーバーで見つけたものが一覧になります。
2. **始める** を選びます。概要に、3 つのステップを持つ **最初のステップ** カードが表示されます。
    1. **セクションを選ぶ**: BombVault がバックアップする対象をオンにします（コンテナ、VM、フラッシュ、フォルダー、ZFS データセット、セルフバックアップ）。**選ぶ** でそのセクションの項目の一覧が開き、**スケジュールを一時停止** で 1 つを外せます。ここでオンにしたセクションは毎晩実行されます。変更は **設定、スケジュール** で行います。
    2. **保存先を追加**: バックアップの送り先です。始めるにはローカルフォルダーで十分です。最も安全なのは、Storage Box や Backblaze B2 のような、拠点の外にある 2 つ目の保存先です。ローカルのリポジトリはデフォルトで `/mnt/user/bombvault/{container,vms,flash,config,files,zfs}` になり、初回バックアップ時に作成されます。
    3. **最初のバックアップ**: その後は毎晩自動で動きます。
3. **バックアップ** を開くと、すべての項目が 1 つの一覧に並びます。**今すぐすべてバックアップ** はオンにしたすべてのセクションの実行を開始し、項目のページの **今すぐバックアップ** はその 1 つだけをバックアップします。

以前に BombVault を使ったことがありますか。ようこそ画面の **バックアップから復元** を押すと復元ページが開き、**緊急ウィザード**が失ったサーバーの設定、コンテナ、VM、フォルダーを元に戻します。[オフサイトと復旧](offsite-recovery.md#emergency)を参照してください。

!!! tip "任意: バックアップ順序を決める"
    一部のコンテナを常に他のコンテナより先にバックアップしたい場合（たとえばデータベースをそれを使うアプリより先に）は、**設定、スケジュール** の**順序**カードを開き、希望する順序にドラッグします。以降、スケジュール実行と全体のバックアップはその順序に従います。順序を指定しなかったものは、最も期限超過のものから順にバックアップされます。

!!! note "ホスト統合チェック"
    概要の **ホスト統合** カードは、すべてのマウントと CLI（Docker ソケット、libvirt、restic、qemu-img、rclone）をプローブし、欠けている部分を報告します。これにより、コンテナに頼る前に、正しく配線されていることを確認できます。追加するまでは **カスタマイズ** の中に置かれています。

## 画面の見方 {#navigation}

![タイルで表示した設定と、選んだタイルのカード。変更はその場で書き込まれます。](assets/screenshots/settings.png)

*タイルで表示した設定と、選んだタイルのカード。変更はその場で書き込まれます。*

サイドバーの項目は 5 つです。**概要**、**異常**（異常検知がオンの間）、**バックアップ**、**復元**、そして **サインアウト** の下の **設定** です。ページの主な操作は右下に浮かび、まれな操作は **その他** にまとまっています。スマートフォンのバーには概要、バックアップ、復元、設定が並び、残りは **その他** にあります。

ページと設定はウィンドウの幅いっぱいに表示されます。ウィンドウはボタンを下部に並べ、先へ進むボタンは右に置かれます。スマートフォンでは、ボタンが 4 つ以上ある下部には、閉じるボタンと主な操作だけを残し、ほかは **その他** にまとめます。

- **バックアップ** には、すべてのコンテナ、VM、フォルダーセット、フラッシュ、すべての ZFS データセット、セルフバックアップが項目として並びます。一覧の上のタイルで種類を選び、**フィルター**、**並べ替え**、**検索** で絞り込みます。各項目に専用のページがあり、**バックアップ**、**設定**、**検証** の 3 つのタブがあります。項目のアイコンの左にある戻るボタンで一覧に戻れます。
- **復元** はすべてを 1 つのページで扱います。セクションを選び、項目を検索して、バックアップを選びます。緊急ウィザードとほかの復元元もここから始まります。
- **設定** は 14 個のタイルです。一般、外観、スケジュール、保存先、復元、通知、検証、セキュリティ、インスタンス、ペアリング、連携、アプリ、システム、情報。`/` または Ctrl+K ですべてを検索でき、以前のバージョンでページが持っていた名前でも探せます。**外観** でタイルを好きな順にドラッグできます。ページの横にタイルの列があるとページが狭くなってしまう場合、たとえば幅が約 1200 ピクセルのウィンドウでは、タイルはページの上にある横スクロールできる帯になります。スマートフォンでも同じ帯が表示されます。
- **保存先** と **インスタンス** は、専用のページを持つ設定タイルです。タイルの **サイドバーにも表示** で、サイドバーに固定されます。

保存ボタンはどこにもなく、折りたたまれるものもありません。まれな項目には専用のカードかウィンドウがあり、説明は (i) の吹き出しにあります。更新後はリリースノートが自動で開き、変わった箇所に緑の点が付きます。クリックすると点が消えます。**設定、情報** のバージョンカードにある **新着** は、まだ見ていないものの数を示し、リリースノートと、すべての変更を **そこへ移動** 付きで並べた一覧を、1 つのウィンドウの 2 つのタブとして開きます。

## ソースからのビルド {#build-from-source}

BombVault は、JSON API と埋め込みの React インターフェースを提供する単一の静的 Go バイナリです。まずインターフェースをビルドしてから、バイナリを実行します:

```bash
npm --prefix web ci
npm --prefix web run build     # web/dist に書き出し、バイナリがこれを埋め込む
export APP_KEY=$(openssl rand -hex 32)
go test ./...                  # ユニットテストと統合テスト（実際の restic の往復を含む）
golangci-lint run ./...
go run ./cmd/bombvault         # 自己署名証明書で https://localhost:3443 を提供
```

`go run` にもインターフェースのビルドが必要です。リポジトリが `web/dist` に置いているのは空の目印だけなので、`npm --prefix web run build` を実行しないとバイナリには何も埋め込まれず、`500 SPA index not found` と応答します。これは想定どおりの動作です。Docker、libvirt、Unraid は CI でテストできないため、プルリクエストを出す前に、実際のホストで概要の **ホスト統合** カード（または `GET /api/spike`）を使ってマウント、restic、VM の SSH 接続を確認してください。
