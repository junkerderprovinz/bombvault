# Ξεκινώντας

Αυτή η σελίδα σας οδηγεί από ένα φρέσκο μηχάνημα Unraid μέχρι το πρώτο σας αντίγραφο ασφαλείας.

## Απαιτήσεις {#requirements}

| Απαίτηση | Σημειώσεις |
|---|---|
| **Unraid 6.12+** | Παλαιότερες εκδόσεις δεν έχουν δοκιμαστεί. Το Unraid είναι η κύρια πλατφόρμα, αλλά το BombVault τρέχει επίσης σε απλό host Docker και σε TrueNAS Scale (δείτε [Γενικός host Docker](#generic-docker-host) και [TrueNAS SCALE](#truenas)). |
| **Τοποθεσία αποθετηρίου restic** | Μια τοπική διαδρομή (συνιστάται: το array ή η cache σας), SMB, NFS, ή οποιοδήποτε backend rclone. |
| **Docker socket** | Προσαρτάται αυτόματα από το template (`/var/run/docker.sock`). |
| **Unraid flash** (`/boot`) | Προσαρτάται ολόκληρο αυτόματα από το template (`/boot` στο `/host/boot`). Τροφοδοτεί το αντίγραφο του flash και επιτρέπει σε ένα επαναφερμένο κοντέινερ να εμφανιστεί ξανά ως κανονική, επεξεργάσιμη εφαρμογή Unraid. |
| **KVM VMs** (προαιρετικά) | Το αντίγραφο των VM επικοινωνεί με το libvirt μέσω SSH, χωρίς προσάρτηση libvirt. Ρυθμίστε το στις **Ρυθμίσεις, Ενσωματώσεις, SSH κεντρικού συστήματος** (δείτε [Διαμόρφωση](configuration.md)). |
| **Σύνολα δεδομένων ZFS** (προαιρετικά) | Η ίδια σύνδεση SSH με τα αντίγραφα VM, `zfs` στον host, και Host Data αντιστοιχισμένο ως `/mnt` με λειτουργία πρόσβασης Read/Write - Slave, την προεπιλογή του template. Δείτε [Σύνολα δεδομένων ZFS](zfs-datasets.md). |
| **Εφαρμογή Android** (προαιρετική) | Android 10 ή νεότερο, σε σύζευξη με διακομιστές στην έκδοση 9.7.0 ή νεότερη. Δείτε [Εφαρμογή Android](android.md). |

## Εγκατάσταση στο Unraid {#install-on-unraid}

Ο ευκολότερος δρόμος είναι μέσω **Community Applications**.

1. Ανοίξτε την καρτέλα **Apps** στο Unraid.
2. Αναζητήστε το **BombVault**.
3. Κάντε κλικ στο **Install**, ορίστε τις απαιτούμενες μεταβλητές (παρακάτω) και εφαρμόστε.

!!! tip "Χειροκίνητη εγκατάσταση template"
    Αν προτιμάτε να προσθέσετε το template με το χέρι:

    1. Πηγαίνετε στο **Docker, Add Container, Template repositories** και προσθέστε:
       ```
       https://github.com/junkerderprovinz/unraid-apps
       ```
    2. Αναζητήστε το **BombVault** στα Templates.
    3. Ορίστε τις απαιτούμενες μεταβλητές και κάντε κλικ στο **Apply**.

## Γενικός host Docker {#generic-docker-host}

Δεν είστε σε Unraid; Το BombVault τρέχει και ως απλό κοντέινερ σε οποιονδήποτε host Docker. Το TrueNAS SCALE έχει δικά του βήματα στο [TrueNAS SCALE](#truenas).

1. Πάρτε από το αποθετήριο το έτοιμο προς επεξεργασία [`deploy/docker-compose.generic.yml`](https://github.com/junkerderprovinz/bombvault/blob/main/deploy/docker-compose.generic.yml).
2. Ορίστε το `APP_KEY` (δείτε παρακάτω) και στρέψτε τον τόμο Host Data στην πραγματική σας ρίζα δεδομένων. Τα σχόλια του αρχείου καλύπτουν και τα δύο.
3. `docker compose up -d`, και μετά ανοίξτε το `https://<host-ip>:3443/`.

Τι διαφέρει από το Unraid:

- **Δεν υπάρχει τομέας Flash.** Δεν υπάρχει USB εκκίνησης να αντιγραφεί ή να επαναφερθεί, οπότε ο τομέας Flash δεν έχει τίποτα να κάνει εδώ. Αντί γι' αυτό, όταν το Host Data φτάνει στο `/etc` του host, η **Προσθήκη** στη σελίδα Αντίγραφα ασφαλείας προσφέρει τη **Διαμόρφωση συστήματος** ως πρόταση φακέλου: ένα αρχικό σύνολο φακέλων `/etc` που ελέγχετε και επεξεργάζεστε πριν το αποθηκεύσετε.
- **Δεν υπάρχουν εγγενείς ειδοποιήσεις Unraid.** Τα δικά του κανάλια ειδοποιήσεων μέσα στην εφαρμογή (webhook, ειδοποιήσεις αποτυχίας εκτός τόπου κ.λπ.) λειτουργούν κανονικά. Παραλείπεται μόνο η αποστολή στο εγγενές σύστημα ειδοποιήσεων του Unraid, αφού δεν υπάρχει τέτοιο σύστημα να δεχτεί.
- **Το αντίγραφο VM είναι προαιρετικό και χρειάζεται ξεχωριστό host libvirtd προσβάσιμο μέσω SSH.** Δείτε το μπλοκ σε σχόλιο στο αρχείο compose. Δεν υπάρχει VM manager ενσωματωμένος σε έναν γενικό host Docker.
- **Δεν υπάρχει widget πίνακα.** Το BombVault Widget είναι πρόσθετο του Unraid, οπότε και αυτό το βήμα παραλείπεται.
- **Εύρεση των δεδομένων ενός κοντέινερ.** Χωρίς τη σύμβαση `appdata` του Unraid, ο φάκελος δεδομένων ενός κοντέινερ βρίσκεται από τα τμήματα στο `DATA_ROOT_SEGMENTS`, τους ονομασμένους τόμους Docker, τον φάκελο εργασίας ενός έργου Compose και την ετικέτα `bombvault.data` (δείτε [Εντοπισμός πηγής αντιγράφου](configuration.md#backup-source-detection)). Οι ονομασμένοι τόμοι και η προεπιλογή `/etc` φτάνουν μόνο σε διαδρομές μέσα στο mount του Host Data, οπότε στρέψτε το Host Data σε έναν κοινό πρόγονο που καλύπτει και τη ρίζα δεδομένων του Docker.
- **`PLATFORM`.** Ορίστε το σε `generic` ή `truenas`. Αν μείνει ανέγγιχτο, το BombVault εντοπίζει το Unraid από τον δικό του δείκτη στο mount του flash και αντιμετωπίζει οτιδήποτε άλλο ως generic, και τα βήματα μόνο για Unraid παραλείπονται αντί να δοκιμαστούν και να αποτύχουν.

### TrueNAS SCALE {#truenas}

Το BombVault δεν είναι ακόμα στον κατάλογο εφαρμογών του TrueNAS, οπότε εγκαταστήστε το ως custom app: **Apps, Discover Apps**, και μετά **Install via YAML** στο μενού δίπλα στο **Custom App**. Το YAML παρακάτω ορίζει τα ίδια πράγματα με την καταχώριση του καταλόγου στον φάκελο `truenas-apps` του αποθετηρίου. Αντικαταστήστε το `tank` με το pool σας και συμπληρώστε το `APP_KEY` όπως περιγράφει η επόμενη ενότητα.

```yaml
services:
  bombvault:
    image: junkerderprovinz/bombvault:latest
    hostname: bombvault
    restart: unless-stopped
    cap_drop: [ALL]
    cap_add: [CHOWN, DAC_OVERRIDE, FOWNER, SETGID, SETPCAP, SETUID, SYS_CHROOT]
    environment:
      APP_KEY: ""
      PLATFORM: truenas
      HOST_SOURCE_ROOT: /mnt/tank
      HOST_MOUNT_ROOT: /mnt/tank
      # For VM backups:
      # LIBVIRT_URI: qemu+ssh://root@<truenas-ip>/system?socket=/run/truenas_libvirt/libvirt-sock
    volumes:
      - /mnt/tank/apps/bombvault:/config
      - /var/run/docker.sock:/var/run/docker.sock
      - type: bind
        source: /mnt/tank
        target: /mnt/tank
        bind:
          propagation: rslave
    ports:
      - "30528:3443"
```

Μετά ανοίξτε το `https://<truenas-ip>:30528/`. Ό,τι αναφέρεται στο [Τι διαφέρει από το Unraid](#generic-docker-host) ισχύει και εδώ, και στο TrueNAS επιπλέον:

- **Δυνατότητες (capabilities).** Το BombVault χρειάζεται τις επτά παραπάνω. Τα αντίγραφα VM αποτυγχάνουν χωρίς το `SETPCAP`, και χωρίς το `SYS_CHROOT` κάθε κοντέινερ σταματά για ολόκληρο το αντίγραφό του αντί να διαβάζεται από στιγμιότυπο.
- Το **Host Data** είναι μια διαδρομή host σε ένα σύνολο δεδομένων, εδώ το `/mnt/tank`, προσαρτημένη στην ίδια διαδρομή μέσα στην εφαρμογή. Γι' αυτό τα `HOST_SOURCE_ROOT` και `HOST_MOUNT_ROOT` το ονομάζουν και τα δύο. Το `rslave` περνά τα mounts που κάνει ο host αργότερα, κάτι που χρειάζονται τα αντίγραφα συνόλων δεδομένων ZFS.
- **Τα δεδομένα σε ixVolume δεν αντιγράφονται.** Μια εφαρμογή με αποθήκευση σε ixVolume κρατά τα δεδομένα της κάτω από το `/mnt/.ix-apps`, έξω από το Host Data. Το BombVault αποθηκεύει μόνο τον ορισμό της εφαρμογής, και η εκτέλεση ονομάζει τους φακέλους που άφησε έξω. Για κάθε εφαρμογή της οποίας τα δεδομένα θέλετε να αντιγράφονται, διαλέξτε αποθήκευση **Host Path** σε ένα σύνολο δεδομένων κάτω από το Host Data.
- **Τα αντίγραφα VM και συνόλων δεδομένων ZFS** φτάνουν στο TrueNAS μέσω SSH ως root. Ενεργοποιήστε την υπηρεσία SSH στα **System, Services**, και προσθέστε το δημόσιο κλειδί από τις **Ρυθμίσεις, Ενσωματώσεις, SSH κεντρικού συστήματος** στον χρήστη root στα **Credentials, Users**. Τα αντίγραφα VM χρειάζονται επίσης το `LIBVIRT_URI` όπως παραπάνω, γιατί το libvirtd του TrueNAS ακούει σε δικό του socket. Αν δεν έχει οριστεί ούτε το `LIBVIRT_URI` ούτε το `LIBVIRT_HOST`, το BombVault χρησιμοποιεί ως host την προεπιλεγμένη πύλη της εφαρμογής, αφού το `host.docker.internal` δεν επιλύεται σε μια εφαρμογή TrueNAS. Ο [οδηγός αντιγράφων VM](vm-backup-ssh-setup.md#truenas-scale) καλύπτει τις λεπτομέρειες, και τις VMs σε zvols.
- **Μια ρεπλίκα ZFS χρησιμοποιεί άλλο κλειδί.** Μια ρεπλίκα σε δεύτερο διακομιστή ZFS συνδέεται με το κλειδί που δείχνει το παράθυρο της ρεπλίκας, όχι με το κλειδί SSH του host. Προσθέστε εκείνο στον διακομιστή που δέχεται.
- **Μια εφαρμογή που διαγράφηκε επιστρέφει σε δύο βήματα.** Εγκαταστήστε την πρώτα ξανά στο TrueNAS με το ίδιο όνομα, κάτι που ξαναδημιουργεί το δίκτυό της, και μετά επαναφέρετε τα δεδομένα της στο BombVault. Μέχρι τότε ο έλεγχος επαναφοράς αναφέρει το δίκτυο που λείπει, και η επαναφορά αρνείται πριν αλλάξει οτιδήποτε.
- Το **Δίπλα στο πρωτότυπο** δημιουργεί ένα απλό κοντέινερ Docker. Τρέχει, αλλά η οθόνη Apps του TrueNAS δεν το απαριθμεί.
- Τα **Αντίγραφα βάσης δεδομένων** λειτουργούν σε mounts συνόλων δεδομένων. Μια εισαγωγή σε φάκελο δεδομένων που είναι σύνολο δεδομένων από μόνος του μετακινεί τα παλιά περιεχόμενα σε έναν φάκελο δίπλα του, οπότε το σύνολο δεδομένων από πάνω χρειάζεται χώρο γι' αυτά.

### ZimaOS, CasaOS και άλλοι hosts {#other-hosts}

- **ZimaOS και CasaOS:** προσθέστε το [κοινοτικό store](https://github.com/junkerderprovinz/zimaos-apps#install) και εγκαταστήστε το BombVault από αυτό. Τρέχει εκεί ως `PLATFORM=generic` με το Host Data στο `/DATA`. Το ZimaOS κρατά τα δεδομένα των εφαρμογών στο `/DATA/AppData/<app>`, που το BombVault βρίσκει μόνο του, αφού το `DATA_ROOT_SEGMENTS` ταιριάζει με το `appdata` με οποιαδήποτε γραφή πεζών και κεφαλαίων.
- **MOS:** εγκαταστήστε το BombVault από το [MOS Hub](https://mos-official.net/apps.html?search=BombVault). Τρέχει εκεί ως `PLATFORM=generic` με το Host Data στο `/mnt/cache`.
- **Synology:** στο Container Manager, δημιουργήστε ένα project από το αρχείο compose (DSM 7.2 ή νεότερο).
- **Proxmox:** τρέξτε το σε μια VM ή σε ένα κοντέινερ LXC που έχει Docker.

Χωρίς σχόλια, το generic αρχείο compose είναι σύντομο. Αντικαταστήστε το `./data` με τον φάκελο του host που κρατά τα δεδομένα των κοντέινερ σας, ορίστε το `HOST_SOURCE_ROOT` στην ίδια διαδρομή και συμπληρώστε το `APP_KEY`:

```yaml
services:
  bombvault:
    image: junkerderprovinz/bombvault:latest
    restart: unless-stopped
    hostname: bombvault
    container_name: bombvault
    volumes:
      - ./config:/config
      - /var/run/docker.sock:/var/run/docker.sock
      - ./data:/host/user
    environment:
      APP_KEY: ""
      PLATFORM: generic
      HOST_SOURCE_ROOT: /host/user
    ports:
      - "3443:3443"
```

Για να αντιγράφονται και οι ονομασμένοι τόμοι του Docker, προσαρτήστε έναν φάκελο που κρατά και τα δεδομένα σας και τη ρίζα δεδομένων του Docker (`docker info -f '{{.DockerRootDir}}'`, συνήθως `/var/lib/docker`), όπως το template του Unraid προσαρτά ολόκληρο το `/mnt`.

## Η μία απαιτούμενη ρύθμιση {#the-one-required-setting}

Η μόνη μεταβλητή που πρέπει να ορίσετε είναι το `APP_KEY`, ένα μυστικό hex 32 byte (64 χαρακτήρες hex) που χρησιμοποιείται για την παραγωγή του κωδικού του αποθετηρίου restic.

Δημιουργήστε ένα σε οποιοδήποτε μηχάνημα:

```bash
openssl rand -hex 32
```

Επικολλήστε το αποτέλεσμα στο πεδίο `APP_KEY` του template (Unraid), ή στη μεταβλητή περιβάλλοντος `APP_KEY` στο `docker-compose.yml` (generic host Docker).

!!! danger "Μη χάσετε το APP_KEY"
    Αν χάσετε το `APP_KEY`, τα κρυπτογραφημένα αντίγραφά σας δεν ανακτώνται. Φυλάξτε το κάπου ασφαλές και ξεχωριστά από τον διακομιστή. Μόλις τρέξει το BombVault, ορίστε έναν κωδικό πρόσβασης εισόδου και κατεβάστε το **κιτ ανάκτησης** στις **Ρυθμίσεις, Επαναφορά** (δείτε [Εκτός τόπου και ανάκτηση](offsite-recovery.md#recovery-kit)). Περιέχει το κλειδί, κάθε προορισμό αποθήκευσης και τις εντολές του restic.

Το template προσαρτά επίσης για εσάς το Docker socket, το flash (`/boot`) και τη ρίζα του **Host Data** (`/mnt`). Οι *πηγές* και οι *προορισμοί* των αντιγράφων βρίσκονται και οι δύο κάτω από το Host Data. Για την πλήρη αναφορά των μεταβλητών και τη ρύθμιση εκτός τόπου, δείτε [Διαμόρφωση](configuration.md).

## Πρώτη εκτέλεση {#first-run}

![Η σελίδα καλωσορίσματος μιας νέας εγκατάστασης, με ό,τι βρήκε το BombVault στον διακομιστή.](assets/screenshots/getting-started/welcome-dark.png#only-dark)
![Η σελίδα καλωσορίσματος μιας νέας εγκατάστασης, με ό,τι βρήκε το BombVault στον διακομιστή.](assets/screenshots/getting-started/welcome-light.png#only-light)

1. Ανοίξτε το web UI στο `https://<your-unraid-ip>:3443` (αυτο-υπογεγραμμένο πιστοποιητικό από την αρχή). Μια νέα εγκατάσταση ανοίγει στο **Καλώς ήρθατε στο BombVault**, που απαριθμεί ό,τι βρήκε το BombVault στον διακομιστή.
2. Επιλέξτε **Πάμε**. Η επισκόπηση δείχνει τότε την κάρτα **Πρώτα βήματα** με τρία βήματα:
    1. **Επιλέξτε τομείς**: ενεργοποιήστε ό,τι αντιγράφει το BombVault (Κοντέινερ, VMs, Flash, Φάκελοι, Σύνολα δεδομένων ZFS, Αυτο-αντίγραφο). Το **Επιλογή** ανοίγει τη λίστα των στοιχείων ενός τομέα, όπου η **Παύση προγραμματισμού** αφήνει ένα έξω. Οι τομείς που ενεργοποιείτε εδώ τρέχουν κάθε νύχτα, κάτι που αλλάζετε στις **Ρυθμίσεις, Προγραμματισμοί**.
    2. **Προσθήκη προορισμού**: ένα δεύτερο μέρος για τα αντίγραφα. Κάθε τομέας έχει ήδη έναν φάκελο σε αυτόν τον διακομιστή, `/mnt/user/bombvault/{container,vms,flash,config,files,zfs}`, που δημιουργείται στο πρώτο αντίγραφο. Το ασφαλέστερο είναι ένας δεύτερος προορισμός αποθήκευσης εκτός χώρου, όπως ένα Storage Box ή το Backblaze B2.
    3. **Πρώτο αντίγραφο ασφαλείας**: μετά τρέχει μόνο του κάθε νύχτα. Η κάρτα μένει μέχρι να τελειώσει το πρώτο αντίγραφο.
3. Ανοίξτε τα **Αντίγραφα ασφαλείας** για να δείτε κάθε στοιχείο σε μία λίστα. Το **Αντιγραφή όλων τώρα** ξεκινά μια εκτέλεση πάνω από όλους τους ενεργούς τομείς, και το **Δημιουργία αντιγράφου τώρα** στη σελίδα ενός στοιχείου αντιγράφει μόνο εκείνο.

![Η κάρτα Πρώτα βήματα με τα τρία βήματά της, με ανοιχτό το δεύτερο.](assets/screenshots/getting-started/first-steps-dark.png#only-dark)
![Η κάρτα Πρώτα βήματα με τα τρία βήματά της, με ανοιχτό το δεύτερο.](assets/screenshots/getting-started/first-steps-light.png#only-light)

Έχετε ξαναχρησιμοποιήσει το BombVault; Η **Επαναφορά από αντίγραφο ασφαλείας** στη σελίδα καλωσορίσματος ανοίγει τη σελίδα Επαναφορά, όπου ο **Οδηγός έκτακτης ανάγκης** φέρνει πίσω τις ρυθμίσεις, τα κοντέινερ, τις VMs και τους φακέλους ενός χαμένου διακομιστή. Δείτε [Εκτός τόπου και ανάκτηση](offsite-recovery.md#emergency).

!!! tip "Προαιρετικά: διαλέξτε σειρά αντιγράφων"
    Αν κάποια κοντέινερ πρέπει να αντιγράφονται πάντα πριν από άλλα (για παράδειγμα μια βάση δεδομένων πριν από την εφαρμογή που τη χρησιμοποιεί), ανοίξτε την κάρτα **Σειρά** κάτω από τις **Ρυθμίσεις, Προγραμματισμοί** και σύρετέ τα στη σειρά που θέλετε. Οι προγραμματισμένες εκτελέσεις και το πλήρες αντίγραφο την ακολουθούν τότε. Ό,τι αφήσετε χωρίς σειρά αντιγράφεται με πρώτο εκείνο που έχει καθυστερήσει περισσότερο.

## Παράδειγμα: το πρώτο σας αντίγραφο κοντέινερ, από την αρχή ως το τέλος {#example-first-backup}

Αυτό διατρέχει ένα φρέσκο μηχάνημα Unraid με μερικά κοντέινερ, ανάμεσά τους το `plex`, μέχρι να γίνει το πρώτο αντίγραφο και να ξέρετε πού να το βρείτε. Παίρνει περίπου δέκα λεπτά συν τον χρόνο του πρώτου αντιγράφου.

1. **Εγκατάσταση.** Στην καρτέλα **Apps** του Unraid, αναζητήστε το **BombVault** και πατήστε **Install**.
2. **Ορίστε το κλειδί.** Σε έναν υπολογιστή, τρέξτε `openssl rand -hex 32` και επικολλήστε τους 64 χαρακτήρες στο πεδίο `APP_KEY` του template. Κρατήστε αντίγραφο στον διαχειριστή κωδικών σας τώρα, πριν από οτιδήποτε άλλο. Πατήστε **Apply**.
3. **Ανοίξτε το.** Πηγαίνετε στο `https://<your-unraid-ip>:3443` και αποδεχτείτε το αυτο-υπογεγραμμένο πιστοποιητικό. Το **Καλώς ήρθατε στο BombVault** απαριθμεί ό,τι βρήκε, όπως 12 κοντέινερ, 2 VMs και τη μονάδα flash.
4. **Πάμε.** Η επισκόπηση ανοίγει με την κάρτα **Πρώτα βήματα**.
5. **Επιλέξτε τομείς.** Τα **Κοντέινερ** είναι ενεργά από την αρχή. Ενεργοποιήστε ό,τι άλλο θέλετε, όπως το **Flash**. Το **Επιλογή** ανοίγει τη λίστα των κοντέινερ που βρέθηκαν, όπου η **Παύση προγραμματισμού** αφήνει ένα έξω, για παράδειγμα ένα δοκιμαστικό κοντέινερ που δεν σας νοιάζει. Οι ενεργοί τομείς τρέχουν κάθε νύχτα στο πλήρες αντίγραφο.
6. **Προσθήκη προορισμού.** Κάθε τομέας έχει ήδη τον δικό του φάκελο σε αυτόν τον διακομιστή, κάτω από το `/mnt/user/bombvault`, οπότε το πρώτο αντίγραφο έχει πού να πάει. Αυτό το βήμα προσθέτει ένα δεύτερο μέρος, και το ασφαλέστερο είναι εκτός χώρου. Μπορείτε να το κάνετε τώρα με το [παράδειγμα S3](offsite-recovery.md#example-s3), ή να επιστρέψετε σε αυτό όταν τελειώσει το πρώτο αντίγραφο. Η κάρτα μένει μέχρι τότε.
7. **Πρώτο αντίγραφο.** Ανοίξτε τα **Αντίγραφα ασφαλείας** και πατήστε **Αντιγραφή όλων τώρα**, ή περιμένετε τη νύχτα. Ο δακτύλιος στην κεφαλίδα κατάστασης γίνεται δακτύλιος προόδου και μετρά τα στοιχεία, όπως **Δημιουργία αντιγράφου τώρα: 3 από 12**. Κάθε κοντέινερ σταματά όσο διαβάζονται τα δεδομένα του και ξεκινά ξανά αμέσως μετά. Ένα κοντέινερ με δεδομένα σε ZFS είναι κάτω μόνο για τα λίγα δευτερόλεπτα ενός στιγμιοτύπου. Το πρώτο αντίγραφο διαβάζει τα πάντα, οπότε παίρνει τον περισσότερο χρόνο. Τα επόμενα αποθηκεύουν μόνο ό,τι άλλαξε.
8. **Ελέγξτε το.** Όταν ο δακτύλιος γράφει **Όλα έχουν αντιγραφεί**, ανοίξτε το **Ιστορικό** στην επισκόπηση: κάθε κοντέινερ έχει μια πράσινη γραμμή στις **Εκτελέσεις**. Ανοίξτε τα **Αντίγραφα ασφαλείας**, κάντε κλικ στο `plex` και δείτε την καρτέλα **Αντίγραφα ασφαλείας** του: το πρώτο στιγμιότυπο είναι εκεί, με το **Τοπικό** ως το μέρος που το κρατά. Λίγα λεπτά αργότερα η καρτέλα **Επαλήθευση** δείχνει τον έλεγχο επαναφοράς, που επανέφερε ένα δείγμα του αντιγράφου και το διάβασε πίσω.
9. **Προστατέψτε το κλειδί.** Ανοίξτε τις **Ρυθμίσεις, Ασφάλεια** και ορίστε έναν κωδικό πρόσβασης εισόδου. Μετά ανοίξτε τις **Ρυθμίσεις, Επαναφορά** και πατήστε **Λήψη κιτ ανάκτησης** στο **Για έκτακτες ανάγκες**. Φυλάξτε το αρχείο εκτός διακομιστή, δίπλα στο αντίγραφο του `APP_KEY` από το βήμα 2. Η υπενθύμιση **Αποθηκεύστε το κιτ ανάκτησής σας** στην επισκόπηση φεύγει μόλις πατήσετε **Το αποθήκευσα με ασφάλεια**.

Από εδώ και πέρα τα κοντέινερ αντιγράφονται κάθε νύχτα. Καλά επόμενα βήματα, με αυτή τη σειρά: ένας [προορισμός αποθήκευσης εκτός τόπου](offsite-recovery.md#example-s3), ώστε ένας χαλασμένος διακομιστής να μην παίρνει μαζί του τα αντίγραφα, μετά οι [ειδοποιήσεις](notifications.md), ώστε μια αποτυχία να σας φτάνει, και μετά μια ματιά στους [Προγραμματισμούς](schedules.md) αν οι 03:00 δεν σας ταιριάζουν.

![Η κεφαλίδα κατάστασης όσο τρέχει το πρώτο αντίγραφο, με τον δακτύλιο προόδου και τους σταθμούς του.](assets/screenshots/getting-started/status-ring-dark.png#only-dark)
![Η κεφαλίδα κατάστασης όσο τρέχει το πρώτο αντίγραφο, με τον δακτύλιο προόδου και τους σταθμούς του.](assets/screenshots/getting-started/status-ring-light.png#only-light)

!!! note "Έλεγχος ενσωμάτωσης host"
    Η κάρτα **Ενσωμάτωση host** στην επισκόπηση ελέγχει κάθε mount και CLI (Docker socket, libvirt, restic, qemu-img, rclone) και αναφέρει ό,τι λείπει, ώστε να επιβεβαιώσετε ότι το κοντέινερ είναι σωστά συνδεδεμένο πριν βασιστείτε σε αυτό. Περιμένει κάτω από την **Προσαρμογή** μέχρι να την προσθέσετε.

## Βρίσκοντας τον δρόμο σας {#navigation}

![Οι Ρυθμίσεις ως πλακίδια, με τις κάρτες του επιλεγμένου πλακιδίου δίπλα τους. Κάθε αλλαγή γράφεται καθώς την κάνετε.](assets/screenshots/getting-started/settings-rail-dark.png#only-dark)
![Οι Ρυθμίσεις ως πλακίδια, με τις κάρτες του επιλεγμένου πλακιδίου δίπλα τους. Κάθε αλλαγή γράφεται καθώς την κάνετε.](assets/screenshots/getting-started/settings-rail-light.png#only-light)

Η πλαϊνή μπάρα έχει πέντε καταχωρίσεις: **Επισκόπηση**, **Ανωμαλίες** (όσο ο εντοπισμός ανωμαλιών είναι ενεργός), **Αντίγραφα ασφαλείας**, **Επαναφορά** και, κάτω από το **Αποσύνδεση**, οι **Ρυθμίσεις**. Η κύρια ενέργεια μιας σελίδας επιπλέει κάτω δεξιά, και τα **Περισσότερα** κρατούν τις σπάνιες. Σε κινητό η μπάρα κρατά Επισκόπηση, Αντίγραφα ασφαλείας, Επαναφορά και Ρυθμίσεις, και τα **Περισσότερα** έχουν τα υπόλοιπα.

Οι σελίδες και οι ρυθμίσεις χρησιμοποιούν όλο το πλάτος του παραθύρου. Ένα παράθυρο κρατά τα κουμπιά του στο κάτω μέρος του, με αυτό που πηγαίνει μπροστά δεξιά. Σε κινητό, ένα κάτω μέρος με περισσότερα από τρία κουμπιά κρατά την έξοδο και την κύρια ενέργεια και βάζει τα άλλα κάτω από τα **Περισσότερα**.

![Σε κινητό, η μπάρα στο κάτω μέρος με ανοιχτά τα Περισσότερα.](assets/screenshots/getting-started/phone-more-dark.png#only-dark)
![Σε κινητό, η μπάρα στο κάτω μέρος με ανοιχτά τα Περισσότερα.](assets/screenshots/getting-started/phone-more-light.png#only-light)

- Η **Επισκόπηση** δείχνει αν όλα έχουν αντιγραφεί και τι χρειάζεται εσάς. Δείτε [Επισκόπηση](overview.md).
- Τα **Αντίγραφα ασφαλείας** απαριθμούν κάθε κοντέινερ, VM, σύνολο φακέλων, τη μονάδα flash, κάθε σύνολο δεδομένων ZFS και το αυτο-αντίγραφο ως στοιχεία. Τα πλακίδια πάνω από τη λίστα διαλέγουν ένα είδος, και τα **Φίλτρα**, η **Ταξινόμηση** και η **Αναζήτηση** τη στενεύουν. Κάθε στοιχείο έχει δική του σελίδα με τρεις καρτέλες: **Αντίγραφα ασφαλείας**, **Ρυθμίσεις** και **Επαλήθευση**. Ένα κουμπί επιστροφής αριστερά από το εικονίδιο του στοιχείου οδηγεί στη λίστα. Δείτε [Αντίγραφα ασφαλείας και στοιχεία](backups.md).
- Η **Επαναφορά** είναι μία σελίδα για όλα: διαλέξτε έναν τομέα, αναζητήστε ένα στοιχείο και επιλέξτε ένα αντίγραφο. Ο Οδηγός έκτακτης ανάγκης και οι άλλες πηγές ξεκινούν κι αυτά από εδώ. Δείτε [Επαναφορά](restore.md).
- Οι **Ρυθμίσεις** είναι δεκατέσσερα πλακίδια: Γενικά, Εμφάνιση, Προγραμματισμοί, Προορισμοί, Επαναφορά, Ειδοποιήσεις, Επαλήθευση, Ασφάλεια, Στιγμιότυπα, Σύζευξη, Ενσωματώσεις, Εφαρμογές, Σύστημα και Πληροφορίες. Δείτε [Ρυθμίσεις](settings.md). Πατήστε `/` ή Ctrl+K για να τις ψάξετε όλες, και με τα ονόματα που είχαν οι σελίδες σε προηγούμενες εκδόσεις. Σύρετε τα πλακίδια στη δική σας σειρά κάτω από την **Εμφάνιση**. Όπου μια στήλη πλακιδίων δίπλα στη σελίδα θα την στένευε, όπως σε παράθυρο πλάτους περίπου 1200 pixel, τα πλακίδια γίνονται μια λωρίδα πάνω από τη σελίδα που κυλά οριζόντια. Ένα κινητό δείχνει την ίδια λωρίδα.
- Οι **Προορισμοί** και τα **Στιγμιότυπα** είναι πλακίδια ρυθμίσεων με δικές τους σελίδες. Το **Εμφάνιση και στην πλαϊνή μπάρα** στο πλακίδιό τους τα καρφιτσώνει στην πλαϊνή μπάρα.

Τίποτα δεν έχει κουμπί Αποθήκευση και τίποτα δεν ανοίγει σε διπλώσεις: τα σπάνια πράγματα έχουν δική τους κάρτα ή παράθυρο, και οι εξηγήσεις βρίσκονται στις φούσκες (i). Μετά από μια ενημέρωση ανοίγει μόνο του ένα παράθυρο με μια κάρτα για κάθε έκδοση από την τελευταία σας, και πράσινες τελείες σημαδεύουν ό,τι άλλαξε. Ένα κλικ κρύβει μια τελεία. Το **Νέο** στην κάρτα Έκδοση κάτω από τις **Ρυθμίσεις, Πληροφορίες** μετρά ό,τι δεν έχετε δει ακόμα και ανοίγει ξανά αυτό το παράθυρο, με τις σημειώσεις κάθε έκδοσης και τις αλλαγές της με **Μετάβαση εκεί**.

## Χτίσιμο από τον πηγαίο κώδικα {#build-from-source}

Το BombVault είναι ένα στατικό δυαδικό Go που σερβίρει ένα JSON API και μια ενσωματωμένη διεπαφή React. Χτίστε πρώτα τη διεπαφή και μετά τρέξτε το δυαδικό:

```bash
npm --prefix web ci
npm --prefix web run build     # writes web/dist, which the binary embeds
export APP_KEY=$(openssl rand -hex 32)
go test ./...                  # unit and integration tests, with a real restic round trip
golangci-lint run ./...
go run ./cmd/bombvault         # serves https://localhost:3443 with a self-signed certificate
```

Το χτίσιμο της διεπαφής χρειάζεται και για το `go run`. Το αποθετήριο παρακολουθεί μόνο έναν κενό δείκτη κάτω από το `web/dist`, οπότε χωρίς το `npm --prefix web run build` το δυαδικό δεν ενσωματώνει τίποτα και απαντά `500 SPA index not found`, κάτι που είναι αναμενόμενο. Το Docker, το libvirt και το Unraid δεν μπορούν να δοκιμαστούν στο CI, οπότε ελέγξτε τα mounts, το restic και τη σύνδεση SSH των VM σε έναν πραγματικό host με την κάρτα **Ενσωμάτωση host** της επισκόπησης (ή το `GET /api/spike`) πριν ανοίξετε ένα pull request.
