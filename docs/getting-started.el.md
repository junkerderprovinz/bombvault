# Ξεκινώντας

Αυτή η σελίδα σας οδηγεί από ένα φρέσκο μηχάνημα Unraid μέχρι το πρώτο σας αντίγραφο ασφαλείας.

## Απαιτήσεις

| Απαίτηση | Σημειώσεις |
|---|---|
| **Unraid 6.12+** | Παλαιότερες εκδόσεις δεν έχουν δοκιμαστεί. Το Unraid είναι η κύρια πλατφόρμα, αλλά το BombVault τρέχει επίσης σε απλό host Docker και σε TrueNAS Scale (δείτε [Γενικός host Docker](#generic-docker-host)). |
| **Τοποθεσία αποθετηρίου restic** | Μια τοπική διαδρομή (συνιστάται: το array ή η cache σας), SMB, NFS, ή οποιοδήποτε backend rclone. |
| **Docker socket** | Προσαρτάται αυτόματα από το template (`/var/run/docker.sock`). |
| **Unraid flash** (`/boot`) | Προσαρτάται ολόκληρο αυτόματα από το template (`/boot` στο `/host/boot`). Τροφοδοτεί το αντίγραφο του flash και επιτρέπει σε ένα επαναφερμένο container να εμφανιστεί ξανά ως κανονική, επεξεργάσιμη εφαρμογή Unraid. |
| **KVM VMs** (προαιρετικά) | Το αντίγραφο των VM επικοινωνεί με το libvirt μέσω SSH, χωρίς προσάρτηση libvirt. Ρυθμίστε το στις **Ρυθμίσεις, Ενσωματώσεις, SSH κεντρικού συστήματος** (δείτε [Διαμόρφωση](configuration.md)). |
| **Σύνολα δεδομένων ZFS** (προαιρετικά) | Η ίδια σύνδεση SSH με τα αντίγραφα VM, `zfs` στον host, και Host Data αντιστοιχισμένο ως `/mnt` με λειτουργία πρόσβασης Read/Write - Slave, την προεπιλογή του template. Δείτε [Σύνολα δεδομένων ZFS](zfs-datasets.md). |
| **Εφαρμογή Android** (προαιρετική) | Android 10 ή νεότερο, σε σύζευξη με διακομιστές στην έκδοση 9.7.0 ή νεότερη. Δείτε [Εφαρμογή Android](android.md). |

## Εγκατάσταση στο Unraid

Ο ευκολότερος δρόμος είναι μέσω **Community Applications**.

1. Ανοίξτε την καρτέλα **Apps** στο Unraid.
2. Αναζητήστε το **BombVault**.
3. Κάντε κλικ στο **Install**, ορίστε τις απαιτούμενες μεταβλητές (παρακάτω) και εφαρμόστε.

!!! tip "Χειροκίνητη εγκατάσταση template"
    Αν προτιμάτε να προσθέσετε το template με το χέρι:

    1. Πηγαίνετε στο **Docker, Add Container, Template repositories** και προσθέστε:
       ```
       https://github.com/junkerderprovinz/unraid-apps
       ```
    2. Αναζητήστε το **BombVault** στα Templates.
    3. Ορίστε τις απαιτούμενες μεταβλητές και κάντε κλικ στο **Apply**.

## Γενικός host Docker {#generic-docker-host}

Δεν είστε σε Unraid; Το BombVault τρέχει και ως απλό container σε οποιονδήποτε host Docker (σε αυτό στηρίζεται και η υποστήριξη containers στο TrueNAS Scale, πριν αποκτήσει δική του καταχώριση στον εκεί κατάλογο εφαρμογών).

1. Πάρτε από το αποθετήριο το έτοιμο προς επεξεργασία [`deploy/docker-compose.generic.yml`](https://github.com/junkerderprovinz/bombvault/blob/main/deploy/docker-compose.generic.yml).
2. Ορίστε το `APP_KEY` (δείτε παρακάτω) και στρέψτε τον τόμο Host Data στην πραγματική σας ρίζα δεδομένων. Τα σχόλια του αρχείου καλύπτουν και τα δύο.
3. `docker compose up -d`, μετά ανοίξτε το `https://<ip-host>:3443/`.

Τι διαφέρει από το Unraid:

- **Δεν υπάρχει τομέας Flash.** Δεν υπάρχει στικάκι εκκίνησης για αποτύπωση ή επαναφορά, οπότε ο τομέας Flash δεν έχει εδώ τίποτα να κάνει. Στη θέση του, η **Προσθήκη** στη σελίδα Αντίγραφα ασφαλείας προσφέρει τη **Διαμόρφωση συστήματος** ως πρόταση φακέλου: ένα αρχικό σύνολο φακέλων `/etc` που ελέγχετε και τροποποιείτε πριν το αποθηκεύσετε.
- **Δεν υπάρχουν εγγενείς ειδοποιήσεις Unraid.** Τα δικά του κανάλια ειδοποιήσεων του BombVault (webhook, ειδοποιήσεις αποτυχίας εκτός έδρας κ.ο.κ.) δουλεύουν κανονικά· παραλείπεται μόνο η αποστολή στο ίδιο το σύστημα ειδοποιήσεων του Unraid, αφού τέτοιο σύστημα εδώ δεν υπάρχει.
- **Το αντίγραφο εικονικών μηχανών είναι προαιρετικό και χρειάζεται ξεχωριστό host libvirtd προσβάσιμο μέσω SSH.** Δείτε το σχολιασμένο μπλοκ στο αρχείο compose. Ένας γενικός host Docker δεν φέρνει από μόνος του διαχείριση εικονικών μηχανών.
- **Χωρίς widget στον πίνακα ελέγχου.** Το BombVault Widget είναι πρόσθετο του Unraid, οπότε κι αυτό το βήμα παραλείπεται.
- **Εύρεση των δεδομένων ενός container.** Χωρίς τη σύμβαση `appdata` του Unraid, ο φάκελος δεδομένων ενός container βρίσκεται από τα τμήματα στο `DATA_ROOT_SEGMENTS`, τους επώνυμους τόμους του Docker, τον κατάλογο εργασίας ενός project Compose και την ετικέτα `bombvault.data` (δείτε [Αναγνώριση των πηγών αντιγράφου ασφαλείας](configuration.md#backup-source-detection)). Οι επώνυμοι τόμοι και η προρύθμιση `/etc` φτάνουν μόνο σε διαδρομές μέσα στην προσάρτηση Host Data, οπότε κατευθύνετε το Host Data σε έναν κοινό γονικό κατάλογο που καλύπτει και τη ρίζα δεδομένων του Docker.
- **`PLATFORM`.** Ορίστε τη σε `generic` ή `truenas`. Αν δεν οριστεί, το BombVault αναγνωρίζει το Unraid από το δικό του σημάδι στην προσάρτηση του flash και αντιμετωπίζει οτιδήποτε άλλο ως γενικό host, και τα βήματα που αφορούν μόνο το Unraid παραλείπονται αντί να επιχειρούνται και να αποτυγχάνουν.

Το **TrueNAS Scale** ακολουθεί τον ίδιο δρόμο μέσω compose· μια καταχώριση καταλόγου είναι έτοιμη στο αποθετήριο, αλλά δεν έχει υποβληθεί ακόμη. Το αντίγραφο VM εκεί χρειάζεται `LIBVIRT_URI`, επειδή το libvirtd του TrueNAS ακούει σε δικό του socket (`/run/truenas_libvirt/libvirt-sock`), που οι τρεις μεταβλητές `LIBVIRT_*` δεν μπορούν να εκφράσουν (δείτε [Διαμόρφωση](configuration.md)). Πόσο έχει επαληθευτεί: το αντίγραφο zvol εκτελέστηκε σε πραγματικό μηχάνημα TrueNAS Scale, σε zvol συνδεδεμένο σε VM που έτρεχε, και τα `zfs snapshot`, `zfs send`, restic και `zfs receive` το πήγαν και το έφεραν πίσω byte προς byte χωρίς διαφορά. Μια πλήρης επαναφορά που την οδηγεί το ίδιο το BombVault δεν έχει εκτελεστεί ακόμη σε υλικό TrueNAS, και εκείνο το zvol ήταν αραιό (sparse), οπότε η απόδοση σε πολλά gigabyte δεν έχει δοκιμαστεί. Δοκιμάστε μια επαναφορά εκεί πριν βασιστείτε σε αυτό.

## Η μία απαιτούμενη ρύθμιση

Η μόνη μεταβλητή που πρέπει να ορίσετε είναι το `APP_KEY`, ένα δεκαεξαδικό μυστικό 32 byte (64 δεκαεξαδικοί χαρακτήρες) που χρησιμοποιείται για την παραγωγή του κωδικού του αποθετηρίου restic.

Δημιουργήστε ένα σε οποιοδήποτε μηχάνημα:

```bash
openssl rand -hex 32
```

Επικολλήστε το αποτέλεσμα στο πεδίο `APP_KEY` του template (Unraid) ή στη μεταβλητή περιβάλλοντος `APP_KEY` του `docker-compose.yml` (γενικός host Docker).

!!! danger "Μη χάσετε το APP_KEY σας"
    Η απώλεια του `APP_KEY` καθιστά τα κρυπτογραφημένα αντίγραφα ασφαλείας μη ανακτήσιμα. Αποθηκεύστε το σε ασφαλές μέρος, ξεχωριστά από τον διακομιστή. Μόλις το BombVault εκτελείται, ορίστε έναν κωδικό σύνδεσης και κατεβάστε το **Κιτ ανάκτησης** στις **Ρυθμίσεις, Επαναφορά** (δείτε [Εκτός τόπου & ανάκτηση](offsite-recovery.md#recovery-kit)). Περιέχει το κλειδί, κάθε προορισμό και τις εντολές του restic.

Το template προσαρτά επίσης για εσάς το Docker socket, το flash (`/boot`) και τη ρίζα **Host Data** (`/mnt`). Οι *πηγές* και οι *προορισμοί* των αντιγράφων βρίσκονται και οι δύο κάτω από το Host Data. Για την πλήρη αναφορά μεταβλητών και τη ρύθμιση εκτός τόπου, δείτε [Διαμόρφωση](configuration.md).

## Πρώτη εκτέλεση

![Η επισκόπηση μετά το πρώτο αντίγραφο: τι χρειάζεται προσοχή, η προστασία κάθε τομέα, οι προορισμοί και το ιστορικό.](assets/screenshots/dashboard.png)

*Η επισκόπηση μετά το πρώτο αντίγραφο: τι χρειάζεται προσοχή, η προστασία κάθε τομέα, οι προορισμοί και το ιστορικό.*

1. Ανοίξτε το περιβάλλον ιστού στο `https://<your-unraid-ip>:3443` (αυτοϋπογεγραμμένο πιστοποιητικό από προεπιλογή). Μια νέα εγκατάσταση ανοίγει στο **Καλώς ήρθατε στο BombVault**, που απαριθμεί ό,τι βρήκε το BombVault στον διακομιστή.
2. Επιλέξτε **Πάμε**. Η Επισκόπηση δείχνει τότε την κάρτα **Πρώτα βήματα** με τρία βήματα:
    1. **Επιλέξτε τομείς**: ενεργοποιήστε ό,τι αντιγράφει το BombVault (Containers, VMs, Flash, Φάκελοι, Σύνολα δεδομένων ZFS, Αυτο-αντίγραφο). Το **Επιλογή** ανοίγει τη λίστα των στοιχείων ενός τομέα, όπου η **Παύση προγραμματισμού** αφήνει ένα απ' έξω. Οι τομείς που ενεργοποιείτε εδώ εκτελούνται κάθε βράδυ, κάτι που αλλάζετε στις **Ρυθμίσεις, Χρονοδιάγραμμα**.
    2. **Προσθήκη προορισμού**: πού πηγαίνουν τα αντίγραφα ασφαλείας. Ένας τοπικός φάκελος αρκεί για αρχή. Ασφαλέστερος είναι ένας δεύτερος προορισμός εκτός χώρου, όπως ένα Storage Box ή το Backblaze B2. Τα τοπικά αποθετήρια έχουν από προεπιλογή `/mnt/user/bombvault/{container,vms,flash,config,files,zfs}` και δημιουργούνται στο πρώτο αντίγραφο.
    3. **Πρώτο αντίγραφο ασφαλείας**: μετά εκτελείται μόνο του κάθε βράδυ.
3. Ανοίξτε τα **Αντίγραφα ασφαλείας** για να δείτε όλα τα στοιχεία σε μία λίστα. Το **Αντιγραφή όλων τώρα** ξεκινά μια εκτέλεση σε όλους τους ενεργούς τομείς και το **Δημιουργία αντιγράφου τώρα** στη σελίδα ενός στοιχείου αντιγράφει μόνο εκείνο.

Έχετε ξαναχρησιμοποιήσει το BombVault; Η **Επαναφορά από αντίγραφο ασφαλείας** στη σελίδα καλωσορίσματος ανοίγει τη σελίδα Επαναφορά, όπου ο **Οδηγός έκτακτης ανάγκης** επαναφέρει τις ρυθμίσεις, τα containers, τις VM και τους φακέλους ενός χαμένου διακομιστή. Δείτε [Εκτός τόπου & ανάκτηση](offsite-recovery.md#emergency).

!!! tip "Προαιρετικό: επιλέξτε σειρά αντιγράφων"
    Αν κάποια containers πρέπει πάντα να αντιγράφονται πριν από άλλα (για παράδειγμα μια βάση δεδομένων πριν από την εφαρμογή που τη χρησιμοποιεί), ανοίξτε την κάρτα **Σειρά** στις **Ρυθμίσεις, Χρονοδιάγραμμα** και σύρετέ τα στην ακολουθία που θέλετε. Οι προγραμματισμένες εκτελέσεις και το πλήρες αντίγραφο την ακολουθούν τότε· οτιδήποτε αφήσετε χωρίς σειρά αντιγράφεται με προτεραιότητα στα πιο καθυστερημένα.

!!! note "Έλεγχος ενσωμάτωσης host"
    Η κάρτα **Ενσωμάτωση host** στην Επισκόπηση ανιχνεύει κάθε προσάρτηση και CLI (Docker socket, libvirt, restic, qemu-img, rclone) και αναφέρει τυχόν κομμάτια που λείπουν, ώστε να επιβεβαιώσετε ότι το container είναι σωστά συνδεδεμένο πριν βασιστείτε σε αυτό. Περιμένει κάτω από το **Προσαρμογή** μέχρι να την προσθέσετε.

## Βρίσκοντας το δρόμο σας {#navigation}

![Οι ρυθμίσεις ως πλακίδια, με τις κάρτες του επιλεγμένου πλακιδίου δίπλα τους. Κάθε αλλαγή γράφεται μόλις την κάνετε.](assets/screenshots/settings.png)

*Οι ρυθμίσεις ως πλακίδια, με τις κάρτες του επιλεγμένου πλακιδίου δίπλα τους. Κάθε αλλαγή γράφεται μόλις την κάνετε.*

Η πλαϊνή μπάρα έχει πέντε στοιχεία: **Επισκόπηση**, **Ανωμαλίες** (όσο είναι ενεργή η ανίχνευση ανωμαλιών), **Αντίγραφα ασφαλείας**, **Επαναφορά** και, κάτω από την **Αποσύνδεση**, οι **Ρυθμίσεις**. Η κύρια ενέργεια μιας σελίδας επιπλέει κάτω δεξιά και τα **Περισσότερα** κρατούν τις σπάνιες. Σε κινητό η μπάρα έχει Επισκόπηση, Αντίγραφα ασφαλείας, Επαναφορά και Ρυθμίσεις, και τα **Περισσότερα** έχουν τα υπόλοιπα.

Οι σελίδες και οι ρυθμίσεις χρησιμοποιούν ολόκληρο το πλάτος του παραθύρου. Ένα παράθυρο κρατά τα κουμπιά του στο κάτω μέρος, με το κουμπί που προχωρά μπροστά δεξιά. Σε κινητό, ένα κάτω μέρος με περισσότερα από τρία κουμπιά κρατά την έξοδο και την κύρια ενέργεια και βάζει τα υπόλοιπα κάτω από τα **Περισσότερα**.

- Τα **Αντίγραφα ασφαλείας** απαριθμούν κάθε container, VM, σύνολο φακέλων, το flash, κάθε σύνολο δεδομένων ZFS και το αυτο-αντίγραφο ως στοιχεία. Πλακίδια πάνω από τη λίστα διαλέγουν ένα είδος, και τα **Φίλτρα**, η **Ταξινόμηση** και η **Αναζήτηση** τη στενεύουν. Κάθε στοιχείο έχει δική του σελίδα με τρεις καρτέλες: **Αντίγραφα ασφαλείας**, **Ρυθμίσεις** και **Επαλήθευση**. Ένα κουμπί επιστροφής αριστερά από το εικονίδιο του στοιχείου οδηγεί στη λίστα.
- Η **Επαναφορά** είναι μία σελίδα για όλα: διαλέγετε έναν τομέα, αναζητάτε ένα στοιχείο και επιλέγετε ένα αντίγραφο. Ο Οδηγός έκτακτης ανάγκης και οι άλλες πηγές ξεκινούν κι αυτές από εδώ.
- Οι **Ρυθμίσεις** είναι δεκατέσσερα πλακίδια: Γενικά, Εμφάνιση, Χρονοδιάγραμμα, Προορισμοί, Επαναφορά, Ειδοποιήσεις, Επαλήθευση, Ασφάλεια, Στιγμιότυπα, Σύζευξη, Ενσωματώσεις, Εφαρμογές, Σύστημα και Πληροφορίες. Το `/` ή το Ctrl+K τα ψάχνει όλα, ακόμη και με τα ονόματα που είχαν οι σελίδες σε προηγούμενες εκδόσεις. Σύρετε τα πλακίδια στη δική σας σειρά κάτω από την **Εμφάνιση**.
- Οι **Προορισμοί** και τα **Στιγμιότυπα** είναι πλακίδια ρυθμίσεων με δικές τους σελίδες. Το **Εμφάνιση και στην πλαϊνή μπάρα** στο πλακίδιό τους τα καρφιτσώνει στην πλαϊνή μπάρα.

Τίποτα δεν έχει κουμπί Αποθήκευσης και τίποτα δεν ανοίγει σε διπλωμένο τμήμα: τα σπάνια πράγματα έχουν δική τους κάρτα ή παράθυρο και οι εξηγήσεις βρίσκονται στις φούσκες (i). Μετά από μια ενημέρωση, πράσινες τελείες σημαδεύουν ό,τι άλλαξε. Ένα κλικ κρύβει μια τελεία και το **Νέα** στην κάρτα Έκδοση στις **Ρυθμίσεις, Πληροφορίες** απαριθμεί κάθε αλλαγή με το **Μετάβαση εκεί**.

## Μεταγλώττιση από τον πηγαίο κώδικα {#build-from-source}

Το BombVault είναι ένα μοναδικό στατικό εκτελέσιμο Go που σερβίρει ένα JSON API και μια ενσωματωμένη διεπαφή React. Μεταγλωττίστε πρώτα τη διεπαφή και μετά εκτελέστε το εκτελέσιμο:

```bash
npm --prefix web ci
npm --prefix web run build     # writes web/dist, which the binary embeds
export APP_KEY=$(openssl rand -hex 32)
go test ./...                  # unit and integration tests, with a real restic round trip
golangci-lint run ./...
go run ./cmd/bombvault         # serves https://localhost:3443 with a self-signed certificate
```

Η μεταγλώττιση της διεπαφής χρειάζεται και για το `go run`. Το αποθετήριο παρακολουθεί κάτω από το `web/dist` μόνο ένα κενό αρχείο-σημάδι, οπότε χωρίς `npm --prefix web run build` το εκτελέσιμο δεν ενσωματώνει τίποτα και απαντά `500 SPA index not found`, κάτι αναμενόμενο. Το Docker, το libvirt και το Unraid δεν μπορούν να δοκιμαστούν στο CI, οπότε ελέγξτε τις προσαρτήσεις, το restic και τη σύνδεση SSH των VM σε πραγματικό host με την κάρτα **Ενσωμάτωση host** της Επισκόπησης (ή το `GET /api/spike`) πριν ανοίξετε pull request.
