# 概要

概要はサイドバーの最初のページで、毎朝確認するページです。「すべてバックアップされているか」「対応が必要なことはあるか」という 2 つの疑問に、ひと目で答えます。上部のステータス欄と 4 枚のカードから始まり、さらに多くのカードが**カスタマイズ**の下に控えています。

## ステータス欄 {#status-head}

ステータス欄はページの一番上にあり、常にそこに表示されています。リングは保護されている割合を示し（たとえば **43 件中 41 件が保護済み**）、その横の一行が現在の状況を伝えます。

| ステータス欄の表示 | 意味 |
|---|---|
| **すべてバックアップ済み** | オンになっているすべてのセクションの、すべての項目に最新のバックアップがあります。 |
| **バックアップ済み（注意事項あり）** | すべてバックアップ済みですが、読み取れなかったファイルなど、いくつかの実行に注意事項が残っています。 |
| **まだすべてが保護されているわけではありません** | 最新のバックアップがない項目があります。たとえば最初のバックアップを待っている場合です。 |
| **3 件に対応が必要です** | 失敗したことや、判断待ちのことがあります。**要対応**カードに一覧が出ます。 |
| **バックアップ中** | バックアップが実行中です。リングは進捗リングに変わり、**停止**、**読み取り**、**起動**の各ステーションが表示されます。フルバックアップでは、進むにつれて項目数を数えます（たとえば **バックアップ中: 43 件中 12 件**）。**実行を表示**で、その実行を開けます。 |
| **オフサイトコピー実行中** | 保存先へのコピーが実行中です。`restic copy` は進捗率を報告しないため、パーセントは表示されません。 |

その下に、直近の実行がいつだったかと、次の予定の実行がいつ始まるかが表示されます。

## 要対応 {#needs-you}

このカードには、確認すべきことが新しい順に並びます。何もないときは **対応は不要です。** と表示されます。各行には、それぞれの対処方法があります。

- **失敗したバックアップ**には、項目名とその理由が出ます。**エラーを表示**で restic 自身の出力を確認でき、**再試行**でバックアップをもう一度開始します。
- **オフサイトコピーに失敗**には、セクション名と、いつから失敗しているかが出ます。**今すぐ複製**でもう一度試します。
- **plex で異常**は、**確認**で該当する検出結果に移動します。重大な検出結果が未処理のあいだは、保持ルールがその項目の古いバックアップを残します。
- **新規**の項目は、BombVault が見つけたもののまだ何もバックアップしていないもの（インストールしたばかりのコンテナなど）で、**バックアップを開始**または**バックアップしない**を選べます。
- **あきらめたバックアップ**は、対象のアプリが待機時間のあいだずっとビジー状態だったものです。[アプリがビジーのとき](backups.md#app-busy)を参照してください。
- **失敗した ZFS レプリカ**は、サーバーに zfs コマンドがないなど、平易な言葉で理由が示され、サーバーの出力は**表示**から見られます。
- **バックアップが停止中です：鍵を開けなくなりました**は、このサーバーがほかのサーバーの鍵を引き継いだあとで `APP_KEY` が変わった場合に表示されます。[トラブルシューティング](troubleshooting.md#backups-stopped-and-say-the-key-can-no-longer-be-opened)を参照してください。
- **リカバリーキットを保存してください**は、キットをダウンロードして**安全に保管しました**を押すまで残ります。

## 保護状況 {#protection-status}

オンになっているセクションごとに、4 つのチェックを持つ行があります。

| チェック | 緑になる条件 | ほかに表示される言葉 |
|---|---|---|
| **ローカル** | 直近のバックアップが最新である | バックアップがまだない、スケジュールがない、直近の実行が失敗、バックアップが遅れている、すべての項目が保護されているわけではない、バックアップがまもなく期限 |
| **オフサイト** | 設置場所の外への直近のコピーが最新である | オフサイトコピーなし、コピー実行中、コピーが遅れている、判断待ち、まだコピーなし、レプリカが失敗 |
| **削除に対する保護** | 改ざんテストで、相手側が削除を拒否することが証明された | なし、なし（リスクを承認済み）、まだ証明されていない、テストが失敗、チェックがオフのため証明されていない |
| **テスト復元** | オフサイトのコピーからの復元に成功した | 未実行、実行中、失敗、遅れている、手動のみ、このセクションでは不可 |

セクションは、検証された事実だけで緑になります。このサーバー上のコピーはオフサイトとは見なされません。また、**削除に対する保護なしで承認**とした保存先は、琥珀色のドットではなくグレーのリングで表示されるため、セクションの色はほかのチェックの結果に従います。

スケジュールされたセクションは、プランが最後に設定された時点から数えて最初の実行の期限が来るまで、**まだバックアップがありません**と表示され、中立のままです。その後は**期限切れ**と表示され、一度だけ通知します。**期限切れ**は、自分のプランから最も遅れている項目で判断するので、動いている隣の項目が、止まった項目を隠すことはありません。コンテナがなくなった項目や、どのスケジュールも届かない項目は数えません。独自の週次プランを持つ項目は、セクションの毎日のプランでは判断されません。スケジュールがどの項目にも届かず、バックアップするものがないセクションは**スケジュールなし**と表示され、期限切れになることはありません。

セクションをクリックすると、すべてのチェックの詳細、対象の項目、そして**テスト復元を開始**または**テスト復元をもう一度実行**が入ったウィンドウが開きます。そこには**整理ルール設定済み**または**整理ルール未設定**も表示され、オフサイトのルールだけでなく、セクションの専用フォルダーの保持ルールも数に入ります。

## 保存先 {#storage-locations}

各保存先は、ここでは容器の形で表示されます。充填率、増える速さ（たとえば **週あたり 4.2 GB 増加**）、そのペースで満杯になる時期（たとえば **約 31 週間で満杯**）が分かります。S3、B2、rest-server は残りの容量を報告しないため、**空き容量は不明**と増加量だけが表示されます。クリックすると、その保存先のページに移動します。[保存先](offsite-recovery.md#destinations)を参照してください。

## 履歴 {#history}

**履歴**には 2 つのタブがあります。**実行**には、すべての実行が結果、所要時間、理由とともに並び、クリックすると開きます。**ログ**には、BombVault が書き出した各行が時刻つきで表示され、1 日に絞り込めます。バックアップ自体は完了したものの何かを除外した場合、その行はオレンジ色になり、何を除外したかが書かれます。

## カスタマイズで追加できるカード {#customize}

ページ上部の**カスタマイズ**で、カードを並べ替えられます。カードはバーをドラッグして移動し、右下隅のドットで大きさを変え、非表示にもできます。非表示のカードは**非表示のカード**に控えていて、**表示**で元に戻せます。並べ替え中はカードが少し揺れ、**完了**で終わります。レイアウトはこのブラウザーに保存されます。

次のカードは、最初は非表示になっています。

- **異常**：未処理の検出結果です。[異常](anomalies.md)を参照してください。
- **未バックアップ**：このサーバー上にあって、スケジュールされたバックアップが対象にしていないものすべてを、その理由とともに表示します。理由は、たとえば **一度も追加されていない**、**スケジュールに含まれていない**、**所属セクションの保存先がすべてオフ**などです。コンテナは Docker から直接読み取るため、BombVault がまだ一度も見たことのないものも見つかります。
- **カレンダー**：直近 90 日を、1 日 1 マスで表示します。日付をクリックすると、**履歴**のログのその日の行が表示されます。
- **ストレージ**：各セクションがどれだけの容量を使っているか、データがどれだけうまく重複排除されているかを表示します。
- **概要**：全セクションを通した最も古いスナップショット、次のバックアップの実行時刻、直近のバックアップの結果です。
- **統計**：コンテナと VM の数、エラーの数、有効なプランと一時停止中のプランの数です。
- **ホスト統合**：Docker ソケット、libvirt、restic、rclone など、BombVault がホスト上で到達できるもの、必要とするものです。何かがつながっていないように思えたら、まずここを見てください。

## BombVault の数え方 {#counting}

すべてのカードとステータス欄は、同じ数え方をします。対象は、オンになっているセクションの項目のうち、まだインストールされていて、**バックアップしない**に設定していないものです。項目が保護されていると数えられるのは、スケジュールがその項目に届いていて、かつバックアップがあるあいだだけです。古いバックアップがあるだけでは数えられません。そのため、スケジュールから外したコンテナは、スケジュールに戻すか**バックアップしない**に設定するまで、未保護と表示されます。

## 最初のステップ {#first-steps}

新規インストールの概要は、**最初のステップ**カードから始まります。内容は **セクションを選ぶ**、**保存先を追加**、**最初のバックアップ**です。最初のバックアップが完了するまで表示され続けます。[はじめに](getting-started.md#first-run)で順を追って説明しています。
