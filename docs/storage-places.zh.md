# 存储位置

存储位置是 BombVault 存放备份的地方：此 Unraid 上的一个文件夹、NAS 上的一个共享、云提供商的一个存储桶、一台 rest-server、一个 SFTP 账户或一个 Nextcloud。每个存储位置只需在**设置，存储**中连接一次，它的凭据、保留策略、保护和所在地点都归它所有。各个域（容器、虚拟机、闪存、BombVault 自身的配置、文件集和 ZFS 数据集）随后从这些存储位置中选择：每个域存放在哪里，又复制到哪里。只要 ZFS 域处于开启状态，ZFS 数据集就在“域”卡片上有自己的一行。

## 添加存储位置 {#add-a-place}

**添加存储位置** 会打开一个窗口，每个提供商一个图块，分为三组：云存储、自托管服务，以及 NAS 设备和本服务器。

1. 选择一个图块并填写它的表单。眼睛按钮会显示您输入的机密信息。
2. **测试连接** 会检查该存储位置，不会创建任何东西。它会针对每个域的文件夹报告发现的情况：为空或尚不存在、已有一个 restic 仓库，或者导致失败的错误。
3. 为存储位置命名，提供商的名称已预先填好。对于您自己运行的设备，请回答 **设备在哪里？**。云提供商总是在另一个地点，此 Unraid 上的文件夹总是在这里。
4. **添加** 保存该存储位置。

新的存储位置尚未被任何域使用。在[“域”卡片](#domains)的 **存放于** 或 **复制到** 下选择它，或者在某个项目的卡片上只为该项目选择它。

## 文件夹 {#folders}

存储位置为每个域保留一个文件夹：`container`、`vms`、`flash`、`config`、`files` 和 `zfs`，与默认备份位置使用的名称相同。这些文件夹列在存储位置的详情中，也可以在那里重命名（参见[更改地址](#addresses)）。在某个存储位置没有文件夹的域无法选择该存储位置。

当一个域以两种角色使用同一个存储位置时，第二种角色的文件夹会加上后缀，第一种角色保留原来的文件夹。已经接收某个域副本的存储位置，会把直接发送给它的项目存放在 `<folder>-direct` 中；已经存放某个域的存储位置，会在 `<folder>-copies` 中接收该域的副本。

有些存储位置本身就是一个 restic 仓库：添加时地址上已有仓库的存储位置、来自现有设置的命名仓库，或者位于存储桶根目录的复制目标。这样的存储位置没有文件夹，所有域共用它的那一个仓库，它也不承担第二种角色。要在同一提供商处存放更多内容，请把另一个存储桶或文件夹连接为单独的存储位置。

## 存储位置详情 {#details}

每个存储位置是一行，显示它的提供商、用途以及最近一次测试或复制。**测试** 会检查该存储位置上的每个地址，**详情** 会打开它的设置。详情中的每项更改都会在您修改时立即保存。

- **常规**：名称、开启和关闭该存储位置的开关、地址，以及对于您自己运行的设备，**设备在哪里？**（参见[场外](#off-the-premises)）。
- **保留**：保留最近、每天、每周和每月，适用于该存储位置上的每个仓库。新的存储位置从默认规则开始；所有规则都为零的存储位置从不精简。
- **保护**：**Append-only** 开关。append-only 必须由远端强制执行；开关打开后，BombVault 绝不会在那里清理或删除。在开启了 append-only 的 rest-server 上，**测试 append-only** 会对该存储位置上的每个域路径、已开启的副本和仓库运行篡改测试，并为整个存储位置显示一个答案：*删除被拒绝* 或 *删除被接受*（参见[异地与恢复](offsite-recovery.md)）。只有远程存储位置才有这一部分，因为本机上没有任何东西能阻止本地仓库被删除。
- **访问**：凭据，以及 S3 的存储类别。使用共享凭据的存储位置会在第一次更改时获得一套自己的凭据。该存储位置上的直接仓库如果无法用新凭据打开，就会保留旧凭据，保存结果会说明这一点。文件夹、SFTP 和 rclone 存储位置没有这一部分。
- **限制**：上传和下载速率以及增长预算。
- **文件夹**：每个域一个开关，附带其文件夹的名称。在这里关闭的域无法选择该存储位置。

降低保留策略之前会先询问，并说明这会影响多少个项目；关闭 append-only 之前会先询问，并说明该存储位置上有多少个仓库会失去它。关闭一个存储位置会关闭其上的每个仓库；有域存放在其中的存储位置无法关闭。

## “域”卡片 {#domains}

该卡片为每个域提供一行，显示它的计划、存放在哪里、复制到哪里以及它的例外。

- **存放于**：当该域的备份位置还没有任何备份时，所选存储位置会成为该域的主存储位置，备份位置也随之移到那里。一旦有了备份，对于容器、虚拟机和文件集，这个选择就成为新项目的默认值，新项目在首次备份时采用它；已有备份的项目留在原处，因为 BombVault 绝不移动备份。对于闪存和 BombVault 自身的配置，主存储位置会移动，已写入的备份则留在旧的存储位置。
- **复制到**：每个可以接收该域副本的存储位置各有一个标签。勾选一个标签，该存储位置就成为该域的复制目标；第一次勾选时，BombVault 会预先说明首次运行将发送多少个项目、多少个快照以及多少数据。取消勾选会停止新的复制：已在那里的副本会保留，并按该存储位置的保留策略老化，自行做出选择的项目也会继续复制到那里。取消勾选最后一个标签会停止所有复制，包括复制到之后添加的存储位置，直到再次勾选某个标签为止。已关闭的存储位置显示为变暗的标签，无法选择。
- **例外**：自行做出选择的项目，以列表形式列出，并链接到它们的卡片。
- **立即复制** 会立即运行该域的复制。

通过 Discover 重建后被暂停的域会在它的行上显示暂停，并提供 **确认默认值**（参见[每个项目的存放位置](offsite-recovery.md#placement)）。

## 更改地址 {#addresses}

域的文件夹可以在存储位置的详情中更改，本地存储位置的地址也可以，例如在手动把仓库移到另一块磁盘之后。BombVault 会测试此更改涉及的每个地址，并在以下两种情况下接受更改：每个新地址都为空且旧地址上没有存放任何内容，或者每个新地址都包含与旧地址相同的 restic 仓库。其他情况一律拒绝，并给出仍在旧地址上的备份数量。远程存储位置的地址保持不变；要备份到别处，请把那里连接为单独的存储位置。

BombVault 根据自己的数据库构建存储位置列表，绝不会为了填充列表而列出远程仓库；测试只在您更改某些内容时运行。

## 移除存储位置 {#remove}

只有在没有任何东西使用某个存储位置时才能移除它：没有域存放在那里，没有默认值指向它，没有项目存放在那里，其上的直接仓库也没有存放任何项目。否则，拒绝消息会列出占用它的内容。移除时会一并移除它的复制目标，以及它自己的凭据，除非有拉取来源或其他存储位置在使用这些凭据。存储本身中的内容不会被删除，确认框会说明有多少副本留在那里。

## 无存储位置 {#without-a-place}

不符合“存储位置加文件夹”形式的地址会继续工作，并连同其地址列在 **无存储位置** 下。原生的 `b2:`、`gs:` 和 `swift:` 地址就属于这一类。**分配到存储位置** 会在经过与[更改地址](#addresses)相同的测试后，把这样一行关联到某个存储位置。没有存储位置的复制目标也会在其所属域的行上、标签旁边列出，并继续复制。那里的远程行有自己的 **Append-only** 开关，关闭它之前会先询问，并给出在该地址保存备份的项目数量。直接仓库跟随其目标的开关。

## 场外 {#off-the-premises}

**设备在哪里？** 有两个答案：**就在同一栋楼里** 和 **在另一个地点**。只有当副本所在的存储位置位于另一个地点时，它才算作一个独立的站点，这适用于卡片上的 3-2-1 行和仪表板的异地检查。同一栋楼里的第二块磁盘或 NAS 只是第二份副本，而不是第二个站点。这个答案不会改变任何副本。云提供商总是在另一个地点，此 Unraid 上的文件夹总是在这里，因此表单不会为它们询问；对于其他每个存储位置，请在其详情中更改答案。位于另一个地点的存储位置会在它的行上带有 **另一个地点** 标记。

## 连接类型

### 此 Unraid 上的文件夹或 NAS {#kind-local}

地址是 `/mnt` 下的一个路径，书写时不带 `/mnt`，例如 `user/bombvault`，每个域的文件夹位于它之下：`user/bombvault/container`。

- **此 Unraid 上的文件夹** 从共享、磁盘和存储池中选择。
- **Synology**、**QNAP**、**TrueNAS**、**另一台 Unraid** 和 **其他共享** 从 `/mnt/remotes` 中选择。请先在 Unraid 上挂载该共享，例如使用 Unassigned Devices 插件。Host Data 必须以 Read/Write - Slave 方式挂载，否则在 BombVault 启动之后才挂载的共享在重启之前一直不可见（参见[配置](configuration.md)）。

文件夹选择器可以用 **新建文件夹** 在当前所在位置创建文件夹。测试会检查该文件夹为空或不存在，以及 BombVault 能够在那里写入。

### S3 {#kind-s3}

地址是 `s3:https://<endpoint>/<bucket>/<path>`，例如 `s3:https://s3.eu-central-003.backblazeb2.com/tower-backups/bombvault`。

- **Backblaze B2** 只需要密钥 ID 和应用程序密钥。BombVault 会向 B2 询问该密钥限定的存储桶、S3 端点和文件夹，并据此构建地址。可以访问所有存储桶的密钥会列出它的存储桶供您选择。
- **Amazon S3**、**Cloudflare R2**、**Wasabi**、**Hetzner Object Storage**、**Storj**、**IDrive e2**、**Scaleway**、**OVHcloud**、**DigitalOcean Spaces**、**IONOS**、**Contabo**、**Exoscale** 和 **Vultr** 会要求填写密钥，并在提供商需要时要求填写区域、账户 ID 或端点。BombVault 会填入端点，并在密钥有权列出存储桶时列出它们；否则请输入存储桶的名称。
- **Google Cloud Storage** 通过其 S3 接口使用 HMAC 密钥访问，该密钥在 Cloud Storage 设置的“互操作性”（Interoperability）下创建。服务账号文件在这里不起作用。
- **MinIO**、**SeaweedFS**、**Garage**、**Ceph**、**JuiceFS**、**RustFS**、**Versity S3 Gateway** 和 **其他 S3 服务** 需要填写该服务的地址和一个密钥。

存储类别在存储位置的详情中设置，仅限于无需解冻即可还原读取的层级。

### rest-server {#kind-rest}

地址是 `rest:<url>/<user>`，例如 `rest:https://nas.lan:8000/tower`。表单会要求填写服务器地址、用户名和密码。使用 `--private-repos` 时，用户只能访问以自己名称开头的路径，因此除非您输入了其他路径，BombVault 会把用户名放在最前面。当服务器拒绝用户自有路径之外的路径时，错误信息会说明这一点。

rest-server 表单附带一份可直接粘贴的配方，用于搭建一台 append-only 模式的 rest-server，其中为这个 BombVault 准备了一个用户。**显示配方** 会生成一个只显示一次的密码，并给出一行 `docker run`、一个 compose 文件和一个 Unraid 模板，每一种都附带要放到服务器上的 `htpasswd` 行；用户名和密码会直接填入表单。

**另一个 BombVault** 会在自己的字段上方列出其他实例通过舰队发来的待接受提议。接受其中一个会添加一个只保存所提供域副本的存储位置，因为一个提议只携带用于该域的一个用户。在舰队页面上接受会添加同一个存储位置。

### SFTP {#kind-sftp}

地址是 `sftp://<user>@<host>:<port>/<path>`，例如 `sftp://bv@backup.lan:22/bombvault`。表单会要求填写主机、端口和用户名，并显示 BombVault 的公钥。请把该密钥添加到服务器上该用户的 `~/.ssh/authorized_keys`；服务器上无需安装其他任何东西。BombVault 在首次连接时接受服务器的主机密钥，此后每次都会核对它。

**Hetzner Storage Box** 会填入 `<user>.your-storagebox.de` 和端口 23。用 Hetzner 自己的命令把密钥安装到 Storage Box 上，该命令会询问一次 Storage Box 的密码：

```sh
echo '<public key>' | ssh -p 23 <user>@<user>.your-storagebox.de install-ssh-key
```

### WebDAV：Nextcloud、ownCloud、OpenCloud {#kind-webdav}

表单会要求填写服务器地址、用户名和应用密码。请在账户的安全设置中创建应用密码，并输入用户 ID 而不是电子邮件地址。BombVault 会构建该产品使用的 WebDAV 路径，并通过 rclone 的环境变量把连接交给 restic，密码采用 rclone 的混淆形式。地址形如 `rclone:bvp<id>:<path>`，其中 `bvp<id>` 是一个只存在于该环境中的远程；rclone 配置中不会写入任何内容。

### Azure Blob {#kind-azure}

地址是 `azure:<container>:/<path>`。表单会要求填写存储账户及其访问密钥；**测试连接** 之后，它会列出该账户的容器供您选择，您也可以输入容器的名称。BombVault 以 `AZURE_ACCOUNT_NAME` 和 `AZURE_ACCOUNT_KEY` 把账户和密钥传给 restic。

### rclone {#kind-rclone}

地址是 `rclone:<remote>:<path>`。表单会列出 BombVault rclone 配置中的远程供您选择。要替换该配置，请在 **rclone 配置** 下粘贴完整的 `rclone.conf`，然后点击 **保存配置**。它会立即保存，并用于每个 rclone 存储位置，无论该窗口随后是否添加存储位置。

## 凭据不同的存储位置之间的复制 {#different-credentials}

存放在远程存储位置的域是其副本的来源。`restic copy` 只在一个环境中运行，当来源和目标没有把同一个变量设为不同的值时，BombVault 会把来源的凭据添加到目标的凭据中。Nextcloud 存储位置和 B2 存储位置使用不同的变量，因此存放在 Nextcloud 中的域可以复制到 B2。两个 S3 账户或两个 rest-server 用户需要让同样的变量取不同的值；restic 无法同时接受两者，“域”卡片上的标签会说明凭据不匹配。
