# 通知

BombVault は、バックアップが失敗したとき、成功したとき、遅れているとき、そして週に 1 回、状況のまとめを知らせることができます。設定はすべて **設定、通知** にあります。個々のバックアップ以外に BombVault が何を送るかは**通知**カード、メッセージの送り先は**チャンネル**カードで決めます。いつ知らせるかはチャンネルごとに決まり、Healthchecks のチェックもチャンネルの 1 つです。

![Gotify チャンネルを入力した設定、通知。](assets/screenshots/notifications/gotify-light.png#only-light)

## メッセージが送られる条件 {#what}

**通知**カードのスイッチは、すべてのチャンネルに適用されます。

- **スケジュール実行をまとめて通知**：コンテナや VM ごとではなく、スケジュール実行 1 回につき 1 通のメッセージにします。たとえば *45 件中 42 件が成功* のようにです。手動で開始したバックアップは、これまでどおり単独でメッセージを送ります。凍結したゲスト、失敗した保持処理、超過した増加予算は、まとめ通知がオンでもすぐに送られます。
- **コンテナ更新時に通知**：**バックアップ成功後にコンテナを更新**で新しいイメージに更新されたコンテナごとに 1 通のメッセージを送るので、まだ動いていることを確認できます。
- **遅延したバックアップを報告**：1 日 1 回 09:00 に、オンになっているバックアップが遅れていないか（スケジュールの 2 倍より古いかどうか）を確認し、該当するたびに、遅れた項目の名前を挙げて 1 通のメッセージを送ります。次にバックアップが成功すると解消されます。
- **週次ダイジェスト**：実行回数、新しいバックアップデータ、遅れているセクション、オフサイトコピーが最新かどうか、主な失敗をまとめた週 1 回のまとめ。プランはほかのプランと同じボタンで、**オフ**で切れます。[スケジュール](schedules.md#plans)を参照してください。

成功も知らせるかどうかは、チャンネルごとに**通知する**で決めます。どの異常がメッセージを送るかは **設定、検証** で決めます。[異常](anomalies.md)を参照してください。延期されたバックアップは、待機を始めたときに 1 通、待機が終わったときに 1 通のメッセージを送り、試行ごとには送りません。

## チャンネル {#channels}

**チャンネル**カードの下にある**チャンネルを追加**では、**Unraid 通知**、**ntfy**、**Gotify**、**Discord**、**Slack**、**Matrix**、**メール (SMTP)**、**Apprise**、**Webhook**、**Healthchecks** を選べます。いくつでも追加でき、同じ種類を 2 つ置くこともできます。たとえば、失敗用の ntfy トピックと、すべてを受け取るトピックを分けられます。新しいチャンネルはオフで始まるので、フィールドを入力する前から保存されます。

各チャンネルには次のものがあります。

- 専用のスイッチ。オフにしても、入力したフィールドは消えません。
- **通知する**：**なし**、**失敗時のみ**、**成功時と失敗時**のどれか。新しいチャンネルは**失敗時のみ**から始まります。成功したものの一部が抜けたバックアップも、失敗時のみのチャンネルに届きます。
- **名前**：任意で、種類の代わりに表示されます。同じ種類が 2 つあるときに便利です。
- **テスト送信**：保存したかどうかに関係なく、フォームの現在の値で、このチャンネルからテストメッセージを送ります。チャンネルの下の行に、サービスが受け取ったかどうかと、受け取らなかった理由が表示されます。
- **チャンネルを削除**：横にあるごみ箱です。

各チャンネルは独自のタイムアウトで単独に送信するため、応答しないホストが 1 つあっても、ほかのチャンネルは待たされません。再試行で直りそうな失敗なら、チャンネルは最大 3 回まで試します。どのチャンネルにも受け取られなかった遅延、予算、異常のアラートは後で再送され、週次ダイジェストも同様です。

| チャンネル | フィールド | 備考 |
|---|---|---|
| **Unraid 通知** | なし | Unraid 自身の通知システムに送信します。そこから Pushover、メール、Discord へ転送できます。**設定、連携、ホスト SSH** の SSH 接続経由で動作するため、その鍵が承認されている必要があります。TrueNAS やほかのホストでは何も送らず、チャンネルにその理由が表示されます。 |
| **ntfy** | **トピック URL**、**アクセストークン（任意）** | アドレスの最後がトピック名です。トークンが必要なのは、保護されたトピックだけです。 |
| **Gotify** | **サーバー URL**、**アプリトークン**、**失敗時の優先度**、**成功時の優先度** | 優先度は 0 から 10 で、標準は失敗が 8、成功が 5 です。 |
| **Discord** | **Webhook URL** | Discord チャンネルの設定で作った Webhook のアドレスです。 |
| **Slack** | **Webhook URL** | Slack アプリの Incoming Webhook のアドレスです。 |
| **Matrix** | **Homeserver URL**、**アクセストークン**、**ルーム ID** | トークンのアカウントがルームに参加している必要があります。 |
| **メール (SMTP)** | **SMTP ホスト**、**ポート**、**暗号化**、**ユーザー名**、**パスワード**、**送信元アドレス**、**宛先アドレス** | **暗号化**は **STARTTLS**、**TLS (implicit)**、**None** のどれかです。 |
| **Apprise** | **Apprise API の URL**、**タグ（任意）**、**Apprise アドレス（任意）** | Apprise API コンテナの `/notify/<key>` エンドポイントを指定すると、100 以上のサービスに届きます。タグで、そのキーの宛先の一部だけを選べます。または Apprise アドレスを 1 行に 1 つずつ書き、API の URL はキーを付けずに `/notify` で終えます。たとえば Telegram なら `tgram://`、Pushover なら `pover://` です。 |
| **Webhook** | **Webhook URL**、**メソッド**、**ヘッダー**、**本文** | 自分で組み立てるリクエストです。[Webhook](#webhook)を参照してください。 |
| **Healthchecks** | **ping URL** | [Healthchecks](#healthchecks)を参照してください。 |

トークン、SMTP のパスワード、Webhook ヘッダーの値などのシークレットは暗号化して保存され、サーバーがページに返すことはありません。保存済みのシークレットのフィールドの下には **保存済みです。そのままにするには空欄のままにします。** と表示されます。チャンネルの送信先を変えると、BombVault は古いシークレットを新しい宛先に送りません。フィールドには **ここをもう一度入力すると、新しいアドレスが保存されます。** と表示されます。

チャンネル一覧より前のバージョンの設定は、初回起動時に引き継がれ、何も失われません。入力済みだったチャンネルは、それぞれ独立した項目になり、以前の**通知する**の選択もそのまま残ります。Discord、Slack、Gotify、ntfy 形式の Webhook はその種類のチャンネルになり、Generic JSON の Webhook は**本文**を通して、これまでどおり `title`、`message`、`ok` を POST します。Unraid のスイッチは Unraid チャンネルに、Healthchecks の URL と例外は Healthchecks チャンネルになります。

### Webhook {#webhook}

**Webhook** チャンネルは、任意のアドレスに HTTP リクエストを 1 回送ります。**メソッド**は GET、POST、PUT のどれかです。**ヘッダーを追加**で**ヘッダー**に行が増えます。ヘッダーの値はシークレットとして保存されるので、`Authorization` ヘッダーも安心して置けます。**本文**は書いたとおりに送られ、次のプレースホルダーが値に置き換わります。

| プレースホルダー | 置き換わる値 |
|---|---|
| `%%title%%` | メッセージのタイトル |
| `%%body%%` | メッセージ本体 |
| `%%ok%%` | `true`、失敗なら `false` |
| `%%event%%` | 起きたこと。たとえば `container.failed` |
| `%%severity%%` | `info`、`success`、`warning`、`failure`、`critical` |
| `%%importance%%` | それに当たる Unraid のレベル：`normal`、`warning`、`alert` |
| `%%link%%` | メッセージに関係するリンク。なければ空 |
| `%%key%%` | セクション。たとえば `container` や `VM` |
| `%%time%%` | UTC の時刻。たとえば `2026-11-09T03:00:00Z` |
| `%%source%%` | `BombVault` |

プレースホルダーはアドレスやヘッダーの値でも使え、値は置かれた場所に合わせてエスケープされます。`Content-Type` ヘッダーが JSON を示していれば JSON として、アドレスの中ではクエリの値としてです。新しい Webhook には最初からこのヘッダーが入っていて、`{"title":"%%title%%","message":"%%body%%","ok":%%ok%%}` を POST します。BombVault が知らない名前は書いたまま残るので、打ち間違いはメッセージで分かります。何も送らないなら、**本文**を空にします。

## Healthchecks {#healthchecks}

[Healthchecks.io](https://healthchecks.io) などのサービスは、BombVault からのチェックインが途絶えるとアラームを出します。**Healthchecks** チャンネルを追加してチェックの **ping URL** を貼り付けると、BombVault はすべてのバックアップのライフサイクル全体にわたって ping を送ります。開始時、そして成功時、または `/fail` 付きで失敗時です。このチャンネルには**通知する**の選択がありません。チェックを緑に保つには、成功の ping が欠かせないからです。バックアップ先がどこにもないセクションは失敗として数えるので、そのチェックは成功の知らせを受ける代わりに赤になります。

同じ URL を使うセクションは、1 つのチェックを共有します。そのうち 1 つのバックアップが失敗すると、ほかのセクションの正常なバックアップも `/fail` で ping を送り、失敗したものの名前を伝えます。そのため、その項目にもう一度正常なバックアップができるか、**要対応**で失敗を確認済みにするまで、チェックは赤のままです。

セクションは専用のアドレスに ping を送ることもできます。Healthchecks チャンネルの**例外**で追加でき、その行には **それ以外のすべてのセクションがこの URL に ping を送ります。** と表示されます。**テスト送信**は各チェックのログに記録を 1 件残し、状態はそのままです。

## 例：スマートフォンで Gotify {#example-gotify}

`https://gotify.example.com` で Gotify を動かしていて、失敗はスマートフォンで音を鳴らし、成功は静かに届くようにしたいとします。

1. Gotify で**アプリ**を開き、`BombVault` というアプリケーションを作成して、そのトークンをコピーします。
2. BombVault で **設定、通知** を開き、**スケジュール実行をまとめて通知**をオンにします。45 件のバックアップがある夜でも、45 通ではなく 1 通だけ送られます。
3. **チャンネル**で**チャンネルを追加**を押し、**Gotify** を選びます。
4. **サーバー URL** に `https://gotify.example.com` を入力します。`/message` は BombVault が自分で追加します。
5. トークンを**アプリトークン**に貼り付けます。
6. **通知する**を**成功時と失敗時**にします。**失敗時の優先度**は 8、**成功時の優先度**は 5 のままにします。Gotify の Android アプリは 8 以上を高優先として扱うので、音が鳴るのは失敗のときだけです。
7. チャンネルをオンにして**テスト送信**を押します。チャンネルの下の行に、Gotify が受け取ったかどうかが表示され、トークンが拒否された場合はそう表示されます。

次のスケジュール実行では、優先度 5 で 1 通のまとめが送られます。その中に失敗があれば、優先度 8 になります。

## 例：アカウントなしで ntfy {#example-ntfy}

ntfy は、公開トピックならアカウントが不要です。トピック名は推測されにくいものにしてください。知っている人は誰でも読めてしまうからです。

1. **チャンネル**で**チャンネルを追加**を押し、**ntfy** を選びます。
2. **トピック URL** にトピックのアドレスを入力します。たとえば `https://ntfy.sh/bombvault-tower-7f3k` や、自分の ntfy サーバー上のトピックです。公開トピックなら、**アクセストークン（任意）** は空のままにします。
3. ntfy アプリで同じトピックを購読し、チャンネルをオンにして**テスト送信**を押します。

BombVault は、メッセージを本文として、タイトルを `Title` ヘッダーに入れて POST します。失敗は優先度 high とタグ `warning` で送られるため、アプリの中で目立ちます。凍結したままの VM は urgent で送られます。
