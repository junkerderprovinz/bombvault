# BombVault

**Τα δεδομένα σας στο Unraid, σφραγισμένα σε ένα θησαυροφυλάκιο. Ρίξτε ένα αντίγραφο ασφαλείας. Πυροδοτήστε μια επαναφορά.**

![Η επισκόπηση: η κεφαλίδα κατάστασης, τι χρειάζεται προσοχή, η προστασία κάθε τομέα, οι προορισμοί αποθήκευσης και το ιστορικό.](assets/screenshots/overview/home-dark.png#only-dark)
![Η επισκόπηση: η κεφαλίδα κατάστασης, τι χρειάζεται προσοχή, η προστασία κάθε τομέα, οι προορισμοί αποθήκευσης και το ιστορικό.](assets/screenshots/overview/home-light.png#only-light)

Το BombVault είναι μια αυτο-φιλοξενούμενη εφαρμογή ιστού για **αντίγραφα ασφαλείας και πλήρη ανάκτηση από καταστροφή** στο Unraid και σε άλλους hosts Docker, όπως το TrueNAS SCALE, το ZimaOS ή ένα απλό Linux. Παίρνει αντίγραφα από Docker containers, KVM/libvirt VMs, φακέλους, σύνολα δεδομένων ZFS και το flash του Unraid. Εκτελείται ως ένα μοναδικό multi-arch Docker container, σας δίνει μια διεπαφή ιστού με σκοτεινό, φωτεινό ή θέμα συστήματος και διαχειρίζεται όλον τον κύκλο ζωής: αντίγραφο, χρονοπρογραμματισμός, επαλήθευση και επαναφορά.

Οι επαναφορές είναι αυτόματες. Στο Unraid τα containers εμφανίζονται ξανά στην καρτέλα Docker ακριβώς όπως πριν, και οι VMs επαναορίζονται στον VM Manager με τους δίσκους τους και το UEFI NVRAM επανασυνδεδεμένα. Καμία χειροκίνητη επανεγκατάσταση, καμία εκ νέου διαμόρφωση, καμία ταλαιπωρία. Στο TrueNAS ένα container που επαναφέρεται δίπλα στο πρωτότυπο τρέχει ως απλό container Docker, που η οθόνη Apps δεν το απαριθμεί.

Στηρίζεται στο [restic](https://restic.net), οπότε κάθε αντίγραφο ασφαλείας είναι απαλλαγμένο από διπλότυπα (deduplicated), αυξητικό (incremental) και κρυπτογραφημένο από προεπιλογή.

!!! note "Κρατήστε το APP_KEY σας ασφαλές"
    Το BombVault παράγει τον κωδικό του αποθετηρίου restic από ένα μυστικό 32 byte με το όνομα `APP_KEY`. Η απώλειά του μαζί με το κιτ ανάκτησης καθιστά τα κρυπτογραφημένα αντίγραφα ασφαλείας μη ανακτήσιμα. Δημιουργήστε ένα με `openssl rand -hex 32` και αποθηκεύστε το σε ασφαλές μέρος. Δείτε [Διαμόρφωση](configuration.md).

## Τι προστατεύει το BombVault {#what-bombvault-protects}

Κάθε container, VM, σύνολο φακέλων, το flash, κάθε σύνολο δεδομένων ZFS και οι ίδιες οι ρυθμίσεις του BombVault είναι ένα **στοιχείο** με δική του σελίδα. Τα στοιχεία του ίδιου είδους σχηματίζουν έναν **τομέα**, που τον ενεργοποιείτε στις **Ρυθμίσεις, Γενικά**.

| Τομέας | Τι αποθηκεύεται |
|---|---|
| **Κοντέινερ** | Ο κατάλογος appdata μαζί με τον ορισμό του container (image, μεταβλητές περιβάλλοντος, θύρες, ετικέτες, τόμοι). |
| **VMs** | Οι εικόνες δίσκου της VM, ο ορισμός XML και το UEFI NVRAM, με αντίγραφο μέσω SSH (χωρίς προσάρτηση libvirt). |
| **Flash** | Ολόκληρο το USB flash (`/boot`): λειτουργικό, άδεια, διαμόρφωση array, κοινόχρηστοι πόροι, δίκτυο και διαμόρφωση plugin. |
| **Αυτο-αντίγραφο** | Το ίδιο το `/config` του BombVault: η βάση ρυθμίσεών του, τα διαπιστευτήρια των προορισμών του και το ζεύγος κλειδιών SSH του libvirt. |
| **Φάκελοι** | Οποιοσδήποτε φάκελος στον διακομιστή ως σύνολο φακέλων, το καθένα με προαιρετικά μοτίβα εξαίρεσης. |
| **Σύνολα δεδομένων ZFS** | Ένα σύνολο δεδομένων και όλα όσα βρίσκονται από κάτω του, διαβασμένα από ένα στιγμιότυπο ZFS και αποθηκευμένα σαν φάκελος. Δείτε [Σύνολα δεδομένων ZFS](zfs-datasets.md). |

## Η επαναφορά είναι ο πρωταγωνιστής {#restore-is-the-star}

Αφού αντιγράψει τα δεδομένα πίσω από το στιγμιότυπο restic, το BombVault αναπαράγει τον αποθηκευμένο ορισμό του container έναντι του Docker API, ώστε το container να εμφανιστεί ξανά στην καρτέλα Docker του Unraid σαν να ήταν πάντα εκεί (ίδιο image, ίδιες ρυθμίσεις, ίδιες αντιστοιχίσεις θυρών). Οι VMs αποκτούν εκ νέου ορισμό του XML τους μέσω SSH και τους δίσκους τους και το UEFI NVRAM επανασυνδεδεμένα, ακόμη και μετά τη διαγραφή της VM.

Ένα παράθυρο επαναφέρει κάθε είδος. Από προεπιλογή διαλέγει **Δίπλα στο πρωτότυπο**, που φέρνει πίσω το αντίγραφο ως αντίγραφο και αφήνει το πρωτότυπο ως έχει. Η **Αντικατάσταση πρωτοτύπου** δημιουργεί πρώτα αντίγραφο ασφαλείας της τρέχουσας κατάστασης, ώστε μια επαναφορά να μπορεί να αναιρεθεί. Ένας φάκελος ή ένα νέο σύνολο δεδομένων ZFS είναι οι άλλοι προορισμοί.

Όταν ένα αντίγραφο ασφαλείας σταματά εξαρτημένα containers, αυτά επανέρχονται με τη σωστή σειρά: το BombVault τα επανεκκινεί με τη σειρά `depends_on` του Compose και περιμένει το καθένα να αναφέρει ότι είναι υγιές πριν ξεκινήσει εκείνα που εξαρτώνται από αυτό, ώστε τίποτα να μην τρέχει μπροστά από μια βάση δεδομένων ή μια πύλη που δεν έχει ακόμη σηκωθεί. Δείτε [Επαναφορά](restore.md) και [Εντολές και άλλα containers](backups.md#commands).

## Πώς λειτουργεί {#how-it-works}

```
Browser --HTTPS--> BombVault container
                   |- Go binary: JSON API + embedded React UI
                   |- Background worker (per-section scheduler + job executor)
                   |
                   |- /var/run/docker.sock  -> Docker API (container stop/inspect/recreate)
                   |- qemu+ssh://host       -> libvirt / KVM on the HOST over SSH (no mount)
                   |- /mnt/ -> /host/user   -> appdata, VM disks + restic repos (read/write)
                   |- /boot/ -> /host/boot  -> Unraid flash backup (whole USB)
                   |- /config               -> BombVault's own settings + sign-ins (self-backup)
                   '- <repo path>           -> restic repository (local or remote: rclone/s3/rest/sftp)
```

Το BombVault χρησιμοποιεί το Docker socket για να σταματά τα containers πριν από ένα αντίγραφο και να τα αναδημιουργεί μετά από μια επαναφορά. Για τις VMs εκτελεί `virsh` στον host μέσω SSH (`qemu+ssh://`) για να τερματίσει ομαλά ένα domain ή να πάρει ζωντανό στιγμιότυπο. Δεν κάνει ποτέ bind mount σε καμία διαδρομή libvirt, οπότε δεν μπορεί να μπει εμπόδιο στον VM Manager του host.

Το BombVault είναι το επίπεδο ενορχήστρωσης και διεπαφής, όχι η μηχανή αποθήκευσης. Όλη η πραγματική μετακίνηση δεδομένων περνάει μέσω του restic.

## Γρήγορη εκκίνηση {#quick-start}

Καινούριοι εδώ; Πηγαίνετε στο **[Ξεκινώντας](getting-started.md)** για να εγκαταστήσετε το BombVault και να εκτελέσετε το πρώτο σας αντίγραφο, και μετά στήστε το **[Εκτός τόπου & ανάκτηση](offsite-recovery.md)**. Τα **[παραδείγματα βήμα προς βήμα](guides.md)** διασχίζουν τις συνηθισμένες δουλειές από την αρχή ως το τέλος, η σελίδα **[Ρυθμίσεις](settings.md)** απαριθμεί κάθε πλακίδιο, και οι **[Δυνατότητες](features.md)** είναι ο σύντομος κατάλογος όσων κάνει το BombVault.

Κάθε τομέας μπορεί να αντιγράφει σε πολλούς προορισμούς ταυτόχρονα, ένα συζευγμένο BombVault μπορεί να κρατά τα αντίγραφά σας εκτός τόπου σε έναν διακομιστή που αρνείται τις διαγραφές, και ο **Οδηγός έκτακτης ανάγκης** επαναφέρει έναν χαμένο διακομιστή από το κιτ ανάκτησής του, μέσω της ομάδας σας ή με το κλειδί που πληκτρολογείτε. Για να μεταφέρετε τη διαμόρφωσή σας σε νέο μηχάνημα, χρησιμοποιήστε την κάρτα **Εξαγωγή / εισαγωγή ρυθμίσεων**. Δείτε [Εκτός τόπου & ανάκτηση](offsite-recovery.md) και [Διαμόρφωση](configuration.md#portable-settings-export-and-import).

Η **[Εφαρμογή Android](android.md)** φέρνει στο κινητό σας όλους τους διακομιστές της ομάδας σας, με το αρχείο δραστηριότητας όλων τους σε μία οθόνη.

Η τεκμηρίωση υπάρχει σε 26 γλώσσες και η διεπαφή σε 42. Οι σελίδες που δεν έχουν ακόμη μετάφραση εμφανίζονται στα αγγλικά.

## Λέξεις που χρησιμοποιούνται εδώ {#glossary}

Μερικές λέξεις έχουν σταθερό νόημα στο BombVault και σε αυτές τις σελίδες.

| Λέξη | Σημασία |
|---|---|
| **Στοιχείο** | Ένα πράγμα που αντιγράφει το BombVault: ένα container, μια VM, ένα σύνολο φακέλων, το flash, ένα σύνολο δεδομένων ZFS με όσα βρίσκονται από κάτω του, ή οι δικές του ρυθμίσεις. Κάθε ένα έχει δική του σελίδα. |
| **Τομέας** | Όλα τα στοιχεία του ίδιου είδους, όπως τα Κοντέινερ. Τους τομείς τους ενεργοποιείτε στις **Ρυθμίσεις, Γενικά**. |
| **Προορισμός** | Ένα μέρος όπου πηγαίνουν τα αντίγραφα: ένας φάκελος σε αυτόν τον διακομιστή, ένας κοινόχρηστος πόρος, ένας δικός σας διακομιστής ή μια υπηρεσία cloud. Δείτε [Προορισμοί](offsite-recovery.md#destinations). |
| **Τοπικό** | Ο προορισμός σε αυτόν τον διακομιστή που κρατά τους φακέλους των τομέων. |
| **Δικός φάκελος** | Το αποθετήριο στο οποίο γράφει πρώτα ένας τομέας τα αντίγραφά του. Από προεπιλογή βρίσκεται σε αυτόν τον διακομιστή και μπορεί να βρίσκεται σε έναν προορισμό. Δείτε [Ο δικός φάκελος ενός τομέα](offsite-recovery.md#own-folder). |
| **Αντιγραφή** | Ένα αντίγραφο ασφαλείας που αντιγράφεται από τον δικό φάκελο σε άλλον προορισμό με `restic copy`. |
| **Άμεσο αποθετήριο** | Ένα αποθετήριο σε προορισμό εκτός τόπου, στο οποίο τα στοιχεία παίρνουν αντίγραφο απευθείας, χωρίς τοπικό αντίγραφο ενδιάμεσα. Δείτε [Άμεσα αποθετήρια](offsite-recovery.md#direct-repositories). |
| **Διαπιστευτήρια** | Το αποθηκευμένο κλειδί ή κωδικός για μια υπηρεσία S3 ή έναν rest-server. Ένα από αυτά είναι το προεπιλεγμένο. Δείτε [Διαπιστευτήρια](offsite-recovery.md#sign-ins). |
| **Τοποθέτηση** | Ποιοι προορισμοί παίρνουν τα αντίγραφα ενός στοιχείου, ορισμένο στο στοιχείο ή ως προεπιλογή του τομέα του. Δείτε [Τοποθέτηση ανά στοιχείο](offsite-recovery.md#placement). |
| **Ρεπλίκα** | Ένα αντίγραφο ενός στοιχείου ZFS, μπλοκ προς μπλοκ, σε δεύτερο διακομιστή ZFS, που γίνεται με `zfs send`. Στέκεται δίπλα στο αντίγραφο ασφαλείας και δεν το αντικαθιστά. Δείτε [Ρεπλίκα](zfs-datasets.md#replica). |
| **Ρόλος** | Κάτι που κάνει μια εγκατάσταση της ομάδας σας για μια άλλη: Δέκτης, Αντλητής, Διακομιστής ZFS ή Φύλακας κλειδιού. Δείτε [Εγκαταστάσεις και ρόλοι](offsite-recovery.md#roles). |

!!! warning "Έλεγχος του host ισοδύναμος με root"
    Μέσω του Docker socket το BombVault μπορεί να σταματήσει, να αφαιρέσει και να αναδημιουργήσει containers και να διαβάσει/γράψει appdata, και για το αντίγραφο των VMs συνδέεται στον host μέσω SSH για να εκτελέσει `virsh`.
