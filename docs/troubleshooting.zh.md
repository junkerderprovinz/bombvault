# 疑难解答

一份简短的常见问题。完整的虚拟机通过 SSH 主机侧疑难解答表（permission-denied、host-key verification、缺失模板变量等等），参见 GitHub 上的[通过 SSH 备份虚拟机指南](https://github.com/junkerderprovinz/bombvault/blob/main/docs/vm-backup-ssh-setup.md)。

## 有些东西没有正确接线

在概览的**自定义**中添加**主机集成**卡片。主机集成检查会探测每个挂载和 CLI（Docker 套接字、libvirt、restic、qemu-img、rclone）并报告任何缺失的部分，**立即检查**会再运行一次。在怀疑是 bug 之前先从这里开始：缺失的挂载或无法访问的主机会立刻显示出来。

## 我无法访问 Web 界面

BombVault 开箱即用地在端口 `3443` 上提供 HTTPS（自签名证书），因此请打开 `https://<your-unraid-ip>:3443`。接受自签名证书警告，或将 BombVault 置于一个带有你自己证书的反向代理之后。如果你以 `HTTP_ONLY=true` 运行，它会改为在端口 `3000` 上提供纯 HTTP（意在用于一个终止 TLS 的代理之后）。

## 我丢失了我的 APP_KEY

`APP_KEY` 用于派生 restic 仓库密码。没有它，又没有恢复工具包，你的组里也没有密钥托管副本，加密备份就无法恢复。这就是概览在你下载恢复工具包之前一直显示**保存你的恢复工具包**的原因。参见[异地与恢复](offsite-recovery.md#recovery-kit)。请用 `openssl rand -hex 32` 生成密钥，并在依赖任何备份之前把它存放在服务器之外。

## 我忘记了登录密码

在登录页选择**忘记密码？**。BombVault 会把一个 12 位字符的验证码写入它的容器日志（在 Unraid 上：Docker 标签页，BombVault 图标，**Logs**）。请在 10 分钟内连同新密码一起输入。重置还会关闭两步验证、移除所有通行密钥、撤销所有 API 令牌、MCP 密钥和 OAuth 登录、结束所有其他会话，并关闭手机配对。请在**设置、安全**中重新添加通行密钥，在那里重新打开手机配对，并在仍然需要的地方创建新的令牌和密钥。参见[安全模型](configuration.md#login)。

## 备份停了，并提示密钥已无法打开

这台服务器在应急向导中接管了另一台服务器的备份密钥，之后 `APP_KEY` 被改过。被接管的密钥是用旧的 APP_KEY 封存的，所以 BombVault 打不开它，也不会用错误的密钥写入，而是什么都不备份。概览上的**需要处理**会点出它。把 APP_KEY 改回原来的值，或在恢复页面的**紧急**下重新上传恢复工具包。

## 手机停在登录页

只有在**设置、安全**中打开**允许手机用群组的十二个单词配对**时，已配对的手机才会通过组获得会话。重置密码会把它关闭。比服务器旧的应用在更新之前同样得不到会话。通过地址添加的服务器始终会询问密码。

## 虚拟机备份无法连接

虚拟机备份通过 SSH 与 libvirt 通信，绝不是通过挂载。

- 确认主机上已启用 SSH，且 BombVault 的公钥已在 `/root/.ssh/authorized_keys` 中获得授权（设置，集成，主机 SSH 会显示该密钥和一个**测试连接**按钮）。
- 在自定义 `br0.x` 网络上，将 `LIBVIRT_HOST` 设置为你的 Unraid LAN IP（在那里容器无法通过 `host.docker.internal` 访问主机）。启用**Settings, Docker, Host access to custom networks**。
- 如果你更改了 Unraid 的 SSH 端口，请相应设置 `LIBVIRT_SSH_PORT`。
- 在 TrueNAS 上，请用 TrueNAS 自己的 libvirt 套接字设置 `LIBVIRT_URI`，给应用加上 `SETPCAP` 能力，并在 **Credentials, Users** 下把密钥添加给 root（参见 [TrueNAS SCALE](getting-started.md#truenas)）。
- 完整的逐步诊断（可达性测试、VLAN 路由、`Permission denied (publickey)`、`Host key verification failed`）位于[通过 SSH 备份虚拟机指南](https://github.com/junkerderprovinz/bombvault/blob/main/docs/vm-backup-ssh-setup.md)。

## 一次实时虚拟机快照没有运行

实时快照需要虚拟机中安装了 qemu guest agent，以及位于 `/mnt/cache`（或 `/mnt/diskX`）而非 `/mnt/user` 上的磁盘。在一台已关机的虚拟机上，实时会自动回退到优雅。优雅备份会将虚拟机关机、备份磁盘、然后重启它，因此它总是一致的。

## 一份备份以 "repository is already locked" 失败

这通常是容器在操作中途被更新或重启后遗留下来的孤立 restic 锁。BombVault 会检测出确定属于孤立的锁，强制清除并自动重试一次。如果问题依旧，请打开**设置、验证**下的**检查备份**卡片，在受影响分区那一行的**更多**下选择**解锁**，手动清除过期的锁。真正的问题仍会暴露出来，不会被掩盖。重启之后，BombVault 会等到这样的锁十分钟没有刷新。仍在运行的 restic（例如同一仓库上的第二个 BombVault）会每五分钟刷新一次它的锁。

## 我的异地副本在备份后没有发生

异地复制在设计上是尽力而为，因此异地的小故障绝不会让本地备份失败。请检查目标何时复制：它的**复制**卡片会写**每次备份之后**，或者写明它自己的计划；而**设置、计划、按分区的异地副本**可以给某个分区单独的计划。要按需运行，请在**设置、目标**中该分区的**异地副本**卡片里使用**立即复制**，并留意概览的状态头：运行期间它会显示**正在异地复制**。失败的复制会显示在**需要处理**下。

## 一次还原在开始前就中止了

在停止或移除任何东西之前，还原会运行一次预检冲突检查：它会验证容器的静态 IP 和已发布的主机端口是否空闲。如果另一个容器已占用其中之一，它会以一条清晰、可操作的消息中止，而不是留下一个只完成一半的还原。释放冲突的端口或 IP，然后重试。

如果容器的网络不存在，例如因为它的 TrueNAS 应用已被删除，还原前的检查会指出该网络，还原会在做出任何更改之前拒绝执行。在 TrueNAS 中以相同名称重新安装该应用，这会重新创建网络，然后再还原它的数据。

## 一次普通导出失败了，没有写出文件

如果在**设置、系统**中打开了**使用 age 加密导出**，但没有设置有效的接收方，导出会以明确的错误失败，而不是写出明文。请添加有效的接收方（age 公钥或 SSH 公钥），或者在你确实想要明文导出时关闭加密。参见[功能](features.md)。

## 数据库转储失败了

转储失败绝不会让它所在的备份失败；它会作为一次独立的失败运行记录下来，原因会说明要修什么。

- **登录被拒绝。** 转储用容器自己的密码变量登录（`POSTGRES_PASSWORD`、`MARIADB_ROOT_PASSWORD`、`MYSQL_ROOT_PASSWORD` 或它们的 `_FILE` 版本）。请在数据库容器上检查这些变量。若 `_FILE` 变量指向的密钥容器自身的用户读不了，结果也一样。
- **权限不足。** 用随机 root 密码时，转储只能以应用用户身份登录，因此只含那一个数据库；MySQL 8.4 及以上甚至可能直接拒绝。给容器设一个真正的 root 密码，或者关掉它的转储。
- **系统表需要升级。** 当 MariaDB 的系统表来自更旧的版本时，它会拒绝转储（错误 1558）。添加变量 `MARIADB_AUTO_UPGRADE=1` 并重启容器，或在容器内运行一次 `mariadb-upgrade`。
- **没有转储工具。** 精简镜像或自制镜像若没有 `pg_dump`、`mysqldump` 或 `mariadb-dump`，就无法转储。请改用官方镜像，或关掉转储。
- **时间上限。** 一次转储有 `DB_DUMP_MAX_HOURS`（默认 6），它所在的备份有 `BACKUP_MAX_HOURS`，而不再有进展的转储会在 `BACKUP_STALL_HOURS` 之后被切断。最后这种情况多半是应用持有的锁造成的。调高触发的那个上限，或者在应用空闲时再转储。
- **容器处于暂停或正在重启。** 转储要和运行中的服务器对话。如果容器不停重启，原因在它自己的日志里。
- **损坏的转储无法删除。** BombVault 会删除没能完成的转储。若那次删除失败，转储会留在列表里并标记为损坏，你可以在那里删掉它。

## 导入失败了

导入会停止容器，把它的数据目录挪到一边，让镜像在原位创建一个空目录。如果失败发生在导入本身之前的某一步，旧目录会自动放回去。如果是导入本身失败，容器会保留新目录，旧的则留在旁边，名为 `<数据目录>.bombvault-before-import-<时间戳>`；该次运行的错误信息会给出确切路径。

本身就是一个数据集的数据目录（如在 TrueNAS 上）无法改名。这时导入会把目录留在原处，把其中的内容移到旁边保留的目录中，因此上一级数据集需要有容纳它们的空间。导入会在停止容器之前检查这一点。

手动放回的做法：停止容器，把当前的数据目录改名挪开，把保留的目录改回原名，然后启动容器。对于数据集，请移动其中的内容，而不是给目录改名。在 Unraid 上，Shares 标签页的文件管理器就能做到。

## ZFS 数据集备份失败或跳过了某个数据集 {#zfs-datasets}

每个问题都带有方括号中的原因代码，[ZFS 数据集](zfs-datasets.md#reason-codes)页面列出了全部代码及解决办法。最常见的三个：

- **`snapshot-loop`**：Host Data 不传递新的挂载，所以快照没有到达 BombVault。编辑容器，把 Host Data 的 Access Mode 设为 Read/Write - Slave，然后重启 BombVault。
- **`key-not-loaded`**：密钥未加载的加密数据集会被跳过。用 `zfs load-key` 加载密钥并挂载数据集，下次备份就会包含它。
- **`ssh-auth`**：服务器拒绝了 BombVault 的密钥。在备份页面用**查看连接**打开的**与这台服务器的 ZFS 连接**会显示授权它的命令；在服务器上运行一次即可。

## 条目一直停在“学习中 N/10”

大多数异常检查在一个条目成功备份 10 次之后才开始，在**标记为预期之内**之后以及条目的选择变化之后，计数会重新开始。没有计划的条目不会学习，没有 appdata 的容器也没有可学的内容，它的徽章会这样说明。异常页面上的**学习进度**为每个条目显示一个分成十段的圆环。

## 保留策略不再删除某个条目的旧备份

有一个未处理的严重异常在把它们留住：该条目的来源几乎为空、急剧缩小，或者某次备份又重新存了它的大部分数据。从条目上的徽章打开该异常。如果数据缺失或已被加密，先从链接的最近一次良好备份还原。然后确认该异常，或者在变化是你造成的情况下把它标记为预期之内，下次运行就会照常清理。保留预览会把这样的条目标为保留。对于 ZFS 条目，只有异常中点名的数据集保留旧备份，树中的其他数据集照常清理。

## 手动清理提示部分条目被保留

原因相同：清理不会动有此类异常的条目的旧备份，并在消息中点出该条目。其余的一切照常清理。

## 历史导入提示某个仓库无法读取

升级之后，BombVault 会从每个仓库一次性读取之前备份的大小。当时无法访问的仓库，例如停机的异地目标或未挂载的共享，会计入**设置、验证**下的**异常**卡片，并每天重试一次。在此期间，它的条目从新的备份中学习。

## 磁盘空间警告与 Unraid 仪表板不一致

在 Unraid 用户共享（`/mnt/user`）上，可用空间是整个阵列的，而不是单个磁盘的。远程仓库只能通过会报告可用空间的 rclone 远程进行测量；S3、B2、REST 和 SFTP 仓库没有数值，会在 **异常** 卡片中列为未测量。

## AI 助手无法连接

[MCP 服务器](mcp.md#troubleshooting) 页面列出了 MCP 连接地址每个状态码和每种拒绝的含义以及应对方法。

## 容器不断重启或看起来不健康

BombVault 通过自己的 `/api/health` 报告健康/不健康。自动修复工具（例如 Autoheal）可以在引擎卡死时自动重启它。请查看容器日志和**主机集成**卡片，找出根本原因。
