# BombVault

**Ваші дані Unraid, запечатані у сховищі. Скиньте резервну копію. Підірвіть відновлення.**

BombVault, це самостійно розміщуваний, рідний для Unraid вебдодаток для **резервного копіювання та повного аварійного відновлення** ваших контейнерів Docker і віртуальних машин KVM/libvirt. Він працює як один мультиархітектурний контейнер Docker, дає вам вебінтерфейс у темній, світлій або системній темі та охоплює весь життєвий цикл: створення резервних копій, планування, перевірка та відновлення.

Відновлення відбувається автоматично. Контейнери знову з'являються на вкладці Docker в Unraid точно такими, як були, а віртуальні машини перевизначаються у VM Manager з повторно приєднаними дисками та UEFI NVRAM. Без ручного перевстановлення, без переналаштування, без драми.

Працює на основі [restic](https://restic.net), тож кожна резервна копія дедуплікована, інкрементна і завжди зашифрована.

!!! note "Бережіть свій APP_KEY"
    BombVault виводить пароль репозиторію restic з 32-байтового секрету з назвою `APP_KEY`. Його втрата разом із набором для відновлення робить зашифровані резервні копії невідновлюваними. Згенеруйте його командою `openssl rand -hex 32` і зберігайте в безпечному місці. Див. [Конфігурація](configuration.md).

## Що захищає BombVault

Кожен контейнер, віртуальна машина, набір папок, флешка, кожен набір даних ZFS і власні налаштування BombVault є **записом** зі своєю сторінкою. Записи одного виду утворюють **розділ**, який ви вмикаєте в **Налаштування, Загальні**.

| Розділ | Що зберігається |
|---|---|
| **Контейнери** | Каталог appdata плюс визначення контейнера (образ, змінні середовища, порти, мітки, томи). |
| **Віртуальні машини** | Образ(и) диска VM, XML-визначення та UEFI NVRAM, резервуються через SSH (без монтування libvirt). |
| **Flash** | Уся USB-флешка (`/boot`): ОС, ліцензія, конфігурація масиву, спільні ресурси, мережа та конфігурація плагінів. |
| **Автобекап** | Власний `/config` BombVault: його база налаштувань, облікові дані його місць призначення та пара SSH-ключів libvirt. |
| **Папки** | Будь-яка папка на сервері як набір папок, кожен з необов'язковими шаблонами виключень. |
| **Набори даних ZFS** | Набір даних з усіма наборами під ним, прочитаний з одного знімка ZFS і збережений як тека. Див. [Набори даних ZFS](zfs-datasets.md). |

## Відновлення, це зірка

Після копіювання даних назад зі знімка restic BombVault відтворює збережене визначення контейнера через Docker API, тож контейнер знову з'являється на вкладці Docker в Unraid так, ніби завжди там був (той самий образ, ті самі налаштування, ті самі відображення портів). Для VM XML перевизначається через SSH, а їхні диски та UEFI NVRAM повторно приєднуються, навіть після того, як VM була видалена.

Одне вікно відновлює будь-який вид. Типово воно вибирає **Поруч з оригіналом**: резервна копія повертається як копія, а оригінал лишається без змін. **Замінити оригінал** спершу створює копію поточного стану, тож відновлення можна скасувати. Інші цілі: папка або новий набір даних ZFS.

Коли резервне копіювання зупиняє залежні контейнери, вони повертаються в правильному порядку: BombVault перезапускає їх у порядку `depends_on` з Compose і чекає, поки кожен повідомить про справність, перш ніж запускати ті, що від нього залежать, тож ніщо не випереджає базу даних чи шлюз, який ще не піднявся. Див. [Можливості](features.md).

## Як це працює

```
Browser --HTTPS--> BombVault container
                   |- Go binary: JSON API + embedded React UI
                   |- Background worker (per-section scheduler + job executor)
                   |
                   |- /var/run/docker.sock  -> Docker API (container stop/inspect/recreate)
                   |- qemu+ssh://host       -> libvirt / KVM on the HOST over SSH (no mount)
                   |- /mnt/ -> /host/user   -> appdata, VM disks + restic repos (read/write)
                   |- /boot/ -> /host/boot  -> Unraid flash backup (whole USB)
                   |- /config               -> BombVault's own settings + credentials (self-backup)
                   '- <repo path>           -> restic repository (local or remote: rclone/s3/rest/sftp)
```

BombVault використовує сокет Docker, щоб зупиняти контейнери перед резервним копіюванням і відтворювати їх після відновлення. Для віртуальних машин він виконує `virsh` на хості через SSH (`qemu+ssh://`), щоб коректно вимкнути машину або зробити живий знімок. Він ніколи не монтує шлях libvirt, тож не може завадити VM Manager на хості.

BombVault, це рівень оркестрації та інтерфейсу, а не механізм зберігання. Усе фактичне переміщення даних проходить через restic.

## Швидкий старт

Уперше тут? Перейдіть до **[Початок роботи](getting-started.md)**, щоб установити BombVault на Unraid через Community Applications і запустити свою першу резервну копію. Потім дослідіть усі **[Можливості](features.md)**, налаштуйте свою **[Конфігурацію](configuration.md)** і налаштуйте **[Зовнішнє копіювання та відновлення](offsite-recovery.md)**.

Кожен розділ може копіювати одразу в кілька місць призначення, спарений BombVault може тримати ваші зовнішні копії на сервері, що відмовляється видаляти, а **Аварійний майстер** повертає втрачений сервер із його набору для відновлення через вашу групу або за введеним ключем. Щоб перенести конфігурацію на нову машину, скористайтеся карткою **Експорт / імпорт налаштувань**. Див. [Зовнішнє копіювання та відновлення](offsite-recovery.md) і [Конфігурація](configuration.md#portable-settings-export-and-import).

**[Застосунок для Android](android.md)** збирає всі сервери вашої групи на телефоні, а журнал активності їх усіх показує на одному екрані.

!!! warning "Root-рівний контроль над хостом"
    Через сокет Docker BombVault може зупиняти, видаляти та відтворювати контейнери й читати/писати appdata, а для резервного копіювання VM він входить на хост через SSH, щоб виконати `virsh`. Кожен, хто має доступ до його вебінтерфейсу, фактично має root на хості. Запускайте BombVault лише в довіреній, не виставленій назовні мережі та задайте пароль для входу в **Налаштування, Безпека**. Набір для відновлення, депозити ключів і видалення резервних копій у місці призначення потребують його. Повну модель безпеки див. у [Конфігурація](configuration.md#security-model).
