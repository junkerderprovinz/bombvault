# BombVault

**Ваші дані Unraid, запечатані у сховищі. Зробіть копію. Підірвіть відновлення.**

![Огляд: рядок стану, те, що потребує уваги, захист кожного розділу, місця призначення та історія.](assets/screenshots/overview/home-dark.png#only-dark)
![Огляд: рядок стану, те, що потребує уваги, захист кожного розділу, місця призначення та історія.](assets/screenshots/overview/home-light.png#only-light)

BombVault — вебзастосунок для самостійного розміщення для **резервного копіювання та повного аварійного відновлення** на Unraid та інших хостах Docker, таких як TrueNAS SCALE, ZimaOS або звичайний Linux. Він копіює контейнери Docker, віртуальні машини KVM/libvirt, папки, набори даних ZFS і флешку Unraid. Він працює як один багатоархітектурний контейнер Docker, дає вебінтерфейс у темній, світлій або системній темі та веде весь життєвий цикл: копіювання, розклад, перевірка й відновлення.

Відновлення автоматичне. В Unraid контейнери знову з'являються на вкладці Docker достеменно як раніше, а віртуальні машини заново визначаються у VM Manager з підключеними дисками й UEFI NVRAM. Без ручного перевстановлення, без переналаштування, без драми. У TrueNAS контейнер, відновлений поруч з оригіналом, працює як звичайний контейнер Docker, якого екран Apps не показує.

Працює на [restic](https://restic.net), тому кожна копія дедуплікована, інкрементна й типово зашифрована.

!!! note "Бережіть свій APP_KEY"
    BombVault виводить пароль репозиторію restic із 32-байтового секрету `APP_KEY`. Якщо втратити його разом із набором для відновлення, зашифровані копії не можна буде відновити. Згенеруйте ключ командою `openssl rand -hex 32` і збережіть його в надійному місці. Див. [Конфігурація](configuration.md).

## Що захищає BombVault {#what-bombvault-protects}

Кожен контейнер, кожна віртуальна машина, набір папок, флешка, кожен набір даних ZFS і власні налаштування BombVault — це **запис** зі своєю сторінкою. Записи одного виду утворюють **розділ**, який вмикається в **Налаштування, Загальні**.

| Розділ | Що зберігається |
|---|---|
| **Контейнери** | Каталог appdata та визначення контейнера (образ, змінні середовища, порти, мітки, томи). |
| **Віртуальні машини** | Образ(и) диска, визначення XML та UEFI NVRAM, копіюються через SSH (без монтування libvirt). |
| **Flash** | Уся USB-флешка (`/boot`): ОС, ліцензія, конфігурація масиву, спільні ресурси, мережа й конфігурація плагінів. |
| **Автобекап** | Власний `/config` BombVault: база даних налаштувань, облікові дані місць призначення, пара SSH-ключів libvirt, ключ і закріплені ключі хостів серверів ZFS та сертифікати. |
| **Папки** | Будь-яка папка на сервері як набір папок, у кожного необов'язкові шаблони виключень. |
| **Набори даних ZFS** | Набір даних разом із кожним набором під ним, прочитаний з одного знімка ZFS і збережений як папка. Див. [Набори даних ZFS](zfs-datasets.md). |

## Відновлення — головне {#restore-is-the-star}

Після копіювання даних назад зі знімка restic BombVault відтворює збережене визначення контейнера через API Docker, тож контейнер з'являється на вкладці Docker в Unraid так, наче був там завжди (той самий образ, ті самі налаштування, ті самі зіставлення портів). Віртуальні машини отримують XML заново через SSH, а їхні диски й UEFI NVRAM підключаються знову, навіть якщо віртуальну машину видалили.

Одне вікно відновлює будь-який вид. Типово воно вибирає **Поруч з оригіналом**, що повертає копію як окремий екземпляр і лишає оригінал як є. **Замінити оригінал** спершу копіює поточний стан, тож відновлення можна скасувати. Інші цілі — папка або новий набір даних ZFS.

Коли копія зупиняє залежні контейнери, вони повертаються в правильному порядку: BombVault запускає їх у порядку `depends_on` з Compose і чекає, поки кожен повідомить, що він здоровий, перш ніж запускати залежні від нього, тож ніщо не забігає наперед бази даних чи шлюзу, які ще не працюють. Див. [Відновлення](restore.md) і [Команди та інші контейнери](backups.md#commands).

## Як це працює {#how-it-works}

```
Browser --HTTPS--> BombVault container
                   |- Go binary: JSON API + embedded React UI
                   |- Background worker (per-section scheduler + job executor)
                   |
                   |- /var/run/docker.sock  -> Docker API (container stop/inspect/recreate)
                   |- qemu+ssh://host       -> libvirt / KVM on the HOST over SSH (no mount)
                   |- /mnt/ -> /host/user   -> appdata, VM disks + restic repos (read/write)
                   |- /boot/ -> /host/boot  -> Unraid flash backup (whole USB)
                   |- /config               -> BombVault's own settings + sign-ins (self-backup)
                   '- <repo path>           -> restic repository (local or remote: rclone/s3/rest/sftp)
```

BombVault використовує сокет Docker, щоб зупиняти контейнери перед копією та перестворювати їх після відновлення. Для віртуальних машин він запускає `virsh` на хості через SSH (`qemu+ssh://`), щоб коректно вимкнути домен або зробити живий знімок. Він ніколи не монтує шлях libvirt, тому не може завадити VM Manager на хості.

BombVault — шар оркестрації та інтерфейсу, а не рушій зберігання. Увесь реальний рух даних іде через restic.

## Швидкий старт {#quick-start}

Ви тут уперше? Перейдіть до **[Початок роботи](getting-started.md)**, щоб встановити BombVault і зробити першу копію, а потім налаштуйте **[Зовнішні копії та відновлення](offsite-recovery.md)**. **[Приклади крок за кроком](guides.md)** проводять через часті завдання від початку до кінця, сторінка **[Налаштування](settings.md)** перелічує кожну плитку, а **[Можливості](features.md)** — короткий каталог усього, що вміє BombVault.

Кожен розділ може копіювати в кілька місць призначення одразу, спарений BombVault може зберігати ваші зовнішні копії на сервері, який відмовляє у видаленні, а **Аварійний майстер** повертає втрачений сервер із набору для відновлення, через вашу групу або з введеним ключем. Щоб перенести конфігурацію на новий сервер, скористайтеся карткою **Експорт / імпорт налаштувань**. Див. [Зовнішні копії та відновлення](offsite-recovery.md) і [Конфігурація](configuration.md#portable-settings-export-and-import).

**[Застосунок для Android](android.md)** збирає всі сервери вашої групи на телефоні з журналом активності всіх одразу на одному екрані.

Документація доступна 26 мовами, а інтерфейс 42. Сторінки, у яких ще немає перекладу, показуються англійською.

## Слова, що вживаються тут {#glossary}

У кількох слів у BombVault і на цих сторінках закріплене значення.

| Слово | Значення |
|---|---|
| **Запис** | Одна річ, яку копіює BombVault: контейнер, віртуальна машина, набір папок, флешка, набір даних ZFS з тими, що під ним, або його власні налаштування. У кожного своя сторінка. |
| **Розділ** | Усі записи одного виду, наприклад «Контейнери». Розділи вмикаються в **Налаштування, Загальні**. |
| **Місце призначення** | Місце, куди йдуть копії: папка на цьому сервері, спільний ресурс, ваш власний сервер або хмарний сервіс. Див. [Місця призначення](offsite-recovery.md#destinations). |
| **Локально** | Місце призначення на цьому сервері, де лежать папки розділів. |
| **Власна тека** | Репозиторій, у який розділ пише свої копії насамперед. Типово він на цьому сервері й може лежати в місці призначення. Див. [Власна тека розділу](offsite-recovery.md#own-folder). |
| **Копія** | Резервна копія, скопійована з власної теки в інше місце призначення через `restic copy`. |
| **Прямий репозиторій** | Репозиторій у зовнішньому місці, в який записи копіюють напряму, без локальної копії між ними. Див. [Прямі репозиторії](offsite-recovery.md#direct-repositories). |
| **Облікові дані** | Збережений ключ або пароль для сервісу S3 чи rest-server. Одні з них — за замовчуванням. Див. [Облікові дані](offsite-recovery.md#sign-ins). |
| **Розміщення** | У які місця призначення йдуть копії запису, задається на самому записі або як значення за замовчуванням його розділу. Див. [Розміщення для окремого запису](offsite-recovery.md#placement). |
| **Репліка** | Точна до блоків копія запису ZFS на другому сервері ZFS, зроблена через `zfs send`. Вона стоїть поруч із копією і не замінює її. Див. [Репліка](zfs-datasets.md#replica). |
| **Роль** | Те, що один екземпляр вашої групи робить для іншого: Приймач, Стягувач, Сервер ZFS або Зберігач ключа. Див. [Екземпляри та ролі](offsite-recovery.md#roles). |

!!! warning "Керування хостом на рівні root"
    Через сокет Docker BombVault може зупиняти, видаляти та перестворювати контейнери й читати та записувати appdata, а для копій віртуальних машин він входить на хост через SSH, щоб запускати `virsh`. Будь-хто, хто може достукатися до його вебінтерфейсу, фактично отримує root на хості. Запускайте BombVault лише в довіреній мережі, недоступній ззовні, і задайте пароль для входу в **Налаштування, Безпека**. Для набору для відновлення, передачі ключів на зберігання, ZIP флешки, експорту копії флешки чи автобекапу та видалення копій у місці призначення він обов'язковий. Повну модель безпеки див. у розділі [Конфігурація](configuration.md#security-model).
