# תחילת העבודה

עמוד זה מוליך אותך מתיבת Unraid טרייה עד הגיבוי הראשון שלך.

## דרישות

| דרישה | הערות |
|---|---|
| **Unraid 6.12+** | גרסאות קודמות אינן נבדקות. |
| **מיקום מאגר restic** | נתיב מקומי (מומלץ: המערך או הזיכרון המטמון שלך), SMB, NFS, או כל backend של rclone. |
| **Docker socket** | מעוגן על ידי התבנית אוטומטית (`/var/run/docker.sock`). |
| **Unraid flash** (`/boot`) | מעוגן במלואו על ידי התבנית אוטומטית (`/boot` אל `/host/boot`). מפעיל את גיבוי ה-flash ומאפשר ל-container משוחזר להופיע מחדש כאפליקציית Unraid רגילה וניתנת לעריכה. |
| **KVM VMs** (הצטרפות מרצון) | גיבוי VM מדבר עם libvirt דרך SSH, ללא עיגון libvirt. הגדר זאת בהגדרות (ראה [הגדרות](configuration.md)). |

## התקנה ב-Unraid

הדרך הקלה ביותר היא **Community Applications**.

1. פתח את לשונית **Apps** ב-Unraid.
2. חפש את **BombVault**.
3. לחץ **Install**, קבע את המשתנים הנדרשים (למטה), והחל.

!!! tip "התקנת תבנית ידנית"
    אם אתה מעדיף להוסיף את התבנית באופן ידני:

    1. עבור אל **Docker, Add Container, Template repositories** והוסף:
       ```
       https://github.com/junkerderprovinz/unraid-apps
       ```
    2. חפש את **BombVault** תחת Templates.
    3. קבע את המשתנים הנדרשים ולחץ **Apply**.

## ההגדרה הנדרשת היחידה

המשתנה היחיד שעליך לקבוע הוא `APP_KEY`, סוד hex באורך 32 בתים (64 תווי hex) המשמש לגזירת סיסמת מאגר ה-restic.

צור אחד בכל מכונה:

```bash
openssl rand -hex 32
```

הדבק את התוצאה בשדה `APP_KEY` של התבנית.

!!! danger "אל תאבד את ה-APP_KEY שלך"
    אובדן ה-`APP_KEY` הופך את הגיבויים המוצפנים שלך לבלתי ניתנים לשחזור. אחסן אותו במקום בטוח ונפרד מהשרת. ברגע ש-BombVault פועלת, השתמש ב**ערכת שחזור מפתח ההצפנה** בלחיצה אחת (ראה [מחוץ לאתר והתאוששות](offsite-recovery.md)) כדי לשמור את חבילת השחזור המלאה.

התבנית גם מעגנת עבורך את ה-Docker socket, את ה-flash (`/boot`) ואת שורש **Host Data** (`/mnt`). *מקורות* הגיבוי וגם *היעדים* חיים תחת Host Data. לעיון המלא במשתנים ולהגדרת מחוץ לאתר, ראה [הגדרות](configuration.md).

## הרצה ראשונה

1. פתח את ממשק הווב בכתובת `https://<your-unraid-ip>:3443` (אישור בחתימה עצמית מהקופסה).
2. ב**הגדרות**, הפעל את דומייני הגיבוי שאתה רוצה (Containers, VMs, Flash, Config, Files) ובחר צבע הדגשה.
3. בלשונית **Containers**, בחר container ולחץ **גבה** כדי ליצור את נקודת השחזור הראשונה שלך. נתיבי המאגר מוגדרים כברירת מחדל ל-`/mnt/user/bombvault/{container,vms,flash,config,files}` ונוצרים בגיבוי הראשון.
4. הגדר תזמון מ**הגדרות, לוחות זמנים**. יש *כלול הכל בלוח הזמנים* בלחיצה אחת עבור containers ו-VMs.

!!! tip "אופציונלי: בחר סדר גיבוי"
    אם כמה containers צריכים תמיד להיות מגובים לפני אחרים (למשל מסד נתונים לפני האפליקציה שמשתמשת בו), פתח את פאנל **סדר הגיבוי** בעמוד Containers וגרור אותם לרצף הרצוי. הרצות מתוזמנות ורב-בחירה עוקבות אחריו; כל מה שתשאיר לא מסודר מגובה לפי הכי-באיחור-קודם, כמו קודם.

!!! note "בדיקת שילוב מארח"
    פתח את `/spike` בממשק הווב לאחר שה-container מתחיל. הוא בודק כל עיגון ו-CLI (Docker socket, libvirt, restic, qemu-img, rclone) ומדווח על כל חלק חסר, כך שתוכל לוודא שה-container מחווט נכון לפני שאתה מסתמך עליו.

## פשוט מול מתקדם

כברירת מחדל הממשק מציג רק את הדברים החיוניים (גיבוי, שחזור, תזמון). השתמש במתג **פשוט / מתקדם** בסרגל הצד כדי לחשוף את בקרות המומחה: שמירה, עותק מחוץ לאתר, hooks לפני/אחרי, שחזור ברמת הקובץ, התראות, מדדי Prometheus וכלי השלמות/תחזוקה. זוהי העדפה לכל דפדפן וכבויה כברירת מחדל, כך שמתחילים מקבלים ממשק נקי ומשתמשי-על מקבלים את הכול.

## הצעדים הבאים

- עיין בכל **[התכונות](features.md)**.
- הוסף רפליקה אחת או יותר של **[מחוץ לאתר והתאוששות](offsite-recovery.md)** (כל דומיין יכול לשלוח למספר יעדים בבת אחת) ושמור את ערכת השחזור שלך.
- משכפל התקנה או עובר לתיבה חדשה? שא את כל התצורה שלך איתך עם כרטיס **ייצוא וייבוא הגדרות**. ראה [הגדרות](configuration.md#portable-settings-export-and-import).
- נתקלת בבעיה? ראה **[פתרון בעיות](troubleshooting.md)**.
