# תחילת העבודה

עמוד זה מוליך מתיבת Unraid טרייה עד הגיבוי הראשון.

## דרישות

| דרישה | הערות |
|---|---|
| **Unraid 6.12+** | גרסאות קודמות אינן נבדקות. ‏Unraid הוא היעד העיקרי, אבל BombVault רצה גם על מארח Docker רגיל ועל TrueNAS Scale (פרטים ב[מארח Docker כללי](#generic-docker-host)). |
| **מיקום מאגר restic** | נתיב מקומי (מומלץ: המערך או הזיכרון המטמון), SMB, NFS, או כל backend של rclone. |
| **Docker socket** | מעוגן על ידי התבנית אוטומטית (`/var/run/docker.sock`). |
| **Unraid flash** (`/boot`) | מעוגן במלואו על ידי התבנית אוטומטית (`/boot` אל `/host/boot`). מפעיל את גיבוי ה-flash ומאפשר ל-container משוחזר להופיע מחדש כאפליקציית Unraid רגילה וניתנת לעריכה. |
| **KVM VMs** (הצטרפות מרצון) | גיבוי VM מדבר עם libvirt דרך SSH, ללא עיגון libvirt. מגדירים זאת ב**הגדרות, אינטגרציות, SSH למארח** (פרטים ב[הגדרות](configuration.md)). |
| **מערכי נתונים של ZFS** (הצטרפות מרצון) | אותו חיבור SSH כמו בגיבויי VM, ‏`zfs` במארח, ו-Host Data ממופה כ-`/mnt` עם מצב הגישה Read/Write - Slave, ברירת המחדל של התבנית. פרטים ב[מערכי נתונים של ZFS](zfs-datasets.md). |
| **אפליקציית Android** (אופציונלי) | ‏Android 10 ומעלה, מצומדת לשרתים בגרסה 9.7.0 ומעלה. פרטים ב[אפליקציית Android](android.md). |

## התקנה ב-Unraid

הדרך הקלה ביותר היא **Community Applications**.

1. יש לפתוח את לשונית **Apps** ב-Unraid.
2. חפש את **BombVault**.
3. יש ללחוץ **Install**, יש לקבוע את המשתנים הנדרשים (למטה), והחל.

!!! tip "התקנת תבנית ידנית"
    להוספת התבנית באופן ידני:

    1. יש לעבור אל **Docker, Add Container, Template repositories** ולהוסיף:
       ```
       https://github.com/junkerderprovinz/unraid-apps
       ```
    2. חפש את **BombVault** תחת Templates.
    3. יש לקבוע את המשתנים הנדרשים וללחוץ **Apply**.

## מארח Docker כללי {#generic-docker-host}

לא Unraid? BombVault רץ גם כמכולה רגילה על כל מארח Docker (זה גם מה שנושא את התמיכה במכולות ב-TrueNAS Scale, עוד לפני רשומה משלו בקטלוג היישומים שם).

1. יש להוריד מהמאגר את הקובץ [`deploy/docker-compose.generic.yml`](https://github.com/junkerderprovinz/bombvault/blob/main/deploy/docker-compose.generic.yml), מוכן לעריכה.
2. יש להגדיר את `APP_KEY` (פרטים בהמשך) ולכוון את כרך Host Data אל שורש הנתונים האמיתי. ההערות בקובץ מלוות את שניהם.
3. `docker compose up -d`, ואז יש לפתוח את `https://<ip-מארח>:3443/`.

מה שונה לעומת Unraid:

- **אין תחום Flash.** אין כונן אתחול שיש ללכוד או לשחזר, ולכן לתחום Flash אין כאן מה לעשות. במקומו **הוספה** בדף גיבויים מציעה את **תצורת המערכת** כהצעת תיקיות: אוסף התחלתי של תיקיות `/etc` שסוקרים ועורכים לפני השמירה.
- **אין התראות מובנות של Unraid.** ערוצי ההתראות של BombVault עצמו (webhook, התראות על כשל מחוץ לאתר וכדומה) פועלים כרגיל; מדולג רק המשלוח הייעודי למערכת ההתראות של Unraid, מכיוון שמערכת כזו אינה קיימת כאן.
- **גיבוי מכונות וירטואליות הוא רשות ודורש מארח libvirtd נפרד הנגיש דרך SSH.** פרטים בקטע המסומן כהערה בקובץ compose. למארח Docker כללי אין בעצמו מנהל מכונות וירטואליות.
- **אין widget ל-Dashboard.** ‏BombVault Widget הוא תוסף של Unraid, ולכן גם השלב הזה מדולג.
- **איתור הנתונים של container.** בלי מוסכמת ה-`appdata` של Unraid, תיקיית הנתונים של container מאותרת לפי המקטעים שב-`DATA_ROOT_SEGMENTS`, לפי volumes בעלי שם של Docker, לפי תיקיית העבודה של פרויקט Compose ולפי התווית `bombvault.data` (פרטים ב[זיהוי מקורות הגיבוי](configuration.md#backup-source-detection)). ‏volumes בעלי שם וערכת ה-`/etc` מגיעים רק לנתיבים בתוך העיגון של Host Data, ולכן כוון את Host Data לתיקיית אב משותפת שמכסה גם את תיקיית הנתונים הראשית של Docker.
- **‏`PLATFORM`.** יש להגדיר אותו ל-`generic` או ל-`truenas`. כשהוא לא מוגדר, BombVault מזהה את Unraid לפי הסמן שלו בעיגון ה-flash ומתייחסת לכל השאר כאל מארח כללי, והשלבים הייחודיים ל-Unraid מדולגים במקום לנסות אותם ולהיכשל.

‏**TrueNAS Scale** הולך באותה דרך של compose; רשומת קטלוג הוכנה במאגר אבל עדיין לא הוגשה. גיבוי VM שם צריך את `LIBVIRT_URI`, כי ה-libvirtd של TrueNAS מאזין על socket משלו (`/run/truenas_libvirt/libvirt-sock`) ששלושת משתני ה-`LIBVIRT_*` לא יכולים לבטא (פרטים ב[הגדרות](configuration.md)). עד כמה זה הוכח: גיבוי ה-zvol הורץ על מכונת TrueNAS Scale אמיתית, על zvol שמחובר ל-VM רצה, ו-`zfs snapshot`, ‏`zfs send`, ‏restic ו-`zfs receive` העבירו אותו הלוך ושוב זהה בית אחר בית. שחזור מלא שמבצעת BombVault עצמה עדיין לא הורץ על חומרת TrueNAS, וה-zvol ההוא היה דליל (sparse), ולכן קצב ההעברה בהיקף של הרבה גיגה-בתים לא נבדק. יש לבדוק שם שחזור לפני שסומכים עליו.

## ההגדרה הנדרשת היחידה

המשתנה היחיד שיש לקבוע הוא `APP_KEY`, סוד hex באורך 32 בתים (64 תווי hex) המשמש לגזירת סיסמת מאגר ה-restic.

יש ליצור אחד בכל מכונה:

```bash
openssl rand -hex 32
```

יש להדביק את התוצאה בשדה `APP_KEY` של התבנית (Unraid), או במשתנה הסביבה `APP_KEY` בקובץ `docker-compose.yml` (מארח Docker כללי).

!!! danger "אין לאבד את ה-APP_KEY"
    אובדן ה-`APP_KEY` הופך את הגיבויים המוצפנים לבלתי ניתנים לשחזור. יש לאחסן אותו במקום בטוח ונפרד מהשרת. ברגע ש-BombVault פועלת, יש להגדיר סיסמת כניסה ולהוריד את **ערכת השחזור** ב**הגדרות, שחזור** (פרטים ב[מחוץ לאתר והתאוששות](offsite-recovery.md#recovery-kit)). היא מכילה את המפתח, את כל היעדים ואת פקודות restic.

התבנית גם מעגנת את ה-Docker socket, את ה-flash (`/boot`) ואת שורש **Host Data** (`/mnt`). *מקורות* הגיבוי וגם *היעדים* חיים תחת Host Data. לעיון המלא במשתנים ולהגדרת מחוץ לאתר, פרטים ב[הגדרות](configuration.md).

## הרצה ראשונה

![הסקירה אחרי גיבוי ראשון: מה דורש תשומת לב, ההגנה על כל תחום, היעדים וההיסטוריה.](assets/screenshots/dashboard.png)

*הסקירה אחרי גיבוי ראשון: מה דורש תשומת לב, ההגנה על כל תחום, היעדים וההיסטוריה.*

1. פותחים את ממשק הווב בכתובת `https://<your-unraid-ip>:3443` (אישור בחתימה עצמית מהקופסה). התקנה חדשה נפתחת ב**ברוכים הבאים ל-BombVault**, שמפרט מה BombVault מצאה בשרת.
2. בוחרים **בואו נתחיל**. הסקירה מציגה אז את הכרטיס **צעדים ראשונים** עם שלושה שלבים:
    1. **בחירת תחומים**: מפעילים את מה ש-BombVault מגבה (Containers, VMs, Flash, תיקיות, מערכי נתונים של ZFS, גיבוי עצמי). **בחירה** פותחת את רשימת הפריטים של תחום, ושם **השהיית התזמון** משאירה פריט אחד בחוץ. התחומים שמפעילים כאן רצים בכל לילה, ואת זה משנים ב**הגדרות, לוח זמנים**.
    2. **הוספת יעד**: לאן הגיבויים הולכים. תיקייה מקומית מספיקה להתחלה. הבטוח ביותר הוא יעד שני מחוץ למבנה, כמו Storage Box או Backblaze B2. מאגרים מקומיים מוגדרים כברירת מחדל ל-`/mnt/user/bombvault/{container,vms,flash,config,files,zfs}` ונוצרים בגיבוי הראשון.
    3. **גיבוי ראשון**: אחרי זה הוא רץ מעצמו בכל לילה.
3. פותחים את **גיבויים** כדי לראות את כל הפריטים ברשימה אחת. **גיבוי הכול עכשיו** מתחיל הרצה על כל התחומים שהופעלו, ו**גיבוי עכשיו** בדף של פריט מגבה רק אותו.

כבר נעשה שימוש ב-BombVault? **שחזור מגיבוי** בדף הפתיחה פותח את דף השחזור, ושם **אשף חירום** מחזיר את ההגדרות, ה-containers, ה-VMs והתיקיות של שרת שאבד. פרטים ב[מחוץ לאתר והתאוששות](offsite-recovery.md#emergency).

!!! tip "אופציונלי: יש לבחור סדר גיבוי"
    אם כמה containers צריכים תמיד להיות מגובים לפני אחרים (למשל מסד נתונים לפני האפליקציה שמשתמשת בו), פותחים את הכרטיס **סדר** ב**הגדרות, לוח זמנים** וגוררים אותם לרצף הרצוי. הרצות מתוזמנות והגיבוי המלא עוקבים אחריו; כל מה שנשאר לא מסודר מגובה לפי הכי-באיחור-קודם.

!!! note "בדיקת שילוב מארח"
    הכרטיס **שילוב מארח** בסקירה בודק כל עיגון ו-CLI (Docker socket, libvirt, restic, qemu-img, rclone) ומדווח על כל חלק חסר, כך שאפשר לוודא שה-container מחווט נכון לפני שמסתמכים עליו. הוא ממתין תחת **התאמה אישית** עד שמוסיפים אותו.

## למצוא את הדרך {#navigation}

![ההגדרות כאריחים, וכרטיסי האריח הנבחר לצדם. כל שינוי נכתב ברגע שנעשה.](assets/screenshots/settings.png)

*ההגדרות כאריחים, וכרטיסי האריח הנבחר לצדם. כל שינוי נכתב ברגע שנעשה.*

בסרגל הצד חמש כניסות: **סקירה**, **חריגות** (כל עוד זיהוי החריגות פועל), **גיבויים**, **שחזור** ומתחת ל**התנתק** את **הגדרות**. הפעולה הראשית של דף צפה בפינה הימנית התחתונה, ו**עוד** מכיל את הנדירות. בטלפון הסרגל מכיל סקירה, גיבויים, שחזור והגדרות, ו**עוד** מכיל את השאר.

- **גיבויים** מפרט כפריטים כל container, כל VM, כל קבוצת תיקיות, את כונן ה-flash, כל מערך נתונים של ZFS ואת הגיבוי העצמי. אריחים מעל הרשימה בוחרים סוג, ו**מסננים**, **מיון** ו**חיפוש** מצמצמים אותה. לכל פריט דף משלו עם שלוש לשוניות: **גיבויים**, **הגדרות** ו**שלמות**.
- **שחזור** הוא דף אחד לכול: בוחרים תחום, מחפשים פריט ובוחרים גיבוי. גם אשף החירום והמקורות האחרים מתחילים כאן.
- **הגדרות** הן ארבעה עשר אריחים: כללי, מראה, לוח זמנים, יעדים, שחזור, התראות, אימות, אבטחה, מופעים, צימוד, אינטגרציות, אפליקציות, מערכת ומידע. אפשר ללחוץ `/` או Ctrl+K כדי לחפש בכולם, גם לפי השמות שהיו לדפים בגרסאות קודמות. את האריחים גוררים לסדר אחר תחת **מראה**.
- **יעדים** ו**מופעים** הם אריחי הגדרות עם דפים משלהם. **הצגה גם בסרגל הצד** באריח שלהם מצמידה אותם לסרגל הצד.

אין כפתור שמירה בשום מקום ושום דבר לא נפתח בקיפול: לדברים נדירים יש כרטיס משלהם או חלון, וההסברים נמצאים בבועות (i). אחרי עדכון, נקודות ירוקות מסמנות מה השתנה. לחיצה מסתירה נקודה, ו**הגדרות, מידע, חדש** מפרט כל שינוי עם **מעבר לשם**.

## בנייה מקוד המקור {#build-from-source}

‏BombVault היא קובץ בינארי סטטי יחיד של Go, שמגיש JSON API וממשק React מוטמע. יש לבנות קודם את הממשק, ואז יש להריץ את הקובץ הבינארי:

```bash
npm --prefix web ci
npm --prefix web run build     # כותב את web/dist, שהקובץ הבינארי מטמיע
export APP_KEY=$(openssl rand -hex 32)
go test ./...                  # בדיקות יחידה ואינטגרציה, עם סבב הלוך ושוב אמיתי של restic
golangci-lint run ./...
go run ./cmd/bombvault         # מגיש את https://localhost:3443 עם תעודה בחתימה עצמית
```

בניית הממשק נדרשת גם עבור `go run`. המאגר עוקב תחת `web/dist` רק אחרי קובץ סמן ריק, ולכן בלי `npm --prefix web run build` הקובץ הבינארי לא מטמיע כלום ועונה `500 SPA index not found`, וזה צפוי. את Docker, ‏libvirt ו-Unraid אי אפשר לבדוק ב-CI, ולכן לפני פתיחת pull request, יש לבדוק את העיגונים, את restic ואת חיבור ה-SSH של ה-VM על מארח אמיתי בעזרת הכרטיס **שילוב מארח** בסקירה (או `GET /api/spike`).
