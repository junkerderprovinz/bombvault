# เซิร์ฟเวอร์ MCP

BombVault มีเซิร์ฟเวอร์ในตัวสำหรับ Model Context Protocol (MCP) ซึ่งเป็นโปรโตคอลที่ผู้ช่วย AI อย่าง Claude Code และ Claude Desktop ใช้เข้าถึงเครื่องมือภายนอก ผ่านมันผู้ช่วยอ่านได้ว่าการสำรองข้อมูลของคุณเป็นอย่างไร และถ้าคุณอนุญาต ก็เริ่มการสำรองหรือยกเลิกอันที่มันเริ่มเองได้ ปิดอยู่จนกว่าคุณจะสร้างคีย์หรือเปิด [การลงชื่อเข้าใช้ผ่าน OAuth](#oauth): จนถึงตอนนั้น endpoint `/mcp` ตอบ `404` กับทุกอย่าง

## ผู้ช่วยทำอะไรได้และทำอะไรไม่ได้ {#tools}

| เครื่องมือ | ทำอะไร | ชนิด |
|---|---|---|
| `get_health` | เวอร์ชัน ชื่ออินสแตนซ์ มีการสำรองกำลังรันอยู่หรือไม่ และสิ่งที่คีย์นี้ทำได้ | อ่าน |
| `get_status` | สถานะการป้องกันต่อโดเมน: การสำรองที่สำเร็จล่าสุด ช่วงที่คาดไว้ การตรวจสอบและการตรวจนอกสถานที่ รอบตามกำหนดถัดไป การสำรองที่รอแอปว่าง และสำหรับคอนเทนเนอร์คือการทดสอบการเริ่มล่าสุด | อ่าน |
| `get_coverage` | BombVault ปกป้องอะไรและไม่ปกป้องอะไร พร้อมเหตุผลของแต่ละอย่าง | อ่าน |
| `list_items` | ทุกคอนเทนเนอร์ VM ชุดโฟลเดอร์ แฟลชไดรฟ์ และการกำหนดค่าแอปที่ป้องกันไว้ พร้อมตารางเวลา สิ่งที่การสำรองมันหยุด การสำรองล่าสุด และใช้เวลานานเท่าไร คอนเทนเนอร์ฐานข้อมูลมีดัมป์ล่าสุดด้วย ชุดข้อมูล ZFS ก็ลิสต์ไว้ด้วย พร้อมผลการตรวจล่าสุด ทุกรายการมีการตรวจกู้คืนล่าสุด และคอนเทนเนอร์มีการทดสอบการเริ่มล่าสุดหรือเหตุที่ทดสอบไม่ได้ คอนเทนเนอร์ที่ถูกสร้างใหม่ด้วยการตั้งค่าอื่นนับจากการสำรองล่าสุดจะลิสต์สิ่งที่เปลี่ยน | อ่าน |
| `list_runs` | ประวัติการรัน ใหม่สุดก่อน กรองตามโดเมน รายการ สถานะ ชนิด และเวลาได้ การสำรองที่ช้าเพราะสิ่งเดียวจะระบุมัน | อ่าน |
| `list_restore_points` | จุดกู้คืนของหนึ่งรายการจากที่เก็บหลักของมัน และสำหรับคอนเทนเนอร์คือไฟล์ดัมป์ฐานข้อมูลของมัน ชุดข้อมูล ZFS ได้หนึ่งจุดกู้คืนต่อการสำรอง พร้อมสแนปช็อตของทุกชุดข้อมูลข้างใต้ | อ่าน |
| `get_activity` | อะไรกำลังรันอยู่ตอนนี้ พร้อมเฟสและเปอร์เซ็นต์ | อ่าน |
| `get_storage_stats` | ประวัติขนาดของที่เก็บหลักของโดเมนหนึ่งและการเติบโตต่อสัปดาห์ และพื้นที่ที่ใช้ ว่าง และทั้งหมดบนดิสก์หรือรีโมตของแต่ละที่เก็บ | อ่าน |
| `get_size_breakdown` | โฟลเดอร์และไฟล์ไหนกินที่ในการสำรองใหม่สุดของคอนเทนเนอร์ VM หรือชุดโฟลเดอร์หนึ่งรายการ และการสำรองล่าสุดเพิ่มเท่าไรในแต่ละอัน | อ่าน |
| `search_files` | ค้นหาไฟล์และโฟลเดอร์ตามชื่อในข้อมูลสำรองของทุกรายการ ของหนึ่งโดเมน หรือของหนึ่งรายการ (ไม่ค้นใน VM) และแสดงข้อมูลสำรองทุกชุดที่มีผลลัพธ์แต่ละรายการ | อ่าน |
| `list_anomalies` | ความผิดปกติที่ BombVault สังเกตเห็นในการสำรอง กรองตามสถานะ ระดับ และโดเมนได้ พร้อมสรุปสิ่งที่เปิดอยู่ | อ่าน |
| `get_anomaly` | หนึ่งในสิ่งที่พบเหล่านั้น พร้อมหมายเหตุที่ทิ้งไว้ตอนยืนยัน | อ่าน |
| `start_backup` | สำรองหนึ่งรายการตอนนี้ | เริ่ม |
| `start_domain_backup` | สำรองทุกรายการที่ป้องกันไว้ของหนึ่งโดเมน | เริ่ม |
| `start_backup_everything` | รันรอบสำรองข้อมูลทั้งหมด | เริ่ม |
| `cancel_backup` | ยกเลิกการสำรองที่กำลังรันซึ่งคีย์นี้เป็นผู้เริ่ม | ยกเลิก |

สิ่งเหล่านี้ยังอยู่ในหน้าเว็บ: การกู้คืนทุกชนิด (รวมถึงการดาวน์โหลด บันทึก หรือนำเข้าไฟล์ดัมป์ฐานข้อมูล) การลบข้อมูลสำรอง prune การปลดล็อก การตรวจและการซ้อม การทำสำเนานอกสถานที่ การตั้งค่า ข้อมูลรับรอง และคีย์ MCP และการยกเลิกการสำรองที่ตารางเวลา หน้าเว็บ หรือคีย์อื่นเป็นผู้เริ่ม รวมถึงการยืนยันความผิดปกติหรือทำเครื่องหมายว่าคาดไว้แล้ว ซึ่งทำที่หน้า **ความผิดปกติ** เหตุผลคือเอาต์พุตของเครื่องมือมีชื่อและข้อความผิดพลาดจากเซิร์ฟเวอร์ของคุณ และอันใดอันหนึ่งอาจมีข้อความที่เขียนมาเพื่อชักนำผู้ช่วย ผู้ช่วยที่หลงเชื่อข้อความแบบนั้นอย่างมากที่สุดก็เริ่มการสำรองภายในขีดจำกัดด้านล่างหรือยกเลิกอันที่มันเริ่มเอง

ถ้าที่เก็บหลักของรายการเป็นรีโมต (S3, REST, SFTP, rclone) `list_restore_points` จะติดต่อมัน การเรียกจึงอาจใช้เวลา ลิสต์สำเนานอกสถานที่ผ่าน MCP ไม่ได้ `search_files` จะอ่านที่เก็บระยะไกล รวมถึงสำเนานอกสถานที่ ก็ต่อเมื่อผู้ช่วยขอเท่านั้น เพราะใช้เวลานานกว่าและผู้ให้บริการบางรายคิดเงินตามข้อมูลที่ดาวน์โหลด การค้นหาอาจใช้เวลาหลายนาที การเรียกครั้งแรกจึงเริ่มค้นหาเบื้องหลัง และการเรียกครั้งถัดไปจะรับผลลัพธ์ สิ่งที่การตรวจความผิดปกติดูอธิบายไว้ใต้ [ความผิดปกติ](anomalies.md) และวิธีที่รายการ ZFS เก็บหนึ่งสแนปช็อตต่อชุดข้อมูลอยู่ใต้ [ชุดข้อมูล ZFS](zfs-datasets.md#contents)

## การสำรองที่เริ่มแล้วทำอะไร {#starting-backups}

การสำรองของผู้ช่วยคือการสำรองเดียวกับที่หน้าเว็บเริ่ม คอนเทนเนอร์ที่กำลังรันจะหยุดจนกว่าการสำรองจะเสร็จ พร้อมกับคอนเทนเนอร์ที่ตั้งให้หยุดไปด้วยกัน VM ที่ใช้วิธีนุ่มนวลจะถูกปิดแล้วเริ่มใหม่ ชุดข้อมูล ZFS หยุดคอนเทนเนอร์ที่ตั้งไว้ให้มันขณะทำสแนปช็อต ชุดโฟลเดอร์ แฟลชไดรฟ์ และการกำหนดค่ารันต่อไป หลังจากนั้น BombVault ใช้นโยบายการเก็บรักษาและอาจคัดลอกไปยังที่เก็บนอกสถานที่ `list_items` บอกผู้ช่วยว่ารายการหยุดอะไรและการสำรองล่าสุดใช้เวลานานเท่าไร และคำอธิบายเครื่องมือขอให้มันบอกคุณก่อนเริ่มอะไร

เพราะการสำรองหยุดสิ่งต่าง ๆ และหมุนจุดกู้คืนเก่าออก การเริ่มผ่าน MCP จึงถูกจำกัด

- เริ่มการสำรองได้ 12 ครั้งต่อชั่วโมงต่อคีย์
- 15 นาทีระหว่างการเริ่มผ่าน MCP สองครั้งของรายการ โดเมน หรือรอบสำรองข้อมูลทั้งหมดเดียวกัน
- เริ่มรายการเดียวผ่าน MCP ได้อย่างมาก 4 ครั้งใน 24 ชั่วโมง
- **ตัวป้องกันการเก็บรักษา** เมื่อโดเมนเก็บจุดกู้คืนจำนวนคงที่ (เฉพาะ "เก็บ N ล่าสุด" ไม่มีกฎรายวัน รายสัปดาห์ หรือรายเดือน ทั้งในเครื่องหรือที่ปลายทางนอกสถานที่) ทุกการสำรองใหม่จะดันอันเก่าสุดออก BombVault จึงปฏิเสธการเริ่มผ่าน MCP ของรายการที่ N-1 การสำรองสำเร็จใหม่สุดของมันเริ่มผ่าน MCP ทั้งหมด จุดกู้คืนอย่างน้อยหนึ่งจุดที่ตารางเวลาหรือคุณสร้างจึงอยู่ในชุดที่เก็บเสมอ ด้วย "เก็บ 1 ล่าสุด" ผู้ช่วยสำรองรายการนั้นไม่ได้เลย การสำรองตามกำหนดครั้งถัดไปทำให้มีที่ว่างอีกครั้ง กฎรายปีอย่างเดียวนับเป็น "เก็บ 1 ล่าสุด" เพราะมันเก็บจุดกู้คืนเดียวของปีปัจจุบัน

การเริ่มโดเมนหรือรอบสำรองข้อมูลทั้งหมดจะเว้นรายการที่ขีดจำกัดยับยั้งไว้และระบุชื่อในคำตอบ หน้าเว็บและตารางเวลาไม่ถูกจำกัดโดยสิ่งเหล่านี้ งบรายชั่วโมงอยู่ในหน่วยความจำ การรีสตาร์ท BombVault จึงรีเซ็ตมัน

การเริ่มผ่าน [API](api.md#errors) และจาก [Home Assistant](api.md#home-assistant) นับรวมในขีดจำกัดต่อรายการเดียวกับการเริ่มผ่าน MCP และนับในตัวป้องกันการเก็บรักษา

## เปิดใช้งาน {#switch-on}

1. เปิด **การตั้งค่า, การเชื่อมต่อ, เซิร์ฟเวอร์ MCP** คลิก **เลือกไคลเอนต์** และเลือกของคุณในหน้าต่าง การค้นหาที่มุมขวาบนหาด้วยชื่อ ไคลเอนต์ที่ไม่อยู่ในรายการเชื่อมต่อผ่าน **ไคลเอนต์อื่น**
2. ใต้ **คีย์** คง **คีย์ใหม่** และชื่อที่มันเสนอ ซึ่งเป็นชื่อของไคลเอนต์ไว้ หรือพิมพ์ชื่อที่บอกว่าคีย์ใช้ที่ไหน เช่น "Claude Code บนแล็ปท็อป" หนึ่งคีย์ต่อหนึ่งไคลเอนต์ทำให้เพิกถอนอันหนึ่งได้โดยไม่แตะอันอื่น **คีย์ที่มีอยู่** ให้ไคลเอนต์ใช้คีย์ที่คุณสร้างไว้ก่อนหน้า
3. เปิด **อนุญาตให้เริ่มการสำรองข้อมูล** สำหรับคีย์ที่ควรเริ่มการสำรองได้ ถ้าไม่เปิด คีย์อ่านได้อย่างเดียว เปลี่ยนภายหลังได้ใน **รายละเอียด** ของคีย์ และการเปลี่ยนมีผลกับคำขอถัดไปของผู้ช่วยโดยไม่ต้องเชื่อมต่อใหม่
4. คลิก **สร้างคีย์** คีย์แสดงครั้งเดียว BombVault เก็บแค่ลายนิ้วมือของมันและแสดงอีกไม่ได้ ดังนั้นให้คัดลอกตอนนี้ ถ้าคุณปิดหน้าต่างก่อนที่ไคลเอนต์จะใช้คีย์ การ์ดจะแสดงมันต่อไปจนกว่าคุณยืนยันว่าคัดลอกแล้ว

ถ้าไม่มีรหัสผ่านเข้าสู่ระบบ หน้าเว็บเองเปิดให้ทุกคนในเครือข่ายของคุณ และใครก็ตามที่เปิดได้ก็สร้างคีย์ได้ด้วย การ์ดบอกเช่นนั้น ถ้าคุณเปิด BombVault ด้วยชื่อที่ดูเหมือนสาธารณะ (เช่น `bombvault.example.com` ผ่าน reverse proxy) และไม่ได้ตั้งรหัสผ่านเข้าสู่ระบบ จะสร้างหรือเปลี่ยนคีย์จากที่อยู่นั้นไม่ได้ เพื่อไม่ให้เว็บเพจใดบนอินเทอร์เน็ตทำให้เบราว์เซอร์ของคุณสร้างคีย์ได้ ตั้งรหัสผ่านเข้าสู่ระบบ หรือเปิด BombVault ด้วยที่อยู่ IP หรือชื่อในเครื่องอย่าง `tower` หรือ `tower.local`

## คีย์ของคุณและบันทึกของมัน {#keys}

แต่ละคีย์มีแถวของตัวเองใต้ **คีย์และไคลเอนต์ที่ลงชื่อเข้าใช้** แสดงชื่อคีย์ ว่าเริ่มการสำรองได้หรืออ่านอย่างเดียว อักขระสี่ตัวสุดท้ายของคีย์ สร้างหรือเปลี่ยนเมื่อไร และไคลเอนต์ใช้ครั้งล่าสุดเมื่อไร **รายละเอียด** เปิดหน้าต่างที่คุณเปลี่ยนชื่อคีย์ เปลี่ยนสิทธิ์ เปลี่ยนคีย์ หรือเพิกถอน และแสดงว่าวันนี้มันเรียกกี่ครั้ง คีย์ที่เพิกถอนย้ายไปรายการคีย์ที่เพิกถอน ซึ่งคุณลบถาวรได้เมื่อไม่มีการรันในประวัติที่ระบุชื่อมัน

ข้างชื่อ แถวแสดงเครื่องหมายของไคลเอนต์ที่คีย์สร้างให้ คีย์ที่สร้างผ่าน **ไคลเอนต์อื่น** หรือก่อนที่การ์ดจะลิสต์ไคลเอนต์ จะแสดงรูปกุญแจแทน

**บันทึก** ในรายละเอียดของคีย์แสดงสิ่งที่คีย์นั้นทำ และคีย์ที่เพิกถอนมีปุ่ม **บันทึก** ของตัวเอง การสำรองที่มันเริ่มมาก่อน แต่ละอันพร้อมสถานะและลิงก์ไปยังการรันนั้นในบันทึกกิจกรรมบนแดชบอร์ด ใต้นั้นคือการเรียกของมัน ใหม่สุดก่อน พร้อมเครื่องมือและผลของการเรียก การปฏิเสธบอกเหตุผล: คีย์อ่านได้อย่างเดียว ตัวป้องกันการเก็บรักษายับยั้งการสำรอง มีการสำรองอื่นรันอยู่แล้ว รายการ โดเมน หรือรอบเดียวกันถูกเริ่มนอกหน้าเว็บเมื่อไม่กี่นาทีก่อน หรือคีย์ส่งคำขอมากเกินไป การยกเลิกลิงก์ไปยังการรันที่มันเกี่ยวกับ

BombVault เก็บรายการของแต่ละคีย์ไว้นานถึง 30 วัน: การเริ่มและยกเลิกที่สำเร็จใหม่สุด 500 รายการ และข้างกันคือการเรียกอื่นใหม่สุด 200 รายการ (การอ่าน การปฏิเสธ และข้อผิดพลาด) ผู้ช่วยที่คอยโพลการสำรองที่กำลังรัน หรือลองเรียกที่ถูกปฏิเสธซ้ำ ๆ จึงดันจุดเริ่มของการสำรองนั้นออกจากบันทึกไม่ได้ สำหรับแต่ละการเรียกมันเก็บเครื่องมือ ผลลัพธ์ และการรันที่การยกเลิกระบุ มันไม่เก็บสิ่งที่ผู้ช่วยส่งมา และไม่เก็บคีย์หรือลายนิ้วมือของมันเลย ชุดวินิจฉัยนับแค่จำนวนรายการ และการส่งออกการตั้งค่าไม่รวมมัน

## เชื่อมต่อไคลเอนต์ {#clients}

**เลือกไคลเอนต์** เปิดหน้าต่างที่มีไคลเอนต์ทุกตัวเป็นไทล์ ใต้ **บนคอมพิวเตอร์เครื่องนี้** หรือ **บนคลาวด์** และช่องค้นหาที่มุมขวาบน ไทล์เปิดการตั้งค่าของไคลเอนต์ในหน้าต่างเดียวกัน เป็นสามขั้น: คีย์ การกำหนดค่าสำหรับไคลเอนต์นั้น พร้อมที่อยู่ที่คุณเปิดการ์ด ปุ่มคัดลอก ที่ที่การกำหนดค่าอยู่ และเมื่อใช้ใบรับรองของ BombVault เอง สิ่งที่ไคลเอนต์ต้องทำเพื่อเชื่อถือมัน และการรอการเรียกครั้งแรกของไคลเอนต์ หน้าต่างเฝ้าดูการใช้คีย์ครั้งล่าสุดและเปลี่ยนเป็นสีเขียวเมื่อการเรียกนั้นเข้ามา

### Claude Code {#claude-code}

Claude Code เข้าถึง BombVault ผ่าน `mcp-remote` ซึ่งต้องมี Node.js บนคอมพิวเตอร์เครื่องนั้น ก่อนอื่นบันทึกคีย์ในไฟล์ข้อความของมันเอง เป็นบรรทัดเดียว

```text
X-API-Key: <your key>
```

จากนั้นรันคำสั่งจากการ์ดหนึ่งครั้งในเทอร์มินัล โดยใส่พาธของไฟล์นั้น หลังใบรับรองที่คอมพิวเตอร์ของคุณเชื่อถือ หน้าตาเป็นแบบนี้

```bash
claude mcp add bombvault --scope user -- npx -y mcp-remote@latest https://bombvault.example.com/mcp --header-file "<path of the file with your key>"
```

กับใบรับรองของ BombVault เอง (ดู [TLS และใบรับรอง](#tls)) คำสั่งจะชี้ Node.js ไปที่ใบรับรองที่ดาวน์โหลดด้วย

```bash
claude mcp add bombvault --scope user -e "NODE_EXTRA_CA_CERTS=<path of the downloaded bombvault-cert.pem>" -- npx -y mcp-remote@latest https://192.168.1.10:3443/mcp --header-file "<path of the file with your key>"
```

ตรวจการเชื่อมต่อด้วย `/mcp` ภายใน Claude Code `--scope user` ทำให้ BombVault ใช้ได้ในทุกโปรเจกต์ของคุณ Claude Code เก็บแค่พาธของไฟล์คีย์ คีย์จึงไม่ปรากฏทั้งในคำสั่งและประวัติเชลล์ หรือในรายการโพรเซส เก็บไฟล์ไว้ในที่ที่มีแต่คุณอ่านได้ และนอกโฟลเดอร์ใด ๆ ที่คุณ commit `@latest` ทำให้ `npx` ดึง `mcp-remote` ที่เป็นปัจจุบัน ตัวเก่ากว่าที่ติดตั้งแบบ global จะถูกใช้แทน และมันไม่รู้จัก `--header-file`

อย่าเขียน `${BOMBVAULT_MCP_KEY}` ลงในอาร์กิวเมนต์ของ `mcp-remote` สำหรับ Claude Code เพราะ Claude Code เติมการอ้างอิงแบบนั้นจากสภาพแวดล้อมของตัวเองก่อนเริ่ม `mcp-remote` คีย์จึงไปอยู่บนบรรทัดคำสั่งของโพรเซสนั้น ซึ่งโปรแกรมอื่นและผู้ใช้อื่นของคอมพิวเตอร์อ่านได้

ถ้าไม่มี Node.js และเฉพาะหลังใบรับรองที่คอมพิวเตอร์ของคุณเชื่อถือ Claude Code เชื่อมต่อเองได้ วางไฟล์ `.mcp.json` ในโฟลเดอร์โปรเจกต์

```json
{
  "mcpServers": {
    "bombvault": {
      "type": "http",
      "url": "https://bombvault.example.com/mcp",
      "headers": {
        "Authorization": "Bearer ${BOMBVAULT_MCP_KEY}"
      }
    }
  }
}
```

ตั้ง `BOMBVAULT_MCP_KEY` ที่ที่ Claude Code เริ่ม เช่นใต้ `"env"` ใน `~/.claude/settings.json` หรือในโปรไฟล์เชลล์ของคุณ โดยแก้ในตัวแก้ไขข้อความ ไม่ใช่พิมพ์ที่พรอมต์ ที่นี่การอ้างอิงปลอดภัย เพราะ Claude Code ไม่เริ่มโพรเซสที่สองที่จะแบกมัน ใบรับรองของ BombVault เองใช้วิธีนี้ไม่ได้: การเชื่อมต่อของ Claude Code เองปฏิเสธมันแม้ตั้ง `NODE_EXTRA_CA_CERTS` อย่า commit `.mcp.json` ที่เขียนคีย์ไว้ในนั้น

### Claude Desktop {#claude-desktop}

Claude Desktop เข้าถึง BombVault ผ่าน `mcp-remote` ซึ่งต้องมี Node.js บนคอมพิวเตอร์เครื่องนั้น บันทึกคีย์ในไฟล์ข้อความของมันเองก่อน เป็นบรรทัดเดียว ตามที่อธิบายสำหรับ [Claude Code](#claude-code) เปิดไฟล์การกำหนดค่าผ่าน **Settings, Developer, Edit Config** ใน Claude Desktop อยู่ที่ `%APPDATA%\Claude\claude_desktop_config.json` บน Windows และ `~/Library/Application Support/Claude/claude_desktop_config.json` บน macOS เพิ่มรายการจากการ์ดภายใน `"mcpServers"` ข้างเซิร์ฟเวอร์ที่มีอยู่แล้ว และรีสตาร์ท Claude Desktop

```json
{
  "mcpServers": {
    "bombvault": {
      "command": "npx",
      "args": ["-y", "mcp-remote@latest", "https://192.168.1.10:3443/mcp", "--header-file", "<path of the file with your key>"],
      "env": {
        "NODE_EXTRA_CA_CERTS": "<path of the downloaded bombvault-cert.pem>"
      }
    }
  }
}
```

- `NODE_EXTRA_CA_CERTS` มีไว้สำหรับใบรับรองของ BombVault เองเท่านั้น ไม่ต้องใส่หลังใบรับรองที่คอมพิวเตอร์ของคุณเชื่อถืออยู่แล้ว
- `--allow-http` เพิ่มเฉพาะสำหรับที่อยู่ `http://` ธรรมดา
- บน Windows เขียนพาธด้วยเครื่องหมายทับไปข้างหน้า เช่น `C:/Users/sam/bombvault-key.txt` เพราะแบ็กสแลชตัวเดียวใช้ไม่ได้ใน JSON อย่าให้พาธของไฟล์คีย์มีช่องว่าง: Claude Desktop บน Windows ส่งพาธที่มีช่องว่างให้ `npx` เป็นสองชิ้น
- การกำหนดค่าระบุแค่ไฟล์คีย์ คีย์จึงไม่ปรากฏทั้งในนั้นและในรายการโพรเซส เก็บไฟล์ไว้ในที่ที่มีแต่คุณอ่านได้

### ไคลเอนต์บนคลาวด์ {#cloud-clients}

ChatGPT, Claude บน claude.ai, Grok และ Le Chat เรียก BombVault จากเซิร์ฟเวอร์ของผู้ให้บริการ BombVault จึงต้องเข้าถึงได้จากอินเทอร์เน็ตด้วยใบรับรองที่เชื่อถือได้สาธารณะ เช่นหลัง reverse proxy Le Chat ปฏิเสธใบรับรองที่เซ็นเอง การเข้าสู่ระบบบน proxy ปกป้องหน้าเว็บได้ แต่ `/mcp` ต้องผ่านไปถึง BombVault โดยไม่มีมัน: บริการเหล่านี้ลงชื่อเข้าใช้ proxy ไม่ได้ และ BombVault ตรวจคีย์หรือโทเค็นของพวกมันเอง Grok และ Le Chat ส่งคีย์คงที่ และปุ่มของพวกมันตั้งค่าเหมือนตัวอื่น ChatGPT และ Claude บน claude.ai ในองค์กรส่วนใหญ่เชื่อมต่อผ่านการลงชื่อเข้าใช้ด้วย OAuth เท่านั้น อธิบายถัดไป

### การลงชื่อเข้าใช้ผ่าน OAuth {#oauth}

สำหรับไคลเอนต์ที่รับคีย์ไม่ได้ BombVault เป็นเซิร์ฟเวอร์อนุญาต OAuth ของตัวเอง ไคลเอนต์ลงทะเบียนเอง ส่งคุณไปที่หน้าของ BombVault และที่นั่นคุณลงชื่อเข้าใช้ด้วยรหัสผ่านเข้าสู่ระบบ (และปัจจัยที่สองถ้าตั้งไว้) แล้วอนุญาต จากนั้นไคลเอนต์ได้โทเค็นที่ใช้ได้กับ endpoint MCP ของ BombVault นี้เท่านั้น และต่ออายุเอง

1. ตั้งรหัสผ่านเข้าสู่ระบบที่ **การตั้งค่า, ความปลอดภัย** ถ้าไม่มี BombVault ไม่เสนอการลงชื่อเข้าใช้เลย เพราะจะไม่มีใครให้ขอความยินยอม
2. ทำให้ BombVault เข้าถึงได้จากอินเทอร์เน็ตผ่าน https ด้วยใบรับรองที่เบราว์เซอร์เชื่อถือ ปกติผ่าน reverse proxy ไคลเอนต์เรียก `/mcp`, `/oauth/` และ `/.well-known/` จากเซิร์ฟเวอร์ของตัวเอง proxy ที่มีการเข้าสู่ระบบของตัวเองจึงต้องปล่อยสามพาธนี้ไปถึง BombVault หน้ายินยอมที่ `/oauth/authorize` เปิดในเบราว์เซอร์ของคุณเองและอยู่หลังการเข้าสู่ระบบของ proxy ได้ ระบุ proxy ใน `TRUSTED_PROXY` ด้วย (ดู [การกำหนดค่า](configuration.md)) BombVault จำกัดการลงทะเบียนไคลเอนต์ต่อที่อยู่ และถ้าไม่มี ทุกไคลเอนต์จะดูเหมือนมาจาก proxy
3. บนการ์ด MCP เปิด **ลงชื่อเข้าใช้ผ่าน OAuth** และกรอก **ที่อยู่สาธารณะ**: ที่อยู่ https ที่ไม่มีพาธ เช่น `https://backup.example.com` ทุกโทเค็นผูกกับที่อยู่นี้ ดังนั้นหลังเปลี่ยน ไคลเอนต์แต่ละตัวต้องลงชื่อเข้าใช้ใหม่
4. เลือก ChatGPT หรือ Claude ใต้ **เลือกไคลเอนต์** หน้าต่างแสดง **URL ของตัวเชื่อมต่อ** ซึ่งคือที่อยู่สาธารณะบวก `/mcp` และที่ที่ต้องใส่ในไคลเอนต์นั้น ใน ChatGPT เปิดโหมดนักพัฒนาที่ **Settings, Apps & Connectors, Advanced settings** เลือก **Create** วาง URL ตัวเชื่อมต่อเป็น URL เซิร์ฟเวอร์ MCP และเลือก OAuth เป็นการยืนยันตัวตน บน claude.ai เปิด **Settings, Connectors, Add custom connector** วาง URL ตัวเชื่อมต่อ ปล่อย OAuth client ID และ secret ว่าง และเลือก **Connect**
5. ไคลเอนต์เปิดหน้ายินยอม แสดงว่าใครขอ คำตอบของคุณส่งกลับไปที่ไหน และสวิตช์ **อนุญาตให้เริ่มการสำรองข้อมูล** ซึ่งเริ่มต้นปิดอยู่ เลือก **อนุญาต** หรือ **ปฏิเสธ**

ไคลเอนต์แต่ละตัวที่ลงชื่อเข้าใช้ได้แถวของตัวเองในรายการเดียวกัน พร้อมเครื่องหมายของมัน **รายละเอียด** ของมันมีบันทึก **เพิกถอน** และ **อนุญาตให้เริ่มการสำรองข้อมูล** และมีขีดจำกัดเดียวกับคีย์ การเพิกถอนมีผลทันที เมื่อไคลเอนต์เดียวกันลงชื่อเข้าใช้อีก การให้สิทธิ์ใหม่ของมันแทนที่อันเก่า และการให้สิทธิ์ที่ไม่มีใครใช้ 30 วันจะหมดอายุ ลงชื่อเข้าใช้ได้พร้อมกันถึง 10 ไคลเอนต์ นอกเหนือจาก 10 คีย์

หน้ายินยอมรับคำขอเฉพาะจากไคลเอนต์ที่ลงทะเบียนซึ่งระบุที่อยู่ส่งกลับที่ลงทะเบียนไว้อันใดอันหนึ่งตรงทุกตัวอักษร: https หรือที่อยู่ loopback บนพอร์ตใดก็ได้สำหรับไคลเอนต์บนคอมพิวเตอร์ของคุณเอง รับเฉพาะ authorization code flow พร้อม PKCE (S256) และคำตอบของคุณผูกกับเซสชันของคุณ ไม่มีเว็บไซต์อื่นส่งแทนคุณได้ โทเค็นการเข้าถึงอยู่ได้หนึ่งชั่วโมง refresh token ถูกแทนที่ทุกครั้งที่ใช้ และอันที่โผล่มาอีกหลังจากนั้นจะเพิกถอนการให้สิทธิ์ เพราะมีคนอื่นถือสำเนา ไคลเอนต์ที่รีเฟรชซ้ำครั้งล่าสุดภายใน 30 วินาที เพราะคำตอบไม่เคยไปถึง จะได้โทเค็นใหม่แทน BombVault ไม่ดึงเอกสารเมทาดาทาของไคลเอนต์จากอินเทอร์เน็ต ไคลเอนต์จึงลงทะเบียนผ่านการลงทะเบียนไคลเอนต์แบบไดนามิก

### ไคลเอนต์อื่น {#other-clients}

ไคลเอนต์ใดก็ตามที่พูด Streamable HTTP ใช้ได้

- URL: ที่อยู่ของหน้าเว็บบวก `/mcp` เช่น `https://192.168.1.10:3443/mcp`
- คีย์ใน `Authorization: Bearer <key>` หรือใน `X-API-Key: <key>` ถ้าส่งทั้งสอง ต้องมีคีย์เดียวกัน
- `POST` พร้อม `Content-Type: application/json` และ `Accept: application/json, text/event-stream`
- หนึ่งข้อความ JSON-RPC ต่อคำขอ ปฏิเสธ batch
- โปรโตคอลเวอร์ชัน 2026-07-28, 2025-11-25, 2025-06-18 และ 2025-03-26

## TLS และใบรับรอง {#tls}

BombVault ให้บริการ HTTPS ด้วยใบรับรองที่มันสร้างเอง และตอนแรกใบรับรองนั้นระบุเฉพาะ `localhost`, `127.0.0.1` และ `::1` Claude Code และ `mcp-remote` ปฏิเสธมันบนที่อยู่ LAN วิธีแก้ เรียงตามที่เหมาะกับการติดตั้ง Unraid ส่วนใหญ่

1. **เพิ่มที่อยู่ในการ์ด MCP** เมื่อเปิดการ์ดผ่าน HTTPS ที่ที่อยู่ซึ่งใบรับรองไม่ระบุ มันจะบอกและเสนอ **เพิ่มที่อยู่นี้ลงในใบรับรอง** BombVault ออกใบรับรองใหม่พร้อมที่อยู่ที่เพิ่ม (เบราว์เซอร์ของคุณเตือนอีกครั้ง เหมือนครั้งแรก) จากนั้นคลิก **ดาวน์โหลดใบรับรอง** ตัวอย่างโค้ดตั้ง `NODE_EXTRA_CA_CERTS` เป็นไฟล์ที่ดาวน์โหลด ไคลเอนต์จึงเชื่อถือใบรับรองนี้พอดี ซึ่งหมายความว่าทุกไคลเอนต์ที่ตั้งค่าด้วยไฟล์ดาวน์โหลดก่อนหน้าจะเชื่อมต่อไม่ได้ทันทีที่ออกใบรับรองใหม่ ทั้งบนคอมพิวเตอร์เครื่องนี้และเครื่องอื่นทุกเครื่อง จนกว่าจะได้ไฟล์ใหม่
2. **reverse proxy ที่มีใบรับรองที่เชื่อถือได้** (Nginx Proxy Manager, SWAG, Caddy, Traefik) ไคลเอนต์เห็นใบรับรองของ proxy และไม่ต้องทำอะไรเพิ่ม และการ์ดไม่เตือนเรื่องใบรับรองของ BombVault เอง
3. **Tailscale** `tailscale serve` หน้าคอนเทนเนอร์ หรืออินทิเกรชัน Tailscale ของ Unraid ให้ชื่อ `ts.net` พร้อมใบรับรองที่เชื่อถือได้
4. **`HTTP_ONLY=true`** เฉพาะหลัง proxy ที่ยุติ TLS หรือบนเครือข่ายที่คุณเชื่อถือเต็มที่ มันเปลี่ยนทั้งหน้าเว็บเป็น HTTP ธรรมดา ต้องแก้การตั้งค่าคอนเทนเนอร์ และส่งคีย์แบบไม่เข้ารหัส

อย่าตั้ง `NODE_TLS_REJECT_UNAUTHORIZED=0` มันปิดการตรวจใบรับรองสำหรับทุกอย่างที่โพรเซส Node.js นั้นคุยด้วย

reverse proxy ต้องส่งต่อส่วนหัว `Authorization` (หรือ `X-API-Key`) ซึ่ง proxy ทำอยู่แล้วเว้นแต่ถูกสั่งไม่ให้ และต้องไม่บัฟเฟอร์หรือเขียนทับ `/mcp` บล็อก location สำหรับ Nginx หรือ Nginx Proxy Manager ที่ตรวจใบรับรองของ BombVault ด้วย

```nginx
location /mcp {
    proxy_pass https://192.168.1.10:3443;
    proxy_ssl_verify on;
    proxy_ssl_trusted_certificate /data/bombvault-cert.pem;
    proxy_ssl_name localhost;
    proxy_http_version 1.1;
    proxy_buffering off;
    proxy_set_header Host $host;
}
```

หลัง proxy ทุกคำขอมีที่อยู่ของ proxy คีย์ผิดห้าครั้งจากไคลเอนต์ที่ตั้งค่าผิดตัวเดียวจึงล็อกไคลเอนต์ MCP ทุกตัวหลัง proxy นั้นหนึ่งนาที ระบุ proxy ใน `TRUSTED_PROXY` (ดู [การกำหนดค่า](configuration.md)) เพื่อนับต่อไคลเอนต์

## โมเดลความปลอดภัย {#security}

- ถ้าไม่มีคีย์ที่ใช้งานอยู่และปิดการลงชื่อเข้าใช้ผ่าน OAuth `/mcp` ตอบ `404`
- การลงชื่อเข้าใช้ผ่าน OAuth เสนอเฉพาะขณะที่ตั้งรหัสผ่านเข้าสู่ระบบ โทเค็น โค้ด และ client secret เก็บเป็นลายนิ้วมือเท่านั้น และโทเค็นใช้ได้เฉพาะกับที่อยู่ที่ออกให้
- ไคลเอนต์ลงทะเบียนได้มากสุด 10 ครั้งต่อชั่วโมงจากที่อยู่เดียว และ BombVault เก็บไคลเอนต์ที่ลงทะเบียนแต่ไม่มีใครลงชื่อเข้าใช้ได้มากสุด 100 ตัว ตัวละหนึ่งวัน โค้ดและ refresh token ที่ผิดนับรวมในการล็อกเดียวกับคีย์ที่ผิด
- การให้สิทธิ์ทำงานเหมือนคีย์เมื่อกู้คืนข้อมูลสำรองการกำหนดค่าหรือ `APP_KEY` เปลี่ยน: หลังการกู้คืน ทุกไคลเอนต์ต้องลงชื่อเข้าใช้ใหม่
- ไม่มีที่อยู่ที่ได้รับการยกเว้น คำขอจาก `localhost` โฮสต์ Unraid reverse proxy หรือ `tailscale serve` ต้องใช้คีย์เหมือนที่อื่น แม้หน้าเว็บไม่มีรหัสผ่านเข้าสู่ระบบ
- คีย์เก็บเป็นลายนิ้วมือเท่านั้น แสดงครั้งเดียว และเปลี่ยนชื่อ เปลี่ยนคีย์ และเพิกถอนได้ มีคีย์ที่ใช้งานได้สูงสุด 10 คีย์ แต่ละคีย์มีสวิตช์ **อนุญาตให้เริ่มการสำรองข้อมูล** ของตัวเอง
- ทุกการสร้าง เปลี่ยนคีย์ เปลี่ยนสิทธิ์ และเพิกถอน ส่งการแจ้งเตือนผ่านช่องทางแจ้งเตือนของคุณ พร้อมที่อยู่ที่มา เว้นแต่ปิดการแจ้งเตือน
- คีย์ผิด 5 ครั้งต่อนาทีต่อที่อยู่ แล้ว `429` 120 คำขอต่อนาทีและเริ่มการสำรอง 12 ครั้งต่อชั่วโมงต่อคีย์ บวกคูลดาวน์และตัวป้องกันการเก็บรักษาข้างบน
- คำขอจากหน้าเบราว์เซอร์บน origin อื่นถูกปฏิเสธ
- สร้างคีย์จากชื่อโฮสต์ที่ดูเหมือนสาธารณะไม่ได้ขณะที่ไม่มีรหัสผ่านเข้าสู่ระบบ
- ทุกการสำรองที่ผู้ช่วยเริ่ม และ prune กับการรันนอกสถานที่ที่มันก่อ ถูกทำเครื่องหมาย "via MCP" พร้อมชื่อคีย์ในบันทึกกิจกรรม แผงข้อผิดพลาด และการแจ้งเตือนการสำรอง
- ทุกการเรียกเครื่องมือถูกเขียนลงบันทึกคอนเทนเนอร์พร้อม id และอักขระสี่ตัวสุดท้ายของคีย์ (ไม่เคยเป็นชื่อ) และนับใน `/metrics` (`bombvault_mcp_requests_total`, `bombvault_mcp_tool_calls_total`, `bombvault_mcp_active_keys`)
- การกู้คืนข้อมูลสำรองการกำหนดค่าเพิกถอนทุกคีย์ เพราะฐานข้อมูลที่กู้คืนอาจมีคีย์ที่คุณเพิกถอนหลังบันทึก สร้างคีย์ใหม่หลังจากนั้น
- คีย์หยุดทำงานเมื่อ `APP_KEY` เปลี่ยน (ติดตั้งใหม่ หรือกู้คืนไปยังอีกคอนเทนเนอร์) การ์ดตรวจพบและทำเครื่องหมายคีย์ และ **เปลี่ยนคีย์** ให้ความลับที่ใช้ได้อีกครั้ง
- ปฏิบัติต่อคีย์เหมือนรหัสผ่าน ไคลเอนต์ที่อ่านคีย์จากตัวแปรสภาพแวดล้อม พรอมต์ หรือไฟล์คีย์ไม่ได้ จะเก็บมันเป็นข้อความธรรมดาในการกำหนดค่าหรือการตั้งค่าของมัน และการตั้งค่าบอกไว้ ควรใช้คีย์แบบอ่านอย่างเดียวบนคอมพิวเตอร์ที่คุณเชื่อถือน้อยกว่า

## อะไรออกจากกล่อง {#privacy}

อะไรก็ตามที่ผู้ช่วยอ่านจะไปที่ผู้ให้บริการ AI เบื้องหลัง: ชื่อรายการ ตารางเวลา ประวัติการรันพร้อมข้อความผิดพลาด id และเวลาของจุดกู้คืน ชื่อเอนจินฐานข้อมูลและขนาดดัมป์ กิจกรรมปัจจุบัน ตัวเลขที่จัดเก็บ ความครอบคลุม และสถานะ การค้นหาไฟล์ยังส่งไฟล์ที่พบด้วย ได้แก่ ชื่อ ขนาด และพาธภายในข้อมูลสำรอง BombVault ลบพาธโฮสต์ ตำแหน่งที่เก็บ ชื่อโฮสต์ ข้อมูลรับรอง คำสั่ง hook และคีย์ออกก่อนที่อะไรจะออกไป

## การแก้ปัญหา {#troubleshooting}

| สิ่งที่คุณเห็น | ความหมาย |
|---|---|
| `404` | ไม่มีคีย์ที่ใช้งานอยู่และปิดการลงชื่อเข้าใช้ผ่าน OAuth หรือพาธผิดอย่าง `/api/mcp` endpoint คือ `/mcp` |
| `401` | คีย์ขาด พิมพ์ผิด ถูกเพิกถอน หรือถูกเปลี่ยน proxy อาจทิ้งส่วนหัว `Authorization` (ลอง `X-API-Key`) ถ้าการ์ดทำเครื่องหมายว่าคีย์ใช้ไม่ได้แล้ว แสดงว่า `APP_KEY` เปลี่ยน: เปลี่ยนคีย์ |
| `403` | คำขอมาจากหน้าเบราว์เซอร์บน origin อื่น ใช้ไคลเอนต์เดสก์ท็อปหรือบรรทัดคำสั่ง |
| `405` บน GET | ปกติ endpoint รับเฉพาะ `POST` |
| `400` "Accept must contain both 'application/json' and 'text/event-stream'" | ไคลเอนต์เก่าเกินไปสำหรับ Streamable HTTP อัปเดตมัน |
| `400` "batch requests are not accepted" | ไคลเอนต์ส่ง batch JSON-RPC ส่งหนึ่งข้อความต่อคำขอ |
| `429` | คีย์ผิดมากเกินไปจากที่อยู่นี้ หรือมากกว่า 120 คำขอต่อนาทีด้วยคีย์เดียว รอหนึ่งนาที และตรวจว่าผู้ช่วยติดลูปหรือไม่ |
| ข้อผิดพลาด "certificate", "self-signed" หรือ "unable to verify" | ไคลเอนต์ไม่เชื่อถือใบรับรองของ BombVault ดู [TLS และใบรับรอง](#tls) |
| `busy` | การสำรองหรืองานบำรุงรักษาอื่นถือโดเมนนั้นอยู่ ลองใหม่เมื่อมันเสร็จ |
| `cooldown` | รายการ โดเมน หรือรอบสำรองข้อมูลทั้งหมดนี้ถูกเริ่มนอกหน้าเว็บเมื่อไม่ถึง 15 นาทีก่อน |
| `retention_guard` | การสำรองผ่าน MCP อีกหนึ่งครั้งจะเหลือเฉพาะจุดกู้คืนที่สร้างผ่าน MCP ในหน้าต่าง "เก็บ N ล่าสุด" หรือรายการนั้นได้การสำรองผ่าน MCP ครบ 4 ครั้งใน 24 ชั่วโมงล่าสุดแล้ว รวมที่ล้มเหลวและที่ยกเลิก ในกรณีแรกการสำรองตามกำหนดครั้งถัดไปทำให้มีที่ว่าง ในกรณีที่สองรายการนั้นว่างอีกครั้ง 24 ชั่วโมงหลังการสำรองที่เก่าสุดในนั้น ไม่ว่ากรณีไหน คุณเริ่มมันในหน้าเว็บได้ |
| `rate_limited` | คีย์ใช้การเริ่ม 12 ครั้งของชั่วโมงนี้หมดแล้ว |
| `not_permitted` ตอนเริ่ม | คีย์อ่านได้อย่างเดียว เปิด **อนุญาตให้เริ่มการสำรองข้อมูล** ในการ์ด ไม่ต้องเชื่อมต่อใหม่ ตอนยกเลิก หมายความว่าการรันนั้นไม่ได้เริ่มโดยคีย์นี้ |
| `domain_off` | ส่วนนั้นปิดอยู่ที่ **การตั้งค่า, ทั่วไป** |
| `not_found` | BombVault ไม่ได้ป้องกันรายการนั้น เพิ่มในหน้าเว็บก่อน MCP ไม่สร้างการกำหนดค่าเลย |
| ไคลเอนต์หาเซิร์ฟเวอร์อนุญาตไม่เจอ | ปิดการลงชื่อเข้าใช้ผ่าน OAuth ไม่ได้ตั้งรหัสผ่านเข้าสู่ระบบ หรือ proxy ไม่ปล่อย `/.well-known/` ไปถึง BombVault |
| หน้ายินยอมบอกว่าที่อยู่ส่งกลับไม่ได้ลงทะเบียน | ไคลเอนต์ส่งที่อยู่ส่งกลับที่ไม่ได้ลงทะเบียน ลบตัวเชื่อมต่อในไคลเอนต์แล้วเพิ่มอีกครั้ง |
| ไคลเอนต์ที่ลงชื่อเข้าใช้แล้วได้ `401` | การให้สิทธิ์ของมันถูกเพิกถอน หมดอายุหลัง 30 วันที่ไม่ได้ใช้ หรือที่อยู่สาธารณะเปลี่ยน ไคลเอนต์ลงชื่อเข้าใช้อีกครั้ง |

อย่าตั้งตัวแปรสภาพแวดล้อม `MCPGODEBUG` บนคอนเทนเนอร์ มันเปลี่ยนพฤติกรรมของไลบรารี MCP และค่าที่ผิดรูปทำให้ BombVault หยุดตอนเริ่มก่อนเขียนบันทึกแม้แต่บรรทัดเดียว
