# เริ่มต้นใช้งาน

หน้านี้พาคุณจากกล่อง Unraid ใหม่เอี่ยมไปจนถึงการสำรองข้อมูลครั้งแรก

## ข้อกำหนด {#requirements}

| ข้อกำหนด | หมายเหตุ |
|---|---|
| **Unraid 6.12+** | รุ่นก่อนหน้านั้นไม่ได้ทดสอบ Unraid คือเป้าหมายหลัก แต่ BombVault ก็รันบนโฮสต์ Docker ธรรมดาและบน TrueNAS Scale ได้ด้วย (ดู [โฮสต์ Docker ทั่วไป](#generic-docker-host) และ [TrueNAS SCALE](#truenas)) |
| **ตำแหน่งที่เก็บ restic** | พาธในเครื่อง (แนะนำ: อาร์เรย์หรือแคชของคุณ) SMB, NFS หรือแบ็กเอนด์ rclone ใดก็ได้ |
| **Docker socket** | เทมเพลตเมานต์ให้อัตโนมัติ (`/var/run/docker.sock`) |
| **แฟลชของ Unraid** (`/boot`) | เทมเพลตเมานต์ทั้งก้อนให้อัตโนมัติ (`/boot` ไปยัง `/host/boot`) ใช้สำรองแฟลช และทำให้คอนเทนเนอร์ที่กู้คืนกลับมาปรากฏเป็นแอป Unraid ปกติที่แก้ไขได้ |
| **VM แบบ KVM** (เลือกเปิด) | การสำรอง VM คุยกับ libvirt ผ่าน SSH ไม่ต้อง mount libvirt ตั้งค่าที่ **การตั้งค่า, การเชื่อมต่อ, SSH ของโฮสต์** (ดู [การกำหนดค่า](configuration.md)) |
| **ชุดข้อมูล ZFS** (เลือกเปิด) | ลิงก์ SSH เดียวกับการสำรอง VM คำสั่ง `zfs` บนโฮสต์ และ Host Data ที่แมปเป็น `/mnt` ด้วยโหมดเข้าถึง Read/Write - Slave ซึ่งเป็นค่าเริ่มต้นของเทมเพลต ดู [ชุดข้อมูล ZFS](zfs-datasets.md) |
| **แอป Android** (ไม่บังคับ) | Android 10 ขึ้นไป จับคู่กับเซิร์ฟเวอร์รุ่น 9.7.0 ขึ้นไป ดู [แอป Android](android.md) |

## ติดตั้งบน Unraid {#install-on-unraid}

ทางที่ง่ายที่สุดคือ **Community Applications**

1. เปิดแท็บ **Apps** ใน Unraid
2. ค้นหา **BombVault**
3. คลิก **Install** ตั้งค่าตัวแปรที่จำเป็น (ด้านล่าง) แล้วนำไปใช้

!!! tip "ติดตั้งเทมเพลตด้วยมือ"
    ถ้าอยากเพิ่มเทมเพลตเอง

    1. ไปที่ **Docker, Add Container, Template repositories** แล้วเพิ่ม:
       ```
       https://github.com/junkerderprovinz/unraid-apps
       ```
    2. ค้นหา **BombVault** ใน Templates
    3. ตั้งค่าตัวแปรที่จำเป็นแล้วคลิก **Apply**

## โฮสต์ Docker ทั่วไป {#generic-docker-host}

ไม่ได้ใช้ Unraid ใช่ไหม BombVault รันเป็นคอนเทนเนอร์ธรรมดาบนโฮสต์ Docker ใดก็ได้ด้วย TrueNAS SCALE มีขั้นตอนของตัวเองใต้ [TrueNAS SCALE](#truenas)

1. ดาวน์โหลด [`deploy/docker-compose.generic.yml`](https://github.com/junkerderprovinz/bombvault/blob/main/deploy/docker-compose.generic.yml) ที่พร้อมแก้ไขจากรีโป
2. ตั้ง `APP_KEY` (ดูด้านล่าง) และชี้วอลุ่ม Host Data ไปที่รากข้อมูลจริงของคุณ คอมเมนต์ในไฟล์อธิบายทั้งสองอย่าง
3. `docker compose up -d` แล้วเปิด `https://<host-ip>:3443/`

สิ่งที่ต่างจาก Unraid

- **ไม่มีส่วน Flash** ไม่มี USB สำหรับบูตให้จับหรือกู้คืน ส่วน Flash จึงไม่มีอะไรทำที่นี่ แต่เมื่อ Host Data เข้าถึง `/etc` ของโฮสต์ **เพิ่ม** บนหน้าการสำรองข้อมูลจะเสนอ **การกำหนดค่าระบบ** เป็นข้อเสนอโฟลเดอร์: ชุดโฟลเดอร์ `/etc` เริ่มต้นที่คุณตรวจดูและแก้ไขก่อนบันทึก
- **ไม่มีการแจ้งเตือนแบบเนทีฟของ Unraid** ช่องทางแจ้งเตือนในแอปของ BombVault เอง (webhook, การเตือนเมื่อสำเนานอกสถานที่ล้มเหลว ฯลฯ) ทำงานตามปกติ เพียงข้ามการส่งไปยังระบบแจ้งเตือนเนทีฟเฉพาะของ Unraid เพราะไม่มีระบบแบบนั้นให้ส่ง
- **การสำรอง VM เลือกเปิดเอง และต้องมีโฮสต์ libvirtd แยกต่างหากที่เข้าถึงได้ผ่าน SSH** ดูบล็อกที่คอมเมนต์ไว้ในไฟล์ compose โฮสต์ Docker ทั่วไปไม่มีตัวจัดการ VM ในตัว
- **ไม่มีไทล์บนแดชบอร์ด** TollRoll เป็นปลั๊กอินของ Unraid ขั้นตอนนั้นจึงถูกข้ามด้วย
- **การหาข้อมูลของคอนเทนเนอร์** เมื่อไม่มีธรรมเนียม `appdata` ของ Unraid โฟลเดอร์ข้อมูลของคอนเทนเนอร์จะหาจากส่วนใน `DATA_ROOT_SEGMENTS` วอลุ่มแบบมีชื่อของ Docker ไดเรกทอรีทำงานของโปรเจกต์ Compose และป้าย `bombvault.data` (ดู [การตรวจหาต้นทางการสำรอง](configuration.md#backup-source-detection)) วอลุ่มแบบมีชื่อและค่าตั้งต้น `/etc` ไปถึงเฉพาะพาธภายใน mount ของ Host Data ให้ชี้ Host Data ไปที่บรรพบุรุษร่วมที่ครอบคลุมรากข้อมูลของ Docker ด้วย
- **`PLATFORM`** ตั้งเป็น `generic` หรือ `truenas` ถ้าไม่ตั้ง BombVault ตรวจจับ Unraid จากเครื่องหมายของมันบน mount ของแฟลช และถือว่าอย่างอื่นเป็น generic ขั้นตอนเฉพาะ Unraid จะถูกข้ามแทนที่จะลองแล้วล้มเหลว

### TrueNAS SCALE {#truenas}

BombVault ยังไม่อยู่ในแคตตาล็อกแอปของ TrueNAS จึงติดตั้งเป็นแอปกำหนดเอง: **Apps, Discover Apps** แล้ว **Install via YAML** ในเมนูข้าง **Custom App** YAML ด้านล่างตั้งค่าเหมือนรายการแคตตาล็อกในโฟลเดอร์ `truenas-apps` ของรีโป แทนที่ `tank` ด้วยพูลของคุณ และกรอก `APP_KEY` ตามที่หัวข้อถัดไปอธิบาย

```yaml
services:
  bombvault:
    image: junkerderprovinz/bombvault:latest
    hostname: bombvault
    restart: unless-stopped
    cap_drop: [ALL]
    cap_add: [CHOWN, DAC_OVERRIDE, FOWNER, SETGID, SETPCAP, SETUID, SYS_CHROOT]
    environment:
      APP_KEY: ""
      PLATFORM: truenas
      HOST_SOURCE_ROOT: /mnt/tank
      HOST_MOUNT_ROOT: /mnt/tank
      # For VM backups:
      # LIBVIRT_URI: qemu+ssh://root@<truenas-ip>/system?socket=/run/truenas_libvirt/libvirt-sock
    volumes:
      - /mnt/tank/apps/bombvault:/config
      - /var/run/docker.sock:/var/run/docker.sock
      - type: bind
        source: /mnt/tank
        target: /mnt/tank
        bind:
          propagation: rslave
    ports:
      - "30528:3443"
```

จากนั้นเปิด `https://<truenas-ip>:30528/` สิ่งที่ลิสต์ไว้ใต้ [สิ่งที่ต่างจาก Unraid](#generic-docker-host) ใช้ที่นี่ด้วย และบน TrueNAS ยังมีเรื่องเหล่านี้

- **ความสามารถ (capabilities)** BombVault ต้องใช้ทั้งเจ็ดอย่างข้างบน การสำรอง VM ล้มเหลวถ้าไม่มี `SETPCAP` และถ้าไม่มี `SYS_CHROOT` ทุกคอนเทนเนอร์จะถูกหยุดตลอดการสำรองแทนที่จะอ่านจากสแนปช็อต
- **Host Data** คือพาธของโฮสต์บนชุดข้อมูล ในที่นี้คือ `/mnt/tank` เมานต์ที่พาธเดียวกันภายในแอป เหตุนี้ `HOST_SOURCE_ROOT` และ `HOST_MOUNT_ROOT` จึงระบุมันทั้งคู่ `rslave` ส่งต่อ mount ที่โฮสต์ทำภายหลัง ซึ่งการสำรองชุดข้อมูล ZFS ต้องการ
- **ข้อมูลใน ixVolume ไม่ถูกสำรอง** แอปที่ใช้ ixVolume เป็นที่เก็บข้อมูลเก็บข้อมูลไว้ใต้ `/mnt/.ix-apps` นอก Host Data BombVault บันทึกเฉพาะคำจำกัดความของแอป และการรันจะบอกชื่อโฟลเดอร์ที่ข้ามไป สำหรับทุกแอปที่คุณต้องการสำรองข้อมูล ให้เลือกที่เก็บข้อมูลแบบ **Host Path** บนชุดข้อมูลใต้ Host Data
- **การสำรอง VM และชุดข้อมูล ZFS** เข้าถึง TrueNAS ผ่าน SSH ในฐานะ root เปิดบริการ SSH ที่ **System, Services** และเพิ่มกุญแจสาธารณะจาก **การตั้งค่า, การเชื่อมต่อ, SSH ของโฮสต์** ให้ผู้ใช้ root ที่ **Credentials, Users** การสำรอง VM ต้องมี `LIBVIRT_URI` ตามด้านบนด้วย เพราะ libvirtd ของ TrueNAS ฟังที่ socket ของตัวเอง ถ้าไม่ตั้งทั้ง `LIBVIRT_URI` และ `LIBVIRT_HOST` BombVault จะใช้เกตเวย์เริ่มต้นของแอปเป็นโฮสต์ เพราะ `host.docker.internal` ไม่ resolve ในแอป TrueNAS [คู่มือการสำรอง VM](vm-backup-ssh-setup.md#truenas-scale) ครอบคลุมรายละเอียด รวมถึง VM บน zvol
- **เรพลิกา ZFS ใช้คีย์อื่น** เรพลิกาบนเซิร์ฟเวอร์ ZFS ตัวที่สองลงชื่อเข้าใช้ด้วยคีย์ที่กล่องเรพลิกาแสดง ไม่ใช่คีย์ SSH ของโฮสต์ เพิ่มคีย์นั้นบนเซิร์ฟเวอร์ที่รับ
- **แอปที่ถูกลบกลับมาใน 2 ขั้น** ติดตั้งใหม่ใน TrueNAS ด้วยชื่อเดียวกันก่อน ซึ่งสร้างเครือข่ายของมันอีกครั้ง แล้วค่อยกู้คืนข้อมูลใน BombVault ก่อนหน้านั้นการตรวจกู้คืนจะรายงานเครือข่ายที่ขาด และการกู้คืนจะปฏิเสธก่อนเปลี่ยนอะไร
- **ข้างต้นฉบับ** สร้างคอนเทนเนอร์ Docker ธรรมดา มันรันได้ แต่หน้า Apps ของ TrueNAS ไม่แสดงมัน
- **ไฟล์ดัมป์ฐานข้อมูล** ใช้ได้บน mount ของชุดข้อมูล การนำเข้าไปยังโฟลเดอร์ข้อมูลที่เป็นชุดข้อมูลของตัวเองจะย้ายเนื้อหาเดิมไปไว้ในโฟลเดอร์ข้าง ๆ ชุดข้อมูลด้านบนจึงต้องมีที่พอสำหรับมัน

### ZimaOS, CasaOS และโฮสต์อื่น {#other-hosts}

- **ZimaOS และ CasaOS:** เพิ่ม [community store](https://github.com/junkerderprovinz/zimaos-apps#install) แล้วติดตั้ง BombVault จากที่นั่น มันรันที่นั่นเป็น `PLATFORM=generic` โดยมี Host Data ที่ `/DATA` ZimaOS เก็บข้อมูลแอปไว้ใน `/DATA/AppData/<app>` ซึ่ง BombVault หาเจอเอง เพราะ `DATA_ROOT_SEGMENTS` ตรงกับ `appdata` ไม่ว่าตัวพิมพ์ใหญ่เล็ก
- **MOS:** ติดตั้ง BombVault จาก [MOS Hub](https://mos-official.net/apps.html?search=BombVault) มันรันที่นั่นเป็น `PLATFORM=generic` โดยมี Host Data ที่ `/mnt/cache`
- **Synology:** ใน Container Manager สร้างโปรเจกต์จากไฟล์ compose (DSM 7.2 ขึ้นไป)
- **Proxmox:** รันใน VM หรือคอนเทนเนอร์ LXC ที่มี Docker

ถ้าไม่มีคอมเมนต์ ไฟล์ compose แบบ generic สั้นมาก แทนที่ `./data` ด้วยโฟลเดอร์โฮสต์ที่เก็บข้อมูลของคอนเทนเนอร์ของคุณ ตั้ง `HOST_SOURCE_ROOT` เป็นพาธเดียวกัน และกรอก `APP_KEY`

```yaml
services:
  bombvault:
    image: junkerderprovinz/bombvault:latest
    restart: unless-stopped
    hostname: bombvault
    container_name: bombvault
    volumes:
      - ./config:/config
      - /var/run/docker.sock:/var/run/docker.sock
      - ./data:/host/user
    environment:
      APP_KEY: ""
      PLATFORM: generic
      HOST_SOURCE_ROOT: /host/user
    ports:
      - "3443:3443"
```

ถ้าจะสำรองวอลุ่มแบบมีชื่อของ Docker ด้วย ให้เมานต์โฟลเดอร์ที่ครอบคลุมทั้งข้อมูลของคุณและรากข้อมูลของ Docker (`docker info -f '{{.DockerRootDir}}'` มักเป็น `/var/lib/docker`) เหมือนที่เทมเพลต Unraid เมานต์ `/mnt` ทั้งหมด

## การตั้งค่าเดียวที่จำเป็น {#the-one-required-setting}

ตัวแปรเดียวที่คุณต้องตั้งคือ `APP_KEY` ความลับฐานสิบหกขนาด 32 ไบต์ (อักขระฐานสิบหก 64 ตัว) ที่ใช้สร้างรหัสผ่านของที่เก็บ restic

สร้างบนเครื่องใดก็ได้

```bash
openssl rand -hex 32
```

วางผลลัพธ์ในช่อง `APP_KEY` ของเทมเพลต (Unraid) หรือตัวแปรสภาพแวดล้อม `APP_KEY` ใน `docker-compose.yml` (โฮสต์ Docker ทั่วไป)

!!! danger "อย่าทำ APP_KEY หาย"
    ถ้า `APP_KEY` หาย ข้อมูลสำรองที่เข้ารหัสจะกู้คืนไม่ได้ เก็บไว้ในที่ปลอดภัยและแยกจากเซิร์ฟเวอร์ เมื่อ BombVault รันแล้ว ให้ตั้งรหัสผ่านเข้าสู่ระบบและดาวน์โหลด **ชุดกู้คืน** ที่ **การตั้งค่า, การกู้คืน** (ดู [นอกสถานที่และการกู้คืน](offsite-recovery.md#recovery-kit)) ในนั้นมีคีย์ ปลายทางที่จัดเก็บทุกแห่ง และคำสั่ง restic

เทมเพลตยังเมานต์ Docker socket แฟลช (`/boot`) และราก **Host Data** (`/mnt`) ให้คุณ *ต้นทาง* และ *ปลายทาง* ของการสำรองอยู่ใต้ Host Data ทั้งคู่ สำหรับรายการตัวแปรครบถ้วนและการตั้งค่านอกสถานที่ ดู [การกำหนดค่า](configuration.md)

## การรันครั้งแรก {#first-run}

1. เปิดหน้าเว็บที่ `https://<your-unraid-ip>:3443` (ใบรับรองที่เซ็นเองมาให้ทันที) การติดตั้งใหม่จะเปิดที่ **ยินดีต้อนรับสู่ BombVault** ซึ่งลิสต์สิ่งที่ BombVault พบบนเซิร์ฟเวอร์
2. เลือก **เริ่มเลย** ภาพรวมจะแสดงการ์ด **ขั้นตอนแรก** พร้อมสามขั้น
    1. **เลือกส่วนที่จะสำรอง**: เปิดสิ่งที่ BombVault สำรอง (คอนเทนเนอร์ VM แฟลช โฟลเดอร์ ชุดข้อมูล ZFS สำรองข้อมูลตัวเอง) **เลือก** เปิดรายการของส่วนนั้น ซึ่ง **หยุดกำหนดการชั่วคราว** ใช้เว้นรายการหนึ่งไว้ ส่วนที่คุณเปิดตรงนี้จะรันทุกคืน ซึ่งเปลี่ยนได้ที่ **การตั้งค่า, ตารางเวลา**
    2. **เพิ่มปลายทาง**: ที่ที่สองสำหรับข้อมูลสำรอง ทุกส่วนมีโฟลเดอร์บนเซิร์ฟเวอร์นี้อยู่แล้ว `/mnt/user/bombvault/{container,vms,flash,config,files,zfs}` ที่สร้างตอนการสำรองครั้งแรก ที่ปลอดภัยที่สุดคือปลายทางที่สองนอกสถานที่ เช่น Storage Box หรือ Backblaze B2
    3. **การสำรองข้อมูลครั้งแรก**: หลังจากนั้นมันรันเองทุกคืน การ์ดอยู่จนกว่าการสำรองครั้งแรกจะเสร็จ
3. เปิด **การสำรองข้อมูล** เพื่อดูทุกรายการในลิสต์เดียว **สำรองข้อมูลทั้งหมดเดี๋ยวนี้** เริ่มรอบที่ครอบคลุมทุกส่วนที่เปิดอยู่ และ **สำรองข้อมูลเดี๋ยวนี้** บนหน้าของรายการสำรองเฉพาะรายการนั้น

![การ์ดขั้นตอนแรกพร้อมสามขั้น โดยขั้นที่สองเปิดอยู่](assets/screenshots/getting-started/first-steps-dark.png#only-dark)
![การ์ดขั้นตอนแรกพร้อมสามขั้น โดยขั้นที่สองเปิดอยู่](assets/screenshots/getting-started/first-steps-light.png#only-light)

เคยใช้ BombVault มาก่อนไหม **กู้คืนจากข้อมูลสำรอง** บนหน้าต้อนรับเปิดหน้าการกู้คืน ซึ่ง **ตัวช่วยฉุกเฉิน** นำการตั้งค่า คอนเทนเนอร์ VM และโฟลเดอร์ของเซิร์ฟเวอร์ที่หายไปกลับมา ดู [นอกสถานที่และการกู้คืน](offsite-recovery.md#emergency)

!!! tip "ไม่บังคับ: เลือกลำดับการสำรอง"
    ถ้าคอนเทนเนอร์บางตัวควรถูกสำรองก่อนตัวอื่นเสมอ (เช่นฐานข้อมูลก่อนแอปที่ใช้มัน) ให้เปิดการ์ด **ลำดับ** ใต้ **การตั้งค่า, ตารางเวลา** แล้วลากให้เป็นลำดับที่ต้องการ รอบตามกำหนดและการสำรองข้อมูลทั้งหมดจะทำตามนั้น อะไรที่คุณไม่ได้เรียงจะถูกสำรองโดยเอาอันที่เลยกำหนดมากที่สุดก่อน

## ตัวอย่าง: สำรองคอนเทนเนอร์ครั้งแรกตั้งแต่ต้นจนจบ {#example-first-backup}

ตัวอย่างนี้พาดูกล่อง Unraid ใหม่ที่มีคอนเทนเนอร์ไม่กี่ตัว รวมถึง `plex` จนการสำรองครั้งแรกเสร็จและคุณรู้ว่าจะหามันได้ที่ไหน ใช้เวลาราวสิบนาทีบวกเวลาของการสำรองครั้งแรก

1. **ติดตั้ง** ในแท็บ **Apps** ของ Unraid ค้นหา **BombVault** แล้วกด **Install**
2. **ตั้งคีย์** บนคอมพิวเตอร์ รัน `openssl rand -hex 32` แล้ววางอักขระ 64 ตัวในช่อง `APP_KEY` ของเทมเพลต เก็บสำเนาไว้ในตัวจัดการรหัสผ่านของคุณตอนนี้เลย ก่อนอย่างอื่น กด **Apply**
3. **เปิด** ไปที่ `https://<your-unraid-ip>:3443` แล้วยอมรับใบรับรองที่เซ็นเอง **ยินดีต้อนรับสู่ BombVault** ลิสต์สิ่งที่พบ เช่นคอนเทนเนอร์ 12 ตัว VM 2 ตัว และแฟลชไดรฟ์
4. **เริ่มเลย** ภาพรวมเปิดพร้อมการ์ด **ขั้นตอนแรก**
5. **เลือกส่วนที่จะสำรอง** **คอนเทนเนอร์** เปิดอยู่ตั้งแต่แรก เปิดอย่างอื่นที่ต้องการ เช่น **Flash** **เลือก** เปิดรายการคอนเทนเนอร์ที่พบ ซึ่ง **หยุดกำหนดการชั่วคราว** เว้นตัวหนึ่งไว้ เช่นคอนเทนเนอร์ทดสอบที่คุณไม่สน ส่วนที่เปิดอยู่รันทุกคืนในการสำรองข้อมูลทั้งหมด
6. **เพิ่มปลายทาง** ทุกส่วนมีโฟลเดอร์ของตัวเองบนเซิร์ฟเวอร์นี้อยู่แล้ว ใต้ `/mnt/user/bombvault` การสำรองครั้งแรกจึงมีที่ไป ขั้นนี้เพิ่มที่ที่สอง และที่ปลอดภัยที่สุดคือนอกสถานที่ ทำตอนนี้ได้ด้วย [ตัวอย่าง S3](offsite-recovery.md#example-s3) หรือกลับมาทำหลังการสำรองครั้งแรกเสร็จ การ์ดอยู่จนถึงตอนนั้น
7. **การสำรองข้อมูลครั้งแรก** เปิด **การสำรองข้อมูล** แล้วกด **สำรองข้อมูลทั้งหมดเดี๋ยวนี้** หรือรอถึงกลางคืน วงแหวนในส่วนหัวสถานะกลายเป็นวงแสดงความคืบหน้าและนับรายการ เช่น **Backing up now: 3 of 12** แต่ละคอนเทนเนอร์ถูกหยุดขณะอ่านข้อมูลและเริ่มใหม่ทันทีหลังจากนั้น คอนเทนเนอร์ที่ข้อมูลอยู่บน ZFS หยุดเพียงไม่กี่วินาทีของสแนปช็อต การสำรองครั้งแรกอ่านทุกอย่าง จึงใช้เวลานานที่สุด ครั้งต่อ ๆ ไปเก็บเฉพาะสิ่งที่เปลี่ยน
8. **ตรวจดู** เมื่อวงแหวนบอกว่า **สำรองข้อมูลครบทุกอย่างแล้ว** ให้เปิด **ประวัติ** บนภาพรวม: ทุกคอนเทนเนอร์มีบรรทัดสีเขียวใน **การรัน** เปิด **การสำรองข้อมูล** คลิก `plex` และดูแท็บ **การสำรองข้อมูล** ของมัน: สแนปช็อตแรกอยู่ที่นั่น โดย **ในเครื่อง** เป็นที่เก็บมัน อีกไม่กี่นาทีแท็บ **ยืนยัน** ของมันจะแสดงการตรวจกู้คืน ซึ่งกู้คืนตัวอย่างของการสำรองและอ่านกลับมา
9. **ปกป้องคีย์** เปิด **การตั้งค่า, ความปลอดภัย** และตั้งรหัสผ่านเข้าสู่ระบบ จากนั้นเปิด **การตั้งค่า, การกู้คืน** และกด **ดาวน์โหลดชุดกู้คืน** ใน **สำหรับกรณีฉุกเฉิน** เก็บไฟล์ไว้นอกเซิร์ฟเวอร์ ข้างสำเนา `APP_KEY` จากขั้นที่ 2 การเตือน **บันทึกชุดกู้คืนของคุณ** บนภาพรวมจะหายไปเมื่อคุณกด **ฉันเก็บไว้อย่างปลอดภัยแล้ว**

ต่อจากนี้คอนเทนเนอร์จะถูกสำรองทุกคืน ขั้นถัดไปที่ดี ตามลำดับนี้: [ปลายทางนอกสถานที่](offsite-recovery.md#example-s3) เพื่อไม่ให้เซิร์ฟเวอร์ที่พังพาข้อมูลสำรองไปด้วย จากนั้น [การแจ้งเตือน](notifications.md) เพื่อให้ความล้มเหลวมาถึงคุณ แล้วดู [ตารางเวลา](schedules.md) ถ้า 03:00 ไม่เหมาะกับคุณ

![ส่วนหัวสถานะขณะที่การสำรองครั้งแรกรัน พร้อมวงแสดงความคืบหน้าและสถานี](assets/screenshots/getting-started/status-ring-dark.png#only-dark)
![ส่วนหัวสถานะขณะที่การสำรองครั้งแรกรัน พร้อมวงแสดงความคืบหน้าและสถานี](assets/screenshots/getting-started/status-ring-light.png#only-light)

!!! note "ตรวจการผสานรวมโฮสต์"
    การ์ด **การผสานรวมโฮสต์** บนภาพรวมตรวจทุก mount และ CLI (Docker socket, libvirt, restic, qemu-img, rclone) และรายงานส่วนที่ขาด คุณจึงยืนยันได้ว่าคอนเทนเนอร์เชื่อมต่อถูกต้องก่อนจะพึ่งมัน การ์ดรออยู่ใต้ **ปรับแต่ง** จนกว่าคุณจะเพิ่ม

แถบด้านข้างมีห้ารายการ: **ภาพรวม**, **ความผิดปกติ** (ขณะที่เปิดการตรวจจับความผิดปกติ), **การสำรองข้อมูล**, **การกู้คืน** และใต้ **ออกจากระบบ** คือ **การตั้งค่า** การกระทำหลักของหน้าลอยอยู่มุมล่างขวา และ **เพิ่มเติม** มีอันที่ใช้น้อย บนโทรศัพท์ แถบมีภาพรวม การสำรองข้อมูล การกู้คืน และการตั้งค่า และ **เพิ่มเติม** มีที่เหลือ

หน้าและการตั้งค่าใช้ความกว้างทั้งหมดของหน้าต่าง หน้าต่างเก็บปุ่มของมันไว้ที่ท้าย โดยปุ่มที่ไปข้างหน้าอยู่ทางขวา บนโทรศัพท์ ท้ายหน้าต่างที่มีปุ่มเกินสามปุ่มจะเก็บทางออกและการกระทำหลักไว้ และใส่ปุ่มอื่นใต้ **เพิ่มเติม**

![บนโทรศัพท์ แถบด้านล่างพร้อมเพิ่มเติมที่เปิดอยู่](assets/screenshots/getting-started/phone-more-dark.png#only-dark)
![บนโทรศัพท์ แถบด้านล่างพร้อมเพิ่มเติมที่เปิดอยู่](assets/screenshots/getting-started/phone-more-light.png#only-light)

- **ภาพรวม** แสดงว่าทุกอย่างถูกสำรองไว้หรือไม่และอะไรต้องดูแล ดู [ภาพรวม](overview.md)
- **การสำรองข้อมูล** ลิสต์ทุกคอนเทนเนอร์ VM ชุดโฟลเดอร์ แฟลชไดรฟ์ ชุดข้อมูล ZFS ทุกชุด และการสำรองตัวเองเป็นรายการ ไทล์เหนือรายการเลือกชนิด และ **ตัวกรอง** **เรียงลำดับ** และ **ค้นหา** ช่วยกรอง ทุกรายการมีหน้าของตัวเองพร้อมสามแท็บ: **การสำรองข้อมูล**, **การตั้งค่า** และ **ยืนยัน** ปุ่มย้อนกลับทางซ้ายของไอคอนรายการพาไปยังลิสต์ ดู [การสำรองข้อมูลและรายการ](backups.md)
- **การกู้คืน** เป็นหน้าเดียวสำหรับทุกอย่าง: เลือกส่วน ค้นหารายการ และเลือกข้อมูลสำรอง ตัวช่วยฉุกเฉินและแหล่งอื่นก็เริ่มที่นี่ ดู [การกู้คืน](restore.md)
- **การตั้งค่า** มีสิบสี่ไทล์: ทั่วไป รูปลักษณ์ ตารางเวลา ปลายทางที่จัดเก็บ การกู้คืน การแจ้งเตือน ยืนยัน ความปลอดภัย อินสแตนซ์ การจับคู่ การเชื่อมต่อ แอป ระบบ และข้อมูล ดู [การตั้งค่า](settings.md) กด `/` หรือ Ctrl+K เพื่อค้นหาทั้งหมด รวมถึงชื่อที่หน้าเคยใช้ในเวอร์ชันก่อน ๆ ลากไทล์ให้เป็นลำดับของคุณเองที่ **รูปลักษณ์** ในที่ที่คอลัมน์ไทล์ข้างหน้าจะทำให้หน้าแคบเกินไป เช่นหน้าต่างกว้างราว 1200 พิกเซล ไทล์จะกลายเป็นแถบเหนือหน้าที่เลื่อนไปด้านข้างได้ โทรศัพท์แสดงแถบเดียวกัน
- **ปลายทางที่จัดเก็บ** และ **อินสแตนซ์** เป็นไทล์การตั้งค่าที่มีหน้าของตัวเอง **แสดงในแถบด้านข้างด้วย** บนไทล์ของมันปักหมุดไว้ในแถบด้านข้าง

ไม่มีอะไรมีปุ่มบันทึก และไม่มีอะไรพับเก็บ: ของที่ใช้น้อยมีการ์ดหรือหน้าต่างของตัวเอง และคำอธิบายอยู่ในบับเบิล (i) หลังการอัปเดต หน้าต่างจะเปิดเองพร้อมการ์ดสำหรับทุกรุ่นนับจากเวอร์ชันล่าสุดของคุณ และจุดสีเขียวทำเครื่องหมายสิ่งที่เปลี่ยน คลิกเพื่อซ่อนจุด **ใหม่** ในการ์ดรุ่นใต้ **การตั้งค่า, ข้อมูล** นับสิ่งที่คุณยังไม่ได้เห็นและเปิดหน้าต่างนั้นอีกครั้ง พร้อมบันทึกของแต่ละรุ่นและการเปลี่ยนแปลงของมันด้วย **ไปที่นั่น**

## สร้างจากซอร์ส {#build-from-source}

BombVault เป็นไบนารี Go แบบ static ตัวเดียวที่ให้ JSON API และหน้าตา React แบบฝัง สร้างหน้าตาก่อน แล้วรันไบนารี

```bash
npm --prefix web ci
npm --prefix web run build     # writes web/dist, which the binary embeds
export APP_KEY=$(openssl rand -hex 32)
go test ./...                  # unit and integration tests, with a real restic round trip
golangci-lint run ./...
go run ./cmd/bombvault         # serves https://localhost:3443 with a self-signed certificate
```

ต้องสร้างหน้าตาสำหรับ `go run` ด้วย รีโปติดตามเพียงเครื่องหมายว่างใต้ `web/dist` ดังนั้นถ้าไม่มี `npm --prefix web run build` ไบนารีจะไม่ฝังอะไรเลยและตอบ `500 SPA index not found` ซึ่งเป็นเรื่องปกติ Docker, libvirt และ Unraid ทดสอบใน CI ไม่ได้ ให้ตรวจ mount, restic และลิงก์ SSH ของ VM บนโฮสต์จริงด้วยการ์ด **การผสานรวมโฮสต์** ของภาพรวม (หรือ `GET /api/spike`) ก่อนเปิด pull request

## ขั้นถัดไป {#next-steps}

- เพิ่มปลายทางที่จัดเก็บนอกสถานที่หนึ่งแห่งหรือมากกว่า (แต่ละส่วนคัดลอกไปหลายแห่งพร้อมกันได้) และบันทึกชุดกู้คืนของคุณ ตามที่อธิบายไว้ใต้ **[นอกสถานที่และการกู้คืน](offsite-recovery.md)** [ตัวอย่าง S3](offsite-recovery.md#example-s3) พาทำหนึ่งแห่ง
- ทำให้แน่ใจว่าความล้มเหลวมาถึงคุณด้วย **[การแจ้งเตือน](notifications.md)**
- ดูว่าอะไรรันเมื่อไรใน **[ตารางเวลา](schedules.md)**
- นำทุกเซิร์ฟเวอร์ในกลุ่มของคุณมาไว้บนโทรศัพท์ด้วย **[แอป Android](android.md)**
- **[ตัวอย่างการใช้งานจริง](guides.md)** พาทำงานทั่วไป และ **[ฟีเจอร์](features.md)** ลิสต์ทุกสิ่งที่ BombVault ทำได้
- จะโคลนการตั้งค่าหรือย้ายไปกล่องใหม่ใช่ไหม ย้ายการกำหนดค่าทั้งหมดด้วยการ์ด **ส่งออก / นำเข้าการตั้งค่า** ดู [การกำหนดค่า](configuration.md#portable-settings-export-and-import)
- เจอปัญหาไหม ดู **[การแก้ปัญหา](troubleshooting.md)**
