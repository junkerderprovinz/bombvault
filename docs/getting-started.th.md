# เริ่มต้นใช้งาน

หน้านี้จะพาคุณจากเครื่อง Unraid ที่เพิ่งติดตั้งใหม่ไปจนถึงการสำรองข้อมูลครั้งแรกของคุณ

## ข้อกำหนด

| ข้อกำหนด | หมายเหตุ |
|---|---|
| **Unraid 6.12+** | ยังไม่ได้ทดสอบเวอร์ชันก่อนหน้า Unraid คือเป้าหมายหลัก แต่ BombVault ก็ทำงานบนโฮสต์ Docker ธรรมดาและบน TrueNAS Scale ได้ด้วย (ดู [โฮสต์ Docker ทั่วไป](#generic-docker-host) และ [TrueNAS SCALE](#truenas)) |
| **ตำแหน่งรีพอสิทอรี restic** | พาธในเครื่อง (แนะนำ: อาร์เรย์หรือแคชของคุณ), SMB, NFS หรือแบ็กเอนด์ rclone ใดก็ได้ |
| **Docker socket** | เมานต์โดยอัตโนมัติจากเทมเพลต (`/var/run/docker.sock`) |
| **Unraid flash** (`/boot`) | เมานต์ทั้งหมดโดยอัตโนมัติจากเทมเพลต (`/boot` ไปยัง `/host/boot`) ขับเคลื่อนการสำรองข้อมูลแฟลชและทำให้ container ที่กู้คืนแล้วปรากฏขึ้นอีกครั้งเป็นแอป Unraid ปกติที่แก้ไขได้ |
| **KVM VMs** (เลือกเปิด) | การสำรองข้อมูล VM ติดต่อ libvirt ผ่าน SSH ไม่ต้องเมานต์ libvirt ตั้งค่าที่ **การตั้งค่า, การเชื่อมต่อ, SSH ของโฮสต์** (ดู [Configuration](configuration.md)) |
| **ชุดข้อมูล ZFS** (เลือกเปิด) | ใช้ลิงก์ SSH เดียวกับการสำรองข้อมูล VM, `zfs` บนโฮสต์ และ Host Data ที่แมปเป็น `/mnt` ด้วยโหมดการเข้าถึง Read/Write - Slave ซึ่งเป็นค่าเริ่มต้นของเทมเพลต ดู [ชุดข้อมูล ZFS](zfs-datasets.md) |
| **แอป Android** (ไม่บังคับ) | Android 10 ขึ้นไป จับคู่กับเซิร์ฟเวอร์เวอร์ชัน 9.7.0 ขึ้นไป ดู [แอป Android](android.md) |

## ติดตั้งบน Unraid

เส้นทางที่ง่ายที่สุดคือ **Community Applications**

1. เปิดแท็บ **Apps** ใน Unraid
2. ค้นหา **BombVault**
3. คลิก **Install** ตั้งค่าตัวแปรที่จำเป็น (ด้านล่าง) แล้วนำไปใช้

!!! tip "ติดตั้งเทมเพลตด้วยมือ"
    หากคุณต้องการเพิ่มเทมเพลตด้วยตัวเอง:

    1. ไปที่ **Docker, Add Container, Template repositories** แล้วเพิ่ม:
       ```
       https://github.com/junkerderprovinz/unraid-apps
       ```
    2. ค้นหา **BombVault** ใน Templates
    3. ตั้งค่าตัวแปรที่จำเป็นแล้วคลิก **Apply**

## โฮสต์ Docker ทั่วไป {#generic-docker-host}

ไม่ได้ใช้ Unraid? BombVault ทำงานเป็นคอนเทนเนอร์ธรรมดาบนโฮสต์ Docker ใดก็ได้ ส่วน TrueNAS SCALE มีขั้นตอนของตัวเองอยู่ใน [TrueNAS SCALE](#truenas)

1. ดึงไฟล์ [`deploy/docker-compose.generic.yml`](https://github.com/junkerderprovinz/bombvault/blob/main/deploy/docker-compose.generic.yml) ที่พร้อมแก้ไขจากที่เก็บโค้ด
2. ตั้งค่า `APP_KEY` (ดูด้านล่าง) และชี้ volume Host Data ไปยังรากข้อมูลจริงของคุณ คำอธิบายในไฟล์อธิบายทั้งสองอย่าง
3. `docker compose up -d` แล้วเปิด `https://<host-ip>:3443/`

อะไรที่ต่างไปจาก Unraid:

- **ไม่มีส่วน Flash** ไม่มี USB บูตให้เก็บหรือกู้คืน ส่วน Flash จึงไม่มีงานทำที่นี่ แต่เมื่อ Host Data เข้าถึง `/etc` ของโฮสต์ได้ **เพิ่ม** บนหน้าการสำรองข้อมูลเสนอ **การกำหนดค่าระบบ** เป็นโฟลเดอร์ที่แนะนำ: ชุดโฟลเดอร์ `/etc` ตั้งต้นที่คุณตรวจก่อนบันทึก
- **ไม่มีการแจ้งเตือนดั้งเดิมของ Unraid** ช่องทางแจ้งเตือนของ BombVault เอง (webhook การเตือนเมื่อสำรองนอกสถานที่ล้มเหลว และอื่น ๆ) ทำงานตามปกติ สิ่งที่ข้ามไปมีเพียงการส่งเข้าสู่ระบบแจ้งเตือนเฉพาะของ Unraid เพราะที่นี่ไม่มีระบบดังกล่าว
- **การสำรองเครื่องเสมือนเป็นทางเลือก และต้องมีโฮสต์ libvirtd แยกต่างหากที่เข้าถึงได้ผ่าน SSH** ดูบล็อกที่ถูกคอมเมนต์ไว้ในไฟล์ compose โฮสต์ Docker ทั่วไปไม่มีตัวจัดการเครื่องเสมือนในตัว
- **ไม่มีวิดเจ็ตแดชบอร์ด** BombVault Widget เป็นปลั๊กอินของ Unraid ขั้นตอนนั้นจึงถูกข้ามไปเช่นกัน
- **การหาข้อมูลของคอนเทนเนอร์** เมื่อไม่มีธรรมเนียม `appdata` ของ Unraid โฟลเดอร์ข้อมูลของคอนเทนเนอร์จะถูกหาจากส่วนต่าง ๆ ใน `DATA_ROOT_SEGMENTS`, volume แบบมีชื่อของ Docker, ไดเรกทอรีทำงานของโปรเจกต์ Compose และป้ายกำกับ `bombvault.data` (ดู [การตรวจหาต้นทางของข้อมูลสำรอง](configuration.md#backup-source-detection)) volume แบบมีชื่อและชุดสำเร็จรูป `/etc` เข้าถึงได้เฉพาะพาธภายใน mount ของ Host Data ดังนั้นให้ชี้ Host Data ไปยังไดเรกทอรีบรรพบุรุษร่วมที่ครอบคลุม data root ของ Docker ด้วย
- **`PLATFORM`** ตั้งเป็น `generic` หรือ `truenas` หากไม่ตั้ง BombVault จะตรวจจับ Unraid จากเครื่องหมายของ Unraid เองบน mount ของแฟลช และถือว่าที่อื่นทั้งหมดเป็นโฮสต์ทั่วไป ขั้นตอนเฉพาะ Unraid จะถูกข้ามไปแทนที่จะลองแล้วล้มเหลว

### TrueNAS SCALE {#truenas}

BombVault ยังไม่อยู่ในแค็ตตาล็อกแอปของ TrueNAS จึงต้องติดตั้งเป็นแอปแบบกำหนดเอง: ไปที่ **Apps, Discover Apps** แล้วเลือก **Install via YAML** ในเมนูข้าง **Custom App** YAML ด้านล่างตั้งค่าเหมือนกับรายการในแค็ตตาล็อกที่อยู่ในโฟลเดอร์ `truenas-apps` ของที่เก็บโค้ด เปลี่ยน `tank` เป็นพูลของคุณ และกรอก `APP_KEY` ตามที่หัวข้อถัดไปอธิบาย

```yaml
services:
  bombvault:
    image: junkerderprovinz/bombvault:latest
    hostname: bombvault
    restart: unless-stopped
    cap_drop: [ALL]
    cap_add: [CHOWN, DAC_OVERRIDE, FOWNER, SETGID, SETPCAP, SETUID, SYS_CHROOT]
    environment:
      APP_KEY: ""
      PLATFORM: truenas
      HOST_SOURCE_ROOT: /mnt/tank
      HOST_MOUNT_ROOT: /mnt/tank
      # สำหรับการสำรอง VM:
      # LIBVIRT_URI: qemu+ssh://root@<truenas-ip>/system?socket=/run/truenas_libvirt/libvirt-sock
    volumes:
      - /mnt/tank/apps/bombvault:/config
      - /var/run/docker.sock:/var/run/docker.sock
      - type: bind
        source: /mnt/tank
        target: /mnt/tank
        bind:
          propagation: rslave
    ports:
      - "30528:3443"
```

จากนั้นเปิด `https://<truenas-ip>:30528/` สิ่งที่ระบุไว้ใน [อะไรที่ต่างไปจาก Unraid](#generic-docker-host) ใช้กับที่นี่ด้วย และบน TrueNAS ยังมีเรื่องต่อไปนี้:

- **Capabilities** BombVault ต้องการทั้งเจ็ดอย่างข้างต้น การสำรอง VM จะล้มเหลวหากไม่มี `SETPCAP` และหากไม่มี `SYS_CHROOT` ทุก container จะถูกหยุดตลอดการสำรองแทนที่จะอ่านจากสแนปช็อต
- **Host Data** คือพาธของโฮสต์บนชุดข้อมูล ในที่นี้คือ `/mnt/tank` ซึ่งเมานต์ที่พาธเดียวกันภายในแอป `HOST_SOURCE_ROOT` และ `HOST_MOUNT_ROOT` จึงระบุพาธนี้ทั้งคู่ `rslave` ส่งต่อการเมานต์ที่โฮสต์ทำภายหลัง ซึ่งการสำรองชุดข้อมูล ZFS ต้องใช้
- **ข้อมูลใน ixVolume จะไม่ถูกสำรอง** แอปที่ใช้ ixVolume เป็นที่เก็บข้อมูลจะเก็บข้อมูลไว้ใต้ `/mnt/.ix-apps` ซึ่งอยู่นอก Host Data BombVault จะบันทึกเฉพาะคำจำกัดความของแอป และการรันจะระบุโฟลเดอร์ที่ถูกเว้นไว้ สำหรับทุกแอปที่คุณต้องการสำรองข้อมูล ให้เลือกที่เก็บแบบ **Host Path** บนชุดข้อมูลที่อยู่ใต้ Host Data
- **การสำรอง VM และชุดข้อมูล ZFS** เข้าถึง TrueNAS ผ่าน SSH ในฐานะ root เปิดบริการ SSH ใน **System, Services** แล้วเพิ่มคีย์สาธารณะจาก **การตั้งค่า, การเชื่อมต่อ, SSH ของโฮสต์** ให้ผู้ใช้ root ใน **Credentials, Users** การสำรอง VM ยังต้องใช้ `LIBVIRT_URI` ตามข้างต้น เพราะ libvirtd ของ TrueNAS รอฟังบนซ็อกเก็ตของตัวเอง หากไม่ได้ตั้งทั้ง `LIBVIRT_URI` และ `LIBVIRT_HOST` BombVault จะใช้เกตเวย์เริ่มต้นของแอปเป็นโฮสต์ เพราะ `host.docker.internal` แปลงชื่อไม่ได้ในแอป TrueNAS [คู่มือการสำรอง VM](https://github.com/junkerderprovinz/bombvault/blob/main/docs/vm-backup-ssh-setup.md#truenas-scale) อธิบายรายละเอียด รวมถึง VM บน zvol
- **เรพลิกา ZFS ใช้คีย์อีกตัวหนึ่ง** เรพลิกาบนเซิร์ฟเวอร์ ZFS เครื่องที่สองล็อกอินด้วยคีย์ที่กล่องโต้ตอบเรพลิกาแสดง ไม่ใช่คีย์ SSH ของโฮสต์ ให้เพิ่มคีย์นั้นบนเซิร์ฟเวอร์ปลายทาง
- **แอปที่ถูกลบกลับมาได้ในสองขั้นตอน** ขั้นแรกติดตั้งแอปใหม่ใน TrueNAS ด้วยชื่อเดิม ซึ่งจะสร้างเครือข่ายของมันขึ้นใหม่ จากนั้นจึงกู้คืนข้อมูลใน BombVault ก่อนหน้านั้น การตรวจก่อนการกู้คืนจะรายงานว่าเครือข่ายหายไป และการกู้คืนจะปฏิเสธก่อนที่จะเปลี่ยนแปลงอะไร
- **ข้างต้นฉบับ** สร้างคอนเทนเนอร์ Docker ธรรมดา คอนเทนเนอร์ทำงานได้ แต่หน้าจอ Apps ของ TrueNAS จะไม่แสดงมัน
- **ดัมป์ฐานข้อมูล** ใช้ได้กับการเมานต์ชุดข้อมูล การนำเข้าไปยังโฟลเดอร์ข้อมูลที่เป็นชุดข้อมูลในตัวเองจะย้ายเนื้อหาเดิมไปไว้ในโฟลเดอร์ข้าง ๆ ชุดข้อมูลที่อยู่เหนือขึ้นไปจึงต้องมีที่ว่างพอสำหรับเนื้อหานั้น

## การตั้งค่าเดียวที่จำเป็น

ตัวแปรเดียวที่คุณต้องตั้งค่าคือ `APP_KEY` ซึ่งเป็นค่าลับ hex ขนาด 32 ไบต์ (64 อักขระ hex) ที่ใช้นำมาสร้างรหัสผ่านของรีพอสิทอรี restic

สร้างขึ้นบนเครื่องใดก็ได้:

```bash
openssl rand -hex 32
```

วางผลลัพธ์ลงในช่อง `APP_KEY` ของเทมเพลต (Unraid) หรือตัวแปรสภาพแวดล้อม `APP_KEY` ใน `docker-compose.yml` (โฮสต์ Docker ทั่วไป)

!!! danger "อย่าทำ APP_KEY ของคุณหาย"
    การทำ `APP_KEY` หายจะทำให้การสำรองข้อมูลที่เข้ารหัสไว้ของคุณไม่สามารถกู้คืนได้ เก็บไว้ในที่ปลอดภัยและแยกจากเซิร์ฟเวอร์ เมื่อ BombVault ทำงานแล้ว ให้ตั้งรหัสผ่านเข้าสู่ระบบและดาวน์โหลด **ชุดกู้คืน** ที่ **การตั้งค่า, กู้คืน** (ดู [Off-site & recovery](offsite-recovery.md#recovery-kit)) ในชุดนี้มีคีย์ ปลายทางทุกแห่ง และคำสั่ง restic

เทมเพลตยังเมานต์ Docker socket, แฟลช (`/boot`) และราก **Host Data** (`/mnt`) ให้คุณด้วย ทั้ง *แหล่งที่มา* และ *ปลายทาง* ของการสำรองข้อมูลอยู่ภายใต้ Host Data สำหรับการอ้างอิงตัวแปรฉบับเต็มและการตั้งค่านอกสถานที่ ดู [Configuration](configuration.md)

## การรันครั้งแรก

![ภาพรวมหลังการสำรองข้อมูลครั้งแรก: สิ่งที่ต้องการคุณ การปกป้องของแต่ละส่วน ปลายทาง และประวัติ](assets/screenshots/dashboard.png)

*ภาพรวมหลังการสำรองข้อมูลครั้งแรก: สิ่งที่ต้องการคุณ การปกป้องของแต่ละส่วน ปลายทาง และประวัติ*

1. เปิดเว็บ UI ที่ `https://<your-unraid-ip>:3443` (ใบรับรองแบบ self-signed มาให้พร้อมใช้งาน) การติดตั้งใหม่จะเปิดที่ **ยินดีต้อนรับสู่ BombVault** ซึ่งแสดงรายการสิ่งที่ BombVault พบบนเซิร์ฟเวอร์
2. เลือก **เริ่มเลย** ภาพรวมจะแสดงการ์ด **ขั้นตอนแรก** ที่มีสามขั้นตอน:
    1. **เลือกส่วนที่จะสำรอง**: เปิดสิ่งที่ BombVault สำรองข้อมูล (Containers, VMs, Flash, โฟลเดอร์, ชุดข้อมูล ZFS, สำรองข้อมูลตัวเอง) **เลือก** เปิดรายการของส่วนนั้น ซึ่ง **หยุดกำหนดการชั่วคราว** ใช้ข้ามรายการหนึ่งได้ ส่วนที่คุณเปิดตรงนี้จะรันทุกคืน ซึ่งเปลี่ยนได้ที่ **การตั้งค่า, ตารางเวลา**
    2. **เพิ่มปลายทาง**: ที่ที่ข้อมูลสำรองไปอยู่ โฟลเดอร์ในเครื่องก็เพียงพอสำหรับเริ่มต้น ที่ปลอดภัยที่สุดคือปลายทางที่สองนอกสถานที่ เช่น Storage Box หรือ Backblaze B2 รีพอสิทอรีในเครื่องใช้ค่าเริ่มต้นเป็น `/mnt/user/bombvault/{container,vms,flash,config,files,zfs}` และจะถูกสร้างขึ้นในการสำรองข้อมูลครั้งแรก
    3. **การสำรองข้อมูลครั้งแรก**: หลังจากนั้นจะรันเองทุกคืน
3. เปิด **การสำรองข้อมูล** เพื่อดูทุกรายการในรายการเดียว **สำรองข้อมูลทั้งหมดเดี๋ยวนี้** เริ่มการรันกับทุกส่วนที่เปิดอยู่ และ **สำรองข้อมูลเดี๋ยวนี้** บนหน้าของรายการจะสำรองเฉพาะรายการนั้น

เคยใช้ BombVault มาก่อน? **กู้คืนจากข้อมูลสำรอง** บนหน้าต้อนรับจะเปิดหน้าการกู้คืน ซึ่ง **ตัวช่วยฉุกเฉิน** นำการตั้งค่า containers VMs และโฟลเดอร์ของเซิร์ฟเวอร์ที่หายไปกลับมา ดู [Off-site & recovery](offsite-recovery.md#emergency)

!!! tip "ทางเลือก: เลือกลำดับการสำรองข้อมูล"
    หาก containers บางตัวควรถูกสำรองข้อมูลก่อนตัวอื่นเสมอ (เช่น ฐานข้อมูลก่อนแอปที่ใช้มัน) ให้เปิดการ์ด **ลำดับ** ที่ **การตั้งค่า, ตารางเวลา** แล้วลากพวกมันเข้าไปในลำดับที่คุณต้องการ การรันตามตารางเวลาและการสำรองข้อมูลทั้งหมดจะทำตามลำดับนั้น ส่วนสิ่งที่คุณไม่ได้จัดลำดับจะถูกสำรองข้อมูลโดยเรียงตามที่เกินกำหนดมากที่สุดก่อน

!!! note "การตรวจสอบการผสานรวมโฮสต์"
    การ์ด **การผสานรวมโฮสต์** บนภาพรวมจะตรวจสอบทุกการเมานต์และ CLI (Docker socket, libvirt, restic, qemu-img, rclone) และรายงานส่วนที่ขาดหายไป เพื่อให้คุณยืนยันได้ว่า container เชื่อมต่อถูกต้องก่อนที่คุณจะพึ่งพามัน การ์ดนี้รออยู่ใต้ **ปรับแต่ง** จนกว่าคุณจะเพิ่มเข้ามา

## หาทางในแอป {#navigation}

![การตั้งค่าเป็นไทล์ โดยมีการ์ดของไทล์ที่เลือกอยู่ข้าง ๆ ทุกการเปลี่ยนแปลงถูกเขียนทันทีที่คุณทำ](assets/screenshots/settings.png)

*การตั้งค่าเป็นไทล์ โดยมีการ์ดของไทล์ที่เลือกอยู่ข้าง ๆ ทุกการเปลี่ยนแปลงถูกเขียนทันทีที่คุณทำ*

แถบด้านข้างมีห้ารายการ: **ภาพรวม**, **ความผิดปกติ** (ขณะที่การตรวจจับความผิดปกติเปิดอยู่), **การสำรองข้อมูล**, **การกู้คืน** และ **การตั้งค่า** ใต้ **ออกจากระบบ** การกระทำหลักของหน้าจะลอยอยู่มุมขวาล่าง และ **เพิ่มเติม** เก็บรายการที่ใช้ไม่บ่อย บนโทรศัพท์ แถบมีภาพรวม การสำรองข้อมูล การกู้คืน และการตั้งค่า ส่วนที่เหลืออยู่ใน **เพิ่มเติม**

หน้าและการตั้งค่าใช้ความกว้างเต็มหน้าต่าง หน้าต่างวางปุ่มไว้ที่ส่วนท้าย โดยปุ่มที่ไปข้างหน้าอยู่ทางขวา บนโทรศัพท์ ส่วนท้ายที่มีปุ่มมากกว่าสามปุ่มจะเก็บปุ่มทางออกและการกระทำหลักไว้ และย้ายปุ่มที่เหลือไปไว้ใต้ **เพิ่มเติม**

- **การสำรองข้อมูล** แสดง container, VM, ชุดโฟลเดอร์, แฟลชไดรฟ์, ชุดข้อมูล ZFS ทุกชุด และสำรองข้อมูลตัวเองเป็นรายการในรายการเดียว ไทล์เหนือรายการเลือกชนิด และ **ตัวกรอง**, **เรียงลำดับ** และ **ค้นหา** ช่วยจำกัดให้แคบลง แต่ละรายการมีหน้าของตัวเองพร้อมสามแท็บ: **การสำรองข้อมูล**, **การตั้งค่า** และ **ยืนยัน** ปุ่มย้อนกลับทางซ้ายของไอคอนของรายการนำไปสู่รายการ
- **การกู้คืน** เป็นหน้าเดียวสำหรับทุกอย่าง: เลือกส่วน ค้นหารายการ แล้วเลือกข้อมูลสำรอง ตัวช่วยฉุกเฉินและแหล่งอื่นก็เริ่มจากที่นี่
- **การตั้งค่า** มีสิบสี่ไทล์: ทั่วไป, รูปลักษณ์, ตารางเวลา, ปลายทาง, กู้คืน, การแจ้งเตือน, ยืนยัน, ความปลอดภัย, อินสแตนซ์, การจับคู่, การเชื่อมต่อ, แอป, ระบบ และข้อมูล กด `/` หรือ Ctrl+K เพื่อค้นหาทั้งหมด รวมถึงค้นด้วยชื่อที่หน้าเหล่านั้นเคยมีในเวอร์ชันก่อน ลากไทล์ไปเรียงตามลำดับของคุณเองได้ที่ **รูปลักษณ์** ในที่ที่คอลัมน์ไทล์ข้างหน้าจะบีบหน้าให้แคบเกินไป เช่นในหน้าต่างกว้างราว 1200 พิกเซล ไทล์จะกลายเป็นแถบเหนือหน้าที่เลื่อนไปด้านข้างได้ โทรศัพท์แสดงแถบเดียวกัน
- **ปลายทาง** และ **อินสแตนซ์** เป็นไทล์การตั้งค่าที่มีหน้าของตัวเอง **แสดงในแถบด้านข้างด้วย** บนไทล์ของทั้งสองปักหมุดไว้ที่แถบด้านข้าง

ไม่มีอะไรมีปุ่มบันทึก และไม่มีอะไรที่พับเก็บ: ของที่ใช้ไม่บ่อยมีการ์ดหรือหน้าต่างของตัวเอง และคำอธิบายอยู่ในบับเบิล (i) หลังการอัปเดต หน้าต่างจะเปิดขึ้นเองพร้อมการ์ดของทุกรุ่นนับจากเวอร์ชันล่าสุดของคุณ และจุดสีเขียวจะทำเครื่องหมายสิ่งที่เปลี่ยน การคลิกจะซ่อนจุด **ใหม่** ในการ์ดรุ่นใต้ **การตั้งค่า, ข้อมูล** นับสิ่งที่คุณยังไม่ได้เห็น และเปิดหน้าต่างนั้นอีกครั้ง พร้อมบันทึกประจำรุ่นของแต่ละรุ่นและการเปลี่ยนแปลงของรุ่นนั้นที่มี **ไปที่นั่น**

## การบิลด์จากซอร์สโค้ด {#build-from-source}

BombVault เป็นไบนารี Go แบบสแตติกไฟล์เดียวที่ให้บริการ JSON API และอินเทอร์เฟซ React ที่ฝังอยู่ในตัว ให้บิลด์อินเทอร์เฟซก่อน แล้วจึงรันไบนารี:

```bash
npm --prefix web ci
npm --prefix web run build     # เขียน web/dist ซึ่งไบนารีจะฝังไว้ในตัว
export APP_KEY=$(openssl rand -hex 32)
go test ./...                  # unit test และ integration test รวมการรับส่งผ่าน restic จริง
golangci-lint run ./...
go run ./cmd/bombvault         # ให้บริการที่ https://localhost:3443 ด้วยใบรับรองแบบ self-signed
```

`go run` ก็ต้องบิลด์อินเทอร์เฟซก่อนเช่นกัน ที่เก็บโค้ดติดตามเพียงไฟล์มาร์กเกอร์ว่างใต้ `web/dist` ดังนั้นหากไม่รัน `npm --prefix web run build` ไบนารีจะไม่ฝังอะไรไว้เลยและตอบกลับ `500 SPA index not found` ซึ่งเป็นสิ่งที่คาดไว้ Docker, libvirt และ Unraid ทดสอบใน CI ไม่ได้ ดังนั้นก่อนเปิด pull request ให้ตรวจ mount, restic และลิงก์ SSH ของ VM บนโฮสต์จริงด้วยการ์ด **การผสานรวมโฮสต์** บนภาพรวม (หรือ `GET /api/spike`)
