# การสำรองข้อมูลและรายการ

ทุกอย่างที่ BombVault สำรองอยู่ในรายการเดียวใต้ **การสำรองข้อมูล** ได้แก่ คอนเทนเนอร์ VM ชุดโฟลเดอร์ แฟลชไดรฟ์ ชุดข้อมูล ZFS และการสำรองตัวเอง แต่ละอย่างเป็น **รายการ** ที่มีหน้าของตัวเอง หน้านี้พาดูรายการ หน้าของรายการกับสามแท็บของมัน และการตั้งค่าที่รายการมีได้

## แต่ละส่วนบันทึกอะไร {#what-is-saved}

| ส่วน | สิ่งที่ถูกบันทึก |
|---|---|
| **คอนเทนเนอร์** | โฟลเดอร์ appdata พร้อมคำจำกัดความของคอนเทนเนอร์: image ตัวแปร พอร์ต ป้ายกำกับ และวอลุ่ม การ์ด **โฟลเดอร์ที่สำรองข้อมูล** บนแท็บ **การตั้งค่า** ของคอนเทนเนอร์ติ๊กว่าการสำรองครอบคลุมโฟลเดอร์ไหนบ้าง พร้อมจำนวนพาธสด และรายการสิ่งที่คุณเว้นไว้ ข้อมูลที่คอนเทนเนอร์เก็บนอก Host Data เช่นใน ixVolume ของ TrueNAS หรือโปรเจกต์ Compose ใต้ `/opt` จะไม่ถูกสำรอง และการรันจะบอกชื่อโฟลเดอร์ที่ข้ามไป การรันยังบอกชื่อโฟลเดอร์ภายใน Host Data ที่ตอนนี้ไม่มีอยู่ด้วย พาธของระบบ เช่น `/etc/localtime` หรือ socket ของ Docker ไม่นับเป็นข้อมูล |
| **VMs** | image ดิสก์ คำจำกัดความ XML และ UEFI NVRAM ด้วยการปิดเครื่องอย่างนุ่มนวลหรือสแนปช็อตแบบสด ผ่าน SSH ดู [การสำรอง VM](vm-backup-ssh-setup.md) |
| **Flash** | เฉพาะ Unraid แฟลช USB ทั้งหมด (`/boot`): ระบบปฏิบัติการ ไลเซนส์ การตั้งค่าอาร์เรย์ share เครือข่าย และการตั้งค่าปลั๊กอิน |
| **สำรองข้อมูลตัวเอง** | `/config` ของ BombVault เอง: ฐานข้อมูลการตั้งค่า ข้อมูลรับรองของปลายทางที่จัดเก็บ คู่คีย์ SSH ของ libvirt คีย์และโฮสต์ที่ปักหมุดไว้ของเซิร์ฟเวอร์ ZFS และใบรับรอง ทำสแนปช็อตด้วย SQLite `VACUUM INTO` ฐานข้อมูลจึงไม่ถูกจับกลางการเขียน |
| **โฟลเดอร์** | โฟลเดอร์ใดก็ได้บนเซิร์ฟเวอร์เป็นชุดโฟลเดอร์ เช่น share เอกสารของคุณ หรือคลังรูปภาพ พร้อมรูปแบบการยกเว้นที่เลือกได้ ชุดโฟลเดอร์มีตารางเวลา การเก็บรักษา สำเนานอกสถานที่ การตรวจ และการซ้อมกู้คืนเหมือนอย่างอื่น |
| **ชุดข้อมูล ZFS** | ชุดข้อมูลหนึ่งและทุกชุดข้างใต้ อ่านจากสแนปช็อต ZFS เดียว ทุกชุดจึงมาจากช่วงเวลาเดียวกัน และเก็บด้วย restic เหมือนโฟลเดอร์ รายการ ZFS เก็บเรพลิกาแบบตรงทุกบล็อกบนเซิร์ฟเวอร์ ZFS ตัวที่สองได้ด้วย ดู [ชุดข้อมูล ZFS](zfs-datasets.md) |

ทุกการสำรองผ่าน restic จึงเพิ่มทีละส่วนและขจัดข้อมูลซ้ำ แม้ดิสก์ VM ขนาดใหญ่ก็ไม่ทำให้ที่เก็บบวม BombVault ไม่เคยสำรอง และจึงไม่เคยหยุด คอนเทนเนอร์ของตัวเอง หยุดการรันได้อย่างปลอดภัย เพราะ restic เขียนสแนปช็อตเป็นอย่างสุดท้าย การรันที่ถูกยกเลิกจึงทิ้งข้อมูลที่ไม่มีใครอ้างถึงไว้และไม่มีสแนปช็อต ล็อกที่ค้างจากการรีสตาร์ทกลางการรันจะถูกล้างและลองการรันอีกครั้ง หลังจากล็อกไม่ถูกต่ออายุเป็นเวลาสิบนาทีเท่านั้น

## รายการ {#list}

ไทล์เหนือรายการเลือกชนิด เช่น **คอนเทนเนอร์** หรือ **ZFS** และแต่ละไทล์นับจำนวนรายการของมัน ไทล์ใช้เลือก ไม่ได้ซ่อนส่วนที่เหลือของหน้า

แต่ละแถวแสดงการรันสิบสี่ครั้งล่าสุดของรายการเป็นสี่เหลี่ยมเล็ก ๆ และหนึ่งสถานะ เช่น **ได้รับการป้องกัน**, **ไม่ได้รับการป้องกัน**, **เลื่อนไว้** หรือ **กำลังจำลอง** ที่เหลือทั้งหมดอยู่ในบับเบิลข้อมูลข้างชื่อ และขณะที่เมาส์อยู่บนแถว ข้อความนั้นจะอยู่ในแถวเอง เครื่องหมายข้างชื่อคอนเทนเนอร์บอกว่ามันถูกสร้างใหม่ด้วย image พอร์ต ตัวแปร หรือวอลุ่มอื่นนับจากการสำรองครั้งล่าสุด เครื่องหมายจะหายไปเมื่อสำรองครั้งถัดไป

สามปุ่มเหนือรายการช่วยกรอง

- **ตัวกรอง**: ตาม **ตารางเวลา** (**ทั้งหมด**, **มีตารางเวลา**, **หยุดชั่วคราว**) ตาม **สำรองข้อมูล** (**สำรองแล้ว**, **ไม่เคยสำรองข้อมูล**) และสำหรับ **Containers และ VMs** คือ **ที่ติดตั้งแล้ว** หรือ **ไม่ได้ติดตั้ง**
- **เรียงลำดับ**: ตามชื่อ สถานะ IP การสำรองล่าสุด ขนาด หรือตารางเวลา ทุกฟิลด์ยกเว้น IP เรียงได้ทั้งสองทาง เช่น **ขนาด ใหญ่สุดก่อน** และ **ขนาด เล็กสุดก่อน**
- **ค้นหา**: ตามชื่อ image หรือ IP

รายการที่ไม่ได้ติดตั้งแล้วแต่ยังมีข้อมูลสำรองจะแยกอยู่ใต้ **ไม่ได้ติดตั้ง (เฉพาะการสำรองข้อมูล)** กู้คืนมัน หรือลบข้อมูลสำรองของมันเพื่อเอาที่คืน

การกระทำหลักของหน้าลอยอยู่มุมล่างขวา: **สำรองข้อมูลทั้งหมดเดี๋ยวนี้** เริ่มรอบที่ครอบคลุมทุกส่วนที่เปิดอยู่ **เพิ่มเติม** มีที่เหลือ

- **เลือก** เริ่มการเลือก ดูด้านล่าง
- **ค้นหาการสำรองข้อมูล** อ่านสิ่งที่ปลายทางที่จัดเก็บมีอยู่และสร้างรายการขึ้นใหม่จากนั้น เช่นหลังติดตั้งใหม่ คอนเทนเนอร์ที่ไม่มีข้อมูลของตัวเองจะไม่มีสแนปช็อต และกลับมาจากคำจำกัดความที่มีสำเนาเก็บไว้ข้างที่เก็บ สำเนานอกสถานที่ของส่วนที่สร้างใหม่จะรอจนกว่าคุณจะรับข้อมูลสำรองของมันเป็นของเซิร์ฟเวอร์นี้ ดู [หลังสร้างใหม่](offsite-recovery.md#after-a-rebuild)
- **การเชื่อมต่อ ZFS กับเซิร์ฟเวอร์นี้** เปิดการทดสอบ SSH ของส่วน ZFS ดู [ชุดข้อมูล ZFS](zfs-datasets.md#requirements)
- **ทำเรพลิกาทั้งหมดตอนนี้** เมื่อเลือกไทล์ ZFS ส่งเรพลิกาของทุกรายการ ZFS

## เลือกหลายรายการ {#select}

เลือกแถวแบบเดียวกับการเลือกไฟล์ในตัวจัดการไฟล์: Ctrl+คลิก Shift+คลิก Ctrl+A หรือกดค้างบนโทรศัพท์ แถวที่เลือกแสดงเครื่องหมายถูกแทนไอคอน และแถบเหนือรายการนับจำนวนและมี **สำรองข้อมูลที่เลือก**, **หยุดกำหนดการชั่วคราว** และ **ทำกำหนดการต่อ**, **เลือกทั้งหมด** และ **ล้างการเลือก** ทุกแถวยังมีเมนูคลิกขวาพร้อมการกระทำของตัวเอง

ชุดที่เลือกถูกสำรองบนเซิร์ฟเวอร์ ทีละรายการ จึงทำงานต่อแม้คุณปิดแท็บ ถ้าจะกู้คืนหลายรายการพร้อมกัน ให้ใช้ [หน้าการกู้คืน](restore.md#several)

## เพิ่มโฟลเดอร์หรือชุดข้อมูล ZFS {#add}

คอนเทนเนอร์ VM และแฟลชไดรฟ์ปรากฏเองเมื่อเปิดส่วนของมันที่ **การตั้งค่า, ทั่วไป** โฟลเดอร์และชุดข้อมูล ZFS คุณต้องเลือกเอง เพราะ BombVault เดาไม่ได้ว่าคุณหมายถึงอันไหน **เพิ่ม** เปิด **BombVault ควรสำรองข้อมูลอะไรเพิ่มอีก**

- **หนึ่งโฟลเดอร์** ลิสต์ share ที่ BombVault พบและรับโฟลเดอร์อื่นใดก็ได้ใต้ Host Data ตั้งชื่อชุดโฟลเดอร์ เช่น `Documents` ชื่อจะตายตัวหลังการสำรองครั้งแรก เพราะสแนปช็อตเก็บอยู่ใต้ชื่อนั้น
- **ชุดข้อมูล ZFS** ลิสต์ชุดข้อมูลของเซิร์ฟเวอร์นี้ เลือกอันบนสุดของสิ่งที่ต้องการสำรอง ดู [รายการและชุดข้อมูลลูก](zfs-datasets.md#items-and-children)
- **การกำหนดค่าระบบ** ปรากฏบนโฮสต์ที่ไม่ใช่ Unraid ซึ่ง Host Data เข้าถึง `/etc` ได้ เป็นชุดโฟลเดอร์ `/etc` เริ่มต้นที่คุณตรวจดูก่อนบันทึก

## เว้นรายการไว้ {#dont-back-up}

รายการที่คุณตั้งใจเว้น เช่นคอนเทนเนอร์ทดสอบ ทำเครื่องหมาย **ไม่สำรองข้อมูล** ได้ แล้วมันจะไม่นับเป็นยังไม่ได้ป้องกัน และ **ยกเลิกการยกเว้น** จะนำกลับ **หยุดกำหนดการชั่วคราว** เป็นวิธีที่นุ่มนวลกว่า รายการออกจากตารางเวลาและการสำรองข้อมูลทั้งหมด มีป้ายสีเทา **กำหนดการถูกหยุดชั่วคราว** และ **สำรองข้อมูลเดี๋ยวนี้** ยังใช้ได้ มันตั้งสวิตช์เดียวกับ **อยู่ในตารางเวลา** บนแท็บการตั้งค่าของรายการ

## หน้าของรายการ {#entry-page}

คลิกที่แถวเพื่อเปิดหน้าของรายการ ส่วนหัวบอกชื่อรายการและสถานะในบรรทัดเดียว เช่น **สำรองข้อมูลล่าสุดเมื่อ 3 ชั่วโมงก่อน** หรือ **เลื่อนไว้ ลองครั้งถัดไปเวลา 03:15** และมีการกระทำของมัน: **สำรองข้อมูลเดี๋ยวนี้**, **กู้คืน** และใต้ **เพิ่มเติม** คืออันที่ใช้น้อย เช่น **ส่งออกข้อมูลสำรองล่าสุด**, **ส่งออกคอนเทนเนอร์** หรือ **ส่งออก VM**, **เชื่อมโยงกับรายการเดิม**, **ลบการสำรองข้อมูลทั้งหมด**, **ลบรายการ** และ **ลบข้อมูลสำรองทุกที่** ปุ่มย้อนกลับทางซ้ายของไอคอนพาไปยังรายการ ขณะที่การสำรองรัน **ยกเลิกการสำรองข้อมูล** อยู่ข้างความคืบหน้าของมัน และการรันที่ยกเลิกจะบันทึกเป็นยกเลิก ไม่ใช่ล้มเหลว

**ลบข้อมูลสำรองทุกที่** ลบข้อมูลสำรองของรายการจากทุกปลายทางในครั้งเดียว รวมถึงสำเนานอกสถานที่ด้วย หน้าต่างจะแสดงแต่ละที่พร้อมจำนวนข้อมูลสำรองที่มี และปุ่มจะใช้ได้เมื่อคุณพิมพ์ชื่อรายการ ที่ที่ตั้งเป็น append-only จะเก็บข้อมูลสำรองไว้และบอกให้ทราบ รายการและการตั้งค่ายังอยู่ ดังนั้นรายการที่คุณไม่ได้สำรองแล้วจะยังเป็นแบบนั้น และที่หายไปมีเพียงข้อมูลสำรองกับประวัติของมัน

หน้ามีสามแท็บ: **การสำรองข้อมูล**, **การตั้งค่า** และ **ยืนยัน**

### แท็บการสำรองข้อมูล {#backups-tab}

แท็บนี้ลิสต์สแนปช็อตของรายการ ใหม่สุดก่อน พร้อมแถบต่อวัน การสำรองที่อยู่ในหลายที่ปรากฏหนึ่งครั้ง โดยทำเครื่องหมายปลายทางที่เก็บมันทุกแห่ง คลิกสแนปช็อตเพื่อกู้คืน และคลิกที่ตำแหน่งภายในสแนปช็อตเพื่อกู้คืนจากตรงนั้น

- **ปลายทาง** ระบุทุกที่ที่มีข้อมูลสำรองของรายการนี้และจำนวน ที่นอกสถานที่จะถูกอ่านเมื่อคุณกด **ตรวจสอบ** เท่านั้น เพราะการลิสต์ที่จัดเก็บบนคลาวด์ใช้เวลา ที่ที่รายการไม่ได้สำรองไปแล้วจะแสดงเป็น **เฉพาะข้อมูลสำรองเก่า** และยังกู้คืนจากมันได้
- ทุกสแนปช็อตมีเมนู: **เพิ่มแท็ก** หรือ **เปลี่ยนแท็ก**, **เปรียบเทียบกับข้อมูลสำรองอื่น** ซึ่งลิสต์ไฟล์ที่เข้ามา หายไป หรือเปลี่ยน, **ส่งออก** เป็น tar, zip หรือที่เก็บ restic ของตัวเอง และลบที่เดียวเท่านั้น
- **ไฟล์ดัมป์ฐานข้อมูล** ของคอนเทนเนอร์อยู่ในรายการของตัวเอง พร้อมดาวน์โหลด บันทึกลงโฟลเดอร์ และนำเข้า

จำนวนสแนปช็อตที่คงไว้ตั้งที่ปลายทาง ดู [เก็บไว้นานแค่ไหน](offsite-recovery.md#keep)

### แท็บการตั้งค่า {#settings-tab}

ทุกรายการเริ่มด้วย **ตารางเวลาและปลายทาง**

- **อยู่ในตารางเวลา** นำรายการเข้าหรือออกจากรอบตามกำหนด
- **กำหนดการของตัวเอง** ให้รายการนี้มีกำหนดการของตัวเอง ดู [กำหนดการของตัวเองสำหรับหนึ่งรายการ](schedules.md#own-plan) ถ้าไม่มี มันรันตามกำหนดการของส่วนหรือในการสำรองข้อมูลทั้งหมด
- แถวปุ่ม **ในเครื่อง** และหนึ่งปุ่มต่อปลายทางนอกสถานที่ บอกว่าข้อมูลสำรองไปที่ไหน **เป็นไปตามค่าเริ่มต้น** หมายถึงรายการไปที่เดียวกับส่วนของมัน และคลิกจะเปิด **ปลายทางแยกตามส่วน** ดู [การวางต่อรายการ](offsite-recovery.md#placement)
- **รีพอสิทอรี** บอกว่าข้อมูลสำรองถูกเขียนที่ไหน (**จัดเก็บที่**) ที่นั้นตายตัวตั้งแต่การสำรองครั้งแรก ส่วนสำเนาเปลี่ยนได้ทุกเมื่อ

### แท็บยืนยัน {#verify-tab}

- **การตรวจสอบ** แสดงการตรวจกู้คืนที่ตามหลังการสำรองครั้งแรก **ตรวจการกู้คืน** รันอีกครั้งบนการสำรองใหม่สุด: BombVault กู้คืนตัวอย่างไม่เกิน 100 ไฟล์และ 256 MiB ลงโฟลเดอร์ชั่วคราว และให้ restic อ่านทุกไฟล์กลับมาเทียบกับแฮช
- **ทดสอบการเริ่ม** บนคอนเทนเนอร์ กู้คืนการสำรองใหม่สุดเป็นสำเนาที่แยกไว้และเริ่มมัน: ชื่อขึ้นต้นด้วย `bombvault-test-` เครือข่าย Docker ภายในของตัวเองที่ไม่มีพอร์ตเผยแพร่และไม่มีทางออกไป LAN, 1 CPU และหน่วยความจำ 2 GiB ผ่านเมื่อสำเนารายงานว่าพร้อม ตอบที่พอร์ตแรกที่เปิดอยู่ หรือถ้าไม่มีทั้งสองอย่าง ก็ยังรันอยู่ ต้นฉบับไม่ถูกแตะเลย และสำเนา เครือข่าย และข้อมูลของมันจะถูกลบทีหลัง แม้หลังการรีสตาร์ทกลางการทดสอบ คอนเทนเนอร์บนเครือข่ายโฮสต์ แบบ privileged แบบมีอุปกรณ์ และแบบที่ต้องใช้คอนเทนเนอร์อื่น จะแสดงว่าทดสอบไม่ได้ **ทดสอบการเริ่ม** ใต้ **การตั้งค่า, ยืนยัน, การตรวจสอบอัตโนมัติ** ทดสอบหนึ่งคอนเทนเนอร์ต่อรอบ ตัวที่ทดสอบนานที่สุดแล้วก่อน
- **ความผิดปกติ** ตั้งความไวและระดับการแจ้งเตือนของรายการนี้ และแสดงสิ่งที่พบที่เปิดอยู่
- **ขนาดตามโฟลเดอร์** แสดงว่าอะไรกินที่ในการสำรองใหม่สุด และการสำรองล่าสุดนำเข้ามาเท่าไร ทีละระดับ
- **การทำงานล่าสุด** ลิสต์การรันล่าสุดพร้อมเวลาเริ่ม สิ้นสุด และระยะเวลา คลิกเพื่อดูรายละเอียด

## รูปแบบการยกเว้น {#excludes}

การ์ด **รูปแบบการยกเว้น** รับหนึ่งรูปแบบต่อบรรทัด พิมพ์พาธตามที่เห็นภายในคอนเทนเนอร์ เช่น `/config/Library/Application Support/Plex Media Server/Cache` หรือชื่อเปล่า ๆ อย่าง `.git` ซึ่งตรงที่ความลึกใดก็ได้ ในชุดโฟลเดอร์ ให้พิมพ์พาธตามที่โฮสต์รู้จัก เช่น `/mnt/user/data/cache` ตัวอย่างใต้ช่องแสดงว่าแต่ละบรรทัดแปลงเป็นอะไร และเตือนเมื่อบรรทัดไม่ตรงกับอะไรเลยหรือจะยกเว้นทุกอย่าง บรรทัด `/` หรือ `*` หรือบรรทัดที่ระบุโฟลเดอร์ที่สำรองทั้งโฟลเดอร์จะถูกเพิกเฉย การยกเว้นจึงทำให้การสำรองว่างเปล่าไม่ได้ ถ้าจะเว้นทั้งโฟลเดอร์ ให้เอาติ๊กออกใต้ **โฟลเดอร์ที่สำรองข้อมูล** แทน

สำหรับ image ที่รู้จักกันดี เช่น Plex, Jellyfin, Sonarr, Radarr, Immich และ Nextcloud การ์ดเสนอโฟลเดอร์ที่แอปเติมให้เต็มเองอีกครั้ง เช่นแคช บันทึก และภาพย่อ ไม่มีอะไรถูกยกเว้นจนกว่าคุณจะกด **ยกเว้นรายการที่เลือก**

ชุดโฟลเดอร์ใหม่เริ่มต้นด้วยกลุ่ม **ไฟล์ขยะของระบบ** ที่เปิดไว้ ได้แก่ `.DS_Store`, `Thumbs.db`, `desktop.ini`, `@eaDir` (Synology), `.Recycle.Bin` (ปลั๊กอิน Recycle Bin ของ Unraid), `.Trash-*` และ `*.tmp` แต่ละรายการเป็นชื่อเปล่า ๆ จึงตรงกันได้ทุกระดับความลึกใต้โฟลเดอร์ และคุณปิดรายการใดก็ได้ก่อนสร้างชุด ชุดโฟลเดอร์ที่มีอยู่แล้วจะเก็บรายการยกเว้นเดิมไว้ **ยกเว้นไฟล์ขยะของระบบ** ในหน้าต่างแก้ไขของชุดนั้นมีบรรทัดเดียวกันให้เลือก และบรรทัดเหล่านี้จะเข้าไปในชุดก็ต่อเมื่อคุณกด **ยกเว้นรายการที่เลือก** แล้วบันทึก

การ์ดเดียวกันมีคำเตือนที่การสแกนโฟลเดอร์มองไม่เห็น ตัวอย่างเช่น Immich เก็บอัลบั้ม ใบหน้า และวันที่ไว้ในฐานข้อมูล PostgreSQL ในคอนเทนเนอร์แยก การสำรองไฟล์ของคอนเทนเนอร์ Immich อย่างเดียวจึงกู้คืนรูปภาพได้โดยไม่มีสิ่งเหล่านั้น และการกู้คืนดูเหมือนสำเร็จ สำรองคอนเทนเนอร์ฐานข้อมูลด้วย

## ไฟล์ดัมป์ฐานข้อมูล {#database-dumps}

คอนเทนเนอร์ PostgreSQL, MySQL และ MariaDB ที่ BombVault รู้จักจะถูกดัมป์ก่อนการสำรองแต่ละครั้ง จากเซิร์ฟเวอร์ที่กำลังรัน เป็นจุดกู้คืนของตัวเองข้างไฟล์ ครอบคลุม image ทางการ PostGIS, TimescaleDB, pgvector, pgautoupgrade, image ฐานข้อมูลของ Immich, image MariaDB ของ linuxserver, yobasystems และ jc21 และ mysql-server ของ Oracle คอนเทนเนอร์ที่แค่ดูเหมือนฐานข้อมูลได้ตัวเลือกเดียวกัน แต่ปิดอยู่จนกว่าคุณจะเลือก

ดัมป์สตรีมตรงเข้าที่เก็บและไม่เคยถูกเขียนลงดิสก์ ข้อมูลรับรองมาจากตัวแปรของคอนเทนเนอร์เอง รวมถึงความลับ `*_FILE` และไม่เคยออกจากมัน การ์ด **ฐานข้อมูล** บนแท็บการตั้งค่าของคอนเทนเนอร์บอกว่าโฟลเดอร์ข้อมูลถูกบันทึกขณะหยุด คัดลอกขณะรัน หรือไม่ถูกบันทึก และเปิดหรือปิดดัมป์สำหรับคอนเทนเนอร์นี้ ป้าย `bombvault.dbdump=false` ทำสิ่งเดียวกันและชนะการ์ด **ดัมป์ฐานข้อมูลอัตโนมัติ** ใต้ **การตั้งค่า, ทั่วไป** เปิดหรือปิดให้ทั้งหมด

ดัมป์ที่ล้มเหลวไม่ทำให้การสำรองล้มเหลว มันปรากฏเป็นการรันที่ล้มเหลวของตัวเองพร้อมเหตุผลและส่งการแจ้งเตือน ดัมป์ไม่ถูกโหลดกลับเอง: ดาวน์โหลดทั้งแบบธรรมดาหรือบีบอัด บันทึกลงโฟลเดอร์ หรือนำเข้าไปยังฐานข้อมูลที่เพิ่งเริ่มใหม่ด้วยคลิกเดียวที่แท็บ **การสำรองข้อมูล** ถ้าจะนำดัมป์กลับมาโดยไม่ใช้ BombVault ดู [นำไฟล์ดัมป์ฐานข้อมูลกลับมา](offsite-recovery.md#database-dumps) เมื่อล้มเหลว ดู [ดัมป์ฐานข้อมูลล้มเหลว](troubleshooting.md#a-database-dump-failed)

## คำสั่งและคอนเทนเนอร์อื่น {#commands}

- **คำสั่งก่อนและหลัง** รันภายในคอนเทนเนอร์ด้วย `sh -c` เช่นเพื่อ flush แคชลงดิสก์ คำสั่งก่อนการสำรองที่ล้มเหลวจะยกเลิกการสำรอง คำสั่งก่อนการสำรองที่ออกด้วยรหัส 75 จะเลื่อนการสำรองตามกำหนดแทน ดูด้านล่าง
- **หยุดคอนเทนเนอร์อื่น** ระบุคอนเทนเนอร์ที่ต้องหยุดขณะสำรองตัวนี้ เช่นฐานข้อมูลของมัน หลังจากนั้นพวกมันเริ่มใหม่ตามลำดับ `depends_on` ของ Compose และโดยค่าเริ่มต้นแต่ละตัวต้องรายงานว่าพร้อมก่อนที่ตัวถัดไปจะเริ่ม การรอและเวลาหมดอยู่ใต้ **รีสตาร์ทหลังการสำรองข้อมูล** ในการ์ด **ลำดับ** ใต้ **การตั้งค่า, ตารางเวลา**
- คอนเทนเนอร์ที่ใช้เนมสเปซเครือข่าย, PID หรือ IPC ร่วมกับตัวที่หยุด ผ่าน `--net=container:` หรือ `network_mode: service:` ของ Compose จะหยุดและเริ่มไปพร้อมกับมัน แม้ไม่อยู่ในรายการ และจะเริ่มหลังคอนเทนเนอร์ที่มันเข้าร่วม คอนเทนเนอร์ที่รีสตาร์ทจะได้เครือข่ายใหม่ และตัวที่ยังรันอยู่บนเครือข่ายเดิมจะเหลือแค่ loopback ของตัวเอง ส่วนรายการเองยังเป็นตามที่คุณตั้ง ถ้าหยุดคอนเทนเนอร์แบบนั้นไม่ได้ การรันจะบอกว่ามันไม่มีเครือข่ายจนกว่าจะรีสตาร์ท คอนเทนเนอร์ของ BombVault เองก็เช่นกัน ซึ่งไม่เคยหยุดตัวเองและใส่ในรายการไม่ได้
- คอนเทนเนอร์ที่ไม่กลับมารันหลังจากนั้นจะถูกระบุชื่อในการรันและในการแจ้งเตือน แม้การสำรองเองจะล้มเหลวก็ตาม

## เมื่อแอปไม่ว่าง {#app-busy}

การสำรองหยุดคอนเทนเนอร์ของมัน การสำรองตามกำหนดจึงรอได้ขณะที่มีคนใช้แอปอยู่ และลองใหม่เอง การ์ด **เมื่อแอปไม่ว่าง** บนแท็บการตั้งค่าของคอนเทนเนอร์ตั้งเรื่องนี้

- **การตรวจสอบกิจกรรม** ถาม Plex, Jellyfin หรือ Emby ก่อนการสำรองตามกำหนดว่ามีใครดูอยู่ไหม Plex ถูกถามด้วยโทเคนจาก `Preferences.xml` ของมันเอง จึงไม่ต้องกรอกอะไร Jellyfin และ Emby ใช้ **คีย์ API** ที่สร้างในแดชบอร์ดของเซิร์ฟเวอร์ใต้ API keys
- **ไม่นับเซสชันที่หยุดชั่วคราวหลังจาก (นาที)** ทำให้หนังที่หยุดค้างไว้ทั้งคืนเลิกนับ
- **สำรองข้อมูลเมื่อเซิร์ฟเวอร์ไม่ตอบ** กำหนดว่าจะเกิดอะไรเมื่อถามเซิร์ฟเวอร์ไม่ได้: เมื่อเปิด การสำรองรันและบันทึกจะบอก เมื่อปิด มันรอเหมือนมีคนดูอยู่
- **รอขณะที่คอนเทนเนอร์ส่งข้อมูล** สำหรับแอปที่ไม่มีการตรวจแบบนั้น เช่นเซิร์ฟเวอร์เกมหรือตัวดาวน์โหลด การสำรองรอขณะที่คอนเทนเนอร์ส่งมากกว่า **ไม่ว่างตั้งแต่ (KiB/s)** ในการอ่านค่าใดก็ตามในช่วง **เงียบนาน (นาที)** นาทีที่ผ่านมา
- **ลองอีกครั้งทุก (นาที)**, **ลองเฉพาะในช่วงเวลาที่กำหนด** พร้อม **ลองระหว่าง** และ **รอนานสุด (ชั่วโมง)** กำหนดวิธีลอง
- **เมื่อหมดเวลารอ** เลือกยอมแพ้ ซึ่งแสดงการสำรองใต้ **ต้องดูแล** พร้อม **ลองอีกครั้ง** หรือ **สำรองข้อมูลเลย**

การสำรองที่รออยู่ถูกบันทึกเป็น **เลื่อนไว้** สีเหลืองอำพัน และส่วนที่เหลือของการรันดำเนินต่อ ภาพรวม รายการ และรายการเดี่ยวแสดงมันพร้อมการลองครั้งถัดไป และการเตือนที่ล่าช้ากับสถานะการป้องกันรอมันจนถึงเส้นตาย คุณได้รับการแจ้งเตือนหนึ่งครั้งเมื่อถูกเลื่อน และอีกหนึ่งครั้งเมื่อจบ ไม่ใช่หนึ่งครั้งต่อการลอง การลองรอขณะที่การสำรองอื่นรันอยู่ และการรอดำเนินต่อหลังรีสตาร์ท การสำรองที่คุณเริ่มเองรันทันทีเสมอ ไม่ว่าจะด้วย **สำรองข้อมูลเดี๋ยวนี้**, **ลองอีกครั้ง**, ชุดที่เลือก, API หรือ MCP และอันที่ผ่านไปได้จะจบการรอที่ค้างอยู่

แท็บการตั้งค่าของคอนเทนเนอร์ยังมีวิธีที่เก่ากว่าและง่ายกว่า: **รอจนกว่าแอปจะว่าง** พร้อม **รอนานสุด (ชั่วโมง)** การสำรองเริ่มทันทีที่แอปว่าง ซึ่งการ์ด **ความว่างก่อนสำรองข้อมูล** ใต้ **การตั้งค่า, ตารางเวลา** เป็นผู้กำหนด สมาชิกของสแตก Compose ที่ถึงกำหนดในการรันเดียวกันรอด้วยกัน และการสำรองที่รออยู่ไม่ถือล็อก คอนเทนเนอร์อื่นจึงไปต่อได้

### ตัวอย่าง: Plex รอขณะมีคนดูอยู่ {#example-plex}

การสำรองข้อมูลทั้งหมดรันทุกคืนเวลา 03:00 ไม่ควรมีใครเห็นหนังหยุดเพราะ Plex ถูกปิดเพื่อสำรอง แต่การสำรองยังควรเกิดขึ้นก่อนเช้า

1. เปิด **การสำรองข้อมูล** แล้วรายการ `plex` แล้วแท็บ **การตั้งค่า** ของมัน
2. ใน **เมื่อแอปไม่ว่าง** ตั้ง **การตรวจสอบกิจกรรม** เป็น Plex ไม่ต้องพิมพ์อะไร
3. ตั้ง **ไม่นับเซสชันที่หยุดชั่วคราวหลังจาก (นาที)** เป็น `30` หนังที่หยุดค้างตอนเที่ยงคืนจะเลิกนับตอนเที่ยงคืนครึ่ง
4. คง **สำรองข้อมูลเมื่อเซิร์ฟเวอร์ไม่ตอบ** ไว้เปิด
5. ตั้ง **ลองอีกครั้งทุก (นาที)** เป็น `15`
6. เปิด **ลองเฉพาะในช่วงเวลาที่กำหนด** และตั้ง **ลองระหว่าง** เป็น `22:00` และ `06:00`
7. ตั้ง **รอนานสุด (ชั่วโมง)** เป็น `3` และ **เมื่อหมดเวลารอ** เป็น **สำรองข้อมูลเลย**

สิ่งที่เกิดขึ้นในคืนที่ยังมีคนดูอยู่ตอน 03:00: BombVault ถาม Plex พบเซสชันที่กำลังเล่น และบันทึกการสำรองเป็น **เลื่อนไว้** โดยลองครั้งถัดไปเวลา 03:15 คอนเทนเนอร์อื่นของรอบถูกสำรองตามปกติ เมื่อหนังจบตอน 04:10 การลองตอน 04:15 พบว่า Plex ว่างและสำรองมัน และการรอจบด้วยการแจ้งเตือนหนึ่งครั้ง ถ้าหนังยังเล่นอยู่ตอน 06:00 การรอจะถึงจุดสิ้นสุดและ Plex จะถูกสำรองอยู่ดี การสำรองของมันจึงไม่เคยล้าหลังเกินสามชั่วโมง

สำหรับการตรวจของคุณเอง ให้ทำให้ **คำสั่งก่อนการสำรองข้อมูล** ออกด้วยรหัส 75 ขณะที่แอปไม่ว่าง เช่น `[ "$(cat /tmp/players)" = 0 ] || exit 75` อาการและวิธีแก้เพิ่มเติมอยู่ใน [การแก้ปัญหา](troubleshooting.md#deferred-backups)

## การส่งออกแบบธรรมดา {#exports}

restic ยังเป็นเอนจิน แต่การส่งออกให้สำเนาที่ไม่ต้องใช้ทั้ง BombVault และ restic

- **ส่งออกคอนเทนเนอร์** และ **ส่งออก VM** ใต้ **เพิ่มเติม** บนหน้าของรายการเขียนสำเนาตามที่เป็นตอนนี้ ข้างที่เก็บ: โฟลเดอร์สำรองของคอนเทนเนอร์พร้อมเทมเพลต Unraid หรือ image ดิสก์ของ VM พร้อมคำจำกัดความ กู้คืนได้ด้วย `virsh define`
- **ส่งออก** บนสแนปช็อตเขียนข้อมูลสำรองที่เก็บไว้ลงโฟลเดอร์ส่งออกบนเซิร์ฟเวอร์ เป็น tar, zip หรือที่เก็บ restic ของตัวเอง และเอาได้ทั้งหนึ่งสแนปช็อตหรือทั้งหมด การสำรองแฟลชและสำรองข้อมูลตัวเองมีคีย์อยู่ การส่งออกจึงต้องมีรหัสผ่านเข้าสู่ระบบและการลงชื่อเข้าใช้ที่อินสแตนซ์

การส่งออกเป็นไฟล์ธรรมดาโดยค่าเริ่มต้น **เข้ารหัสการส่งออกด้วย age** ใต้ **การตั้งค่า, ระบบ** ปิดผนึกมัน รวมถึง ZIP ของแฟลช สำหรับผู้รับที่คุณลิสต์ แต่ละคนเป็นกุญแจสาธารณะ age หรือ SSH คุณถอดรหัสทีหลังนอกกล่องด้วยกุญแจส่วนตัวที่คู่กัน เมื่อเปิดการเข้ารหัสแต่ไม่มีผู้รับที่ใช้ได้ การส่งออกจะล้มเหลวพร้อมข้อผิดพลาดที่ชัดเจน แทนที่จะเขียนไฟล์ธรรมดาออกมา

## การรันบอกอะไรคุณ {#run-notes}

- **เวลา** ทุกการรันอ่านได้ว่าเริ่ม สิ้นสุด และระยะเวลา และแต่ละรายการมี **การทำงานล่าสุด** ของตัวเอง
- **ทำไมการสำรองช้า** ขณะที่การสำรองรัน BombVault เฝ้าดูว่า CPU ดิสก์ และเครือข่ายยุ่งแค่ไหน เมื่อการสำรองใช้เวลานานกว่าปกติมากและมีสิ่งหนึ่งเต็มขีดจำกัดชัดเจน การรันจะบอก เช่น "ดิสก์ปลายทาง disk1 ยุ่ง 98%" ถ้าไม่เช่นนั้นก็ไม่บอกอะไร
- **ความคืบหน้าของการตรวจและ prune** บันทึกกิจกรรมและการ์ด **ตรวจสอบข้อมูลสำรอง** แสดงว่า restic นับไปถึงไหน เช่น *12 จาก 47 pack* พร้อมเวลาที่เหลือในขั้นนั้นเมื่อมีข้อมูลพอจะประมาณ
- **ไฟล์ที่อ่านไม่ได้** การสำรองที่ผ่านไปแต่เว้นบางอย่างไว้ ทำให้บรรทัดของมันเป็นสีส้มและระบุสิ่งที่เว้นไว้
