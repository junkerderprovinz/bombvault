# BombVault

**הנתונים שלך ב-Unraid, אטומים בכספת. מניחים גיבוי. מפעילים שחזור.**

![הסקירה: ראש הסטטוס, מה שדורש אותך, ההגנה על כל תחום, היעדים וההיסטוריה.](assets/screenshots/overview/home-dark.png#only-dark)
![הסקירה: ראש הסטטוס, מה שדורש אותך, ההגנה על כל תחום, היעדים וההיסטוריה.](assets/screenshots/overview/home-light.png#only-light)

BombVault היא אפליקציית רשת באירוח עצמי ל**גיבוי ולהתאוששות מלאה מאסון** ב-Unraid ובמארחי Docker אחרים, כמו TrueNAS SCALE,‏ ZimaOS או מחשב Linux רגיל. היא מגבה קונטיינרים של Docker, מכונות וירטואליות של KVM/libvirt, תיקיות, מערכי נתונים של ZFS וכונן ה-flash של Unraid. היא רצה כקונטיינר Docker יחיד מרובה ארכיטקטורות, נותנת לך ממשק רשת בערכת נושא כהה, בהירה או של המערכת, ומטפלת בכל מחזור החיים: גיבוי, תזמון, אימות ושחזור.

שחזורים הם אוטומטיים. ב-Unraid קונטיינרים מופיעים שוב בלשונית Docker בדיוק כמו קודם, ומכונות וירטואליות מוגדרות מחדש במנהל ה-VM עם הדיסקים וה-NVRAM של UEFI מחוברים מחדש. בלי התקנה ידנית מחדש, בלי הגדרה מחדש, בלי דרמה. ב-TrueNAS קונטיינר ששוחזר לצד המקור רץ כקונטיינר Docker רגיל שמסך האפליקציות לא מציג.

מבוססת על [restic](https://restic.net), ולכן כל גיבוי מנוכה כפילויות, מצטבר ומוצפן כברירת מחדל.

!!! note "שומרים את ה-APP_KEY בטוח"
    BombVault גוזרת את סיסמת מאגר ה-restic מסוד של 32 בייטים בשם `APP_KEY`. איבוד שלו, יחד עם ערכת השחזור, הופך גיבויים מוצפנים לבלתי ניתנים לשחזור. יוצרים אחד עם `openssl rand -hex 32` ושומרים אותו במקום בטוח. ראו [הגדרות](configuration.md).

## מה BombVault מגנה עליו {#what-bombvault-protects}

כל קונטיינר, מכונה וירטואלית, ערכת תיקיות, כונן ה-flash, כל מערך נתונים של ZFS וההגדרות של BombVault עצמה הם **פריט** עם דף משלו. פריטים מאותו סוג יוצרים **תחום**, שמפעילים תחת **הגדרות, כללי**.

| תחום | מה נשמר |
|---|---|
| **קונטיינרים** | תיקיית appdata יחד עם הגדרת הקונטיינר (image, משתני סביבה, פורטים, תוויות, volumes). |
| **VMs** | תמונות דיסק של המכונה, הגדרת ה-XML וה-NVRAM של UEFI, בגיבוי דרך SSH (בלי עיגון של libvirt). |
| **Flash** | כל כונן ה-USB flash (`/boot`): מערכת ההפעלה, הרישיון, תצורת המערך, השיתופים, הרשת ותצורת התוספים. |
| **גיבוי עצמי** | ה-`/config` של BombVault עצמה: מסד ההגדרות שלה, פרטי הגישה של היעדים שלה וזוג מפתחות ה-SSH של libvirt. |
| **תיקיות** | כל תיקייה בשרת כערכת תיקיות, כל אחת עם תבניות החרגה אופציונליות. |
| **מערכי נתונים של ZFS** | מערך נתונים וכל מערך מתחתיו, שנקראים מתצלום ZFS אחד ונשמרים כמו תיקייה. ראו [מערכי נתונים של ZFS](zfs-datasets.md). |

## שחזור הוא הכוכב {#restore-is-the-star}

אחרי העתקת הנתונים בחזרה מתצלום ה-restic, BombVault מריצה מחדש את הגדרת הקונטיינר השמורה מול ה-Docker API, כך שהקונטיינר מופיע שוב בלשונית Docker של Unraid כאילו תמיד היה שם (אותו image, אותן הגדרות, אותם מיפויי פורטים). מכונות וירטואליות מקבלות את ה-XML שלהן מוגדר מחדש דרך SSH ואת הדיסקים וה-NVRAM של UEFI מחוברים מחדש, גם אחרי שהמכונה נמחקה.

חלון אחד משחזר כל סוג. כברירת מחדל הוא בוחר **לצד המקור**, שמחזיר את הגיבוי כעותק ומשאיר את המקור כמו שהוא. **החלפת המקור** מגבה קודם את המצב הנוכחי, כך שאפשר לבטל שחזור. תיקייה או מערך נתונים חדש של ZFS הם היעדים האחרים.

כשגיבוי עוצר קונטיינרים תלויים, הם חוזרים בסדר הנכון: BombVault מפעילה אותם מחדש לפי סדר ה-`depends_on` של Compose שלהם וממתינה שכל אחד ידווח תקין לפני שהיא מפעילה את אלה שתלויים בו, כך ששום דבר לא רץ לפני מסד נתונים או שער שעוד לא למעלה. ראו [שחזור](restore.md) ו[פקודות וקונטיינרים אחרים](backups.md#commands).

## איך זה עובד {#how-it-works}

```
Browser --HTTPS--> BombVault container
                   |- Go binary: JSON API + embedded React UI
                   |- Background worker (per-section scheduler + job executor)
                   |
                   |- /var/run/docker.sock  -> Docker API (container stop/inspect/recreate)
                   |- qemu+ssh://host       -> libvirt / KVM on the HOST over SSH (no mount)
                   |- /mnt/ -> /host/user   -> appdata, VM disks + restic repos (read/write)
                   |- /boot/ -> /host/boot  -> Unraid flash backup (whole USB)
                   |- /config               -> BombVault's own settings + sign-ins (self-backup)
                   '- <repo path>           -> restic repository (local or remote: rclone/s3/rest/sftp)
```

BombVault משתמשת בשקע Docker כדי לעצור קונטיינרים לפני גיבוי וליצור אותם מחדש אחרי שחזור. למכונות וירטואליות היא מריצה `virsh` במארח דרך SSH (`qemu+ssh://`) כדי לכבות דומיין בצורה מסודרת או לקחת snapshot חי. היא אף פעם לא מעגנת נתיב של libvirt, ולכן היא לא יכולה להפריע למנהל ה-VM במארח.

BombVault היא שכבת התזמור והממשק, לא מנוע האחסון. כל העברת הנתונים בפועל עוברת דרך restic.

## התחלה מהירה {#quick-start}

חדש כאן? עוברים אל **[תחילת העבודה](getting-started.md)** כדי להתקין את BombVault ולהריץ את הגיבוי הראשון, ואחר כך מגדירים **[מחוץ לאתר והתאוששות](offsite-recovery.md)**. **[הדוגמאות המעשיות](guides.md)** עוברות על המשימות הנפוצות מההתחלה עד הסוף, הדף **[הגדרות](settings.md)** מפרט כל אריח, ו**[תכונות](features.md)** הוא הקטלוג הקצר של כל מה ש-BombVault עושה.

כל תחום יכול להעתיק לכמה יעדים בבת אחת, BombVault מצומדת יכולה לשמור את העותקים שלך מחוץ לאתר בשרת שמסרב למחיקות, ו**אשף החירום** מחזיר שרת שאבד מתוך ערכת השחזור שלו, דרך הקבוצה או עם המפתח בהקלדה. כדי להעביר את התצורה שלך לתיבה חדשה משתמשים בכרטיס **ייצוא / ייבוא הגדרות**. ראו [מחוץ לאתר והתאוששות](offsite-recovery.md) ו[הגדרות](configuration.md#portable-settings-export-and-import).

**[אפליקציית Android](android.md)** מביאה לטלפון את כל שרתי הקבוצה שלך, עם יומן הפעילות של כולם במסך אחד.

התיעוד זמין ב-26 שפות והממשק ב-42. דפים שעוד אין להם תרגום מוצגים באנגלית.

## מילים שמשמשות כאן {#glossary}

לכמה מילים יש משמעות קבועה ב-BombVault ובדפים האלה.

| מילה | משמעות |
|---|---|
| **פריט** | דבר אחד ש-BombVault מגבה: קונטיינר, מכונה וירטואלית, ערכת תיקיות, כונן ה-flash, מערך נתונים של ZFS עם אלה שמתחתיו, או ההגדרות שלה עצמה. לכל אחד דף משלו. |
| **תחום** | כל הפריטים מסוג אחד, כמו קונטיינרים. מפעילים תחומים תחת **הגדרות, כללי**. |
| **יעד** | מקום שבו גיבויים נכנסים: תיקייה בשרת הזה, שיתוף, שרת משלך או שירות ענן. ראו [יעדים](offsite-recovery.md#destinations). |
| **מקומי** | היעד בשרת הזה שמחזיק את התיקיות של התחומים. |
| **תיקייה עצמית** | המאגר שתחום כותב אליו את הגיבויים שלו קודם. הוא בשרת הזה כברירת מחדל ויכול להיות ביעד. ראו [התיקייה העצמית של תחום](offsite-recovery.md#own-folder). |
| **העתקה** | גיבוי שהועתק מהתיקייה העצמית ליעד אחר עם `restic copy`. |
| **מאגר ישיר** | מאגר ביעד מחוץ לאתר שפריטים מגבים אליו ישירות, בלי עותק מקומי באמצע. ראו [מאגרים ישירים](offsite-recovery.md#direct-repositories). |
| **פרטי גישה** | המפתח או הסיסמה השמורים לשירות S3 או ל-rest-server. אחד מהם הוא ברירת המחדל. ראו [פרטי גישה](offsite-recovery.md#sign-ins). |
| **מיקום** | אילו יעדים מקבלים את הגיבויים של פריט, כפי שנקבע בפריט או כברירת המחדל של התחום שלו. ראו [מיקום לפי פריט](offsite-recovery.md#placement). |
| **רפליקה** | עותק מדויק לבלוק של פריט ZFS בשרת ZFS שני, שנעשה עם `zfs send`. הוא עומד לצד הגיבוי ולא מחליף אותו. ראו [רפליקה](zfs-datasets.md#replica). |
| **תפקיד** | משהו שמופע אחד בקבוצה שלך עושה למופע אחר: מקלט, מושך, שרת ZFS או שומר מפתח. ראו [מופעים ותפקידים](offsite-recovery.md#roles). |
