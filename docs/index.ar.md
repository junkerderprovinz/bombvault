# BombVault

**بيانات Unraid الخاصة بك، مختومة في خزنة. أسقط نسخة احتياطية. فجّر استعادة.**

![النظرة العامة: رأس الحالة، وما يحتاج إليك، وحماية كل قسم، والوجهات والتاريخ.](assets/screenshots/overview/home-dark.png#only-dark)
![النظرة العامة: رأس الحالة، وما يحتاج إليك، وحماية كل قسم، والوجهات والتاريخ.](assets/screenshots/overview/home-light.png#only-light)

BombVault تطبيق ويب تستضيفه بنفسك لـ **النسخ الاحتياطي والتعافي الكامل من الكوارث** على Unraid ومضيفات Docker الأخرى، مثل TrueNAS SCALE أو ZimaOS أو جهاز Linux عادي. ينسخ حاويات Docker وأجهزة KVM/libvirt الافتراضية والمجلدات ومجموعات بيانات ZFS وفلاش Unraid. يعمل كحاوية Docker واحدة متعددة المعماريات، ويمنحك واجهة ويب بمظهر داكن أو فاتح أو مظهر النظام، ويتولى دورة الحياة كلها: النسخ والجدولة والتحقق والاستعادة.

الاستعادة تلقائية. في Unraid تعود الحاويات إلى تبويب Docker تمامًا كما كانت، وتُعاد تعريف الأجهزة الافتراضية في VM Manager مع إعادة ربط أقراصها وUEFI NVRAM. لا إعادة تثبيت يدوية، ولا إعادة تهيئة، ولا دراما. وعلى TrueNAS تعمل الحاوية المستعادة بجانب الأصل كحاوية Docker عادية لا تسردها شاشة Apps.

يعمل بـ [restic](https://restic.net)، فكل نسخة احتياطية مُزالة التكرار وتزايدية ومشفّرة افتراضيًا.

!!! note "احفظ APP_KEY بأمان"
    يشتق BombVault كلمة مرور مستودع restic من سر بحجم 32 بايتًا اسمه `APP_KEY`. فقدانه، مع حقيبة الاستعادة، يجعل النسخ المشفرة غير قابلة للاسترداد. أنشئ واحدًا بـ `openssl rand -hex 32` واحفظه في مكان آمن. راجع [التهيئة](configuration.md).

## ما الذي يحميه BombVault {#what-bombvault-protects}

كل حاوية وجهاز افتراضي ومجموعة مجلدات والفلاش وكل مجموعة بيانات ZFS وإعدادات BombVault نفسه **عنصر** له صفحته الخاصة. العناصر من نوع واحد تشكل **قسمًا**، تفعّله ضمن **الإعدادات، عام**.

| القسم | ما الذي يُحفظ |
|---|---|
| **الحاويات** | مجلد appdata وتعريف الحاوية (الصورة ومتغيرات البيئة والمنافذ والوسوم والأحجام). |
| **VMs** | صورة (صور) قرص الجهاز الافتراضي وتعريف XML وUEFI NVRAM، تُنسخ عبر SSH (دون تركيب libvirt). |
| **Flash** | كامل فلاش USB (`/boot`): النظام والترخيص وإعداد المصفوفة والمشاركات والشبكة وإعداد الإضافات. |
| **النسخ الذاتي** | `/config` الخاص بـ BombVault: قاعدة بيانات إعداداته وبيانات اعتماد وجهاته وزوج مفاتيح SSH لـ libvirt. |
| **المجلدات** | أي مجلد على الخادم كمجموعة مجلدات، لكل منها أنماط استبعاد اختيارية. |
| **مجموعات بيانات ZFS** | مجموعة بيانات وكل مجموعة تحتها، تُقرأ من لقطة ZFS واحدة وتُخزَّن كمجلد. راجع [مجموعات بيانات ZFS](zfs-datasets.md). |

## الاستعادة هي النجم {#restore-is-the-star}

بعد نسخ البيانات من لقطة restic، يعيد BombVault تشغيل تعريف الحاوية المحفوظ على واجهة Docker، فتظهر الحاوية في تبويب Docker في Unraid كأنها كانت هناك دائمًا (الصورة نفسها والإعدادات نفسها وربط المنافذ نفسه). تحصل الأجهزة الافتراضية على XML معاد تعريفه عبر SSH وتُعاد أقراصها وUEFI NVRAM، حتى بعد حذف الجهاز الافتراضي.

نافذة واحدة تستعيد كل نوع. تختار افتراضيًا **بجانب الأصل**، الذي يعيد النسخة كنسخة ويترك الأصل كما هو. **استبدال الأصل** ينسخ الحالة الحالية أولًا، فيمكن التراجع عن استعادة. المجلد أو مجموعة بيانات ZFS جديدة وجهتان أخريان.

حين توقف نسخة احتياطية حاويات تابعة، فإنها تعود بالترتيب الصحيح: يعيد BombVault تشغيلها بترتيب `depends_on` في Compose وينتظر أن تبلّغ كل منها بأنها سليمة قبل أن يبدأ التي تعتمد عليها، فلا يتقدم شيء على قاعدة بيانات أو بوابة لم تعمل بعد. راجع [الاستعادة](restore.md) و[الأوامر والحاويات الأخرى](backups.md#commands).

## كيف يعمل {#how-it-works}

```
Browser --HTTPS--> BombVault container
                   |- Go binary: JSON API + embedded React UI
                   |- Background worker (per-section scheduler + job executor)
                   |
                   |- /var/run/docker.sock  -> Docker API (container stop/inspect/recreate)
                   |- qemu+ssh://host       -> libvirt / KVM on the HOST over SSH (no mount)
                   |- /mnt/ -> /host/user   -> appdata, VM disks + restic repos (read/write)
                   |- /boot/ -> /host/boot  -> Unraid flash backup (whole USB)
                   |- /config               -> BombVault's own settings + sign-ins (self-backup)
                   '- <repo path>           -> restic repository (local or remote: rclone/s3/rest/sftp)
```

يستخدم BombVault مقبس Docker لإيقاف الحاويات قبل نسخة احتياطية ولإعادة إنشائها بعد استعادة. وللأجهزة الافتراضية يشغّل `virsh` على المضيف عبر SSH (`qemu+ssh://`) ليوقف نطاقًا بسلام أو يأخذ لقطة حية. ولا يركّب أي مسار libvirt أبدًا، فلا يمكنه أن يعترض طريق VM Manager على المضيف.

BombVault طبقة تنسيق وواجهة، لا محرك تخزين. كل نقل فعلي للبيانات يمر عبر restic.

## بداية سريعة {#quick-start}

جديد هنا؟ توجّه إلى **[البدء](getting-started.md)** لتثبيت BombVault وإجراء أول نسخة احتياطية، ثم أعدّ **[خارج الموقع والاستعادة](offsite-recovery.md)**. تمرّ **[الأمثلة خطوة بخطوة](guides.md)** على المهام الشائعة من أولها إلى آخرها، وتسرد صفحة **[الإعدادات](settings.md)** كل بلاطة، وتمثل **[الميزات](features.md)** الفهرس الموجز لكل ما يفعله BombVault.

يستطيع كل قسم النسخ إلى عدة وجهات معًا، ويستطيع BombVault مقترن أن يحتفظ بنسخك خارج الموقع في خادم يرفض الحذف، ويعيد **معالج الطوارئ** خادمًا مفقودًا من حقيبة استعادته أو عبر مجموعتك أو بمفتاحه المكتوب. لنقل إعداداتك إلى جهاز جديد استخدم بطاقة **تصدير / استيراد الإعدادات**. راجع [خارج الموقع والاستعادة](offsite-recovery.md) و[التهيئة](configuration.md#portable-settings-export-and-import).

يضع **[تطبيق Android](android.md)** كل خادم في مجموعتك على هاتفك، مع سجل نشاطها كلها على شاشة واحدة.

التوثيق متاح بـ 26 لغة والواجهة بـ 42. تظهر الصفحات التي لا ترجمة لها بعد بالإنجليزية.

## كلمات مستخدمة هنا {#glossary}

لعدة كلمات معنى ثابت في BombVault وفي هذه الصفحات.

| الكلمة | المعنى |
|---|---|
| **عنصر** | شيء واحد ينسخه BombVault: حاوية أو جهاز افتراضي أو مجموعة مجلدات أو الفلاش أو مجموعة بيانات ZFS مع ما تحتها أو إعداداته الخاصة. لكل منها صفحته الخاصة. |
| **قسم** | كل العناصر من نوع واحد، مثل الحاويات. تفعّل الأقسام ضمن **الإعدادات، عام**. |
| **وجهة** | مكان تذهب إليه النسخ: مجلد على هذا الخادم أو مشاركة أو خادم خاص بك أو خدمة سحابية. راجع [الوجهات](offsite-recovery.md#destinations). |
| **محلي** | الوجهة على هذا الخادم التي تحتفظ بمجلدات الأقسام. |
| **المجلد الخاص** | المستودع الذي يكتب فيه قسم نسخه أولًا. هو على هذا الخادم افتراضيًا ويمكن أن يقع في وجهة. راجع [المجلد الخاص بقسم](offsite-recovery.md#own-folder). |
| **نسخة** | نسخة احتياطية منسوخة من المجلد الخاص إلى وجهة أخرى بـ `restic copy`. |
| **مستودع مباشر** | مستودع في موقع خارجي تنسخ إليه العناصر مباشرة، دون نسخة محلية بينهما. راجع [المستودعات المباشرة](offsite-recovery.md#direct-repositories). |
| **بيانات الاعتماد** | المفتاح أو كلمة المرور المحفوظان لخدمة S3 أو rest-server. إحداها هي الافتراضية. راجع [بيانات الاعتماد](offsite-recovery.md#sign-ins). |
| **التوزيع** | أي الوجهات تحصل على نسخ عنصر، يُضبط على العنصر أو كافتراضي لقسمه. راجع [التوزيع لكل عنصر](offsite-recovery.md#placement). |
| **نسخة طبق الأصل** | نسخة على مستوى الكتل من عنصر ZFS على خادم ZFS ثانٍ، تُصنع بـ `zfs send`. تقف بجانب النسخة الاحتياطية ولا تحل محلها. راجع [النسخة المتماثلة](zfs-datasets.md#replica). |
| **دور** | ما يفعله مثيل في مجموعتك لمثيل آخر: المستقبِل أو الساحب أو خادم ZFS أو حافظ المفتاح. راجع [المثيلات والأدوار](offsite-recovery.md#roles). |
