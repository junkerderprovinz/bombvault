# Начало работы

Эта страница проведёт вас от свежей машины Unraid до вашей первой резервной копии.

## Требования

| Требование | Примечания |
|---|---|
| **Unraid 6.12+** | Более ранние версии не тестировались. Основная цель, это Unraid, но BombVault работает и на обычном хосте Docker, и на TrueNAS Scale (см. [Обычный хост Docker](#generic-docker-host) и [TrueNAS SCALE](#truenas)). |
| **Расположение репозитория restic** | Локальный путь (рекомендуется: ваш массив или кэш), SMB, NFS или любой бэкенд rclone. |
| **Сокет Docker** | Монтируется шаблоном автоматически (`/var/run/docker.sock`). |
| **Unraid flash** (`/boot`) | Монтируется шаблоном целиком автоматически (`/boot` в `/host/boot`). Обеспечивает резервное копирование flash и позволяет восстановленному контейнеру снова появиться как обычное, редактируемое приложение Unraid. |
| **Виртуальные машины KVM** (по желанию) | Резервное копирование VM обращается к libvirt через SSH, без монтирования libvirt. Настройте его в **Настройки, Интеграции, SSH хоста** (см. [Конфигурация](configuration.md)). |
| **Наборы данных ZFS** (по желанию) | То же SSH-соединение, что и для резервного копирования VM, `zfs` на хосте и Host Data, подключённый как `/mnt` с режимом доступа Read/Write - Slave (значение шаблона по умолчанию). См. [Наборы данных ZFS](zfs-datasets.md). |
| **Приложение для Android** (необязательно) | Android 10 или новее, сопряжение с серверами версии 9.7.0 или новее. См. [Приложение для Android](android.md). |

## Установка на Unraid

Самый простой путь, это **Community Applications**.

1. Откройте вкладку **Apps** в Unraid.
2. Найдите **BombVault**.
3. Нажмите **Install**, задайте необходимые переменные (ниже) и примените.

!!! tip "Ручная установка шаблона"
    Если вы предпочитаете добавить шаблон вручную:

    1. Перейдите в **Docker, Add Container, Template repositories** и добавьте:
       ```
       https://github.com/junkerderprovinz/unraid-apps
       ```
    2. Найдите **BombVault** в Templates.
    3. Задайте необходимые переменные и нажмите **Apply**.

## Обычный хост Docker {#generic-docker-host}

Не Unraid? BombVault работает и как обычный контейнер на любом хосте Docker. Для TrueNAS SCALE есть свои шаги в разделе [TrueNAS SCALE](#truenas).

1. Возьмите из репозитория готовый к правке файл [`deploy/docker-compose.generic.yml`](https://github.com/junkerderprovinz/bombvault/blob/main/deploy/docker-compose.generic.yml).
2. Задайте `APP_KEY` (см. ниже) и направьте том Host Data на ваш настоящий корень данных: комментарии в файле проводят через оба шага.
3. `docker compose up -d`, затем откройте `https://<ip-хоста>:3443/`.

Чем это отличается от Unraid:

- **Нет раздела Flash.** Загрузочной флешки, которую нужно сохранять или восстанавливать, здесь нет, поэтому разделу Flash делать нечего. Вместо этого, если Host Data достаёт до `/etc` хоста, **Добавить** на странице «Резервные копии» предлагает **Конфигурация системы** как подсказку для папки: стартовый набор папок `/etc`, который вы просматриваете перед сохранением.
- **Нет собственных уведомлений Unraid.** Собственные каналы уведомлений BombVault (webhook, оповещения о неудачной внешней копии и прочее) работают как обычно; пропускается только отправка в систему уведомлений Unraid, потому что такой системы здесь нет.
- **Резервное копирование виртуальных машин необязательно и требует отдельного хоста libvirtd, доступного по SSH.** См. закомментированный блок в файле compose. У обычного хоста Docker собственного менеджера виртуальных машин нет.
- **Нет виджета для Dashboard.** BombVault Widget, это плагин Unraid, поэтому и этот шаг пропускается.
- **Как находятся данные контейнера.** Без соглашения Unraid об `appdata` папка данных контейнера находится по сегментам из `DATA_ROOT_SEGMENTS`, именованным томам Docker, рабочему каталогу проекта Compose и метке `bombvault.data` (см. [Определение источников резервной копии](configuration.md#backup-source-detection)). Именованные тома и набор `/etc` достают только до путей внутри монтирования Host Data, поэтому направьте Host Data на общего родителя, который охватывает и корень данных Docker.
- **`PLATFORM`.** Задайте `generic` или `truenas`. Если переменная не задана, BombVault распознаёт Unraid по его собственному маркеру на монтировании flash и считает всё остальное обычным хостом, а шаги только для Unraid пропускаются, вместо того чтобы запускаться и завершаться ошибкой.

### TrueNAS SCALE {#truenas}

BombVault пока нет в каталоге приложений TrueNAS, поэтому установите его как пользовательское приложение: **Apps, Discover Apps**, затем **Install via YAML** в меню рядом с **Custom App**. YAML ниже задаёт то же, что и запись для каталога в папке `truenas-apps` репозитория. Замените `tank` на ваш пул и заполните `APP_KEY`, как описано в следующем разделе.

```yaml
services:
  bombvault:
    image: junkerderprovinz/bombvault:latest
    hostname: bombvault
    restart: unless-stopped
    cap_drop: [ALL]
    cap_add: [CHOWN, DAC_OVERRIDE, FOWNER, SETGID, SETPCAP, SETUID, SYS_CHROOT]
    environment:
      APP_KEY: ""
      PLATFORM: truenas
      HOST_SOURCE_ROOT: /mnt/tank
      HOST_MOUNT_ROOT: /mnt/tank
      # Для резервного копирования VM:
      # LIBVIRT_URI: qemu+ssh://root@<truenas-ip>/system?socket=/run/truenas_libvirt/libvirt-sock
    volumes:
      - /mnt/tank/apps/bombvault:/config
      - /var/run/docker.sock:/var/run/docker.sock
      - type: bind
        source: /mnt/tank
        target: /mnt/tank
        bind:
          propagation: rslave
    ports:
      - "30528:3443"
```

Затем откройте `https://<truenas-ip>:30528/`. Всё, что перечислено в [Чем это отличается от Unraid](#generic-docker-host), действует и здесь, а в TrueNAS ещё:

- **Права (capabilities).** BombVault нужны все семь, перечисленные выше. Без `SETPCAP` резервное копирование VM завершается ошибкой, а без `SYS_CHROOT` каждый контейнер останавливается на всё время своей копии вместо чтения из снимка.
- **Host Data** это путь хоста на наборе данных, здесь `/mnt/tank`, смонтированный по тому же пути внутри приложения. Поэтому и `HOST_SOURCE_ROOT`, и `HOST_MOUNT_ROOT` называют именно его. `rslave` передаёт дальше монтирования, которые хост делает позже, а они нужны копиям наборов данных ZFS.
- **Данные в ixVolume не копируются.** Приложение, чьё хранилище это ixVolume, держит свои данные в `/mnt/.ix-apps`, вне Host Data. BombVault сохраняет только определение приложения, и запуск называет папки, которые он пропустил. Для каждого приложения, чьи данные нужно сохранять, выберите хранилище **Host Path** на наборе данных под Host Data.
- **Копии VM и наборов данных ZFS** обращаются к TrueNAS по SSH от имени root. Включите службу SSH в **System, Services** и добавьте публичный ключ из **Настройки, Интеграции, SSH хоста** пользователю root в **Credentials, Users**. Копиям VM нужен ещё `LIBVIRT_URI`, как показано выше, потому что libvirtd в TrueNAS слушает собственный сокет. Если не задан ни `LIBVIRT_URI`, ни `LIBVIRT_HOST`, BombVault берёт в качестве хоста шлюз по умолчанию приложения, потому что `host.docker.internal` в приложении TrueNAS не разрешается. Подробности, включая VM на zvol, есть в [руководстве по копированию VM](https://github.com/junkerderprovinz/bombvault/blob/main/docs/vm-backup-ssh-setup.md#truenas-scale).
- **Реплика ZFS использует другой ключ.** Реплика на втором сервере ZFS входит с ключом, который показывает окно реплики, а не с ключом SSH хоста. Добавьте этот ключ на принимающем сервере.
- **Удалённое приложение возвращается в два шага.** Сначала заново установите его в TrueNAS под тем же именем, при этом снова создаётся его сеть, затем восстановите его данные в BombVault. До этого проверка перед восстановлением сообщает об отсутствующей сети, и восстановление отказывается работать, прежде чем что-либо изменить.
- **Рядом с оригиналом** создаёт обычный контейнер Docker. Он работает, но экран Apps в TrueNAS его не показывает.
- **Дампы баз данных** работают на монтированиях наборов данных. Импорт в папку данных, которая сама является набором данных, переносит старое содержимое в папку рядом с ней, поэтому набору данных уровнем выше нужно для него место.

## Единственная обязательная настройка

Единственная переменная, которую вы обязаны задать, это `APP_KEY`, 32-байтовый шестнадцатеричный секрет (64 hex-символа), используемый для вывода пароля репозитория restic.

Сгенерируйте его на любой машине:

```bash
openssl rand -hex 32
```

Вставьте результат в поле `APP_KEY` шаблона (Unraid) или в переменную окружения `APP_KEY` в `docker-compose.yml` (обычный Docker-хост).

!!! danger "Не потеряйте свой APP_KEY"
    Потеря `APP_KEY` делает ваши зашифрованные резервные копии невосстановимыми. Храните его в надёжном месте отдельно от сервера. Как только BombVault запущен, задайте пароль для входа и скачайте **набор для восстановления** в **Настройки, Восстановление** (см. [Внешняя копия и восстановление](offsite-recovery.md#recovery-kit)). В нём лежат ключ, все места назначения и команды restic.

Шаблон также монтирует за вас сокет Docker, flash (`/boot`) и корень **Host Data** (`/mnt`). *Источники* и *назначения* резервного копирования оба находятся под Host Data. Полный справочник переменных и настройку внешней копии см. в [Конфигурации](configuration.md).

## Первый запуск

![Обзор после первой резервной копии: что требует вашего внимания, защита каждого раздела, места назначения и история.](assets/screenshots/dashboard.png)

*Обзор после первой резервной копии: что требует вашего внимания, защита каждого раздела, места назначения и история.*

1. Откройте веб-интерфейс по адресу `https://<your-unraid-ip>:3443` (самоподписанный сертификат из коробки). Новая установка открывается на странице **Добро пожаловать в BombVault**, где перечислено, что BombVault нашёл на сервере.
2. Выберите **Начать**. Затем на обзоре появится карточка **Первые шаги** с тремя шагами:
    1. **Выберите разделы**: включите то, что BombVault будет копировать (Контейнеры, Виртуальные машины, Flash, Папки, Наборы данных ZFS, Автобэкап). **Выбрать** открывает список записей раздела, где **Приостановить расписание** оставляет одну из них в стороне. Включённые здесь разделы выполняются каждую ночь, это меняется в **Настройки, Расписание**.
    2. **Добавить место назначения**: куда попадают резервные копии. Для начала хватит локальной папки. Надёжнее всего второе место назначения вне дома, например Storage Box или Backblaze B2. Локальные репозитории по умолчанию лежат в `/mnt/user/bombvault/{container,vms,flash,config,files,zfs}` и создаются при первой резервной копии.
    3. **Первая резервная копия**: после неё копирование идёт само каждую ночь.
3. Откройте **Резервные копии**, чтобы увидеть все записи в одном списке. **Создать копию всего сейчас** запускает прогон по всем включённым разделам, а **Создать резервную копию** на странице записи копирует только её.

Уже пользовались BombVault? **Восстановить из резервной копии** на странице приветствия открывает страницу «Восстановление», где **Аварийный мастер** возвращает настройки, контейнеры, виртуальные машины и папки утерянного сервера. См. [Внешняя копия и восстановление](offsite-recovery.md#emergency).

!!! tip "Необязательно: выберите порядок резервного копирования"
    Если некоторые контейнеры всегда должны резервироваться раньше других (например база данных перед приложением, которое её использует), откройте карточку **Порядок** в **Настройки, Расписание** и перетащите их в нужную вам последовательность. Запланированные запуски и полный бэкап затем следуют этому порядку; всё, что вы оставите без порядка, резервируется в порядке наибольшей просрочки.

!!! note "Проверка интеграции с хостом"
    Карточка **Интеграция с хостом** на обзоре проверяет каждое монтирование и CLI (сокет Docker, libvirt, restic, qemu-img, rclone) и сообщает о любых недостающих частях, чтобы вы могли убедиться, что контейнер подключён правильно, прежде чем на него полагаться. Она ждёт в **Настроить**, пока вы её не добавите.

## Ориентироваться в интерфейсе {#navigation}

![Настройки в виде плиток, рядом карточки выбранной плитки. Каждое изменение записывается сразу.](assets/screenshots/settings.png)

*Настройки в виде плиток, рядом карточки выбранной плитки. Каждое изменение записывается сразу.*

В боковой панели пять пунктов: **Обзор**, **Аномалии** (пока включено обнаружение аномалий), **Резервные копии**, **Восстановление** и, под **Выйти**, **Настройки**. Главное действие страницы плавает внизу справа, а редкие собраны в **Ещё**. На телефоне в панели Обзор, Резервные копии, Восстановление и Настройки, а остальное в **Ещё**.

Страницы и настройки занимают всю ширину окна. Окно держит свои кнопки в нижней части, а кнопка, ведущая дальше, стоит справа. На телефоне нижняя часть с более чем тремя кнопками оставляет выход и главное действие, а остальное убирает в **Ещё**.

- **Резервные копии** перечисляют как записи каждый контейнер, виртуальную машину, набор папок, флешку, каждый набор данных ZFS и автобэкап. Плитки над списком выбирают вид, а **Фильтры**, **Сортировка** и **Поиск** сужают его. У каждой записи своя страница с тремя вкладками: **Резервные копии**, **Настройки** и **Проверка**. Кнопка «назад» слева от значка записи ведёт к списку.
- **Восстановление** это одна страница для всего: выберите раздел, найдите запись и выберите резервную копию. Аварийный мастер и другие источники тоже начинаются здесь.
- **Настройки** это четырнадцать плиток: Общие, Внешний вид, Расписание, Места назначения, Восстановление, Уведомления, Проверка, Безопасность, Экземпляры, Сопряжение, Интеграции, Приложения, Система и Информация. Нажмите `/` или Ctrl+K, чтобы искать по всем, в том числе по названиям, которые страницы носили в прежних версиях. Перетащите плитки в свой порядок в **Внешний вид**. Там, где колонка плиток рядом со страницей сделала бы её слишком узкой, например в окне шириной около 1200 пикселей, плитки становятся полосой над страницей, которая прокручивается вбок. Телефон показывает ту же полосу.
- **Места назначения** и **Экземпляры** это плитки настроек со своими страницами. **Показывать также в боковой панели** на их плитке закрепляет их в боковой панели.

Ни у чего нет кнопки «Сохранить», и ничего не раскрывается: у редких настроек своя карточка или окно, а пояснения лежат в подсказках (i). После обновления сами открываются примечания к выпуску, а зелёные точки отмечают, что изменилось. Щелчок скрывает точку. **Новое** в карточке «Версия» в **Настройки, Информация** считает, что вы ещё не видели, и открывает примечания к выпуску и список всех изменений с кнопкой **Перейти туда** как две вкладки одного окна.

## Сборка из исходного кода {#build-from-source}

BombVault, это единый статический бинарный файл Go, который обслуживает JSON API и встроенный интерфейс на React. Сначала соберите интерфейс, затем запустите бинарный файл:

```bash
npm --prefix web ci
npm --prefix web run build     # пишет web/dist, который встраивается в бинарный файл
export APP_KEY=$(openssl rand -hex 32)
go test ./...                  # модульные и интеграционные тесты с настоящим проходом restic туда и обратно
golangci-lint run ./...
go run ./cmd/bombvault         # обслуживает https://localhost:3443 с самоподписанным сертификатом
```

Сборка интерфейса нужна и для `go run`. Репозиторий отслеживает в `web/dist` только пустой маркер, поэтому без `npm --prefix web run build` бинарный файл ничего не встраивает и отвечает `500 SPA index not found`, и это ожидаемо. Docker, libvirt и Unraid нельзя протестировать в CI, поэтому прежде чем открыть pull request, проверьте монтирования, restic и SSH-соединение для VM на настоящем хосте с помощью карточки **Интеграция с хостом** на обзоре (или `GET /api/spike`).

## Следующие шаги

- Изучите полный набор **[Возможностей](features.md)**.
- Соберите все серверы вашей группы на телефоне с помощью **[Приложения для Android](android.md)**.

- Клонируете установку или переезжаете на новую машину? Перенесите всю конфигурацию с помощью карточки **Экспорт / импорт настроек**. См. [Конфигурация](configuration.md#portable-settings-export-and-import).
- Столкнулись с загвоздкой? См. **[Устранение неполадок](troubleshooting.md)**.
