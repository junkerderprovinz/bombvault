# 备份与条目

BombVault 备份的所有东西都列在**备份**下的同一个列表里：容器、虚拟机、文件夹集、闪存、ZFS 数据集和自我备份。每一项都是一个**条目**，有自己的页面。本页带你看列表、条目页面及其三个标签页，以及条目可以有的设置。

![选中容器磁贴的备份列表：每一行用一条小色带显示最近的运行，并给出一个状态。](assets/screenshots/backups/list-light.png#only-light)

## 每个分区保存什么 {#what-is-saved}

| 分区 | 保存的内容 |
|---|---|
| **容器** | appdata 文件夹，加上容器定义：镜像、变量、端口、标签和卷。容器**设置**标签页上的**备份文件夹**卡片可以精确勾选备份涵盖哪些文件夹，实时统计路径数量，并列出你排除的内容。容器放在 Host Data 之外的数据，例如在 TrueNAS 的 ixVolume 里的数据，不会被备份，运行记录里会写明漏掉了哪些文件夹。 |
| **虚拟机** | 磁盘映像、XML 定义和 UEFI NVRAM，通过 SSH 正常关机或实时快照。参见[虚拟机备份](vm-backup-ssh-setup.md)。 |
| **闪存** | 仅限 Unraid。整个 USB 闪存（`/boot`）：系统、许可证、阵列配置、共享、网络和插件配置。 |
| **自我备份** | BombVault 自己的 `/config`：设置数据库、各存储位置的登录凭据和 libvirt SSH 密钥对，用 SQLite 的 `VACUUM INTO` 做快照，所以数据库绝不会在写入中途被抓取。 |
| **文件夹** | 服务器上的任意文件夹，作为一个文件夹集，例如一个共享、你的文档或照片库，可以设置排除模式。文件夹集和其他东西一样，有计划、保留、异地副本、检查和恢复演练。 |
| **ZFS 数据集** | 一个数据集及其下的所有数据集，从一个 ZFS 快照读取，所以它们都来自同一时刻，并像文件夹一样用 restic 保存。ZFS 条目还可以在第二台 ZFS 服务器上保留一份逐块精确的副本。参见 [ZFS 数据集](zfs-datasets.md)。 |

每次备份都经过 restic，所以是增量的、去重的，即使很大的虚拟机磁盘也不会让仓库膨胀。BombVault 从不备份、因此也从不停止自己的容器。一次运行可以安全地停止，因为 restic 最后才写快照，所以中止的运行只留下没有被引用的数据，没有快照。重启发生在运行中途而留下的锁，会在锁超过十分钟没有刷新之后被清除，然后重试一次这次运行。

## 列表 {#list}

列表上方的磁贴选择种类，例如**容器**或 **ZFS**，每个磁贴会统计它的条目数。磁贴只是选择，不会隐藏页面的其余部分。

每一行用小方块显示该条目最近十四次运行，并给出一个状态，例如**已受保护**、**未受保护**、**已推迟**或**正在复制**。其他的信息都在名称旁边的提示气泡里，鼠标停在这一行上时，这段文字会显示在行内。容器名称旁边的标记表示，自上次备份以来它用另一个镜像、其他端口、变量或卷重新创建过。下一次备份之后标记就会消失。

列表上方的三个按钮可以缩小范围：

- **筛选**：按**计划**（**全部**、**已计划**、**已暂停**）、按**备份**（**已备份**、**从未备份**），对于**容器和虚拟机**，还可以选**已安装**或**未安装**。
- **排序**：按名称、状态、IP、上次备份、大小或计划。除 IP 外，每个字段都可以双向排序，例如**大小，最大优先**和**大小，最小优先**。
- **搜索**：按名称、镜像或 IP。

已经不再安装、但仍有备份的条目会单独放在**未安装（仅备份）**下。可以恢复它们，或删除它们的备份来释放空间。

页面的主要操作浮在右下角：**立即备份全部**会对所有开启的分区执行一次运行。**更多**里放着其余的：

- **选择**开始选择，见下文。
- **发现备份**读取各存储位置里存放的内容并据此重建条目，例如在全新安装之后。重建的分区的异地副本随后会暂停，直到你确认它们的默认设置，参见[重建之后](offsite-recovery.md#after-a-rebuild)。
- **与这台服务器的 ZFS 连接**打开 ZFS 分区的 SSH 测试，参见 [ZFS 数据集](zfs-datasets.md#requirements)。
- 选中 ZFS 磁贴时的**立即复制全部**会发送每个 ZFS 条目的副本。

## 选择多个条目 {#select}

像在文件管理器里选文件一样选择行：Ctrl+点击、Shift+点击、Ctrl+A，或者在手机上长按。选中的行用一个勾号代替图标，列表上方的栏会统计数量，并提供**备份已选项**、**暂停计划**和**恢复计划**、**全选**和**清除选择**。每一行还有自己的右键菜单，带有对应的操作。

选中的条目在服务器上依次备份，一个接一个，所以关闭标签页后它也会继续。要一起恢复多个条目，请使用[恢复页面](restore.md#several)。

## 添加文件夹或 ZFS 数据集 {#add}

容器、虚拟机和闪存在**设置、常规**中开启对应分区之后会自动出现。文件夹和 ZFS 数据集需要你自己选，因为 BombVault 猜不出你指的是哪些。**添加**会打开**BombVault 还应备份什么？**：

- **一个文件夹**列出 BombVault 找到的共享，也可以选 Host Data 之下的任何其他文件夹。给文件夹集起一个名字，例如 `Documents`。名字在第一次备份之后就固定了，因为快照是以它存放的。
- **一个 ZFS 数据集**列出这台服务器的数据集。选你想备份的最顶层那一个，参见[条目与子数据集](zfs-datasets.md#items-and-children)。
- **系统配置**出现在没有 Unraid、且 Host Data 能到达 `/etc` 的主机上。它是一个以 `/etc` 为起点的文件夹集，保存前由你检查。

## 把条目排除在外 {#dont-back-up}

你有意排除的条目，例如测试容器，可以标记为**不备份**。这样它就不再算作未受保护，点击**取消排除**可以把它带回来。**暂停计划**是比较温和的办法：条目离开计划和全部备份，带上灰色的**计划已暂停**徽章，**立即备份**仍然可用。它设置的是和条目设置标签页上的**在计划中**同一个开关。

## 条目的页面 {#entry-page}

点击一行会打开条目的页面。页头用一行写出条目名称和它的状态，例如**上次备份于 3 小时前**或**已推迟，下次尝试在 03:15**，并放着它的操作：**立即备份**、**恢复**，以及在**更多**下面不常用的，例如**导出最新备份**、**导出容器**或**导出虚拟机**、**关联到原条目**、**删除所有备份**和**移除条目**。图标左边的返回按钮回到列表。备份运行时，**取消备份**就在进度旁边，被取消的运行会记录为已取消，不是失败。

页面有三个标签页：**备份**、**设置**和**验证**。

### 备份标签页 {#backups-tab}

这个标签页列出条目的快照，最新的在前，每天一个柱条。存放在多个地方的备份只出现一次，标出每个保存它的存储位置。点击一个快照就会恢复它，点击快照里的某个位置，就会从那里精确地恢复。

- **目标**列出这个条目有备份的每个位置以及数量。异地位置只在你点击**检查**时才读取，因为列出云存储需要一些时间。条目不再备份到的位置会显示为**仅旧备份**，仍然可以从中恢复。
- 每个快照都有一个菜单：**添加标签**或**更改标签**、**与另一个备份比较**（列出新增、消失或变化的文件）、以 tar、zip 或独立的 restic 仓库形式**导出**，以及只在一个位置删除。
- 容器的**数据库转储**放在单独的列表里，可以下载、保存到文件夹和导入。

保留多少个快照由存储位置决定，参见[保留多久](offsite-recovery.md#keep)。

### 设置标签页 {#settings-tab}

每个条目都以**计划和目标**开头：

- **在计划中**把条目放进或移出计划运行。
- **独立计划**给这一个条目设置自己的计划，参见[单个条目的独立计划](schedules.md#own-plan)。没有的话，它按所属分区的计划或在全部备份里运行。
- 一排按钮，**本地**加上每个异地存储位置一个，说明备份存到哪里。**跟随默认**表示条目去所属分区去的地方，点击它会打开**按分区划分的目标**。参见[按条目放置](offsite-recovery.md#placement)。
- **仓库**说明备份写在哪里（**存放于**）。这个位置从第一次备份起就固定了，复制则可以随时更改。

下面的卡片取决于条目的种类：

| 种类 | 卡片 |
|---|---|
| 容器 | **备份文件夹**（备份哪些映射的文件夹，带**跳过缓存文件夹（CACHEDIR.TAG）**）、**排除模式**、**停止其他容器**、**前后命令**、**数据库**、**应用繁忙时**、**备份成功后更新**、**用快照代替停止**、**曾用名** |
| 虚拟机 | **虚拟机**，带**方式**（**优雅（关机）**或**实时快照**）和**仅变更的块**，参见[虚拟机备份指南](vm-backup-ssh-setup.md#per-vm-method) |
| 文件夹集 | **文件夹**和**排除模式** |
| 闪存 | **Flash ZIP 导出**，把每个闪存备份写成普通的 `.zip`，放到你选的文件夹 |
| ZFS 数据集 | 子数据集、要停止的容器和快照前后的命令、**副本**和**测试快照访问**，参见 [ZFS 数据集](zfs-datasets.md) |

设置在你更改时自动保存。

### 验证标签页 {#verify-tab}

- **检查项**显示第一次备份之后的恢复检查。**检查恢复**会在最新的备份上再运行一次：BombVault 把最多 100 个文件、256 MiB 的样本恢复到临时文件夹，并让 restic 对照哈希把每个文件读回来。
- 容器上的**启动测试**会把最新的备份恢复成一个隔离的副本并启动它：名称以 `bombvault-test-` 开头，使用它自己的内部 Docker 网络，不发布端口，也无法访问局域网，1 个 CPU 和 2 GiB 内存。副本报告健康、在它暴露的第一个端口上有应答，或者两者都没有但保持运行，就算通过。原容器绝不会被碰到，副本、它的网络和它的数据之后都会被删除，测试中途重启之后也一样。主机网络上的容器、特权容器、带设备的容器和需要另一个容器的容器，会显示为无法测试。**设置、验证、自动检查**下的**启动测试**每次运行测试一个容器，最久没测试的优先。
- **异常**设置这个条目自己的灵敏度和通知级别，并显示它未处理的发现。
- **按文件夹统计大小**显示最新备份里什么占了空间，以及最近一次备份带来了其中多少，一次一层。
- **最近运行**列出最近的运行及其开始、结束和耗时。点击可以查看详情。

## 排除模式 {#excludes}

**排除模式**卡片每行接受一个模式。路径按你在容器内看到的样子输入，例如 `/config/Library/Application Support/Plex Media Server/Cache`，或者像 `.git` 这样的单独名称，它会在任何层级匹配。字段下方的预览会显示每一行解析成什么，当某一行什么都匹配不到或会排除一切时给出警告。内容为 `/` 或 `*` 的行，或写的是整个已备份文件夹的行，会被忽略，所以排除规则绝不会把备份清空。要排除整个文件夹，请改为在**备份文件夹**下取消勾选它。

对于 Plex、Jellyfin、Sonarr、Radarr、Immich 和 Nextcloud 这类知名镜像，卡片会提供应用自己会重新生成的文件夹，例如缓存、日志和缩略图。在你点击**排除所选项**之前，什么都不会被排除。

同一张卡片还带有文件夹扫描看不到的警告。例如 Immich 把相册、人脸和日期放在另一个容器的 PostgreSQL 数据库里，所以只对 Immich 容器做文件备份，恢复出来的是图片，却没有这些信息，而且恢复看起来像是成功了。请把数据库容器也一起备份。

## 数据库转储 {#database-dumps}

BombVault 认得的 PostgreSQL、MySQL 和 MariaDB 容器，会在每次备份之前从运行中的服务器转储出来，放进文件旁边它们自己的恢复点。涵盖官方镜像、PostGIS、TimescaleDB、pgvector、pgautoupgrade、Immich 的数据库镜像、linuxserver、yobasystems 和 jc21 的 MariaDB 镜像，以及 Oracle 的 mysql-server。只是看起来像数据库的容器也有同样的选项，但在你选择之前是关闭的。

转储直接流进仓库，从不写到磁盘上。凭据来自容器自己的变量，包括 `*_FILE` 密钥，并且绝不会离开容器。容器设置标签页上的**数据库**卡片会说明数据文件夹是在停止时保存、运行时复制，还是不保存，并为这个容器开关转储。标签 `bombvault.dbdump=false` 作用相同，而且优先于这张卡片。**设置、常规**下的**自动数据库转储**为所有容器统一开关。

转储失败不会让备份失败。它会作为单独的失败运行出现，附带原因，并发送一条通知。转储从不会自己被加载回去：你可以下载它（原样或压缩的），保存到文件夹，或在**备份**标签页上一键导入一个刚启动的数据库。没有 BombVault 时如何取回转储，参见[取回数据库转储](offsite-recovery.md#database-dumps)。转储失败时，参见[数据库转储失败](troubleshooting.md#a-database-dump-failed)。

## 命令与其他容器 {#commands}

- **前后命令**用 `sh -c` 在容器内运行，例如把缓存刷到磁盘。备份前的命令失败会中止备份。备份前的命令以退出码 75 退出，会推迟计划备份，见下文。
- **停止其他容器**列出在备份这个容器期间要停止的容器，例如它的数据库。之后它们按 Compose 的 `depends_on` 顺序重新启动，默认每一个都要报告健康，下一个才会启动。等待及其超时在**设置、计划**下**顺序**卡片的**备份后重启**里。

## 应用繁忙时 {#app-busy}

备份会停止它的容器，所以计划备份可以在有人使用应用时等一等，然后自己再试。容器设置标签页上的**应用繁忙时**卡片负责设置：

- **活动检查**会在计划备份之前询问 Plex、Jellyfin 或 Emby 有没有人在观看。Plex 用它自己 `Preferences.xml` 里的令牌来询问，所以不用输入任何东西。Jellyfin 和 Emby 需要一个 **API 密钥**，在服务器控制台的 API 密钥下创建。
- **忽略暂停超过此时长的会话（分钟）**让为了过夜而暂停的电影不再被计入。
- **服务器无响应时仍然备份**决定无法询问服务器时怎么办：开启则备份运行，日志里会写明。关闭则像有人在看一样等待。
- **容器发送数据时等待**适用于没有此类检查的应用，例如游戏服务器或下载器。在最近**保持安静（分钟）**分钟内的任何一次读数里，容器发送的数据超过**繁忙阈值（KiB/s）**，备份就会等待。
- **重试间隔（分钟）**、带**尝试时段**的**仅在时间窗口内尝试**，以及**最长等待（小时）**设置如何重试。
- **等待结束时**要么放弃，这时备份会在**需要处理**里出现并带有**重试**，要么**仍然备份**。

等待中的备份会记录为琥珀色的**已推迟**，这次运行的其余部分继续。概览、列表和条目会显示它以及下次尝试的时间，逾期提醒和保护状态会等到它的截止时间。推迟时你会收到一条通知，结束时再收到一条，而不是每次尝试都有。尝试会在另一个备份运行时等待，重启之后等待会继续。你自己启动的备份总是立即运行，无论是**立即备份**、**重试**、批量选择、API 还是 MCP，而且成功执行的备份会结束尚未结束的等待。

容器的设置标签页上还有一种较旧、较简单的办法：**等待应用空闲**，配合**最长等待（小时）**。应用一空闲，备份就开始，空闲的定义在**设置、计划**下的**备份前空闲**卡片里。同一次运行中到期的 Compose 栈成员会一起等待，等待中的备份不持有锁，所以其他容器照常进行。

### 示例：有人在看时 Plex 先等一等 {#example-plex}

全部备份每晚 03:00 运行。没有人应该因为 Plex 要备份而停机，看到电影中断，但备份仍然应该在早晨之前完成。

1. 打开**备份**，然后是 `plex` 条目，再到它的**设置**标签页。
2. 在**应用繁忙时**里，把**活动检查**设为 Plex。不用输入任何东西。
3. 把**忽略暂停超过此时长的会话（分钟）**设为 `30`，这样午夜暂停的电影在十二点半就不再被计入。
4. 保持**服务器无响应时仍然备份**开启。
5. 把**重试间隔（分钟）**设为 `15`。
6. 开启**仅在时间窗口内尝试**，把**尝试时段**设为 `22:00` 到 `06:00`。
7. 把**最长等待（小时）**设为 `3`，**等待结束时**设为**仍然备份**。

在 03:00 仍然有人在看的夜晚会发生这些：BombVault 询问 Plex，发现有会话在播放，把备份记录为**已推迟**，下次尝试在 03:15。这次运行的其他容器照常备份。电影在 04:10 结束时，04:15 的尝试发现 Plex 空闲，把它备份了，等待随一条通知结束。如果电影到 06:00 还在放，等待会走到尽头，Plex 会照样被备份，所以它的备份落后不会超过三小时。

如果想自己做检查，可以让**备份前命令**在应用繁忙时以退出码 75 退出，例如 `[ "$(cat /tmp/players)" = 0 ] || exit 75`。更多症状和解决办法见[故障排除](troubleshooting.md#deferred-backups)。

## 普通导出 {#exports}

restic 仍然是引擎，但导出可以给你一份既不需要 BombVault 也不需要 restic 的副本。

- 条目页面**更多**下的**导出容器**和**导出虚拟机**会把此刻的副本写在仓库旁边：容器的备份文件夹加上它的 Unraid 模板，或虚拟机的磁盘映像加上它的定义，可以用 `virsh define` 恢复。
- 快照上的**导出**会把已存储的备份写到服务器上的导出文件夹，格式是 tar、zip 或独立的 restic 仓库，可以导出一个快照，也可以导出全部。

导出默认是普通文件。**设置、系统**下的**使用 age 加密导出**会为你列出的收件人把它们封存起来，包括 Flash ZIP，每个收件人是一个 age 公钥或 SSH 公钥。之后你在服务器之外用对应的私钥解密。开启加密但没有有效收件人时，导出会带着明确的错误失败，而不是写出普通文件。

## 运行会告诉你什么 {#run-notes}

- **时间。** 每次运行都会读取开始、结束和耗时，每个条目都有自己的**最近运行**。
- **备份为什么慢。** 备份运行时，BombVault 会观察 CPU、磁盘和网络有多忙。当备份花的时间比平时长很多，并且有一样东西明显已到极限时，运行记录会说明，例如"目标磁盘 disk1 有 98% 在忙"。否则它什么都不说。
- **检查和清理的进度。** 活动日志和**检查备份**卡片会显示 restic 数到了哪里，例如*12 / 47 个包*，当足以估算时还会显示这一步剩下的时间。
- **读不到的文件。** 备份完成但漏掉了某些东西，对应的行会变成橙色，并写出漏掉了什么。
