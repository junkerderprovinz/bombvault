# ZFS 数据集

ZFS 数据集是**备份**列表中的条目，和容器、虚拟机一样。一个条目是一个数据集连同它之下的所有数据集。每次备份，BombVault 会对整棵树做一个 ZFS 快照，所以其中的每个数据集都在同一时刻被捕获。随后它从这个快照读取每个数据集的文件，用 restic 像存储文件夹一样存储它们，并在之后立即移除该快照。备份会去重，你可以浏览其中任何一份，也可以还原单个文件。

备份从不向 restic 发送数据流，也从不回滚数据集。BombVault 只销毁它自己创建的快照。可选的[副本](#replica)是唯一使用 `zfs send` 的地方：它把数据集复制到第二台 ZFS 服务器，不触碰备份。

## 前提条件 {#requirements}

- **到这台服务器的 SSH 连接。** ZFS 数据集使用与虚拟机备份相同的密钥、主机和用户。如果虚拟机备份已经可用，这里也可以用。否则请按照 GitHub 上的[通过 SSH 备份虚拟机指南](https://github.com/junkerderprovinz/bombvault/blob/main/docs/vm-backup-ssh-setup.md)操作。模板字段名为 **Host SSH: Address**、**Host SSH: Port** 和 **Host SSH: User**。
- **该主机上的 `zfs` 命令。** Unraid 6.12 及更高版本和 TrueNAS SCALE 都有。
- **Host Data 映射为 `/mnt`，Access Mode 为 Read/Write - Slave。** 这是模板的默认值。数据集的快照要在 BombVault 启动之后才会出现在数据集的 `.zfs/snapshot` 文件夹中，因此容器必须能收到主机之后创建的挂载。
- **数据集挂载在 `/mnt` 之下。** 在 Unraid 上，池位于 `/mnt/<pool>`，所以这一点已经满足。

在**设置、常规**中打开该分区（ZFS 数据集）。备份页面**更多**下的**与这台服务器的 ZFS 连接**随后会打开**与这台服务器的连接**。它测试 SSH 链路，说明连接的用户和主机，并在有问题时说明缺了什么。链路中断时，备份列表会通过**查看连接**说明这一点，而概览上的**主机集成**卡片显示同样的结果。

## 条目与子数据集 {#items-and-children}

在备份页面上选择**添加**，然后选择**一个 ZFS 数据集**。列表来自服务器。选择你想备份的内容最上层的数据集，例如 `cache/appdata`，条目就会涵盖它以及它之下的每个数据集。

- **新的子数据集会自动加入。** 之后在条目下创建的数据集会在下一次运行时被备份，该次运行会点出它是新的。它的首次备份会完整读取一次；之后只读取变化。
- **个别子数据集可以排除。** 在条目的设置标签页上关闭某个子数据集，它连同其下的一切都会被排除。服务器上已不存在的被排除子数据集会被标注出来，并可以从列表中移除。
- **读取不了的子数据集会被跳过，但绝不会悄悄跳过。** 运行会列出它们，条目显示跳过了多少个，概览上的**未备份**卡片把每一个算作未受保护。运行仍会备份其他所有内容，不会因为跳过的子数据集而失败。原因见[原因代码表](#reason-codes)：数据集未挂载、`canmount=off`、挂载点为 `legacy` 或没有、加密密钥未加载、快照访问被关闭，或 BombVault 看不到的挂载点。
- **被跳过的数据集不会连带跳过它的子数据集。** 只包含其他数据集的 `canmount=off` 数据集会被跳过（显示为"仅结构"），而它已挂载的子数据集会被备份。密钥未加载的加密数据集会与共用其密钥的子数据集一起被跳过。
- **属于虚拟机磁盘或系统数据的子数据集在添加对话框中默认关闭**，原因显示在开关旁边。添加整个池时需要确认，确认窗口会列出池中包含的内容。

### 卷 {#volumes}

卷（zvol）保存的是虚拟磁盘而不是文件，ZFS 条目绝不会备份它。

- 虚拟机使用的卷会随该虚拟机一起备份。
- 没有任何虚拟机使用的卷（iSCSI extent、你已分离的磁盘）**不会被 BombVault 备份**。添加窗口和备份页面会统计这些卷并说明这一点。以后的版本会备份它们。

条目树中的卷会在每次运行时被跳过并点名。

### Docker 的存储 {#docker-storage}

使用 Docker 的 ZFS 存储驱动时，每个镜像层都是一个挂载点为 `legacy` 的数据集。添加对话框会把它们按父级折叠为一行。包含超过 20 个这类数据集的树不能成为条目：只要它的快照存在，Docker 就无法移除镜像层。请改为添加它之下的数据集，例如 `appdata`。

### 条目绝不重叠 {#overlap}

一个数据集只能属于一个条目。BombVault 会拒绝位于现有条目之内、或会包含现有条目的新条目。要把几个子条目合并成一个父条目，请先删除子条目并选择保留它们的备份，然后添加父条目。每个数据集都以自己的名称保留历史，所以下一次备份会从旧条目停下的地方继续，而不会重新读取所有内容。

## 快照前后停止容器与执行命令 {#consistency}

正在运行的数据库的快照就像突然断电：数据库通常会恢复，但它必须去恢复。每个条目可以针对这一点做两件事，两者都只涵盖快照的那一瞬间，而不是整个备份。

- **为快照停止这些容器。** BombVault 停止列出的容器，创建快照，然后立即重新启动它们。同一依赖层级的容器并行停止，依赖方先停，因此整个窗口通常只有几秒钟；运行记录会显示具体时长。随后备份在应用已经重新运行时读取被冻结的快照。只有原本在运行的容器才会被停止。
- **快照前后执行的命令。** 它在你选择的容器中运行，例如在快照前一刻把数据库导出到数据集中，而无需停止任何东西。如果快照前的命令失败，备份失败，也不会创建快照。快照后的命令失败会显示在运行记录中，但不会导致备份失败。

出现问题时会发生什么：

- 如果某个容器无法停止，BombVault 会启动已经停止的容器，备份失败并指出该容器。它从不退而对运行中的应用做快照。
- 停止操作会等待正在进行的容器备份结束（手动运行最多 30 分钟，计划运行最多到备份的时间上限），这样两者就不会同时停止和启动同一个容器。
- 在第一个容器停止之前，BombVault 会记下它停止了哪些容器。如果 BombVault 在这段时间内被杀掉，它会在下次启动时再次启动那些容器、发送通知，并且条目会为任何未能启动的容器显示红色提示。

自动数据库转储（参见[功能](features.md)）随容器自己的备份运行，而不是随 ZFS 条目运行。仅通过其数据集备份容器的数据库不会有转储，所以请在这里给它一条命令。

一个容器可以在这个列表中，同时也作为容器被备份。它的数据随后会在两个仓库中存储两次，全部备份也会让它停止两次。条目会这样说明。

## 还原 {#restore}

打开条目并选择**还原**，或在**恢复**页面中选择它。还原窗口会询问备份，然后是**数据集**。默认是条目的顶层数据集。在**内容**下，你可以还原全部，或只还原你挑选的文件和文件夹。**目标位置**提供：

- **恢复回数据集里。** 备份中的文件会写入数据集的挂载点。同名文件会被覆盖，其他文件保持不变。数据集从不会被回滚或替换。BombVault 会在开始前检查一次、在写入前再检查一次，确认数据集已挂载、可见且可写。数据集内部挂载了子数据集的位置不会写入任何内容：子数据集保留它的文件、属主和权限，并从它自己的备份中还原。
- **还原到文件夹。** 选择 `/mnt` 下的一个文件夹。BombVault 会检查该文件夹位于已挂载的存储池或共享上，并且有足够的可用空间。这在没有 SSH 链路时也能工作，也适用于已不存在的数据集。
- **到新数据集。** 为一个尚不存在的数据集命名；窗口会建议 `<dataset>-restored`。BombVault 用备份中保存的 ZFS 属性创建它并还原到其中，参见[还原为新数据集](#new-dataset)。

把**这份备份里的所有数据集**选作数据集，会把树的每个数据集写入你所选文件夹的各自子文件夹中。该备份中被跳过的数据集会被点名。要从另一个 BombVault 的仓库还原，请使用还原页面上的**从旧的备份文件夹**；它总是还原到文件夹：一份备份的所有数据集，各自进入自己的子文件夹，或树中的某一个数据集，整个或所选文件。

条目的待停止容器列表也适用于还原到数据集。这些容器在整个还原期间保持停止，容器备份在此期间等待。

### 安全快照 {#safety-snapshot}

在写入某个数据集之前，BombVault 会只对那一个数据集做一个名为 `bombvault-prerestore-<time>` 的 ZFS 快照。**先留一份当前状态的 ZFS 快照**默认开启；关闭它需要再次确认。如果无法创建快照，则不会还原任何内容。

BombVault 绝不会自行删除安全快照。条目会列出它们及其年龄和大小，每个都有**删除**操作，并在最旧的一个超过 30 天时发出警告，因为它在存储池上保留着已删除和已更改的数据。

还原后若要回退，请从数据集内的 `.zfs/snapshot/bombvault-prerestore-<时间>` 复制单个文件。`zfs rollback <dataset>@bombvault-prerestore-<时间>` 只在它仍是该数据集最新快照时有效。`zfs rollback -r` 会删除所有更新的快照，包括自动快照。

### 还原为新数据集 {#new-dataset}

BombVault 每次备份都会保存每个数据集在本地设置的 ZFS 属性：compression、recordsize、quota、reservation、atime、xattr、acltype、casesensitivity 以及你自己的用户属性。继承的值和只读值会自行恢复，因此不保存。在 BombVault 开始保存之前的备份中没有这些属性。

- **到新数据集**会带上所有保存的属性运行 `zfs create`。casesensitivity、normalization 和 utf8only 只能这样设置。配额和预留会在写入文件之后才设置，因此不会拒绝这些文件。挂载点不带过去，以免副本与原数据集冲突；`canmount`、`readonly` 和加密设置也不带过去，以便还原可以写入。在加密数据集下创建的新数据集会继承它的加密。上级数据集必须存在。如果创建之后出了问题，新数据集会留在服务器上，因为 BombVault 从不销毁数据集。
- **恢复回数据集里**会在还原旁边列出保存的属性。**同时设置这些属性** 会在写入任何文件之前，设置现有数据集仍然接受的属性。配额和预留会在写入文件之后才设置，因此不会拒绝这些文件。不打开此开关，数据集会保留自己的设置。

## 备份里包含什么 {#contents}

备份中包含：每个已备份数据集的文件和文件夹，以及 restic 保存的属主、权限、时间戳和扩展属性，以及每个数据集在本地设置的 ZFS 属性。

备份中不包含：

- 每个数据集顶层文件夹本身的属主和权限（其下的内容都包含在内）。还原回数据集时保留现有的顶层文件夹不变，还原到文件夹时以 `0755` 权限创建它；
- 已有的 ZFS 快照；
- 被跳过或被排除的子数据集；
- 卷。

要还原到新池，请先创建池，再把每个数据集还原为新数据集。TrueNAS 在 SMB 数据集上使用的 NFSv4 ACL 能否按预期恢复，目前尚未验证，所以在依赖它之前，请先用自己的数据试一次还原。

## 加密的数据集 {#encryption}

加密数据集只有在其密钥已加载时才会被备份。否则会被跳过并给出警告；请用 `zfs load-key` 加载密钥并挂载数据集。BombVault 以解密后的形式读取数据，并保存到经过加密的 restic 仓库中。如果你在 BombVault 中关闭了加密，这个仓库就不是加密的。

## 副本 {#replica}

副本是条目的数据集在第二台 ZFS 服务器上的拷贝。BombVault 用 `zfs send` 和 `zfs receive` 让它保持最新。第一次运行发送全部内容，之后只传输变化的块。在另一台服务器上，你可以立即挂载这份拷贝。

副本绝不取代备份。较旧的版本、单个文件和检查仍来自备份，副本只保留你设定数量的快照。最新的副本算作场所之外的一份拷贝，但有副本而没有备份的条目仍然是橙色。

副本卡片上的**仅副本，不备份**会让整个 ZFS 分区只发送副本、不做备份。本地文件夹和异地目标保留各自的开关，所以关掉它后又会备份到那里；每个 ZFS 条目的卡片都按当前状态显示分区的这个开关。这样的条目等待的是第一份副本而不是备份，**立即备份**显示为**立即复制**，并且在快照前后，条目的容器会停止、命令会运行，与备份时相同。它的副本计入每隔几天一次的计划、逾期提醒和覆盖范围。

在条目设置标签页的**副本**卡片中打开它。在那里你选择副本去哪里、何时运行（**每次备份后**或**独立计划**），以及目标上保留多少个快照。卡片列出每个数据集和卷及其状态，**立即复制**会启动一次运行。副本运行有自己的锁，所以较长的首次传输绝不会拖住备份。

在备份页面上选中 ZFS 磁贴时，备份操作旁边会出现**立即复制全部**，它会逐个发送每个 ZFS 条目的副本。这个批处理由服务器运行，所以你离开页面后它仍会继续；无法复制的条目会被点名并跳过。

### 推送到 ZFS 服务器 {#replica-push}

任何装有 ZFS 和 SSH 的机器都可以接收，例如第二台 Unraid 或 TrueNAS。BombVault 不必在那里运行。

1. 在**设置、配对**下，选择**没有 BombVault 的 ZFS 服务器**中的**通过 SSH 连接**，或条目**副本**卡片中的**添加 ZFS 服务器**。
2. 输入地址、用户和端口。对话框会显示 BombVault 的公钥。把它加入服务器上该用户的 `~/.ssh/authorized_keys`。在 Unraid 上，它位于 **Users, root, SSH keys**。根据 **Display Settings**，Users 位于页眉菜单或 Settings 下。在 TrueNAS 上，请在 **Credentials, Users** 下编辑该用户。 这是副本密钥。它与虚拟机和主机 SSH 连接所用的密钥不同，即使那个密钥已经授权，也请添加这一个。
3. 测试连接。对话框随后列出服务器的存储池。选择一个并设置根路径，默认是 `<pool>/bombvault-replica`。
4. 在条目的**副本**卡片中选择新服务器。该服务器随后在实例页面上有自己的卡片，**打开**会通向它的页面。

使用 root 时不需要其他设置。独立用户需要在目标的存储池上拥有这些权限，对话框也会显示它们：

```
zfs allow <user> receive,create,mount,rollback,destroy,userprop <pool>
```

在源端，同类用户需要在条目的顶层数据集上具备这些权限：

```
zfs allow <user> send,snapshot,hold,release,bookmark,destroy <dataset>
```

按这个方向，持有条目的 BombVault 也持有一个可以在该服务器上写入的密钥。

BombVault 会在首次连接时保存服务器出示的主机密钥，之后拒绝任何其他密钥。如果服务器已重装，请在服务器页面上点击**忘记主机密钥**，下一次连接会保存新密钥。

当这台服务器的主机自己就能连到 ZFS 服务器时，它会用副本密钥和已保存的主机密钥，把 `zfs send` 直接通过自己的 ssh 送到服务器，因此数据流不经过 BombVault。否则数据流会经过 BombVault。

### 发送到已配对的实例 {#replica-receive}

已配对的 BombVault 可以自己接收副本。任何人都不会获得另一台主机的 SSH 访问权限，也不会有密钥写入 `authorized_keys` 文件。

1. 在条目的**副本**卡片中，选择已配对的实例作为目标，或在实例页面上该实例的卡片里打开**ZFS 服务器**角色并在那里选择 ZFS 条目。在它应答之前，卡片会显示**等待批准**。
2. 在接收实例上打开**实例**。请求会在发送实例的卡片上显示为徽章，它的**详情**会列出它。选择该服务器上的存储池和根，以及保留多少个快照，然后按**允许**或**拒绝**。
3. 点击**允许**后，源端按自己的计划发送，与其他任何目标相同。

接收实例只接受批准所涵盖的内容：条目的数据集，放入它自己的根下。它自己运行 `zfs receive`，源端没有办法在那里删除或回滚任何东西。因此即使源端被人接管，这份拷贝也能保全。接收实例保留它自己的保留策略。源端在请求时只提出一条建议规则。

接收端实例上的 **Revoke access** 可随时终止批准，并通知源端。源端随后显示批准已被撤回并停止发送。接收端实例已经拥有的内容会留在那里。被拒绝的请求保持拒绝状态。要增加数据集，或在撤销之后重新请求，需要再次发出请求。

接收端实例必须通过 HTTPS 应答。源端不会向普通 http 地址发送任何内容，因为令牌和数据会以未加密的形式经过网络。每次传输还会在接收端存储池中留出十分之一的空间，并在占用这部分空间之前停止，所以单个源端无法填满接收端服务器的存储池。

### 数据存放在哪里 {#replica-target}

每个数据集存放在 `<root>/<server>/<pool>/<path>`。服务器文件夹是源实例的名称，在首次传输时确定，因此两台存储池同名的服务器不会互相干扰。例如，名为 `tower` 的服务器上的 `cache/appdata` 最终位于 `backup/bombvault-replica/tower/cache/appdata`。

BombVault 重新设置后，目标会拒绝这个 BombVault 之前填充的文件夹。这时副本卡片会提供**接管此文件夹**，下一份副本会接着该文件夹中的拷贝继续。只有在没有其他 BombVault 仍在向该文件夹复制时才接管它。

目标上的拷贝是只读的，也不会被挂载，所以不会覆盖那台服务器上的任何内容。ZFS 属性会一并传输，但挂载点、`sharenfs` 和 `sharesmb` 除外。预留（`reservation` 和 `refreservation`）也不会传输，所以拷贝只占用其数据所需的空间。

### 包含什么 {#replica-contents}

条目备份的所有内容都会进入，它之下的卷也会，而备份会跳过这些卷。你在条目中关闭的子数据集则不包含。一次运行的所有数据集都来自同一个快照，与备份相同。

### 快照保留多久 {#replica-retention}

在目标上，新副本保留 7 个每日快照和 3 个每周快照。也可以改选 **Short**、**均衡** 或 **Long**，或者设置 **Custom values**。那里只会删除名为 `bombvault-replica-<14 digits>` 的快照，并且永远不会删除双方共有的最新一个。

在源端，BombVault 只保留最新的副本快照，外加每个已发送状态的一个书签。书签不占用空间。下一次传输从它们开始。

### 副本中的加密数据集 {#replica-encryption}

加密数据集以原始方式发送。它在目标上保持加密，目标永远看不到密钥。请妥善保管密钥：恢复后要打开拷贝需要它，没有密钥的副本无法读取。

### 使用副本 {#replica-use}

打开条目的**备份**标签页，在保存其快照的位置中点击**ZFS 副本**一行。该页面列出目标上的快照，并显示带有你真实名称的命令。

要查看旧的状态，可在目标上克隆一个快照。克隆在有内容变化之前不占用空间，副本保持不变：

```
zfs clone backup/bombvault-replica/tower/cache/appdata@bombvault-replica-20261006014100 backup/bombvault-replica/clone-appdata
```

如果源端出了故障，可在目标上把拷贝变成普通的、可写的数据集：

```
zfs inherit -r readonly backup/bombvault-replica/tower/cache/appdata && zfs inherit -r canmount backup/bombvault-replica/tower/cache/appdata && zfs mount -a
```

之后 BombVault 会停止向该数据集复制，直到你开始新的首次运行。

要把某个状态取回源端，请在弹出页面中点击 **Bring back as a new dataset**。BombVault 会把快照发送到原数据集旁边的一个新数据集，名称是 `<dataset>-bombvault-restore-` 加上时间戳。它从不写入原数据集。

## 遗留的快照 {#leftover-snapshots}

备份快照的名称为 `<dataset>@bombvault-<14 位数字>`，例如 `cache/appdata@bombvault-20260924021500`（UTC）。BombVault 会在备份完成后立即删除它。如果删除失败，例如因为数据集正忙或 BombVault 被停止，BombVault 会在以下时机删除它：

- 在该条目的下一次备份之前，
- 在 BombVault 启动时，对每个条目，即使该分区已关闭也是如此，
- 在你删除该条目时，
- 在你对该条目按**立即移除**时，它会显示还剩多少个。

只有与 `bombvault-` 加 14 位数字完全一致的名称才会被删除。安全快照、你自己的快照和自动快照从不会被触碰。手动删除某个快照：

```
zfs destroy -r cache/appdata@bombvault-20260924021500
```

副本的快照名为 `<dataset>@bombvault-replica-<14 digits>`，不属于遗留快照。它在源端保留到下一次副本运行将其替换，在目标上则保留到保留策略不再需要它。清理程序从不触碰它，因为它只匹配 `bombvault-` 后面恰好跟 14 位数字的名称。

## 异常 {#anomalies}

被清空的子数据集几乎不会改变大型树的总量，所以异常检测会单独监视条目的每个数据集：它的大小、文件数、新数据和 restic 耗时各有自己的历史。这份历史属于数据集的名称，所以之后即使该树由另一个条目备份，它也会保留。

只要条目的选择没有变化，上一次运行备份过、而这次运行读取不了的数据集就算作被清空。这涵盖了未加载的密钥、未挂载的数据集，以及已从树中消失的数据集。你自己排除的子数据集会改变选择，因此它的历史会重新开始。当关于数据丢失的发现处于未处理状态时，保留只保留那一个数据集的旧备份，并照常清理树的其余部分。

每个数据集在条目的监控中都有自己的一行，监控通过异常页面上的**监控**打开，也位于条目的**验证**标签页。未处理的发现显示在每个数据集旁边。发现中的链接会在该数据集最近一次良好的备份上打开还原窗口。一次运行是否完成是针对整个条目判断的，因为一次运行要么整体成功，要么整体失败。

检查本身在[功能](features.md)下描述。通过 [MCP 服务器](mcp.md)连接的助手可以列出 ZFS 条目的还原点、启动它的备份并读取发现，但确认某个发现要在异常页面上进行。

## 原因代码 {#reason-codes}

条目的页面、运行历史和通知会用这些代码之一来说明问题。其中大多数在页面上也有紧邻的修复办法。

| 代码 | 含义 | 处理方法 |
|---|---|---|
| `ssh-missing` | 此容器中没有设置 SSH 连接。 | 按虚拟机备份的方式设置 SSH 连接。 |
| `host-placeholder` | Host SSH: Address 仍是示例值，`host.docker.internal` 也没有响应。 | 把 Host SSH: Address 设为这台服务器的局分区网 IP。 |
| `host-fallback` | Host SSH: Address 仍是示例值，但 `host.docker.internal` 可用。 | 无需处理，或者设置局分区网 IP。 |
| `ssh-unreachable` | 无法通过 SSH 连接到服务器。 | 检查地址和端口，并确认 SSH 已开启。 |
| `ssh-auth` | 服务器拒绝了 BombVault 的密钥。 | 在服务器上运行一次**与这台服务器的连接**下显示的命令。 |
| `zfs-not-found` | SSH 主机上没有 `zfs` 命令。 | 把 Host SSH: Address 指向拥有这些池的机器。 |
| `zfs-permission` | SSH 用户无权运行这条 zfs 命令。 | 使用 root，或参见 [TrueNAS SCALE](#truenas)。 |
| `uri-mismatch` | `LIBVIRT_URI` 指定的主机或用户与 SSH 字段不同。 | 使二者一致，或清空 SSH 字段，让两者都取自 URI。 |
| `zfs-error` | zfs 报告了其他错误。 | 详细信息中会显示其消息。 |
| `propagation-missing` | 主机上的新挂载无法到达容器。 | 把 Host Data 的 Access Mode 设为 Read/Write - Slave，然后重启 BombVault。 |
| `invalid-name` | BombVault 不接受的数据集名称。 | 重命名该数据集。 |
| `name-too-long` | 树中的某个数据集对快照名称来说太长。 | 重命名它，或把它之下的某个数据集添加为条目。 |

| `overlaps-item` | 该数据集与现有条目重叠。 | 参见[条目绝不重叠](#overlap)。 |

| `nothing-readable` | 条目中的所有数据集此刻都读取不了。 | 查看被跳过数据集的代码。 |
| `snapshot-failed` | 无法创建快照。 | 详细信息中会显示 zfs 的消息。 |
| `containers-busy` | 需要停止容器时，还有容器备份在运行。 | 稍后再开始。计划运行会自动等待。 |

| `leftover-snapshots` | 服务器上还留有 BombVault 无法删除的快照。 | 按 **立即移除**，参见[遗留的快照](#leftover-snapshots)。 |

| `gone` | 该数据集已不在服务器上。 | 无需处理。它的备份仍可还原。 |

| `destination-not-mounted` | 该文件夹不在已挂载的池或共享上。 | 选择池或共享上的文件夹。 |
| `not-enough-space` | 目标位置的可用空间不足。 | 释放空间，或选择其他文件夹。 |

### 检查容器能看到什么 {#mountinfo}

条目设置标签页上的**测试快照访问**会对它的树做一个真实的快照，在 BombVault 内部为每个数据集查找它，然后再移除。这是在第一次计划运行之前证明整条路径的最快方式。

如需自己查看，请在服务器上运行：

```
docker exec BombVault grep zfs /proc/self/mountinfo
```

每一行是容器内的一个挂载。数据集所在的行显示它在容器内的路径（位于 `/host/user` 之下）和数据集名称。该行中如果有 `master:N` 字段，表示这个挂载能收到主机之后创建的挂载，而快照访问需要的正是这一点。如果没有，请把 Host Data 的 Access Mode 设为 Read/Write - Slave，然后重启 BombVault。

## TrueNAS SCALE {#truenas}

- 设置了 `LIBVIRT_URI` 时（与 TrueNAS 上的虚拟机备份相同），BombVault 会从 URI 中获取其 zfs 命令所用的 SSH 主机、用户和端口中未单独设置的项。如果不做虚拟机备份，则无需设置任何内容：`host.docker.internal` 在 TrueNAS 应用中无法解析，因此 BombVault 会通过应用的默认网关，以 root 身份经端口 22 连接主机。想用其他地址或用户时，在应用的 `environment` 中设置 `LIBVIRT_HOST`、`LIBVIRT_SSH_USER` 和 `LIBVIRT_SSH_PORT`。
- 在 **Credentials, Users** 下把**设置、集成、主机 SSH** 中的主机 SSH 密钥添加给 root，并在 **System, Services** 下开启 SSH 服务。发往这台或另一台 TrueNAS 的[副本](#replica-push)还需要副本密钥，那是另一把密钥。
- 非 root 的用户需要在条目的顶层数据集上拥有权限，这随后涵盖其下的每个数据集：

  ```
  zfs allow <user> snapshot,destroy,mount <dataset>
  ```

  还原到新数据集还需要对上级数据集拥有 `create` 权限，设置保存的属性则需要这些属性的权限。

  在 TrueNAS 上，非 root 的 SSH 会话路径中没有 `/usr/sbin`；这时 BombVault 会直接调用 `/usr/sbin/zfs`。
- 应用的 **Host Data** 必须是数据集之上的主机路径，例如 `/mnt/tank`，而不是 ixVolume。使用主机路径时，应用会把主机的新挂载传给 BombVault（`rslave`），而快照访问需要的正是这一点。完整的应用设置参见 [TrueNAS SCALE](getting-started.md#truenas)。
