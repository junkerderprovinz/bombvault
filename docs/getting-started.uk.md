# Початок роботи

Ця сторінка проведе вас від свіжої машини Unraid до вашої першої резервної копії.

## Вимоги

| Вимога | Примітки |
|---|---|
| **Unraid 6.12+** | Раніші версії не тестувалися. Основна ціль, це Unraid, але BombVault працює також на звичайному хості Docker і на TrueNAS Scale (див. [Звичайний хост Docker](#generic-docker-host) і [TrueNAS SCALE](#truenas)). |
| **Розташування репозиторію restic** | Локальний шлях (рекомендовано: ваш масив або кеш), SMB, NFS або будь-який бекенд rclone. |
| **Сокет Docker** | Монтується шаблоном автоматично (`/var/run/docker.sock`). |
| **Unraid flash** (`/boot`) | Монтується цілком шаблоном автоматично (`/boot` до `/host/boot`). Забезпечує резервне копіювання flash і дає змогу відновленому контейнеру знову з'явитися як звичайний, редагований додаток Unraid. |
| **Віртуальні машини KVM** (за вибором) | Резервне копіювання VM спілкується з libvirt через SSH, без монтування libvirt. Налаштуйте його в **Налаштування, Інтеграції, SSH хоста** (див. [Конфігурація](configuration.md)). |
| **Набори даних ZFS** (за вибором) | Те саме SSH-з'єднання, що й для резервного копіювання VM, `zfs` на хості та Host Data, підключений як `/mnt` з режимом доступу Read/Write - Slave (типове значення шаблону). Див. [Набори даних ZFS](zfs-datasets.md). |
| **Застосунок для Android** (необов'язково) | Android 10 або новіший, спарювання із серверами версії 9.7.0 або новішої. Див. [Застосунок для Android](android.md). |

## Встановлення на Unraid

Найпростіший шлях, це **Community Applications**.

1. Відкрийте вкладку **Apps** в Unraid.
2. Знайдіть **BombVault**.
3. Натисніть **Install**, задайте обов'язкові змінні (нижче) і застосуйте.

!!! tip "Ручне встановлення шаблону"
    Якщо ви віддаєте перевагу додати шаблон вручну:

    1. Перейдіть до **Docker, Add Container, Template repositories** і додайте:
       ```
       https://github.com/junkerderprovinz/unraid-apps
       ```
    2. Знайдіть **BombVault** у Templates.
    3. Задайте обов'язкові змінні та натисніть **Apply**.

## Звичайний хост Docker {#generic-docker-host}

Не Unraid? BombVault працює і як звичайний контейнер на будь-якому хості Docker. Для TrueNAS SCALE є власні кроки в розділі [TrueNAS SCALE](#truenas).

1. Візьміть із репозиторію готовий до редагування файл [`deploy/docker-compose.generic.yml`](https://github.com/junkerderprovinz/bombvault/blob/main/deploy/docker-compose.generic.yml).
2. Задайте `APP_KEY` (див. нижче) і спрямуйте том Host Data на ваш справжній корінь даних. Коментарі у файлі проводять через обидва кроки.
3. `docker compose up -d`, потім відкрийте `https://<ip-хоста>:3443/`.

Чим це відрізняється від Unraid:

- **Немає розділу Flash.** Завантажувальної флешки, яку треба зберігати чи відновлювати, тут немає, тож розділу Flash тут нічого робити. Натомість, якщо Host Data досягає `/etc` хоста, **Додати** на сторінці «Резервні копії» пропонує **Конфігурація системи** як підказку для папки: початковий набір `/etc`, який ви переглядаєте та правите перед збереженням.
- **Немає власних сповіщень Unraid.** Власні канали сповіщень BombVault (webhook, попередження про невдалу зовнішню копію тощо) працюють як звичайно; пропускається лише надсилання до системи сповіщень Unraid, бо такої системи тут немає.
- **Резервне копіювання віртуальних машин необов'язкове і потребує окремого хоста libvirtd, доступного через SSH.** Див. закоментований блок у файлі compose. У звичайного хоста Docker власного керування віртуальними машинами немає.
- **Немає віджета для Dashboard.** BombVault Widget, це плагін Unraid, тож і цей крок пропускається.
- **Як знаходяться дані контейнера.** Без угоди Unraid про `appdata` папку даних контейнера знаходять за сегментами з `DATA_ROOT_SEGMENTS`, іменованими томами Docker, робочим каталогом проєкту Compose і міткою `bombvault.data` (див. [Визначення джерел резервної копії](configuration.md#backup-source-detection)). Іменовані томи та набір `/etc` досягають лише шляхів усередині монтування Host Data, тож спрямуйте Host Data на спільного предка, який охоплює й корінь даних Docker.
- **`PLATFORM`.** Задайте `generic` або `truenas`. Якщо змінну не задано, BombVault розпізнає Unraid за його власним маркером на монтуванні flash і вважає все інше звичайним хостом, а кроки лише для Unraid пропускаються, замість того щоб запускатися й завершуватися помилкою.

### TrueNAS SCALE {#truenas}

BombVault поки немає в каталозі застосунків TrueNAS, тож установіть його як власний застосунок: **Apps, Discover Apps**, потім **Install via YAML** у меню поруч із **Custom App**. YAML нижче задає те саме, що й запис для каталогу в теці `truenas-apps` репозиторію. Замініть `tank` на свій пул і заповніть `APP_KEY`, як описано в наступному розділі.

```yaml
services:
  bombvault:
    image: junkerderprovinz/bombvault:latest
    hostname: bombvault
    restart: unless-stopped
    cap_drop: [ALL]
    cap_add: [CHOWN, DAC_OVERRIDE, FOWNER, SETGID, SETPCAP, SETUID]
    environment:
      APP_KEY: ""
      PLATFORM: truenas
      HOST_SOURCE_ROOT: /mnt/tank
      HOST_MOUNT_ROOT: /mnt/tank
      # Для резервного копіювання VM:
      # LIBVIRT_URI: qemu+ssh://root@<truenas-ip>/system?socket=/run/truenas_libvirt/libvirt-sock
    volumes:
      - /mnt/tank/apps/bombvault:/config
      - /var/run/docker.sock:/var/run/docker.sock
      - type: bind
        source: /mnt/tank
        target: /mnt/tank
        bind:
          propagation: rslave
    ports:
      - "30528:3443"
```

Потім відкрийте `https://<truenas-ip>:30528/`. Усе, що перелічено в [Чим це відрізняється від Unraid](#generic-docker-host), діє і тут, а в TrueNAS ще:

- **Права (capabilities).** BombVault потрібні всі шість, перелічені вище. Без `SETPCAP` резервне копіювання VM завершується помилкою.
- **Host Data** це шлях хоста на наборі даних, тут `/mnt/tank`, змонтований за тим самим шляхом усередині застосунку. Тому і `HOST_SOURCE_ROOT`, і `HOST_MOUNT_ROOT` називають саме його. `rslave` передає далі монтування, які хост робить пізніше, а вони потрібні копіям наборів даних ZFS.
- **Дані в ixVolume не копіюються.** Застосунок, чиє сховище це ixVolume, тримає свої дані в `/mnt/.ix-apps`, поза Host Data. BombVault зберігає лише визначення застосунку, і запуск називає теки, які він пропустив. Для кожного застосунку, чиї дані треба зберігати, виберіть сховище **Host Path** на наборі даних під Host Data.
- **Копії VM і наборів даних ZFS** звертаються до TrueNAS через SSH як root. Увімкніть службу SSH у **System, Services** і додайте публічний ключ із **Налаштування, Інтеграції, SSH хоста** користувачу root у **Credentials, Users**. Копіям VM потрібен ще `LIBVIRT_URI`, як показано вище, бо libvirtd у TrueNAS слухає власний сокет. Якщо не задано ні `LIBVIRT_URI`, ні `LIBVIRT_HOST`, BombVault бере як хост типовий шлюз застосунку, бо `host.docker.internal` у застосунку TrueNAS не розпізнається. Подробиці, зокрема про VM на zvol, є в [посібнику з резервного копіювання VM](https://github.com/junkerderprovinz/bombvault/blob/main/docs/vm-backup-ssh-setup.md#truenas-scale).
- **Репліка ZFS використовує інший ключ.** Репліка на другому сервері ZFS входить із ключем, який показує діалог репліки, а не з ключем SSH хоста. Додайте цей ключ на сервері, що приймає.
- **Видалений застосунок повертається у два кроки.** Спершу заново встановіть його в TrueNAS під тим самим ім'ям, при цьому знову створюється його мережа, потім відновіть його дані в BombVault. До того перевірка перед відновленням повідомляє про відсутню мережу, і відновлення відмовляється працювати, перш ніж щось змінити.
- **Поруч з оригіналом** створює звичайний контейнер Docker. Він працює, але екран Apps у TrueNAS його не показує.
- **Дампи баз даних** працюють на монтуваннях наборів даних. Імпорт у теку даних, яка сама є набором даних, переносить старий вміст у теку поруч із нею, тож набору даних рівнем вище потрібне для нього місце.

## Єдине обов'язкове налаштування

Єдина змінна, яку ви повинні задати, це `APP_KEY`, 32-байтовий шістнадцятковий секрет (64 шістнадцяткові символи), що використовується для виведення пароля репозиторію restic.

Згенеруйте його на будь-якій машині:

```bash
openssl rand -hex 32
```

Вставте результат у поле `APP_KEY` шаблону (Unraid) або у змінну середовища `APP_KEY` у `docker-compose.yml` (звичайний Docker-хост).

!!! danger "Не втрачайте свій APP_KEY"
    Втрата `APP_KEY` робить ваші зашифровані резервні копії невідновлюваними. Зберігайте його в безпечному місці окремо від сервера. Щойно BombVault запрацює, задайте пароль для входу та завантажте **набір для відновлення** в **Налаштування, Відновлення** (див. [Зовнішнє копіювання та відновлення](offsite-recovery.md#recovery-kit)). У ньому є ключ, усі місця призначення та команди restic.

Шаблон також монтує за вас сокет Docker, flash (`/boot`) і корінь **Host Data** (`/mnt`). Як *джерела*, так і *місця призначення* резервних копій живуть під Host Data. Повний довідник змінних і налаштування зовнішнього копіювання див. у [Конфігурація](configuration.md).

## Перший запуск

![Огляд після першої копії: що потребує уваги, захист кожного розділу, місця призначення та історія.](assets/screenshots/dashboard.png)

*Огляд після першої копії: що потребує уваги, захист кожного розділу, місця призначення та історія.*

1. Відкрийте вебінтерфейс за адресою `https://<your-unraid-ip>:3443` (самопідписаний сертифікат з коробки). Нове встановлення відкривається на сторінці **Ласкаво просимо до BombVault**, яка перелічує все, що BombVault знайшов на сервері.
2. Виберіть **Почати**. Огляд тоді показує картку **Перші кроки** з трьома кроками:
    1. **Оберіть розділи**: увімкніть те, що BombVault копіює (Контейнери, Віртуальні машини, Flash, Папки, Набори даних ZFS, Автобекап). **Обрати** відкриває список записів розділу, де **Призупинити розклад** виключає один із них. Розділи, які ви тут увімкнули, виконуються щоночі, і змінити це можна в **Налаштування, Розклад**.
    2. **Додати місце призначення**: куди потрапляють копії. Для початку досить локальної папки. Найнадійніше мати друге місце призначення поза домом, наприклад Storage Box або Backblaze B2. Локальні репозиторії типово лежать у `/mnt/user/bombvault/{container,vms,flash,config,files,zfs}` і створюються під час першої копії.
    3. **Перша резервна копія**: далі вона виконується сама щоночі.
3. Відкрийте **Резервні копії**, щоб побачити всі записи одним списком. **Створити копію всього зараз** запускає виконання для всіх увімкнених розділів, а **Створити резервну копію** на сторінці запису копіює лише його.

Користувалися BombVault раніше? **Відновити з резервної копії** на вітальній сторінці відкриває сторінку «Відновлення», де **Аварійний майстер** повертає налаштування, контейнери, віртуальні машини й папки втраченого сервера. Див. [Зовнішнє копіювання та відновлення](offsite-recovery.md#emergency).

!!! tip "Необов'язково: виберіть порядок резервного копіювання"
    Якщо деякі контейнери завжди мають резервуватися перед іншими (наприклад база даних перед застосунком, що її використовує), відкрийте картку **Порядок** у **Налаштування, Розклад** і перетягніть їх у потрібну послідовність. Заплановані виконання й повне резервне копіювання тоді йдуть за нею; усе, що ви лишили без порядку, копіюється за принципом «найбільш прострочене першим».

!!! note "Перевірка інтеграції з хостом"
    Картка **Інтеграція з хостом** в огляді тестує кожне монтування та CLI (сокет Docker, libvirt, restic, qemu-img, rclone) і повідомляє про будь-які відсутні частини, тож ви можете переконатися, що контейнер підключено правильно, перш ніж на нього покладатися. Вона чекає в **Налаштувати**, доки ви її не додасте.

## Як зорієнтуватися {#navigation}

![Налаштування як плитки, а поруч картки вибраної плитки. Кожна зміна записується одразу.](assets/screenshots/settings.png)

*Налаштування як плитки, а поруч картки вибраної плитки. Кожна зміна записується одразу.*

Бічна панель має п'ять пунктів: **Огляд**, **Аномалії** (поки ввімкнено виявлення аномалій), **Резервні копії**, **Відновлення** і, під **Вийти**, **Налаштування**. Головна дія сторінки плаває внизу праворуч, а **Більше** містить рідкісні. На телефоні панель містить Огляд, Резервні копії, Відновлення та Налаштування, а решта в **Більше**.

Сторінки й налаштування займають усю ширину вікна. Вікно тримає свої кнопки внизу, а та, що веде вперед, стоїть праворуч. На телефоні низ із понад трьома кнопками лишає вихід і головну дію, а решту ховає під **Більше**.

- **Резервні копії**, це перелік усіх контейнерів, віртуальних машин, наборів папок, флешки, кожного набору даних ZFS і автобекапу як записів. Плитки над списком вибирають вид, а **Фільтри**, **Сортування** і **Пошук** звужують його. Кожен запис має власну сторінку з трьома вкладками: **Резервні копії**, **Налаштування** та **Перевірка**. Кнопка «назад» ліворуч від значка запису веде до списку.
- **Відновлення**, це одна сторінка для всього: оберіть розділ, знайдіть запис і виберіть копію. Звідси ж починаються Аварійний майстер та інші джерела.
- **Налаштування**, це чотирнадцять плиток: Загальні, Вигляд, Розклад, Місця призначення, Відновлення, Сповіщення, Перевірка, Безпека, Екземпляри, Спарювання, Інтеграції, Застосунки, Система та Інформація. Натисніть `/` або Ctrl+K, щоб шукати серед усіх, у тому числі за назвами, які сторінки мали в попередніх версіях. Перетягніть плитки у власний порядок у **Вигляд**. Там, де стовпець плиток поряд зі сторінкою зробив би її надто вузькою, наприклад у вікні завширшки близько 1200 пікселів, плитки стають смугою над сторінкою, яку можна гортати вбік. Телефон показує ту саму смугу.
- **Місця призначення** та **Екземпляри**, це плитки налаштувань зі своїми сторінками. **Показувати також у бічній панелі** на їхній плитці закріплює їх на бічній панелі.

Ніщо не має кнопки «Зберегти» і ніщо не розгортається: рідкісні речі мають власну картку або вікно, а пояснення лежать у бульбашках (i). Після оновлення нотатки до випуску відкриваються самі, а зелені крапки позначають, що змінилося. Клацання ховає крапку. **Нове** в картці «Версія» в **Налаштування, Інформація** рахує, чого ви ще не бачили, і відкриває нотатки до випуску та список усіх змін з **Перейти туди** як дві вкладки одного вікна.

## Збирання з вихідного коду {#build-from-source}

BombVault, це один статичний бінарний файл Go, який обслуговує JSON API і вбудований інтерфейс на React. Спершу зберіть інтерфейс, потім запустіть бінарний файл:

```bash
npm --prefix web ci
npm --prefix web run build     # пише web/dist, який вбудовується в бінарний файл
export APP_KEY=$(openssl rand -hex 32)
go test ./...                  # модульні та інтеграційні тести зі справжнім проходом restic туди й назад
golangci-lint run ./...
go run ./cmd/bombvault         # обслуговує https://localhost:3443 із самопідписаним сертифікатом
```

Збирання інтерфейсу потрібне і для `go run`. Репозиторій відстежує в `web/dist` лише порожній маркер, тож без `npm --prefix web run build` бінарний файл нічого не вбудовує і відповідає `500 SPA index not found`, і це очікувано. Docker, libvirt і Unraid не можна протестувати в CI, тож перед відкриттям pull request перевірте монтування, restic і SSH-зв'язок із VM на справжньому хості карткою **Інтеграція з хостом** в огляді (або `GET /api/spike`).

## Наступні кроки

- Перегляньте всі **[Можливості](features.md)**.
- Зберіть усі сервери вашої групи на телефоні за допомогою **[Застосунку для Android](android.md)**.
- Додайте одне або кілька місць призначення поза домом (кожен розділ може копіювати в кілька одночасно) і збережіть свій набір для відновлення, як описано в **[Зовнішнє копіювання та відновлення](offsite-recovery.md)**.

- Клонуєте налаштування або переходите на нову машину? Перенесіть усю свою конфігурацію за допомогою картки **Експорт / імпорт налаштувань**. Див. [Конфігурація](configuration.md#portable-settings-export-and-import).
- Виникла проблема? Див. **[Усунення несправностей](troubleshooting.md)**.
