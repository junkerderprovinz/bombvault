# Сервер MCP

В BombVault встроен сервер Model Context Protocol (MCP), протокола, по которому ИИ-помощники вроде Claude Code и Claude Desktop обращаются к внешним инструментам. Через него помощник может прочитать, как идут ваши копии, и, если вы разрешите, запустить копию или отменить ту, которую сам запустил. Он выключен, пока вы не создадите ключ или не включите [вход через OAuth](#oauth): до тех пор конечная точка `/mcp` на всё отвечает `404`.

## Что помощник может и чего не может {#tools}

| Инструмент | Что делает | Вид |
|---|---|---|
| `get_health` | Версия, имя экземпляра, идёт ли копирование и что разрешено этому ключу | чтение |
| `get_status` | Состояние защиты по разделам: последняя успешная копия, ожидаемый интервал, проверки и внешние проверки, ближайшие плановые запуски, копии, ждущие простоя приложения, а для контейнеров самый свежий тестовый запуск | чтение |
| `get_coverage` | Что BombVault защищает и что нет, с причиной для каждого | чтение |
| `list_items` | Каждый защищённый контейнер, виртуальная машина, набор папок, флешка и конфигурация приложения с расписанием, тем, что останавливает копия, последней копией и тем, сколько она заняла. У контейнеров баз данных есть и последний дамп. Наборы данных ZFS тоже перечислены, с результатом их последней проверки. У каждой записи есть последняя проверка восстановления, а у контейнера последний тестовый запуск или причина, почему его нельзя проверить. Контейнер, пересозданный с другими настройками после последней копии, перечисляет, что изменилось | чтение |
| `list_runs` | История запусков, новые сверху, с фильтрами по разделу, записи, состоянию, виду и времени. Медленная копия, которую что-то одно задержало, называет это | чтение |
| `list_restore_points` | Точки восстановления одной записи из её основного репозитория, а для контейнера и его дампы баз данных. Набор данных ZFS получает одну точку восстановления на копию, со снимком каждого набора под ним | чтение |
| `get_activity` | Что выполняется сейчас, с фазой и процентом | чтение |
| `get_storage_stats` | История размера основного репозитория одного раздела и его рост за неделю, а также занятое, свободное и общее место на диске или удалённом ресурсе каждого из его репозиториев | чтение |
| `get_size_breakdown` | Какие папки и файлы занимают место в новейшей копии одного контейнера, виртуальной машины или набора папок и сколько из каждого добавила последняя копия | чтение |
| `search_files` | Ищет файлы и папки по имени в копиях всех записей, одного раздела или одной записи (виртуальные машины не просматриваются) и для каждой находки перечисляет все копии, где она есть | чтение |
| `list_anomalies` | Аномалии, которые BombVault заметил в копиях, с фильтрами по состоянию, серьёзности и разделу и со сводкой открытых | чтение |
| `get_anomaly` | Одна из этих находок, с заметкой, оставленной при подтверждении | чтение |
| `start_backup` | Копирует одну запись сейчас | запуск |
| `start_domain_backup` | Копирует каждую защищённую запись одного раздела | запуск |
| `start_backup_everything` | Запускает проход «Создать копию всего» | запуск |
| `cancel_backup` | Отменяет идущую копию, запущенную этим ключом | отмена |

В веб-интерфейсе остаётся следующее: восстановление любого вида (в том числе скачивание, сохранение или импорт дампа базы данных), удаление копий, очистка, разблокировка, проверки и учения, внешняя репликация, настройки, учётные данные и ключи MCP, а также отмена копии, которую запустили расписание, веб-интерфейс или другой ключ. То же относится к подтверждению аномалии и отметке её как ожидаемой, что делается на странице **Аномалии**. Причина в том, что вывод инструментов содержит имена и сообщения об ошибках с вашего сервера, и в любом из них мог быть текст, написанный, чтобы направлять помощника. Помощник, поддавшийся такому тексту, в худшем случае запустит копию в пределах ограничений ниже или отменит ту, которую запустил сам.

Если основной репозиторий записи удалённый (S3, REST, SFTP, rclone), `list_restore_points` обращается к нему, так что вызов может занять время. Внешние копии через MCP перечислить нельзя. `search_files` читает удалённые репозитории, включая внешние копии, только когда об этом просит помощник, потому что это дольше, а некоторые провайдеры берут плату за скачанные данные. Поиск может занять несколько минут, поэтому первый вызов запускает его в фоне, а результат забирает один из следующих вызовов. Что смотрят проверки аномалий, описано в разделе [Аномалии](anomalies.md), а как запись ZFS хранит по одному снимку на набор данных, в разделе [Наборы данных ZFS](zfs-datasets.md#contents).

## Что делает запущенная копия {#starting-backups}

Копия помощника — та же копия, которую запускает веб-интерфейс. Работающий контейнер останавливается, пока его копия не закончится, вместе с контейнерами, которые должны останавливаться с ним. Виртуальная машина с методом корректного выключения выключается и запускается снова. Набор данных ZFS останавливает заданные для него контейнеры, пока делается его снимок. Наборы папок, флешка и конфигурация продолжают работать. После этого BombVault применяет политику хранения и может скопировать во внешний репозиторий. `list_items` сообщает помощнику, что останавливает запись и как долго длилась её последняя копия, а описания инструментов просят его предупредить вас, прежде чем что-либо запускать.

Поскольку копия что-то останавливает и вытесняет старые точки восстановления, запуски через MCP ограничены:

- 12 запущенных копий в час на ключ.
- 15 минут между двумя запусками MCP той же записи, раздела или «Создать копию всего».
- Не больше 4 запусков MCP одной записи за 24 часа.
- **Защита хранения.** Когда раздел хранит фиксированное число точек восстановления (только «хранить последние N», без дневного, недельного или месячного правила, локально или во внешнем месте), каждая новая копия вытесняет самую старую. BombVault тогда отказывает в запуске MCP для записи, у которой все новейшие N-1 успешных копий были запущены через MCP. Так что хотя бы одна точка восстановления, сделанная расписанием или вами, всегда остаётся среди сохранённых. При «хранить последнюю 1» помощник не может скопировать эту запись вообще. Следующая плановая копия снова освобождает место. Годовое правило само по себе считается за «хранить последнюю 1», так как хранит одну точку восстановления за текущий год.

Запуск раздела или «Создать копию всего» пропускает записи, которые задерживает ограничение, и называет их в ответе. Веб-интерфейс и расписание ничем из этого не ограничены. Часовой бюджет живёт в памяти, поэтому перезапуск BombVault его сбрасывает.

Запуски через [API](api.md#errors) и из [Home Assistant](api.md#home-assistant) учитываются в тех же ограничениях на запись, что и запуски через MCP, и в защите хранения.

## Как включить {#switch-on}

1. Откройте **Настройки, Интеграции, Сервер MCP**, нажмите **Выбрать клиент** и выберите свой в окне. Поиск справа вверху находит его по имени. Клиент, которого нет в списке, подключается через **Другой клиент**.
2. В разделе **Ключ** оставьте **Новый ключ** и предложенное имя, то есть имя клиента, или введите такое, которое говорит, где ключ используется, например «Claude Code на ноутбуке». Один ключ на клиента позволяет отозвать один, не трогая остальные. **Существующий ключ** даёт клиенту ключ, который вы создали раньше.
3. Включите **Разрешить запуск копирования** для ключа, который должен уметь запускать копии. Без этого ключ может только читать. Позже это можно изменить в **Подробнее** ключа, и изменение действует при следующем запросе помощника без повторного подключения.
4. Нажмите **Создать ключ**. Ключ показывается один раз. BombVault хранит только его отпечаток и не может показать его снова, поэтому скопируйте его сейчас. Если вы закроете окно, прежде чем клиент воспользуется ключом, карточка продолжает его показывать, пока вы не подтвердите, что скопировали.

Без пароля для входа сам веб-интерфейс открыт всем в вашей сети, и любой, кто может его открыть, может создать и ключ. Карточка об этом говорит. Если вы открываете BombVault под именем, похожим на публичное (например `bombvault.example.com` через обратный прокси), и пароль для входа не задан, ключи с этого адреса создавать и заменять нельзя, чтобы никакая веб-страница в интернете не могла заставить ваш браузер создать ключ. Задайте пароль для входа или откройте BombVault по его IP-адресу или локальному имени вроде `tower` или `tower.local`.

## Ваши ключи и их журнал {#keys}

У каждого ключа своя строка в разделе **Ключи и вошедшие клиенты**. Она показывает имя ключа, может ли он запускать копии или только читать, последние четыре символа ключа, когда он создан или заменён в последний раз и когда им в последний раз пользовался клиент. **Подробнее** открывает окно, где ключ можно переименовать, изменить его разрешение, заменить или отозвать и где видно, сколько вызовов он сделал за сегодня. Отозванный ключ уходит в список отозванных, где его можно удалить окончательно, когда ни один запуск в истории его больше не называет.

Рядом с именем в строке стоит значок клиента, для которого создан ключ. Ключ, созданный через **Другой клиент** или до того, как карточка перечисляла клиентов, показывает вместо этого ключ.

**Журнал** в подробностях ключа показывает, что этот ключ делал, а у отозванного ключа остаётся собственная кнопка **Журнал**. Сначала идут запущенные им копии, каждая с состоянием и ссылкой на этот запуск в журнале активности на панели. Ниже идут его вызовы, новые сверху, с инструментом и тем, чем вызов кончился. Отказ говорит почему: ключ может только читать, защита хранения задержала копию, другая копия уже шла, та же запись, раздел или проход были запущены вне веб-интерфейса несколько минут назад или ключ прислал слишком много запросов. Отмена ссылается на запуск, о котором шла речь.

BombVault хранит записи каждого ключа до 30 дней: новейшие 500 успешных запусков и отмен, а рядом с ними новейшие 200 других вызовов (чтение, отказы и ошибки). Помощник, который всё время опрашивает идущую копию или повторяет отклонённый вызов, не может вытеснить из журнала начало этой копии. Для каждого вызова сохраняются инструмент, исход и запуск, который назвала отмена. То, что прислал помощник, никогда не сохраняется, как и ключ или его отпечаток. Пакет диагностики лишь считает записи, а экспорт настроек их не включает.

## Подключение клиента {#clients}

**Выбрать клиент** открывает окно, где каждый клиент показан плиткой в разделе **На этом компьютере** или **В облаке**, с поиском справа вверху. Плитка открывает настройку клиента в том же окне в три шага: ключ, конфигурация для этого клиента с адресом, по которому вы открыли карточку, кнопкой копирования, местом, где конфигурация хранится, и, с собственным сертификатом BombVault, тем, что клиенту нужно для доверия ему. И ожидание первого вызова клиента. Окно следит за последним использованием ключа и становится зелёным, когда этот вызов приходит.

Настройка не пускает ключ ни в одну командную строку. Там, где клиент может прочитать его из переменной окружения (`BOMBVAULT_MCP_KEY`), маскированного запроса или собственного файла, конфигурация лишь называет его. Там, где у клиента такого способа нет, ключ лежит в его файле конфигурации или настройках, и настройка об этом говорит. Там, где в документации клиента не сказано, как он обращается с незнакомым сертификатом, настройка записывает этот шаг как то, что делать, если клиент отклонит сертификат BombVault.

### Claude Code {#claude-code}

Claude Code обращается к BombVault через `mcp-remote`, которому на этом компьютере нужен Node.js. Сначала сохраните ключ в отдельном текстовом файле одной строкой:

```text
X-API-Key: <your key>
```

Затем один раз выполните в терминале команду с карточки, подставив путь к этому файлу. За сертификатом, которому ваш компьютер доверяет, она выглядит так:

```bash
claude mcp add bombvault --scope user -- npx -y mcp-remote@latest https://bombvault.example.com/mcp --header-file "<path of the file with your key>"
```

С собственным сертификатом BombVault (см. [TLS и сертификаты](#tls)) команда ещё и указывает Node.js скачанный сертификат:

```bash
claude mcp add bombvault --scope user -e "NODE_EXTRA_CA_CERTS=<path of the downloaded bombvault-cert.pem>" -- npx -y mcp-remote@latest https://192.168.1.10:3443/mcp --header-file "<path of the file with your key>"
```

Проверьте подключение командой `/mcp` в Claude Code. `--scope user` делает BombVault доступным во всех ваших проектах. Claude Code хранит только путь к файлу ключа, так что ключ не виден ни в команде и истории вашей оболочки, ни в списке процессов. Держите файл там, где его можете прочитать только вы, и вне любой папки, которую вы коммитите. `@latest` заставляет `npx` взять актуальный `mcp-remote`. Более старый, установленный глобально, использовался бы вместо него, а он не знает `--header-file`.

Не пишите `${BOMBVAULT_MCP_KEY}` в аргументы `mcp-remote` для Claude Code. Claude Code подставляет такую ссылку из собственного окружения, прежде чем запустить `mcp-remote`, так что ключ оказывается в командной строке этого процесса, где его могут прочитать другие программы и пользователи компьютера.

Без Node.js и только за сертификатом, которому ваш компьютер доверяет, Claude Code может подключиться сам. Положите `.mcp.json` в папку проекта:

```json
{
  "mcpServers": {
    "bombvault": {
      "type": "http",
      "url": "https://bombvault.example.com/mcp",
      "headers": {
        "Authorization": "Bearer ${BOMBVAULT_MCP_KEY}"
      }
    }
  }
}
```

Задайте `BOMBVAULT_MCP_KEY` там, где запускается Claude Code, например в `"env"` в `~/.claude/settings.json` или в профиле оболочки, отредактированном в текстовом редакторе, а не набранном в командной строке. Здесь ссылка безопасна, потому что Claude Code не запускает второго процесса, который бы её нёс. Собственный сертификат BombVault так не работает: собственное подключение Claude Code отклоняет его даже при заданном `NODE_EXTRA_CA_CERTS`. Никогда не коммитьте `.mcp.json` с записанным в него ключом.

### Claude Desktop {#claude-desktop}

Claude Desktop обращается к BombVault через `mcp-remote`, которому на этом компьютере нужен Node.js. Сначала сохраните ключ в отдельном текстовом файле одной строкой, как описано для [Claude Code](#claude-code). Откройте файл конфигурации через **Settings, Developer, Edit Config** в Claude Desktop. В Windows он лежит в `%APPDATA%\Claude\claude_desktop_config.json`, в macOS в `~/Library/Application Support/Claude/claude_desktop_config.json`. Добавьте запись с карточки внутрь `"mcpServers"`, рядом с уже существующими серверами, и перезапустите Claude Desktop:

```json
{
  "mcpServers": {
    "bombvault": {
      "command": "npx",
      "args": ["-y", "mcp-remote@latest", "https://192.168.1.10:3443/mcp", "--header-file", "<path of the file with your key>"],
      "env": {
        "NODE_EXTRA_CA_CERTS": "<path of the downloaded bombvault-cert.pem>"
      }
    }
  }
}
```

- `NODE_EXTRA_CA_CERTS` нужен только для собственного сертификата BombVault. За сертификатом, которому ваш компьютер уже доверяет, его не указывайте.
- `--allow-http` добавляется только для обычного адреса `http://`.
- В Windows пишите пути с прямыми слэшами, например `C:/Users/sam/bombvault-key.txt`, потому что одиночный обратный слэш в JSON недопустим. Путь к файлу ключа не должен содержать пробелов: Claude Desktop в Windows передаёт путь с пробелом в `npx` двумя частями.
- Конфигурация называет только файл ключа, так что ключ не виден ни в ней, ни в списке процессов. Держите файл там, где его можете прочитать только вы.

### Облачные клиенты {#cloud-clients}

ChatGPT, Claude на claude.ai, Grok и Le Chat обращаются к BombVault с серверов своих поставщиков, поэтому BombVault должен быть доступен из интернета с публично доверенным сертификатом, например за обратным прокси. Le Chat самоподписанные отклоняет. Вход на прокси может защищать веб-интерфейс, но `/mcp` должен проходить к BombVault без него: эти службы не умеют входить в прокси, а BombVault проверяет их ключ или токен сам. Grok и Le Chat присылают фиксированный ключ, и их кнопки настраивают их, как остальных. ChatGPT и Claude на claude.ai в большинстве организаций подключаются только через вход с OAuth, описанный далее.

### Вход через OAuth {#oauth}

Для клиента, который не принимает ключ, BombVault сам является сервером авторизации OAuth. Клиент регистрируется сам, отправляет вас на страницу BombVault, и там вы входите с паролем для входа (и вторым фактором, если вы его настроили) и разрешаете ему доступ. Затем клиент получает токен, который работает только для конечной точки MCP этого BombVault, и сам его обновляет.

1. Задайте пароль для входа в **Настройки, Безопасность**. Без него BombVault вообще не предлагает вход, потому что спрашивать согласие было бы некого.
2. Сделайте BombVault доступным из интернета по https с сертификатом, которому доверяют браузеры, обычно через обратный прокси. Клиент обращается к `/mcp`, `/oauth/` и `/.well-known/` со своих серверов, так что прокси с собственным входом должен пропускать эти три пути к BombVault. Страница согласия `/oauth/authorize` открывается в вашем браузере и может оставаться за входом на прокси. Назовите прокси и в `TRUSTED_PROXY` (см. [Конфигурация](configuration.md)). BombVault ограничивает регистрации клиентов с одного адреса, и без этого каждый клиент кажется пришедшим с прокси.
3. В карточке MCP включите **Вход через OAuth** и введите **Публичный адрес**: адрес https без пути, например `https://backup.example.com`. Каждый токен привязан к этому адресу, так что после его смены каждому клиенту нужно войти заново.
4. Выберите ChatGPT или Claude в **Выбрать клиент**. Окно показывает **URL коннектора**, то есть публичный адрес плюс `/mcp`, и где его вводить в этом клиенте. В ChatGPT включите Developer mode в **Settings, Apps & Connectors, Advanced settings**, выберите **Create**, вставьте URL коннектора как URL сервера MCP и выберите OAuth как аутентификацию. На claude.ai откройте **Settings, Connectors, Add custom connector**, вставьте URL коннектора, оставьте ID клиента и секрет OAuth пустыми и выберите **Connect**.
5. Клиент открывает страницу согласия. Она показывает, кто просит, куда вас вернёт ваш ответ, и переключатель **Разрешить запуск копирования**, который сначала выключен. Выберите **Разрешить** или **Отказать**.

Каждый клиент, который вошёл, получает в том же списке свою строку со своим значком. Его **Подробнее** содержит журнал, **Отозвать** и **Разрешить запуск копирования**, и на него действуют те же ограничения, что и на ключ. Отзыв вступает в силу сразу. Когда тот же клиент входит снова, его новое разрешение заменяет прежнее, а разрешение, которым никто не пользовался 30 дней, истекает. Одновременно могут быть вошедшими до 10 клиентов, сверх 10 ключей.

Страница согласия принимает запрос только от зарегистрированного клиента, который точно называет один из своих зарегистрированных адресов возврата: https или адрес loopback на любом порту для клиента на вашем собственном компьютере. Принимается только поток кода авторизации с PKCE (S256), а ваш ответ привязан к вашему сеансу, так что никакой другой сайт не может отправить его за вас. Токены доступа живут час. Токен обновления заменяется при каждом использовании, а тот, что появляется снова после этого, отзывает разрешение, потому что копия есть у кого-то другого. Клиент, который повторяет своё последнее обновление в течение 30 секунд, потому что ответ до него не дошёл, получает новые токены. BombVault не загружает документы метаданных клиентов из интернета, поэтому клиенты регистрируются через динамическую регистрацию клиентов.

### Другие клиенты {#other-clients}

Подходит любой клиент, который понимает Streamable HTTP:

- URL: адрес веб-интерфейса плюс `/mcp`, например `https://192.168.1.10:3443/mcp`.
- Ключ в `Authorization: Bearer <key>` или в `X-API-Key: <key>`. Если отправлены оба, они должны нести один и тот же ключ.
- `POST` с `Content-Type: application/json` и `Accept: application/json, text/event-stream`.
- Одно сообщение JSON-RPC на запрос. Пакеты отклоняются.
- Версии протокола 2026-07-28, 2025-11-25, 2025-06-18 и 2025-03-26.

## TLS и сертификаты {#tls}

BombVault отдаёт HTTPS с сертификатом, который сделал сам, и сначала этот сертификат называет только `localhost`, `127.0.0.1` и `::1`. Claude Code и `mcp-remote` отклоняют его на адресе в локальной сети. Способы это обойти в порядке, который подходит большинству установок Unraid:

1. **Добавьте адрес в карточке MCP.** Когда карточка открыта по HTTPS на адресе, которого в сертификате нет, она об этом говорит и предлагает **Добавить этот адрес в сертификат**. BombVault выпускает сертификат заново с добавленным адресом (браузер предупредит ещё раз, как в первый раз). Затем нажмите **Скачать сертификат**. Фрагменты задают `NODE_EXTRA_CA_CERTS` скачанным файлом, так что клиент доверяет именно этому сертификату. Это также означает, что каждый клиент, настроенный по более раннему скачиванию, перестаёт подключаться, как только сертификат выпущен заново, на этом компьютере и на любом другом, пока не получит новый файл.
2. **Обратный прокси с доверенным сертификатом** (Nginx Proxy Manager, SWAG, Caddy, Traefik). Клиент тогда видит сертификат прокси и ему ничего дополнительного не нужно, а карточка не предупреждает о собственном сертификате BombVault.
3. **Tailscale.** `tailscale serve` перед контейнером или интеграция Tailscale в Unraid даёт имя `ts.net` с доверенным сертификатом.
4. **`HTTP_ONLY=true`**, только за прокси, который завершает TLS, или в сети, которой вы полностью доверяете. Он переключает весь веб-интерфейс на обычный HTTP, требует изменения настроек контейнера и отправляет ключ незашифрованным.

Никогда не задавайте `NODE_TLS_REJECT_UNAUTHORIZED=0`. Это отключает проверку сертификатов для всего, с чем разговаривает этот процесс Node.js.

Обратный прокси должен пропускать заголовок `Authorization` (или `X-API-Key`), что прокси делают, если им не сказано иное, и не должен буферизовать или переписывать `/mcp`. Блок location для Nginx или Nginx Proxy Manager, который заодно проверяет сертификат BombVault:

```nginx
location /mcp {
    proxy_pass https://192.168.1.10:3443;
    proxy_ssl_verify on;
    proxy_ssl_trusted_certificate /data/bombvault-cert.pem;
    proxy_ssl_name localhost;
    proxy_http_version 1.1;
    proxy_buffering off;
    proxy_set_header Host $host;
}
```

За прокси каждый запрос несёт адрес прокси. Пять неверных ключей от одного неправильно настроенного клиента тогда на минуту блокируют всех клиентов MCP за этим прокси. Назовите прокси в `TRUSTED_PROXY` (см. [Конфигурация](configuration.md)), чтобы считать по клиентам.

## Модель безопасности {#security}

- Без активного ключа и при выключенном входе через OAuth `/mcp` отвечает `404`.
- Вход через OAuth предлагается, только пока задан пароль для входа. Токены, коды и секреты клиентов хранятся только как отпечатки, а токен работает только для адреса, для которого был выдан.
- Клиент может зарегистрироваться не более 10 раз в час с одного адреса, а BombVault хранит не более 100 зарегистрированных клиентов, в которые никто не входил, каждого по одному дню. Неверные коды и токены обновления считаются в той же блокировке, что и неверные ключи.
- Разрешения ведут себя как ключи, когда восстанавливается копия конфигурации или меняется `APP_KEY`: после восстановления каждому клиенту нужно войти заново.
- Никаких исключённых адресов. Запросам с `localhost`, хоста Unraid, обратного прокси или `tailscale serve` нужен ключ, как и всем остальным, в том числе когда у веб-интерфейса нет пароля для входа.
- Ключи хранятся только как отпечатки, показываются один раз, и их можно переименовывать, заменять и отзывать. До 10 активных ключей, у каждого свой переключатель **Разрешить запуск копирования**.
- Каждое создание, замена, изменение разрешения и отзыв отправляет уведомление по вашим каналам уведомлений с адресом, с которого оно пришло, если только уведомления не выключены.
- 5 неверных ключей в минуту с одного адреса, затем `429`. 120 запросов в минуту и 12 запущенных копий в час на ключ, плюс перерыв и защита хранения выше.
- Запросы со страницы браузера на другом источнике (origin) отклоняются.
- Ключи нельзя создавать с имени хоста, похожего на публичное, пока не задан пароль для входа.
- Каждая копия, которую запускает помощник, и вызванные ею очистка и внешние запуски помечаются «через MCP» с именем ключа в журнале активности, в панели ошибок и в уведомлении о копии.
- Каждый вызов инструмента записывается в журнал контейнера с идентификатором ключа и его последними четырьмя символами (никогда не с именем) и считается в `/metrics` (`bombvault_mcp_requests_total`, `bombvault_mcp_tool_calls_total`, `bombvault_mcp_active_keys`).
- Восстановление копии конфигурации отзывает все ключи, потому что восстановленная база данных могла бы содержать ключи, которые вы отозвали после её сохранения. После этого создайте новые ключи.
- Ключ перестаёт работать, когда меняется `APP_KEY` (переустановка или восстановление в другой контейнер). Карточка это обнаруживает и помечает ключ, а **Заменить ключ** снова даёт ему рабочий секрет.
- Относитесь к ключу как к паролю. Клиент, который не может прочитать ключ из переменной окружения, запроса или файла ключа, хранит его открытым текстом в своей конфигурации или настройках, и его настройка об этом говорит. Предпочитайте ключ только для чтения на компьютере, которому вы доверяете меньше.

## Что покидает сервер {#privacy}

Всё, что читает помощник, уходит к поставщику ИИ за ним: названия записей, расписания, история запусков с сообщениями об ошибках, идентификаторы и время точек восстановления, названия движков баз данных и размеры дампов, текущая активность, цифры хранилища, охват и состояние. Поиск файлов отправляет и найденные файлы: их имена, размеры и пути внутри копии. BombVault удаляет пути хоста, расположения репозиториев, имена хостов, учётные данные, команды хуков и ключи, прежде чем что-либо уйдёт.

## Устранение неполадок {#troubleshooting}

| Что вы видите | Что это значит |
|---|---|
| `404` | Нет активного ключа, а вход через OAuth выключен, или неверный путь вроде `/api/mcp`. Конечная точка — `/mcp`. |
| `401` | Ключ отсутствует, набран с ошибкой, отозван или заменён. Прокси может отбрасывать заголовок `Authorization` (попробуйте `X-API-Key`). Если карточка помечает ключ как больше не действительный, `APP_KEY` изменился: замените ключ. |
| `403` | Запрос пришёл со страницы браузера на другом источнике (origin). Используйте клиент для рабочего стола или командной строки. |
| `405` на GET | Это нормально. Конечная точка принимает только `POST`. |
| `400` "Accept must contain both 'application/json' and 'text/event-stream'" | Клиент слишком старый для Streamable HTTP. Обновите его. |
| `400` "batch requests are not accepted" | Клиент присылает пакеты JSON-RPC. Присылайте по одному сообщению на запрос. |
| `429` | Слишком много неверных ключей с этого адреса или больше 120 запросов в минуту с одним ключом. Подождите минуту и проверьте, не застрял ли помощник в цикле. |
| Ошибки «certificate», «self-signed» или «unable to verify» | Клиент не доверяет сертификату BombVault. См. [TLS и сертификаты](#tls). |
| `busy` | Другая копия или задача обслуживания держит этот раздел. Повторите, когда она закончится. |
| `cooldown` | Эта запись, раздел или «Создать копию всего» были запущены вне веб-интерфейса меньше 15 минут назад. |
| `retention_guard` | Ещё одна копия через MCP оставила бы в окне «хранить последние N» только точки восстановления, сделанные через MCP, или запись уже получила 4 копии через MCP за последние 24 часа, включая неудавшиеся и отменённые. В первом случае следующая плановая копия освобождает место, во втором запись снова свободна через 24 часа после самой старой из этих копий. В любом случае вы можете запустить её в веб-интерфейсе. |
| `rate_limited` | Ключ израсходовал свои 12 запусков на этот час. |
| `not_permitted` при запуске | Ключ только для чтения. Включите **Разрешить запуск копирования** в карточке. Повторное подключение не нужно. При отмене это означает, что запуск начал не этот ключ. |
| `domain_off` | Этот раздел выключен в **Настройки, Общие**. |
| `not_found` | Запись не защищена BombVault. Сначала добавьте её в веб-интерфейсе. MCP никогда не создаёт конфигурацию. |
| Клиент не находит сервер авторизации | Вход через OAuth выключен, пароль для входа не задан или прокси не пропускает `/.well-known/` к BombVault. |
| Страница согласия сообщает, что адрес возврата не зарегистрирован | Клиент прислал адрес возврата, который не зарегистрировал. Удалите коннектор в клиенте и добавьте его снова. |
| Вошедший клиент получает `401` | Его разрешение отозвано, истекло после 30 дней без использования или изменился публичный адрес. Клиент входит заново. |

Не задавайте переменную окружения `MCPGODEBUG` на контейнере. Она меняет поведение библиотеки MCP, а некорректное значение останавливает BombVault при запуске ещё до записи единственной строки журнала.
