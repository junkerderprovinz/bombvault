# 功能

BombVault 备份的一切都在同一个列表里，每个条目都有自己的页面，还原从同一个页面开始，设置则是一块块磁贴。无需开启什么高级模式；不常用的功能有自己的卡片或窗口。本页汇总了完整的功能集。

## 备份范围

![备份列表：每个条目都带有以条带显示的最近运行、一个状态和它的操作。](assets/screenshots/containers.png)

*备份列表：每个条目都带有以条带显示的最近运行、一个状态和它的操作。*

| 分区 | 保存的内容 |
|---|---|
| **容器** | Appdata 目录以及容器定义（镜像、环境变量、端口、标签、卷）。默认为整个 appdata 目录；容器**设置**标签页中的**备份文件夹**卡片会精确勾选备份涵盖哪些文件夹，并实时显示路径数量、你排除的内容列表，以及一个**跳过缓存文件夹（CACHEDIR.TAG）**开关。 |
| **虚拟机** | 虚拟机磁盘映像、XML 定义和 UEFI NVRAM（正常关机或在线快照，通过 SSH）。如果无法创建快照，在线快照会自动回退为正常关机备份，因此虚拟机备份不会直接报错了事。开启**仅变更的块**后，带 qcow2 磁盘的运行中虚拟机会通过 libvirt 检查点读取，所以一次备份只读取自上次以来写入的块，而每个备份仍能单独还原整块磁盘。位于 ZFS zvol 上的磁盘通过同一条 SSH 链路用 `zfs send` 以流方式传输，因此磁盘是 zvol 的虚拟机仍作为一台虚拟机备份。当分区 XML 写明了直通 vTPM 的路径时，它的状态会保存在 NVRAM 旁边。TrueNAS 为 Windows 11 客户机设置的模拟 vTPM 不公开该路径，所以请把这类客户机的恢复密钥放在手边。参见[虚拟机备份指南](https://github.com/junkerderprovinz/bombvault/blob/main/docs/vm-backup-ssh-setup.md)。 |
| **闪存** | 整个 USB 闪存（`/boot`）：操作系统、许可证、阵列配置、共享、网络和插件配置。还原是下载一个 `.zip`，绝不会覆盖正在运行的闪存。 |
| **自我备份** | BombVault 自身的 `/config`（设置数据库、各目标的登录信息、libvirt SSH 密钥对），用 SQLite `VACUUM INTO` 做快照，因此 WAL 模式的数据库不会在写入中途被采集。它通过应急向导找回，该向导会重启 BombVault，所以运行中的数据库不会在打开的句柄下被覆盖。 |
| **文件夹** | 文件夹集：服务器上的任意文件夹（共享、你的文档、照片库），每个都可选配排除模式。备份页面上的**添加**会列出它找到的共享，并接受任何其他文件夹。文件夹集拥有其他分区的全部功能：计划、保留、异地副本、检查和还原演练。 |
| **ZFS 数据集** | 一个数据集及其下的所有数据集，从一个 ZFS 快照读取，让它们都来自同一时刻，并用 restic 像文件夹一样存储：去重、可浏览、可还原单个文件。新的子数据集会自动加入，个别子数据集可以排除，读取不了的子数据集会被跳过并点名。还可以选择只在快照的瞬间停止容器或运行一条命令。卷不包含在内：虚拟机的卷随该虚拟机一起备份，没有虚拟机的卷暂时不备份。ZFS 条目还可以在第二台 ZFS 服务器上保留块级一致的副本。参见 [ZFS 数据集](zfs-datasets.md)。 |

## 备份与条目页面 {#backups}

- **一个列表。** 容器、虚拟机、文件夹集、闪存、ZFS 数据集和自我备份都在**备份**下的同一个列表里。上方的磁贴用来选择类型，**筛选**、**排序**和**搜索**可缩小范围。排序可按名称、状态、上次备份、大小或计划，双向均可，搜索能按名称、镜像或 IP 找到容器。
- **以条带显示最近运行。** 一行用小方块显示它最近的十四次运行和一个状态。关于它的其他一切都在名称旁的信息气泡里，鼠标停在这一行上时，它也显示同样的文字。
- **像文件管理器一样选择。** Ctrl+点击、Shift+点击和 Ctrl+A 可选中多行，在手机上长按即可，**更多**下的**选择**会开始选择。选中的行用对勾代替它的图标，每一行都有右键菜单。选中的内容可以备份，或在计划中暂停与恢复。多个条目在恢复页面上一起还原。
- **添加**会打开一个窗口，用于 BombVault 无法猜到的内容：文件夹或 ZFS 数据集。容器、虚拟机和闪存会自行出现。在没有 Unraid 的主机上，该窗口会提供**系统配置**，这是一份起步的 `/etc` 文件夹集，保存前由你审阅。
- **不备份**是有意把某个条目排除在外。之后它不再算作未受保护，而**取消排除**会把它带回来。
- 备份页面上的**更多**包含**发现备份**和**还原堆栈**：前者根据各目标所存的内容重建条目（例如全新安装之后），后者用于 Compose 项目。
- **每个条目都有自己的页面**，有一个写出它的状态并放着它的操作的标题，图标左侧有一个通向列表的返回按钮，还有三个标签页：
    - **备份**列出备份，每天一条柱，以及保存它们的目标和数据库转储。
    - **设置**包含计划和目标、仓库、备份文件夹、排除模式、要停止的其他容器、前后命令、数据库转储和曾用名。在条目有自己的选择之前，计划和目标沿用所属分区的默认值。
    - **验证**显示检查、按文件夹统计的大小、该条目的异常监控及其最近运行。
- **标记与比较。** 备份可以带你自己的标签，**与另一个备份比较**会列出两者之间新增、消失或变化的文件。虚拟机则比较磁盘映像，并说明有多少不同。
- **导出**把一个备份、一个条目的所有备份，或容器或虚拟机此刻的样子，以 tar、zip 或独立的 restic 仓库形式写入服务器上的导出文件夹。

## 还原

![还原页面：选择一个分区，搜索条目并选择一份备份。](assets/screenshots/recovery.png)

*还原页面：选择一个分区，搜索条目并选择一份备份。*

- **一个页面。** **恢复**把各分区列为磁贴。搜索你想找回的内容，并从最新在顶部的列表中选择一份备份；推荐的那份有标记，出现异常之后则是异常之前的最后一份。**打开条目**通向条目的页面，进行中的还原显示在**正在运行**下。
- **所有类型共用一个窗口。** 它分步询问：哪份**备份**（推荐的已预先选中）、哪个**来源**（本地最快）、**内容**（全部，或你挑选的文件和文件夹）以及**目标位置**。一幅示意图显示你选择的目标，而**会发生什么**在你开始前用文字说明。
- **一次多个。** 在恢复页面上，Ctrl+点击、Shift+点击、Ctrl+A、长按或**选择**可选中条目，选中的条目用对勾代替它的图标，**还原**会为所有条目打开同一个窗口。每个条目取自己的最新备份，或取你为所有条目选定的同一时刻的最新备份，并放在原件旁边或替换原件。还原依次进行，每一行显示它自己的还原结果。闪存以 ZIP 形式下载。ZFS 数据集和自我备份则逐个还原。
- **默认放在原件旁边。** 容器会作为名为 `<name>-restored` 的第二个容器回来，使用自己的端口，原件继续运行。虚拟机的磁盘和 NVRAM 落在原件旁名为 `<folder>-restored` 的文件夹里，不会产生第二台虚拟机。文件夹集作为 `<path>-restored` 回来。在你把它加入计划之前，副本在备份中列为已排除。
- **替换原件会先备份。** 默认开启的**先备份当前状态**会让 BombVault 在替换之前先备份现有内容，你因此可以回退。如果那次备份失败，还原不会开始。替换时会要求你输入条目的名称。
- **还原到文件夹**只写出文件，供浏览。ZFS 数据集也可以**到新数据集**，闪存则以**下载为 ZIP** 的方式回来。
- **容器会被自动重装。** 容器定义会对 Docker API 重新执行，因此容器会原样重新出现在 Unraid 的 Docker 标签页中。
- **GPU、限制和链接都会回来。** 恢复的容器会取回它的资源限制、日志驱动、DNS 设置、旧式链接以及 GPU 或运行时（`--gpus`、`--runtime=nvidia`）。在缺少该 GPU 驱动或运行时的主机上，恢复会说明这一点并提供 **不带 GPU 和运行时恢复**，恢复多个容器或一个 stack 之后也一样。指向不存在的容器，或在恢复的容器启动时已停止的容器的链接会被去掉，运行历史会注明。
- **虚拟机会自动重建。** XML 会通过 SSH 重新导入，使虚拟机重新出现在虚拟机管理器中，磁盘和 UEFI NVRAM 重新挂接，即使虚拟机已被删除也是如此。
- **闪存还原是一个 `.zip` 下载。** 它会以 `flash-<id>.zip` 流式传输到你的浏览器，可直接放入 Unraid USB 创建器。运行中的 `/boot` 绝不会被触碰。
- **一次一个插件。** 闪存还原窗口会列出每份闪存备份中的插件及其版本和大小，并把单个插件放回运行中的闪存：它的 `.plg` 文件、`config/plugins` 下的文件夹以及备份中保存的包文件。闪存上的其他内容都不变。Unraid 会在下次启动时安装该插件，或在**插件、安装插件**下立即安装。
- **计划的闪存 zip 导出。** 每次闪存备份之后，可选择把备份写成普通 `.zip`，放到你选择的文件夹（一个被覆盖的 `flash-latest.zip`，或滚动的历史）。它是闪存条目设置标签页上的 **Flash ZIP 导出**卡片。把它指向 Syncthing 或 rclone 文件夹，你的可启动 USB 备份就会自动离开服务器。
- **预检冲突检查。** 在停止或移除任何东西之前，还原会验证容器的静态 IP 和已发布的主机端口是否空闲，若被占用则以清晰的消息中止，而不是留下一个只完成一半的还原。
- **还原前的检查。** 窗口首先检查仓库有响应、保存的密钥能打开它、还原点存在，以及目标有足够空间容纳还原要写入的内容。检查失败期间“开始”保持锁定，按钮里的 (i) 会说明是哪一项。
- **还原会改变什么。** 在你确认之前，窗口会显示还原相对于现有内容要做什么：新增、替换和不变的文件（按需可看列表），以及目标上不在备份中且会原样保留的文件。对于容器和虚拟机，它还会把还原重建的设置与运行中的比较：镜像和标签、端口、变量名和卷，或内存、vCPU、磁盘和网络。restic 以试运行的方式根据大小和修改时间算出这些，不读取文件；非常大的目录树会在 30 秒后停止并说明。堆栈还原会检查并规划每个成员，并点名阻碍它的那一个。
- **共享文件夹。** 原位恢复会列出所有其他容器（无论是否在运行），只要它们的绑定挂载触及恢复要写入的文件夹，例如“nextcloud-db 也在使用此路径”。这只是提醒，不会阻止恢复。
- **ZFS 数据集还原。** 把一个条目的单个数据集还原到原位（在一个会保留到你删除为止的 ZFS 安全快照之后）、到文件夹、到新数据集，或只还原你挑选的文件，也可以把一份备份的所有数据集还原到文件夹。数据集绝不会被回滚或替换。
- **还原保留运行状态。** 备份时正在运行的容器或虚拟机会以运行状态回来；已停止的保持停止。打开**之后保持停止**可以只重建而不启动。
- **还原整个堆栈。** 来自同一个 Docker Compose 项目、至少有两个已备份成员的容器构成一个堆栈。备份页面**更多**下的**还原堆栈**会用每个成员的最新备份重建它们，然后可选择按 `depends_on` 顺序启动。
- **实时进度、取消和忙碌反馈。** 长时间的还原会显示实时百分比条，并可通过按类型区分的确认来取消。被取消的还原记录为*已取消*，而不是失败。窗口可以关闭；进度也显示在还原下。
- **应急向导。** 用于已经消失或重新设置过的服务器，使用恢复工具包、通过组或使用输入的密钥。参见[异地与恢复](offsite-recovery.md#emergency)。
- **从旧的备份文件夹。** 只读会话用该实例的恢复工具包或输入的 `APP_KEY` 打开另一个 BombVault 的仓库，让你无需触碰自己的设置，就能把容器从服务器 A 拉到服务器 B。参见[异地与恢复](offsite-recovery.md#restore-from-another-bombvault-repo)。
- **ZFS 属性也会回来。** 每次 ZFS 备份都会保存每个数据集在本地设置的属性，例如压缩、记录大小、配额和大小写敏感。还原到新数据集时会用这些属性创建它；还原到现有数据集时会列出这些属性，只在你要求时才设置。参见 [ZFS 数据集](zfs-datasets.md#new-dataset)。
- **从 Appdata.Backup 插件导入。** 在还原页面的**其他来源**下，把 BombVault 指向该插件的备份文件夹。每个容器归档都会成为该容器的一个还原点，日期为插件创建它的时间。之前导入过的归档会被跳过，归档本身只被读取。容器需要先在 BombVault 中有一份备份，这样还原才有它的定义。保留策略不会动导入的还原点，所以不再需要时请自己删除。

## 存储与计划

- 通过 restic 进行增量、去重的备份，因此即使是大型虚拟机磁盘也不会让仓库膨胀。
- **目标。** 本地文件夹和异地位置排在**目标**页面的同一个列表里，你可以从它的设置磁贴打开，或把它固定到侧边栏。这台服务器上各分区备份到的文件夹叫作**本地**，与放置按钮上的叫法一致。每个目标都有自己的页面，包含连接、凭据、删除保护、复制设置、保留与按分区划分的规则，以及一个显示它有多满、按最近几周增速何时写满的容器图。参见[目标](offsite-recovery.md#destinations)。
- **存储类型：** 本地路径，通过 rclone、无需主机挂载的 SMB 共享和 WebDAV 服务器（Nextcloud、ownCloud、SharePoint），NFS（在 Unraid 上挂载导出并当作本地文件夹使用），无需 rclone 的原生 restic 后端（`s3:...`、`rest:http://host:8000/repo`、`sftp:user@host:/repo`），或经 `rclone:<remote>:<bucket>/path` 使用的任意 rclone 远程。所有凭据都加密存储。
- **SSH 目标的远端无需安装任何东西。** `sftp:` 只需要一个 SSH 服务器，所以一台什么都没装的树莓派（没有 Docker，没有 restic）就能充当异地目标。主机密钥在首次连接时自动固定。
- **用一幅图呈现 3-2-1。** **按分区划分的目标**卡片画出哪个分区备份到了哪里。从分区到目标的每条线对每个分区都是一个开关，**本地**也包括在内，点一下就会立即切换。**图 / 开关**则以普通按钮给出同样的内容。只有异地目标的分区会直接备份到它们，进入 BombVault 自己在那里选择的仓库，每条线都关闭的分区显示**未备份**。当条目备份到其所属分区之外的地方时，流程图会说明有多少个，例如**2 个条目不同**，并带你过去。闪存、ZFS 数据集和自我备份先备份到各自的本地文件夹，再从那份备份复制到异地。它们通向**本地**的线也可以关闭，关闭后它们的备份直接送到各自的异地目标；有副本却没有任何目标的 ZFS 条目只发送它的副本。
- **异地副本（本地 + 远程）。** 保留快速的本地备份，再添加一个或多个异地目标，用 `restic copy` 尽力而为地复制（异地的小故障绝不会让本地备份失败）。一次复制只传输目标尚没有的数据包。每个目标的**复制**卡片设定**复制时机**（**每次备份之后**或自己的计划）及其带宽，分区也可以在**设置、计划**下按自己的计划复制。
- **每个分区多个目标。** 每个分区可以同时复制到多个异地目标。目标的**按分区划分的规则**让某个分区在那里拥有自己的保留、压缩或仓库，而登录、凭据、带宽和时机来自目标本身。
- **迁移分区的历史。** 目标上的**移动**会把某个分区的副本连同全部历史带到另一个目标。旧位置保留一切；BombVault 不会在那里删除任何东西。
- **命名仓库。** **设置、目标**下的**仓库**卡片把你的备份位置一次性写下来，可以是本地路径，也可以是带自己凭据集的任意 restic 远程，供选作条目的位置。一行会显示有多少条目指向它，被条目或默认值使用的仓库不能被移动或删除，因为 BombVault 绝不会移动已经写好的备份。
- **多套凭据。** 共享云凭据默认适用于各处，但任何目标都可以改用命名的凭据集（**设置、目标**下的**附加凭据集**，或目标页面上的**凭据**），因此 Hetzner S3 存储桶和本地 Garage 服务器可以并行运行，各用各的密钥。
- **每个条目的存放位置。** 条目设置标签页上的**计划和目标**卡片有一排按钮，**本地**以及每个异地目标各一个，点亮的会接收它的备份。已经放在 NAS 上的共享不必再多送一份到 B2。遵循所属分区的条目会在分区的位置更改时跟着走，它离开的位置显示为**仅旧备份**，仍然可以从那里恢复。在条目上选择的位置从第一次备份起就固定，副本可以随时更改，卡片还会说明有多少个地点保存着该条目以及 3-2-1 是否满足。**遵循默认**会先询问，并说明这会舍弃或上传什么。参见[每个条目的存放位置](offsite-recovery.md#placement)。
- **手动备份顺序。** **设置、计划**下的**顺序**卡片设定容器和虚拟机备份的精确顺序。计划运行和全部备份会遵循它；任何未排序的条目保持最逾期优先的顺序，单次备份不变。
- **以时间线呈现的保留。** 每个目标按**保留多久**保留备份：**短**、**均衡**、**长**，或针对最近备份、天、周、月和年的**自定义值**，自动清理。时间线显示规则保留了哪些备份。**减少保留前先询问**会在更短的规则要删除仅有一份副本在那里的较旧备份之前先询问。分区可以在**按分区划分的规则**下于某个目标保留自己的值。
- **按仓库压缩：** 关闭、自动（restic 的默认）或最大，在每个目标上设置，对某个分区则在它那里的规则下设置。备份、异地复制和清理都按它写入，恢复工具包会写明它，所以原生 restic 可以继续以同样的方式写入。
- **计划读起来像句子**，例如*每周日 04:00*，并从这句话来编辑。**设置、计划**包含全部：带有周一到周日每次计划运行的**一周**带、带一条前置命令和一条后置命令的**全部备份**、**按分区的计划**、**按分区的异地副本**以及**已计划的条目**。**每 N 天**也适用于还原演练、篡改测试和每周摘要。
- **有自己计划的分区会离开全部备份。** **按分区的计划**下的**例外**按钮给某个分区自己的计划，该分区随后在自己的时间运行，不会在全部备份中再跑一次，因此不会有东西被备份两次。**立即备份全部**仍会包含每个已开启的分区。开启**按条目的独立计划**后，单个容器、虚拟机、文件夹集或 ZFS 数据集可以在自己的页面上获得独立计划，它随后也会离开全部备份。
- **备份成功后更新容器。** **设置、计划、备份后的更新**下的一个开关，默认关闭，只在前面的备份完成后才拉取新镜像。单个容器可以在自己的页面上另行设置。
- **等待应用空闲。** 容器可以让它的计划备份在应用繁忙时等待，最多等你设定的小时数，并在应用空闲时立刻开始。媒体服务器在不串流时算空闲，其他任何容器则要它的 CPU 和流量在几分钟内都低于**设置、计划**下**备份前空闲**卡片中的限值（在主机网络上只计 CPU）。等待中的备份会在活动日志和容器上显示原因和截止时间。它不持有任何锁，所以其他容器照常进行。手动备份从不等待。同一次运行中到期的 compose 堆栈成员一起等待，重启后等待会带着截止时间继续。关闭这些容器会放弃所有等待中的备份，关闭它们的计划会放弃其运行所拦下的那些。缩短小时数会缩短已经开始的等待。
- **异地带宽限制。** 限制 restic 的上传/下载速率，以免复制占满你的 WAN，设置在**设置、目标**下的**异地带宽**卡片中，也可在每个目标自己的**复制**卡片中按目标设置。
- **串流优先。** 当 Plex、Jellyfin 或 Emby 之类的媒体服务器在串流时，异地复制会以较低的限值上传，并在串流结束几分钟后恢复正常限值。BombVault 从 Docker 读取媒体服务器的出站流量。REST、S3、B2、Azure、Google Cloud、Swift 以及基于 HTTP 的 rclone 会在复制中途放慢；SFTP 以及本地或已挂载的文件夹则在下一个复制步骤采用较低限值。主机网络上的媒体服务器无法测量。它就是目标页面上的**串流**卡片。
- **冷存储和归档存储类别（S3）。** 对于 S3 目标，你可以选择存储类别，仅限可读取还原的层级（Standard、Standard-IA、One Zone-IA、Intelligent-Tiering、Glacier Instant Retrieval），这样归档定价绝不会悄悄破坏还原。需要先异步解冻的深度归档层级（Glacier Flexible、Deep Archive）被排除在外，因为 restic 无法从中读取。仅限原生 S3 后端；rclone 远程在 rclone 配置中设置其类别。
- **备份文件夹保持可离机复制。** 每次备份后 BombVault 会将本地仓库树放宽到目录 `0755` / 文件 `0644`（仓库是加密的，因此不会暴露任何东西），这样通过 SMB 的非 root 同步用户不会被拒之门外。恢复定义存放在每个仓库内部，因此被复制的仓库文件夹是完全自包含的。

## 洞察、验证与监控

- **概览。** 它以一个状态头和四张卡片开始：**需要处理**、**保护状态**、带有各目标何时写满预测的**目标**，以及带有运行记录和日志的**历史**。头部的圆环显示有多少受到保护，备份运行时会变成带有各站点的进度环。更多卡片在**自定义**下等候：**异常**、**未备份**、**日历**、**存储**、**概览**、**统计**和**主机集成**。每张卡片都可以移动、调整大小和隐藏，布局保存在浏览器中。
- **各处统一计数。** 每张卡片都以同样的方式统计已开启分区的条目。不在计划内的条目不算受保护，无论它最近一次备份有多新。
- **从条目暂停。** **暂停计划**把条目从计划和全部备份中拿掉，**恢复计划**把它带回来。它设置的是与条目设置标签页上的**在计划中**相同的开关，所以两者始终一致。暂停的条目带有灰色的**计划已暂停**徽章，**立即备份**仍然可用。
- **保护状态。** 每个分区有四项检查：本服务器上的当前备份、异地副本、那里的删除保护，以及从那里做的试还原。逾期的备份会变红而不是藏在日志里，点一下分区就会显示详情。
- **日历。** 最近 90 天，每天一个方块，显示当天的备份结果。点一下某一天，会在历史下的日志中显示它的行。
- **各处显示运行耗时。** 每次运行读作 `开始，结束（时长）`，每个条目在其验证标签页上都有自己的**最近运行**列表。
- **仓库大小与去重趋势。** **存储**卡片显示每个分区占用多少，以及数据去重得有多好。
- **还原验证演练。** BombVault 定期证明你的备份可以还原（`restic check --read-data-subset`，有限度），在**设置、验证、自动检查**下设置。同一磁贴上的**检查备份**卡片按分区显示结果，并在**更多**下放着**解锁**和**清理**。
- **首次备份后的还原检查。** 条目的首次备份完成后，BombVault 会把其中一个样本（最多 100 个文件和 256 MiB）还原到还原文件夹下的临时文件夹，让 restic 对照哈希把每个文件读回来，并把大小与备份比较。对样本来说太大的文件，比如虚拟机磁盘，则改为读回它的前 64 MiB。条目的验证标签页显示结果，失败会作为通知发出，**检查恢复**可随时对最新备份运行同样的检查。之后的备份不会重复。
- **启动测试。** 检查字节并不能说明应用能否回来。容器验证标签页上的**启动测试**会把它的最新备份还原成一份隔离的副本并启动：名称以 `bombvault-test-` 开头，有独立的内部 Docker 网络，没有发布端口，也无法访问局分区网，1 个 CPU 和 2 GiB 内存，数据放在还原文件夹下的临时文件夹中。当容器的健康检查报告健康时测试通过；没有健康检查时，当它的第一个暴露端口从该网络内部应答时通过；两者都没有时，当它持续运行时通过。原始容器绝不会被停止或更改，副本、它的网络和它的数据事后都会被移除，即使测试中途 BombVault 重启也是如此。主机网络上的、特权的、带设备的以及需要另一个容器的容器会显示为无法测试。在**设置、验证、自动检查**下打开**启动测试**，即可每次运行测试一个容器，最久没测过的优先。副本不带原始容器的任何标签，并且在没有原始容器所添加的能力、安全选项、sysctl 和 cgroup 父级的情况下运行。需要它们的容器会测试失败，结果会写明副本在缺少什么的情况下运行。
- **自愈操作。** 确定属于孤立的 restic 锁（因操作中途重启而遗留）会被强制清除并自动重试一次。保留策略对身份稳定（按条目清理，不受路径或主机变化影响），保留失败会发送通知。
- **文件夹扫描看不到的警告。** 排除助手回答的是大小问题。而一些代价最高的备份错误并不是大小问题，所以它还带有针对具体应用的注意事项，说明某个应用如何存放它的数据。它最初就是为这个例子而存在的：Immich 把每张照片的相册、人脸和日期保存在一个运行于*单独*容器中的 PostgreSQL 数据库里，所以对 Immich 容器做文件级备份，还原出来的只有图片，这些信息一概没有，而还原看起来却是成功的。无论是否提供了排除建议，这条警告都会显示，在一个没有选择任何扫描内容的容器上也会显示，因为这条注意事项在两种情况下都成立。
- **未备份（覆盖范围）。** 一张概览卡片，点名服务器上所有没有被任何计划备份覆盖的内容，并写明各自的原因：从未加入 BombVault、存在但不在计划中、它自己的计划设为关闭、哪里都没有开启计划，或者它所属分区的每个目标都已关闭。保护状态回答的是另一个问题，即*已*计划的备份是否按时运行，它看不到那个从未有人设置过的容器。容器是从实时的 Docker 列表读取的，而不是从 BombVault 自己的行读取，因为没有行的条目恰恰就是需要被点名的那个。你关闭的分区和你标记为**不备份**的条目不计入，因为那是你的选择。
- **保留预览。** **设置、目标**下的**预览**卡片会在下一次运行删除内容之前，先告诉你它打算删除什么：按仓库、按条目，并点出还原点。它不持有任何仓库锁，也不改变任何东西，因此备份正在运行时也能应答。关闭保留时它会说明，而不是显示一个空列表；append-only 仓库会被标注出来（保留在那里根本不运行）；无法访问的仓库会被点名，而不是悄悄缺席。
- **异常。** 容器、虚拟机、文件夹集、数据库转储、闪存和自我备份的每次备份，都会与该条目自己的历史比较。检查会关注一次运行存下的新数据，对照近期备份通常的最大量，以及通常的每小时速率；关注存下了大部分数据的备份，其中包括被重命名并重写的文件；关注 restic 为每个条目和每个数据库转储报告的来源大小和文件数；关注 restic 自己的备份耗时；关注连续失败和间歇性失败；关注不再通过的还原检查；还有本地、SFTP 和 rclone 仓库的可用空间，根据仓库的增长推算。条目从它最初的 10 次备份中学习，而几乎为空的来源、大部分数据被重写以及失败则从一开始就会检查。灵敏度（严格、均衡、宽松）和会发送通知的最低严重程度，在**设置、验证**下的**异常**卡片中全局设置，也可以在每个条目的验证标签页上按条目更改。警告在原因消失后自动关闭；关于数据丢失和磁盘将满的严重发现会一直保留到你确认为止，已确认的发现在其原因至少消失一次之前不会再次提出。**标记为预期之内**在 10 次备份之后把新的水平视为正常，但绝不会关闭几乎为空的检查，所选内容改变则会自行重新开始该条目的历史。当来源几乎为空、急剧缩小或大部分数据被重新存储时，保留会保留该条目的旧备份，直到你确认该发现或把它标记为预期之内，并且该发现会链接到最近一次良好的备份。每次事件只发一次通知，已经会通知的失败和还原检查不会重复报告。它不做的事：S3、B2 和 REST 仓库没有可用空间的数值，在 Unraid 用户共享上可用空间是整个阵列的，而 restic 0.17 之前做的备份没有大小历史。ZFS 条目也会检查，逐个数据集进行：树中的每个数据集都有自己的历史，被清空或不再能读取的数据集算作数据丢失，只有该数据集的旧备份会被保留。ZFS 条目如何逐个数据集监控，见 [ZFS 数据集](zfs-datasets.md#anomalies)，助手可以通过 [MCP 服务器](mcp.md#tools)读取未处理的发现。关于来源大小或文件数的发现会标注它出现的第一次备份的日期，**与之前的备份比较**会列出文件消失、新增或变化的文件夹，并在几乎全部都位于搜索索引、缓存或应用会自行重建的缩略图中时附上说明。
- **异常页面。** **严重**、**警告**和**提示**磁贴选择严重程度，列表上方是未处理和已关闭的发现。严重发现和其他发现在同一表面上；严重程度体现在它的徽章和彩色边缘上。发现会先给出修复办法，其详情把数值显示为通常范围内的曲线。没有未处理项时，每个条目一个圆环，显示检测已经学到多少什么是正常的。
- **每个应用的推荐排除项。** 对于知名镜像（来自 linuxserver、hotio、binhex 或官方发布者的 Plex、Jellyfin、Emby、Sonarr、Radarr、Lidarr、Readarr、Prowlarr、Immich、Nextcloud、PhotoPrism 和 Tautulli），**排除模式**卡片中的排除助手会提供应用会自己重新填充的文件夹：缓存、日志、预览图和海报。每一项都说明它装着什么，任何一项都可以关掉，并且在你按下**排除所选项**之前什么都不会被排除。
- **错误报告。** **设置、信息**下**帮助**卡片中的**错误报告**会下载一个用于 GitHub issue 的脱敏 ZIP：主机集成检查、去掉所有机密的配置、最近的运行、接下来的计划，以及最近的日志。它还包含每个数据库最近一次转储的情况、带有容器所见挂载的 ZFS 条目、未处理的异常，以及存在多少 MCP 密钥（绝不含它们的名称）。密码、令牌、rclone 配置、通知凭据以及嵌在仓库位置中的任何密码都会被去除，而且这个包在自己的清单里这样写明，因为支持文件绝不能被误认为配置备份。出于与恢复工具包相同的理由，它需要登录密码。它附带的日志是此容器自上次启动以来的输出；对于导致容器重启的崩溃，该看的地方仍是 `docker logs`。
- **恢复工具包。** **设置、还原**下的**下载恢复工具包**会给你密钥、派生的 restic 密码以及精确的仓库位置和命令，这样没有运行中的 BombVault 你也能还原。它需要登录密码。参见[异地与恢复](offsite-recovery.md#recovery-kit)。
- **导出和导入你的设置。** **设置、系统**下的**导出 / 导入设置**卡片会把你的整套配置（分区设置、目标、计划、保留、通知）写入一个可移植的 JSON 文件，因此换新机器或克隆一套配置不必手动重新输入所有内容。是否包含异地和通知凭据由你选择；包含时，这个文件和你的恢复工具包一样敏感。导入会显示预览并要求确认，并且绝不会触碰你的备份数据或历史。
- **通知。** Webhook（Discord / Slack / Gotify / ntfy）、Matrix、Healthchecks.io、电子邮件（SMTP）、自托管的 [Apprise API](https://github.com/caronc/apprise-api) 服务器，以及 Unraid 原生的通知系统。每次备份的策略：从不 / 失败时 / 总是。包含许多条目的计划运行可以发送一条*成功 N 个，共 M 个条目*的汇总。只要设置了 URL，Healthchecks 就会收到完整生命周期（`/start`，然后是成功或 `/fail`）。
- **每周摘要。** 每周通过同样的渠道发一条消息：运行次数、到了多少新的备份数据、异地是否最新，以及最主要的失败。默认关闭，在**设置、通知**下有自己的节奏，所以平静的一周也会被如实报告。
- **Prometheus `/metrics`。** 可选启用（默认关闭，可选 bearer 令牌），位于**设置、集成**下的**服务**卡片，供 Grafana 或 Uptime Kuma 使用。公开备份状态、大小和时间戳，标签中没有机密或路径。
- **HTTP API、Home Assistant 和 mDNS。** 脚本和仪表板可以获得 `/api/v1` 下带有命名令牌的 API，只读或允许启动备份。Home Assistant 通过 MQTT 发现找到 BombVault，作为带传感器的设备，如果你允许，还带有每个分区一个备份按钮。BombVault 还会在网络上以 `bombvault.local` 宣告自己。参见 [API 与集成](api.md)。
- **可用空间和距写满的周数。** 会报告空间的本地仓库、SFTP 仓库以及 SMB 或 WebDAV 目标，会显示它们的可用空间以及按当前增速还剩多少周。S3、B2 和 REST 仓库显示“大小未知”，因为这些后端不报告。
- **按文件夹统计大小。** 在容器、虚拟机或文件夹集的验证标签页上，**按文件夹统计大小**一次一层地显示最新备份中哪些文件夹和文件占用空间，以及最近一次备份为每个带来了多少新增或变化。BombVault 从仓库的索引读取，不读取文件，并在你打开过一次之后于每次备份后保持更新。
- **备份为什么慢。** 备份运行时，BombVault 会观察 CPU、磁盘和网络的繁忙程度。如果某次备份比平时慢得多，并且明显只有一样东西到了极限，这次运行会注明，例如“目标磁盘 disk1 的占用率为 98%”或“BombVault 用掉了其容器 CPU 限额的 100%”。否则不显示任何内容。
- **上次备份后已更改。** 如果容器在上次备份后以其他镜像、端口、变量或卷重新创建，名称旁会出现一个标记。它的 (i) 会列出更改内容，变量只显示名称。这只是提示，下次备份后就会消失。

## 勒索软件防护

- **删除保护（append-only）。** 为异地目标打开它，勒索软件或被入侵的主机就无法删除或重写你的备份。远端（以 `--append-only` 模式运行的 `restic/rest-server`）强制执行；BombVault 只负责验证，绝不会仅凭配置声明就显示绿色。本服务器上的文件夹无法拒绝删除，所以本地目标不提供这个开关。
- **篡改测试。** BombVault 会定期通过真正对异地仓库尝试一次删除（针对一个不存在的对象）来证明 append-only 保证：被拒绝即受保护，被接受即未受保护。无定论的结果绝不会翻转已存的结论。目标页面上的**立即测试防删除保护**会按需运行它。
- **引导式设置。** **添加目标**会带你从服务商经过登录、连接测试和文件夹，到关于删除保护的坦率说明，以及备份到那里的分区。
- **DR 演练（异地）。** 试还原会把异地仓库中的一个真实目标放进密封的沙箱，逐文件、逐字节验证，然后清理。参见[异地与恢复](offsite-recovery.md)。
- **保护状态。** 概览卡片按当前备份、异地副本、那里的删除保护以及从那里做的试还原来检查每个分区。只有在事实经过验证时才会变绿。
- **增长预算告警。** 对于 append-only 目标（旧备份永远不会从这里被清理），设置一个大小预算，在它失控之前收到告警。
- **删除需要密码。** 删除某个目标上的备份需要登录密码和在实例本机登录，所以已配对的手机和敞开的界面都做不到。
- **用口令配对。** 实例通过十二个单词加入同一个组：在一台上生成口令，在下一台上输入。同一网络中的成员直接通信，其他成员通过中继（项目中继、你自己的中继，或不用），它们之间的每次调用都经过端到端加密。组承载实例页面上的保护状态、角色请求、目标提议，以及角色被允许后接收端或拉取端所需的内容，绝不含备份数据，也绝不含 APP_KEY。参见[异地与恢复](offsite-recovery.md#pairing)。
- **实例与角色。** 在**设置、实例、多台服务器**下打开**实例**，会得到一个页面，你的组里每个实例都有一张卡片，包括本机：它的地址、是否已连接，以及每个分区的保护状况和上次备份。它的角色以磁贴形式显示在卡片上：**接收端**、**拉取端**、**ZFS 服务器**和**密钥保管端**。角色只有在另一个实例上有人按下**允许**之后才会启动，组会以谁为谁做什么的网络形式显示。**立即检查**请某个成员验证一个分区的仓库。页面上没有任何东西能在另一台机器上启动备份、还原或删除任何内容。参见[实例与角色](offsite-recovery.md#roles)。
- **目标提议。** 成员可以通过组向另一个成员提议自己的异地目标。另一位管理员在实例页面上该成员的**详情**中看到提议，并接受或拒绝；接受会创建一个普通的凭据集和目标。以这种方式传递的只有连接信息，绝不含备份数据。
- **已接收的仓库（接收侧）。** 在从另一个 BombVault 接收 append-only 异地副本的机器上，在**设置、实例**下打开**接收端**，并在发送成员的**详情**中以只读方式添加已接收的仓库（用发送实例的 restic 密码打开，该密码通过配对组传来）。你会看到按来源分组的备份清单、每个来源最后一次到达的时间，并且可以在接收端硬件上运行独立的 `restic check`。当某个来源在你设定的窗口内停止发送（死人开关）或完整性检查失败时，它会向你告警。严格只读，因此绝不会写入已接收的仓库，并且默认关闭。参见[异地与恢复](offsite-recovery.md#receiver)。
- **从另一个实例拉取（拉取侧）。** 异地副本的镜像：不是本机把备份推出去，而是把别人的拉进来。在**设置、实例**下打开**拉取**，然后在另一个成员的**详情**中添加一个来源：它的仓库位置、它保存哪种备份，以及多久拉取一次。它的 restic 密码通过组传来，绝不是它的 APP_KEY。远端无需再配置任何东西，也不必正在运行。来源仓库只会被读取：打开它是为了检查密码、列出内容，并作为复制的来源被点名，绝不会被初始化、解锁、清理或写入。各方保管各自的凭据，`rclone:` 来源会被拒绝，因为 rclone 会用本实例的远程去访问它。参见[异地与恢复](offsite-recovery.md#receiver)。
- **密钥保管端。** 你组里的另一个实例可以保存这台服务器恢复工具包的一份封存副本，只有你的 20 位取回码能打开它，并且只有在那边有人按下**允许**之后才会交出。参见[异地与恢复](offsite-recovery.md#key-keeper)。

## 普通导出

- **容器与虚拟机导出。** 条目页面**更多**下的**导出容器**和**导出虚拟机**会在仓库旁写出一份可浏览、无需工具的副本：容器此刻的备份文件夹加上它的 Unraid 模板，或虚拟机的磁盘映像加上它的定义，用 `virsh define` 加磁盘即可还原，无需 BombVault 或 restic。备份上的**导出**以同样的方式把已存储的备份写成 tar、zip 或独立的 restic 仓库。引擎仍是 restic；这只是一份额外的便利副本。
- **加密纯文本导出（age）。** 导出位于 restic 之外，因此默认是明文。在**设置、系统**下打开**使用 age 加密导出**，并添加一个或多个接收方（age 公钥或 SSH 公钥）。之后每个导出（包括闪存 ZIP）都会为这些接收方封存，你之后在机器之外用匹配的私钥解密。作为一条安全规则，开启加密但没有设置有效接收方时，导出会以明确的错误失败，而不是写出明文。
- **恢复工具包也会被密封。** 开启同一设置后，工具包会以 `bombvault-recovery-kit.md.age` 下载。它是 ASCII 装甲格式而不是二进制，所以仍是可直接阅读的纯文本：你依然可以把它粘贴到密码管理器或打印出来，这正是工具包的用途。同样的安全规则也适用，因此在加密开启却没有可用收件人时，下载会被拒绝，而不是退回到以明文交出主密钥。开启此功能时有一点必须做对：打开工具包需要你的 age 私钥，所以请把这把密钥存放在不依赖工具包本身的地方。

## AI 助手（MCP） {#mcp}

BombVault 内置 MCP 服务器，因此 Claude Code 或 Claude Desktop 之类的助手可以读取备份状态、覆盖范围、运行历史、还原点和当前活动。使用允许的密钥，助手还可以启动一个条目、一个分区或全部的备份，并取消它自己启动的备份。还原、删除、清理和设置仍留在网页界面中。每个客户端在**设置、集成、MCP 服务器**下获得自己的密钥；密钥只显示一次，仅以指纹形式存储，可随时重命名、替换或撤销。启动按小时和按条目限流，保留保护则防止助手的备份把你自己的还原点挤出“保留最近 N 份”的策略。助手启动的每次运行都带着密钥的名称标为“经由 MCP”。参见 [MCP 服务器](mcp.md)。数据库转储和 [ZFS 数据集](zfs-datasets.md)也在它读取的条目和还原点之列，它还可以列出 BombVault 注意到的异常。

## 应用与配套工具 {#apps}

- **Android 应用。** 你群组中的每台服务器都在手机上，所有服务器的活动日志在同一个屏幕上。它通过二维码与你的群组配对，并以已登录状态打开每台服务器，会话只能访问应用所展示的内容。参见 [Android 应用](android.md)。
- **接收服务器。** 接收异地副本的机器运行一个 append-only 的 rest-server，在它第一次允许**接收端**请求时设置好，并提供给你组里的其他实例，每个实例有自己的登录。参见[接收服务器](offsite-recovery.md#receiving-server)。
- **设置、应用。** 页面从 Android 应用开始，提供服务器所运行版本的 APK 和对应的二维码，之后是为每个配套工具各设的一张卡片。ParleyPort 的卡片提供其 Unraid 模板，可复制启动它的 Docker 命令，并链接到它的仓库以及配对下的中继设置。BombVault Widget 的卡片提供其模板和仓库，并通过主机 SSH 连接安装或移除该插件。
- **BombVault Widget。** Unraid 仪表板上的一个磁贴，显示 BombVault 的活动日志和下一次计划运行。没有主机 SSH 连接时，卡片会给出 `.plg` 地址，供你在 **Plugins, Install Plugin** 下安装，之后也可以像其他插件一样在那里移除。
- **可嵌入的活动日志。** 在**设置、集成**下的**仪表盘小组件**卡片中生成一个只读令牌，你就会得到一个地址，可用于任何显示 iframe 的仪表板，比如 Homepage、Organizr 或 Heimdall：一个只含实时活动日志的小页面。该令牌只授予这份日志，别无其他，**停用**会立刻撤销它。嵌入的页面只有英文。

## 其他

- **停止正在运行的备份。** 运行进行期间，**取消备份**就在其进度旁边。该运行记录为*已取消*，而不是失败。停止是安全的，因为 restic 最后才写入快照，所以中止的运行只留下未被引用的数据，没有快照。
- **一次备份多个。** 在备份列表中选择条目并备份所选内容。批处理在服务器端运行，所以即使你关闭标签页或断开连接它也会继续。BombVault 绝不会备份（也因此绝不会停止）它自己的容器。
- **条目页面上的备份**，带还原点列表、按备份删除、你自己的标签以及两个备份之间的比较。
- **按分区的仓库维护**，在**设置、验证**下的**检查备份**卡片中：一次检查（`restic check`），以及在**更多**下的**解锁**（清除过期的锁）和**清理**（设置了保留策略时按需应用，否则只是普通的空间回收）。
- **检查、还原检查和清理的进度。** 其中任何一项运行时，活动日志和**检查备份**卡片会显示 restic 已计数多少，例如*47 个包中的 12 个*，并在数据足够估算时显示该步骤的剩余时间。restic 在这里计数的是包、快照和索引文件，而不是字节，所以进度条显示的就是这些；在第一次计数之前它不带数字运行。
- **自动数据库转储。** 被识别的 PostgreSQL、MySQL 和 MariaDB 容器（官方镜像、PostGIS、TimescaleDB、pgvector、pgautoupgrade、Immich 的数据库镜像、linuxserver、yobasystems 和 jc21 的 MariaDB，以及 Oracle 的 mysql-server）会在每次备份之前从运行中的服务器转储。仅仅看起来像数据库的容器，会在其设置标签页的**数据库**卡片中得到同样的选项，在你选择之前保持关闭。转储直接流入仓库，作为紧挨着文件备份的独立还原点，绝不写入磁盘。凭据来自容器自己的变量，包括 `*_FILE` 机密，并且绝不离开容器。卡片会显示数据库的数据文件夹是在停止时保存、运行时复制，还是根本没有保存。失败的转储不会让备份失败：它显示为一次带原因和修复提示的失败运行，并发送通知。转储绝不会自动载回。可以下载一份（纯文本或压缩）、保存到某个文件夹、一键导入刚启动的数据库，或用 restic CLI 取回。用标签 `bombvault.dbdump=false` 按容器关闭，或在**设置、常规**下用**自动数据库转储**对所有容器关闭。异常检测也会监视每份转储的大小，助手可以通过 [MCP 服务器](mcp.md#tools)列出容器的转储。
- **每个容器的前后命令。** 在容器内部运行的 shell 命令（例如刷新缓存）；备份前失败的命令会中止备份。被识别的数据库会自动转储，所以不需要命令。
- **备份期间停止其他容器，并按健康状态重启。** 在**停止其他容器**中点名依赖它的容器（例如数据库），在这个容器备份期间停止。之后 BombVault 按它们的 Compose `depends_on` 顺序把它们带回来，并默认等待每一个报告健康（没有健康检查则为运行中），然后才启动依赖它的容器，这样像 Pi-hole、数据库或 VPN 网关这样的依赖在需要它的服务之前确实已经起来，而不是让那些服务带着*连接被拒绝*回来。等待受每个容器的超时限制（默认 120 秒），所以缓慢或永远不健康的容器不会卡死这次运行；等待和超时都在**设置、计划**下**顺序**卡片的**备份后重启**中（关闭等待即可一次全部重启）。同样有序、按健康状态的重启也包裹着备份后的镜像更新，因此在有更新的那天，依赖者在重建期间保持关闭，直到完成才按健康状态带回来。
- **每个容器的排除模式。** 列出被备份的卷内部要跳过的子目录，每行一个。按你在容器内部看到的样子输入路径；实时预览会显示每一行解析成什么，并在某一行不会排除任何内容时发出警告。
- **备份成功后更新（默认关闭）。** 在**设置、计划、备份后的更新**下打开**备份成功后更新容器**，或在单个容器的页面上另行设置，BombVault 就会拉取最新镜像并重建容器，但只在确实有更新的镜像时才这样做，所以总是先有一个新的还原点。可选的附加项：每个更新的容器一条通知，以及**更新后删除旧镜像**（被其他容器共享的基础镜像绝不会被删除）。更新后 BombVault 还会请求 Unraid 重新检查那一个容器的更新状态，使 Docker 标签页上陈旧的*有可用更新*横幅自行消失而不是一直挂着（Unraid 的更新直接走 Docker API，所以它缓存的状态，以及在某些版本上缓存的摘要，否则会一直显示横幅）。它尽力而为，绝不影响备份，默认开启，并由同一张卡片中的**更新容器后刷新 Unraid 的更新状态**切换。
- **还原到另一个文件夹**，用于克隆或检查。
- **更新后的新内容。** 每个新版本一次，一个窗口会自动打开发行说明，内容来自嵌入二进制文件的说明，所以离线也能用。绿点在各自页面上标出每处变化。窗口有两个标签页，**发行说明**和**更改**，后者是每项变化的列表，每项都有**前往**。**设置、信息**下版本卡片里的**新内容**会统计你还没看过的内容，例如**新内容 · 4**，有未看内容时窗口打开在**更改**上，否则打开在说明上。
- **信息。** **设置、信息**包含**版本**（BombVault、GlimStone、restic 和 rclone，带**新内容**和**检查更新**）、带**手册**（用 README 里文档按钮的黄色）和**错误报告**的**帮助**，以及**关于 BombVault**。
- **开箱即用的 HTTPS**（自签名，或在反向代理后使用你自己的证书）。
- **Docker 健康检查。** 容器从其自身的 `/api/health` 报告健康/不健康，因此如果引擎卡死，自愈工具可以重启它。
- **42 种语言**，在**设置、外观**下用旗帜选择器切换。
- **设置会自动保存。** 拨动开关或离开字段，改动就会立即写入，控件上有一次短暂闪烁，服务器拒绝时则会抖动。少数地方保留保存按钮，因为只保存一半会不安全，例如 rclone 配置框、凭据集编辑器和登录密码。
- **安静的通知。** 在**设置、外观**下你可以静音例行确认，这样只有失败才会打扰你。这不会影响通知渠道。
- **让它呈现你想要的样子。** **设置、外观**设定**主题**（深色、浅色或系统）、颜色（一种强调色，或带八色调色板的*彩虹模式*）、圆角（圆润、微圆或直角）、动画（关闭、轻微、狂野或狂暴）以及设置磁贴的顺序。主题、圆角和动画为每个选项显示一个符号；按钮的标签模式设为**符号**时，选项只显示它的符号，名称放在悬停气泡里。BombVault 把外观保存在服务器上，第一次来的浏览器会接管它。目标容器里的液体会晃动，按住徽标时它抖得越来越厉害，然后炸开：在侧边栏里，以及在手机上概览的上方。当你的系统要求减少动态效果时，那始终优先。
