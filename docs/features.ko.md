# 기능

BombVault가 백업하는 모든 것은 하나의 목록에 있고, 모든 항목에는 전용 페이지가 있으며, 복원은 한 페이지에서 시작하고, 설정은 타일입니다. 켜야 하는 고급 모드는 없고, 드문 기능에는 전용 카드나 창이 있습니다. 이 페이지는 전체 기능을 묶어 보여 줍니다.

## 백업 범위

![백업 목록: 각 항목이 최근 실행을 띠로 보여 주고, 상태 하나와 동작을 가집니다.](assets/screenshots/containers.png)

*백업 목록: 각 항목이 최근 실행을 띠로 보여 주고, 상태 하나와 동작을 가집니다.*

| 섹션 | 저장되는 항목 |
|---|---|
| **컨테이너** | Appdata 디렉터리와 컨테이너 정의(이미지, 환경 변수, 포트, 레이블, 볼륨). 기본으로 appdata 디렉터리 전체입니다. 컨테이너의 **설정** 탭에 있는 **백업 폴더** 카드에서 백업이 다루는 폴더를 정확히 체크할 수 있으며, 경로 수가 실시간으로 표시되고 제외한 항목의 목록과 **캐시 폴더 건너뛰기 (CACHEDIR.TAG)** 스위치가 있습니다. TrueNAS ixVolume처럼 Host Data 바깥에 있는 컨테이너 데이터는 백업되지 않으며, 실행은 제외한 폴더를 알려 줍니다. |
| **VM** | VM 디스크 이미지, XML 정의, UEFI NVRAM(SSH를 통한 정상 종료 또는 라이브 스냅샷). 스냅샷을 만들 수 없으면 라이브 스냅샷은 자동으로 정상 백업으로 전환되므로 VM 백업이 그냥 오류로 끝나는 일은 없습니다. **변경된 블록만**을 켜면 qcow2 디스크가 있는 실행 중인 VM은 libvirt 체크포인트로 읽히므로, 백업은 이전 이후에 기록된 블록만 읽으며, 각 백업은 여전히 혼자서 디스크 전체를 복원합니다. ZFS zvol 위의 디스크는 같은 SSH 연결로 ZFS 스냅샷에서 읽어 원시 이미지로 저장되므로, 바뀌지 않은 블록은 다시 저장되지 않고 디스크가 zvol인 VM도 하나의 VM으로 백업됩니다. 복원은 각 zvol을 제자리에 다시 쓰며, 그 전에 덮어쓸 내용을 ZFS 스냅샷(`bombvault-before-restore-<time>`)으로 남겨 둡니다. 이 스냅샷으로 `zfs rollback`하면 복원이 취소되며, 스냅샷은 직접 삭제할 때까지 남아 있습니다. 파일로 내보내기에는 zvol 디스크가 포함되지 않습니다. 패스스루 vTPM의 상태는 도메인 XML이 경로를 밝히면 NVRAM 옆에 저장됩니다. TrueNAS가 Windows 11 게스트에 설정하는 에뮬레이트 vTPM은 그 경로를 공개하지 않으므로, 그런 게스트의 복구 키는 가까이 두세요. [VM 백업 가이드](https://github.com/junkerderprovinz/bombvault/blob/main/docs/vm-backup-ssh-setup.md)를 참고하세요. |
| **플래시** | Unraid 전용. USB 플래시 전체(`/boot`): OS, 라이선스, 배열 구성, 공유, 네트워크 및 플러그인 구성. 복원은 `.zip` 다운로드이며 실행 중인 플래시를 덮어쓰지 않습니다. |
| **셀프 백업** | BombVault 자체 `/config`(설정 데이터베이스, 대상의 로그인 정보, libvirt SSH 키 쌍). SQLite `VACUUM INTO`로 스냅샷을 만들어 WAL 모드 데이터베이스가 쓰는 도중에 담기는 일이 없습니다. BombVault를 재시작하는 긴급 마법사를 통해 돌아오므로, 열린 핸들 아래에서 실행 중인 데이터베이스가 덮어써지는 일이 없습니다. |
| **폴더** | 폴더 세트: 서버의 모든 폴더(공유, 문서, 사진 라이브러리)이며, 각각 선택적으로 제외 패턴을 가질 수 있습니다. 백업 페이지의 **추가**는 찾은 공유를 나열하고 다른 폴더도 받습니다. 폴더 세트에는 다른 섹션이 가진 모든 것이 있습니다. 일정, 보존, 오프사이트 사본, 검사, 복원 훈련입니다. |
| **ZFS 데이터세트** | 데이터세트와 그 아래의 모든 데이터세트를 하나의 ZFS 스냅샷에서 읽으므로 모두 같은 순간의 것이며, restic으로 폴더처럼 저장됩니다. 중복 제거되고, 탐색할 수 있고, 개별 파일을 복원할 수 있습니다. 새 하위 데이터세트는 스스로 합류하고, 개별 하위 항목은 제외할 수 있으며, 읽을 수 없는 하위 항목은 건너뛰고 이름을 알려 줍니다. 선택적으로 스냅샷 순간에만 컨테이너를 멈추거나 명령을 실행합니다. 볼륨은 포함되지 않습니다. VM의 볼륨은 그 VM과 함께 백업되고, VM 없는 볼륨은 아직 백업되지 않습니다. ZFS 항목은 두 번째 ZFS 서버에 블록 단위로 동일한 복제본을 둘 수도 있습니다. [ZFS 데이터세트](zfs-datasets.md)를 참고하세요. |

## 백업과 항목 페이지 {#backups}

- **하나의 목록.** 컨테이너, VM, 폴더 세트, 플래시, ZFS 데이터세트, 셀프 백업이 **백업** 아래 하나의 목록에 있습니다. 위의 타일로 종류를 고르고 **필터**, **정렬**, **검색**으로 좁힙니다. 정렬은 이름, 상태, 마지막 백업, 크기, 일정 기준으로 양방향이 되고, 검색은 컨테이너를 이름, 이미지, IP로 찾습니다.
- **최근 실행을 띠로.** 행은 최근 열네 번의 실행을 작은 사각형과 하나의 상태로 보여 줍니다. 나머지는 모두 이름 옆의 정보 말풍선에 있으며, 마우스를 올리면 행에도 같은 글이 표시됩니다.
- **파일 관리자처럼 선택.** Ctrl+클릭, Shift+클릭, Ctrl+A로 행을 고르고, 휴대폰에서는 길게 눌러 고르며, **더보기** 아래의 **선택**으로도 선택을 시작합니다. 고른 행에는 아이콘 대신 체크 표시가 나타나고, 모든 행에는 오른쪽 클릭 메뉴가 있습니다. 선택한 항목은 백업하거나 일정에서 일시 중지하고 재개할 수 있습니다. 여러 항목은 복원 페이지에서 함께 복원합니다.
- **추가**는 BombVault가 짐작할 수 없는 것을 위한 창 하나를 엽니다. 폴더나 ZFS 데이터세트입니다. 컨테이너, VM, 플래시는 저절로 나타납니다. Unraid가 없는 호스트에서 Host Data가 `/etc`까지 닿으면 창이 **시스템 구성**을 제안합니다. 저장 전에 살펴보는 `/etc` 폴더 세트의 시작 묶음입니다.
- **백업하지 않음**은 항목을 일부러 뺍니다. 그러면 보호되지 않는 것으로 세지 않으며, **제외 해제**가 되돌립니다.
- 백업 페이지의 **더보기**에는 대상에 있는 것으로 항목을 다시 만드는 **백업 검색**(예: 새로 설치한 뒤)과 Compose 프로젝트용 **스택 복원**이 있습니다.
- **모든 항목에 전용 페이지**가 있으며, 상태를 알리고 동작을 담은 머리글, 아이콘 왼쪽에서 목록으로 돌아가는 뒤로 가기 버튼, 세 개의 탭이 있습니다.
    - **백업**은 백업을 일별 막대와 함께, 그것을 보관하는 대상과 데이터베이스 덤프를 나열합니다.
    - **설정**에는 일정과 대상, 저장소, 백업 폴더, 제외 패턴, 멈출 다른 컨테이너, 전후 명령, 데이터베이스 덤프, 이전 이름이 있습니다. 일정과 대상은 항목이 자체 값을 가질 때까지 섹션의 기본값을 따릅니다.
    - **검증**은 검사, 폴더별 크기, 항목의 이상 징후 모니터링, 최근 실행을 보여 줍니다.
- **표시하고 비교.** 백업에는 자신만의 태그를 달 수 있고, **다른 백업과 비교**는 둘 사이에 생기거나, 사라지거나, 바뀐 파일을 나열합니다. VM은 디스크 이미지를 비교하고 얼마나 다른지 알려 줍니다.
- **내보내기**는 백업 하나, 항목의 모든 백업, 또는 지금 상태의 컨테이너나 VM을 서버의 내보내기 폴더에 tar, zip, 또는 별도의 restic 저장소로 기록합니다.

## 복원

![복원 페이지: 섹션을 고르고, 항목을 검색하고, 백업을 선택합니다.](assets/screenshots/recovery.png)

*복원 페이지: 섹션을 고르고, 항목을 검색하고, 백업을 선택합니다.*

- **한 페이지.** **복원**은 섹션을 타일로 나열합니다. 되찾고 싶은 것을 검색하고, 최신이 맨 위인 목록에서 백업을 고릅니다. 권장 백업에는 표시가 있으며, 이상 징후 뒤에는 그 직전 것입니다. **항목 열기**는 항목의 페이지로 이어지고, 실행 중인 복원은 **실행 중**에 나타납니다.
- **모든 종류를 위한 하나의 창.** 단계별로 묻습니다. 어떤 **백업**인지(권장 백업이 미리 선택됨), 어떤 **소스**인지(로컬이 가장 빠름), **무엇**(전부, 또는 고른 파일과 폴더), 그리고 **어디로**입니다. 한 장면이 고른 위치를 보여 주고, 시작하기 전에 **진행 내용**이 말로 설명합니다.
- **한 번에 여러 개.** 복원 페이지에서 Ctrl+클릭, Shift+클릭, Ctrl+A, 길게 누르기 또는 **선택**으로 항목을 고르면 고른 항목에 아이콘 대신 체크 표시가 나타나고, **복원**이 모두를 위한 창 하나를 엽니다. 각 항목은 가장 최근 백업이나, 모두에 대해 고른 한 시점의 가장 최근 백업을 사용하고, 원본 옆에 놓이거나 원본을 대체합니다. 복원은 차례로 실행되고, 각 행에는 그 항목의 결과가 표시됩니다. 플래시는 ZIP으로 내려받습니다. ZFS 데이터세트와 셀프 백업은 하나씩 복원합니다.
- **원본 옆에가 기본입니다.** 컨테이너는 `<name>-restored`라는 이름의 두 번째 컨테이너로 자체 포트와 함께 돌아오고, 원본은 계속 실행됩니다. VM의 디스크와 NVRAM은 두 번째 VM 없이 원본 옆의 `<folder>-restored` 폴더에 놓입니다. 폴더 세트는 `<path>-restored`로 돌아옵니다. 사본은 일정에 추가하기 전까지 백업 목록에 제외된 것으로 표시됩니다.
- **원본 교체는 먼저 백업합니다.** 기본으로 켜져 있는 **먼저 현재 상태 백업**으로, BombVault는 교체하기 전에 지금 있는 것을 백업하므로 되돌아갈 수 있습니다. 그 백업이 실패하면 복원은 시작되지 않습니다. 교체하려면 항목 이름을 입력해야 합니다.
- **폴더로**는 둘러보기 위해 파일만 기록합니다. ZFS 데이터세트는 **새 데이터세트로**도 복원할 수 있고, 플래시는 **ZIP으로 다운로드**로 돌아옵니다.
- **컨테이너는 자동으로 재설치됩니다.** 컨테이너 정의가 Docker API에 대해 재생되므로, 컨테이너가 이전과 똑같이 Unraid Docker 탭에 다시 나타납니다. 컨테이너는 나중에 받은 더 새로운 이미지가 아니라, 복원한 백업을 만들 때 실행하던 이미지로 돌아오며, 원본 옆에 두는 사본도 그 이미지로 시작합니다. 이미지는 없을 때만 받아 옵니다.
- **GPU, 제한, 링크가 돌아옵니다.** 복원된 컨테이너는 리소스 제한, 로그 드라이버, DNS 설정, 레거시 링크, GPU 또는 런타임(`--gpus`, `--runtime=nvidia`)을 되찾습니다. 해당 GPU 드라이버나 런타임이 없는 호스트에서는 복원이 이를 알리고 **GPU와 런타임 없이 복원**을 제안합니다. 여러 컨테이너나 stack을 복원한 뒤에도 마찬가지입니다. 없는 컨테이너나 복원된 컨테이너가 시작될 때 중지된 컨테이너로의 링크는 빠지며, 실행 기록에 그 사실이 남습니다.
- **VM은 자동으로 다시 만들어집니다.** XML이 SSH를 통해 다시 가져와지므로, VM은 디스크와 UEFI NVRAM이 다시 연결된 채 VM Manager에 다시 나타나며, VM이 삭제된 후에도 마찬가지입니다.
- **플래시 복원은 `.zip` 다운로드입니다.** `flash-<id>.zip`으로 브라우저에 스트리밍되어, Unraid USB 작성기에 바로 넣을 준비가 됩니다. 실행 중인 `/boot`은 절대 건드리지 않습니다.
- **플러그인 하나씩.** 플래시 복원 창은 각 플래시 백업의 플러그인을 버전과 크기와 함께 나열하고, 하나만 실행 중인 플래시에 되돌립니다. `.plg` 파일, `config/plugins` 아래의 폴더, 백업에 있는 패키지 파일입니다. 플래시의 다른 부분은 바뀌지 않습니다. Unraid는 다음 부팅 때, 또는 **Plugins, Install Plugin**에서 바로 플러그인을 설치합니다.
- **예약된 플래시 zip 내보내기.** 플래시 백업 뒤에 선택적으로 백업을 고른 폴더에 일반 `.zip`으로 기록합니다(덮어쓰는 `flash-latest.zip` 하나 또는 롤링 기록). 플래시 항목의 설정 탭에 있는 **플래시 zip 내보내기** 카드입니다. Syncthing이나 rclone 폴더를 가리키게 하면 부팅 가능한 USB 백업이 자동으로 서버를 벗어납니다.
- **사전 점검 충돌 검사.** 어떤 것이 중지되거나 제거되기 전에, 복원은 컨테이너의 고정 IP와 게시된 호스트 포트가 비어 있는지 확인하고, 중간에 끝난 복원을 남기는 대신 명확한 메시지와 함께 중단합니다. 복원 전 확인은 삭제된 TrueNAS 앱이 만들었던 네트워크처럼 사라진 네트워크도 알려 주고, 먼저 그 앱을 다시 설치하라고 안내합니다.
- **복원 전 확인.** 창은 먼저 저장소가 응답하는지, 저장된 키로 열리는지, 복원 지점이 있는지, 복원 위치에 복원이 쓰는 만큼의 공간이 있는지 확인합니다. 확인이 실패하는 동안은 시작이 잠기고, 버튼의 (i)가 어느 것인지 알려 줍니다.
- **복원이 바꾸는 것.** 확정하기 전에 창은 지금 있는 것과 비교해 복원이 무엇을 하는지 보여 줍니다. 새 파일, 교체되는 파일, 그대로인 파일이며, 요청하면 목록이 나오고, 복원 위치에 있으면서 백업에 없는 파일은 그대로 남습니다. 컨테이너와 VM에서는 복원이 다시 만드는 설정을 실행 중인 것과도 비교합니다. 이미지와 태그, 포트, 변수 이름과 볼륨, 또는 메모리, vCPU, 디스크, 네트워크입니다. restic이 크기와 수정 시각으로 드라이 런으로 계산하며 파일을 읽지 않습니다. 매우 큰 트리는 30초 뒤에 멈추고 그렇게 알려 줍니다. 스택 복원은 모든 구성원을 확인하고 계획하며 막는 것을 지목합니다.
- **공유 폴더.** 원래 위치로 복원할 때, 복원이 쓰는 폴더까지 마운트가 닿는 다른 컨테이너를 실행 여부와 관계없이 모두 이름으로 알려 줍니다. 예: "이 경로는 nextcloud-db도 사용합니다". 경고만 하고 막지는 않습니다.
- **ZFS 데이터세트 복원.** 항목의 데이터세트 하나를 제자리에(삭제할 때까지 남는 ZFS 안전 스냅샷을 만든 뒤), 폴더에, 새 데이터세트에, 고른 파일만, 또는 백업의 모든 데이터세트를 폴더에 복원합니다. 데이터세트가 롤백되거나 교체되는 일은 없습니다.
- **복원은 실행 상태를 유지합니다.** 백업 때 실행 중이던 컨테이너나 VM은 실행 상태로 돌아오고, 멈춰 있던 것은 멈춘 채로 있습니다. **끝난 뒤 중지 상태로 두기**를 켜면 시작하지 않고 다시 만듭니다.
- **전체 스택 복원.** 같은 Docker Compose 프로젝트의 컨테이너 중 백업된 구성원이 둘 이상인 것은 스택을 이룹니다. 백업 페이지의 **더보기** 아래 **스택 복원**은 각 구성원을 최신 백업에서 다시 만들고, 선택적으로 `depends_on` 순서로 시작합니다.
- **실시간 진행 상황, 취소, 처리 중 표시.** 긴 복원은 실시간 퍼센트 막대를 보여 주고 종류에 맞는 확인과 함께 취소할 수 있습니다. 취소된 복원은 실패가 아니라 *취소됨*으로 기록됩니다. 창은 닫을 수 있고, 진행 상황은 복원 페이지에도 표시됩니다.
- **긴급 마법사.** 사라졌거나 다시 설정한 서버를 위한 것으로, 복구 키트, 그룹을 통해, 또는 입력한 키로 진행합니다. [오프사이트 및 복구](offsite-recovery.md#emergency)를 참고하세요.
- **이전 백업 폴더에서.** 읽기 전용 세션이 다른 BombVault의 저장소를 그 인스턴스의 복구 키트 또는 입력한 `APP_KEY`로 열므로, 자신의 설정을 건드리지 않고 서버 A의 컨테이너를 서버 B로 가져올 수 있습니다. [오프사이트 및 복구](offsite-recovery.md#restore-from-another-bombvault-repo)를 참고하세요.
- **ZFS 속성도 돌아옵니다.** 모든 ZFS 백업은 각 데이터세트에 로컬로 설정된 속성(압축, 레코드 크기, 할당량, 대소문자 구분 등)을 보관합니다. 새 데이터세트로 복원하면 그 속성으로 만들고, 기존 데이터세트로 복원하면 속성을 보여 주되 요청할 때만 설정합니다. [ZFS 데이터세트](zfs-datasets.md#new-dataset)를 참고하세요.
- **Appdata.Backup 플러그인에서 가져오기.** 복원 페이지의 **다른 출처**에서 BombVault가 플러그인의 백업 폴더를 가리키게 합니다. 각 컨테이너 아카이브는 그 컨테이너의 복원 지점이 되며, 날짜는 플러그인이 만든 때입니다. 전에 가져온 아카이브는 건너뛰고, 아카이브 자체는 읽기만 합니다. 복원이 정의를 얻도록 컨테이너는 먼저 BombVault에서 한 번 백업되어 있어야 합니다. 보존은 가져온 복원 지점을 건드리지 않으므로 더 필요 없으면 직접 삭제하세요.

## 저장 공간 및 예약

- restic을 통한 증분, 중복 제거 백업이므로 큰 VM 디스크조차 저장소를 부풀리지 않습니다.
- **대상.** 로컬 폴더와 오프사이트 장소는 **대상** 페이지의 하나의 목록에 있으며, 설정 타일에서 열거나 사이드바에 고정합니다. 섹션이 백업하는 이 서버의 폴더는 배치 버튼과 같이 **로컬**이라고 부릅니다. 각 대상에는 연결, 자격 증명, 삭제 방지, 복사 설정, 보존, 섹션별 규칙이 있는 전용 페이지와, 얼마나 찼는지와 최근 몇 주의 증가 속도로 언제 가득 찰지 보여 주는 용기가 있습니다. [대상](offsite-recovery.md#destinations)을 참고하세요.
- **저장소의 종류:** 로컬 경로, 호스트 마운트 없이 rclone을 통한 SMB 공유와 WebDAV 서버(Nextcloud, ownCloud, SharePoint), NFS(Unraid에 export를 마운트해 로컬 폴더로 사용), rclone 없는 네이티브 restic 백엔드(`s3:...`, `rest:http://host:8000/repo`, `sftp:user@host:/repo`), 또는 `rclone:<remote>:<bucket>/path`를 통한 모든 rclone 리모트. 모든 자격 증명은 암호화되어 저장됩니다.
- **SSH 대상은 맞은편에 아무것도 설치할 필요가 없습니다.** `sftp:`에는 SSH 서버만 있으면 되므로, 맨몸의 Raspberry Pi(Docker도 restic도 없음)도 오프사이트 대상으로 작동합니다. 호스트 키는 처음 접속할 때 자동으로 고정됩니다. SFTP와 Storage Box의 연결 테스트는 **서버 키**를 보여 주며, 나중에 서버가 다른 키를 내밀면 BombVault는 그 서버를 거부합니다. **키 추가**는 계정 비밀번호로 BombVault의 키를 서버에 넣으며, 이 비밀번호는 그 한 번의 로그인에만 쓰이고 어디에도 저장되지 않습니다.
- **3-2-1을 그림으로.** **섹션별 대상** 카드는 어떤 섹션이 어디에 백업되는지 그립니다. 섹션에서 대상으로 가는 모든 선이 **로컬**을 포함해 모든 섹션에서 스위치이고, 한 번 클릭하면 바로 바뀝니다. **그래프 / 스위치**는 같은 내용을 일반 버튼으로 보여 줍니다. 오프사이트 대상만 있는 섹션은 BombVault가 그곳에서 직접 고른 저장소로 바로 백업하고, 모든 선이 꺼진 섹션에는 **백업 안 됨**이 표시됩니다. 항목이 자신의 섹션과 다른 곳에 백업하면 흐름이 그 수를 **2개 항목이 다릅니다**처럼 알려 주고 그 항목들로 안내합니다. 플래시, ZFS 데이터세트, 셀프 백업은 로컬 폴더에 백업하고 그 백업에서 오프사이트로 복사합니다. **로컬**로 가는 선도 끌 수 있으며, 그러면 백업은 오프사이트 대상으로 바로 갑니다. 복제본이 있고 대상이 전혀 없는 ZFS 항목은 복제본만 보냅니다.
- **오프사이트 복사(로컬 + 원격).** 빠른 로컬 백업을 유지하고 오프사이트 대상을 하나 이상 추가해, `restic copy`로 최선 노력 방식으로 복사합니다(오프사이트 장애가 로컬 백업을 실패시키는 일은 없습니다). 복사는 대상에 아직 없는 데이터 팩만 전송합니다. 각 대상의 **복사** 카드는 **복사 시점**(**백업할 때마다** 또는 자체 계획)과 대역폭을 설정하고, 섹션은 **설정, 일정**에서 자체 계획으로 복사할 수 있습니다.
- **섹션당 여러 대상.** 각 섹션은 여러 오프사이트 대상에 동시에 복사할 수 있습니다. 대상의 **섹션별 규칙**은 한 섹션에 그곳에서 쓸 자체 보존, 압축, 저장소를 주며, 로그인, 자격 증명, 대역폭, 시점은 대상에서 정해집니다.
- **섹션의 기록 옮기기.** 대상의 **이동**은 한 섹션의 사본을 전체 기록과 함께 다른 대상으로 옮깁니다. 이전 장소는 모든 것을 유지하며 BombVault는 거기서 아무것도 삭제하지 않습니다.
- **이름이 있는 저장소.** **설정, 대상**의 **저장소** 카드는 백업 위치(로컬 경로 또는 자체 자격 증명 세트를 가진 모든 restic 리모트)를 한 번 적어 두어 항목의 위치로 고르게 합니다. 행에는 몇 개의 항목이 가리키는지 표시되며, 항목이나 기본값이 쓰는 저장소는 BombVault가 이미 쓴 백업을 옮기지 않으므로 옮기거나 삭제할 수 없습니다.
- **여러 자격 증명 세트.** 공유 클라우드 자격 증명은 기본으로 어디에나 적용되지만, 어떤 대상이든 이름이 있는 세트를 대신 쓸 수 있습니다(**설정, 대상**의 **추가 자격 증명 세트**, 또는 대상 페이지의 **자격 증명**). 그래서 Hetzner S3 버킷과 로컬 Garage 서버를 각자의 키로 나란히 운영할 수 있습니다.
- **항목별 배치.** 항목의 설정 탭에 있는 **일정 및 대상** 카드에는 **로컬**과 오프사이트 대상마다 하나씩 버튼 줄이 있고, 켜진 것이 그 항목의 백업을 받습니다. 이미 NAS에 있는 공유를 B2에까지 보낼 필요는 없습니다. 섹션을 따르는 항목은 섹션의 위치가 바뀌면 함께 옮겨 가고, 떠난 위치는 **이전 백업만**으로 표시되며 거기서 계속 복원할 수 있습니다. 항목에서 직접 고른 위치는 첫 백업부터 고정되고 사본은 언제든 바꿀 수 있으며, 카드는 몇 곳이 항목을 보관하는지와 3-2-1이 충족되는지를 알려 줍니다. **기본값 따르기**는 먼저 확인을 요청하고 무엇이 빠지고 무엇이 업로드되는지 알려 줍니다. [항목별 배치](offsite-recovery.md#placement)를 참고하세요.
- **수동 백업 순서.** **설정, 일정**의 **순서** 카드가 컨테이너와 VM을 백업하는 정확한 순서를 정합니다. 예약 실행과 전체 백업이 이를 따르고, 순서를 정하지 않은 것은 기한이 가장 많이 지난 것부터 순서를 유지하며, 단일 백업은 그대로입니다.
- **시간 축으로 보는 보존.** 각 대상은 **보존 기간**에 따라 백업을 유지합니다. **짧게**, **균형**, **길게**, 또는 최근 백업, 일, 주, 월, 년에 대한 **사용자 지정 값**이며 자동으로 정리됩니다. 시간 축은 규칙이 어떤 백업을 유지하는지 보여 줍니다. **보존을 줄이기 전에 확인**은 더 짧은 규칙이 유일한 사본이 거기에 있는 오래된 백업을 삭제하기 전에 묻습니다. 섹션은 **섹션별 규칙**에서 한 대상에 자체 값을 둘 수 있습니다.
- **저장소별 압축:** 끔, 자동(restic의 기본값), 최대. 각 대상에, 그리고 한 섹션에는 그곳의 규칙 아래에 설정합니다. 백업, 오프사이트 복사, 정리가 이것으로 기록하며 복구 키트에도 적혀 있으므로, 일반 restic도 같은 방식으로 계속 쓸 수 있습니다.
- **일정은 문장으로 읽힙니다.** 예를 들어 *매주 일요일 04:00*처럼, 그 문장에서 편집합니다. **설정, 일정**에 모든 것이 있습니다. 월요일부터 일요일까지 계획된 모든 실행이 있는 **주** 띠, 앞뒤로 명령 하나씩을 둘 수 있는 **전체 백업**, **섹션별 일정**, **섹션별 오프사이트 복사**, **예약된 항목**입니다. **N일마다**는 복원 훈련, 변조 테스트, 주간 요약에도 쓸 수 있습니다.
- **자체 계획이 있는 섹션은 전체 백업에서 빠집니다.** **섹션별 일정**의 **예외** 버튼이 섹션에 자체 계획을 주면, 그 섹션은 자기 시간에 실행되고 전체 백업에서 다시 실행되지 않으므로 중복 백업이 없습니다. **지금 모두 백업**은 여전히 켜진 모든 섹션을 다룹니다. **항목별 고유 일정**을 켜면 컨테이너, VM, 폴더 세트, ZFS 데이터세트 하나가 자신의 페이지에서 자체 계획을 가질 수 있고, 그 경우 그것도 전체 백업에서 빠집니다.
- **백업 성공 후 컨테이너 업데이트.** **설정, 일정, 백업 후 업데이트**의 스위치 하나(기본 꺼짐)는 앞선 백업이 끝난 뒤에만 새 이미지를 가져옵니다. 개별 컨테이너는 자신의 페이지에서 다르게 설정할 수 있습니다.
- **중지 대신 스냅샷.** 데이터가 ZFS에 있는 컨테이너는 BombVault가 그 데이터의 스냅샷을 만드는 동안, 보통 몇 초만 중지되고 바로 다시 시작됩니다. 백업은 이후 스냅샷에서 읽혀, 컨테이너를 중지하고 만든 백업과 같은 경로와 태그로 저장소에 저장되므로 복원, 복원 점검, **이전 백업과 비교**, 이상 징후 점검은 둘을 똑같이 다룹니다. 백업 전 명령과 데이터베이스 덤프는 그대로 먼저 실행되고, 함께 중지해야 하는 다른 컨테이너도 같이 내려갔다가 같이 올라오며, 백업 후 명령은 컨테이너가 다시 올라오는 즉시 실행됩니다. 백업 후 업데이트는 여전히 백업이 끝날 때까지 기다립니다. 더 새로운 이미지가 있으면 다른 컨테이너가 재생성을 위해 한 번 더 중지됩니다. 이 기능에는 [ZFS 데이터세트](zfs-datasets.md)와 마찬가지로 호스트로의 SSH 연결이 필요하며, 하나의 ZFS 풀에 있는 Unraid 사용자 공유에서 동작합니다. 데이터 일부가 어레이나 다른 파일 시스템에 있는 컨테이너는 이전처럼 백업 내내 중지되며, 해당 실행 기록에 이유가 표시됩니다. ZFS에 데이터가 전혀 없는 컨테이너는 이전처럼 중지되며 따로 표시되지 않습니다. TrueNAS에서는 앱에 `SYS_CHROOT` 기능도 필요합니다([TrueNAS SCALE](getting-started.md#truenas) 참고). 스위치는 **설정, 일정, 중지 대신 스냅샷**에 있고 기본값은 켜짐이며, 개별 컨테이너는 자신의 페이지에서 다르게 설정할 수 있습니다. 실행 기록에는 **스냅샷**과 컨테이너가 중지되어 있던 시간(초)이 표시됩니다. BombVault가 어떤 컨테이너의 백업 도중 중단되면, 다음에 시작할 때 중지해 둔 컨테이너를 다시 시작합니다.
- **앱이 한가해질 때까지 대기.** 컨테이너는 앱이 바쁜 동안 예약된 백업을 설정한 시간까지 기다리게 하고, 앱이 한가해지는 대로 시작할 수 있습니다. 미디어 서버는 스트리밍하지 않을 때, 다른 컨테이너는 CPU와 트래픽이 **설정, 일정**의 **백업 전 유휴 상태** 카드에 있는 한도 아래에 몇 분간 머물 때 한가한 것으로 봅니다(호스트 네트워크에서는 CPU만 계산). 대기 중인 백업은 사유와 기한과 함께 활동 로그와 컨테이너에 표시됩니다. 잠금을 잡지 않으므로 다른 컨테이너는 계속 진행됩니다. 수동 백업은 기다리지 않습니다. 같은 실행에서 기한이 된 compose 스택의 구성원은 함께 기다리고, 대기는 재시작 뒤에도 기한을 유지한 채 이어집니다. 컨테이너를 끄면 대기 중인 모든 백업이 버려지고, 일정을 끄면 그 실행이 붙잡아 둔 것이 버려집니다. 시간을 줄이면 이미 시작된 대기도 짧아집니다.
- **오프사이트 대역폭 제한.** restic 업로드/다운로드 속도에 상한을 두어 복사가 WAN을 포화시키지 않게 합니다. **설정, 대상**의 **오프사이트 대역폭** 카드에서, 또는 대상별로 그 **복사** 카드에서 설정합니다.
- **스트리밍 우선.** Plex, Jellyfin, Emby 같은 미디어 서버가 스트리밍하는 동안 오프사이트 복사는 더 낮은 한도로 업로드하고, 스트림이 끝나고 몇 분 뒤에 보통 한도로 돌아옵니다. BombVault는 Docker에서 미디어 서버의 송신 트래픽을 읽습니다. REST, S3, B2, Azure, Google Cloud, Swift, HTTP 위의 rclone은 복사 도중에 느려지고, SFTP와 로컬 또는 마운트된 폴더는 다음 복사 단계에서 낮은 한도를 적용합니다. 호스트 네트워크의 미디어 서버는 측정할 수 없습니다. 대상 페이지의 **스트리밍** 카드입니다.
- **콜드 및 아카이브 스토리지 클래스(S3).** S3 대상에서는 복원 가능한 계층(Standard, Standard-IA, One Zone-IA, Intelligent-Tiering, Glacier Instant Retrieval)으로 한정해 스토리지 클래스를 고를 수 있어, 아카이브 요금이 복원을 조용히 망가뜨리는 일이 없습니다. 먼저 비동기 해동이 필요한 딥 아카이브 계층(Glacier Flexible, Deep Archive)은 restic이 읽을 수 없어 제외됩니다. 네이티브 S3 백엔드만 해당하며, rclone 리모트는 rclone 설정에서 클래스를 지정합니다.
- **백업 폴더는 장비 밖으로 복사 가능한 상태를 유지합니다.** 매 백업 후 BombVault는 로컬 저장소 트리를 디렉터리 `0755` / 파일 `0644`로 완화하므로(저장소는 암호화되어 있어 아무것도 노출되지 않음) SMB를 통한 비root 동기화 사용자가 차단되지 않습니다. 복구 정의는 각 저장소 안에 있으므로, 복사한 저장소 폴더는 완전히 자기 완결적입니다.

## 통찰, 검증 및 모니터링

- **개요.** 상태 머리와 네 개의 카드로 시작합니다. **조치 필요**, **보호 상태**, 각각 언제 가득 찰지 예측을 보여 주는 **대상**, 실행과 로그가 있는 **기록**입니다. 머리의 링은 얼마나 보호되는지 보여 주고, 백업이 실행되는 동안에는 각 단계를 가진 진행 링이 됩니다. 더 많은 카드가 **사용자 지정** 아래에서 기다립니다. **이상 징후**, **백업 안 됨**, **달력**, **저장 공간**, **개요**, **통계**, **호스트 통합**입니다. 모든 카드는 옮기고, 크기를 바꾸고, 숨길 수 있으며 레이아웃은 브라우저에 저장됩니다.
- **어디서나 같은 개수.** 모든 카드는 켜진 섹션의 항목을 같은 방식으로 셉니다. 일정에서 벗어난 항목은 마지막 백업이 아무리 최근이어도 보호된 것으로 세지 않습니다.
- **항목에서 일시 중지.** **일정 일시 중지**는 항목을 일정과 전체 백업에서 빼고, **일정 재개**가 되돌립니다. 항목의 설정 탭에 있는 **일정에 포함**과 같은 스위치를 설정하므로 둘은 항상 일치합니다. 일시 중지된 항목에는 회색 **일정 일시 중지됨** 배지가 붙고, **지금 백업**은 계속 작동합니다.
- **보호 상태.** 모든 섹션에는 네 가지 검사가 있습니다. 이 서버의 최신 백업, 오프사이트 사본, 거기서의 삭제 방지, 거기서 하는 시험 복원입니다. 기한이 지난 백업은 로그에 묻히지 않고 빨갛게 바뀌며, 섹션을 클릭하면 세부 정보가 나옵니다.
- **달력.** 최근 90일을 하루에 사각형 하나로, 그날의 백업 결과와 함께 보여 줍니다. 날짜를 클릭하면 **기록** 아래 로그에서 그날의 줄이 나옵니다.
- **어디서나 실행 시간 표시.** 모든 실행은 `시작, 끝 (소요 시간)`으로 읽히며, 각 항목에는 검증 탭에 자체 **최근 실행** 목록이 있습니다.
- **저장소 크기와 중복 제거 추세.** **저장 공간** 카드는 각 섹션이 얼마나 차지하는지와 데이터가 얼마나 잘 중복 제거되는지 보여 줍니다.
- **복원 검증 훈련.** BombVault는 백업이 복원 가능함을 주기적으로 증명합니다(`restic check --read-data-subset`, 범위 한정). **설정, 검증, 자동 검사**에서 설정합니다. 같은 타일의 **백업 확인** 카드는 섹션별 결과를 보여 주고, **더보기** 아래에 **잠금 해제**와 **정리**가 있습니다.
- **첫 백업 후 복원 확인.** 항목의 첫 백업이 끝나면 BombVault는 그 일부(최대 파일 100개, 256 MiB)를 복원 폴더 안의 임시 폴더에 복원하고, restic이 각 파일을 해시와 대조해 다시 읽게 한 뒤 크기를 백업과 비교합니다. VM 디스크처럼 샘플에 넣기에 너무 큰 파일은 대신 처음 64 MiB를 다시 읽습니다. 항목의 검증 탭에 결과가 표시되고, 실패하면 알림이 전송되며, **복원 확인**을 누르면 언제든 최신 백업에 같은 검사를 실행합니다. 이후 백업에서는 반복하지 않습니다.
- **시작 테스트.** 바이트가 맞다고 해서 앱이 다시 올라온다는 보장은 없습니다. 컨테이너의 검증 탭에 있는 **시작 테스트**는 최신 백업을 격리된 사본으로 복원하고 시작합니다. 이름은 `bombvault-test-`로 시작하고, 게시된 포트도 LAN으로 가는 경로도 없는 자체 내부 Docker 네트워크, CPU 1개와 메모리 2 GiB, 복원 폴더 안의 임시 폴더에 둔 데이터를 씁니다. 컨테이너의 헬스체크가 정상으로 보고하면 통과하고, 헬스체크가 없으면 첫 번째 노출 포트가 그 네트워크 안에서 응답할 때, 둘 다 없으면 계속 실행될 때 통과합니다. 원래 컨테이너는 절대 중지되거나 변경되지 않으며, 사본과 그 네트워크, 데이터는 테스트 후 제거됩니다. 테스트 도중 BombVault가 다시 시작되어도 마찬가지입니다. 호스트 네트워크를 쓰는 컨테이너, 특권 컨테이너, 장치를 쓰는 컨테이너, 다른 컨테이너가 필요한 컨테이너는 테스트할 수 없다고 표시됩니다. 예약된 복원 검사에서 **시작 테스트**를 켜면 실행마다 가장 오래전에 테스트한 컨테이너부터 하나씩 테스트합니다. 복사본은 원본의 레이블을 하나도 갖지 않고, 원본이 추가한 capabilities, 보안 옵션, sysctl, cgroup parent 없이 실행됩니다. 이것이 필요한 컨테이너는 테스트에 실패하고, 결과에 복사본이 무엇 없이 실행됐는지 표시됩니다.
- **자가 치유 작업.** 확실히 고아가 된 restic 잠금(작업 도중 재시작으로 남겨진 것)은 자동으로 강제 해제되고 한 번 재시도됩니다. 보존은 정체성이 안정적이며(항목별로 정리, 경로나 호스트 변경에 영향받지 않음), 보존 실패는 알림을 보냅니다.
- **폴더 스캔이 볼 수 없는 경고.** 제외 도우미는 크기에 관한 질문에 답합니다. 그런데 가장 값비싼 백업 실수 중 일부는 크기 문제가 아니므로, 애플리케이션이 데이터를 저장하는 방식에 관한 앱별 주의 사항도 함께 담고 있습니다. 이 기능이 존재하는 이유가 된 사례는 Immich입니다. Immich는 모든 사진의 앨범, 얼굴, 날짜를 *별도의* 컨테이너에서 실행되는 PostgreSQL 데이터베이스에 보관하므로, Immich 컨테이너를 파일 수준으로 백업하면 그 정보 없이 사진만 복원되고, 복원은 성공한 것처럼 보입니다. 이 경고는 제외 항목이 제안되는지와 관계없이 표시되며, 스캔할 항목이 하나도 선택되지 않은 컨테이너에서도 표시됩니다. 주의 사항은 어느 쪽이든 사실이기 때문입니다.
- **백업되지 않음(적용 범위).** 예약된 백업이 다루지 않는 서버의 모든 것을 이유와 함께 나열하는 개요 카드입니다. BombVault에 전혀 추가되지 않았거나, 있지만 일정에 없거나, 자체 일정이 꺼져 있거나, 어디에도 일정이 켜져 있지 않거나, 섹션의 모든 대상이 꺼져 있는 경우입니다. 보호 상태는 다른 질문, 곧 예약된 백업이 제때 실행되었는지에 답하며, 아무도 설정한 적 없는 컨테이너는 보지 못합니다. 컨테이너는 BombVault 자체의 행이 아니라 실시간 Docker 목록에서 읽습니다. 행이 없는 항목이야말로 이름을 불러야 하는 것이기 때문입니다. 꺼 둔 섹션과 **백업하지 않음**으로 표시한 항목은 직접 선택한 것이므로 개수에서 빠집니다.
- **보존 미리 보기.** **설정, 대상**의 **미리 보기** 카드는 다음 실행이 무엇을 삭제하려는지 실행 전에 보여 줍니다. 저장소별, 항목별로 복원 지점의 이름과 함께입니다. 저장소 잠금을 잡지 않고 아무것도 바꾸지 않으므로 백업이 실행 중일 때도 응답합니다. 보존이 꺼져 있으면 빈 목록 대신 그렇게 알려 주고, 추가 전용 저장소는 그렇게 표시되며(거기서는 보존이 아예 실행되지 않음), 닿지 못한 저장소는 조용히 빠지는 대신 이름이 표시됩니다.
- **이상 징후.** 컨테이너, VM, 폴더 세트, 데이터베이스 덤프, 플래시 드라이브, 셀프 백업의 모든 백업을 그 항목 자신의 기록과 비교합니다. 검사 대상은 다음과 같습니다. 실행에서 저장된 새 데이터를 최근 백업의 평소 가장 큰 양 및 평소 시간당 속도와 비교한 값, 데이터 대부분을 다시 저장한 백업(이름을 바꾸고 다시 쓴 파일 포함), restic이 항목마다 그리고 덤프마다 보고하는 소스 크기와 파일 수, restic 자체의 백업 시간, 연속 실패와 간헐적 실패, 더 이상 통과하지 않는 복원 검사, 그리고 저장소 증가량으로 예측한 로컬, SFTP 및 rclone 저장소의 여유 공간입니다. 항목은 처음 10번의 백업으로 학습하지만, 거의 빈 소스, 데이터 대부분의 재작성, 실패는 처음부터 검사합니다.민감도(엄격, 균형, 느슨)와 알림을 보내는 가장 낮은 심각도는 **설정, 검증**의 **이상 징후** 카드에서 전체적으로 설정하고 항목마다 검증 탭에서 바꿀 수 있습니다. 경고는 원인이 사라지면 스스로 닫힙니다. 잃어버린 데이터와 차오르는 디스크에 대한 심각한 발견은 확인할 때까지 남아 있고, 확인한 발견은 그 원인이 한 번 사라지기 전에는 다시 보고되지 않습니다. **예상된 것으로 표시**는 10번의 백업 뒤에 새 수준을 정상으로 만들지만 거의 빈 소스 검사는 절대 끄지 않으며, 선택을 바꾸면 항목의 기록이 저절로 새로 시작됩니다. 소스가 거의 비었거나, 크게 줄었거나, 한 백업이 데이터 대부분을 다시 저장한 동안에는 발견을 확인하거나 예상된 것으로 표시할 때까지 보존 정책이 그 항목의 오래된 백업을 남겨 두고, 발견은 마지막 정상 백업으로 연결됩니다. 알림은 한 사건마다 한 번 보내며, 이미 알림을 보내는 실패와 복원 검사는 두 번 보고하지 않습니다. 하지 않는 일: S3, B2, REST 저장소에는 여유 공간 값이 없고, Unraid 사용자 공유에서는 여유 공간이 어레이 전체의 것이며, restic 0.17 이전의 백업에는 크기 기록이 없습니다. ZFS 항목도 데이터세트별로 검사합니다. 트리의 각 데이터세트는 자기만의 기록을 가지며, 비워졌거나 더 이상 읽을 수 없게 된 데이터세트는 데이터 손실로 취급되고, 그 데이터세트의 오래된 백업만 보존됩니다. ZFS 항목을 데이터세트별로 살피는 방식은 [ZFS 데이터세트](zfs-datasets.md#anomalies)에 설명되어 있으며, 어시스턴트는 [MCP 서버](mcp.md#tools)를 통해 열린 이상 징후를 읽을 수 있습니다. 소스의 크기나 파일 수에 관한 탐지는 처음 나타난 백업의 시점으로 표시되며, **이전 백업과 비교** 는 파일이 사라지거나 새로 들어오거나 바뀐 폴더를 나열하고, 거의 전부가 앱이 스스로 다시 만드는 검색 인덱스, 캐시 또는 미리보기 이미지에 있으면 그 점을 알려 줍니다.
- **이상 징후 페이지.** **심각**, **경고**, **참고** 타일이 심각도를 고르며, 목록 위에 열린 발견과 닫힌 발견이 있습니다. 심각한 발견도 다른 발견과 같은 면에 놓이며, 심각도는 배지와 색이 있는 테두리로 나타납니다. 발견은 먼저 해결 방법을 제시하고, 세부 정보에서는 값이 평소 범위 위의 곡선으로 표시됩니다. 열린 것이 없으면 항목별 링이 감지가 무엇이 정상인지 어디까지 학습했는지 보여 줍니다.
- **앱별 권장 제외.** 잘 알려진 이미지(Plex, Jellyfin, Emby, Sonarr, Radarr, Lidarr, Readarr, Prowlarr, Immich, Nextcloud, PhotoPrism, Tautulli. linuxserver, hotio, binhex 또는 공식 게시자의 것)에 대해 **제외 패턴** 카드의 제외 도우미가 앱이 스스로 다시 채우는 폴더를 제안합니다. 캐시, 로그, 미리 보기 이미지, 포스터입니다. 각 줄은 무엇이 들어 있는지 알려 주고, 어느 것이든 끌 수 있으며, **선택 항목 제외**를 누르기 전까지는 아무것도 제외되지 않습니다.
- **버그 신고.** **설정, 정보**의 **도움말** 카드에 있는 **버그 신고**는 GitHub 이슈용으로 민감 정보를 지운 ZIP을 내려받습니다. 호스트 통합 검사, 모든 비밀을 제거한 구성, 최근 실행, 다음 예약, 최근 로그입니다. 각 데이터베이스의 마지막 덤프가 어떻게 되었는지, 컨테이너가 보는 마운트가 있는 ZFS 항목, 열린 이상 징후, MCP 키가 몇 개인지(이름은 절대 아님)도 담습니다. 비밀번호, 토큰, rclone 설정, 알림 자격 증명, 저장소 위치에 내장된 비밀번호는 모두 제거되며, 번들은 자체 매니페스트에도 그렇게 적습니다. 지원용 파일을 구성 백업으로 오인해서는 안 되기 때문입니다. 복구 키트와 같은 이유로 로그인 비밀번호가 필요합니다. 담기는 로그는 이 컨테이너가 마지막으로 시작된 뒤의 출력입니다. 컨테이너를 재시작시킨 충돌은 계속 `docker logs`를 보세요.
- **복구 키트.** **설정, 복원**의 **복구 키트 다운로드**는 키, 파생된 restic 비밀번호, 정확한 저장소 위치와 명령을 주므로, 실행 중인 BombVault 없이도 복원할 수 있습니다. 로그인 비밀번호가 필요합니다. [오프사이트 및 복구](offsite-recovery.md#recovery-kit)를 참고하세요.
- **설정 내보내기와 가져오기.** **설정, 시스템**의 **설정 내보내기 / 가져오기** 카드는 전체 구성(섹션 설정, 대상, 일정, 보존, 알림)을 이식 가능한 JSON 파일로 기록하므로, 새 장비로 옮기거나 설정을 복제할 때 모든 것을 손으로 다시 입력할 필요가 없습니다. 오프사이트와 알림 자격 증명을 포함할지는 직접 고르며, 포함하면 파일은 복구 키트만큼 민감합니다. 가져오기는 미리 보기를 표시하고 확인을 요청하며, 백업 데이터나 기록을 건드리지 않습니다.
- **알림.** 웹훅(Discord / Slack / Gotify / ntfy), Matrix, Healthchecks.io, 이메일(SMTP), 셀프 호스팅 [Apprise API](https://github.com/caronc/apprise-api) 서버, Unraid의 기본 알림 시스템. 백업별 정책: 안 함 / 실패 시 / 항상. 많은 항목의 예약 실행은 *N개 중 M개 항목 성공*이라는 요약 하나를 보낼 수 있습니다. URL이 설정되어 있으면 Healthchecks는 전체 수명 주기(`/start`, 이어서 성공 또는 `/fail`)를 받습니다.
- **주간 요약.** 같은 채널로 일주일에 한 번 보냅니다. 실행 횟수, 도착한 새 백업 데이터의 양, 오프사이트가 최신인지, 주요 실패입니다. 기본은 꺼짐이며 **설정, 알림**에 자체 주기가 있어 조용한 주도 그렇게 보고됩니다.
- **Prometheus `/metrics`.** 선택 사용(기본 꺼짐, 선택적 bearer 토큰)이며 **설정, 연동**의 **서비스** 카드에 있어 Grafana나 Uptime Kuma용입니다. 백업 상태, 크기, 타임스탬프를 내보내며 레이블에는 비밀이나 경로가 없습니다.
- **HTTP API, Home Assistant, mDNS.** 스크립트와 대시보드는 이름이 있는 토큰으로 `/api/v1` 아래 API를 쓰며, 읽기 전용이거나 백업 시작이 허용될 수 있습니다. Home Assistant는 MQTT 디스커버리로 BombVault를 찾아 센서가 있는 장치로 보고, 허용하면 섹션별 백업 버튼도 둡니다. 또 BombVault는 네트워크에서 `bombvault.local`로 자신을 알립니다. [API 및 연동](api.md)을 참고하세요.
- **여유 공간과 가득 찰 때까지의 주 수.** 보고하는 로컬 저장소, SFTP 저장소, SMB 또는 WebDAV 대상은 여유 공간과 현재 증가 속도로 몇 주가 남았는지 표시합니다. S3, B2, REST 저장소는 해당 백엔드가 보고하지 않으므로 "크기 알 수 없음"이라고 표시합니다.
- **폴더별 크기.** 컨테이너, VM, 폴더 세트의 검증 탭에서 **폴더별 크기**는 최신 백업에서 어떤 폴더와 파일이 공간을 차지하는지, 최근 백업이 그중 얼마를 새로 또는 변경으로 가져왔는지를 한 단계씩 보여 줍니다. BombVault는 파일을 읽지 않고 저장소 인덱스에서 읽으며, 한 번 열어 본 뒤에는 백업마다 최신 상태로 유지합니다.
- **백업이 느렸던 이유.** 백업이 도는 동안 BombVault는 CPU, 디스크, 네트워크가 얼마나 바쁜지 봅니다. 백업이 평소보다 훨씬 오래 걸리고 한 가지가 분명히 한계에 있었다면 실행 기록에 그 내용이 나옵니다. 예를 들어 "대상 디스크 disk1의 사용률이 98%였습니다" 또는 "BombVault가 컨테이너 CPU 한도의 100%를 사용했습니다"입니다. 그렇지 않으면 아무것도 표시하지 않습니다.
- **마지막 백업 이후 변경됨.** 마지막 백업 이후 다른 이미지, 포트, 변수, 볼륨으로 다시 만들어진 컨테이너는 이름 옆에 표시가 붙습니다. 그 (i)는 바뀐 내용을 보여 주며 변수는 이름만 표시합니다. 알림일 뿐이며 다음 백업 후에 사라집니다.

## 랜섬웨어 보호

- **삭제 방지(추가 전용).** 오프사이트 대상에서 켜면 랜섬웨어나 침해된 호스트가 백업을 삭제하거나 다시 쓸 수 없습니다. 맞은편(`--append-only` 모드의 `restic/rest-server`)이 강제하며, BombVault는 검증만 하고 설정상의 주장만으로 초록을 표시하는 일은 없습니다. 이 서버의 폴더는 삭제를 거부할 수 없으므로 로컬 대상에는 스위치가 없습니다.
- **변조 테스트.** BombVault는 오프사이트 저장소에 실제로 삭제를 시도(존재하지 않는 객체를 겨냥)하여 추가 전용 보장을 주기적으로 증명합니다. 거부되면 보호됨, 허용되면 보호되지 않음입니다. 결론이 나지 않은 결과가 저장된 판정을 뒤집는 일은 없습니다. 대상 페이지의 **지금 삭제 방지 테스트**는 필요할 때 바로 실행합니다.
- **안내형 설정.** **대상 추가**는 공급자 선택에서 로그인, 연결 테스트, 폴더를 거쳐 삭제 방지에 대한 솔직한 안내와 거기에 백업하는 섹션까지 안내합니다.
- **DR 훈련(오프사이트).** 시험 복원은 오프사이트 저장소에서 실제 대상을 격리된 샌드박스에 놓고 파일 단위, 바이트 단위로 검증한 뒤 정리합니다. [오프사이트 및 복구](offsite-recovery.md)를 참고하세요.
- **보호 상태.** 개요 카드는 각 섹션에 대해 최신 백업, 오프사이트 사본, 거기서의 삭제 방지, 거기서 하는 시험 복원을 검사합니다. 검증된 사실에서만 초록이 됩니다.
- **증가 예산 경보.** 추가 전용 대상(여기서는 오래된 백업을 절대 정리하지 않음)에 크기 예산을 설정하면, 폭주하기 전에 알림을 받습니다.
- **삭제에는 비밀번호가 필요합니다.** 대상의 백업을 삭제하려면 로그인 비밀번호와 인스턴스 자체에서의 로그인이 필요하므로, 페어링된 휴대폰도 열린 화면도 삭제할 수 없습니다.
- **문구로 페어링.** 인스턴스는 12개 단어로 하나의 그룹에 합류합니다. 한 곳에서 문구를 만들고 다음 곳에서 입력합니다. 같은 네트워크의 구성원은 직접 통신하고 나머지는 릴레이(프로젝트 릴레이, 직접 운영하는 릴레이, 또는 없음)를 거치며, 그 사이의 모든 호출은 종단 간 암호화됩니다. 그룹이 나르는 것은 인스턴스 페이지의 보호 상태, 역할 요청, 대상 제안, 역할이 허용된 뒤 수신기나 가져오기 측에 필요한 것이며, 백업 데이터와 APP_KEY는 절대 아닙니다. [오프사이트 및 복구](offsite-recovery.md#pairing)를 참고하세요.
- **인스턴스와 역할.** **설정, 인스턴스, 여러 서버**에서 **인스턴스**를 켜면 이 인스턴스를 포함해 그룹의 모든 인스턴스에 카드가 있는 페이지가 생깁니다. 주소, 연결 여부, 각 섹션의 보호 상태와 마지막 백업입니다. 역할은 카드에 타일로 나옵니다. **수신기**, **가져오기 측**, **ZFS 서버**, **키 보관 측**입니다. 역할은 상대 인스턴스에서 누군가 **허용**을 눌러야 시작되고, 그룹은 누가 누구를 위해 무엇을 하는지 그물로 보여 줍니다. **지금 확인**은 구성원에게 한 섹션의 저장소를 검증하도록 요청합니다. 이 페이지에서는 다른 장비에서 백업, 복원, 삭제를 시작할 수 없습니다. [인스턴스와 역할](offsite-recovery.md#roles)을 참고하세요.
- **대상 제안.** 구성원은 그룹을 통해 자신의 오프사이트 대상을 다른 구성원에게 제안할 수 있습니다. 상대 관리자는 인스턴스 페이지에서 구성원의 **세부 정보**에서 제안을 보고 수락하거나 거절합니다. 수락하면 일반 자격 증명 세트와 대상이 만들어집니다. 이렇게 오가는 것은 연결 정보뿐이며 백업 데이터는 절대 아닙니다.
- **수신한 저장소(수신 측).** 다른 BombVault로부터 추가 전용 오프사이트 사본을 받는 장비에서 **설정, 인스턴스**의 **수신기**를 켜고, 보내는 구성원의 **세부 정보**에서 수신한 저장소를 읽기 전용으로 추가합니다(보내는 인스턴스의 restic 비밀번호로 열며, 이는 페어링 그룹을 통해 도착함). 소스별로 묶은 백업 목록, 각 소스가 마지막으로 도착한 시각을 보고, 수신 하드웨어에서 독립적인 `restic check`를 실행할 수 있습니다. 소스가 설정한 기간 안에 보내지 않거나(데드맨 스위치) 무결성 검사가 실패하면 알려 줍니다. 엄격히 읽기 전용이라 수신한 저장소에 쓰지 않으며 기본은 꺼짐입니다. [오프사이트 및 복구](offsite-recovery.md#receiver)를 참고하세요.
- **다른 인스턴스에서 가져오기(가져오는 측).** 오프사이트 복사의 거울상입니다. 이 장비가 백업을 밖으로 밀어내는 대신 다른 곳의 것을 가져옵니다. **설정, 인스턴스**에서 **가져오기**를 켜고, 다른 구성원의 **세부 정보**에서 소스를 추가합니다. 저장소 위치, 어떤 종류의 백업을 담고 있는지, 얼마나 자주 가져올지입니다. 그 restic 비밀번호는 그룹을 통해 오고 APP_KEY는 절대 오지 않습니다. 맞은편은 더 설정할 것이 없고 실행 중일 필요도 없습니다. 소스 저장소는 읽기만 합니다. 비밀번호 확인을 위해 열고, 나열하고, 복사의 소스로 지정할 뿐, 초기화, 잠금 해제, 정리, 쓰기는 절대 하지 않습니다. 각 쪽이 자신의 자격 증명을 유지하며, `rclone:` 소스는 rclone이 이 인스턴스의 리모트로 접근하게 되므로 거부됩니다. [오프사이트 및 복구](offsite-recovery.md#receiver)를 참고하세요.
- **키 보관 측.** 그룹의 다른 인스턴스가 이 서버의 복구 키트를 봉인한 사본으로 보관할 수 있습니다. 20자 수령 코드만이 그것을 열 수 있고, 그곳에서 누군가 **허용**을 누른 뒤에만 내줍니다. [키 보관 측](offsite-recovery.md#key-keeper)을 참고하세요.

## 일반 내보내기

- **컨테이너와 VM 내보내기.** 항목 페이지의 **더보기** 아래 **컨테이너 내보내기**와 **VM 내보내기**는 저장소 옆에 탐색할 수 있고 도구가 필요 없는 사본을 기록합니다. 컨테이너의 백업 폴더를 지금 상태로 Unraid 템플릿과 함께, 또는 VM의 디스크 이미지와 정의를 `virsh define`과 디스크로 복원할 수 있는 형태로, BombVault도 restic도 필요 없습니다. 백업의 **내보내기**는 저장된 백업을 같은 방식으로 tar, zip, 또는 별도의 restic 저장소로 기록합니다. restic이 엔진이라는 점은 그대로이며, 이것은 추가 편의 사본입니다.
- **일반 내보내기 암호화(age).** 내보내기는 restic 밖에 있으므로 기본으로 평문입니다. **설정, 시스템**에서 **age 로 내보내기 암호화**를 켜고 수신자를 하나 이상 추가하세요(age 공개 키 또는 SSH 공개 키). 플래시 ZIP을 포함한 각 내보내기는 그 수신자용으로 봉인되며, 나중에 장비 밖에서 해당 개인 키로 복호화합니다. 안전 규칙으로, 암호화가 켜져 있는데 유효한 수신자가 없으면 내보내기는 평문을 쓰는 대신 분명한 오류와 함께 실패합니다.
- **복구 키트도 봉인됩니다.** 같은 설정이 켜져 있으면 키트는 `bombvault-recovery-kit.md.age`로 다운로드됩니다. 바이너리가 아니라 ASCII 아머 형식이므로 그대로 읽을 수 있는 일반 텍스트입니다. 비밀번호 관리자에 붙여 넣거나 인쇄할 수 있으며, 키트는 바로 그런 용도입니다. 같은 안전 규칙이 적용되므로, 암호화가 켜져 있는데 쓸 수 있는 수신자가 없으면 마스터 키를 평문으로 내주는 쪽으로 돌아가지 않고 다운로드를 거부합니다. 이것을 켤 때 제대로 챙겨야 할 점이 하나 있습니다. 키트를 열려면 age 개인 키가 필요하므로, 그 키는 키트 자체에 의존하지 않는 곳에 보관하세요.

## AI 어시스턴트 (MCP) {#mcp}

BombVault에는 MCP 서버가 내장되어 있어 Claude Code나 Claude Desktop 같은 어시스턴트가 백업 상태, 적용 범위, 실행 기록, 복원 지점, 진행 중인 활동을 읽을 수 있습니다. 허용된 키가 있으면 어시스턴트는 한 항목, 한 섹션 또는 전체의 백업을 시작하고 자신이 시작한 백업을 취소할 수도 있습니다. 복원, 삭제, prune, 설정은 웹 인터페이스에 남습니다. 클라이언트마다 **설정, 연동, MCP 서버**에서 자신의 키를 받습니다. 키는 한 번만 표시되고 지문으로만 저장되며, 언제든 이름을 바꾸거나 교체하거나 폐기할 수 있습니다. 시작은 시간당과 항목당으로 제한되고, 보존 가드가 어시스턴트의 백업이 "최근 N개 보존" 정책에서 여러분의 복원 지점을 밀어내지 못하게 합니다. 어시스턴트가 시작한 실행에는 키 이름과 함께 "MCP 경유"가 표시됩니다. [MCP 서버](mcp.md)를 참고하세요. 데이터베이스 덤프와 [ZFS 데이터세트](zfs-datasets.md)도 어시스턴트가 읽는 항목과 복원 지점에 포함되며, BombVault가 발견한 이상 징후도 나열할 수 있습니다.

## 앱과 동반 도구 {#apps}

- **Android 앱.** 그룹의 모든 서버를 휴대폰에 담고, 모든 서버의 활동 로그를 한 화면에 보여 줍니다. QR 코드로 그룹과 페어링하며 각 서버를 이미 로그인된 상태로 엽니다. 세션은 앱이 보여 주는 것에만 닿습니다. [Android 앱](android.md)을 참고하세요.
- **수신 서버.** 오프사이트 사본을 받는 장비는 처음 **수신기** 요청을 허용할 때 설정되는 추가 전용 rest-server를 실행하고, 그룹의 다른 인스턴스에 각각 전용 로그인과 함께 제공합니다. [수신 서버](offsite-recovery.md#receiving-server)를 참고하세요.
- **설정, 앱.** 맨 위에 Android 앱 카드가 있어 서버가 실행 중인 릴리스의 APK와 그 QR 코드를 제공하고, 이어서 동반 도구마다 카드가 있는 페이지입니다. ParleyPort 카드는 Unraid 템플릿을 제공하고, ParleyPort를 시작하는 Docker 명령을 복사해 주며, 그 저장소와 페어링 아래의 릴레이 설정으로 안내합니다. BombVault Widget 카드는 템플릿과 저장소를 제공하고, 호스트 SSH 연결을 통해 플러그인을 설치하거나 제거합니다.
- **BombVault Widget.** Unraid 대시보드의 타일로, BombVault의 활동 로그와 다음 예약 실행을 보여 줍니다. 호스트 SSH 연결이 없으면 카드는 **Plugins, Install Plugin**에서 설치할 `.plg` 주소를 알려 주며, 플러그인은 다른 플러그인처럼 그곳에서 제거할 수 있습니다.
- **임베드 가능한 활동 로그.** **설정, 연동**의 **대시보드 위젯** 카드에서 읽기 전용 토큰을 만들면 Homepage, Organizr, Heimdall처럼 iframe을 보여 주는 모든 대시보드용 주소가 생깁니다. 실시간 활동 로그만 있는 작은 페이지입니다. 토큰은 그 로그만 허용하며, **끄기**는 즉시 폐기합니다. 임베드 페이지는 영어로만 제공됩니다.

## 기타

- **실행 중인 백업 멈추기.** 실행이 활성인 동안 진행 상황 옆에 **백업 취소**가 있습니다. 실행은 실패가 아니라 *취소됨*으로 기록됩니다. restic이 스냅샷을 마지막에 쓰므로 멈추는 것은 안전하며, 중단된 실행은 참조되지 않는 데이터만 남기고 스냅샷은 남기지 않습니다.
- **여럿을 한꺼번에 백업.** 백업 목록에서 항목을 선택하고 선택한 것을 백업합니다. 일괄 작업은 서버에서 실행되므로 탭을 닫거나 연결이 끊겨도 계속됩니다. BombVault는 자신의 컨테이너를 백업하지 않으며(따라서 멈추지도 않습니다).
- **백업당 메모리 제한.** **설정, 시스템**의 **성능** 카드에 있는 **백업당 메모리 제한 (MiB, 0 = 없음)**은 각 백업 프로세스에 느슨한 상한을 둡니다. 상한에 가까워지면 restic이 메모리를 더 자주 비우므로, 큰 백업은 메모리 부족으로 강제 종료되는 대신 느려집니다. 0이면 제한이 없습니다.
- **항목 페이지의 백업.** 복원 지점 목록, 백업별 삭제, 자신만의 태그, 두 백업의 비교가 있습니다.
- **섹션별 저장소 유지 관리.** **설정, 검증**의 **백업 확인** 카드에서 검사(`restic check`)와, **더보기** 아래 **잠금 해제**(남은 잠금 제거) 및 **정리**(보존 정책이 있으면 요청 시 적용하고, 없으면 단순한 공간 회수)를 실행합니다.
- **검사, 복원 검사, 정리의 진행 상황.** 이 중 하나가 실행되는 동안 활동 로그와 **백업 확인** 카드는 restic이 어디까지 세었는지를 *47개 팩 중 12개*처럼 보여 주고, 추정할 만큼 데이터가 쌓이면 그 단계의 남은 시간도 보여 줍니다. restic은 여기서 바이트가 아니라 팩, 스냅샷, 인덱스 파일을 세므로 막대가 보여 주는 것은 그것입니다. 첫 집계 전에는 숫자 없이 실행됩니다.
- **데이터베이스 자동 덤프.** 인식된 PostgreSQL, MySQL, MariaDB 컨테이너(공식 이미지, PostGIS, TimescaleDB, pgvector, pgautoupgrade, Immich의 데이터베이스 이미지, linuxserver, yobasystems, jc21의 MariaDB, Oracle의 mysql-server)는 백업 전마다 실행 중인 서버에서 덤프됩니다. 데이터베이스처럼 보이기만 하는 컨테이너도 카드에 설정 탭의 **데이터베이스** 카드에서 같은 선택지를 받지만, 직접 켤 때까지는 꺼져 있습니다. 덤프는 저장소로 곧장 흘러들어 파일 백업 옆에 자체 복원 지점이 되며, 디스크에는 결코 기록되지 않습니다. 자격 증명은 컨테이너 자신의 변수에서 오고(`*_FILE` 비밀 포함), 컨테이너를 떠나지 않습니다. 이 카드는 데이터베이스의 데이터 폴더가 컨테이너를 멈춘 상태로 저장되는지, 실행 중에 복사되는지, 아예 저장되지 않는지 보여 줍니다. 덤프가 실패해도 백업은 실패하지 않습니다. 이유와 해결 힌트가 붙은 실패한 실행으로 나타나고 알림을 보냅니다. 덤프가 저절로 되돌려지는 일은 없습니다. 덤프를 내려받고(원본 또는 압축), 폴더에 저장하고, 갓 시작한 데이터베이스로 한 번의 클릭으로 가져오거나, restic CLI로 꺼낼 수 있습니다. 컨테이너별로, 라벨 `bombvault.dbdump=false`로, 또는 **설정, 일반**의 **데이터베이스 자동 덤프**로 모든 컨테이너에 대해 끌 수 있습니다. 이상 징후 감지는 각 덤프의 크기도 살피며, 어시스턴트는 [MCP 서버](mcp.md#tools)를 통해 컨테이너의 덤프를 나열할 수 있습니다.
- **컨테이너별 전후 명령.** 컨테이너 안에서 실행되는 셸 명령(예: 캐시 비우기). 백업 전 명령이 실패하면 백업이 중단됩니다. 인식된 데이터베이스는 자동으로 덤프되므로 명령이 필요 없습니다.
- **앱이 사용 중이면 대기.** 백업은 컨테이너를 멈추므로, 예약된 백업은 누군가 앱을 쓰는 동안 기다릴 수 있습니다. **백업 전 명령**이 코드 75(`EX_TEMPFAIL`)로 끝나거나, 컨테이너 **설정** 탭의 **앱이 사용 중일 때** 카드에 있는 검사가 앱이 사용 중이라고 판단하면, 실행은 실패가 아니라 호박색 **미뤄짐**으로 기록됩니다. 실행의 나머지는 계속되고, 컨테이너는 저절로 다시 시도됩니다. **다시 시도 간격(분)**에서 정한 분마다, 원하면 **시도 시간대**로 정한 두 시각 사이에서만(22:00과 06:00 같은 시간대는 자정을 넘기며, 서버의 시간대를 따릅니다), 그리고 처음 미뤄진 뒤 최대 **최대 대기 시간(시간)**까지 시도합니다. **대기가 끝나면** 포기하고 **조치 필요**에 **다시 시도**가 있는 실패한 실행을 기록하거나, 그래도 백업합니다. 다른 백업이 실행 중이면 시도는 기다리고, 대기는 재시작 후에도 이어집니다. 알림은 시도마다 오지 않고, 백업이 미뤄질 때 한 번, 백업이 완료되거나 대기가 끝날 때 한 번 옵니다. 요약 모드에서는 미뤄진 사실이 실행 요약에 나옵니다. 개요, 백업 목록, 항목에는 다음 시도와 함께 **미뤄짐**이 표시되고, 활동 로그에는 그 시각이 나옵니다. 기한 초과 알림과 보호 상태는 미뤄진 백업을 그 기한까지 기다려 줍니다. 그 밖의 종료 코드는 여전히 백업을 실패시킵니다. 직접 시작한 백업은 항상 바로 실행됩니다. **지금 백업**, **조치 필요**의 **다시 시도**, 선택 항목 백업, API나 MCP로 시작한 백업은 검사와 종료 코드 75를 무시하며, 그중 하나가 완료되면 걸려 있던 대기가 끝납니다. [문제 해결](troubleshooting.md#deferred-backups)을 참고하세요.
- **먼저 미디어 서버에 묻기.** 같은 카드의 **활동 확인**은 예약된 백업 전에 Plex, Jellyfin, Emby에 누군가 시청 중인지 물어보며, 직접 스크립트를 쓸 필요가 없습니다. Plex에는 Plex 자체의 `Preferences.xml`에 있는 토큰으로 묻고, Jellyfin과 Emby에는 **API 키**가 필요합니다. 키는 암호화되어 저장되고 다시는 표시되지 않습니다. 재생 중인 세션과 일시 정지된 세션은 모두 백업을 기다리게 하며, **일시 정지 세션 무시 기준(분)**을 설정하면 밤새 일시 정지해 둔 영화는 더 이상 세지 않습니다. BombVault는 컨테이너에 닿을 수 있는 곳에서는 서버에 직접 묻고, 그렇지 않으면 컨테이너 안에서 curl이나 wget을 실행하므로 br0나 macvlan에 있는 컨테이너에서도 됩니다. **서버가 응답하지 않으면 백업**은 서버에 물을 수 없을 때 어떻게 할지 정합니다. 켜면 백업이 실행되고 로그에 그렇게 남으며, 끄면 누군가 시청 중인 것처럼 기다립니다.
- **컨테이너가 데이터를 보내는 동안 대기.** 게임 서버나 다운로더처럼 그런 검사가 없는 앱에서는 **컨테이너가 데이터를 보내는 동안 대기**가 Docker 자체 카운터를 기준으로, 최근 **조용한 시간(분)** 동안의 어느 측정에서든 컨테이너가 **사용 중 기준(KiB/s)**보다 많이 보냈다면 예약된 백업을 미룹니다. 호스트 네트워크의 컨테이너에는 이 카운터가 없으므로 그대로 백업됩니다.
- **백업 중 다른 컨테이너 중지, 상태 게이트 재시작 포함.** 이 컨테이너가 백업되는 동안 중지할 종속 컨테이너(예: 데이터베이스)를 지정하세요. 이후 BombVault는 Compose의 `depends_on` 순서대로 다시 가져오고, 기본적으로 각 컨테이너가 정상 상태(또는 헬스체크가 없으면 실행 중)를 보고할 때까지 기다린 후에 그에 의존하는 컨테이너를 시작합니다. 따라서 Pi-hole, 데이터베이스, VPN 게이트웨이 같은 종속 항목이 그것을 필요로 하는 서비스보다 실제로 먼저 가동되어, 그 서비스가 *connection refused*로 되돌아가는 일이 없습니다. 대기는 컨테이너별 타임아웃(기본 120초)으로 제한되므로 느리거나 절대 정상이 되지 않는 컨테이너가 실행을 멈추게 할 수 없습니다. 대기와 타임아웃은 모두 **설정, 일정**의 **순서** 카드에 있는 **백업 후 재시작** 아래에 있습니다(한꺼번에 재시작하려면 대기를 끄세요). 동일한 순서화된 상태 게이트 재시작은 사후 백업 이미지 업데이트도 감싸므로, 업데이트가 도착하는 날에는 종속 항목이 재생성 동안 내려간 상태로 유지되고 완료된 후에만 상태 게이트를 거쳐 다시 가동됩니다.
- **컨테이너별 제외 패턴.** 백업되는 볼륨 내부에서 건너뛸 하위 디렉터리를 한 줄에 하나씩 나열하세요. 컨테이너 내부에서 보이는 대로 경로를 입력하세요. 실시간 미리 보기가 각 줄이 무엇으로 해석되는지 보여주고, 어떤 줄이 아무것도 제외하지 않으면 경고합니다. Host Data 밖에 있는 폴더(익명 Docker 볼륨 등)의 줄은 백업되지 않았다는 경고를 끕니다([문제 해결](troubleshooting.md#data-outside-host-data)).
- **백업 성공 후 업데이트(기본 꺼짐).** **설정, 일정, 백업 후 업데이트**의 **백업 성공 후 컨테이너 업데이트**를 켜거나 개별 컨테이너를 자신의 페이지에서 다르게 설정하면 BombVault가 최신 이미지를 가져와 재생성하지만, 실제로 더 새로운 이미지가 있을 때만 그렇게 하므로 항상 새 복원 지점이 먼저 존재합니다. 선택적 추가 기능: 업데이트된 컨테이너별 알림과 이미지 정리(다른 컨테이너가 공유하는 기본 이미지는 절대 삭제되지 않음). 업데이트 후 BombVault는 Unraid에 그 컨테이너의 업데이트 상태를 다시 확인하도록 요청하므로, Docker 탭의 오래된 *update available* 배너가 남아 있는 대신 스스로 지워집니다(Unraid 업데이트는 Docker API를 바로 거치므로, 그 캐시된 상태와 일부 버전에서는 캐시된 다이제스트가 그렇지 않으면 계속 배너를 표시함). 최선 노력 방식이며 백업에 절대 영향을 주지 않고, 기본적으로 켜져 있으며 같은 카드의 **컨테이너를 업데이트한 후 Unraid의 업데이트 상태 새로 고침**으로 전환합니다.
- **다른 폴더로 복원**하여 복제 또는 검사에 사용합니다.
- **업데이트 후 새 기능.** 새 버전마다 한 번 직전에 쓰던 버전 이후의 릴리스마다 카드가 하나씩 있는 창이 저절로 열리며, 최신 릴리스가 맨 위에 옵니다. 각 카드에는 릴리스 노트와 그 릴리스가 가져온 변경이 표시되며, 페이지에 나타나는 변경에는 **바로 가기**가 붙습니다. 노트는 바이너리에 내장되어 있으므로 창은 오프라인에서도 작동합니다. 초록 점이 각 변경을 해당 페이지에 표시합니다. **설정, 정보**의 버전 카드에 있는 **새 소식**은 아직 보지 않은 것의 수를 **새 소식 · 4**처럼 세고, 같은 창을 엽니다.
- **정보.** **설정, 정보**에는 **버전**(BombVault, GlimStone, restic, rclone과 **새 소식** 및 **업데이트 확인**), README 문서 버튼의 노란색으로 된 **설명서**와 **버그 신고**가 있는 **도움말**, **BombVault 정보**가 있습니다.
- **기본으로 HTTPS**(자체 서명, 또는 리버스 프록시 뒤에 자체 인증서 사용).
- **Docker 헬스체크.** 컨테이너는 자체 `/api/health`에서 정상/비정상을 보고하므로, 엔진이 멈추면 자가 치유 도구가 재시작할 수 있습니다.
- **42개 언어**를 **설정, 모양**의 국기 선택기로 쓸 수 있습니다.
- **설정은 저절로 저장됩니다.** 스위치를 바꾸거나 입력란을 벗어나면 변경이 즉시 기록되고, 컨트롤이 잠깐 깜박이며, 서버가 거부하면 흔들립니다. 중간 상태로 저장하면 안전하지 않은 몇 곳에는 저장 버튼이 남아 있습니다. rclone 설정 상자, 자격 증명 세트 편집기, 로그인 비밀번호 등입니다.
- **조용한 알림.** **설정, 모양**에서 정기 확인 메시지를 음소거하면 실패만 방해합니다. 이는 알림 채널에는 영향을 주지 않습니다.
- **원하는 모습으로.** **설정, 모양**에서 **테마**(다크, 라이트, 시스템), 색상(강조색 하나, 또는 여덟 가지 팔레트의 *Rainbow Mode*), 모서리(둥글게, 부드럽게, 각지게), 애니메이션(끔, 은은하게, 와일드, 스톰), 설정 타일의 순서를 정합니다. 테마, 모서리, 애니메이션은 선택지마다 기호를 보여 주며, 버튼의 라벨 모드가 **기호**이면 선택지는 기호만 보이고 이름은 마우스를 올렸을 때의 말풍선에 나옵니다. BombVault는 모양을 서버에 보관하며, 처음 오는 브라우저는 그것을 이어받습니다. 대상의 용기 속 액체는 출렁이고, 로고는 누르고 있을수록 더 세게 흔들리다가 터집니다. 사이드바에서, 그리고 휴대폰에서는 개요 위에서 그렇게 됩니다. 시스템이 움직임 줄이기를 요청하면 항상 그것이 우선합니다.
