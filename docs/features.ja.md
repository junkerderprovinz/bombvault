# 機能

BombVault がバックアップするものはすべて 1 つの一覧に並び、各項目に専用のページがあり、復元は 1 つのページから始まり、設定はタイルです。オンにする詳細モードはありません。まれな操作には専用のカードかウィンドウがあります。このページでは機能全体をまとめています。

## バックアップ範囲

![バックアップの一覧。各項目の直近の実行が帯で並び、状態が 1 つと操作が付きます。](assets/screenshots/containers.png)

*バックアップの一覧。各項目の直近の実行が帯で並び、状態が 1 つと操作が付きます。*

| セクション | 保存される内容 |
|---|---|
| **コンテナ** | Appdata ディレクトリに加え、コンテナ定義（イメージ、環境変数、ポート、ラベル、ボリューム）。既定では appdata ディレクトリ全体です。コンテナの **設定** タブにある **バックアップ対象フォルダ** カードで、バックアップが対象とするフォルダーを正確に選べます。パスの数がリアルタイムで表示され、外したものの一覧と、**キャッシュフォルダをスキップ（CACHEDIR.TAG）** スイッチがあります。TrueNAS の ixVolume のように Host Data の外にあるコンテナのデータはバックアップされず、実行は対象外にしたフォルダーを示します。 |
| **VM** | VM ディスクイメージ、XML 定義、UEFI NVRAM（正常シャットダウンまたはライブスナップショット、SSH 経由）。スナップショットを作れない場合、ライブスナップショットは自動的に正常シャットダウン方式のバックアップに切り替わるため、VM バックアップが単にエラーで終わることはありません。**変更ブロックのみ** をオンにすると、qcow2 ディスクの稼働中の VM は libvirt のチェックポイント経由で読み取られ、バックアップは前回以降に書かれたブロックだけを読みます。それでも各バックアップは単独でディスク全体を復元できます。ZFS の zvol 上のディスクは同じ SSH 接続で ZFS スナップショットから読み取られ、生イメージとして保存されます。変更のないブロックは再び保存されず、ディスクが zvol の VM も 1 つの VM としてバックアップされます。復元は各 zvol を元の場所に書き戻し、その前に置き換える内容の ZFS スナップショット（`bombvault-before-restore-<time>`）を残します。そこへ `zfs rollback` すれば復元を取り消せ、このスナップショットは自分で削除するまで残ります。ファイルとしてのエクスポートには zvol のディスクは含まれません。パススルー vTPM の状態は、ドメイン XML にそのパスがあれば NVRAM の隣に保存されます。TrueNAS が Windows 11 ゲスト向けに設定するエミュレート vTPM はそのパスを公開しないため、そのようなゲストの回復キーは手元に置いてください。[VM バックアップガイド](https://github.com/junkerderprovinz/bombvault/blob/main/docs/vm-backup-ssh-setup.md)を参照してください。 |
| **フラッシュ** | Unraid のみ。USB フラッシュ全体（`/boot`）：OS、ライセンス、アレイ設定、共有、ネットワークおよびプラグイン設定。復元は `.zip` のダウンロードで、稼働中のフラッシュを上書きすることはありません。 |
| **セルフバックアップ** | BombVault 自身の `/config`（設定データベース、保存先のサインイン情報、libvirt の SSH 鍵ペア）。SQLite の `VACUUM INTO` でスナップショットを取るため、WAL モードのデータベースが書き込み途中で取り込まれることはありません。緊急ウィザードで戻します。このウィザードは BombVault を再起動するので、稼働中のデータベースが開いたハンドルの下で上書きされることはありません。 |
| **フォルダー** | フォルダーセット：サーバー上の任意のフォルダー（共有、ドキュメント、写真ライブラリ）で、それぞれに除外パターンを任意で設定できます。バックアップページの **追加** は見つけた共有を一覧にし、ほかのフォルダーも受け付けます。フォルダーセットには、ほかのセクションと同じものがすべてあります。スケジュール、保持、オフサイトコピー、チェック、復元ドリルです。 |
| **ZFS データセット** | データセットとその下のすべてのデータセットを、1 つの ZFS スナップショットから読み取るので、すべて同じ瞬間のものになります。restic でフォルダーのように保存され、重複排除され、閲覧でき、個別のファイルを復元できます。新しい子データセットは自動で加わり、個別の子は除外でき、読み取れない子はスキップされて名前が示されます。必要に応じて、スナップショットの瞬間だけコンテナを停止したりコマンドを実行したりできます。ボリュームは含まれません。VM のボリュームはその VM と一緒にバックアップされ、VM のないボリュームはまだバックアップされません。ZFS 項目は、2 台目の ZFS サーバーにブロック単位で同一のレプリカを持つこともできます。[ZFS データセット](zfs-datasets.md)を参照してください。 |

## バックアップと項目ページ {#backups}

- **1 つの一覧。** コンテナ、VM、フォルダーセット、フラッシュ、ZFS データセット、セルフバックアップが **バックアップ** の下に 1 つの一覧で並びます。上のタイルで種類を選び、**フィルター**、**並べ替え**、**検索** で絞り込みます。並べ替えは名前、状態、最後のバックアップ、サイズ、スケジュールで、昇順にも降順にもでき、検索ではコンテナを名前、イメージ、IP で見つけられます。
- **直近の実行を帯で表示。** 行には直近 14 回の実行が小さな四角と 1 つの状態で表示されます。ほかはすべて名前の隣の情報バブルにあり、マウスを重ねると行にも同じ文章が表示されます。
- **ファイルマネージャーのように選択。** Ctrl+クリック、Shift+クリック、Ctrl+A で行を選び、スマートフォンでは長押しで選べ、**その他** の下の **選択** でも選択を始められます。選んだ行にはアイコンの代わりにチェックが表示され、各行には右クリックメニューがあります。選択したものは、バックアップや、スケジュールでの一時停止と再開ができます。複数の項目は復元ページでまとめて復元します。
- **追加** は、BombVault が推測できないもののために 1 つのウィンドウを開きます。フォルダーや ZFS データセットです。コンテナ、VM、フラッシュは自動で現れます。Unraid のないホストで Host Data が `/etc` まで届く場合、ウィンドウに **システム構成** が表示されます。保存前に確認する `/etc` フォルダーセットの初期案です。
- **バックアップしない** は項目をあえて対象外にします。その項目は未保護として数えられなくなり、**除外を解除** で元に戻ります。
- バックアップページの **その他** には、保存先にあるものから項目を作り直す **バックアップを検出**（たとえば新規インストール後）と、Compose プロジェクト向けの **スタックを復元** があります。
- **すべての項目に専用のページ** があり、状態を示して操作を並べたヘッダー、アイコンの左にある一覧へ戻るボタン、3 つのタブがあります。
    - **バックアップ** は、バックアップを日ごとのバーで、それを保持している保存先、データベースダンプとともに一覧にします。
    - **設定** には、スケジュールと保存先、リポジトリ、バックアップ対象フォルダー、除外パターン、停止する他のコンテナ、前後のコマンド、データベースダンプ、以前の名前があります。スケジュールと保存先は、項目が独自の設定を持つまでセクションの既定に従います。
    - **検証** には、チェック、フォルダー別のサイズ、項目の異常の監視、最近の実行が表示されます。
- **印を付けて比較。** バックアップには独自のタグを付けられ、**別のバックアップと比較** は 2 つのバックアップの間で増えた、消えた、変わったファイルを一覧にします。VM ではディスクイメージを比較し、どれだけ違うかを示します。
- **エクスポート** は、バックアップ、項目のすべてのバックアップ、または今の状態のコンテナや VM を、サーバーのエクスポートフォルダーに tar、zip、または独立した restic リポジトリとして書き出します。

## 復元

![復元ページ。セクションを選び、項目を検索して、バックアップを選びます。](assets/screenshots/recovery.png)

*復元ページ。セクションを選び、項目を検索して、バックアップを選びます。*

- **1 つのページ。** **復元** はセクションをタイルで並べます。戻したいものを検索し、最新が一番上の一覧からバックアップを選びます。推奨のものには印が付き、異常のあとではその直前のものです。**項目を開く** で項目のページに移り、実行中の復元は **実行中** に表示されます。
- **すべての種類に 1 つのウィンドウ。** 手順を追って尋ねます。どの **バックアップ** か（推奨のものがあらかじめ選ばれています）、どの **ソース** か（ローカルが最速）、**対象**（すべて、または選んだファイルとフォルダー）、そして **復元先** です。場面が選んだ復元先を示し、開始の前に **実行内容** が言葉で説明します。
- **まとめて復元。** 復元ページでは、Ctrl+クリック、Shift+クリック、Ctrl+A、長押し、または **選択** で項目を選びます。選んだ項目にはアイコンの代わりにチェックが表示されます。**復元** を押すと全項目に対して 1 つのウィンドウが開きます。各項目は最新のバックアップか、全項目に対して選んだ 1 つの時点での最新のバックアップを使い、元の隣に置かれるか、元を置き換えます。復元は 1 つずつ順番に実行され、各行にはそれぞれの結果が表示されます。フラッシュは ZIP としてダウンロードできます。ZFS データセットとセルフバックアップは 1 つずつ復元します。
- **既定は「元の隣に」。** コンテナは `<name>-restored` という名前の 2 つ目のコンテナとして独自のポートで戻り、元のコンテナは動き続けます。VM のディスクと NVRAM は、2 つ目の VM を作らずに、元の隣の `<folder>-restored` フォルダーに置かれます。フォルダーセットは `<path>-restored` として戻ります。コピーは、スケジュールに加えるまで、バックアップの一覧で対象外として表示されます。
- **「元を置き換える」は先にバックアップします。** 既定でオンの **先に現在の状態をバックアップ** で、BombVault は置き換える前に今あるものをバックアップするので、元に戻せます。そのバックアップが失敗したら復元は始まりません。置き換えでは項目名の入力を求められます。
- **フォルダーに** はファイルだけを書き出し、閲覧向けです。ZFS データセットは **新しいデータセットへ** も復元でき、フラッシュは **ZIP でダウンロード** として戻ります。
- **コンテナは自動的に再インストールされます。** コンテナ定義が Docker API に対して再生されるため、コンテナは Unraid の Docker タブに以前とまったく同じ状態で再び現れます。
- **GPU、制限、リンクが戻ります。** 復元したコンテナは、リソース制限、ログドライバー、DNS 設定、従来のリンク、GPU またはランタイム (`--gpus`、`--runtime=nvidia`) を取り戻します。その GPU ドライバーやランタイムがないホストでは、復元がそれを伝え、**GPU とランタイムなしで復元** を提案します。複数のコンテナや stack を復元した後も同様です。存在しないコンテナ、または復元したコンテナの起動時に停止しているコンテナへのリンクは外され、実行履歴にそのことが記録されます。
- **VM は自動的に再作成されます。** XML が SSH 経由で再インポートされ、VM は VM Manager にディスクと UEFI NVRAM を再アタッチした状態で再び現れます。VM が削除された後でも同様です。
- **フラッシュの復元は `.zip` ダウンロード。** `flash-<id>.zip` としてブラウザにストリーミングされ、そのまま Unraid の USB クリエーターに投入できます。稼働中の `/boot` に触れることは一切ありません。
- **プラグインをひとつずつ。** フラッシュの復元ウィンドウには、各フラッシュバックアップに含まれるプラグインがバージョンとサイズ付きで並び、1 つだけを稼働中のフラッシュに戻せます。`.plg` ファイル、`config/plugins` の下のフォルダー、バックアップにあるパッケージファイルです。フラッシュのほかの部分は何も変わりません。Unraid は次回の起動時、または **Plugins、Install Plugin** で今すぐそのプラグインをインストールします。
- **スケジュールされたフラッシュ zip エクスポート。** フラッシュバックアップのたびに、選んだフォルダーへバックアップを通常の `.zip` として書き出せます（上書きされる 1 つの `flash-latest.zip`、または履歴を残す方式）。フラッシュ項目の設定タブにある **フラッシュ ZIP エクスポート** カードです。Syncthing や rclone のフォルダーに向ければ、起動用 USB のバックアップが自動でサーバーの外に出ます。
- **プリフライトの競合チェック。** 何かを停止または削除する前に、復元はコンテナの静的 IP と公開ホストポートが空いていることを検証し、途中で終わった復元を残す代わりに、明確なメッセージとともに中止します。復元前の確認は、削除された TrueNAS アプリが作成していたネットワークのように、なくなったネットワークも示し、先にそのアプリを再インストールするよう案内します。
- **復元前の確認。** ウィンドウはまず、リポジトリが応答すること、保存された鍵で開けること、復元ポイントがあること、復元先に書き込む分の空きがあることを確認します。確認が失敗している間は開始がロックされ、ボタンの (i) がどれかを示します。
- **復元で変わること。** 確定の前に、ウィンドウは今あるものと比べて復元が何をするかを示します。新規、置き換え、変更なしのファイルで、一覧は求めに応じて表示され、復元先にありバックアップにないファイルはそのまま残ります。コンテナと VM では、復元が再作成する設定を稼働中のものと比較します。イメージとタグ、ポート、変数名とボリューム、またはメモリ、vCPU、ディスク、ネットワークです。restic がサイズと更新時刻からドライランとして求め、ファイルは読みません。非常に大きなツリーは 30 秒で打ち切られ、その旨が表示されます。スタックの復元は、すべてのメンバーを確認して計画し、妨げているものを名指しします。
- **共有フォルダー。** 元の場所への復元では、書き込むフォルダーにマウントが届いているほかのコンテナーを、動作中かどうかにかかわらずすべて名前で示します。たとえば「このパスは nextcloud-db も使っています」。警告だけで、止めはしません。
- **ZFS データセットの復元。** 項目の 1 つのデータセットを元の場所に（削除するまで残る ZFS 安全スナップショットのあとで）、フォルダーに、新しいデータセットに、選んだファイルだけ、またはバックアップのすべてのデータセットをフォルダーに復元します。データセットがロールバックされたり置き換えられたりすることはありません。
- **復元は実行状態を保ちます。** バックアップ時に稼働していたコンテナや VM は稼働状態で戻り、停止していたものは停止したままです。**終了後は停止したままにする** をオンにすると、起動せずに再作成します。
- **スタック全体の復元。** 同じ Docker Compose プロジェクトのコンテナで、バックアップ済みのメンバーが 2 つ以上あるものはスタックになります。バックアップページの **その他** にある **スタックを復元** は、各メンバーを最新のバックアップから作り直し、任意で `depends_on` の順に起動します。
- **ライブの進捗、キャンセル、処理中の表示。** 長い復元はリアルタイムのパーセントバーを表示し、種類に応じた確認でキャンセルできます。キャンセルした復元は失敗ではなく *キャンセル* として記録されます。ウィンドウは閉じられ、進捗は復元ページにも表示されます。
- **緊急ウィザード。** 失われた、または作り直したサーバー向けです。リカバリーキット、グループ経由、または入力した鍵を使います。[オフサイトと復旧](offsite-recovery.md#emergency)を参照してください。
- **古いバックアップフォルダーから。** 読み取り専用のセッションで、別の BombVault のリポジトリを、そのインスタンスのリカバリーキットまたは入力した `APP_KEY` で開きます。自分の設定に触れずに、サーバー A のコンテナをサーバー B に取り込めます。[オフサイトと復旧](offsite-recovery.md#restore-from-another-bombvault-repo)を参照してください。
- **ZFS プロパティも戻ります。** ZFS のバックアップはすべて、各データセットでローカルに設定されたプロパティ（圧縮、レコードサイズ、クォータ、大文字小文字の区別など）を保存します。新しいデータセットへの復元ではそれを使って作成し、既存のデータセットへの復元では一覧を表示し、頼んだときだけ設定します。[ZFS データセット](zfs-datasets.md#new-dataset)を参照してください。
- **Appdata.Backup プラグインからの取り込み。** 復元ページの **ほかの取得元** で、プラグインのバックアップフォルダーを指定します。各コンテナのアーカイブは、そのコンテナの復元ポイントになり、日付はプラグインが作成した日です。以前に取り込んだアーカイブはスキップされ、アーカイブ自体は読み取られるだけです。復元が定義を得られるよう、コンテナには先に BombVault で 1 回バックアップが必要です。保持は取り込んだ復元ポイントに手を付けないので、不要になったら自分で削除してください。

## ストレージとスケジュール

- restic による増分・重複排除バックアップ。大きな VM ディスクでもリポジトリが膨れ上がりません。
- **保存先。** ローカルフォルダーとオフサイトの場所が、**保存先** ページの 1 つの一覧に並びます。設定のタイルから開くか、サイドバーに固定します。セクションがバックアップするこのサーバー上のフォルダーは、配置のボタンと同じく **ローカル** と呼ばれます。各保存先には専用のページがあり、接続、認証情報、削除に対する保護、コピーの設定、保持、セクションごとのルールがあり、どれだけ埋まっているか、直近数週間の増え方でいつ満杯になるかを示す容器もあります。[保存先](offsite-recovery.md#destinations)を参照してください。
- **ストレージの種類：** ローカルパス、ホストにマウントしない rclone 経由の SMB 共有と WebDAV サーバー（Nextcloud、ownCloud、SharePoint）、NFS（Unraid にエクスポートをマウントしてローカルフォルダーとして使います）、rclone なしのネイティブ restic バックエンド（`s3:...`、`rest:http://host:8000/repo`、`sftp:user@host:/repo`）、または `rclone:<remote>:<bucket>/path` による任意の rclone リモート。認証情報はすべて暗号化して保存されます。
- **SSH 保存先は、向こう側に何もインストールする必要がありません。** `sftp:` に必要なのは SSH サーバーだけなので、素の Raspberry Pi（Docker も restic もなし）もオフサイトの保存先として使えます。ホスト鍵は最初の接続時に自動で固定されます。
- **3-2-1 を図で。** **セクションごとの保存先** カードは、どのセクションがどこにバックアップされるかを描きます。セクションから保存先へのどの線も、**ローカル** を含むすべてのセクションでスイッチになっており、1 回のクリックですぐに切り替わります。**グラフ / スイッチ** で同じ内容を通常のボタンとして表示できます。オフサイトの保存先だけを持つセクションは、BombVault がそこで自ら選んだリポジトリに直接バックアップし、すべての線がオフのセクションには **バックアップなし** と表示されます。セクションとは別の場所にバックアップする項目がある場合は、フローがその数を **2 件の項目が異なります** のように示し、それらへ案内します。フラッシュ、ZFS データセット、セルフバックアップは、ローカルフォルダーへバックアップし、そのバックアップからオフサイトへコピーします。**ローカル** への線もオフにでき、その場合バックアップは直接オフサイトの保存先へ送られます。レプリカがあり保存先がまったくない ZFS 項目は、レプリカだけを送ります。
- **オフサイトコピー（ローカル + リモート）。** 高速なローカルバックアップを残しつつ、1 つ以上のオフサイト保存先を追加し、`restic copy` でベストエフォートでコピーします（オフサイトの不調でローカルバックアップが失敗することはありません）。コピーは、保存先にまだないデータパックだけを転送します。各保存先の **コピー** カードで **コピーのタイミング**（**バックアップのたびに**、または独自のプラン）と帯域を設定し、セクションは **設定、スケジュール** で独自のプランでコピーできます。
- **セクションごとに複数の保存先。** 各セクションは複数のオフサイト保存先へ同時にコピーできます。保存先の **セクションごとのルール** で、1 つのセクションにそこでの独自の保持、圧縮、リポジトリを持たせられ、サインイン、認証情報、帯域、タイミングは保存先から決まります。
- **セクションの履歴を移す。** 保存先の **移動** は、セクションのコピーを履歴ごと別の保存先に移します。元の場所はすべてを保持し、BombVault はそこで何も削除しません。
- **名前付きリポジトリ。** **設定、保存先** の **リポジトリ** カードで、バックアップの場所（ローカルパス、または独自の認証情報セットを持つ任意の restic リモート）を一度書き留めておき、項目の場所として選びます。行には指している項目の数が表示され、項目や既定が使っているリポジトリは、BombVault が書き込み済みのバックアップを移動しないため、移動も削除もできません。
- **複数の認証情報セット。** 共有クラウド認証情報は既定でどこにでも適用されますが、どの保存先も名前付きセットを代わりに使えます（**設定、保存先** の **追加の認証情報セット**、または保存先ページの **認証情報**）。そのため、Hetzner の S3 バケットとローカルの Garage サーバーを、それぞれ別の鍵で並べて運用できます。
- **項目ごとの配置。** 項目の設定タブの **スケジュールと保存先** カードには、**ローカル** と各オフサイト保存先のボタンが並び、点灯しているものにその項目のバックアップが送られます。すでに NAS にある共有を B2 にまで送る必要はありません。セクションに従う項目は、セクションの場所が変わるとそれに合わせて移り、離れた場所は **以前のバックアップのみ** と表示され、そこから引き続き復元できます。項目で選んだ場所は最初のバックアップから固定され、コピーはいつでも変えられ、カードは何か所が項目を保持しているか、3-2-1 を満たしているかを示します。**既定に従う** は先に確認を求め、何が外れ、何がアップロードされるかを示します。[項目ごとの配置](offsite-recovery.md#placement)を参照してください。
- **手動のバックアップ順序。** **設定、スケジュール** の **順序** カードで、コンテナと VM をバックアップする正確な順序を決めます。スケジュール実行と全体のバックアップはそれに従い、順序を決めなかったものは期限超過が最も長いものから順に並び、単独のバックアップは変わりません。
- **保持を時間軸で。** 各保存先は **保持期間** でバックアップを残します。**短め**、**標準**、**長め**、または最新のバックアップ、日、週、月、年に対する **カスタム値** で、自動的に整理されます。時間軸には、ルールが残すバックアップが表示されます。**保持を減らす前に確認する** は、短いルールによってそこにしかコピーがない古いバックアップが削除される前に確認します。セクションは **セクションごとのルール** で、ある保存先に独自の値を持てます。
- **リポジトリごとの圧縮：** オフ、自動（restic の既定）、最大。保存先ごとに、またセクション単位ではそこでのルールで設定します。バックアップ、オフサイトコピー、整理がこれで書き込み、リカバリーキットにも記載されるので、素の restic も同じ方式で書き込み続けられます。
- **スケジュールは文で読めます。** たとえば *毎週日曜の 04:00* のようにで、その文から編集します。**設定、スケジュール** にすべてがあります。月曜から日曜までの予定された実行を並べた **週** の帯、前後に 1 つずつコマンドを持てる **全体バックアップ**、**セクションごとのスケジュール**、**セクションごとのオフサイトコピー**、**スケジュール済みの項目** です。**N 日ごと** は、復元ドリル、改ざんテスト、週次ダイジェストでも使えます。
- **独自のプランを持つセクションは全体バックアップから外れます。** **セクションごとのスケジュール** の **例外** ボタンでセクションに独自のプランを持たせると、そのセクションは自分の時刻に実行され、全体バックアップでは再実行されないため、二重にバックアップされません。**今すぐすべてバックアップ** は、オンのセクションをすべて対象にします。**項目ごとの独自スケジュール** をオンにすると、コンテナ、VM、フォルダーセット、ZFS データセットが自分のページで独自のプランを持て、その場合も全体バックアップから外れます。
- **バックアップ成功後にコンテナを更新。** **設定、スケジュール、バックアップ後の更新** のスイッチ（既定はオフ）は、直前のバックアップが完了してからのみ新しいイメージを取得します。個別のコンテナは自分のページで別に設定できます。
- **停止の代わりにスナップショット。** データが ZFS 上にあるコンテナは、BombVault がそのデータのスナップショットを取る間、通常は数秒だけ停止し、すぐにまた起動します。バックアップはそのスナップショットから読み取られ、コンテナを停止して取ったバックアップと同じパスとタグでリポジトリに保存されるため、復元、復元チェック、**前のバックアップと比較**、異常チェックはどちらも同じように扱います。バックアップ前のコマンドとデータベースのダンプはこれまでどおり最初に実行され、停止対象の他のコンテナも一緒に停止して一緒に戻り、バックアップ後のコマンドはコンテナが再び起動したらすぐに実行されます。バックアップ後の更新は、これまでどおりバックアップが完了するまで待ちます。新しいイメージがある場合は、再作成のために他のコンテナがもう一度停止します。これには、[ZFS データセット](zfs-datasets.md)と同様にホストへの SSH 接続が必要で、単一の ZFS プール上にある Unraid のユーザー共有で動作します。データの一部でもアレイや別のファイルシステムにあるコンテナは、従来どおりバックアップの間ずっと停止され、その実行に理由が表示されます。ZFS 上にデータがまったくないコンテナは従来どおり停止され、注記は付きません。TrueNAS ではアプリにさらに `SYS_CHROOT` ケーパビリティが必要です（[TrueNAS SCALE](getting-started.md#truenas)を参照）。スイッチは **設定、スケジュール、停止の代わりにスナップショット** にあり、既定はオンで、個別のコンテナは自分のページで別に設定できます。実行履歴には **スナップショット** と、コンテナが停止していた秒数が表示されます。BombVault がコンテナのバックアップの途中で停止した場合は、次回の起動時に、停止していたコンテナを再び起動します。
- **アプリがアイドルになるまで待つ。** コンテナは、アプリが忙しい間、スケジュールされたバックアップを、設定した時間を上限に待たせ、アプリがアイドルになり次第開始できます。メディアサーバーはストリーミングしていなければアイドルとみなされ、ほかのコンテナは、**設定、スケジュール** の **バックアップ前のアイドル** カードの制限を CPU とトラフィックが数分間下回ればアイドルとみなされます（ホストネットワークでは CPU のみ）。待機中のバックアップは、理由と期限とともにアクティビティログとコンテナに表示されます。ロックを保持しないので、ほかのコンテナは先に進みます。手動のバックアップは待ちません。同じ実行で期限の来た compose スタックのメンバーは一緒に待ち、待機は再起動後も期限を保って続きます。コンテナをオフにすると待機中のバックアップはすべて破棄され、スケジュールをオフにすると、その実行が保留していたものが破棄されます。時間を短くすると、すでに始まった待機も短くなります。
- **オフサイト帯域制限。** restic のアップロード/ダウンロード速度に上限を設け、コピーが WAN を占有しないようにします。**設定、保存先** の **オフサイト帯域幅** カード、または保存先ごとのその **コピー** カードで設定します。
- **ストリーミング優先。** Plex、Jellyfin、Emby などのメディアサーバーがストリーミングしている間、オフサイトコピーは低い制限でアップロードし、ストリーム終了の数分後に通常の制限に戻ります。BombVault は Docker からメディアサーバーの送信トラフィックを読み取ります。REST、S3、B2、Azure、Google Cloud、Swift、HTTP 上の rclone はコピーの途中で速度が落ち、SFTP とローカルまたはマウントしたフォルダーは次のコピーステップで低い制限になります。ホストネットワーク上のメディアサーバーは測定できません。保存先ページの **ストリーミング** カードです。
- **コールド/アーカイブのストレージクラス（S3）。** S3 の保存先では、復元可能な階層（Standard、Standard-IA、One Zone-IA、Intelligent-Tiering、Glacier Instant Retrieval）に限ってストレージクラスを選べるため、アーカイブ料金が復元を黙って壊すことはありません。先に非同期の解凍が必要なディープアーカイブ階層（Glacier Flexible、Deep Archive）は、restic が読み取れないので除外されています。ネイティブ S3 バックエンドのみで、rclone リモートは rclone の設定でクラスを指定します。
- **バックアップフォルダーはマシン外へコピー可能なまま。** 各バックアップの後、BombVault はローカルリポジトリツリーを、ディレクトリ `0755` / ファイル `0644` に緩めます（リポジトリは暗号化されているため何も露出しません）。これにより、SMB 経由の非 root の同期ユーザーが締め出されません。リカバリー定義は各リポジトリの内側に存在するため、コピーされたリポジトリフォルダーは完全に自己完結しています。

## インサイト、検証、監視

- **概要。** ステータスヘッドと 4 つのカードから始まります。**要対応**、**保護ステータス**、それぞれがいつ満杯になるかの予測つきの **保存先**、実行とログを持つ **履歴** です。ヘッドのリングは保護の度合いを示し、バックアップの実行中は各ステーションつきの進捗リングに変わります。ほかのカードは **カスタマイズ** の中で待機しています。**異常**、**未バックアップ**、**カレンダー**、**ストレージ**、**概要**、**統計**、**ホスト統合** です。どのカードも移動、サイズ変更、非表示にでき、レイアウトはブラウザーに保存されます。
- **どこでも同じ数え方。** どのカードも、オンのセクションの項目を同じ方法で数えます。スケジュール外の項目は、直近のバックアップがどれだけ新しくても保護されているとは数えません。
- **項目から一時停止。** **スケジュールを一時停止** は項目をスケジュールと全体バックアップから外し、**スケジュールを再開** で戻します。項目の設定タブの **スケジュールに含める** と同じスイッチを操作するので、両者は常に一致します。一時停止中の項目には灰色の **スケジュール一時停止中** バッジが付き、**今すぐバックアップ** は引き続き使えます。
- **保護ステータス。** 各セクションに 4 つのチェックがあります。このサーバーでの最新のバックアップ、オフサイトのコピー、そこでの削除に対する保護、そこからの試験復元です。期限を過ぎたバックアップはログに埋もれず赤くなり、セクションをクリックすると詳細が表示されます。
- **カレンダー。** 直近 90 日を、1 日 1 つの四角で、その日のバックアップ結果とともに表示します。日をクリックすると、**履歴** のログにその日の行が表示されます。
- **どこでも実行時間を表示。** すべての実行は `開始、終了 (所要時間)` と読め、各項目には検証タブに専用の **最近の実行** 一覧があります。
- **リポジトリサイズと重複排除の推移。** **ストレージ** カードは、各セクションがどれだけ使っているか、データがどれだけ重複排除されているかを示します。
- **復元検証ドリル。** BombVault は定期的に、バックアップが復元可能であることを証明します（`restic check --read-data-subset`、範囲を限定）。**設定、検証、自動チェック** で設定します。同じタイルの **バックアップをチェック** カードはセクションごとの結果を示し、**その他** の下に **ロック解除** と **整理** があります。
- **最初のバックアップ後の復元チェック。** 項目の最初のバックアップが終わると、BombVault はその一部（最大 100 ファイル、256 MiB）を復元フォルダー内の一時フォルダーに復元し、restic に各ファイルをハッシュと照合して読み戻させ、サイズをバックアップと比較します。VM ディスクのようにサンプルに収まらない大きなファイルは、代わりに先頭 64 MiB を読み戻します。結果は項目の検証タブに表示され、失敗は通知で届きます。**復元を確認** を押すと、いつでも最新のバックアップで同じチェックを実行できます。以降のバックアップでは繰り返しません。
- **起動テスト。** バイトが正しくても、アプリが再び動くとは限りません。コンテナの検証タブの **起動テスト** は、最新のバックアップを隔離コピーとして復元して起動します。名前は `bombvault-test-` で始まり、公開ポートも LAN への経路もない専用の内部 Docker ネットワーク、CPU 1 個とメモリー 2 GiB、データは復元フォルダー内の一時フォルダーに置かれます。コンテナーのヘルスチェックが正常を報告すれば合格、ヘルスチェックがなければ最初の公開ポートがそのネットワーク内から応答すれば合格、どちらもなければ動作し続ければ合格です。元のコンテナーは停止も変更もされず、コピーとそのネットワーク、データはテスト後に削除されます。テスト途中で BombVault が再起動した場合も同じです。ホストネットワーク上のもの、特権モードのもの、デバイスを使うもの、別のコンテナーが必要なものはテスト不可と表示されます。スケジュールされた復元チェックで **起動テスト** をオンにすると、実行ごとに 1 つのコンテナーを、最もテストされていないものから順にテストします。コピーには元のコンテナのラベルが一切付かず、元のコンテナが追加している capabilities、セキュリティオプション、sysctl、cgroup parent なしで動きます。それらが必要なコンテナはテストに失敗し、結果にはコピーに何がなかったかが表示されます。
- **自己修復オペレーション。** 操作の途中の再起動によって残された、証明可能な孤立 restic ロックは、自動で強制解除され、一度だけリトライされます。保持は identity-stable（項目ごとに整理され、パスやホストの変更に影響されない）で、保持の失敗は通知を送ります。
- **フォルダースキャンでは見えない警告。** 除外アシスタントはサイズの問いに答えます。けれども最も高くつくバックアップの失敗のいくつかはサイズの問題ではないため、アプリケーションがデータをどう保存しているかについて、アプリ固有の注意書きも備えています。その目的となった例が Immich です。Immich はすべての写真のアルバム、顔、日付を*別の*コンテナで動く PostgreSQL データベースに保存しているため、Immich コンテナをファイルレベルでバックアップすると、それらを一切含まないまま写真だけが復元され、しかも復元は成功したように見えます。この警告は除外の提案があるかどうかにかかわらず表示され、スキャン対象が何も選ばれていないコンテナでも表示されます。注意書きはどちらの場合でも当てはまるからです。
- **未バックアップ（カバレッジ）。** スケジュールされたバックアップのどれにも含まれない、サーバー上のすべてを理由つきで挙げる概要のカードです。BombVault にまったく追加されていない、存在するがスケジュールにない、独自のスケジュールがオフ、どこにもスケジュールがオンになっていない、セクションのすべての保存先がオフ、のいずれかです。保護ステータスは別の問いに答えます。つまり、スケジュールされたバックアップが時間どおりに実行されたかであり、誰も設定していないコンテナは見えません。コンテナは BombVault 自身の行ではなく稼働中の Docker の一覧から読み取ります。行のない項目こそ名指しが必要だからです。オフにしたセクションと、**バックアップしない** にした項目は、あなたの選択なので数に含まれません。
- **保持のプレビュー。** **設定、保存先** の **プレビュー** カードは、次の実行が何を削除しようとしているかを実行前に示します。リポジトリごと、項目ごとに、復元ポイントの名前つきです。リポジトリロックを取らず、何も変更しないため、バックアップ中でも応答します。保持がオフの場合は空の一覧ではなくその旨を表示し、追記専用のリポジトリはそのように表示され（そこでは保持はまったく実行されません）、到達できなかったリポジトリは黙って欠けるのではなく名前が示されます。
- **異常。** コンテナ、VM、フォルダーセット、データベースダンプ、フラッシュドライブ、セルフバックアップのバックアップを、毎回その項目自身の履歴と比べます。チェックの対象は次のとおりです。実行で保存された新しいデータ量を、最近のバックアップで普段いちばん多い量と普段の 1 時間あたりのペースと比べたもの。データの大部分を保存し直したバックアップ (名前を変えて書き換えたファイルも含みます)。restic が項目ごと、ダンプごとに報告するソースのサイズとファイル数。restic 自身のバックアップ時間。失敗の連続と散発的な失敗。通らなくなったリストアチェック。そしてローカル、SFTP、rclone のリポジトリの空き容量で、これはリポジトリの増え方から予測します。項目は最初の 10 回のバックアップから学習しますが、ほぼ空のソース、データの大部分の書き換え、失敗は最初からチェックします。感度 (厳しめ、標準、緩め) と、通知を送る最低の重大度は **設定、検証** の **異常** カードで全体に設定し、項目ごとに検証タブで変えられます。警告は原因がなくなると自動で閉じます。失われたデータと埋まりつつあるディスクについての重大な検出結果は確認済みにするまで残り、確認済みの検出結果は、その原因が一度なくなるまで再び報告されません。**想定どおりと印を付ける** を使うと 10 回のバックアップの後に新しい水準が普通になりますが、ほぼ空のソースのチェックは決してオフになりません。また選択を変えると、項目の履歴は自動でやり直しになります。ソースがほぼ空になった、大きく縮んだ、またはバックアップがデータの大部分を保存し直した間は、検出結果を確認済みにするか想定どおりと印を付けるまで、保持ポリシーはその項目の古いバックアップを残し、検出結果は最後の正常なバックアップへリンクします。通知は 1 つの出来事につき 1 回だけ送られ、すでに自分で通知する失敗やリストアチェックが二重に報告されることはありません。できないこと: S3、B2、REST のリポジトリには空き容量の値がありません。Unraid のユーザー共有ではアレイ全体の空き容量になります。restic 0.17 より前のバックアップにはサイズの履歴がありません。ZFS 項目もデータセットごとに調べます。ツリーの各データセットはそれぞれの履歴を持ち、空になったデータセットや読めなくなったデータセットはデータの喪失として扱われ、そのデータセットの古いバックアップだけが保持されます。 ZFS 項目をデータセットごとに見守る仕組みは [ZFS データセット](zfs-datasets.md#anomalies) で説明しています。アシスタントは [MCP サーバー](mcp.md#tools) を通じて未対応の異常を読み取れます。 ソースのサイズやファイル数に関する検出は、それが最初に現れたバックアップの日時で示されます。**前のバックアップと比較** は、ファイルが消えた、増えた、変わったフォルダーを一覧にし、そのほぼすべてがアプリが自分で作り直す検索インデックス、キャッシュ、サムネイルにある場合は注記を付けます。
- **異常ページ。** **重大**、**警告**、**参考情報** のタイルで重大度を選び、一覧の上に未解決と解決済みの検出結果が並びます。重大な検出結果もほかと同じ面に置かれ、重大度はバッジと色つきの縁で示されます。検出結果はまず修正方法を示し、詳細では値が通常の範囲の上に曲線として表示されます。未解決のものがないときは、項目ごとのリングが、検出が何を通常とみなすかをどこまで学習したかを示します。
- **アプリ別の推奨除外。** よく知られたイメージ（Plex、Jellyfin、Emby、Sonarr、Radarr、Lidarr、Readarr、Prowlarr、Immich、Nextcloud、PhotoPrism、Tautulli。linuxserver、hotio、binhex、公式提供元のもの）に対して、**除外パターン** カードの除外アシスタントは、アプリが自力で再生成するフォルダーを提示します。キャッシュ、ログ、プレビュー画像、ポスターです。各行には何が入っているかが表示され、どれもオフにでき、**選択したものを除外** を押すまで何も除外されません。
- **バグ報告。** **設定、情報** の **ヘルプ** カードにある **バグ報告** は、GitHub の issue 向けに伏せ字処理した ZIP をダウンロードします。ホスト統合チェック、秘密をすべて除いた設定、最近の実行、次の予定、最近のログです。各データベースの直近のダンプの結果、コンテナから見えるマウントを含む ZFS 項目、未解決の異常、MCP キーの数（名前は決して含みません）も入っています。パスワード、トークン、rclone の設定、通知の認証情報、リポジトリの場所に埋め込まれたパスワードはすべて取り除かれ、バンドル自身のマニフェストにもその旨が書かれます。サポート用ファイルはセルフバックアップと取り違えられてはならないからです。リカバリーキットと同じ理由でログインパスワードが必要です。含まれるログは、このコンテナの最後の起動以降の出力です。コンテナを再起動させたクラッシュについては、引き続き `docker logs` を見てください。
- **リカバリーキット。** **設定、復元** の **リカバリーキットをダウンロード** で、鍵、導出した restic パスワード、リポジトリの正確な場所とコマンドが手に入り、BombVault が動いていなくても復元できます。ログインパスワードが必要です。[オフサイトと復旧](offsite-recovery.md#recovery-kit)を参照してください。
- **設定のエクスポートとインポート。** **設定、システム** の **設定のエクスポート / インポート** カードは、設定一式（セクション設定、保存先、スケジュール、保持、通知）を持ち運べる JSON ファイルに書き出すので、新しいマシンへの移行や設定の複製で、すべてを手で入れ直す必要がありません。オフサイトと通知の認証情報を含めるかは選べます。含めた場合、ファイルはリカバリーキットと同じくらい機密です。インポートはプレビューを表示して確認を求め、バックアップデータや履歴には触れません。
- **通知。** Webhook（Discord / Slack / Gotify / ntfy）、Matrix、Healthchecks.io、メール（SMTP）、セルフホストの [Apprise API](https://github.com/caronc/apprise-api) サーバー、Unraid のネイティブ通知システム。バックアップごとのポリシー：しない / 失敗時 / 常に。多数の項目のスケジュール実行は、*N 件中 M 件の項目が成功* という 1 つのまとめを送れます。URL が設定されていれば、Healthchecks にはライフサイクル全体（`/start`、続いて成功または `/fail`）が送られます。
- **週次ダイジェスト。** 週に 1 通、同じチャンネルで送られます。実行回数、届いた新しいバックアップデータの量、オフサイトが最新か、主な失敗です。既定ではオフで、**設定、通知** に独自の周期があり、静かな週もそのように報告されます。
- **Prometheus `/metrics`。** オプトイン（既定はオフ、任意のベアラートークン）で、**設定、連携** の **サービス** カードにあり、Grafana や Uptime Kuma 向けです。バックアップの状態、サイズ、タイムスタンプを公開し、ラベルに秘密やパスは含みません。
- **HTTP API、Home Assistant、mDNS。** スクリプトやダッシュボードは `/api/v1` の API を、名前付きトークンで利用でき、読み取り専用にも、バックアップ開始を許可することもできます。Home Assistant は MQTT ディスカバリーで BombVault を見つけ、センサーを持つデバイスとして、許可すればセクションごとのバックアップボタンも表示します。BombVault はネットワーク上で `bombvault.local` として自分を告知します。[API と連携](api.md)を参照してください。
- **空き容量と満杯までの週数。** 報告できるローカルリポジトリ、SFTP リポジトリ、SMB または WebDAV の保存先は、空き容量と、現在の増加ペースであと何週間かを表示します。S3、B2、REST リポジトリは、それらのバックエンドが報告しないため「サイズ不明」と表示します。
- **フォルダー別のサイズ。** コンテナ、VM、フォルダーセットの検証タブで、**フォルダー別のサイズ** は、最新のバックアップでどのフォルダーとファイルが容量を使っているか、最新のバックアップがそのうちどれだけを新規または変更として取り込んだかを、1 階層ずつ示します。BombVault はファイルを読まずにリポジトリのインデックスから読み取り、一度開いた後は各バックアップのあとに最新の状態を保ちます。
- **バックアップが遅かった理由。** バックアップの実行中、BombVault は CPU、ディスク、ネットワークの使用率を見ています。バックアップがいつもよりかなり長くかかり、ひとつのものが明らかに限界だった場合、実行記録にそれが表示されます。たとえば「保存先ディスク disk1 の使用率は 98% でした」や「BombVault はコンテナーの CPU 上限の 100% を使っていました」です。それ以外の場合は何も表示しません。
- **前回のバックアップ後に変更。** 前回のバックアップ後に別のイメージ、ポート、変数、ボリュームで作り直されたコンテナには、名前の横に印が付きます。その (i) は変更点を一覧にし、変数は名前だけを示します。これは通知にすぎず、次のバックアップで消えます。

## ランサムウェア対策

- **削除に対する保護（追記専用）。** オフサイトの保存先でオンにすると、ランサムウェアや侵害されたホストがバックアップを削除したり書き換えたりできなくなります。向こう側（`--append-only` モードの `restic/rest-server`）が強制し、BombVault は検証するだけで、設定の主張だけで緑を表示することはありません。このサーバー上のフォルダーは削除を拒否できないので、ローカルの保存先にはこのスイッチがありません。
- **改ざんテスト。** BombVault は、オフサイトのリポジトリに対して実際に削除を試みる（存在しないオブジェクトを狙う）ことで、追記専用の保証を定期的に証明します。拒否されれば保護されている、受け入れられれば保護されていない、という意味です。結論の出ない結果が、保存された判定を変えることはありません。保存先のページの **削除に対する保護を今すぐテスト** で、いつでも実行できます。
- **ガイド付きセットアップ。** **保存先を追加** は、プロバイダーの選択から、サインイン、接続テスト、フォルダーへ進み、削除に対する保護についての正直な説明と、そこにバックアップするセクションまで案内します。
- **DR ドリル（オフサイト）。** 試験復元は、オフサイトリポジトリから実際の対象を隔離したサンドボックスに置き、ファイル単位・バイト単位で検証してから片付けます。[オフサイトと復旧](offsite-recovery.md)を参照してください。
- **保護ステータス。** 概要のカードは、各セクションについて、最新のバックアップ、オフサイトのコピー、そこでの削除に対する保護、そこからの試験復元を確認します。検証された事実にのみ基づいて緑になります。
- **増加予算アラーム。** 追記専用の保存先（ここからは古いバックアップが整理されない）に容量の予算を設定すると、暴走する前に通知されます。
- **削除にはパスワードが必要。** 保存先のバックアップを削除するには、ログインパスワードと、インスタンス自体でのサインインが必要なので、ペアリング済みのスマートフォンも開いたままの画面も、これを実行できません。
- **フレーズによるペアリング。** インスタンスは 12 個の単語で 1 つのグループに加わります。1 台でフレーズを作り、次の 1 台で入力します。同じネットワーク上のメンバーは直接やり取りし、それ以外はリレー（プロジェクトのリレー、自分のもの、または使わない）を経由し、メンバー間のすべての呼び出しはエンドツーエンドで暗号化されます。グループが運ぶのは、インスタンスページの保護ステータス、ロールの要求、ストレージの提案、そしてロールが許可された後にレシーバーや取得側が必要とするものであり、バックアップデータや APP_KEY は決して運びません。[オフサイトと復旧](offsite-recovery.md#pairing)を参照してください。
- **インスタンスとロール。** **設定、インスタンス、複数のサーバー** で **インスタンス** をオンにすると、このインスタンスを含め、グループの各インスタンスのカードがあるページが現れます。アドレス、接続されているか、各セクションの保護と最後のバックアップです。そのロールはカード上にタイルで並びます。**レシーバー**、**取得側**、**ZFS サーバー**、**鍵の保管側** です。ロールは、相手のインスタンスで誰かが **許可** を押して初めて始まり、グループは誰が誰のために何をするかを網として示します。**今すぐ確認** は、メンバーにセクションのリポジトリを検証するよう依頼します。このページから、他のマシンでバックアップ、復元、削除を始めることはできません。[インスタンスとロール](offsite-recovery.md#roles)を参照してください。
- **ストレージの提案。** メンバーは、グループ経由で自分のオフサイトストレージを別のメンバーに提案できます。もう一方の管理者は、インスタンスページのメンバーの **詳細** で提案を見て、承認または辞退します。承認すると通常の認証情報セットと保存先が作られます。この方法で送られるのは接続の詳細だけで、バックアップデータは決して送られません。
- **受信リポジトリ（受信側）。** 別の BombVault から追記専用のオフサイトコピーを受け取るマシンで、**設定、インスタンス** の **レシーバー** をオンにし、送信側メンバーの **詳細** で受信したリポジトリを読み取り専用で追加します（送信側インスタンスの restic パスワードで開き、これはペアリンググループ経由で届きます）。ソース別にまとめたバックアップの一覧、各ソースが最後に届いた時刻が見られ、受信側のハードウェア上で独立した `restic check` を実行できます。設定した期間内にソースからの送信が止まったとき（デッドマンスイッチ）や、整合性チェックが失敗したときに通知します。厳密に読み取り専用で、受信したリポジトリに書き込むことはなく、既定ではオフです。[オフサイトと復旧](offsite-recovery.md#receiver)を参照してください。
- **別のインスタンスから取得（取得側）。** オフサイトコピーの鏡像です。このマシンがバックアップを押し出す代わりに、他のマシンのものを取り込みます。**設定、インスタンス** で **取得** をオンにし、もう一方のメンバーの **詳細** でソースを追加します。リポジトリの場所、それが保持するバックアップの種類、取得の頻度です。その restic パスワードはグループ経由で届き、APP_KEY は決して届きません。向こう側は追加の設定が不要で、動いている必要もありません。ソースのリポジトリは読み取られるだけです。パスワードの確認のために開かれ、一覧され、コピー元として指定されますが、初期化、ロック解除、整理、書き込みは決して行われません。それぞれの側が自分の認証情報を保持し、`rclone:` のソースは、rclone がこのインスタンスのリモートで到達してしまうため拒否されます。[オフサイトと復旧](offsite-recovery.md#receiver)を参照してください。
- **鍵の保管側。** グループ内の別のインスタンスが、このサーバーのリカバリーキットを封印したコピーとして保管できます。開けるのは 20 文字の取り出しコードだけで、そこで誰かが **許可** を押した後にのみ引き渡します。[鍵の保管側](offsite-recovery.md#key-keeper)を参照してください。

## プレーンエクスポート

- **コンテナと VM のエクスポート。** 項目のページの **その他** の下にある **コンテナをエクスポート** と **VM をエクスポート** は、リポジトリの隣に、閲覧できてツール不要のコピーを書き出します。コンテナのバックアップフォルダーを今の状態で、Unraid テンプレートとともに、または VM のディスクイメージと定義を、`virsh define` とディスクで復元できる形で、BombVault も restic も不要です。バックアップの **エクスポート** は、保存されたバックアップを同じ方法で tar、zip、または独立した restic リポジトリとして書き出します。restic が主役であることは変わらず、これは追加の利便コピーです。
- **プレーンエクスポートを暗号化（age）。** エクスポートは restic の外にあるため、既定では平文です。**設定、システム** で **age でエクスポートを暗号化** をオンにして、1 つ以上の受信者（age 公開鍵または SSH 公開鍵）を追加してください。フラッシュの ZIP を含む各エクスポートがその受信者向けに封印され、後でマシンの外で対応する秘密鍵で復号します。安全のための規則として、暗号化がオンで有効な受信者がない場合、エクスポートは平文を書き出す代わりに明確なエラーで失敗します。
- **リカバリーキットも封印されます。** 同じ設定がオンなら、キットは `bombvault-recovery-kit.md.age` としてダウンロードされます。バイナリではなく ASCII アーマー形式なので、プレーンな読めるテキストのままです。パスワードマネージャーに貼り付けたり印刷したりでき、それこそがキットの用途です。同じ安全策が適用されるため、暗号化がオンで使える受信者がない場合は、マスターキーを平文で渡すことに戻らず、ダウンロードを拒否します。これをオンにするときに正しく押さえておくべき点が 1 つあります。キットを開くには age の秘密鍵が必要なので、その鍵はキット自体に依存しない場所に保管してください。

## AI アシスタント (MCP) {#mcp}

BombVault には MCP サーバーが組み込まれており、Claude Code や Claude Desktop などのアシスタントがバックアップの状態、カバレッジ、実行履歴、復元ポイント、実行中のアクティビティを読み取れます。許可されたキーがあれば、アシスタントは 1 つの項目、1 つのセクション、またはすべてのバックアップを開始し、自分で開始したバックアップをキャンセルすることもできます。復元、削除、prune、設定は Web インターフェースに残ります。クライアントごとに **設定、連携、MCP サーバー** で専用のキーを作成します。キーは一度だけ表示され、指紋としてだけ保存され、いつでも名前の変更、交換、取り消しができます。開始は 1 時間あたりと項目ごとに制限され、保持ガードによって、アシスタントのバックアップが「最新 N 個を保持」のポリシーからあなた自身の復元ポイントを押し出すことはありません。アシスタントが開始した実行には、キー名とともに「MCP 経由」と表示されます。[MCP サーバー](mcp.md) を参照してください。 データベースのダンプと [ZFS データセット](zfs-datasets.md) も、アシスタントが読み取れる項目と復元ポイントに含まれ、BombVault が見つけた異常も一覧できます。

## アプリと関連ツール {#apps}

- **Android アプリ。** グループ内のすべてのサーバーをスマートフォンで扱え、全サーバーのアクティビティログを 1 つの画面で見られます。QR コードでグループとペアリングし、各サーバーをサインイン済みの状態で開きます。セッションが届くのはアプリが表示するものだけです。[Android アプリ](android.md)を参照してください。
- **受信サーバー。** オフサイトコピーを受け取るマシンは、最初に **レシーバー** の要求を許可したときに設定される追記専用の rest-server を動かし、グループ内の他のインスタンスに、それぞれ専用のログインとともに提供します。[受信サーバー](offsite-recovery.md#receiving-server)を参照してください。
- **設定、アプリ。** 最初に Android アプリのカードがあり、サーバーが動かしているリリースの APK とその QR コードを入手できます。続いて関連ツールごとのカードが並ぶページです。ParleyPort のカードでは、Unraid テンプレートを入手し、ParleyPort を起動する Docker コマンドをコピーでき、そのリポジトリとペアリングのリレー設定へ移動できます。BombVault Widget のカードでは、テンプレートとリポジトリを入手でき、ホスト SSH 接続を通じてプラグインをインストールまたは削除します。
- **BombVault Widget。** Unraid のダッシュボードに置くタイルで、BombVault のアクティビティログと次に予定された実行を表示します。ホスト SSH 接続がない場合、カードは **Plugins, Install Plugin** でインストールするための `.plg` アドレスを示します。プラグインは、ほかのプラグインと同じようにそこから削除できます。
- **埋め込み可能なアクティビティログ。** **設定、連携** の **ダッシュボードウィジェット** カードで読み取り専用のトークンを生成すると、Homepage、Organizr、Heimdall など iframe を表示する任意のダッシュボード向けのアドレスが得られます。ライブのアクティビティログだけを表示する小さなページです。トークンが許可するのはそのログだけで、**無効にする** で即座に失効します。埋め込みページは英語のみです。

## その他

- **実行中のバックアップを止める。** 実行がアクティブな間、進捗の隣に **バックアップを中止** が表示されます。実行は失敗ではなく *キャンセル* として記録されます。restic はスナップショットを最後に書くため、中止は安全で、中断した実行には参照されないデータが残るだけでスナップショットは残りません。
- **まとめてバックアップ。** バックアップの一覧で項目を選び、選択したものをバックアップします。バッチはサーバー側で実行されるため、タブを閉じたり接続が切れたりしても続きます。BombVault は自分自身のコンテナをバックアップしません（したがって停止もしません）。
- **項目のページのバックアップ。** 復元ポイントの一覧、バックアップごとの削除、独自のタグ、2 つのバックアップの比較があります。
- **セクションごとのリポジトリメンテナンス。** **設定、検証** の **バックアップをチェック** カードで、チェック（`restic check`）、そして **その他** の下の **ロック解除**（古いロックの解除）と **整理**（保持ポリシーがあればオンデマンドで適用し、なければ単なる容量の回収）を実行します。
- **チェック、復元チェック、整理の進捗。** いずれかの実行中は、アクティビティログと **バックアップをチェック** カードに、restic がどこまで数えたかが *47 パック中 12* のように表示され、見積もれるだけのデータがあればそのステップの残り時間も表示されます。restic はここでバイトではなくパック、スナップショット、インデックスファイルを数えるので、バーが示すのはそれです。最初のカウントの前は数字なしで動きます。
- **データベースの自動ダンプ。** 認識された PostgreSQL、MySQL、MariaDB のコンテナ（公式イメージ、PostGIS、TimescaleDB、pgvector、pgautoupgrade、Immich のデータベースイメージ、linuxserver、yobasystems、jc21 の MariaDB、そして Oracle の mysql-server）は、各バックアップの前に稼働中のサーバーからダンプされます。データベースに似ているだけのコンテナにも同じ選択肢が設定タブの **データベース** カードに出ますが、あなたが選ぶまではオフのままです。ダンプはリポジトリへ直接流れ込み、ファイルのバックアップと並ぶ独立した復元ポイントになります。ディスクに書かれることはありません。認証情報はコンテナ自身の変数（`*_FILE` のシークレットを含む）から取られ、コンテナの外には出ません。このカードは、データベースのデータフォルダーがコンテナ停止中に保存されるのか、稼働中にコピーされるのか、まったく保存されないのかを示します。ダンプが失敗してもバックアップは失敗しません。理由と対処のヒントを添えた失敗した実行として現れ、通知を送ります。ダンプが自動で戻されることはありません。ダウンロード（そのまま、または圧縮して）、フォルダーへの保存、起動したての空のデータベースへのワンクリック取り込み、restic の CLI での取り出しができます。コンテナごとに、ラベル `bombvault.dbdump=false` で、あるいは **設定、一般** の **データベースの自動ダンプ** で全コンテナまとめてオフにできます。 異常検知は各ダンプのサイズも見守ります。アシスタントは [MCP サーバー](mcp.md#tools) を通じてコンテナのダンプを一覧できます。
- **コンテナごとの前後のコマンド。** コンテナ内で実行されるシェルコマンド（たとえばキャッシュのフラッシュ）。バックアップ前のコマンドが失敗すると、バックアップは中止されます。認識されたデータベースは自動でダンプされるので、コマンドは不要です。
- **バックアップ中に他のコンテナを停止し、ヘルスゲート付きで再起動。** 依存するコンテナ（たとえばデータベース）を、このコンテナのバックアップ中に停止するよう指定します。その後、BombVault はそれらを Compose の `depends_on` 順で復帰させ、デフォルトでは、それに依存するコンテナを起動する前に、各コンテナが healthy を報告する（ヘルスチェックがなければ running を報告する）まで待機します。これにより、Pi-hole、データベース、VPN ゲートウェイのような依存先が、それを必要とするサービスより先に実際に立ち上がり、それらが *connection refused* に戻ることがなくなります。待機はコンテナごとのタイムアウト（デフォルト 120 秒）で上限が定められているため、遅い、あるいは決して healthy にならないコンテナが実行をハングさせることはありません。待機とタイムアウトはどちらも **設定、スケジュール** の **順序** カードの **バックアップ後の再起動** にあります（一斉再起動にするには待機をオフにします）。同じ順序付き・ヘルスゲート付き再起動は、バックアップ後のイメージ更新もラップします。そのため、更新が入る日には、依存先は再作成の間ずっと停止したまま保たれ、完了後にはじめてヘルスゲート付きで復帰します。
- **コンテナごとの除外パターン。** バックアップされるボリューム内でスキップするサブディレクトリを 1 行に 1 つ列挙します。コンテナ内で見えるとおりのパスを入力します。ライブプレビューが各行の解決先を示し、何も除外しない行があれば警告します。
- **バックアップ成功後に更新（デフォルトはオフ）。** **設定、スケジュール、バックアップ後の更新** の **バックアップ成功後にコンテナを更新** をオンにするか、個別のコンテナを自分のページで別に設定すると、BombVault は最新のイメージを取得して再作成します。ただし、実際により新しいイメージがある場合のみで、常に先に新しい復元ポイントが確保されます。オプションの追加機能: 更新されたコンテナごとの通知と、イメージのクリーンアップ（他のコンテナと共有されるベースイメージは決して削除されません）。更新後、BombVault は Unraid にそのコンテナの更新ステータスを再チェックするよう依頼します。そのため、Docker タブの古い *update available* バナーが、居座る代わりに自分で消えます（Unraid の更新は Docker API を直接通るため、そのキャッシュされたステータス、そして一部のバージョンではキャッシュされたダイジェストが、そうしなければバナーを表示し続けてしまいます）。これはベストエフォートで、バックアップに影響することは決してなく、デフォルトでオンで、同じカードの **コンテナの更新後に Unraid の更新ステータスを更新する** で切り替えます。
- **別のフォルダーへの復元**。複製や検査のために使えます。
- **更新後の新機能。** 新しいバージョンごとに一度、リリースノートのウィンドウが自動で開きます。バイナリに埋め込まれたノートから提供されるので、オフラインでも動作します。緑の点が各変更を該当するページに示します。ウィンドウには **リリースノート** と **変更点** の 2 つのタブがあり、後者はすべての変更の一覧で、それぞれに **そこへ移動** があります。**設定、情報** のバージョンカードにある **新着** は、まだ見ていないものの数を **新着 · 4** のように示し、未確認のものがあるうちは **変更点** で、なければリリースノートでウィンドウを開きます。
- **情報。** **設定、情報** には、**バージョン**（BombVault、GlimStone、restic、rclone、**新着** と **更新を確認** つき）、README のドキュメントボタンの黄色の **マニュアル** と **バグ報告** を持つ **ヘルプ**、**BombVault について** があります。
- **HTTPS をデフォルトで**（自己署名、またはリバースプロキシの背後に独自の証明書を持ち込み）。
- **Docker ヘルスチェック。** コンテナは自身の `/api/health` から healthy/unhealthy を報告するため、エンジンが動かなくなった場合に auto-heal ツールがそれを再起動できます。
- **42 言語** に対応し、**設定、外観** に国旗のピッカーがあります。
- **設定は自動で保存されます。** スイッチを切り替えるか入力欄を離れると、変更はすぐに書き込まれ、コントロールが短く光り、サーバーが拒否したときは揺れます。途中までの保存が安全でない一部の場所には保存ボタンが残ります。rclone 設定ボックス、認証情報セットのエディター、ログインパスワードなどです。
- **静かな通知。** **設定、外観** で定型の確認メッセージをミュートでき、失敗だけがあなたの作業を中断します。通知チャンネルには影響しません。
- **好みの見た目に。** **設定、外観** では、**テーマ**（ダーク、ライト、システム）、色（アクセント 1 色、または 8 色パレットの *Rainbow Mode*）、角（丸、やわらかい、四角）、アニメーション（オフ、控えめ、ワイルド、ストーム）、設定タイルの順序を設定します。テーマ、角、アニメーションは選択肢ごとに記号を表示します。ボタンのラベルモードが **記号** のときは、選択肢は記号だけを表示し、名前はホバーの吹き出しに出ます。BombVault は見た目をサーバーに保存し、初めて来たブラウザーはそれを引き継ぎます。保存先の容器の中の液体は揺れ、ロゴは押し続けるほど激しく震えたあと、はじけます。サイドバーのほか、スマートフォンでは概要の上で動きます。システムがモーションの軽減を求めている場合は、常にそちらが優先されます。
