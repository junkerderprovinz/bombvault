# BombVault

**ข้อมูล Unraid ของคุณ ถูกผนึกไว้ในห้องนิรภัย ปล่อยการสำรองข้อมูลลงไป จุดชนวนการกู้คืน**

![ภาพรวม: ส่วนหัวแสดงสถานะ สิ่งที่ต้องดูแล การป้องกันของแต่ละส่วน ปลายทางที่จัดเก็บ และประวัติ](assets/screenshots/overview/home-dark.png#only-dark)
![ภาพรวม: ส่วนหัวแสดงสถานะ สิ่งที่ต้องดูแล การป้องกันของแต่ละส่วน ปลายทางที่จัดเก็บ และประวัติ](assets/screenshots/overview/home-light.png#only-light)

BombVault คือเว็บแอปแบบ self-hosted สำหรับ **การสำรองข้อมูลและกู้คืนจากภัยพิบัติแบบครบวงจร** บน Unraid และโฮสต์ Docker อื่น ๆ เช่น TrueNAS SCALE, ZimaOS หรือกล่อง Linux ธรรมดา มันสำรองคอนเทนเนอร์ Docker, VM แบบ KVM/libvirt, โฟลเดอร์, ชุดข้อมูล ZFS และแฟลชไดรฟ์ของ Unraid ทำงานเป็นคอนเทนเนอร์ Docker ตัวเดียวที่รองรับหลายสถาปัตยกรรม มีหน้าเว็บให้เลือกธีมมืด สว่าง หรือตามระบบ และดูแลวงจรทั้งหมด ตั้งแต่สำรองข้อมูล ตั้งเวลา ตรวจสอบ ไปจนถึงกู้คืน

การกู้คืนทำงานอัตโนมัติ บน Unraid คอนเทนเนอร์จะกลับมาปรากฏในแท็บ Docker เหมือนเดิมทุกอย่าง และ VM จะถูกนิยามใหม่ใน VM Manager พร้อมต่อดิสก์และ UEFI NVRAM กลับให้ ไม่ต้องติดตั้งใหม่เอง ไม่ต้องตั้งค่าใหม่ ไม่มีเรื่องวุ่นวาย บน TrueNAS คอนเทนเนอร์ที่กู้คืนข้างต้นฉบับจะรันเป็นคอนเทนเนอร์ Docker ธรรมดาที่หน้า Apps ไม่แสดง

ขับเคลื่อนด้วย [restic](https://restic.net) ทุกการสำรองข้อมูลจึงขจัดข้อมูลซ้ำ เพิ่มทีละส่วน และเข้ารหัสโดยค่าเริ่มต้น

!!! note "เก็บ APP_KEY ของคุณให้ปลอดภัย"
    BombVault สร้างรหัสผ่านของที่เก็บ restic จากความลับขนาด 32 ไบต์ชื่อ `APP_KEY` ถ้าทำหายพร้อมกับชุดกู้คืน ข้อมูลสำรองที่เข้ารหัสจะกู้คืนไม่ได้ สร้างด้วย `openssl rand -hex 32` และเก็บไว้ในที่ปลอดภัย ดู [การกำหนดค่า](configuration.md)

## BombVault ปกป้องอะไรบ้าง {#what-bombvault-protects}

ทุกคอนเทนเนอร์ VM ชุดโฟลเดอร์ แฟลชไดรฟ์ ชุดข้อมูล ZFS ทุกชุด และการตั้งค่าของ BombVault เองเป็น **รายการ** ที่มีหน้าของตัวเอง รายการชนิดเดียวกันรวมเป็น **ส่วน** ซึ่งคุณเปิดได้ที่ **การตั้งค่า, ทั่วไป**

| ส่วน | สิ่งที่ถูกบันทึก |
|---|---|
| **คอนเทนเนอร์** | ไดเรกทอรี appdata พร้อมคำจำกัดความของคอนเทนเนอร์ (image, ตัวแปร env, พอร์ต, ป้ายกำกับ, วอลุ่ม) |
| **VMs** | image ดิสก์ของ VM, คำจำกัดความ XML และ UEFI NVRAM สำรองผ่าน SSH (ไม่ต้อง mount libvirt) |
| **Flash** | แฟลช USB ทั้งหมด (`/boot`): ระบบปฏิบัติการ, ไลเซนส์, การตั้งค่าอาร์เรย์, share, เครือข่าย และการตั้งค่าปลั๊กอิน |
| **สำรองข้อมูลตัวเอง** | `/config` ของ BombVault เอง: ฐานข้อมูลการตั้งค่า ข้อมูลรับรองของปลายทางที่จัดเก็บ และคู่คีย์ SSH ของ libvirt |
| **โฟลเดอร์** | โฟลเดอร์ใดก็ได้บนเซิร์ฟเวอร์เป็นชุดโฟลเดอร์ แต่ละชุดมีรูปแบบการยกเว้นที่เลือกได้ |
| **ชุดข้อมูล ZFS** | ชุดข้อมูลหนึ่งและทุกชุดข้างใต้ อ่านจากสแนปช็อต ZFS เดียวและเก็บเหมือนโฟลเดอร์ ดู [ชุดข้อมูล ZFS](zfs-datasets.md) |

## การกู้คืนคือพระเอก {#restore-is-the-star}

หลังจากคัดลอกข้อมูลกลับจากสแนปช็อต restic แล้ว BombVault จะเล่นคำจำกัดความของคอนเทนเนอร์ที่บันทึกไว้ซ้ำกับ Docker API คอนเทนเนอร์จึงกลับมาปรากฏในแท็บ Docker ของ Unraid เหมือนอยู่ที่นั่นมาตลอด (image เดิม การตั้งค่าเดิม การแมปพอร์ตเดิม) VM ได้ XML นิยามใหม่ผ่าน SSH และดิสก์กับ UEFI NVRAM ถูกต่อกลับ แม้ VM จะถูกลบไปแล้ว

หน้าต่างเดียวกู้คืนได้ทุกชนิด โดยค่าเริ่มต้นจะเลือก **ข้างต้นฉบับ** ซึ่งนำข้อมูลสำรองกลับมาเป็นสำเนาและปล่อยต้นฉบับไว้ตามเดิม **แทนที่ต้นฉบับ** จะสำรองสถานะปัจจุบันก่อน การกู้คืนจึงย้อนกลับได้ โฟลเดอร์หรือชุดข้อมูล ZFS ใหม่เป็นปลายทางอื่น ๆ

เมื่อการสำรองหยุดคอนเทนเนอร์ที่พึ่งพากัน คอนเทนเนอร์เหล่านั้นจะกลับมาตามลำดับที่ถูกต้อง BombVault เริ่มพวกมันใหม่ตามลำดับ `depends_on` ของ Compose และรอให้แต่ละตัวรายงานว่าพร้อมก่อนเริ่มตัวที่พึ่งพามัน จึงไม่มีอะไรวิ่งนำหน้าฐานข้อมูลหรือเกตเวย์ที่ยังไม่ขึ้น ดู [การกู้คืน](restore.md) และ [คำสั่งและคอนเทนเนอร์อื่น](backups.md#commands)

## ทำงานอย่างไร {#how-it-works}

```
Browser --HTTPS--> BombVault container
                   |- Go binary: JSON API + embedded React UI
                   |- Background worker (per-section scheduler + job executor)
                   |
                   |- /var/run/docker.sock  -> Docker API (container stop/inspect/recreate)
                   |- qemu+ssh://host       -> libvirt / KVM on the HOST over SSH (no mount)
                   |- /mnt/ -> /host/user   -> appdata, VM disks + restic repos (read/write)
                   |- /boot/ -> /host/boot  -> Unraid flash backup (whole USB)
                   |- /config               -> BombVault's own settings + sign-ins (self-backup)
                   '- <repo path>           -> restic repository (local or remote: rclone/s3/rest/sftp)
```

BombVault ใช้ Docker socket เพื่อหยุดคอนเทนเนอร์ก่อนการสำรองและสร้างใหม่หลังการกู้คืน สำหรับ VM มันรัน `virsh` บนโฮสต์ผ่าน SSH (`qemu+ssh://`) เพื่อปิด domain อย่างนุ่มนวลหรือทำสแนปช็อตแบบสด มันไม่เคย bind-mount พาธของ libvirt จึงไม่รบกวน VM Manager บนโฮสต์

BombVault เป็นชั้นประสานงานและหน้าตา ไม่ใช่เอนจินจัดเก็บ การเคลื่อนย้ายข้อมูลจริงทั้งหมดผ่าน restic

## เริ่มอย่างรวดเร็ว {#quick-start}

เพิ่งมาใช้ใช่ไหม ไปที่ **[เริ่มต้นใช้งาน](getting-started.md)** เพื่อติดตั้ง BombVault และรันการสำรองครั้งแรก แล้วตั้งค่า **[นอกสถานที่และการกู้คืน](offsite-recovery.md)** **[ตัวอย่างการใช้งานจริง](guides.md)** พาทำงานทั่วไปตั้งแต่ต้นจนจบ หน้า **[การตั้งค่า](settings.md)** ลิสต์ทุกไทล์ และ **[ฟีเจอร์](features.md)** คือแคตตาล็อกสั้น ๆ ของทุกสิ่งที่ BombVault ทำได้

แต่ละส่วนคัดลอกไปยังหลายปลายทางพร้อมกันได้ BombVault ที่จับคู่กันเก็บสำเนานอกสถานที่ของคุณไว้ในเซิร์ฟเวอร์ที่ปฏิเสธการลบได้ และ **ตัวช่วยฉุกเฉิน** นำเซิร์ฟเวอร์ที่หายไปกลับมาจากชุดกู้คืน ผ่านกลุ่มของคุณ หรือด้วยคีย์ที่พิมพ์ใส่ ถ้าจะย้ายการกำหนดค่าไปยังกล่องใหม่ ให้ใช้การ์ด **ส่งออก / นำเข้าการตั้งค่า** ดู [นอกสถานที่และการกู้คืน](offsite-recovery.md) และ [การกำหนดค่า](configuration.md#portable-settings-export-and-import)

**[แอป Android](android.md)** นำทุกเซิร์ฟเวอร์ในกลุ่มของคุณมาไว้บนโทรศัพท์ โดยมีบันทึกกิจกรรมของทุกตัวอยู่บนหน้าจอเดียว

เอกสารมี 26 ภาษาและหน้าตาโปรแกรมมี 42 ภาษา หน้าที่ยังไม่มีคำแปลจะแสดงเป็นภาษาอังกฤษ

## คำที่ใช้ที่นี่ {#glossary}

บางคำมีความหมายตายตัวใน BombVault และในหน้าเหล่านี้

| คำ | ความหมาย |
|---|---|
| **รายการ** | สิ่งหนึ่งที่ BombVault สำรอง: คอนเทนเนอร์ VM ชุดโฟลเดอร์ แฟลชไดรฟ์ ชุดข้อมูล ZFS พร้อมชุดข้างใต้ หรือการตั้งค่าของมันเอง แต่ละรายการมีหน้าของตัวเอง |
| **ส่วน** | รายการทั้งหมดของชนิดเดียวกัน เช่น คอนเทนเนอร์ คุณเปิดส่วนต่าง ๆ ได้ที่ **การตั้งค่า, ทั่วไป** |
| **ปลายทาง** | ที่ที่ข้อมูลสำรองไป: โฟลเดอร์บนเซิร์ฟเวอร์นี้ share เซิร์ฟเวอร์ของคุณเอง หรือบริการคลาวด์ ดู [ปลายทางที่จัดเก็บ](offsite-recovery.md#destinations) |
| **ในเครื่อง** | ปลายทางบนเซิร์ฟเวอร์นี้ที่เก็บโฟลเดอร์ของแต่ละส่วน |
| **โฟลเดอร์ของตัวเอง** | ที่เก็บที่ส่วนหนึ่งเขียนข้อมูลสำรองลงก่อน โดยค่าเริ่มต้นอยู่บนเซิร์ฟเวอร์นี้ และอยู่ในปลายทางได้ ดู [โฟลเดอร์ของตัวเองของส่วน](offsite-recovery.md#own-folder) |
| **คัดลอก** | ข้อมูลสำรองที่คัดลอกจากโฟลเดอร์ของตัวเองไปยังปลายทางอื่นด้วย `restic copy` |
| **ที่เก็บโดยตรง** | ที่เก็บที่ปลายทางนอกสถานที่ซึ่งรายการสำรองลงไปตรง ๆ โดยไม่มีสำเนาในเครื่องคั่นกลาง ดู [ที่เก็บโดยตรง](offsite-recovery.md#direct-repositories) |
| **ข้อมูลรับรอง** | คีย์หรือรหัสผ่านที่บันทึกไว้สำหรับบริการ S3 หรือ rest-server หนึ่งในนั้นเป็นค่าเริ่มต้น ดู [ข้อมูลรับรอง](offsite-recovery.md#sign-ins) |
| **การวาง** | ปลายทางไหนได้รับข้อมูลสำรองของรายการ ตั้งที่รายการหรือเป็นค่าเริ่มต้นของส่วน ดู [การวางต่อรายการ](offsite-recovery.md#placement) |
| **เรพลิกา** | สำเนาแบบตรงทุกบล็อกของรายการ ZFS บนเซิร์ฟเวอร์ ZFS ตัวที่สอง ทำด้วย `zfs send` อยู่ข้างการสำรองและไม่ได้แทนที่มัน ดู [เรพลิกา](zfs-datasets.md#replica) |
| **บทบาท** | สิ่งที่อินสแตนซ์หนึ่งของกลุ่มทำให้อีกตัว: ตัวรับ ตัวดึง เซิร์ฟเวอร์ ZFS หรือผู้เก็บคีย์ ดู [อินสแตนซ์และบทบาท](offsite-recovery.md#roles) |
