# การกำหนดค่า

หน้านี้ครอบคลุมตัวแปรสภาพแวดล้อมของคอนเทนเนอร์ mount ที่เทมเพลตจัดให้ โมเดลความปลอดภัย การสำรอง VM ผ่าน SSH และการตั้งค่านอกสถานที่ ที่ที่ข้อมูลสำรองไปตั้งค่าภายในแอปเป็น **ปลายทางที่จัดเก็บ** ไม่ใช่ผ่านตัวแปรสภาพแวดล้อม

## ตัวแปรสภาพแวดล้อม {#environment-variables}

| ตัวแปร | จำเป็น | คำอธิบาย |
|---|---|---|
| `APP_KEY` | **ใช่** | ความลับฐานสิบหกขนาด 32 ไบต์ (อักขระฐานสิบหก 64 ตัว) ใช้สร้างรหัสผ่านที่เก็บ restic สร้างด้วย `openssl rand -hex 32` เก็บให้ปลอดภัย ถ้าทำหาย ข้อมูลสำรองที่เข้ารหัสจะกู้คืนไม่ได้ |
| `LIBVIRT_HOST` | สำหรับ VM และชุดข้อมูล ZFS | โฮสต์ Unraid ที่เข้าถึงผ่าน SSH สำหรับการสำรอง VM และชุดข้อมูล ZFS (ช่องเทมเพลต **Host SSH: Address** ค่าเริ่มต้น `host.docker.internal`) เทมเพลตกรอกตัวยึดที่ `192.168.x.x` ไว้ให้ ซึ่งนับว่าไม่ได้ตั้ง ใช้ IP LAN ของ Unraid ของคุณ จำเป็นบนเครือข่าย `br0.x` แบบกำหนดเอง เมื่อ `host.docker.internal` ไม่ resolve เช่นในแอป TrueNAS และ `LIBVIRT_URI` ก็ไม่ระบุโฮสต์ BombVault จะใช้เกตเวย์เริ่มต้นของคอนเทนเนอร์และบันทึกการบูตจะบอกชื่อ |
| `LIBVIRT_SSH_PORT` | ไม่ | พอร์ต SSH ของโฮสต์สำหรับการสำรอง VM และชุดข้อมูล ZFS (ช่องเทมเพลต **Host SSH: Port** ค่าเริ่มต้น `22`) |
| `LIBVIRT_SSH_USER` | ไม่ | ผู้ใช้ SSH บนโฮสต์สำหรับการสำรอง VM และชุดข้อมูล ZFS (ช่องเทมเพลต **Host SSH: User** ค่าเริ่มต้น `root`) |
| `LIBVIRT_URI` | ไม่ | URI เชื่อมต่อ libvirt แบบเต็ม ใช้ **ตามตัวอักษร** แทนการสร้างจากตัวแปร `LIBVIRT_*` สามตัวข้างบน (ซึ่งจะถูกเพิกเฉยสำหรับสตริงการเชื่อมต่อ) ค่าเริ่มต้นไม่ตั้ง จำเป็นบน TrueNAS Scale ที่ libvirtd ฟังบน socket ที่ไม่ใช่มาตรฐานซึ่งรูปแบบที่สร้างขึ้นเองบอกไม่ได้: `qemu+ssh://<user>@<truenas-host>/system?socket=/run/truenas_libvirt/libvirt-sock` ดู [คู่มือการสำรอง VM](vm-backup-ssh-setup.md#truenas-scale) เมื่อเป็น URI แบบ `qemu+ssh://` ตัวแปร `LIBVIRT_HOST`, `LIBVIRT_SSH_USER` และ `LIBVIRT_SSH_PORT` ที่ไม่ได้ตั้งจะรับค่าจากมัน รวมถึงสำหรับคำสั่ง SSH ของ BombVault เอง (การถ่ายโอน NVRAM ชุดข้อมูล ZFS) |
| `PORT` | ไม่ | พอร์ต HTTP (ค่าเริ่มต้น `3000` ใช้เฉพาะกับ `HTTP_ONLY=true`) |
| `HTTPS_PORT` | ไม่ | พอร์ต HTTPS (ค่าเริ่มต้น `3443` เทมเพลตเผยแพร่แบบ 1:1 หน้าเว็บจึงตอบที่ `https://<ip>:3443`) |
| `HTTP_ONLY` | ไม่ | ตั้งเป็น `true` เพื่อปิดตัวฟัง HTTPS แบบเซ็นเองและให้บริการ HTTP ธรรมดาเท่านั้น (สำหรับใช้หลัง reverse proxy ที่ทำ TLS) |
| `BIND_HOST` | ไม่ | ที่อยู่ที่หน้าเว็บฟัง (ค่าเริ่มต้น `0.0.0.0` ทุกอินเทอร์เฟซ) ปล่อยไว้ไม่ตั้งในคอนเทนเนอร์ ซึ่งพอร์ตที่เผยแพร่ต้องใช้ทุกอินเทอร์เฟซ `127.0.0.1` เหมาะกับการรันนอก Docker healthcheck ถามที่อยู่เดียวกัน |
| `TRUSTED_PROXY` | ไม่ | ที่อยู่หรือช่วง CIDR คั่นด้วยจุลภาคของ reverse proxy หน้า BombVault (เช่น `192.168.20.11` หรือ `10.0.0.0/8`) `X-Forwarded-For` จะเชื่อถือเฉพาะจากฮอปเหล่านั้น และตัวจำกัดการเข้าสู่ระบบจะนับความล้มเหลวต่อไคลเอนต์จริง แทนที่จะรวมทุกคนหลัง proxy ไว้ในถังเดียว ถ้าไม่ตั้ง (ค่าเริ่มต้น) จะไม่เชื่อถือใครเลย เพราะส่วนหัวที่เชื่อโดยไม่มีเงื่อนไขจะให้ผู้เรียกใครก็เลือกถังของตัวเองได้ |
| `HOST_SOURCE_ROOT` | ไม่ | พาธโฮสต์ที่เมานต์เป็น **Host Data** (ค่าเริ่มต้น `/mnt`) BombVault แปลงต้นทาง bind-mount ที่ Docker รายงานเป็นพาธใต้ mount นี้ เปลี่ยนเฉพาะเมื่อคุณเมานต์รากโฮสต์อื่น |
| `HOST_MOUNT_ROOT` | ไม่ | ที่ที่ Host Data ถูกเมานต์ภายในคอนเทนเนอร์ (ค่าเริ่มต้น `/host/user`) บน TrueNAS Host Data เมานต์ที่พาธโฮสต์ของมันเอง ตัวนี้และ `HOST_SOURCE_ROOT` จึงระบุพาธเดียวกัน เช่น `/mnt/tank` (ดู [TrueNAS SCALE](getting-started.md#truenas)) |
| `DATA_ROOT_SEGMENTS` | ไม่ | ชื่อส่วนของพาธคั่นด้วยจุลภาคที่ทำเครื่องหมายต้นทาง bind-mount ว่าเป็นข้อมูลสำรอง (ค่าเริ่มต้น `appdata` ตามธรรมเนียม `/mnt/user/appdata/<container>` ของ Unraid) bind mount ของคอนเทนเนอร์จะถูกเลือกสำรองอัตโนมัติเมื่อส่วนใดก็ตามในลิสต์ปรากฏเป็นส่วนเต็มของพาธต้นทางบนโฮสต์ เช่น `DATA_ROOT_SEGMENTS=appdata,config` จะรับ bind `.../config` ด้วย การจับคู่ไม่สนตัวพิมพ์ใหญ่เล็ก ค่าเริ่มต้นจึงครอบคลุม `/DATA/AppData/<container>` ของ ZimaOS ด้วย ดู [การตรวจหาต้นทางการสำรอง](#backup-source-detection) สำหรับวิธีอื่นที่ทำงานเสมอในการหาโฟลเดอร์ข้อมูลของคอนเทนเนอร์ |
| `PLATFORM` | ไม่ | บังคับว่า BombVault ถือว่าตัวเองรันบนแพลตฟอร์มไหน แทนการตรวจจับอัตโนมัติ: `unraid`, `generic` หรือ `truenas` (ค่าเริ่มต้นไม่ตั้ง: ตรวจจับ Unraid อัตโนมัติด้วยการหาเครื่องหมาย `dockerMan` ใต้ mount ของแฟลช ไม่เช่นนั้นเป็น `generic` ค่าที่ไม่รู้จักก็ถอยไปเป็น `generic` และบันทึกไว้) ตั้งอย่างชัดเจนบนโฮสต์ Docker ทั่วไปหรือ TrueNAS Scale แทนการพึ่งการตรวจเฉพาะ Unraid ไฟล์ compose แบบ generic ทำเช่นนี้ ส่งผลต่อธรรมเนียม appdata สำรอง ค่าเริ่มต้นปลายทางการกู้คืนข้ามอินสแตนซ์ และว่าจะลองขั้นตอนแจ้งเตือน/ปลั๊กอินเสริมเฉพาะ Unraid หรือไม่ (ดู `internal/platform`) |
| `BOMBVAULT_SELF_CONTAINER` | ไม่ | ชื่อของคอนเทนเนอร์ BombVault เอง เพื่อไม่ให้มันสำรอง (และจึงหยุด) ตัวเอง |
| `BACKUP_MAX_HOURS` | ไม่ | จำนวนชั่วโมงสูงสุดตามนาฬิกาที่การสำรองหนึ่งรอบถือล็อกโดเมนได้ก่อนถูกยกเลิกแบบบังคับ (ตัวป้องกันไม่ให้การรันที่ค้างบล็อกโดเมนตลอดไป) ว่าง (ค่าเริ่มต้น) ใช้ `48` เพิ่มสำหรับการสำรองคลาวด์ที่ใหญ่หรือช้ามาก (การรันที่ถูกยกเลิกที่เพดานจะล้มเหลวด้วย `context deadline exceeded`) ตั้ง `0` เพื่อปิดเพดานทั้งหมด prune ถูกจำกัดด้วยเพดานเดียวกัน และ check หรือ prune รันได้นานเท่าที่ restic ยังรายงานความคืบหน้า |
| `BACKUP_STALL_HOURS` | ไม่ | จำนวนชั่วโมงที่การสำรองไม่มี **ความคืบหน้าเลย** ได้ก่อนถูกยกเลิก ว่าง (ค่าเริ่มต้น) ใช้ `2` ตั้ง `0` เพื่อไม่ยกเลิกเมื่อค้างเลย นี่คือตัวป้องกันที่ละเอียดกว่าในสองตัวและมักเป็นตัวที่ทำงาน: มันดูว่ายังมีอะไรเกิดขึ้นอยู่ไหม แทนที่จะดูว่ารันมานานแค่ไหน การสำรองหลายเทราไบต์ที่ช้าแต่ปกติจึงถูกปล่อยไว้ ส่วนอันที่ค้างบน share ที่ไม่ตอบสนองจะถูกหยุดภายในไม่กี่ชั่วโมงแทนที่จะเป็นหลายวัน จะมีคำเตือนบันทึกหลังเงียบไป 30 นาที ก่อนที่จะยกเลิกอะไร การสแกนนับเป็นความคืบหน้า: restic ไม่เขียนไบต์ใดขณะเดินผ่านต้นไม้ใหญ่ และช่วงนั้นถูกเฝ้าดูผ่านยอดรวมไฟล์และไบต์ ไม่ใช่ผ่านไบต์ที่เขียน ตัวแปรสองตัวเป็นอิสระต่อกัน และ `BACKUP_MAX_HOURS` ยังจำกัดช่วงหลังการสำรองเอง (การเก็บรักษา สถิติ สำเนานอกสถานที่) ที่ไม่มีตัวนับให้เฝ้าดู |
| `DB_DUMP_MAX_HOURS` | ไม่ | จำนวนชั่วโมงที่ดัมป์ฐานข้อมูลอัตโนมัติหนึ่งครั้งรันได้ก่อนถูกหยุด ว่าง (ค่าเริ่มต้น) ใช้ `6` ค่าที่อนุญาตคือ `1` ถึง `48` และขีดจำกัดถูกเก็บให้ต่ำกว่า `BACKUP_MAX_HOURS` หนึ่งชั่วโมง (ครึ่งหนึ่งของมันเมื่อน้อยกว่าสองชั่วโมง) ดัมป์ที่ยาวจึงถูกตัดด้วยขีดจำกัดของตัวเองและรายงานเช่นนั้น แทนที่จะลากการสำรองลงไปด้วย ดัมป์ที่ไม่มีความคืบหน้าจะถูกหยุดเร็วกว่านั้น หลัง `BACKUP_STALL_HOURS` ดัมป์ที่ถูกหยุดล้มเหลวเอง และการสำรองคอนเทนเนอร์ดำเนินต่อ บน Unraid เพิ่มลงในคอนเทนเนอร์ BombVault ด้วย **Add another Path, Port, Variable** |
| `TZ` | ไม่ | เขตเวลาของตัวตั้งเวลา (เช่น `Europe/Berlin`) **ถ้าไม่ตั้ง ทุกตารางเวลาจะรันตาม UTC**: อันที่ตั้งเป็น 02:30 จะทำงานตอน 02:30 UTC ไม่ใช่ตามนาฬิกาของคุณ บน Unraid คุณไม่ต้องตั้งเอง: ระบบส่งเขตเวลาของตัวเองเข้าทุกคอนเทนเนอร์ บันทึกการบูตบอกว่า resolve ได้เขตไหน เขตที่มีเวลาออมแสงจะข้ามหนึ่งรอบในฤดูใบไม้ผลิและรันหนึ่งรอบสองครั้งในฤดูใบไม้ร่วง ส่วน UTC ไม่เป็นทั้งสองอย่าง แต่เลื่อนไปหนึ่งชั่วโมงเทียบกับนาฬิกาของคุณปีละสองครั้ง |
| `DATA_DIR` | ไม่ | ที่ที่ BombVault เก็บฐานข้อมูล คีย์ และแคช (ค่าเริ่มต้น `/config`) อย่าแตะในคอนเทนเนอร์ มีความสำคัญเมื่อคุณรันไบนารีนอก Docker |
| `FLASH_DIR`, `FLASH_TEMPLATES_DIR` | ไม่ | ที่ที่แฟลชไดรฟ์และเทมเพลต Docker ของมันถูกเมานต์ภายในคอนเทนเนอร์ (ค่าเริ่มต้น `/host/boot` และ `/host/boot/config/plugins/dockerMan/templates-user`) ตามการเมานต์ `/boot` ของเทมเพลต จึงไม่ต้องตั้ง |

## Mount {#mounts}

เมานต์ Docker socket แฟลช (`/boot`) และราก **Host Data** (`/mnt`) ตามที่เทมเพลต CA แสดง *ต้นทาง* และ *ปลายทาง* ของการสำรองอยู่ใต้ Host Data ทั้งคู่ และเมานต์แบบ **slave** เพื่อให้ share ระยะไกลที่เมานต์หลังคอนเทนเนอร์เริ่ม (เช่นใต้ `/mnt/remotes`) มองเห็นได้โดยไม่ต้องรีสตาร์ท

บน TrueNAS Host Data คือพาธชุดข้อมูล เช่น `/mnt/tank` ไม่ใช่ ixVolume เด็ดขาด ข้อมูลที่แอปเก็บใน ixVolume อยู่นอกมันและไม่ถูกสำรอง ดู [TrueNAS SCALE](getting-started.md#truenas)

การสำรองชุดข้อมูล ZFS ต้องใช้โหมดนี้ด้วย: โฮสต์เมานต์สแนปช็อตของชุดข้อมูลหลังคอนเทนเนอร์เริ่มแล้วเท่านั้น ดู [ชุดข้อมูล ZFS](zfs-datasets.md)

ที่เก็บในเครื่องมีค่าเริ่มต้นที่ `/mnt/user/bombvault/{container,vms,flash,config,files,zfs}` ที่สร้างตอนการสำรองครั้งแรก เป็น **โฟลเดอร์ของตัวเอง** ของแต่ละส่วนและเป็นปลายทางที่จัดเก็บ **ในเครื่อง** บนหน้าของมันใต้ **ปลายทาง** การ์ด **การเชื่อมต่อ** เปลี่ยนโฟลเดอร์ของแต่ละส่วน

โฟลเดอร์ของตัวเองของส่วนอยู่ในปลายทางที่คุณมีอยู่แล้วได้ด้วย เช่น NAS หรือบักเก็ต S3: **ใช้เป็นโฟลเดอร์ของตัวเอง** บนหน้าของปลายทางนั้นย้ายมันไปที่นั่น และบอกก่อนว่าจะเกิดอะไรกับข้อมูลสำรองที่ทำไว้แล้ว ดู [โฟลเดอร์ของตัวเองของส่วน](offsite-recovery.md#own-folder)

โฟลเดอร์ที่เก็บในเครื่องคงโหมด `0755` และ `0644` ผู้ใช้ซิงก์ที่ไม่ใช่ root ผ่าน SMB จึงไม่ถูกล็อกออก และที่เก็บเข้ารหัสอยู่แล้ว สิ่งนี้จึงไม่เปิดเผยอะไร คำจำกัดความสำหรับกู้คืนอยู่ในแต่ละที่เก็บ โฟลเดอร์ที่คัดลอกจึงสมบูรณ์ในตัวเอง ที่เก็บของการสำรองตัวเองอ่านได้เฉพาะ root

!!! note "ตรวจการผสานรวมโฮสต์"
    การ์ด **การผสานรวมโฮสต์** บนภาพรวม (เพิ่มได้ที่ **ปรับแต่ง**) ตรวจทุก mount และ CLI (Docker socket, libvirt, restic, qemu-img, rclone) และรายงานส่วนที่ขาด

## การตรวจหาต้นทางการสำรอง {#backup-source-detection}

สำหรับแต่ละคอนเทนเนอร์ BombVault เลือกอัตโนมัติว่าจะสำรอง bind mount และวอลุ่มแบบมีชื่อไหน พาธจะถูกรับเมื่อข้อใดข้อหนึ่งต่อไปนี้เป็นจริง (คุณแทนที่ผลได้เสมอในการ์ด **โฟลเดอร์ที่สำรองข้อมูล** บนแท็บการตั้งค่าของคอนเทนเนอร์)

- **จับคู่ส่วนรากข้อมูล:** ต้นทางบนโฮสต์ของ bind มีส่วนหนึ่งของ `DATA_ROOT_SEGMENTS` เป็นส่วนประกอบพาธเต็ม (ค่าเริ่มต้นคือ `appdata` เท่านั้น)
- **วอลุ่มแบบมีชื่อของ Docker** รวมไว้เสมอ เพราะไม่มีสิ่งที่ใช้ทดแทนแบบทิ้งได้และไม่มีอะไรต้องกรอง **แต่เฉพาะเมื่อพาธจัดเก็บจริงบนโฮสต์ของวอลุ่มเข้าถึงได้ผ่าน mount ของ Host Data** เหมือนพาธโฮสต์อื่นที่ BombVault สำรอง ไดรเวอร์ local-volume เริ่มต้นของ Docker เก็บวอลุ่มใต้รากข้อมูลของ daemon เอง (`/var/lib/docker/volumes/<name>/_data` เว้นแต่คุณปรับแต่ง ตรวจด้วย `docker info -f '{{.DockerRootDir}}'`) ซึ่งไม่ถูกครอบคลุมด้วย mount Host Data แบบแคบที่มีไดเรกทอรีเดียวซึ่ง `docker-compose.yml` แบบ generic ใช้โดยค่าเริ่มต้น วอลุ่มที่เข้าถึงไม่ได้จะถูกข้ามเงียบ ๆ ไม่ใช่ข้อผิดพลาด ถ้าจะสำรองวอลุ่มแบบมีชื่อบนโฮสต์ทั่วไปจริง ๆ ให้ชี้ Host Data (และ `HOST_SOURCE_ROOT`) ไปที่บรรพบุรุษร่วมที่ครอบคลุมรากข้อมูลของ Docker ด้วย คอมเมนต์ Host Data ในไฟล์ compose อธิบายข้อแลกเปลี่ยน (Unraid เลี่ยงเรื่องนี้ด้วยการเมานต์ `/mnt` ทั้งหมดซึ่งเป็นธรรมเนียมระดับบนสุดสากลของมัน ด้วยเหตุผลเดียวกัน)
- **ไดเรกทอรีโปรเจกต์ Docker Compose:** ถ้าคอนเทนเนอร์มีป้ายมาตรฐาน `com.docker.compose.project.working_dir` (ตั้งอัตโนมัติโดย `docker compose up`) ไดเรกทอรีนั้นจะถูกเพิ่มด้วย ไม่ว่า bind ใดจะตรงกับส่วนรากข้อมูลหรือไม่
- **การแทนที่ด้วยป้าย `bombvault.data`:** ตั้งป้าย `bombvault.data=true` บนคอนเทนเนอร์เพื่อรวม bind mount ทั้งหมดของมัน สำหรับรูปแบบที่ไม่มีธรรมเนียมใดข้างบนจับได้ (เช่น bind `/srv/plex/config` เดียวโดยไม่มีโปรเจกต์ Compose) ค่าที่ไม่ว่างใด ๆ นอกจาก `false` นับเป็นจริง ป้ายที่ไม่มีหรือ `bombvault.data=false` ไม่เปลี่ยนอะไร
- **ป้าย `bombvault.dbdump`:** ตั้ง `bombvault.dbdump=false` บนคอนเทนเนอร์เพื่อปิดดัมป์ฐานข้อมูลอัตโนมัติของมัน (`0`, `no` และ `off` ทำเหมือนกัน) หรือระบุเอนจิน (`postgres`, `mysql`, `mariadb`) เพื่อดัมป์คอนเทนเนอร์ที่ BombVault ไม่รู้จักเอง ป้ายชนะสวิตช์ในการ์ด **ฐานข้อมูล** บนแท็บการตั้งค่าของคอนเทนเนอร์ ซึ่งเป็นวิธีที่ใช้บน Unraid

## โมเดลความปลอดภัย {#security-model}

!!! warning "ควบคุมโฮสต์ในระดับเทียบเท่า root"
    ผ่าน Docker socket BombVault หยุด ลบ และสร้างคอนเทนเนอร์ใหม่ได้ อ่านและเขียน appdata ได้ และสำหรับการสำรอง VM มันเข้าสู่ระบบโฮสต์ผ่าน SSH (`qemu+ssh://` โดยค่าเริ่มต้นเป็น root) เพื่อรัน `virsh` ใครก็ตามที่เข้าถึงหน้าเว็บของมันได้จึงมีสิทธิ์ root บนโฮสต์ในทางปฏิบัติ

### การเข้าสู่ระบบ {#login}

- **การป้องกันด้วยรหัสผ่านแบบเลือกได้** (การ์ด **รหัสผ่าน** ใต้ **การตั้งค่า, ความปลอดภัย**): ตั้งรหัสผ่านเพื่อบังคับเข้าสู่ระบบ ล้างเพื่อปิด ปิดไว้โดยค่าเริ่มต้นสำหรับ LAN ที่เชื่อถือได้ รหัสผ่านเก็บด้วย Argon2id บน pepper ที่ใช้ `APP_KEY` เป็นกุญแจ `/config` ที่ถูกคัดลอกจึงไร้ค่าถ้าไม่มีคีย์ และช้าที่จะโจมตีแม้มีคีย์ รหัสผ่านใหม่ต้องมีอย่างน้อย 12 ตัวอักษร อันเดิมที่สั้นกว่ายังใช้ได้จนกว่าจะเปลี่ยน เซสชันเซ็นไว้ (HMAC ที่สร้างจาก `APP_KEY`) และการเปลี่ยนรหัสผ่านทำให้เซสชันเป็นโมฆะ การเข้าสู่ระบบจำกัดห้าครั้งที่ล้มเหลวต่อนาทีต่อไคลเอนต์ การเปลี่ยนหรือล้างรหัสผ่านขอ **รหัสผ่านปัจจุบัน** และเมื่อเปิดการยืนยันตัวตนสองขั้นตอนอยู่ก็ขอรหัสด้วย
- **บางอย่างต้องใช้รหัสผ่าน** การดาวน์โหลดชุดกู้คืน รายงานบั๊ก และ ZIP ของการสำรองแฟลช การส่งออกการสำรองแฟลชหรือสำรองข้อมูลตัวเอง การฝากคีย์กับผู้เก็บคีย์ การอนุญาตให้ส่งมอบการฝาก การสร้างรหัสกู้คืนใหม่ การส่งออกการตั้งค่าพร้อมข้อมูลรับรอง การยืนยันตัวตนสองขั้นตอน และพาสคีย์ จะถูกปฏิเสธจนกว่าจะตั้งรหัสผ่านเข้าสู่ระบบ และต้องลงชื่อเข้าใช้ที่อินสแตนซ์เอง การลบข้อมูลสำรองทำได้โดยไม่ต้องมีรหัสผ่าน และเมื่อตั้งรหัสผ่านไว้แล้ว ก็ต้องลงชื่อเข้าใช้แบบเดียวกันนี้
- **ปลายทางไม่แสดงรหัสผ่าน** ปลายทางอาจมีข้อมูลรับรองอยู่ในตัว เช่น `rest:https://user:password@host/repo` และทุกหน้าและทุกคำตอบของ API แสดงเป็น `rest:https://[redacted]@host/repo` ไม่ว่าจะมีรหัสผ่านเข้าสู่ระบบหรือไม่ ถ้าเปลี่ยนพาธที่อยู่ข้างหลัง รหัสผ่านที่เก็บไว้ก็ยังอยู่ ถ้าจะให้ปลายทางชี้ไปเซิร์ฟเวอร์อื่น ให้พิมพ์ปลายทางทั้งหมดพร้อมรหัสผ่าน เพราะรหัสผ่านที่ซ่อนไว้ผูกอยู่กับเซิร์ฟเวอร์ของมัน
- **การยืนยันตัวตนสองขั้นตอน** (**การตั้งค่า, ความปลอดภัย**): รหัสเวลาจากแอปยืนยันตัวตนเพิ่มจากรหัสผ่าน พร้อมรหัสกู้คืนใช้ครั้งเดียวแปดรหัสที่แจกครั้งเดียวเมื่อเปิด ความลับร่วมถูกเก็บแบบเข้ารหัสด้วย `APP_KEY` และการปิดปัจจัยนี้อีกครั้งต้องใช้รหัสปัจจุบัน
- **พาสคีย์** (WebAuthn) อยู่ในการ์ดของตัวเองเมื่อตั้งรหัสผ่านแล้ว ควบคู่กับรหัสผ่านและไม่เคยแทนที่ การลบพาสคีย์ทั้งหมดจึงไม่ล็อกใครออก ต้องมีชื่อโดเมนจริงและใบรับรองที่เบราว์เซอร์เชื่อถือ ค่าเริ่มต้น `https://<ip>:3443` คือสิ่งที่ WebAuthn ปฏิเสธพอดี และการ์ดบอกเช่นนั้นแทนการเสนอปุ่มที่ล้มเหลว เมื่อเปิดการยืนยันตัวตนสองขั้นตอนอยู่ พาสคีย์ต้องตรวจ PIN ลายนิ้วมือ หรือใบหน้าของคุณ ไม่เช่นนั้นการเข้าสู่ระบบจะขอรหัสด้วย
- **การกู้คืนการกำหนดค่า** (**นำการตั้งค่ากลับมา** ในตัวช่วยฉุกเฉิน) จบทุกเซสชัน ลบทุกพาสคีย์ และเพิกถอนทุกโทเคน API และคีย์ MCP เพราะการตั้งค่าที่กู้คืนอาจนำสิ่งที่ถูกลบหลังบันทึกกลับมา ลงชื่อเข้าใช้ด้วยรหัสผ่านและตั้งพาสคีย์ใหม่ที่ **การตั้งค่า, ความปลอดภัย**
- **รหัสผ่านที่ลืม** รีเซ็ตที่หน้าเข้าสู่ระบบ **ลืมรหัสผ่าน?** ให้ BombVault เขียนรหัส 12 ตัวอักษร สามกลุ่มกลุ่มละสี่ ลงบันทึกคอนเทนเนอร์ของมัน (บน Unraid: แท็บ Docker ไอคอน BombVault **Logs**) รหัสนั้นและรหัสผ่านใหม่ทำให้คุณเข้าสู่ระบบได้ การรีเซ็ตยังปิดการยืนยันตัวตนสองขั้นตอน ลบทุกพาสคีย์ เพิกถอนทุกโทเคน API คีย์ MCP และการลงชื่อเข้าใช้ OAuth จบทุกเซสชันอื่น ให้ทุกโทรศัพท์ที่จับคู่ออกจากระบบ และปิดการจับคู่โทรศัพท์ หน้าหลังจากนั้นลิสต์สิ่งที่หายไป รหัสใช้ได้ 10 นาที และการเดาผิดไม่ทำให้มันหมดไป โทเคนวิดเจ็ตและ metrics ยังอยู่ เพราะมันอ่านอย่างเดียว
- **ใครอ่านบันทึกคอนเทนเนอร์ได้ก็รีเซ็ตรหัสผ่านได้** นั่นคือ root บนโฮสต์ แต่ก็รวมถึงตัวดูบันทึกอย่าง Dozzle คอนเทนเนอร์ใดก็ตามที่ได้ Docker socket (แบบอ่านอย่างเดียวก็พอ) และตัวส่งบันทึกที่ส่งต่อเอาต์พุตคอนเทนเนอร์ ให้สิ่งเหล่านั้นแก่คนที่คุณไว้ใจกับรหัสผ่านเท่านั้น คนที่เข้าถึงแค่หน้าเว็บจะไม่เห็นรหัส

### โทรศัพท์และสมาชิกกลุ่ม {#phones-and-members}

- **โทรศัพท์ที่จับคู่แล้วเข้าถึงรายการที่อนุญาต** โทรศัพท์ที่รู้คำสิบสองคำของกลุ่มลงชื่อเข้าใช้โดยไม่ต้องใช้รหัสผ่าน ตราบที่เปิด **โทรศัพท์จับคู่ด้วยคำสิบสองคำของกลุ่มได้** ในการ์ด **แอป Android** ใต้ **การตั้งค่า, ความปลอดภัย** เซสชันของมันเข้าถึงเฉพาะสิ่งที่แอปแสดง ได้แก่ ภาพรวม การรัน ข้อมูลสำรองที่ดู เริ่ม และกู้คืนได้ ความผิดปกติที่อ่านได้ และหน้าอินสแตนซ์ที่ดูได้ ปลายทางที่จัดเก็บและคำสั่งไปถึงมันโดยตัดที่อยู่และความลับออก และการกู้คืนที่แทนที่ต้นฉบับจะสำรองสถานะปัจจุบันก่อน การกู้คืนไปยังโฟลเดอร์รับเฉพาะโฟลเดอร์ใหม่หรือโฟลเดอร์ว่างภายในโฟลเดอร์กู้คืน และโทรศัพท์มองเข้าไปในโฟลเดอร์อื่นไม่ได้ อย่างอื่นทั้งหมดตอบว่าต้องลงชื่อเข้าใช้ที่อินสแตนซ์เอง ได้แก่ คีย์ ชุดกู้คืน การฝากคีย์ การตั้งค่า การลบข้อมูลสำรอง การรีเซ็ตรหัสผ่านปิดการจับคู่โทรศัพท์จนกว่าคุณจะเปิดอีกครั้ง โทรศัพท์ที่ถูกลบจากหน้าอินสแตนซ์ หรือปิด **สอบถามอินสแตนซ์นี้** ในรายละเอียดของมัน จะเสียเซสชันทันที และโทรศัพท์ที่ถูกลบแล้วเปิดแอปอีกจะกลับมาในสถานะปิด
- **เมื่อไม่อยู่บ้าน โทรศัพท์เปิดหน้าผ่านรีเลย์** ทุกคำขอของหน้าถูกปิดผนึกด้วยคีย์ของกลุ่ม ซึ่งรีเลย์อ่านหรือเปลี่ยนไม่ได้ และเซ็นด้วยคีย์ของโทรศัพท์เอง ซึ่งเซิร์ฟเวอร์ปักหมุดไว้ตอนที่โทรศัพท์เรียกครั้งแรก และยอมให้เข้าเมื่อมีคนอนุมัติโทรศัพท์นั้นบนหน้าการจับคู่ เซิร์ฟเวอร์รันคำขอหนึ่งครั้งและเฉพาะขณะที่ยังใหม่ มันตอบเฉพาะโทรศัพท์ที่อยู่ในหน้าอินสแตนซ์ขณะเปิดการจับคู่โทรศัพท์ และเฉพาะด้วยเซสชันที่มันให้โทรศัพท์นั้น การออกจากระบบทุกที่และการรีเซ็ตรหัสผ่านจึงจบหน้าเหล่านี้ด้วย เซิร์ฟเวอร์เซ็นทุกคำตอบ และแอปตรวจลายเซ็นกับคีย์ที่ปักหมุดไว้สำหรับเซิร์ฟเวอร์นั้นและเตือนเมื่อคีย์เปลี่ยน หน้าแบบนี้เข้าถึงรายการที่อนุญาตเดียวกับโทรศัพท์ที่จับคู่แล้ว ไม่ว่าจะมีรหัสผ่านเข้าสู่ระบบหรือไม่ บวกสถานะการลงชื่อเข้าใช้ที่หน้าอ่านก่อน การลงชื่อเข้าใช้และออก การรีเซ็ตรหัสผ่าน และการดาวน์โหลดอยู่ที่ที่อยู่ของเซิร์ฟเวอร์เอง และหนึ่งคำตอบถูกจำกัดที่ 16 MB
- **สมาชิกเซ็นสิ่งที่ขอ** คำขอบทบาทและคำตอบ ข้อเสนอที่จัดเก็บ การส่งมอบรหัสผ่าน restic ให้ตัวรับหรือตัวดึง การเข้าสู่ระบบของตัวรับ และการฝากคีย์ ถูกเซ็นด้วยคีย์ของสมาชิกแต่ละตัว ซึ่งอินสแตนซ์ปักหมุดไว้ครั้งแรกที่เห็นสมาชิกนั้น การเรียกที่เซ็นด้วยคีย์อื่นจะถูกปฏิเสธ **ลืมคีย์** ในรายละเอียดของอินสแตนซ์ทิ้งคีย์ที่ปักหมุดไว้ สำหรับกรณีที่คีย์ที่รู้อยู่ที่นี่ไม่ใช่ของสมาชิกเอง สมาชิกจะถูกขอคีย์อีกครั้งในการเรียกที่เซ็นครั้งถัดไป สมาชิกบน BombVault 9.x ไม่เซ็น และใครก็ตามที่มีคำเหล่านั้นแอบอ้างได้ เหมือนใน 9.9 คำขอบทบาทหรือข้อเสนอที่จัดเก็บจากสมาชิกบน 10.4 หรือเก่ากว่าจะถูกปฏิเสธจนกว่าสมาชิกนั้นจะอัปเดต
- **คำสิบสองคำคือรหัสผ่าน** ใครมีมันก็เข้าร่วมกลุ่ม เห็นสถานะการป้องกันของสมาชิก และขอบทบาทได้ ซึ่งคนบนอินสแตนซ์อีกฝั่งยังต้องอนุญาต ถ้าไม่มีรหัสผ่านเข้าสู่ระบบ ใครก็ตามที่เปิดหน้าเว็บได้ก็อ่านมันได้ และการ์ดการจับคู่บอกเช่นนั้นจนกว่าจะตั้งรหัสผ่าน

### คีย์ {#keys}

- **APP_KEY ทำสองอย่าง** มันปิดผนึกสิ่งที่การติดตั้งนี้เก็บ (รหัสผ่าน ข้อมูลรับรอง โทเคน) และเป็นกุญแจของข้อมูลสำรอง: รหัสผ่าน restic สร้างจากมัน และคำจำกัดความของคอนเทนเนอร์และ VM ถูกปิดผนึกด้วยมัน
- **คีย์ที่รับช่วงมาถูกเก็บแยก** เมื่อตัวช่วยฉุกเฉินรับข้อมูลสำรองของเซิร์ฟเวอร์อื่นมา การติดตั้งนี้ยังปิดผนึกด้วย APP_KEY ของตัวเองและเก็บคีย์ของเซิร์ฟเวอร์อื่นเป็น **คีย์ข้อมูลสำรอง** ปิดผนึกเหมือนความลับอื่น ชุดกู้คืนจะพิมพ์ทั้งสองคีย์ ถ้า APP_KEY ถูกเปลี่ยนภายหลัง คีย์ข้อมูลสำรองจะเปิดไม่ได้อีก: BombVault หยุดสำรองและบอกไว้ใต้ **ต้องดูแล** แทนที่จะเขียนด้วยคีย์ที่ผิด อัปโหลดชุดกู้คืนอีกครั้งใต้ **การกู้คืน, ฉุกเฉิน** หรือตั้ง APP_KEY กลับ ดู [ตัวช่วยฉุกเฉิน](offsite-recovery.md#emergency)
- **การเข้ารหัส** เปิดอยู่โดยค่าเริ่มต้น (**เข้ารหัสข้อมูลสำรอง** ในการ์ด **การเข้ารหัส** ใต้ **การตั้งค่า, ความปลอดภัย**) ข้อมูลสำรองถูกเข้ารหัสโดย restic ด้วยรหัสผ่านที่สร้างจากคีย์ข้อมูลสำรอง
- **การฝากคีย์** ผู้เก็บคีย์ในกลุ่มของคุณเก็บสำเนาชุดกู้คืนของเซิร์ฟเวอร์นี้ที่ปิดผนึกไว้ซึ่งมันเปิดเองไม่ได้ เฉพาะรหัสกู้คืน 20 ตัวอักษรที่เปิดได้ และผู้เก็บจะส่งมอบเมื่อมีคนที่นั่นกด **อนุญาต** เท่านั้น ดู [ผู้เก็บคีย์](offsite-recovery.md#key-keeper)

### เครือข่าย {#network}

- **การเปลี่ยนแปลงต้องใช้ JSON** คำขอที่เปลี่ยนอะไรต้องส่ง `Content-Type: application/json` และต้องไม่ถูกเบราว์เซอร์ทำเครื่องหมายว่าข้ามไซต์ หน้าบนไซต์อื่นจึงทำให้เบราว์เซอร์ของคุณเปลี่ยนการตั้งค่าบนที่อยู่ LAN ไม่ได้ สคริปต์ที่ขับ API ส่งส่วนหัวนั้น อย่างอื่นถูกปฏิเสธด้วย `415`
- เพราะประตูนี้เลือกเปิดเอง เมื่อไม่ตั้ง ทั้ง UI และ API (รวมถึงปลายทางที่จัดเก็บ เส้นทางการทดสอบการแก้ไขข้อมูล และเส้นทางการกู้คืน) เข้าถึงได้โดยใครก็ตามที่เข้าถึงพอร์ตได้ ตั้งรหัสผ่านเข้าสู่ระบบทันทีที่ใช้ข้อมูลสำรองนอกสถานที่ แบบ append-only หรือการเข้ารหัส
- รัน BombVault บนเครือข่ายที่เชื่อถือได้และไม่เปิดสู่ภายนอกเท่านั้น สำหรับการเข้าถึงระยะไกลให้วางไว้หลัง reverse proxy ที่เพิ่มการยืนยันตัวตนและ TLS การตอบสนองมีส่วนหัวความปลอดภัยพื้นฐาน (CSP, `nosniff`, `X-Frame-Options`, `Referrer-Policy`)
- หลัง reverse proxy ทุกคำขอมีที่อยู่ของ proxy ดังนั้นถ้าไม่มี `TRUSTED_PROXY` ตัวจำกัดการเข้าสู่ระบบจะนับทุกไคลเอนต์ในถังเดียว และความล้มเหลวของผู้โจมตีจะล็อกคุณออกด้วย ระบุ proxy ใน `TRUSTED_PROXY` เพื่อให้นับต่อไคลเอนต์อีกครั้ง
- reverse proxy หน้า BombVault ต้องส่งต่อส่วนหัว `Authorization` หรือ `X-API-Key` ไปยัง `/mcp` และต้องไม่บัฟเฟอร์การตอบสนอง ไม่เช่นนั้นผู้ช่วยจะเชื่อมต่อไม่ได้ ดู [เซิร์ฟเวอร์ MCP](mcp.md#tls)
- endpoint MCP `/mcp` ตอบ `404` จนกว่าจะมีคีย์หรือเปิดการลงชื่อเข้าใช้ผ่าน OAuth และมันขอคีย์หรือโทเคนจากทุกไคลเอนต์แม้ปิดรหัสผ่านเข้าสู่ระบบ ไม่มีที่อยู่ใดได้รับการยกเว้น แม้แต่ `localhost` มันไม่มีเครื่องมือกู้คืนหรือลบ และการกู้คืนข้อมูลสำรองการกำหนดค่าจะเพิกถอนทุกคีย์ ดู [เซิร์ฟเวอร์ MCP](mcp.md#security)
- เมื่อ `HTTP_ONLY=true` คุกกี้เซสชันเสียแฟลก `Secure` (ต้องเป็นเช่นนั้นจึงใช้ได้บน HTTP ธรรมดา) ดังนั้นเปิดรหัสผ่านหลัง proxy ที่ทำ TLS เท่านั้นถ้าความลับสำคัญ
- การเชื่อมต่อ SSH ของการสำรอง VM เชื่อถือคีย์โฮสต์ตอนเชื่อมต่อครั้งแรก (TOFU) และปักหมุดหลังจากนั้น ตรวจคีย์ของโฮสต์ผ่านช่องทางอื่นถ้าเส้นทางจากคอนเทนเนอร์ไปโฮสต์ของคุณไม่น่าเชื่อถือ
- **ลิงก์ไม่พาออกนอกจุดเมานต์** การสำรองหรือการกู้คืนทับที่เดิมจะหยุดพร้อมข้อความ เมื่อลิงก์ที่อยู่เหนือพาธของมันพาออกนอกจุดเมานต์ของโฮสต์ เพราะคอนเทนเนอร์ที่เขียนลงใน share ของตัวเองอาจวางลิงก์แบบนั้นไว้ได้ ปลายทางที่จัดเก็บที่โฮสต์หรือ remote ของ rclone ขึ้นต้นด้วยขีดจะถูกปฏิเสธแบบเดียวกัน ทั้งตอนบันทึกและในการรันครั้งถัดไป เพราะ `ssh` หรือ `rclone` จะอ่านมันเป็นตัวเลือก

## เซิร์ฟเวอร์ MCP {#mcp-server}

เซิร์ฟเวอร์ MCP ไม่ต้องใช้ตัวแปรสภาพแวดล้อม คุณเปิดมันด้วยการสร้างคีย์ที่ **การตั้งค่า, การเชื่อมต่อ, เซิร์ฟเวอร์ MCP** และมันตอบที่ `/mcp` บนพอร์ตเดียวกับหน้าเว็บ (เช่น `https://192.168.1.10:3443/mcp`) ถ้าไม่มีคีย์ที่ใช้งานอยู่ พาธนั้นตอบ `404` ไคลเอนต์ ใบรับรอง และขีดจำกัดอธิบายไว้ที่ [เซิร์ฟเวอร์ MCP](mcp.md)

## การสำรอง VM ผ่าน SSH {#vm-backup-over-ssh}

BombVault สำรอง VM แบบ KVM/libvirt **โดยไม่เมานต์พาธ libvirt ใด ๆ** มันรัน `virsh` บนโฮสต์ผ่าน SSH (`qemu+ssh://`) จึงไม่มีทางกระทบ VM Manager ของโฮสต์คุณ

การเมานต์ socket libvirt ของโฮสต์เข้าคอนเทนเนอร์เปราะบางบน Unraid: VM Manager เป็นเจ้าของพาธเหล่านั้น และการสลับ "Enable VMs" อาจทำให้ libvirt เริ่มไม่ได้ คีย์ SSH ให้สิทธิ์ root บนโฮสต์ ซึ่งเป็นระดับความไว้วางใจเดียวกับ Docker socket ที่ BombVault ใช้อยู่แล้ว

การตั้งค่าอย่างรวดเร็ว

1. **การตั้งค่า, การเชื่อมต่อ, SSH ของโฮสต์:** คัดลอกกุญแจสาธารณะที่แสดง
2. ต่อท้ายใน `/root/.ssh/authorized_keys` ของ Unraid (เก็บลงแฟลชด้วยเพื่อให้อยู่รอดหลังรีบูต)
3. คลิก **ทดสอบการเชื่อมต่อ**

เทมเพลตเพิ่ม `--add-host=host.docker.internal:host-gateway` เพื่อให้คอนเทนเนอร์เข้าถึงโฮสต์ได้ ตั้ง `LIBVIRT_HOST` เป็น IP LAN ของ Unraid ถ้าชื่อนั้น resolve ไม่ได้ (เช่นเมื่อคอนเทนเนอร์รันบนเครือข่าย `br0.x` แบบกำหนดเอง) ถ้าคุณเปลี่ยนพอร์ต SSH ของ Unraid ให้ตั้ง `LIBVIRT_SSH_PORT` ให้ตรงกัน **สแนปช็อตขณะทำงาน** ต้องมี qemu guest agent ใน VM และดิสก์อยู่บน `/mnt/cache` (ไม่ใช่ `/mnt/user`) ด้วย

!!! important "คู่มือ VM และเครือข่ายฉบับเต็ม"
    คู่มือทีละขั้นฉบับสมบูรณ์ (การเปิด SSH การอนุญาตคีย์ถาวร การกำหนดเส้นทางเครือข่ายแบบกำหนดเองและ VLAN วิธีต่อ VM และการแก้ปัญหาฝั่งโฮสต์) คือ [คู่มือการสำรอง VM](vm-backup-ssh-setup.md)

## การตั้งค่านอกสถานที่ {#off-site-setup}

สำเนานอกสถานที่ไปยัง **ปลายทางที่จัดเก็บ** เปิด **ปลายทาง** จากไทล์การตั้งค่าของมัน (หรือปักหมุดไว้ในแถบด้านข้าง) และเลือก **เพิ่มปลายทาง** ดู [นอกสถานที่และการกู้คืน](offsite-recovery.md) สำหรับขั้นตอนเต็ม (การป้องกันการลบ การทดสอบการแก้ไขข้อมูล และการซ้อม DR) โดยสรุป

- **แบ็กเอนด์:** SMB/CIFS และ WebDAV ผ่าน rclone โดยไม่ต้อง mount บนโฮสต์ NFS (เมานต์ export บนโฮสต์และใช้เป็นโฟลเดอร์ในเครื่อง) แบ็กเอนด์เนทีฟของ restic โดยไม่ใช้ rclone (`s3:...`, `rest:http://host:8000/repo`, `sftp:user@host:/repo`) หรือ rclone remote ใดก็ได้ (`rclone:<remote>:<bucket>/path`) Backblaze B2 ไม่มีแบ็กเอนด์เนทีฟที่นี่: เข้าถึงผ่าน endpoint S3 ของมัน (`s3:https://s3.<region>.backblazeb2.com/<bucket>/<path>`) โดยใช้ key ID และ application key เป็นข้อมูลรับรอง S3
- **ข้อมูลรับรอง** เก็บแบบเข้ารหัส เป็นรายการเดียวของข้อมูลรับรองที่บันทึกไว้ในการ์ด **ข้อมูลรับรอง** ใต้ **การตั้งค่า, ปลายทางที่จัดเก็บ** ดาวทำเครื่องหมายค่าเริ่มต้น ซึ่งใช้ทุกที่ที่ไม่ได้เลือกข้อมูลรับรอง หน้าของปลายทางเลือกอันที่มันใช้ในการ์ด **ข้อมูลรับรอง** ของมัน ดู [ข้อมูลรับรอง](offsite-recovery.md#sign-ins)
- **ปลายทาง SSH ไม่ต้องติดตั้งอะไรที่ฝั่งไกล** `sftp:` ต้องการแค่เซิร์ฟเวอร์ SSH เพิ่มกุญแจสาธารณะจาก **การตั้งค่า, การเชื่อมต่อ, SSH ของโฮสต์** (อยู่ที่ `/config/ssh/id_ed25519.pub` ด้วย) ลงใน `~/.ssh/authorized_keys` ของผู้ใช้ปลายทาง หรือให้ **เพิ่มคีย์** ใน **เพิ่มปลายทาง** ใส่ให้ด้วยรหัสผ่านของบัญชี
- **rest-server ที่มีใบรับรองเซ็นเอง:** วางใบรับรองของมัน หรือของผู้ออกที่เซ็น เป็นไฟล์ PEM ในโฟลเดอร์ `certs` ของโฟลเดอร์ข้อมูลของ BombVault (`/config/certs` ในคอนเทนเนอร์ `appdata/bombvault/certs` บน Unraid) การสำรอง การคัดลอก และการทดสอบการป้องกันการลบจะเชื่อถือมันโดยไม่ต้องรีสตาร์ท
- **สำเนานอกสถานที่:** BombVault คัดลอกสแนปช็อตใหม่ด้วย `restic copy` แบบ best-effort ทับบนที่เก็บหลัก (ซึ่งมักเป็นในเครื่อง) การ์ด **คัดลอก** ของปลายทางกำหนดว่าจะคัดลอก **หลังสำรองทุกครั้ง** หรือตามกำหนดการของตัวเอง และ **การตั้งค่า, ตารางเวลา, สำเนานอกสถานที่รายส่วน** ให้ส่วนหนึ่งมีกำหนดการคัดลอกของตัวเอง **จำลองตอนนี้** อยู่ในแถวของส่วนในการ์ด **สำเนานอกสถานที่** ใต้ **การตั้งค่า, ปลายทางที่จัดเก็บ**
- **หลายปลายทางต่อส่วน:** การ์ด **ปลายทางแยกตามส่วน** บนหน้าปลายทางที่จัดเก็บเปิดหรือปิดแต่ละบรรทัดจากส่วนไปยังปลายทางด้วยคลิกเดียว รวมถึง **ในเครื่อง** ส่วนที่มีเฉพาะปลายทางนอกสถานที่จะสำรองตรงไปที่นั่น และส่วนที่ปิดทุกบรรทัดจะไม่ถูกสำรอง **กฎแยกตามส่วน** ของปลายทางให้ส่วนหนึ่งมีที่เก็บ การเก็บรักษา หรือการบีบอัดของตัวเองที่นั่น
- **การวางต่อรายการ:** คอนเทนเนอร์ VM และชุดโฟลเดอร์แต่ละรายการจะไฟติด **ในเครื่อง** และปลายทางที่ได้รับข้อมูลสำรองของมัน ในการ์ด **ตารางเวลาและปลายทาง** บนแท็บการตั้งค่าของมัน รายการที่ไม่มีตัวเลือกของตัวเองตามส่วนของมัน ดู [การวางต่อรายการ](offsite-recovery.md#placement)
- **การเก็บรักษา:** แต่ละปลายทางเก็บข้อมูลสำรองตามการ์ด **เก็บไว้นานแค่ไหน** ของมัน และส่วนหนึ่งเก็บค่าของตัวเองที่นั่นได้ใต้ **กฎแยกตามส่วน** รวมถึงสำเนาในช่องนอกสถานที่ของส่วน ศูนย์ทั้งหมดไม่ตัดสแนปช็อตของปลายทางเลย
- **ขีดจำกัดแบนด์วิดท์:** จำกัดอัตราอัปโหลด/ดาวน์โหลดของ restic ในการ์ด **แบนด์วิดท์นอกสถานที่** ใต้ **การตั้งค่า, ปลายทางที่จัดเก็บ** หรือต่อปลายทางในการ์ด **คัดลอก** ของมัน คุณกรอก KiB/s และช่องแสดงอัตราเดียวกันเป็น MB/s และ Mbit/s
- **สตรีมมิงมาก่อน:** ในการ์ด **สตรีมมิง** บนหน้าปลายทางที่จัดเก็บ เลือกมีเดียเซิร์ฟเวอร์ (Plex, Jellyfin และ Emby เลือกไว้ล่วงหน้าตามชื่อ image) อัตราส่งที่นับว่าสตรีม ขีดจำกัดอัปโหลดขณะสตรีม และนานแค่ไหนหลังสตรีมที่ขีดจำกัดปกติกลับมา
- **ชั้นเก็บแบบเย็นและอาร์ไคฟ์ (S3):** สำหรับปลายทาง S3 เลือกชั้นที่กู้คืนอ่านได้ (Standard, Standard-IA, One Zone-IA, Intelligent-Tiering, Glacier Instant Retrieval) บนหน้าของมัน rclone remote ตั้งชั้นของมันในการกำหนดค่า rclone
- **โฟลเดอร์ของตัวเองในปลายทางแทนในเครื่อง:** โฟลเดอร์ของตัวเองของส่วนอยู่ในปลายทางข้างบนแห่งใดแห่งหนึ่งได้ โดยไม่มีสำเนาในเครื่องและไม่มีขั้นตอนคัดลอก ดู [โฟลเดอร์ของตัวเองของส่วน](offsite-recovery.md#own-folder)

## ความผิดปกติ {#anomalies}

การตรวจจับความผิดปกติไม่ต้องใช้ตัวแปรสภาพแวดล้อม ตั้งค่าในการ์ด **ความผิดปกติ** ใต้ **การตั้งค่า, ยืนยัน** ซึ่งอธิบายที่ [ความผิดปกติ](anomalies.md#settings)

## การตั้งค่าแบบพกพา (ส่งออกและนำเข้า) {#portable-settings-export-and-import}

การ์ด **ส่งออก / นำเข้าการตั้งค่า** ใต้ **การตั้งค่า, ระบบ** เขียนการกำหนดค่า BombVault ทั้งหมดของคุณ (การตั้งค่าส่วน ปลายทางที่จัดเก็บ ตารางเวลา การเก็บรักษา การแจ้งเตือน) เป็นไฟล์ JSON แบบพกพาที่นำเข้าบนอินสแตนซ์อื่นได้ การย้ายไปกล่องใหม่หรือโคลนการตั้งค่าจึงไม่ต้องกรอกทุกอย่างใหม่ด้วยมือ การนำเข้าแสดงตัวอย่างและขอการยืนยัน และไม่แตะข้อมูลสำรองหรือประวัติของคุณเลย ลิงก์ในไฟล์ไปยังปลายทางที่จัดเก็บหรือที่เก็บที่ไม่มีอยู่แล้วจะถูกเว้นไว้ และตัวอย่างบอกชื่อมัน ขณะที่เรพลิกา ZFS รันอยู่ การนำเข้าจะถูกปฏิเสธก่อนเขียนอะไร

!!! warning "การส่งออกอาจมีข้อมูลรับรอง"
    คุณเลือกว่าจะรวมข้อมูลรับรองนอกสถานที่ การแจ้งเตือน และโบรกเกอร์ MQTT ไว้ในไฟล์หรือไม่ เมื่อรวมข้อมูลรับรอง การส่งออกมีความอ่อนไหวเท่ากับชุดกู้คืนของคุณ จึงควรเก็บไว้ในที่ปลอดภัย ถ้าไม่รวม ไฟล์จะมีเฉพาะการตั้งค่าที่ไม่ใช่ความลับ

!!! warning "APP_KEY ไม่ได้ไปกับไฟล์"
    ที่เก็บถูกล็อกด้วยรหัสผ่านที่สร้างจาก `APP_KEY` และไฟล์ไม่มีคีย์นี้ ถ้าวางแผนย้ายเครื่อง ให้ใส่ `APP_KEY` เดิมในเทมเพลตของกล่องใหม่ หรือรับช่วงคีย์ด้วยชุดกู้คืนใต้ **ฉุกเฉิน** ถ้าใช้คีย์อื่น ที่เก็บจะตอบว่ารหัสผ่านผิด ไม่มีอะไรหาย และเมื่อตั้งคีย์ที่ถูกต้อง ที่เก็บก็จะเปิดได้อีกครั้ง
