# 保存場所

保存場所とは、BombVault がバックアップを置く場所のことです。この Unraid 上のフォルダー、NAS の共有、クラウドプロバイダーのバケット、rest-server、SFTP アカウント、Nextcloud などがあります。各保存場所は **設定、ストレージ** で一度だけ接続し、その認証情報、保持、保護、設置場所はその保存場所に属します。ドメイン（コンテナ、VM、フラッシュ、BombVault 自身の設定、ファイルセット、ZFS データセット）は、これらの保存場所の中から、各ドメインをどこに保存し、どこへコピーするかを選びます。ZFS データセットの行は、ZFS ドメインがオンの間、「ドメイン」カードに表示されます。

## 保存場所の追加 {#add-a-place}

**保存場所を追加** を押すと、プロバイダーごとに 1 つのタイルを並べたウィンドウが開きます。タイルはクラウドストレージ、セルフホスト、NAS とこのサーバーの 3 つのグループに分かれています。

1. タイルを選び、そのフォームに入力します。目のボタンを押すと、入力したシークレットが表示されます。
2. **接続をテスト** は保存場所を確認するだけで、何も作成しません。各ドメインのフォルダーについて、見つかった状態を報告します。空またはまだない、すでに restic リポジトリがある、あるいは確認を妨げたエラーのいずれかです。
3. 保存場所に名前を付けます。プロバイダー名があらかじめ入っています。自分で運用している機器の場合は、**機器はどこにありますか？** に答えてください。クラウドプロバイダーは常に別の拠点にあり、この Unraid 上のフォルダーは常にここにあります。
4. **追加** で保存場所を保存します。

新しい保存場所は、まだどのドメインにも使われていません。[「ドメイン」カード](#domains)の **保存先** または **コピー先** で選ぶか、その項目だけに使うなら項目のカードで選んでください。

## フォルダー {#folders}

保存場所には、ドメインごとに 1 つのフォルダーがあります。`container`、`vms`、`flash`、`config`、`files`、`zfs` で、既定のバックアップ先と同じ名前です。フォルダーは保存場所の詳細に一覧表示され、そこで名前を変更できます（[アドレスの変更](#addresses)を参照）。保存場所にフォルダーのないドメインは、その保存場所を選べません。

ドメインが 1 つの保存場所を両方の役割で使う場合、2 つ目の役割には接尾辞が付き、1 つ目の役割は自分のフォルダーをそのまま使います。すでにドメインのコピーを受け取っている保存場所は、直接送られてくる項目を `<folder>-direct` に保存します。すでにドメインを保存している保存場所は、そのコピーを `<folder>-copies` で受け取ります。

保存場所の中には、それ自体が restic リポジトリであるものもあります。保存場所を追加したときにすでにリポジトリがあったアドレス、既存の構成から引き継いだ名前付きリポジトリ、バケットのルートにあるコピー先などです。このような保存場所にはフォルダーがなく、すべてのドメインが 1 つのリポジトリを共有し、2 つ目の役割は持てません。同じプロバイダーにさらに保存するには、別のバケットやフォルダーを独立した保存場所として接続してください。

## 保存場所の詳細 {#details}

各保存場所は 1 行で表示され、プロバイダー、用途、最後のテストまたはコピーが示されます。**テスト** は保存場所のすべてのアドレスを確認し、**詳細** はその設定を開きます。詳細での変更は、行うたびに保存されます。

- **一般**: 名前、保存場所のオンとオフを切り替えるスイッチ、アドレス、そして自分で運用している機器の場合は **機器はどこにありますか？**（[敷地外](#off-the-premises)を参照）。
- **保持**: 最新を保持、日次、週次、月次で、保存場所のすべてのリポジトリに適用されます。新しい保存場所は既定のルールで始まります。すべてのルールがゼロの保存場所は何も整理しません。
- **保護**: **append-only** スイッチ。追記専用を強制するのは相手側です。スイッチがオンなら、BombVault はそこで整理も削除も行いません。append-only をオンにした rest-server では、**append-only をテスト** が、その保存場所にあるすべてのドメインのパス、オンになっているコピー、リポジトリに対して改ざんテストを実行し、保存場所全体として 1 つの答え、*削除は拒否されました* または *削除が受け付けられました* を表示します（[オフサイトと復旧](offsite-recovery.md)を参照）。このセクションはリモートの保存場所にしかありません。この機器上の何ものも、ローカルリポジトリの削除を止められないためです。
- **アクセス**: 認証情報と、S3 の場合はストレージクラス。共有の認証情報を使っている保存場所は、最初に変更したときに専用のセットを持ちます。保存場所にあるダイレクトリポジトリを新しい認証情報で開けない場合、そのダイレクトリポジトリは古い認証情報を使い続け、応答でその旨が示されます。フォルダー、SFTP、rclone の保存場所にはこのセクションはありません。
- **制限**: アップロードとダウンロードのレート、そして成長予算。
- **フォルダー**: ドメインごとに 1 つのスイッチと、そのフォルダーの名前。ここでオフにしたドメインは、その保存場所を選べません。

保持を減らすときは、先に確認を求め、影響を受ける項目の数を示します。append-only をオフにするときは、先に確認を求め、保護を失うその保存場所のリポジトリの数を示します。保存場所をオフにすると、そこにあるすべてのリポジトリがオフになります。ドメインの保存先になっている保存場所はオフにできません。

## 「ドメイン」カード {#domains}

このカードにはドメインごとに 1 行があり、スケジュール、保存先、コピー先、例外が表示されます。

- **保存先**: ドメインのバックアップ先にまだバックアップがない間は、選んだ保存場所がドメインの保存先になり、バックアップ先もそこへ移ります。バックアップができた後は、コンテナ、VM、ファイルセットではこの選択が新しい項目の既定値になり、新しい項目は最初のバックアップでそれを使います。すでにバックアップのある項目はそのままの場所に残ります。BombVault はバックアップを決して移動しないためです。フラッシュと BombVault 自身の設定では保存先そのものが移り、すでに書き込まれたバックアップは古い保存場所に残ります。
- **コピー先**: ドメインのコピーを受け取れる保存場所ごとに 1 つのチップがあります。チップにチェックを入れると、その保存場所がドメインのコピー先になります。初回は、最初の実行で何個の項目とスナップショット、どれだけのデータが送られるかを BombVault が事前に示します。チェックを外すと新しいコピーは止まります。すでにあるコピーはそのまま残って保存場所の保持ルールに従って整理され、独自の選択を持つ項目は引き続きそこへコピーします。最後のチップのチェックを外すと、再びどれかにチェックを入れるまで、後から追加した保存場所も含めてすべてのコピーが止まります。オフになっている保存場所は薄く表示されたチップになり、選べません。
- **例外**: 独自の選択を持つ項目を、それぞれのカードへのリンク付きで一覧表示します。
- **今すぐコピー** は、ドメインのコピーをすぐに実行します。

検出経由の再構築の後に一時停止したドメインは、その行に一時停止が表示され、**既定を確認** があります（[項目ごとの配置](offsite-recovery.md#placement)を参照）。

## アドレスの変更 {#addresses}

ドメインのフォルダーは保存場所の詳細で変更できます。ローカルの保存場所のアドレスも同様で、たとえばリポジトリを手動で別のディスクへ移した後に使います。BombVault は変更が影響するすべてのアドレスをテストし、新しいアドレスがどれも空で古いアドレスに何も保存されていなかった場合、または新しいアドレスがどれも古いアドレスと同じ restic リポジトリを持っている場合に変更を受け入れます。それ以外は拒否され、古いアドレスにまだ残っているバックアップの数が示されます。リモートの保存場所のアドレスは変えられません。別の場所へバックアップするには、それを独立した保存場所として接続してください。

BombVault は保存場所の一覧を自分のデータベースから作り、一覧を埋めるためにリモートリポジトリを列挙することはありません。テストは何かを変更したときにだけ実行されます。

## 保存場所の削除 {#remove}

保存場所を削除できるのは、何もそれを使っていない間だけです。そこに保存されているドメインがなく、そこを指す既定値がなく、そこに保存されている項目がなく、そこにあるダイレクトリポジトリが項目を持っていないことが条件です。そうでなければ、何が使っているかを一覧にして拒否されます。削除すると、その保存場所へのコピー先の設定も一緒に削除され、取得元や別の保存場所が使っていなければ専用の認証情報も削除されます。ストレージそのものの中では何も削除されず、確認ではそこに残るコピーの数が示されます。

## 保存場所なし {#without-a-place}

保存場所とフォルダーという形に当てはまらないアドレスはそのまま動作し続け、**保存場所なし** にそのアドレスとともに一覧表示されます。ネイティブの `b2:`、`gs:`、`swift:` のアドレスもこれに含まれます。**保存場所に割り当て** は、[アドレスの変更](#addresses)と同じテストの後で、そのような行を保存場所に結び付けます。保存場所のないコピー先は、そのドメインの行にもチップの隣に名前が表示され、コピーを続けます。そこにあるリモートの行には独自の **append-only** スイッチがあり、オフにするときは、そのアドレスにバックアップを置いている項目の数を示して先に確認を求めます。直接リポジトリは、そのターゲットのスイッチに従います。

## 敷地外 {#off-the-premises}

**機器はどこにありますか？** には **同じ建物内** と **別の拠点** の 2 つの答えがあります。カード上の 3-2-1 の行でも、ダッシュボードのオフサイトのチェックでも、コピーが独立したサイトとして数えられるのは、その保存場所が別の拠点にある場合だけです。同じ建物内の 2 台目のディスクや NAS は 2 つ目のコピーであり、2 つ目のサイトではありません。この答えでコピーが変わることはありません。クラウドプロバイダーは常に別の拠点にあり、この Unraid 上のフォルダーは常にここにあるため、フォームではこれらについて尋ねません。それ以外の保存場所では、詳細で答えを変更できます。別の拠点にある保存場所には、その行に **別の拠点** の印が付きます。

## 接続方式

### この Unraid 上のフォルダーまたは NAS {#kind-local}

アドレスは `/mnt` 配下のパスで、`/mnt` を付けずに書きます。たとえば `user/bombvault` で、各ドメインのフォルダーはその下に置かれます: `user/bombvault/container`。

- **この Unraid 上のフォルダー** は、共有、ディスク、プールから選びます。
- **Synology**、**QNAP**、**TrueNAS**、**別の Unraid**、**その他の共有** は `/mnt/remotes` から選びます。先に Unraid で共有をマウントしてください（たとえば Unassigned Devices プラグインで）。Host Data は Read/Write - Slave でマウントされている必要があります。そうでないと、BombVault の起動後にマウントされた共有は、再起動するまで見えません（[設定](configuration.md)を参照）。

フォルダーピッカーでは、**新しいフォルダー** で今いる場所にフォルダーを作成できます。テストでは、フォルダーが空または存在しないこと、そして BombVault がそこに書き込めることを確認します。

### S3 {#kind-s3}

アドレスは `s3:https://<endpoint>/<bucket>/<path>` で、たとえば `s3:https://s3.eu-central-003.backblazeb2.com/tower-backups/bombvault` です。

- **Backblaze B2** に必要なのはキー ID とアプリケーションキーだけです。BombVault は、そのキーがどのバケット、S3 エンドポイント、フォルダーに限定されているかを B2 に問い合わせ、そこからアドレスを組み立てます。すべてのバケットにアクセスできるキーの場合は、バケットの一覧から選べます。
- **Amazon S3**、**Cloudflare R2**、**Wasabi**、**Hetzner Object Storage**、**Storj**、**IDrive e2**、**Scaleway**、**OVHcloud**、**DigitalOcean Spaces**、**IONOS**、**Contabo**、**Exoscale**、**Vultr** は、キーと、プロバイダーが必要とする場合はリージョン、アカウント ID、エンドポイントを求めます。BombVault はエンドポイントを入力し、キーにバケットを一覧表示する権限があればバケットを一覧表示します。権限がなければバケット名を入力してください。
- **Google Cloud Storage** は S3 インターフェース経由で、HMAC キーを使って接続します。HMAC キーは Cloud Storage の設定の「相互運用性」で作成します。サービスアカウントのファイルはここでは使えません。
- **MinIO**、**SeaweedFS**、**Garage**、**Ceph**、**JuiceFS**、**RustFS**、**Versity S3 Gateway**、**その他の S3 サービス** は、サービスのアドレスとキーを使います。

ストレージクラスは保存場所の詳細で設定します。選べるのは、解凍なしで復元が読み取れる階層だけです。

### rest-server {#kind-rest}

アドレスは `rest:<url>/<user>` で、たとえば `rest:https://nas.lan:8000/tower` です。フォームはサーバーのアドレス、ユーザー、パスワードを求めます。`--private-repos` を付けると、ユーザーは自分の名前で始まるパスにしかアクセスできないため、別のパスを入力しないかぎり、BombVault はユーザー名を先頭に置きます。サーバーがユーザー自身のもの以外のパスを拒否した場合は、エラーにその旨が示されます。

rest-server のフォームには、この BombVault 用のユーザーを 1 人持つ append-only モードの rest-server の、すぐ貼り付けられるレシピがあります。**レシピを表示** はパスワードを作って一度だけ表示し、`docker run` の行、compose ファイル、Unraid テンプレートを示します。どれにも、サーバーに置く `htpasswd` の行が付いています。ユーザーとパスワードはそのままフォームに入力されます。

**別の BombVault** では、ほかのインスタンスがフリート経由で送ってきた未処理の提案が、自身の入力欄の上に一覧表示されます。提案を承認すると、提案されたドメインのコピーだけを保存する保存場所が追加されます。提案にはその 1 つのドメイン用のユーザーしか含まれていないためです。フリートページで承認しても、同じ保存場所が追加されます。

### SFTP {#kind-sftp}

アドレスは `sftp://<user>@<host>:<port>/<path>` で、たとえば `sftp://bv@backup.lan:22/bombvault` です。フォームはホスト、ポート、ユーザーを求め、BombVault の公開鍵を表示します。その鍵をサーバー上のユーザーの `~/.ssh/authorized_keys` に追加してください。サーバーにはほかに何もインストールする必要はありません。BombVault は初回接続時にサーバーのホスト鍵を受け入れ、以後はそれを確認します。

**Hetzner Storage Box** では `<user>.your-storagebox.de` とポート 23 が入力されます。鍵は Hetzner 独自のコマンドで Storage Box にインストールします。このコマンドは Storage Box のパスワードを一度だけ尋ねます:

```sh
echo '<public key>' | ssh -p 23 <user>@<user>.your-storagebox.de install-ssh-key
```

### WebDAV: Nextcloud、ownCloud、OpenCloud {#kind-webdav}

フォームはサーバーのアドレス、ユーザー、アプリパスワードを求めます。アプリパスワードはアカウントのセキュリティ設定で作成し、メールアドレスではなくユーザー ID を入力してください。BombVault は製品が使う WebDAV のパスを組み立て、rclone の環境変数を通じて接続を restic に渡します。パスワードは rclone の難読化された形式で渡されます。アドレスは `rclone:bvp<id>:<path>` となり、`bvp<id>` はその環境の中にだけ存在するリモートです。rclone 設定には何も書き込まれません。

### Azure Blob {#kind-azure}

アドレスは `azure:<container>:/<path>` です。フォームはストレージアカウントとそのアクセスキーを求めます。**接続をテスト** の後、アカウントのコンテナーが一覧表示されるので、そこから選ぶか、コンテナー名を入力します。BombVault はアカウントとキーを `AZURE_ACCOUNT_NAME` と `AZURE_ACCOUNT_KEY` として restic に渡します。

### rclone {#kind-rclone}

アドレスは `rclone:<remote>:<path>` です。フォームには BombVault の rclone 設定にあるリモートが一覧表示されるので、そこから選びます。その設定を置き換えるには、`rclone.conf` 全体を **rclone 設定** に貼り付けて **設定を保存** をクリックします。設定はすぐに保存され、そのあとウィンドウで保存場所を追加するかどうかに関係なく、すべての rclone の保存場所で使われます。

## 認証情報の異なる保存場所間のコピー {#different-credentials}

リモートの保存場所に保存されたドメインは、そのコピーの元になります。`restic copy` は 1 つの環境で実行されます。BombVault は、コピー元とコピー先が同じ変数に異なる値を設定していなければ、コピー元の認証情報をコピー先の認証情報に加えます。Nextcloud の保存場所と B2 の保存場所は異なる変数を使うため、Nextcloud に保存されたドメインを B2 へコピーできます。2 つの S3 アカウントや 2 人の rest-server ユーザーでは、同じ変数に異なる値が必要になります。restic は両方を受け取れないため、「ドメイン」カードのチップに、認証情報が合わない旨が表示されます。
