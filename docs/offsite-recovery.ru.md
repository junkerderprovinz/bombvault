# Внешняя копия и восстановление

!!! note "Внешние копии ждут после пересборки"
    Когда Аварийный мастер или **Найти резервные копии** пересобирает записи без прежних настроек, внешние копии этих разделов приостанавливаются, пока не подтверждено их значение по умолчанию. См. [После пересборки](#after-a-rebuild).

Локальные копии защищают от потерянного контейнера или неудачного обновления. Внешние копии и проверенный набор для восстановления защищают от потери всей машины, шифровальщика или пожара. Эта страница охватывает места назначения и внешние копии, защиту копии от подделки, доказательство того, что вы можете восстановиться, сопряжение нескольких серверов и возврат всего, когда самого BombVault больше нет.

## Внешние копии {#off-site-copies}

Оставьте быструю локальную копию и добавьте одно или несколько мест назначения вне дома. BombVault копирует туда новые резервные копии через `restic copy` по принципу максимальных усилий, поэтому сбой внешней копии никогда не делает неудачной локальную. В такой схеме локальный репозиторий остаётся основным, а внешний это копия, но основной репозиторий раздела вообще не обязан быть локальным; см. ниже [Удалённые основные репозитории](#remote-primary-repositories) о копировании сразу в S3, rest-server и подобное вместо копирования туда.

- **Несколько мест назначения на раздел.** Каждый раздел (контейнеры, виртуальные машины, flash, автобэкап, папки и наборы данных ZFS) может копироваться сразу в несколько внешних мест назначения, так что можно держать, например, rest-server на машине друга и корзину S3 параллельно. Карточка **Места назначения по разделам** на странице мест назначения включает и выключает каждую линию от раздела к месту назначения.
- **Когда идут копии.** Карточка **Копировать** места назначения задаёт **Когда копировать**: **После каждой резервной копии** или по собственному плану, который собирает резервные копии и копирует в назначенное время. В **Настройки, Расписание, Внешние копии по разделам** кнопка **Исключение** даёт разделу собственный план копирования. **Реплицировать сейчас** в карточке внешней копии раздела в **Настройки, Места назначения** запускает копирование по требованию.
- **Хранение** задаётся для каждого места назначения в **Как долго хранить**, так что внешние копии можно хранить дольше, как архив. Копия в поле внешней копии раздела следует карточке **Внешнее хранение** в **Настройки, Места назначения**; оставьте её со всеми нулями, чтобы никогда автоматически не обрезать внешние резервные копии.
- **Ограничения пропускной способности** (**Внешняя пропускная способность** в **Настройки, Места назначения** или карточка **Копировать** места назначения) ограничивают скорость выгрузки/загрузки restic, чтобы копии не забивали ваш WAN.
- Пока идёт копирование, шапка состояния на обзоре говорит **Идёт копирование во внешнее место назначения**. Это индикатор активности, а не полоса процентов, потому что `restic copy` не отдаёт машиночитаемого прогресса.

!!! note "Восстановление из любого места"
    Каждая запись показывает свои копии единой временной шкалой по всем местам, где лежит копия, на вкладке **Резервные копии**. Копия, скопированная в B2, появляется один раз с отметкой каждого места, где она есть. Восстановление берёт первое место, до которого может добраться, начиная с репозитория, в который пишется запись, и для каждой резервной копии можно выбрать другое место. Внешние места назначения читаются только по нажатию **Проверить**, потому что перечисление облачного хранилища занимает время. Удаление в одном месте сначала проверяет остальные и сообщает, была ли это последняя копия.

## Места назначения {#destinations}

Место назначения это место, куда попадают копии: локальная папка, общий ресурс, ваш собственный сервер или облачный сервис. Оно настраивается один раз и затем обслуживает каждый раздел. Откройте **Места назначения** с её плитки настроек или включите там **Показывать также в боковой панели**, чтобы закрепить.

**Добавить место назначения** открывает окно из четырёх шагов:

1. **Провайдер.** Каждый сервис перечислен со своим логотипом, справа вверху окна поиск, по группам: сервисы хранения с корзинами S3 (Backblaze B2, Wasabi, Cloudflare R2, Hetzner Object Storage, Amazon S3 и другие), ваш собственный сервер S3 (Garage, SeaweedFS, RustFS, Silo, Ceph, JuiceFS, Versity S3 Gateway), ваш собственный сервер и общие ресурсы (rest-server, Hetzner Storage Box, SFTP, SMB, WebDAV, смонтированный путь), облачные хранилища (OneDrive, Google Drive, Dropbox, pCloud, Nextcloud и остальное, что поддерживает rclone) и принимающие серверы вашей группы. Каждый говорит, насколько подходит для копий: облачные диски замедляются при множестве запросов, поэтому первая копия и очистка там идут дольше.
2. **Вход.** Поля зависят от сервиса: ключ доступа для S3, пользователь и пароль для WebDAV и SMB, пароль приложения там, где двухфакторный вход блокирует обычный, открытый SSH-ключ BombVault для SFTP и Storage Box или токен для сервисов, входящих через браузер. Для них окно показывает команду `rclone authorize`, которую нужно выполнить на компьютере с браузером; напечатанный ею токен вставляется в поле. **Проверить** проверяет вход до сохранения чего-либо. Затем окно перечисляет папки в месте назначения, с **Новая папка** для создания и свободным местом там, где сервис его сообщает. Безопаснее всего пустая папка; BombVault кладёт в неё по одной папке на раздел.
3. **Защита.** Окно прямо говорит, что умеет сервис. Rest-server в режиме append-only отказывает в удалении, и тест на подделку это проверяет. Корзина S3 может хранить старые версии через версионирование и object lock, чего BombVault пока проверить не может. Облачный диск не может отказать в удалении вообще: кто попал на сервер, попал и в эту копию. Включайте **Защита от удаления (append-only)** только там, где дальняя сторона действительно отказывает в удалении; BombVault тогда никогда не очищает там. **На случай аварии** говорит, что набор для восстановления хранит для этого места назначения.
4. **Для каких разделов.** Выберите разделы, которые копируются сюда. Первая копия приносит всю историю. Записи, выбравшие собственные места назначения, новое сами не получают, и окно их называет.

Сервисы S3 работают через собственный бэкенд S3 restic, что и позволяет применять класс хранения и object lock. Любой другой сервис работает через rclone, поставляемый с BombVault, и его удалённое хранилище затем появляется в карточке **Внешнее (rclone)** в **Настройки, Места назначения**. Экспорт настроек несёт места назначения; с включёнными учётными данными он несёт и их вход.

У каждого места назначения своя страница:

- **Подключение** с названием, переключателем **Доступен** (выключено означает, что BombVault сюда больше не пишет, а записи, которые копируются сюда, завершаются понятным сообщением, а не попадают куда-то ещё), папкой, сжатием, классом хранения и **Вне помещения**. **Изменить подключение** проверяет и сохраняет новый адрес или вход.
- **Учётные данные**: общий набор или собственный.
- **Защита от удаления** с **Проверить защиту от удаления сейчас** и указанием, кто очищает эту копию.
- **Копировать**: когда копировать и лимиты выгрузки и загрузки.
- **Как долго хранить**: **Коротко**, **Средне**, **Долго** или **Свои значения** с временной шкалой, какие копии сохраняет правило. **Спрашивать перед сокращением хранения** спрашивает, прежде чем более короткое правило удалит копии, единственный экземпляр которых здесь.
- **Правила по разделам**: собственный репозиторий, хранение или сжатие раздела в этом месте назначения. **Изменить правила** открывает их, а **Вернуть настройки места назначения** возвращает раздел.
- **Уже под этим местом назначения**: разделы, чей введённый вручную адрес лежит в папке этого места назначения. Перенятие оставляет репозиторий на месте; вход, класс хранения и защита от удаления тогда берутся от места назначения. BombVault сначала проверяет, что вход места назначения открывает репозиторий, и отказывается подводить репозиторий append-only под место назначения, которое не append-only.
- Сосуд, показывающий, насколько заполнено место назначения, с отметкой, где оно заполнится, и сколько недель осталось при росте за последние недели. Место назначения, не сообщающее свой размер, говорит **Размер неизвестен**.

Принимающий сервер, который запускает другой экземпляр вашей группы, появляется среди провайдеров как **Из вашей группы**; см. [Принимающий сервер](#receiving-server).

### Перенос и удаление {#move-remove}

- **Переместить** переносит копию одного раздела в другое место назначения со всей историей. Всё остаётся на старом месте; BombVault там ничего не удаляет. Перенос идёт в фоне и может занять много времени: около 9 минут на 100 ГБ между локальными дисками, часы по медленному каналу. Обзор показывает его, пока он идёт.
- **Удалить место назначения** предлагает два пути. **Удалить место назначения, оставить копии** прекращает запись туда и оставляет копии на месте; позже их можно прочитать в **Восстановление, Из старой папки с копиями**. **Удалить место назначения и стереть резервные копии там** сначала читает, что там хранится, и перечисляет: какие копии уйдут, какие из них больше нигде не лежат и какие репозитории остаются, потому что защита от удаления отказывает, записи ещё копируются прямо в них, другое место назначения или раздел держит там свои копии либо их не удалось прочитать. Записи, которые потеряли бы единственную копию, перечислены отдельно и сохраняются, пока вы не включите **Стереть и эти**. Подтверждение это ввод имени места назначения, а удаление идёт в фоне.
- Удаление копий в месте назначения требует пароль для входа и вход на самом экземпляре. Без пароля место назначения всё равно можно удалить, только его копии отсюда стереть нельзя.

## Размещение для каждой записи {#placement}

Карточка **Расписание и место назначения** на вкладке «Настройки» записи содержит ряд кнопок: **Локально** и по одной кнопке на каждое внешнее место назначения раздела. Подсвеченные кнопки получают копии записи.

- С подсвеченной **Локально** запись пишется в репозиторий, указанный в **Сохранено на**, и копируется в каждое другое подсвеченное место. Погасите место, и оно ничего нового от этой записи не получит. Одна Локально никуда не копирует, что подходит данным, у которых уже есть вторая копия, например общему ресурсу, лежащему на NAS.
- С погашенной **Локально** запись пишется прямо в прямой репозиторий первого подсвеченного места и копируется оттуда в остальные подсвеченные. В первый раз окно создаёт этот прямой репозиторий.
- Одна кнопка остаётся подсвеченной, потому что копии нужно куда-то идти. Чтобы вывести запись из копирования, используйте **Не копировать**.

Место фиксируется с первой копии записи, потому что BombVault никогда не переносит копии между репозиториями; карточка **Репозиторий** на вкладке «Настройки» его называет. Копии можно менять в любое время. Место назначения, которое больше не получает запись, сохраняет имеющиеся копии и обрезает их по собственному хранению при следующем внешнем запуске раздела. Из мест назначения append-only удалять нельзя.

Под рядом карточка говорит, куда идёт запись и что там реально есть: сколько мест её хранят, когда в последний раз видели каждое место назначения и выполнено ли 3-2-1. Место это сервер с исходными данными, каждое внешнее место назначения и каждый репозиторий, отмеченный **Вне помещения**. BombVault проверяет копии и места; часть «два носителя» из 3-2-1 он не проверяет.

### Умолчания по разделам {#placement-defaults}

Карточка **Места назначения по разделам** на странице мест назначения это умолчание каждого раздела. На схеме каждая линия это копия, и щелчок по линии или точке включает или выключает её; пунктирные линии выключены. **Схема / Переключатели** показывает то же рядами кнопок. Флешка, наборы данных ZFS и автобэкап всегда сначала копируются в свою локальную папку, а их внешние копии делаются из этой копии, поэтому их линию к ней выключить нельзя. Копии сразу применяются к каждой записи без собственного выбора и к папкам проектов стеков Compose. Место применяется к новой записи при её первой копии; его изменение ничего не переносит. Перед сохранением BombVault называет каждое место назначения, которое получает или теряет записи, и сколько резервных копий это означает.

Записи, которые копируются не туда, куда их раздел, стоят в карточке **Свой выбор**, каждая с **Следовать умолчанию**. Новые копии тогда идут в места назначения раздела, а прежние остаются где были.

Новое внешнее место назначения получает каждую запись, для которой не выбрана только Локально. Окно, добавляющее его, говорит, сколько это записей и, где известно, сколько истории.

### Прямые репозитории

Выключение Локально для записи, чтобы домом стало место назначения без прямого репозитория, открывает окно с предлагаемым расположением рядом, например `s3:https://s3.eu-central-003.backblazeb2.com/bucket/containers-direct`, и проверкой подключения, которая ничего не создаёт. **Создать и использовать** создаёт репозиторий и направляет запись на него. Прямой репозиторий берёт ключ места назначения, класс хранения, лимиты, настройку append-only и хранение и меняется вместе с ними; карточка «Репозитории» показывает его только для чтения. Когда новый ключ места назначения не может его открыть, прямой репозиторий сохраняет свой ключ, а сохранение об этом сообщает. Запись в прямом репозитории копируется оттуда в другие подсвеченные места, но никогда в то место назначения, которому принадлежит репозиторий. Её снимки несут метку `bv:direct`, и любой другой проход хранения их сохраняет, так что прямой репозиторий, потерявший связь со своим местом назначения, никогда не стареет по локальным правилам. B2 достигается через конечную точку S3, с идентификатором ключа и ключом приложения как учётными данными S3; ключ, ограниченный собственной папкой места назначения, не доберётся до соседней папки, поэтому ограничьте ключ папкой уровнем выше.

### Вне помещения

Место назначения или именованный репозиторий можно отметить **Вне помещения**. Удалённые отмечены с самого начала; снимите отметку для rest-server в том же здании. Отметка только учитывает места и 3-2-1 на карточках. Она не меняет ни одной копии.

Реплика ZFS это копия вне помещения, но не резервная копия с историей. Она хранит только заданные вами снимки, а старые версии и отдельные файлы по-прежнему берутся из копий. Она идёт с одного сервера ZFS прямо на другой, по SSH на сервер ZFS или на приёмную точку сопряжённого экземпляра. Группа сопряжения несёт только запрос. См. [Реплика](zfs-datasets.md#replica).

### После пересборки {#after-a-rebuild}

Выбор копирования хранится в собственных настройках BombVault. После пересборки через **Найти резервные копии** или Аварийный мастер без восстановленных настроек он исчезает, а копирование всего отправило бы в B2 снова записи, которые вы исключили. Поэтому внешние копии каждого пересобранного раздела приостанавливаются. Обзор об этом говорит, а карточка **Места назначения по разделам** предлагает **Подтвердить значение по умолчанию** с предпросмотром того, что скопирует следующий запуск, и именами в копиях без записи, которые там можно исключить. Паузу завершает только подтверждение; импорт файла настроек возвращает правила и умолчания, но паузу не завершает.

## Удалённые основные репозитории {#remote-primary-repositories}

Собственный путь раздела не ограничен локальной папкой: направьте его прямо на удалённое хранилище restic (`s3:...`, `rest:http://host:8000/repo`, `sftp:user@host:/repo`, `rclone:remote:bucket/path`), и BombVault копирует туда напрямую, без отдельной локальной копии и без шага копирования. Это другая схема, чем внешние копии выше: там локальный репозиторий основной, а внешний это архив по принципу максимальных усилий; здесь удалённый репозиторий **и есть** основной и единственная копия, если вы не копируете этот раздел ещё и в другое место назначения.

Путь каждого раздела (Контейнеры, Виртуальные машины, Flash, Автобэкап, Папки, Наборы данных ZFS) задаётся на странице места назначения **Локально**: **Изменить** рядом с разделом в карточке **Подключение** открывает окно с переключателем **Локально / Удалённо**:

- **Локально** показывает привычный обзор папок.
- **Удалённо** заменяет его простым полем URL и настройками подключения, которые использует внешнее место назначения, настроенными здесь для основного репозитория. Отсюда вы получаете:
    - **Проверка подключения** по живому пути, прежде чем вы на него положитесь.
    - **Ограничения пропускной способности** (выгрузка/загрузка), чтобы плановая копия в удалённый основной репозиторий не забивала ваш WAN: те же флаги restic `--limit-upload`/`--limit-download`, что используют внешние копии, применённые к самой копии.
    - **Защиту append-only**, проверяемую тем же активным тестом на подделку (настоящая проба DELETE на дальней стороне), что и у внешних мест назначения. Когда она включена, BombVault отказывается сам очищать репозиторий, поскольку за ним нет отдельной локальной копии, а учётные данные на этой машине не должны уметь удалять единственную копию.
    - **Сигнал бюджета роста**, снимаемый по тому же тренду размера репозитория, который уже отслеживает карточка «Хранилище».

Ничего из этого не обязательно: введённый вручную удалённый путь без сохранённых настроек безопасности копирует без ограничений, с возможностью очистки и без сигнала бюджета. Настройки безопасности нужны для случая, когда хочется защит, которые получает внешняя копия, без отдельного места назначения только ради них.

!!! note "Облачные учётные данные и REST общие"
    Удалённый основной репозиторий проходит проверку общими облачными учётными данными из **Настройки, Места назначения**; отдельного хранилища учётных данных для основных репозиториев нет.

### SMB и WebDAV без монтирования на хосте {#smb-webdav}

В карточке **Внешнее (rclone)** в **Настройки, Места назначения** есть форма для общего ресурса Windows или Samba и для сервера WebDAV (Nextcloud, ownCloud, SharePoint или любого другого). Заполните короткое имя, хост и общий ресурс (SMB) либо URL и тип сервера (WebDAV), пользователя и пароль, и BombVault запишет раздел rclone за вас. rclone сам скрывает пароль перед сохранением; добавление с уже существующим именем заменяет этот раздел, а не добавляет второй. **Добавить место назначения** предлагает SMB и WebDAV как провайдеров с теми же полями.

Форма отвечает готовым расположением, например `rclone:nas:backups`. Используйте его как путь раздела или места назначения и добавьте подпапку, если хотите (`rclone:nas:backups/bombvault`). Общий ресурс это первый сегмент пути, а не часть имени.

Это лучший путь, чем монтировать общий ресурс на Unraid: restic не советует держать репозиторий на смонтированном ресурсе CIFS, а здесь ничего не монтируется. NFS в форме нет, потому что ни у restic, ни у rclone нет бэкенда NFS; для NFS смонтируйте экспорт на хосте и используйте его как локальную папку.

## Защита от удаления (append-only)

Включите защиту от удаления для внешнего места назначения, чтобы шифровальщик или скомпрометированный хост не могли удалить или переписать ваши копии. Её **обеспечивает** дальняя сторона (`restic/rest-server` в режиме `--append-only`). BombVault её только **проверяет** и никогда не показывает зелёным по одному утверждению в конфигурации. Папка на этом сервере не может отказать в удалении, потому что кто управляет BombVault, управляет и папкой, поэтому локальные места назначения этот переключатель не предлагают.

Самый быстрый путь к копии append-only это сопряжённый BombVault с [принимающим сервером](#receiving-server): он сам запускает rest-server в режиме append-only.

!!! note "Успешное удаление под `/locks/` ожидаемо"
    Append-only не означает, что нельзя убрать вообще ничего. restic должен брать и освобождать собственные блокировки, поэтому `/locks/` по замыслу остаётся доступным для записи и удаления. Снимки и данные за ними, то есть то, за чем охотится шифровальщик, удалить нельзя. Если вы сами проверяете дальнюю сторону, успешное удаление под `/locks/` это правильное поведение, а не дыра в защите.

!!! warning "Репозитории append-only никогда не очищаются с этой машины"
    Место назначения append-only никогда не очищает старые резервные копии отсюда; очистка это дело дальней стороны. Задайте для него **сигнал бюджета роста**, чтобы получить предупреждение до того, как размер репозитория разрастётся.

## Тест на подделку

BombVault периодически доказывает гарантию append-only, действительно пытаясь удалить во внешнем репозитории, нацелившись на несуществующий объект. **Проверить защиту от удаления сейчас** на странице места назначения запускает это по требованию, а **Проверять защиту от удаления** в **Настройки, Проверка, Автоматические проверки** запускает по расписанию.

- **Отказано** означает защищено.
- **Принято** означает не защищено.
- **Неубедительный** результат (сервер недоступен, ошибка авторизации) никогда не переворачивает сохранённый вердикт.

Настоящий переход от защищённого к незащищённому вызывает одно предупреждение.

## Учебные DR

BombVault предлагает два уровня доказательства того, что ваши копии действительно восстановимы, а не просто существуют.

- **Учебные проверки восстановления (локально).** BombVault периодически выполняет `restic check --read-data-subset` (ограниченно, никогда не полное восстановление, забивающее диск). Периодичность находится в **Настройки, Проверка, Автоматические проверки**, а карточка **Проверить резервные копии** на той же плитке показывает результат.
- **Пробное восстановление (внешнее).** BombVault восстанавливает реальную цель из внешнего репозитория в изолированную песочницу, проверяет её файл за файлом и байт за байтом, затем убирает за собой. Это доказывает, что вы можете восстановиться с внешней копии, а не только что репозиторий отвечает.

Карточка **Состояние защиты** на обзоре сводит это по разделам в четыре проверки: актуальная копия на этом сервере, внешняя копия, защита от удаления там и пробное восстановление оттуда. Щелчок по разделу показывает подробности, а карточка зеленеет только по проверенным фактам.

## Сопряжение экземпляров {#pairing}

Несколько BombVault работают вместе как одна группа: они показывают друг другу состояние защиты, берут на себя роли друг для друга и могут хранить ключ друг друга. Экземпляр вступает в группу по двенадцати словам.

На первом экземпляре откройте **Настройки, Сопряжение** и нажмите **Сгенерировать фразу**. Три карточки шагов показывают, как это идёт. Двенадцать слов появляются в окне с кнопкой **Копировать**. На каждом другом экземпляре откройте то же место, нажмите **Ввести фразу** и вставьте или введите их, либо нажмите **Вставить** в этом окне. Слово, которого нет в списке, называется с его позицией по ходу набора, а последнее слово несёт контрольную сумму, так что неверно набранное или переставленное слово обнаруживается до сопряжения. Генерируйте фразу только на одном экземпляре: два экземпляра, каждый из которых сгенерировал свою, образуют две отдельные группы. Если за минуту никто не появился, страница предлагает два выхода: показать слова снова, чтобы ввести их там, или ввести слова другого экземпляра и вступить в его группу за один шаг. Сопряжение работает без пароля для входа, но задайте его: без него любой, кто открывает веб-интерфейс, может прочитать слова и через группу запросить роли, выдающие пароль restic экземпляров в ней. Карточка сопряжения говорит об этом, пока пароль не задан. С паролем повторный показ фразы его запрашивает. **Покинуть группу** снова выводит экземпляр. Карточка **Экземпляры** на странице сопряжения перечисляет участников группы; картинка о том, кто что для кого делает, находится на странице «Экземпляры».

Любой, кто знает слова, может вступить в группу, поэтому относитесь к ним как к паролю.

**Как участники находят друг друга.** Каждый экземпляр узнаёт свой адрес в сети от вашего браузера в момент входа; он указан в **Известные адреса** в карточке **Этот экземпляр** на странице сопряжения вместе с найденными самим экземпляром; исправьте его там, если перед ним обратный прокси или необычный порт. В одной сети участники объявляют этот адрес мультикастом и говорят напрямую, а там, где мультикаст не проходит через сеть контейнеров, например мост Docker по умолчанию, экземпляр вместо этого ищет остальных в своей подсети подписанным вызовом, на который может ответить только участник группы, так что сопряжение всё равно завершается за секунды без Relay. Если ничего не нашлось, **Не можете его найти?** принимает один адрес вручную, для другой подсети или нестандартного порта. Экземпляры в разных сетях идут через Relay, выбираемый одним рядом из четырёх в карточке **Relay** на той же странице; каждая форма снабжена картинкой:

- **Relay проекта** (по умолчанию): `parleyport.halleluja.design`, тот же Relay использует и KnightLoader. Настраивать ничего не нужно.
- **Собственный Relay**: контейнер [**ParleyPort**](https://github.com/junkerderprovinz/parleyport) из Unraid Community Apps (также в **Настройки, Приложения**). Введите его адрес на каждом экземпляре, который должен им пользоваться.
- **Экземпляр BombVault**: один из ваших экземпляров, уже доступный извне, с включённым **Работать как Relay**. Этот экземпляр тогда отвечает по `/relay/connect` на собственном адресе, за уже имеющимся обратным прокси и сертификатом, и пускает только вашу группу. Введите его адрес на каждом экземпляре, который должен им пользоваться.
- **Без Relay**: участники находят друг друга автоматически в одной сети и больше нигде.

**Что видит Relay.** Кнопка с тем же названием рядом с четырьмя формами показывает это для выбранной формы. Каждый вызов между участниками запечатывается AES-256-GCM под ключом, выведенным из двенадцати слов, и этот ключ никогда не покидает ваши экземпляры. Relay узнаёт хэш, группирующий соединения, для какого экземпляра сообщение, его размер и когда оно проходит. Прямой вызов в локальной сети запечатывается так же и дополнительно подписывается, так что ничего не зависит от самоподписанного сертификата, который отдаёт экземпляр. Вызовы, что-то выдающие (ответы на роли, пароль restic, входы получателя, депозиты ключей), подписываются также ключом отправляющего участника, закреплённым при первой встрече; см. [Модель безопасности](configuration.md#security-model).

**Что идёт через группу.** Состояние защиты на странице «Экземпляры», запрос проверить один раздел сейчас, запросы ролей и ответы на них, предложения мест назначения и то, что нужно приёмнику или загрузчику после разрешения его роли: расположения репозиториев другого экземпляра и его пароль restic. Данные копий никогда не идут; они по-прежнему идут прямо к бэкендам restic. Не идёт и APP_KEY: пароль restic открывает репозитории этого экземпляра и больше ничего, ни его хранимые секреты, ни сеансы, ни коды восстановления.

**Записи, существовавшие до сопряжения.** Экземпляры, добавленные токеном парка, а также принятые репозитории и источники подтягивания, настроенные по APP_KEY другого экземпляра, остаются после обновления и отмечены **Сопрячь заново**. Они продолжают работать: при первом запуске BombVault заменяет каждый сохранённый APP_KEY выведенным из него паролем restic. Сопрягите оба экземпляра, затем отредактируйте запись и выберите её экземпляр. До тех пор такие записи стоят в карточке **Без экземпляра** на странице «Экземпляры».

Единственное место, которое всё ещё принимает APP_KEY вручную, это [Из старой папки с копиями](#restore-from-another-bombvault-repo), на случай, когда другого экземпляра больше нет и он не может ответить в группе.

## Экземпляры и роли {#roles}

Страница **Экземпляры** (плитка настроек, которую можно закрепить в боковой панели) показывает группу сетью того, кто что для кого делает, карточкой этого экземпляра и карточкой каждого другого участника, телефонов Android и серверов ZFS. **Сопряжение** внизу справа ведёт на страницу сопряжения. Какие части включены, задаётся в **Настройки, Экземпляры, Несколько серверов**: **Экземпляры**, **Приёмник** и **Подтягивание**.

Каждая карточка показывает состояние защиты участника и его роли плитками. Роль это то, что один экземпляр делает для другого:

- **Приёмник** хранит внешние копии этого сервера в rest-server в режиме append-only. Этот сервер отправляет после каждой копии и не может там ничего удалить, даже если им завладеют.
- **Подтягивающий** подтягивает копии этого сервера по собственному расписанию. Этому серверу для этого не нужно быть включённым.
- **Сервер ZFS** принимает реплики ZFS этого сервера. Каждая запись ZFS выбирает его в **Реплика** в своих настройках.
- **Хранитель ключа** хранит запечатанную копию набора для восстановления этого сервера. См. [Хранитель ключа](#key-keeper).

Включение роли отправляет запрос, и ничего не начинается, пока кто-то на другом экземпляре не нажмёт **Разрешить**. Запрос виден на карточке того экземпляра как значок, а его **Подробности** перечисляют его с **Разрешить** и **Отклонить**; разрешённую роль там можно в любой момент отозвать. Пунктирная линия в сети это роль, которая ещё ждёт. Экземпляр на BombVault 9.x не может ответить на запрос, поэтому роль там активна, как только вы её включили, а запрос от экземпляра 9.x ждёт здесь **Разрешить**.

**Подробности** на карточке открывают остальное: принятые репозитории и источники подтягивания этого участника, предложения мест назначения, мониторинг, **Удалить** и **Забыть ключ**.

## Приёмник и подтягивающий {#receiver}

![Принятая внешняя копия в сведениях об экземпляре, наблюдаемая только для чтения, с проверкой целостности на этом оборудовании.](assets/screenshots/receiver.png)

*Принятая внешняя копия в сведениях об экземпляре, наблюдаемая только для чтения, с проверкой целостности на этом оборудовании.*

На машине, которая **принимает** копии append-only от другого BombVault, принятые репозитории дают независимое наблюдение только для чтения на принимающем оборудовании, так что тихий сбой на дальнем конце не остаётся незамеченным. Включите **Приёмник** в **Настройки, Экземпляры**, затем откройте **Подробности** отправляющего экземпляра на странице «Экземпляры» и добавьте принятый репозиторий (только для чтения, открывается паролем restic отправляющего экземпляра, который он получает через [группу сопряжения](#pairing)). Вы получаете:

- **Опись по источникам**, чтобы точно видеть, какие контейнеры, виртуальные машины и наборы папок поступили.
- **Последний приём** по источникам, чтобы знать, насколько свеж каждый.
- **Независимый `restic check`**, выполняемый на принимающем оборудовании, чтобы целостность проверялась там, где данные действительно лежат, а не только у отправителя.
- **Выключатель мёртвой руки:** предупреждение, когда источник перестаёт присылать в заданное вами окно.
- **Предупреждения о целостности:** предупреждение, когда проверка на принимающей стороне не проходит.

Приёмник строго только для чтения. Он никогда не пишет в принятый репозиторий, поэтому никогда не сможет нарушить гарантию append-only, на которую полагается отправитель.

Подтягивающий работает наоборот: с включённым **Подтягивание** экземпляр читает копии другого участника в свой репозиторий по собственному расписанию. Его источники также стоят в сведениях об этом участнике.

### Принимающий сервер {#receiving-server}

Принимающая машина может также запускать rest-server, куда копируют другие. Он настраивается при первом разрешении запроса **Приёмник**, который его просит: окно говорит, что серверу нужен принимающий сервер, и просит папку на общем ресурсе, с **Новая папка** для создания, и порт (8000, если его не занимает другой контейнер). Затем BombVault:

1. отказывается, если контейнер с именем `rest-server` уже существует или другой контейнер занимает порт;
2. подтягивает `restic/rest-server` и запускает его через сокет Docker в режиме append-only с закрытыми репозиториями и файлом логинов в папке;
3. записывает его шаблон Unraid на флешку, чтобы контейнер оставался редактируемым на вкладке Docker, либо предлагает шаблон для скачивания, когда флешка недоступна;
4. выполняет против него тест на подделку и показывает, отказывает ли он в удалении.

Экземпляры вашей группы затем находят сервер среди провайдеров в **Из вашей группы** под именем принимающей машины, а роль **Приёмник** предлагает его как безопасный выбор. Каждый экземпляр получает собственный логин при первом использовании сервера и пишет только в свою папку там. С включённым **Приёмник** в **Настройки, Экземпляры** кнопка **Принимающий сервер** на карточке этого экземпляра снова открывает сервер. Его окно перечисляет логины в **Партнёры с логином**, а **Отозвать логин** убирает один; то, что экземпляр уже скопировал, остаётся в папке. Настройка также создаёт один **Логин вне группы**, пароль которого окно показывает один раз.

Экземпляр, достигающий принимающей машины только через Relay, не может пользоваться сервером, потому что Relay не переносит копии. Сначала добавьте адрес принимающей машины на странице сопряжения. Когда BombVault работает на собственном IP-адресе (например, на br0), заполните **Адрес для партнёров**, потому что сервер слушает адрес хоста.

## Полный пример: две машины Unraid от начала до конца

Всё выше описывает части. Это одна полная настройка, потому что части проще собирать, увидев их собранными один раз.

Две машины: **TOWER** запускает контейнеры и отправляет копии; **VAULT** их принимает и обеспечивает append-only. Подставьте свои имена, адреса и пути к общим ресурсам.

**1. Сопрягите две машины.** На TOWER откройте **Настройки, Сопряжение**, нажмите **Сгенерировать фразу** и введите двенадцать слов на VAULT в **Ввести фразу**. Сначала задайте пароль для входа на обеих.

**2. На TOWER попросите VAULT быть приёмником.** На странице «Экземпляры» включите **Приёмник** на карточке VAULT, выберите разделы и **принимающий сервер VAULT** как место и отправьте запрос.

**3. На VAULT разрешите.** Страница «Экземпляры» на VAULT показывает запрос на карточке TOWER. Нажмите **Разрешить**. В первый раз VAULT просит папку для своего принимающего сервера, например `user/appdata/rest-server`, запускает rest-server в режиме append-only и выполняет против него тест на подделку.

**4. Снова на TOWER.** С этого момента TOWER копирует на VAULT после каждой резервной копии, а новое место назначения появляется на странице мест назначения TOWER с его защитой от удаления.

Что отвечает тест на подделку:

| Результат | Что произошло |
| --- | --- |
| **защищено** | VAULT отказал в удалении. Это единственное успешное состояние. |
| **не защищено** | VAULT принял удаление. `--append-only` отсутствует или был убран. |
| **неубедительно** | Ни то ни другое. Обычно URL не тот, который использует сам restic, или изменились учётные данные. Ничего не записывается, и предупреждение не срабатывает. |

**5. По желанию наблюдайте за тем, что приходит.** Включите **Приёмник** в **Настройки, Экземпляры** на VAULT, откройте **Подробности** TOWER и добавьте принятый репозиторий. VAULT получает пароль restic TOWER через группу; никто не вводит ключ.

**6. Сделайте это взаимным.** Повторите шаги в обратную сторону: VAULT просит TOWER быть его приёмником. Каждая машина тогда обеспечивает append-only для другой, и ни одна не может удалить копии другой.

Rest-server, запущенный вручную, тоже подходит: добавьте его через **Добавить место назначения** как rest-server с пользователем и паролем из его `.htpasswd` и включите защиту от удаления. Оставьте `--append-only` в его параметрах; без него дальняя сторона снова обычный общий ресурс.

!!! warning "Локальный путь это путь внутри контейнера"
    Там, где BombVault просит папку на этом сервере, вводите её относительно монтирования хоста, например `user/appdata/rest-server/bombvault-containers`, а не `/mnt/user/appdata/...`. BombVault работает в контейнере, где `/mnt` хоста смонтирован в другом месте; абсолютного пути хоста внутри нет. Если вставить такой, BombVault подскажет относительный путь, который нужно использовать.

## Аварийный мастер {#emergency}

**Аварийный мастер** возвращает утерянный или заново установленный сервер. Он запускается на странице **Восстановление** в **Аварийное** и по **Восстановить из резервной копии** на странице приветствия новой установки. Он идёт в четыре шага: **Доступ**, **Настройки**, **Выбор** и **Восстановление**.

1. **Доступ.** Покажите BombVault ключ старых копий одним из трёх способов:
    - **Загрузить набор для восстановления**: файл, скачанный при настройке. В нём ключ и каждое место назначения, а остальное BombVault заполняет из него. Набор, запечатанный через age, запрашивает идентичность, для которой он запечатан; она используется один раз и не сохраняется.
    - **Через группу**: экземпляр вашей группы хранит ключ как депозит. Вам нужны двенадцать слов группы, ваш код выдачи и кто-то у этого экземпляра. См. [Хранитель ключа](#key-keeper).
    - **Ввести ключ**: `APP_KEY` старого сервера и где лежат его копии.

    Затем BombVault пробует ключ на каждом месте назначения и говорит для каждого, читается ли оно, не найдено, заблокировано другим ключом, недоступно или ещё без входа. Пока ничего не сохранено, а ключ остаётся в памяти ограниченное время. **Перенять ключ** заставляет этот сервер с этого момента писать копии этим ключом; **Отменить перенятие** возвращает собственный ключ, пока не выполнена первая копия. Сервер, у которого уже есть собственные копии, отказывается от перенятия и отсылает к [Из старой папки с копиями](#restore-from-another-bombvault-repo). **Сохранить учётные данные** сохраняет входы, которые несёт набор для удалённых мест назначения, и спрашивает, прежде чем заменить входы, уже имеющиеся на этом сервере.
2. **Настройки.** **Вернуть настройки** восстанавливает собственные настройки BombVault из самого нового автобэкапа: места назначения, учётные данные, расписания и правила. BombVault перезапускается, чтобы их применить, через сокет Docker, поэтому действующая база данных настроек никогда не перезаписывается под открытым дескриптором, а мастер потом продолжает сам. Вход этого сервера остаётся: вы продолжаете входить с паролем, который используете сейчас. Секреты, которые хранил старый сервер и которые нельзя перенять, перечислены, чтобы вы могли ввести их снова.
3. **Выбор.** BombVault просматривает ваши копии и перечисляет найденные контейнеры, виртуальные машины, наборы папок и наборы данных ZFS. Самая новая резервная копия выбрана везде заранее. То, что на этом сервере ещё есть, начинается выключенным, потому что восстановление его заменило бы. Наборы папок после пересборки больше не знают, откуда пришли, поэтому идут в выбранную вами папку.
4. **Восстановление.** Всё выбранное возвращается разом, остановленным, если вы хотите запустить каждый контейнер и VM сами, что безопаснее всего после полной потери. Потом скачайте новый набор для восстановления: старый принадлежит прежней установке.

!!! tip "Плановая миграция и катастрофа"
    Аварийный мастер восстанавливает собственные настройки BombVault из копии. Для *плановой* миграции на новую машину можно вместо этого перенести конфигурацию напрямую карточкой **Экспорт / импорт настроек** (переносимый файл JSON). См. [Конфигурация](configuration.md#portable-settings-export-and-import).

### Из старой папки с копиями {#restore-from-another-bombvault-repo}

**Из старой папки с копиями** в **Другие источники** на странице «Восстановление» открывает репозиторий *другого* экземпляра BombVault (общий ресурс, смонтированный под `/mnt`, или удалённый адрес) с набором для восстановления того экземпляра или его введённым `APP_KEY` в одноразовой сессии только для чтения. Просматривайте хранящиеся там контейнеры, виртуальные машины, наборы папок и наборы данных ZFS, выберите резервную копию и восстановите её, и восстановленный объект станет обычным локальным контейнером, VM или набором папок. В другой репозиторий никогда ничего не пишется, а ваши собственные настройки копирования остаются нетронутыми (сессия живёт в памяти и истекает сама). Перенос контейнера с сервера A на сервер B не означает перенаправлять ваши настройки и затем их возвращать. Это окно одноразовое: оно открывает сессию, восстанавливает выбранное и забывает другой экземпляр. Если вам нужна постоянная схема, где эта машина по расписанию подтягивает резервные копии другого экземпляра в свой репозиторий, это роль **Подтягивающий** на странице «Экземпляры».

Контейнер, сети которого нет на этом сервере, например сеть Unraid `br0` на обычном хосте Docker, показывает под своей строкой выбор сети. BombVault создаёт его в выбранной вами сети вместе с другими его сетями. Фиксированные IP и MAC-адрес принадлежали прежней сети и отбрасываются, так что новая сеть назначает их сама.

## Хранитель ключа {#key-keeper}

Хранитель ключа это экземпляр вашей группы, который держит запечатанную копию набора для восстановления этого сервера. Открыть копию сам он не может. Если этот сервер когда-нибудь будет потерян, новая установка, вступившая в вашу группу, запросит копию у хранителя и откроет её вашим кодом выдачи.

1. На странице «Экземпляры» включите **Хранитель ключа** на карточке экземпляра, который должен её хранить, и выберите **Сделать депозит**. Для депозита нужен пароль для входа.
2. Этот сервер один раз показывает **Код выдачи**: двадцать букв и цифр в четырёх группах по пять. Запишите его и подтвердите **Код у меня записан**. Этот сервер код не хранит, только то, что нужно, чтобы запечатать для него депозит.
3. Теперь хранитель держит депозит, а этот сервер обновляет его при изменении набора. **Депозит ключа** на карточке этого экземпляра перечисляет **Депозит этого сервера** с каждым хранителем и его состоянием, а **Депозиты, которые хранит этот сервер** для остальных. **Создать новый код** заменяет код; каждый хранитель переходит на новый, получив новый депозит.

В тот день вам понадобятся три вещи: двенадцать слов вашей группы, код выдачи и доступ к интерфейсу хранителя, где кто-то должен нажать **Разрешить**. В Аварийном мастере выберите **Через группу**, выберите депозит, запросите его и введите код выдачи. Код используется на новом сервере и хранителю не отправляется. У хранителя запрос виден в **Депозит ключа** с тем, кто просит, видели ли этот экземпляр там раньше и сколько раз он просил; **Разрешить** выдаёт запечатанную копию, а разрешение требует пароль для входа. У новой установки есть 30 минут на то, чтобы забрать копию после «Разрешить», запрос, на который никто не ответил, истекает через сутки, а экземпляр, просящий слишком часто, должен ждать час.

Без кода никто не может открыть копию, включая хранителя. Если код потерян, создайте новый, пока этот сервер ещё работает; если сервера уже нет, набор для восстановления и введённый APP_KEY по-прежнему работают. Хранитель может в любой момент удалить депозит, и владельцу тогда придётся просить снова.

## Набор для восстановления {#recovery-kit}

Это та часть, которая делает аварийное восстановление возможным, даже когда нет работающего BombVault.

**Скачать набор для восстановления** в карточке **На случай аварии** в **Настройки, Восстановление** даёт **ключ**, **производный пароль restic**, каждое **место назначения** с репозиторием каждого раздела, входы, нужные новой установке, чтобы до них добраться, и **точные команды restic**, чтобы восстановиться прямо через CLI restic на любой машине. Требуется пароль для входа. Набор печатает ключ и при выключенном шифровании, потому что определения контейнеров и VM всегда им запечатаны. После перенятия он печатает перенятый ключ копий и APP_KEY этого сервера, нужный новой установке только для возврата настроек. Карточка **Сохраните набор для восстановления** на обзоре напоминает, пока вы его не сохранили.

!!! danger "Храните набор для восстановления вне сервера"
    Набор содержит секрет, расшифровывающий ваши копии. Храните его в надёжном месте отдельно от сервера (менеджер паролей, распечатка в сейфе). Если вы потеряете и BombVault, и `APP_KEY` без набора для восстановления и депозита ключа, зашифрованные резервные копии восстановить будет нельзя.

!!! warning "Самый новый снимок не всегда тот, который нужно восстанавливать"
    Начиная с restic 0.17, `restic snapshots` показывает размер каждого снимка. После потери данных самым новым снимком может оказаться опустошённый, поэтому не восстанавливайте снимок, который намного меньше предыдущих. После шифровальщика им может оказаться зашифрованный снимок обычного размера. Если BombVault ещё работает, сначала загляните на страницу **Аномалии**: она называет последнюю хорошую копию, и окно восстановления предвыбирает её. Для восстановления не нужны никакие данные аномалий BombVault, а пауза хранения лишь сохраняет больше снимков.

### Запечатывание набора

Если вы включили **Шифровать экспорты с помощью age** в **Настройки, Система**, набор тоже запечатывается им и скачивается как `bombvault-recovery-kit.md.age`. Он в ASCII-броне, а не двоичный, поэтому остаётся обычным текстом: вставка в менеджер паролей или распечатка работают как прежде, просто содержимое нечитаемо без вашего ключа.

!!! warning "Не храните ключ age внутри набора"
    Чтобы открыть запечатанный набор, нужен ваш **закрытый** ключ age. Храните его там, где он не зависит от самого набора, иначе у вас будет два предмета для восстановления вместо одного. Запечатывание оправдано, когда набор хранится там, что вы не полностью контролируете (общий менеджер паролей, облачные заметки, распечатка в офисе); набор в собственном сейфе уже защищён сейфом.

    При включённом шифровании и без пригодного получателя загрузка отклоняется наотрез. BombVault никогда не возвращается к выдаче главного ключа открытым текстом.

### Если набора нет под рукой

Пароль нигде не хранится, он **вычисляется** из ключа копий, так что вы можете воспроизвести его сами, имея только ключ и оболочку:

```sh
printf 'bombvault:restic-repo'   | openssl dgst -sha256 -mac HMAC -macopt hexkey:$APP_KEY -r   | cut -d' ' -f1
```

Это HMAC-SHA256 от фиксированной строки `bombvault:restic-repo` с ключом из сырых байтов hex-`APP_KEY`, напечатанный как 64 шестнадцатеричных символа в нижнем регистре. То же значение есть в наборе, указано как производный пароль restic; это на тот день, когда набор не при вас. На сервере, который перенял чужие копии, используйте перенятый ключ копий, то есть прежний APP_KEY того сервера.

!!! warning "Для принятого репозитория используйте ключ ОТПРАВЛЯЮЩЕГО экземпляра"
    Репозиторий, пришедший сюда через внешнюю копию, был создан отправившей его машиной с **её** ключом. Вывод из ключа принимающей машины даёт пароль, который restic отвергнет, что выглядит точно как повреждённый репозиторий, но им не является. Это обычная причина, по которой `restic check` на принятом репозитории снова и снова запрашивает пароль.

Поскольку определения для восстановления лежат **внутри** каждого репозитория (`<repo>/def`, `<repo>/vm-def`), скопированная папка репозитория полностью самодостаточна, так что набор плюс репозиторий это всё, что нужно для восстановления на голом железе.

## Возврат дампа базы данных {#database-dumps}

Дамп базы данных это отдельная точка восстановления в репозитории контейнеров с меткой `dbdump:<container>`, содержащая единственный файл `/dbdump/<container>.sql`. BombVault перечисляет, скачивает и импортирует их на вкладке **Резервные копии** контейнера; ниже те же шаги только с restic, на тот день, когда BombVault нет.

```sh
restic -r <repo> snapshots --tag dbdump:<container>
restic -r <repo> dump --tag dbdump:<container> latest /dbdump/<container>.sql > <container>.sql
```

Метки `dbversion:` и `dbname:` на каждом дампе говорят, с какой версии сервера он получен и какие базы данных в нём. Полный файл заканчивается строкой `-- PostgreSQL database cluster dump complete` или `-- Dump completed`.

Импортируйте его в контейнер той же или более новой версии (PostgreSQL) либо той же основной версии (MySQL и MariaDB), запущенный один раз с пустой папкой данных, чтобы он инициализировался. Клиент базы данных на хосте не нужен, он есть в контейнере:

```sh
docker exec -i <container> sh -c 'exec psql -X -U "${POSTGRES_USER:-postgres}" -d postgres' < <container>.sql
docker exec -i <container> sh -c 'exec mariadb -uroot -p"$MARIADB_ROOT_PASSWORD"' < <container>.sql
docker exec -i <container> sh -c 'exec mysql -uroot -p"$MYSQL_ROOT_PASSWORD"' < <container>.sql
```

Для одной базы данных из полного дампа MySQL и MariaDB принимают `--one-database <имя>` в команде клиента. В дампе PostgreSQL по разделу на базу данных, каждый начинается со строки `\connect <имя>`: скопируйте этот раздел в отдельный файл и импортируйте его с `-d <имя>` после создания базы данных.

!!! warning "Дамп от имени root несёт пользователей сервера"
    Полный дамп MySQL или MariaDB, снятый от имени root, содержит системную базу данных `mysql`, поэтому его импорт заменяет учётные записи нового сервера, включая пароль root, записями из дампа. В PostgreSQL `role ... already exists` для пользователя, созданного контейнером, ожидаемо и безвредно.
