# ชุดข้อมูล ZFS

ชุดข้อมูล ZFS เป็นรายการในรายการ **การสำรองข้อมูล** เหมือน containers และ VMs หนึ่งรายการคือชุดข้อมูลหนึ่งพร้อมทุกชุดข้อมูลที่อยู่ข้างใต้ สำหรับการสำรองแต่ละครั้ง BombVault ถ่ายสแนปช็อต ZFS ครั้งเดียวของทั้งทรี ดังนั้นทุกชุดข้อมูลในนั้นถูกจับในช่วงเวลาเดียวกัน จากนั้นอ่านไฟล์ของแต่ละชุดข้อมูลจากสแนปช็อตนั้นและเก็บด้วย restic แบบเดียวกับโฟลเดอร์ แล้วลบสแนปช็อตทันที ข้อมูลสำรองขจัดข้อมูลซ้ำ เรียกดูได้ทุกชุด และกู้คืนไฟล์เดี่ยวได้

การสำรองข้อมูลไม่เคยส่งสตรีมเข้า restic และไม่เคยย้อนชุดข้อมูลกลับ BombVault ทำลายเฉพาะสแนปช็อตที่มันสร้างเอง [สำเนาจำลอง](#replica) ที่เป็นทางเลือกเป็นที่เดียวที่ใช้ `zfs send` โดยจะคัดลอกชุดข้อมูลไปยังเซิร์ฟเวอร์ ZFS เครื่องที่สอง และไม่แตะต้องข้อมูลสำรอง

## สิ่งที่ต้องมี {#requirements}

- **การเชื่อมต่อ SSH ไปยังเซิร์ฟเวอร์นี้** ชุดข้อมูล ZFS ใช้คีย์ โฮสต์ และผู้ใช้เดียวกับการสำรองข้อมูล VM ถ้าการสำรองข้อมูล VM ใช้งานได้อยู่แล้ว ส่วนนี้ก็ใช้ได้เช่นกัน ไม่เช่นนั้นให้ทำตาม[คู่มือการสำรองข้อมูล VM ผ่าน SSH](https://github.com/junkerderprovinz/bombvault/blob/main/docs/vm-backup-ssh-setup.md)บน GitHub ช่องในเทมเพลตชื่อ **Host SSH: Address**, **Host SSH: Port** และ **Host SSH: User**
- **คำสั่ง `zfs` บนโฮสต์นั้น** Unraid 6.12 ขึ้นไปและ TrueNAS SCALE มีคำสั่งนี้
- **Host Data แมปเป็น `/mnt` โดยใช้ Access Mode แบบ Read/Write - Slave** นี่คือค่าเริ่มต้นของเทมเพลต สแนปช็อตของชุดข้อมูลจะปรากฏในโฟลเดอร์ `.zfs/snapshot` ของชุดข้อมูลหลังจาก BombVault เริ่มทำงานแล้วเท่านั้น คอนเทนเนอร์จึงต้องได้รับการเมานต์ที่โฮสต์ทำภายหลัง
- **ชุดข้อมูลเมานต์อยู่ใต้ `/mnt`** บน Unraid พูลอยู่ที่ `/mnt/<pool>` จึงเป็นเช่นนี้อยู่แล้ว

เปิดส่วนนี้ใต้ **การตั้งค่า, ทั่วไป** (ชุดข้อมูล ZFS) จากนั้น **การเชื่อมต่อ ZFS กับเซิร์ฟเวอร์นี้** ใต้ **เพิ่มเติม** บนหน้าการสำรองข้อมูลเปิด **การเชื่อมต่อกับเซิร์ฟเวอร์นี้** มันทดสอบลิงก์ SSH ระบุผู้ใช้และโฮสต์ที่เชื่อมต่อ และบอกสิ่งที่ขาดเมื่อมีอะไรขาด เมื่อลิงก์ล่ม รายการการสำรองข้อมูลบอกด้วย **ดูการเชื่อมต่อ** และการ์ด **การผสานรวมโฮสต์** บนภาพรวมแสดงผลเดียวกัน

## รายการและชุดข้อมูลลูก {#items-and-children}

เลือก **เพิ่ม** บนหน้าการสำรองข้อมูล แล้วเลือก **ชุดข้อมูล ZFS** รายการมาจากเซิร์ฟเวอร์ เลือกชุดข้อมูลที่อยู่บนสุดของสิ่งที่ต้องการสำรอง เช่น `cache/appdata` แล้วรายการจะครอบคลุมมันและทุกชุดข้อมูลข้างใต้

- **ชุดข้อมูลลูกใหม่เข้าร่วมเอง** ชุดข้อมูลที่สร้างใต้รายการภายหลังจะถูกสำรองในการรันครั้งถัดไป และการรันนั้นระบุว่าเป็นของใหม่ การสำรองครั้งแรกของมันอ่านทั้งหมดหนึ่งครั้ง หลังจากนั้นอ่านเฉพาะการเปลี่ยนแปลง
- **เว้นลูกบางตัวได้** ปิดลูกบนแท็บการตั้งค่าของรายการ แล้วมันถูกเว้นพร้อมทุกอย่างข้างใต้ ลูกที่เว้นไว้แต่ไม่มีบนเซิร์ฟเวอร์แล้วจะถูกทำเครื่องหมายเช่นนั้นและนำออกจากรายการได้
- **ลูกที่อ่านไม่ได้ถูกข้าม ไม่เคยข้ามเงียบ ๆ** การรันแสดงรายการ รายการแสดงว่าข้ามกี่ตัว และการ์ด **ไม่ได้สำรองข้อมูล** บนภาพรวมนับแต่ละตัวว่าไม่ได้รับการปกป้อง การรันสำรองส่วนที่เหลือทั้งหมดและไม่ล้มเหลวเพราะลูกที่ข้าม เหตุผลอยู่ใน[ตารางรหัสเหตุผล](#reason-codes): ชุดข้อมูลที่ไม่ได้เมานต์ มี `canmount=off` จุดเมานต์ `legacy` หรือไม่มี คีย์เข้ารหัสที่ไม่ได้โหลด การเข้าถึงสแนปช็อตที่ปิดอยู่ หรือจุดเมานต์ที่ BombVault มองไม่เห็น
- **ชุดข้อมูลที่ถูกข้ามจะไม่ลากลูกของมันไปด้วย** ชุดข้อมูล `canmount=off` ที่มีแต่ชุดข้อมูลอื่นจะถูกข้าม (แสดงว่า "โครงสร้างเท่านั้น") และลูกที่เมานต์อยู่จะถูกสำรอง ชุดข้อมูลที่เข้ารหัสและยังไม่ได้โหลดคีย์จะถูกข้ามพร้อมกับลูกที่ใช้คีย์เดียวกัน
- **ลูกที่เป็นดิสก์ VM หรือข้อมูลระบบจะเริ่มต้นแบบปิด** ในหน้าต่างเพิ่ม พร้อมเหตุผลข้างสวิตช์ การเพิ่มทั้งพูลจะต้องยืนยันในหน้าต่างที่แสดงสิ่งที่พูลมี

### วอลุ่ม {#volumes}

โวลุ่ม (zvol) เก็บดิสก์เสมือนแทนไฟล์ และรายการ ZFS ไม่สำรองโวลุ่มเลย

- โวลุ่มที่ VM ใช้ถูกสำรองไปกับ VM นั้น
- โวลุ่มที่ไม่มี VM ใช้ (extent ของ iSCSI ดิสก์ที่คุณถอดออก) **BombVault ไม่สำรอง** หน้าต่างเพิ่มและหน้าการสำรองข้อมูลนับโวลุ่มเหล่านี้และบอกเรื่องนี้ เวอร์ชันถัดไปจะสำรองมัน

โวลุ่มภายในทรีของรายการถูกข้ามและระบุชื่อทุกครั้งที่รัน

### ที่เก็บของ Docker {#docker-storage}

กับไดรเวอร์จัดเก็บ ZFS ของ Docker ทุกเลเยอร์ของอิมเมจคือชุดข้อมูลที่มีจุดเมานต์ `legacy` กล่องโต้ตอบเพิ่มรวมสิ่งเหล่านี้เป็นหนึ่งบรรทัดต่อพาเรนต์ ทรีที่มีชุดข้อมูลแบบนี้เกิน 20 ชุดกลายเป็นรายการไม่ได้: ขณะที่สแนปช็อตของมันมีอยู่ Docker ลบเลเยอร์อิมเมจไม่ได้ ให้เพิ่มชุดข้อมูลข้างใต้แทน เช่น `appdata`

### รายการไม่ซ้อนทับกันเด็ดขาด {#overlap}

ชุดข้อมูลหนึ่งอยู่ในรายการเดียวเท่านั้น BombVault ปฏิเสธรายการใหม่ที่อยู่ภายในรายการที่มีอยู่หรือที่จะมีรายการหนึ่งอยู่ภายใน หากต้องการรวมรายการลูกหลายรายการเป็นรายการพาเรนต์เดียว ให้ลบรายการลูกก่อนโดยเลือกเก็บข้อมูลสำรองของมัน แล้วเพิ่มพาเรนต์ ทุกชุดข้อมูลเก็บประวัติไว้ใต้ชื่อของตัวเอง การสำรองครั้งถัดไปจึงต่อจากที่รายการเก่าค้างไว้และไม่อ่านทุกอย่างใหม่

## หยุดคอนเทนเนอร์และคำสั่งรอบสแนปช็อต {#consistency}

สแนปช็อตของฐานข้อมูลที่กำลังรันเหมือนไฟดับกะทันหัน: ฐานข้อมูลมักกู้คืนได้ แต่ต้องทำ แต่ละรายการทำได้สองอย่างเกี่ยวกับเรื่องนี้ และทั้งสองครอบคลุมเฉพาะช่วงเวลาของสแนปช็อต ไม่ใช่ทั้งการสำรอง

- **หยุดคอนเทนเนอร์เหล่านี้เพื่อถ่ายสแนปช็อต** BombVault หยุดคอนเทนเนอร์ในรายการ สร้างสแนปช็อต แล้วเริ่มคอนเทนเนอร์ใหม่ทันที คอนเทนเนอร์ในระดับการพึ่งพาเดียวกันจะหยุดพร้อมกัน โดยตัวที่พึ่งพาหยุดก่อน ช่วงเวลาทั้งหมดจึงมักใช้เพียงไม่กี่วินาที และการรันจะแสดงว่าใช้เวลานานเท่าใด จากนั้นการสำรองจะอ่านสแนปช็อตที่หยุดนิ่งไว้ขณะที่แอปกลับมาทำงานแล้ว จะหยุดเฉพาะคอนเทนเนอร์ที่กำลังทำงานอยู่
- **คำสั่งก่อนและหลังสแนปช็อต** คำสั่งนี้ทำงานภายในคอนเทนเนอร์ที่คุณเลือก เช่น เพื่อดัมพ์ฐานข้อมูลลงในชุดข้อมูลก่อนสแนปช็อตโดยไม่ต้องหยุดอะไร ถ้าคำสั่งก่อนสแนปช็อตล้มเหลว การสำรองจะล้มเหลวและไม่มีการสร้างสแนปช็อต คำสั่งหลังสแนปช็อตที่ล้มเหลวจะแสดงในการรัน แต่ไม่ทำให้การสำรองล้มเหลว

เมื่อเกิดปัญหา:

- ถ้าหยุดคอนเทนเนอร์ใดไม่ได้ BombVault จะเริ่มคอนเทนเนอร์ที่หยุดไปแล้ว และการสำรองจะล้มเหลวพร้อมชื่อคอนเทนเนอร์นั้น มันไม่เคยหันไปใช้สแนปช็อตของแอปที่กำลังทำงานแทน
- การหยุดจะรอให้การสำรองคอนเทนเนอร์ที่กำลังทำอยู่เสร็จก่อน (สูงสุด 30 นาทีสำหรับการรันด้วยตนเอง และถึงขีดจำกัดเวลาของการสำรองสำหรับการรันตามกำหนดเวลา) ทั้งสองจึงไม่เคยหยุดและเริ่มคอนเทนเนอร์เดียวกันพร้อมกัน
- ก่อน container แรกหยุด BombVault จดไว้ว่ามันหยุดตัวไหน หาก BombVault ถูกฆ่าภายในช่วงนั้น มันจะเริ่ม container เหล่านั้นอีกครั้งเมื่อเริ่มครั้งถัดไป ส่งการแจ้งเตือน และรายการแสดงหมายเหตุสีแดงสำหรับ container ที่เริ่มไม่ได้

ดัมป์ฐานข้อมูลอัตโนมัติ (ดู [Features](features.md)) รันกับการสำรองของ container เอง ไม่ใช่กับรายการ ZFS ฐานข้อมูลที่ container ถูกสำรองผ่านชุดข้อมูลเท่านั้นจะไม่ได้ดัมป์ ดังนั้นให้คำสั่งกับมันที่นี่

Container อยู่ในรายการนี้และถูกสำรองเป็น container ในเวลาเดียวกันได้ ข้อมูลของมันจะถูกเก็บสองครั้งในสองรีพอสิทอรี และการสำรองทั้งหมดหยุดมันสองครั้ง รายการบอกเรื่องนี้

## การกู้คืน {#restore}

เปิดรายการแล้วเลือก **การกู้คืน** หรือเลือกบนหน้า **การกู้คืน** หน้าต่างการกู้คืนถามข้อมูลสำรอง แล้วถาม **ชุดข้อมูล** โดยค่าเริ่มต้นคือชุดข้อมูลบนสุดของรายการ ใต้ **อะไร** คุณกู้คืนทั้งหมดหรือเฉพาะไฟล์และโฟลเดอร์ที่เลือก **ไปที่ไหน** เสนอ:

- **กู้คืนกลับเข้าชุดข้อมูล** ไฟล์จากข้อมูลสำรองจะถูกเขียนลงในจุดเมานต์ของชุดข้อมูล ไฟล์ที่ชื่อซ้ำจะถูกเขียนทับ ไฟล์อื่นยังคงอยู่ ชุดข้อมูลจะไม่ถูกย้อนกลับหรือแทนที่ BombVault ตรวจว่าชุดข้อมูลเมานต์อยู่ มองเห็นได้ และเขียนได้ หนึ่งครั้งก่อนเริ่มและอีกครั้งก่อนเขียน ตำแหน่งที่มีชุดข้อมูลลูกเมานต์อยู่ภายในจะไม่ถูกเขียนอะไร ลูกจะคงไฟล์ เจ้าของ และสิทธิ์ของตัวเองไว้ และถูกกู้คืนจากข้อมูลสำรองของตัวเอง
- **ไปยังโฟลเดอร์** เลือกโฟลเดอร์ใต้ `/mnt` BombVault ตรวจว่าโฟลเดอร์อยู่บนพูลหรือแชร์ที่เมานต์ และมีพื้นที่ว่างพอ ใช้ได้โดยไม่ต้องมีลิงก์ SSH และสำหรับชุดข้อมูลที่ไม่มีอยู่แล้ว
- **ไปยังชุดข้อมูลใหม่** ตั้งชื่อชุดข้อมูลที่ยังไม่มี หน้าต่างแนะนำ `<ชุดข้อมูล>-restored` BombVault สร้างมันด้วยคุณสมบัติ ZFS ที่เก็บในข้อมูลสำรองและกู้คืนเข้าไป ดู [การกู้คืนเป็นชุดข้อมูลใหม่](#new-dataset)

การเลือก **ชุดข้อมูลทั้งหมดของการสำรองนี้** เป็นชุดข้อมูลเขียนทุกชุดข้อมูลของทรีลงโฟลเดอร์ย่อยของตัวเองในโฟลเดอร์ที่คุณเลือก ชุดข้อมูลที่ถูกข้ามในการสำรองนั้นถูกระบุชื่อ หากต้องการกู้คืนจากรีพอสิทอรีของ BombVault อีกเครื่อง ใช้ **จากโฟลเดอร์สำรองข้อมูลเก่า** บนหน้าการกู้คืน มันกู้คืนลงโฟลเดอร์เสมอ: ทุกชุดข้อมูลของการสำรองหนึ่งชุด แต่ละชุดลงโฟลเดอร์ย่อยของตัวเอง หรือชุดข้อมูลหนึ่งของทรี ทั้งชุดหรือไฟล์ที่เลือก

รายการ container ที่ต้องหยุดของรายการยังถูกเสนอสำหรับการกู้คืนลงชุดข้อมูลด้วย container เหล่านั้นหยุดอยู่ตลอดการกู้คืน และการสำรอง container รอในระหว่างนั้น

### สแนปช็อตเพื่อความปลอดภัย {#safety-snapshot}

ก่อนเขียนลงชุดข้อมูล BombVault ถ่ายสแนปช็อต ZFS ของชุดข้อมูลนั้นอย่างเดียว ชื่อ `bombvault-prerestore-<เวลา>` **เก็บสแนปช็อต ZFS ของสภาพตอนนี้ไว้ก่อน** เปิดอยู่เป็นค่าเริ่มต้น การปิดต้องยืนยันครั้งที่สอง หากถ่ายสแนปช็อตไม่ได้ จะไม่กู้คืนอะไรเลย

BombVault ไม่เคยลบสแนปช็อตนิรภัยเอง รายการแสดงรายการพร้อมอายุและขนาด แต่ละอันมีการดำเนินการ **ลบ** และเตือนเมื่ออันเก่าที่สุดมีอายุเกิน 30 วัน เพราะมันเก็บข้อมูลที่ลบและเปลี่ยนไว้บนพูล

หากต้องการย้อนกลับหลังการกู้คืน ให้คัดลอกไฟล์ทีละไฟล์จาก `.zfs/snapshot/bombvault-prerestore-<เวลา>` ภายในชุดข้อมูล `zfs rollback <dataset>@bombvault-prerestore-<เวลา>` ใช้ได้เฉพาะเมื่อเป็นสแนปช็อตล่าสุดของชุดข้อมูลนั้น `zfs rollback -r` จะลบสแนปช็อตที่ใหม่กว่าทั้งหมด รวมถึงสแนปช็อตอัตโนมัติ

### กู้คืนเป็นชุดข้อมูลใหม่ {#new-dataset}

BombVault บันทึกคุณสมบัติ ZFS ที่ตั้งไว้เฉพาะของทุกชุดข้อมูลไปกับข้อมูลสำรองทุกครั้ง ได้แก่ compression, recordsize, quota, reservation, atime, xattr, acltype, casesensitivity และคุณสมบัติผู้ใช้ของคุณเอง ค่าที่สืบทอดและค่าแบบอ่านอย่างเดียวจะไม่ถูกบันทึก เพราะกลับมาเอง ข้อมูลสำรองจากก่อนที่ BombVault จะเริ่มบันทึกจะไม่มีคุณสมบัติเหล่านี้

- **ไปยังชุดข้อมูลใหม่** จะรัน `zfs create` พร้อมคุณสมบัติที่บันทึกไว้ทั้งหมด casesensitivity, normalization และ utf8only ตั้งได้ด้วยวิธีนี้เท่านั้น ส่วนโควตาและการจองพื้นที่จะตั้งหลังเขียนไฟล์ เพื่อไม่ให้ปฏิเสธการเขียนไฟล์ จุดเมานต์จะไม่ถูกนำไปใช้เพื่อให้สำเนาไม่ชนกับต้นฉบับ `canmount`, `readonly` และการเข้ารหัสก็เช่นกัน เพื่อให้การกู้คืนเขียนได้ ชุดข้อมูลใหม่ที่อยู่ใต้ชุดข้อมูลที่เข้ารหัสจะได้การเข้ารหัสนั้นไปด้วย ชุดข้อมูลที่อยู่ด้านบนต้องมีอยู่ ถ้ามีอะไรล้มเหลวหลังการสร้าง ชุดข้อมูลใหม่จะยังอยู่บนเซิร์ฟเวอร์ เพราะ BombVault ไม่ทำลายชุดข้อมูลเลย
- **กู้คืนกลับเข้าชุดข้อมูล** จะแสดงคุณสมบัติที่บันทึกไว้ข้างการกู้คืน **ตั้งคุณสมบัติเหล่านี้ด้วย** จะตั้งคุณสมบัติที่ชุดข้อมูลที่มีอยู่ยังรับได้ก่อนเขียนไฟล์ใดๆ ส่วนโควตาและการจองพื้นที่จะตั้งหลังเขียนไฟล์ เพื่อไม่ให้ปฏิเสธการเขียนไฟล์ ถ้าไม่เปิดสวิตช์นี้ ชุดข้อมูลจะคงการตั้งค่าเดิมไว้

## สิ่งที่อยู่ในข้อมูลสำรอง {#contents}

อยู่ในข้อมูลสำรอง: ไฟล์และโฟลเดอร์ของทุกชุดข้อมูลที่สำรอง พร้อมเจ้าของ โหมด เวลา และแอตทริบิวต์เพิ่มเติมตามที่ restic เก็บ รวมถึงคุณสมบัติ ZFS ที่ตั้งไว้เฉพาะของแต่ละชุดข้อมูล

ไม่อยู่ในข้อมูลสำรอง:

- เจ้าของและโหมดของโฟลเดอร์บนสุดของแต่ละชุดข้อมูลเอง (ทุกอย่างที่อยู่ใต้โฟลเดอร์นั้นรวมอยู่ด้วย) การกู้คืนกลับเข้าชุดข้อมูลจะคงโฟลเดอร์บนสุดเดิมไว้ ส่วนการกู้คืนไปยังโฟลเดอร์จะสร้างโฟลเดอร์นั้นด้วยโหมด `0755`
- สแนปช็อต ZFS ที่มีอยู่
- ลูกที่ถูกข้ามหรือถูกเว้นไว้
- วอลุ่ม

หากจะกู้คืนไปยังพูลใหม่ ให้สร้างพูลแล้วกู้คืนแต่ละชุดข้อมูลไปยังชุดข้อมูลใหม่ ยังไม่ได้ตรวจสอบว่า NFSv4 ACL แบบที่ TrueNAS ใช้กับชุดข้อมูล SMB จะกลับมาตามที่คุณคาดหรือไม่ จึงควรทดลองกู้คืนกับข้อมูลของคุณเองก่อนจะพึ่งพา

## ชุดข้อมูลที่เข้ารหัส {#encryption}

ชุดข้อมูลที่เข้ารหัสจะถูกสำรองเฉพาะเมื่อโหลดคีย์ไว้แล้ว ไม่เช่นนั้นจะถูกข้ามพร้อมคำเตือน ให้โหลดคีย์ด้วย `zfs load-key` แล้วเมานต์ชุดข้อมูล BombVault อ่านข้อมูลที่ถอดรหัสแล้วและเก็บลงในรีพอสิทอรีของ restic ซึ่งเข้ารหัสไว้ ถ้าคุณปิดการเข้ารหัสใน BombVault รีพอสิทอรีนั้นก็จะไม่ถูกเข้ารหัส

## สำเนาจำลอง {#replica}

เรพลิกาคือสำเนาของชุดข้อมูลของรายการบนเซิร์ฟเวอร์ ZFS เครื่องที่สอง BombVault ทำให้ทันสมัยด้วย `zfs send` และ `zfs receive` การรันครั้งแรกส่งทุกอย่าง หลังจากนั้นส่งเฉพาะบล็อกที่เปลี่ยน บนเซิร์ฟเวอร์อีกเครื่องคุณเมานต์สำเนาได้ทันที

เรพลิกาไม่เคยแทนที่ข้อมูลสำรอง เวอร์ชันเก่า ไฟล์เดี่ยว และการตรวจสอบยังมาจากข้อมูลสำรอง และเรพลิกาเก็บสแนปช็อตเท่าที่คุณตั้ง เรพลิกาที่ทันสมัยนับเป็นสำเนานอกสถานที่ แต่รายการที่มีเรพลิกาและไม่มีข้อมูลสำรองยังเป็นสีส้ม

เปิดในการ์ด **เรพลิกา** บนแท็บการตั้งค่าของรายการ ที่นั่นคุณเลือกว่าเรพลิกาไปที่ไหน รันเมื่อไร (**หลังสำรองทุกครั้ง** หรือ **แผนของตัวเอง**) และเหลือสแนปช็อตกี่ชุดบนเป้าหมาย การ์ดแสดงทุกชุดข้อมูลและโวลุ่มพร้อมสถานะ และ **ทำเรพลิกาตอนนี้** เริ่มการรัน การรันเรพลิกามีล็อกของตัวเอง การถ่ายโอนครั้งแรกที่ยาวจึงไม่ขวางการสำรอง

### ส่งไปยังเซิร์ฟเวอร์ ZFS {#replica-push}

เครื่องใดก็ตามที่มี ZFS และ SSH รับได้ เช่น Unraid เครื่องที่สองหรือ TrueNAS ไม่จำเป็นต้องรัน BombVault ที่นั่น

1. ใต้ **การตั้งค่า, การจับคู่** เลือก **เชื่อมต่อผ่าน SSH** ใน **เซิร์ฟเวอร์ ZFS ที่ไม่มี BombVault** หรือ **เพิ่มเซิร์ฟเวอร์ ZFS** ในการ์ด **เรพลิกา** ของรายการ
2. ใส่ที่อยู่ ผู้ใช้ และพอร์ต กล่องโต้ตอบจะแสดงคีย์สาธารณะของ BombVault ให้เพิ่มคีย์นี้ใน `~/.ssh/authorized_keys` ของผู้ใช้บนเซิร์ฟเวอร์ บน Unraid อยู่ที่ **Users, root, SSH keys** ขึ้นอยู่กับ **Display Settings** Users จะอยู่ในเมนูส่วนหัวหรืออยู่ใต้ Settings บน TrueNAS ให้แก้ไขผู้ใช้ใน **Credentials, Users** นี่คือคีย์ของเรพลิกา ซึ่งต่างจากคีย์ของการเชื่อมต่อ SSH สำหรับ VM และโฮสต์ ดังนั้นให้เพิ่มคีย์นี้ แม้คีย์นั้นจะได้รับอนุญาตแล้วก็ตาม
3. ทดสอบการเชื่อมต่อ จากนั้นกล่องโต้ตอบจะแสดงรายการพูลของเซิร์ฟเวอร์ เลือกหนึ่งพูลแล้วตั้งรูท ซึ่งค่าเริ่มต้นคือ `<pool>/bombvault-replica`
4. เลือกเซิร์ฟเวอร์ใหม่ในการ์ด **เรพลิกา** ของรายการ จากนั้นเซิร์ฟเวอร์มีการ์ดของตัวเองบนหน้าอินสแตนซ์ และ **เปิด** นำไปยังหน้าของมัน

ถ้าใช้ root ไม่ต้องทำอะไรเพิ่ม ผู้ใช้ของตัวเองต้องมีสิทธิ์เหล่านี้บนพูลของปลายทาง ซึ่งกล่องโต้ตอบก็แสดงให้เช่นกัน:

```
zfs allow <user> receive,create,mount,rollback,destroy,userprop <pool>
```

บนต้นทาง ผู้ใช้ชนิดเดียวกันต้องมีสิ่งเหล่านี้บนชุดข้อมูลบนสุดของรายการ:

```
zfs allow <user> send,snapshot,hold,release,bookmark,destroy <dataset>
```

ในทิศทางนี้ BombVault ที่ถือรายการยังถือคีย์ที่เขียนบนเซิร์ฟเวอร์ได้ด้วย

BombVault บันทึกกุญแจโฮสต์ที่เซิร์ฟเวอร์แสดงในการเชื่อมต่อครั้งแรก และภายหลังจะปฏิเสธกุญแจอื่น หากติดตั้งเซิร์ฟเวอร์ใหม่ ให้กด **ลืมกุญแจโฮสต์** ในหน้าของเซิร์ฟเวอร์ แล้วการเชื่อมต่อครั้งถัดไปจะบันทึกกุญแจใหม่

### ส่งไปยังอินสแตนซ์ที่จับคู่ {#replica-receive}

BombVault ที่จับคู่กันไว้รับสำเนาจำลองได้เอง ไม่มีใครได้สิทธิ์ SSH ไปยังโฮสต์อีกเครื่อง และไม่มีคีย์ใดถูกเพิ่มลงในไฟล์ `authorized_keys`

1. ในการ์ด **เรพลิกา** ของรายการ เลือกอินสแตนซ์ที่จับคู่เป็นเป้าหมาย หรือเปิดบทบาท **เซิร์ฟเวอร์ ZFS** บนการ์ดของอินสแตนซ์นั้นบนหน้าอินสแตนซ์และเลือกรายการ ZFS ที่นั่น การ์ดแสดง **รอการอนุมัติ** จนกว่าจะตอบ
2. บนอินสแตนซ์ที่รับ เปิด **อินสแตนซ์** คำขอแสดงบนการ์ดของอินสแตนซ์ที่ส่งเป็นป้าย และ **รายละเอียด** ของมันแสดงรายการ เลือกพูลและรูทบนเซิร์ฟเวอร์นั้นและจำนวนสแนปช็อตที่เหลือ แล้วกด **อนุญาต** หรือ **ปฏิเสธ**
3. หลังจาก **อนุญาต** ต้นทางจะส่งตามแผนของตัวเอง เหมือนกับปลายทางอื่น

อินสแตนซ์ที่รับยอมรับเฉพาะสิ่งที่การอนุมัติครอบคลุม: ชุดข้อมูลของรายการ เข้ารูทของตัวเอง มันรัน `zfs receive` เอง และต้นทางไม่มีทางลบหรือย้อนกลับอะไรที่นั่น สำเนาจึงอยู่รอดแม้ต้นทางถูกยึด อินสแตนซ์ที่รับใช้การเก็บรักษาของตัวเอง ต้นทางเพียงเสนอกฎเมื่อขอ

**Revoke access** บนอินสแตนซ์ที่รับจะยุติการอนุมัติได้ทุกเมื่อ และแจ้งต้นทาง ซึ่งจะแสดงว่าการอนุมัติถูกถอนและหยุดส่ง สิ่งที่อินสแตนซ์ที่รับมีอยู่แล้วจะยังอยู่ที่นั่น คำขอที่ปฏิเสธแล้วจะยังเป็นปฏิเสธ หากต้องการชุดข้อมูลเพิ่ม หรือขอใหม่หลังเพิกถอน ต้องขออีกครั้ง

อินสแตนซ์ที่รับต้องตอบผ่าน HTTPS ต้นทางจะไม่ส่งอะไรไปยังที่อยู่ http ธรรมดา เพราะโทเค็นและข้อมูลจะผ่านเครือข่ายโดยไม่เข้ารหัส การถ่ายโอนแต่ละครั้งยังเว้นพื้นที่หนึ่งในสิบของพูลที่รับไว้ และหยุดก่อนจะใช้ส่วนนั้น ต้นทางเดียวจึงทำให้พูลของเซิร์ฟเวอร์ที่รับเต็มไม่ได้

### ข้อมูลไปอยู่ที่ไหน {#replica-target}

ชุดข้อมูลแต่ละชุดจะไปอยู่ที่ `<root>/<server>/<pool>/<path>` โฟลเดอร์เซิร์ฟเวอร์คือชื่อของอินสแตนซ์ต้นทาง ซึ่งถูกกำหนดตอนส่งครั้งแรก เซิร์ฟเวอร์สองเครื่องที่ใช้ชื่อพูลเดียวกันจึงไม่ชนกัน ตัวอย่างเช่น `cache/appdata` ของเซิร์ฟเวอร์ชื่อ `tower` จะไปอยู่ที่ `backup/bombvault-replica/tower/cache/appdata`

สำเนาบนปลายทางเป็นแบบอ่านอย่างเดียวและไม่ถูกเมานต์ จึงไม่ทับสิ่งใดบนเซิร์ฟเวอร์นั้น คุณสมบัติของ ZFS จะถูกส่งไปด้วย ยกเว้นจุดเมานต์ `sharenfs` และ `sharesmb` การจองพื้นที่ `reservation` และ `refreservation` ก็ไม่ถูกส่งไปเช่นกัน สำเนาจึงใช้พื้นที่เท่าที่ข้อมูลต้องการเท่านั้น

### สิ่งที่รวมอยู่ {#replica-contents}

ทุกอย่างที่รายการสำรองเข้ามา และโวลุ่มข้างใต้ด้วย ซึ่งการสำรองข้าม ชุดข้อมูลลูกที่คุณปิดในรายการยังอยู่ข้างนอก ทุกชุดข้อมูลของการรันมาจากสแนปช็อตเดียว เหมือนในการสำรอง

### สแนปช็อตอยู่นานเท่าไร {#replica-retention}

บนปลายทาง สำเนาจำลองใหม่เก็บสแนปช็อตรายวัน 7 อันและรายสัปดาห์ 3 อัน เลือก **Short**, **Balanced** หรือ **Long** แทนก็ได้ หรือตั้ง **Custom values** ที่นั่นจะลบเฉพาะสแนปช็อตที่ชื่อ `bombvault-replica-<14 digits>` และไม่เคยลบอันใหม่สุดที่ทั้งสองฝั่งมีร่วมกัน

บนต้นทาง BombVault เก็บเฉพาะสแนปช็อตสำเนาจำลองล่าสุด พร้อมบุ๊กมาร์กของทุกสถานะที่ส่งไปแล้ว บุ๊กมาร์กไม่ใช้พื้นที่ การส่งครั้งถัดไปเริ่มจากบุ๊กมาร์กเหล่านั้น

### ชุดข้อมูลที่เข้ารหัสในสำเนาจำลอง {#replica-encryption}

ชุดข้อมูลที่เข้ารหัสจะถูกส่งแบบดิบ มันยังคงเข้ารหัสอยู่บนปลายทาง และปลายทางไม่เคยเห็นคีย์ เก็บคีย์ไว้ให้ดี: คุณต้องใช้คีย์เพื่อเปิดสำเนาหลังการกู้คืน และสำเนาจำลองที่ไม่มีคีย์จะอ่านไม่ได้

### การใช้สำเนาจำลอง {#replica-use}

เปิดแท็บ **การสำรองข้อมูล** ของรายการแล้วคลิกแถว **เรพลิกา ZFS** ในบรรดาที่เก็บสแนปช็อตของมัน แผ่นรายการแสดงสแนปช็อตบนเป้าหมายและคำสั่งพร้อมชื่อจริงของคุณ

หากต้องการดูสถานะเก่า ให้โคลนสแนปช็อตบนปลายทาง โคลนไม่ใช้พื้นที่จนกว่าจะมีอะไรเปลี่ยน และสำเนาจำลองไม่ถูกแตะต้อง:

```
zfs clone backup/bombvault-replica/tower/cache/appdata@bombvault-replica-20261006014100 backup/bombvault-replica/clone-appdata
```

หากต้นทางเสีย ให้เปลี่ยนสำเนาบนปลายทางเป็นชุดข้อมูลปกติที่เขียนได้:

```
zfs inherit -r readonly backup/bombvault-replica/tower/cache/appdata && zfs inherit -r canmount backup/bombvault-replica/tower/cache/appdata && zfs mount -a
```

หลังจากนั้น BombVault จะหยุดทำสำเนาจำลองไปยังชุดข้อมูลนั้น จนกว่าคุณจะเริ่มการรันครั้งแรกใหม่

หากต้องการนำสถานะกลับมายังต้นทาง ให้กด **Bring back as a new dataset** ในแผ่น BombVault จะส่งสแนปช็อตเข้าไปในชุดข้อมูลใหม่ข้างชุดข้อมูลเดิม ตั้งชื่อว่า `<dataset>-bombvault-restore-` ตามด้วยเวลา และไม่เคยเขียนทับของเดิม

## สแนปช็อตที่ค้างอยู่ {#leftover-snapshots}

สแนปช็อตของการสำรองมีชื่อ `<dataset>@bombvault-<ตัวเลข 14 หลัก>` เช่น `cache/appdata@bombvault-20260924021500` (UTC) BombVault จะลบมันทันทีหลังการสำรอง ถ้าลบไม่สำเร็จ เช่น เพราะชุดข้อมูลกำลังถูกใช้งานหรือ BombVault ถูกหยุด BombVault จะลบมันในเวลาต่อไปนี้:

- ก่อนการสำรองครั้งถัดไปของรายการนั้น
- เมื่อ BombVault เริ่ม สำหรับทุกรายการ แม้ปิดส่วนไว้
- เมื่อคุณลบรายการ
- เมื่อคุณกด **ลบตอนนี้** บนรายการ ซึ่งแสดงว่าเหลือกี่ชุด

จะลบเฉพาะชื่อที่ตรงกับ `bombvault-` ตามด้วยตัวเลข 14 หลักพอดีเท่านั้น สแนปช็อตเพื่อความปลอดภัย สแนปช็อตของคุณเอง และสแนปช็อตอัตโนมัติจะไม่ถูกแตะต้อง หากต้องการลบเองด้วยมือ:

```
zfs destroy -r cache/appdata@bombvault-20260924021500
```

สแนปช็อตของสำเนาจำลองชื่อ `<dataset>@bombvault-replica-<14 digits>` และไม่ใช่สแนปช็อตที่ค้างอยู่ มันอยู่บนต้นทางจนกว่าการรันสำเนาจำลองครั้งถัดไปจะมาแทนที่ และอยู่บนปลายทางตราบเท่าที่นโยบายการเก็บรักษายังเก็บไว้ ตัวกวาดไม่แตะต้องมัน เพราะจับคู่เฉพาะ `bombvault-` ตามด้วยตัวเลข 14 หลักพอดี

## ความผิดปกติ {#anomalies}

ลูกที่ถูกทำให้ว่างแทบไม่เปลี่ยนยอดรวมของทรีใหญ่ การตรวจจับความผิดปกติจึงเฝ้าดูทุกชุดข้อมูลของรายการแยกกัน: ขนาด จำนวนไฟล์ ข้อมูลใหม่ และเวลา restic ต่างมีประวัติของตัวเอง ประวัตินั้นเป็นของชื่อชุดข้อมูล จึงคงอยู่เมื่อทรีถูกสำรองโดยรายการอื่นภายหลัง

ชุดข้อมูลที่การรันก่อนหน้าสำรองและการรันนี้อ่านไม่ได้นับว่าถูกทำให้ว่าง ตราบที่การเลือกของรายการไม่เปลี่ยน นั่นครอบคลุมคีย์ที่ไม่ได้โหลด ชุดข้อมูลที่ไม่ได้เมานต์ และชุดที่หายไปจากทรี ลูกที่คุณยกเว้นเองเปลี่ยนการเลือก ประวัติของมันจึงเริ่มใหม่แทน ขณะที่สิ่งที่พบเรื่องข้อมูลสูญหายเปิดอยู่ การเก็บรักษาเก็บข้อมูลสำรองเก่าของชุดข้อมูลนั้นอย่างเดียวและตัดทิ้งส่วนที่เหลือของทรีตามปกติ

ทุกชุดข้อมูลมีบรรทัดของตัวเองในการเฝ้าติดตามของรายการ ซึ่งเปิดด้วย **การเฝ้าติดตาม** บนหน้า **ความผิดปกติ** และอยู่บนแท็บ **ยืนยัน** ของรายการ สิ่งที่พบที่เปิดอยู่แสดงข้างแต่ละชุดข้อมูล ลิงก์ในสิ่งที่พบเปิดหน้าต่างการกู้คืนบนข้อมูลสำรองที่ดีล่าสุดของชุดข้อมูล การรันเสร็จหรือไม่ตัดสินสำหรับทั้งรายการ เพราะการรันสำเร็จหรือล้มเหลวทั้งก้อน

การตรวจเองอธิบายไว้ใน [Features](features.md) ผู้ช่วยที่เชื่อมต่อผ่าน[เซิร์ฟเวอร์ MCP](mcp.md) แสดงรายการจุดกู้คืนของรายการ ZFS เริ่มการสำรอง และอ่านสิ่งที่พบได้ แต่การรับทราบสิ่งที่พบทำบนหน้า **ความผิดปกติ**

## รหัสเหตุผล {#reason-codes}

หน้าของรายการ ประวัติการรัน และการแจ้งเตือนระบุปัญหาด้วยหนึ่งในรหัสเหล่านี้ ส่วนใหญ่มีวิธีแก้ข้างกันบนหน้าด้วย

| รหัส | ความหมาย | สิ่งที่ต้องทำ |
|---|---|---|
| `ssh-missing` | ยังไม่ได้ตั้งค่าการเชื่อมต่อ SSH ในคอนเทนเนอร์นี้ | ตั้งค่าการเชื่อมต่อ SSH แบบเดียวกับการสำรองข้อมูล VM |
| `host-placeholder` | Host SSH: Address ยังเป็นค่าตัวอย่าง และ `host.docker.internal` ก็ไม่ตอบ | ตั้ง Host SSH: Address เป็น IP ใน LAN ของเซิร์ฟเวอร์นี้ |
| `host-fallback` | Host SSH: Address ยังเป็นค่าตัวอย่าง แต่ `host.docker.internal` ใช้งานได้ | ไม่ต้องทำอะไร หรือตั้ง IP ใน LAN |
| `ssh-unreachable` | เข้าถึงเซิร์ฟเวอร์ผ่าน SSH ไม่ได้ | ตรวจที่อยู่และพอร์ต และตรวจว่าเปิด SSH อยู่ |
| `ssh-auth` | เซิร์ฟเวอร์ปฏิเสธคีย์ของ BombVault | รันคำสั่งที่แสดงใต้ **การเชื่อมต่อกับเซิร์ฟเวอร์นี้** หนึ่งครั้งบนเซิร์ฟเวอร์ |
| `zfs-not-found` | โฮสต์ SSH ไม่มีคำสั่ง `zfs` | ชี้ Host SSH: Address ไปยังเครื่องที่เป็นเจ้าของพูล |
| `zfs-permission` | ผู้ใช้ SSH ไม่มีสิทธิ์รันคำสั่ง zfs นี้ | ใช้ root หรือดู [TrueNAS SCALE](#truenas) |
| `uri-mismatch` | `LIBVIRT_URI` ระบุโฮสต์หรือผู้ใช้ต่างจากช่อง SSH | ทำให้ตรงกัน หรือล้างช่อง SSH เพื่อให้ทั้งสองมาจาก URI |
| `zfs-error` | zfs รายงานข้อผิดพลาดอื่น | รายละเอียดจะแสดงข้อความของมัน |
| `propagation-missing` | การเมานต์ใหม่บนโฮสต์ไม่ถึงคอนเทนเนอร์ | ตั้ง Access Mode ของ Host Data เป็น Read/Write - Slave แล้วรีสตาร์ท BombVault |
| `invalid-name` | ชื่อชุดข้อมูลที่ BombVault ไม่รับ | เปลี่ยนชื่อชุดข้อมูล |
| `name-too-long` | ชุดข้อมูลในทรียาวเกินไปสำหรับชื่อสแนปช็อต | เปลี่ยนชื่อ หรือเพิ่มชุดข้อมูลข้างใต้เป็นรายการ |
| `invalid-exclude` | รูปแบบการยกเว้นหรือลูกที่เว้นไว้ไม่เข้ากับรายการ | แก้รายการที่ข้อความระบุ หากต้องการเว้นชุดข้อมูลลูกทั้งก้อน ให้ปิดมันแทนการเขียนรูปแบบ |
| `not-found` | ไม่มีชุดข้อมูลนี้บนเซิร์ฟเวอร์ | ลบรายการ หรือสร้างชุดข้อมูลใหม่ ข้อมูลสำรองของมันยังกู้คืนได้ |
| `not-filesystem` | นี่เป็นวอลุ่ม ไม่ใช่ระบบไฟล์ | ดู [วอลุ่ม](#volumes) |
| `overlaps-item` | ชุดข้อมูลซ้อนทับกับรายการที่มีอยู่ | ดู [รายการไม่ซ้อนทับกันเด็ดขาด](#overlap) |
| `docker-storage` | ต้นไม้มีที่เก็บอิมเมจของ Docker | ดู [ที่เก็บของ Docker](#docker-storage) |
| `nothing-readable` | ไม่มีชุดข้อมูลใดในรายการอ่านได้ตอนนี้ | ดูรหัสของชุดข้อมูลที่ข้าม |
| `snapshot-failed` | สร้างสแนปช็อตไม่ได้ | รายละเอียดจะแสดงข้อความของ zfs |
| `containers-busy` | การสำรองคอนเทนเนอร์ยังทำงานอยู่ตอนที่ต้องหยุดคอนเทนเนอร์ | เริ่มใหม่ภายหลัง การรันตามกำหนดเวลาจะรอเอง |
| `consistency-stop-failed` | หยุดคอนเทนเนอร์ไม่ได้ จึงไม่มีการสร้างสแนปช็อต | ตรวจคอนเทนเนอร์ หรือนำออกจากรายการ |
| `pre-snapshot-failed` | คำสั่งก่อนสแนปช็อตล้มเหลว | รายละเอียดของการรันจะแสดงผลลัพธ์ของคำสั่ง |
| `container-unknown` | ไม่มีคอนเทนเนอร์ที่อยู่ในรายการ | นำออกจากรายการ |
| `container-is-self` | BombVault หยุดคอนเทนเนอร์ของตัวเองไม่ได้ | นำออกจากรายการ |
| `leftover-snapshots` | ยังมีสแนปช็อตที่ BombVault ลบไม่ได้ค้างอยู่บนเซิร์ฟเวอร์ | กด **ลบตอนนี้** ดู [สแนปช็อตที่ค้างอยู่](#leftover-snapshots) |
| `zvol` | วอลุ่มในต้นไม้ ถูกข้าม | ดู [วอลุ่ม](#volumes) |
| `canmount-off` | ไม่เคยถูกเมานต์ (`canmount=off`) ถูกข้าม | ถ้ามีข้อมูลอยู่ ให้เมานต์ หรือย้ายข้อมูลไปยังชุดข้อมูลลูก |
| `legacy-mount` | จุดเมานต์แบบ legacy ถูกข้าม | กำหนดจุดเมานต์ใต้ `/mnt` ให้ |
| `no-mountpoint` | ไม่มีจุดเมานต์ ถูกข้าม | กำหนดจุดเมานต์ใต้ `/mnt` ให้ |
| `not-mounted` | ไม่ได้เมานต์บนเซิร์ฟเวอร์ ถูกข้าม | เมานต์ด้วย `zfs mount` หรือตั้ง `canmount=on` |
| `key-not-loaded` | เข้ารหัสไว้และยังไม่ได้โหลดคีย์ ถูกข้าม | `zfs load-key` แล้วเมานต์ |
| `snapdir-disabled` | ปิดการเข้าถึงสแนปช็อตไว้ ถูกข้าม | `zfs set snapdir=hidden <dataset>` โฟลเดอร์ `.zfs` จะยังซ่อนอยู่ |
| `not-visible` | BombVault มองไม่เห็นจุดเมานต์ของชุดข้อมูล | ย้ายจุดเมานต์ไปไว้ใต้พาธ Host Data หรือแมปเข้าไปในคอนเทนเนอร์ที่พาธเดียวกันด้วย Read/Write - Slave |
| `shfs-only` | ชุดข้อมูลมองเห็นได้ผ่าน `/mnt/user` เท่านั้น ซึ่งซ่อนสแนปช็อต | แมป `/mnt` ไม่ใช่ `/mnt/user` เป็น Host Data |
| `snapshot-not-visible` | สร้างสแนปช็อตแล้วแต่ไม่ปรากฏภายใน BombVault | รัน **ทดสอบการเข้าถึงสแนปช็อต** ดูด้านล่าง |
| `snapshot-loop` | สแนปช็อตไปไม่ถึง BombVault เพราะ Host Data ไม่ส่งต่อการเมานต์ใหม่ | ตั้ง Access Mode ของ Host Data เป็น Read/Write - Slave แล้วรีสตาร์ท BombVault |
| `backup-failed` | restic ล้มเหลวสำหรับชุดข้อมูลนี้ | รายละเอียดของการรันจะแสดงสาเหตุ |
| `not-reached` | การรันจบก่อนถึงชุดข้อมูลนี้ | รันการสำรองอีกครั้ง |
| `gone` | ชุดข้อมูลไม่อยู่บนเซิร์ฟเวอร์แล้ว | ไม่ต้องทำอะไร ข้อมูลสำรองของมันยังกู้คืนได้ |
| `read-only-mount` | BombVault อ่านชุดข้อมูลได้อย่างเดียว จึงกู้คืนเข้าไปไม่ได้ | ตั้งการแมปเป็น Read/Write - Slave หรือกู้คืนไปยังโฟลเดอร์ |
| `destination-not-mounted` | โฟลเดอร์ไม่ได้อยู่บนพูลหรือแชร์ที่เมานต์อยู่ | เลือกโฟลเดอร์บนพูลหรือแชร์ |
| `not-enough-space` | ปลายทางมีพื้นที่ว่างไม่พอ | เพิ่มพื้นที่ว่าง หรือเลือกโฟลเดอร์อื่น |
| `safety-snapshot-failed` | สร้างสแนปช็อตเพื่อความปลอดภัยไม่ได้ จึงไม่มีการกู้คืนใด ๆ | รายละเอียดจะแสดงข้อความของ zfs |
| `safety-name-too-long` | ชื่อชุดข้อมูลยาวเกินกว่าจะใช้กับสแนปช็อตเพื่อความปลอดภัย | ปิดสแนปช็อตเพื่อความปลอดภัย หรือกู้คืนไปยังโฟลเดอร์ |
| `dataset-exists` | มีชุดข้อมูลชื่อนี้อยู่แล้ว | เลือกชื่อใหม่ หรือกู้คืนลงในชุดข้อมูลนั้นเอง |
| `create-failed` | สร้างชุดข้อมูลใหม่ไม่ได้ | รายละเอียดแสดงข้อความจาก zfs ตรวจสอบว่าชุดข้อมูลด้านบนมีอยู่ |
| `new-dataset-not-visible` | สร้างชุดข้อมูลใหม่แล้ว แต่ BombVault มองไม่เห็น จึงไม่มีการกู้คืนใดๆ | ชุดข้อมูลยังอยู่บนเซิร์ฟเวอร์ เมานต์ไว้ใต้พาธ Host Data แล้วกู้คืนลงไป |
| `set-properties-failed` | ตั้งคุณสมบัติที่บันทึกไว้ไม่ได้ จึงไม่มีการกู้คืนใดๆ | รายละเอียดจะแสดงข้อความของ zfs |
| `set-limits-failed` | กู้คืนไฟล์แล้ว แต่ตั้งโควตาหรือการจองพื้นที่ที่บันทึกไว้ไม่ได้ | รายละเอียดแสดงข้อความจาก zfs ตั้งโควตาหรือการจองพื้นที่เองด้วย `zfs set` |

### ตรวจว่าคอนเทนเนอร์มองเห็นอะไร {#mountinfo}

**ทดสอบการเข้าถึงสแนปช็อต** บนแท็บการตั้งค่าของรายการถ่ายสแนปช็อตจริงของทรี มองหามันภายใน BombVault สำหรับทุกชุดข้อมูล และลบอีกครั้ง เป็นวิธีเร็วที่สุดในการพิสูจน์ทั้งเส้นทางก่อนการรันตามตารางเวลาครั้งแรก

หากต้องการดูเอง ให้รันคำสั่งนี้บนเซิร์ฟเวอร์:

```
docker exec BombVault grep zfs /proc/self/mountinfo
```

แต่ละบรรทัดคือการเมานต์หนึ่งรายการภายในคอนเทนเนอร์ บรรทัดของชุดข้อมูลแสดงพาธภายในคอนเทนเนอร์ (ใต้ `/host/user`) และชื่อชุดข้อมูล ช่อง `master:N` ในบรรทัดนั้นหมายความว่าการเมานต์นี้ได้รับการเมานต์ที่โฮสต์ทำภายหลัง ซึ่งการเข้าถึงสแนปช็อตต้องการ ถ้าไม่มี ให้ตั้ง Access Mode ของ Host Data เป็น Read/Write - Slave แล้วรีสตาร์ท BombVault

## TrueNAS SCALE {#truenas}

- เมื่อตั้งค่า `LIBVIRT_URI` ไว้ (เหมือนการสำรองข้อมูล VM บน TrueNAS) BombVault จะนำโฮสต์ ผู้ใช้ และพอร์ต SSH สำหรับคำสั่ง zfs จาก URI สำหรับค่าที่ไม่ได้ตั้งแยกไว้ หากไม่ได้สำรองข้อมูล VM ก็ไม่ต้องตั้งอะไรเลย: `host.docker.internal` แปลงชื่อไม่ได้ในแอป TrueNAS ดังนั้น BombVault จะเข้าถึงโฮสต์ผ่านเกตเวย์เริ่มต้นของแอป ในฐานะ root ที่พอร์ต 22 ตั้ง `LIBVIRT_HOST`, `LIBVIRT_SSH_USER` และ `LIBVIRT_SSH_PORT` ใน `environment` ของแอป เมื่อคุณต้องการที่อยู่หรือผู้ใช้อื่น
- เพิ่มคีย์ SSH ของโฮสต์จาก **การตั้งค่า, การเชื่อมต่อ, SSH ของโฮสต์** ให้ root ใน **Credentials, Users** และเปิดบริการ SSH ใน **System, Services** [เรพลิกา](#replica-push) ไปยัง TrueNAS เครื่องนี้หรือเครื่องอื่นต้องใช้คีย์ของเรพลิกาด้วย ซึ่งเป็นคีย์อีกตัวหนึ่ง
- ผู้ใช้อื่นที่ไม่ใช่ root ต้องมีสิทธิ์บนชุดข้อมูลบนสุดของรายการ ซึ่งครอบคลุมทุกชุดข้อมูลข้างใต้:

  ```
  zfs allow <user> snapshot,destroy,mount <dataset>
  ```

  การกู้คืนไปยังชุดข้อมูลใหม่ต้องมีสิทธิ์ `create` บนชุดข้อมูลด้านบนด้วย และการตั้งคุณสมบัติที่บันทึกไว้ต้องมีสิทธิ์สำหรับคุณสมบัติเหล่านั้น

  เซสชัน SSH ที่ไม่ใช่ root บน TrueNAS ไม่มี `/usr/sbin` ในพาธ BombVault จึงเรียก `/usr/sbin/zfs` โดยตรง
- **Host Data** ของแอปต้องเป็นพาธของโฮสต์ที่อยู่เหนือชุดข้อมูล เช่น `/mnt/tank` ไม่ใช่ ixVolume เมื่อใช้พาธของโฮสต์ แอปจะส่งต่อการเมานต์ใหม่ของโฮสต์ไปยัง BombVault (`rslave`) ซึ่งการเข้าถึงสแนปช็อตต้องการ ดู [TrueNAS SCALE](getting-started.md#truenas) สำหรับการตั้งค่าแอปทั้งหมด
