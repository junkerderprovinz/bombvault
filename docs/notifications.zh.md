# 通知

BombVault 可以在备份失败、成功、逾期时通知你，并且每周一次告诉你整体情况如何。一切都在**设置、通知**下设置：**通知**卡片决定什么会触发消息，**渠道**卡片决定消息发到哪里，**Healthchecks** 卡片管理签到 ping。

## 什么会发送消息 {#what}

**通知**卡片一次性为所有渠道设置规则：

- **通知**：**从不**、**仅在失败时**或**成功和失败时**，适用于下面所有渠道。
- **汇总计划运行**：每次计划运行发送一条消息，例如*45 个中有 42 个成功*，而不是每个容器或虚拟机一条。你手动启动的备份仍然会各自发送消息。即使开启了汇总，冻结的客户机、失败的保留规则或超出的增长预算也会立即发出。
- **容器更新时通知**：**备份成功后更新容器**把某个容器更新到较新的镜像时，为每个这样的容器发送一条消息，方便你确认它仍然正常。
- **报告逾期的备份**：BombVault 每天 09:00 检查一次，有没有开启的备份逾期，也就是比它的计划时间超过两倍，并为每种情况发送一条消息。下一次成功的备份会清除它。
- **Unraid 通知**：发送到 Unraid 自己的通知系统，它可以转发到 Pushover、邮件或 Discord。它通过**设置、集成、主机 SSH** 的 SSH 连接运行，所以那把密钥必须已被授权。在 TrueNAS 和其他主机上它保持关闭。
- **每周摘要**：每周一份摘要，包括运行次数、新的备份数据、异地副本是否是最新的，以及最主要的失败。它的计划是一个按钮，和其他计划一样，**关闭**可以把它关掉。参见[计划](schedules.md#plans)。

哪些异常会发送消息，在**设置、验证**下设置，参见[异常](anomalies.md)。被推迟的备份开始等待时发送一条消息，等待结束时再发送一条，而不是每次尝试一条。

卡片底部的**发送测试**会通过每个开启的渠道发送一条测试消息，使用表单里当前的值。

## 渠道 {#channels}

每个渠道在**渠道**卡片里都有自己的开关，开启后它的字段才会出现。每个渠道各自发送，有自己的时间限制，所以一个始终不应答的主机不会拖住其他渠道，没有渠道接收的消息会重试。

| 渠道 | 字段 | 说明 |
|---|---|---|
| **Webhook** | **Webhook 网址**、**Webhook 格式** | 格式：**Generic JSON**、**Discord**、**Slack**、**Gotify** 和 **ntfy**。Generic JSON 会发送 `title`、`message` 和 `ok`。 |
| **Apprise** | **Apprise API URL**、**标签（可选）** | 指向你的 Apprise API 容器的 `/notify/<key>` 端点，就能用到它的 100 多种服务。标签用来选择该密钥下目标的一个子集。 |
| **Matrix** | **Homeserver 网址**、**访问令牌**、**房间 ID** | 令牌保存在服务器上，不会再次显示。 |
| **Gotify** | **服务器 URL**、**应用令牌**、**失败时的优先级**、**成功时的优先级** | 优先级从 0 到 10，失败默认为 8，成功默认为 5。 |
| **邮件 (SMTP)** | **SMTP 主机**、**端口**、**加密**、**用户名**、**密码**、**发件地址**、**收件地址** | **加密**可选 **STARTTLS**、**TLS（隐式）**或**无**。 |

Matrix 令牌、Gotify 应用令牌和 SMTP 密码这类密钥会加密保存。在已保存的密钥下面，字段会显示**已保存。留空即可保留。**当你更改服务器地址时，BombVault 不会把旧的密钥发到新的地方：字段会再次要求输入，你输入之后才会保存新地址。

## Healthchecks {#healthchecks}

[Healthchecks.io](https://healthchecks.io) 这类服务会在 BombVault 停止签到时发出警报。粘贴检查项的 **ping 网址**，BombVault 就会在每次备份的整个生命周期里 ping 它：开始时、成功时，或失败时用 `/fail`。只要设置了网址，不管**通知**怎么设置，它都会这样做，所以即使只在失败时发消息，成功时检查项也保持绿色。

分区可以 ping 自己的地址：卡片里的**例外**会添加一个，那一行会写**所有其他分区 ping 这个网址。**

## 示例：手机上的 Gotify {#example-gotify}

你在 `https://gotify.example.com` 运行 Gotify，希望失败时手机响铃，成功时静静到达。

1. 在 Gotify 里打开 **Apps**，创建一个名为 `BombVault` 的应用并复制它的令牌。
2. 在 BombVault 里打开**设置、通知**。在**通知**里把**通知**设为**成功和失败时**，并开启**汇总计划运行**，这样 45 次备份的一晚只发送一条消息，而不是 45 条。
3. 在**渠道**里开启 **Gotify**。
4. 把 `https://gotify.example.com` 填入**服务器 URL**。BombVault 会自己加上 `/message`。
5. 把令牌粘贴到**应用令牌**。
6. **失败时的优先级**保持 8，**成功时的优先级**保持 5。Gotify 的 Android 应用把 8 及以上视为高优先级，所以只有失败才会发出声音。
7. 点击**发送测试**。卡片下面的那一行会说明 Gotify 是否接收了，令牌被拒绝时也会如实写出来。

下一次计划运行会以优先级 5 发送一条摘要，如果其中有任何失败，则以 8 发送。

## 示例：把 ntfy 当作 webhook {#example-ntfy}

公开主题的 ntfy 不需要账号。请选一个难以猜到的主题名称，因为任何知道它的人都能读到。

1. 在**渠道**里开启 **Webhook**。
2. 把主题的地址填入 **Webhook 网址**，例如 `https://ntfy.sh/bombvault-tower-7f3k`，或者你自己 ntfy 服务器的地址。
3. 把 **Webhook 格式**设为 **ntfy**。
4. 在 ntfy 应用里订阅同一个主题，然后点击**发送测试**。

BombVault 把消息作为正文发送，标题放在 `X-Title` 里。失败会以高优先级和标签 `warning` 发出，所以在应用里很显眼。
