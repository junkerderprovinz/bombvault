# 异地与恢复

!!! note "重建之后异地副本会等待"
    当应急向导或**发现备份**在没有旧设置的情况下重建条目时，这些分区的异地副本会等待，直到你把它们的备份接收为此服务器自己的备份。参见[重建之后](#after-a-rebuild)。

本地备份保护你免于丢失容器或一次糟糕的更新。异地副本和经过测试的恢复工具包则保护你免于整台机器出事、勒索软件或一场火灾。本页涵盖存储位置和异地副本、让副本防篡改、证明你能恢复、配对多台服务器，以及在 BombVault 本身没了之后把一切找回来。

## 异地副本 {#off-site-copies}

保留快速的本地备份，再在场所之外添加一个或多个存储位置。BombVault 用 `restic copy` 尽力把新的快照复制过去，所以异地的小故障绝不会让本地备份失败。在这种形态下，每个分区先写入自己的文件夹，异地仓库是一份副本。专属文件夹不必在这台服务器上：如何把它放在 S3 或 rest-server 这类存储位置里，参见[分区的专属文件夹](#own-folder)。

- **每个分区多个存储位置。** 每个分区（容器、虚拟机、闪存、自我备份、文件夹和 ZFS 数据集）可以同时复制到多个异地存储位置，例如你可以同时在朋友的机器上放一台 rest-server，并保留一个 S3 存储桶。目标页面上的**按分区划分的目标**卡片开关每一条从分区到位置的线。
- **复制何时运行。** 位置的**复制**卡片设置**复制时机**：**每次备份后**，或按它自己的计划，在固定的时间收集快照并复制。在**设置、计划、按分区的异地副本**下，**例外**可以给某个分区单独的复制计划。
- **异地副本卡片。** 在**设置、目标**下，每个有异地副本的分区在**异地副本**里都有一行，带**测试连接**、按需启动复制的**立即复制**，以及**设置**或**编辑**。分区复制设置的其余部分从那里在它的窗口里打开。
- **保留**按存储位置在**保留多久**下设置，所以你可以把异地副本保留得更久，当作存档。分区异地字段里的副本和其他所有副本一样遵循它，分区可以在**按分区划分的规则**下保留自己的值。全部为零则绝不修剪异地快照。参见[保留多久](#keep)。
- **带宽限制**（**设置、目标**下的**异地带宽**，或位置的**复制**卡片）限制 restic 的上传和下载速率，让复制不会占满你的广域网。以 KiB/s 输入（restic 使用的单位），每个字段在你输入时会同时显示以 MB/s 和 Mbit/s 表示的同一速率：2048 显示为约 2.0 MB/s（16.8 Mbit/s）。
- **压缩**可选**关闭**、**自动**（restic 的默认值）或**最大**，在每个存储位置上设置，对某个分区则在那里的规则下设置。备份、复制和清理都按它写入，恢复工具包也会写明它，这样普通的 restic 可以继续以同样的方式写入。
- **串流优先。** 当 Plex、Jellyfin 或 Emby 这类媒体服务器在串流时，复制会以较低的限制上传，并在串流结束几分钟后恢复正常。目标页面上的**串流**卡片有**串流时减慢异地副本**、**媒体服务器**（在你选择之前，是镜像名称里含 Plex、Jellyfin 或 Emby 的容器）、**串流阈值 (Mbit/s)**、**串流时的上传限制 (KiB/s)** 和**恢复常规前等待 (分钟)**。BombVault 从 Docker 读取流量，所以主机网络上的媒体服务器无法测量。REST、S3、B2、Azure、Google Cloud、Swift 和基于 HTTP 的 rclone 会在复制中途就减速。SFTP 以及本地或已挂载的文件夹则在下一个复制步骤才采用较低的限制。
- **冷存储（S3）。** S3 位置可以使用更便宜、且 restic 仍可立即读取的**存储类别**，例如 Standard-IA、One Zone-IA、Intelligent-Tiering 或 Glacier Instant Retrieval。Glacier Flexible Retrieval 和 Deep Archive 不在其中，因为 restic 无法从它们恢复。rclone 远端在 rclone 配置里设置它的类别。
- **同时连接数。** 在 S3、B2、Azure、Google Cloud、Swift、rest-server、SFTP 或 rclone 位置上，**连接**卡片里的**同时连接数**决定 restic 一次打开多少个连接，范围是 1 到 32。留空时 restic 保持默认值 5。连接多一些能让远距离或慢速线路更快，少一些则对限速的服务商更友好。该位置上的备份、复制、检查、清理和恢复都会用到它，设置导出也会带上它。本地或已挂载的文件夹没有这个设置。
- **增长预算。** 分区复制窗口里的**增长预算（GB，0 = 关闭）**会在仓库增长超过这个大小时发出警报。它绝不会删除任何东西，所以适合这里不做清理的 append-only 副本。
- 复制运行期间，概览的状态栏会显示**正在异地复制**。它是一个活动指示，不是百分比进度条，因为 `restic copy` 不提供机器可读的进度。

!!! note "从任何地方恢复"
    每个条目在它的**备份**标签页上，把它的备份列成跨所有存放位置的一条时间线。复制到 B2 的备份只出现一次，标出每个保存它的位置。恢复会取它能到达的第一个位置，从条目写入的仓库开始，你也可以为每个快照选另一个位置。异地存储位置只在你点击**检查**时才读取，因为列出云存储需要一些时间。在一个位置删除时，会先检查其他位置，并说明这是否是最后一份副本。参见[恢复](restore.md)。

## 存储位置 {#destinations}

存储位置是备份存放的地方：本地文件夹、共享、你自己的服务器或云服务。设置一次之后，它为每个分区服务。从它的设置磁贴打开**目标**，或在那里开启**同时显示在侧边栏**把它固定住。

![目标页面：位置列表，以及哪个分区去哪里的流程图。](assets/screenshots/storage/locations-dark.png#only-dark)
![目标页面：位置列表，以及哪个分区去哪里的流程图。](assets/screenshots/storage/locations-light.png#only-light)

**添加目标**会打开一个分四步的窗口：

1. **服务商。** 每个服务都带着它的标志列出，窗口右上角有搜索，并分组：连接到这台服务器的磁盘或共享为**本地**，**NAS 或服务器**（rest-server、Hetzner Storage Box、SFTP、SMB、WebDAV 等），**S3 服务**（Backblaze B2、Wasabi、Cloudflare R2、Hetzner Object Storage、Amazon S3 等），你自己的 S3 服务器（Garage、SeaweedFS、RustFS、Silo、Ceph、JuiceFS、Versity S3 Gateway），**云存储**（OneDrive、Google Drive、Dropbox、pCloud、Nextcloud 以及 rclone 支持的其他服务），以及**来自你的组**，即你的组里的接收服务器。每一个都会说明它有多适合备份：云盘在大量请求下会变慢，所以第一次备份和清理在那里要花更长时间。对于没有磁贴涵盖的服务，**自定义 rclone 配置**下的 **Rclone** 磁贴接受从 rclone.conf 粘贴的远端。
2. **登录。** 字段取决于服务：S3 用访问密钥，WebDAV 和 SMB 用用户名和密码，两步登录挡住普通密码的地方用应用密码，SFTP 和 Storage Box 用 BombVault 的 SSH 公钥，通过浏览器登录的服务则用令牌。对这些服务，窗口会显示一条 `rclone authorize` 命令，在有浏览器的电脑上运行，它打印出的令牌填入字段。如果你已经有该服务的[已保存凭据](#sign-ins)，**已保存的凭据**可以选它，而不用**新密钥**。**测试连接**会在保存任何东西之前检查登录。窗口随后会列出存储位置上的文件夹，用**新建文件夹**创建一个，并在服务报告时显示可用空间。空文件夹最安全。BombVault 会在其中为每个分区放一个文件夹。
3. **保护。** 窗口会直白地说明这个服务能做什么。append-only 模式的 rest-server 会拒绝删除，防篡改测试会检查这一点。S3 存储桶可以通过版本控制和对象锁保留旧版本，BombVault 目前还无法检查。云盘根本无法拒绝删除：能进入服务器的人也能进入那份副本。只在对方确实会拒绝删除的地方才开启**防删除保护（append-only）**。BombVault 此后绝不会在那里清理。**应对紧急情况**说明恢复工具包为这个位置保存了什么。
4. **针对哪些分区。** 选择备份到这里的分区。第一次复制会带上整个历史。自己选择了存储位置的条目不会自动得到新的位置，窗口会点出它们的名字。

有些服务在登录时还要多问一点：

- **SFTP 和 Storage Box。** **添加密钥**会用**账户密码**把 BombVault 的公钥放到服务器上，这个密码只用于那一次登录，不会在任何地方保存。手动操作的命令显示在它下面。测试会显示带指纹的**服务器密钥**。BombVault 会记住它，如果服务器之后显示不同的密钥，就会拒绝这台服务器。
- **只对单个存储桶的 S3 密钥**，例如 Cloudflare R2 的对象令牌或限定范围的 AWS 密钥，可能无法列出其他存储桶。请把存储桶填入**桶**，测试和文件夹列表就会打开那个存储桶。
- **S3 区域和地址。** 区域会从写明它的端点读取（AWS、Backblaze B2、Hetzner、Scaleway、OVH、Wasabi），Garage 从它自己的默认区域开始，IDrive e2 则要求填写它的控制台所显示的端点。像 R2 控制台那样、带着存储桶粘贴的地址，会填好服务器和存储桶。从文件夹浏览器创建的存储桶会放进表单里写明的区域。
- **存储类别。** 选择器只提供服务接受的类别，**更多设置**只显示会影响新存储桶的选项。
- **Google Drive 和 OneDrive。** 清理掉的数据会被永久删除，而不是进入回收站，否则它们仍然会占用配额。Google 共享云端硬盘放在**更多设置**下。
- **不列出共享的 SMB 服务器**在**共享**下填写其中一个的名称，测试会直接打开那个共享。
- **FTP** 会询问它的**加密**：**无**、**显式 TLS (FTPES)** 或**隐式 TLS (FTPS，端口 990)**。
- **OneDrive 和 Zoho WorkDrive。** 当一次登录打开多个驱动器或工作区时，窗口会询问备份存到哪一个。
- **使用自签名证书的 rest-server。** 把证书作为 PEM 文件放进 BombVault 数据文件夹的 `certs` 文件夹（容器里是 `/config/certs`，Unraid 上是 `appdata/bombvault/certs`）。备份、复制和防删除保护测试无需重启就会信任它。

S3 服务通过 restic 自己的 S3 后端运行，这使得存储类别和对象锁可以生效。restic 直接访问 rest-server。其他所有服务都通过 BombVault 附带的 rclone 运行，它们在 rclone 配置中的部分显示在位置页面的 **rclone.conf** 卡片里，密钥已隐藏。设置导出会带上存储位置，包含凭据时也会带上它们的登录凭据。

保存一个已经保存有容器、虚拟机或文件夹备份的存储位置（例如你移除后又重新添加的位置）时，它会作为未勾选的副本加入这些分区。在你勾选之前不会往那里复制任何东西，但**恢复**会立即提供旧的备份。

这台服务器上的文件夹在所有地方都叫做**本地**：在存储页面上、在流程图里、在条目上和在恢复里。这台服务器上有多个文件夹时，各自使用自己的名称。由分区的异地字段设置的存储位置，以它的位置命名：地址的最后一个文件夹，没有的话就是它的服务器，当另一个位置已使用该名称时，会加上编号。每个位置都可以在它的**连接**卡片的**名称**字段里重命名，包括多个分区共用的存储桶文件夹，以及分区异地字段所描述的副本，你给的名称会保留。两个同名的位置并排出现时，每个都会带上它的服务器或文件夹。

### 存储位置的页面 {#location-page}

每个存储位置都有自己的页面。它只显示适用于该位置的卡片，顺序如下：

![存储位置的页面：专属文件夹、连接和凭据。](assets/screenshots/storage/location-page-dark.png#only-dark)
![存储位置的页面：专属文件夹、连接和凭据。](assets/screenshots/storage/location-page-light.png#only-light)

- **专属文件夹**：先把备份写到这里的分区。这个位置的登录凭据、保护和限制适用于它们。**用作专属文件夹**会把更多分区的专属文件夹搬到这里，**更改**会把某一个再搬走。参见[分区的专属文件夹](#own-folder)。
- **直接备份到这里**：条目不经过自己的专属文件夹、直接备份到这个位置的每个分区，以及有多少条目这样做。这样的直接仓库所有设置都取自这个位置。不再有任何东西备份到的仓库会这样说明，**移除**可以把它从列表里拿掉。它所在位置的备份会保留。参见[直接仓库](#direct-repositories)。
- **连接**：**名称**、开关**可用**（关闭意味着 BombVault 不再往这里写，备份到这里的条目会带着明确的信息失败，而不是落到别处）、文件夹、**压缩**、**存储类别**、**同时连接数**和**场所之外**。在**本地**位置上，它在**此处的专属文件夹**下列出每个分区的文件夹。**更改连接**会测试并保存新的地址或登录凭据。当其他位置使用同一个已保存的凭据登录时，窗口会这样说明，在这里更改会给这个位置一个自己的凭据，而不是改写共享的那个。
- **凭据**：它使用哪个已保存的凭据（**登录使用**）、还有哪些位置也使用它（**其他使用者**），以及打开凭据窗口的**编辑**。参见[登录凭据](#sign-ins)。
- **rclone.conf**：这个位置在 rclone 配置里的部分，适用于通过 rclone 运行的位置。
- **防删除保护**，带**防删除保护（append-only）**、**在没有防删除保护的情况下接受**、**立即测试防删除保护**和**谁来清理**，后者说明 BombVault 是在这里清理副本和专属文件夹（依据这个位置的**保留多久**卡片，或分区在**按分区划分的规则**下自己的值），还是留给对方去做。本地文件夹只在它有可以关闭的保护时才显示这张卡片。参见[防删除保护](#delete-protection-append-only)。
- **复制**：**复制时机**，以及**上传限制 (KiB/s)** 和**下载限制 (KiB/s)**。只有专属文件夹、没有副本的位置，把限制显示为名为**带宽**的卡片。
- **保留多久**：**短**、**均衡**、**长**或**自定义值**，带一条显示规则保留哪些备份的时间线。参见[保留多久](#keep)。
- **已在此目标下**：手动输入的地址位于这个位置某个文件夹里的分区。接管其中一个会让仓库留在原处。登录凭据、存储类别和防删除保护随后取自这个位置。BombVault 会先检查位置的登录凭据能否打开仓库，并且拒绝把 append-only 仓库放在不是 append-only 的位置下。
- **按分区划分的规则**：某个分区在这个位置的专属仓库、保留或压缩。**更改规则**会打开它们，**恢复为目标的设置**会把某个分区带回来。登录凭据、带宽和复制何时运行始终取自这个位置。
- 一个显示位置有多满的容器，标出它写满的位置，以及按最近几周的增长还剩几周。不报告大小的位置会显示**大小未知**。

**移动**和**移除目标**位于页面的操作之中，说明见[移动与移除](#move-remove)。

曾经存有备份、突然没有仓库的远程存储位置，例如磁盘没有挂载的 rest-server，不会自己得到一个新的空仓库。一旦备份或复制发现仓库不见了，它的页面就会这样说明。请重新挂载磁盘。如果你有意清空了旧仓库，**在这里新建存储库**会对该位置及其仓库的所有分区一次性重新开始。这项保护针对的是一直留在原处的位置。你新添加的存储位置，或你在某个位置勾选的分区，会从头开始：如果那个地址没有仓库，第一次复制就会创建一个，即使之前移除的某个位置在那里有过仓库。

有两种拒绝会在复制的运行记录和该位置的页面上指出要纠正什么。**服务器上没有这个桶，因此无法向其中复制任何内容**会在 S3 服务器这样回答时立刻出现，BombVault 不会在那里创建任何东西，所以输错的桶名会一直显而易见。完全不应答的服务器是另一种情况：restic 会在每次调用时持续重试大约 15 分钟，以防它恢复。**这里已有一个 restic 存储库，本实例的密钥无法打开它**表示那里的备份属于另一个 `APP_KEY`。

你的组里另一个实例运行的接收服务器，会在服务商里显示为**来自你的组**。参见[接收服务器](#receiving-server)。

BombVault 在每次启动时检查它的存储位置。不需要你做决定的问题它会自己纠正，例如指向已不存在的副本或仓库的链接、专属文件夹上的副本，或副本已不存在的直接仓库，并为每次修正在日志里写一行。没有安全修复办法的只会记录下来。

### 保留多久 {#keep}

备份保留多久是按存储位置设置的，在它的**保留多久**卡片里。这个规则涵盖该位置的副本和位于那里的专属文件夹，包括**本地**位置。分区可以在**按分区划分的规则**下，在某个位置保留自己的值，对这个分区而言它们优先于位置的卡片。

规则会按你设置的时间跨度，每天、每周、每月和每年保留一份备份，并在每次备份或复制之后清理其余的：

| 预设 | 最新备份 | 天 | 周 | 月 | 年 |
|---|---|---|---|---|---|
| **短** | 0 | 7 | 4 | 3 | 0 |
| **均衡** | 0 | 7 | 4 | 6 | 2 |
| **长** | 0 | 14 | 8 | 12 | 3 |

**自定义值**由你自己设置这五个数。0 表示关闭那一项，五项全为 0 的规则会保留一切。卡片里的圆点显示规则会保留 40 个示例备份中的哪些，最新的在最右边。示例对每个位置都一样，因为图是在 BombVault 读取那里的备份之前画出来的。示例从今天往回数，所以留下多少个圆点会随日期变化。

这台主机上的文件夹和手动输入的远程文件夹也各有自己的卡片，它只涵盖那个文件夹里的专属文件夹，不涉及其他。保存之前，这样的文件夹按 BombVault 原本对它使用的规则处理旧备份。

**减少保留前先询问**默认开启，会在保存一个会保留更少备份的更改之前询问，并说明新规则会从 40 个示例备份中去掉多少个。它适用于每个存储位置。**按分区划分的规则**下的**恢复为目标的设置**会问同样的问题。

有防删除保护的位置绝不会在这台机器上被清理。它的对方按自己的规则保留或丢弃旧备份。条目有关于数据丢失的未处理严重异常期间，保留规则会保留该条目的旧备份，直到你确认它。参见[异常](anomalies.md)。

内容比应有的少的备份，绝不会让之前的备份过期。这指的是：之前的备份有文件而这次一个文件都没读到、缺少某个选中的文件夹，或有些文件读不了的备份。它的运行会以一条警告结束，写明缺了什么，并说明较旧的备份已保留，你的通知渠道也会收到同样的消息。在一次完整的备份完成之前，无论在条目的专属文件夹还是在它的副本上，任何清理都不会动这个条目的旧备份。第一次备份，以及一直为空的选中文件夹，都算作完整。

要看下一次运行真正会删除什么，请打开**设置、目标**下的**预览**。它会针对分区的专属文件夹和它的每个副本，按仓库和按条目列出**下次运行将删除的内容**，并点出恢复点的名称。它不加锁，也不改变任何东西。

#### 示例：均衡保留什么 {#example-retention}

一个容器自 2024 年 10 月 1 日起每晚 03:00 备份，所以到 2026 年 11 月 4 日星期三，它已有 765 份备份。它的存储位置设为**均衡**：7 天、4 周、6 个月和 2 年。

每一项都保留其所在天、周、月或年的最新备份，被多项选中的备份只保留一份。周从星期一算到星期日：

| 规则 | 它选中的备份 | 它新增的 |
|---|---|---|
| 7 天 | 11 月 4 日、3 日、2 日、1 日，10 月 31 日、30 日、29 日 | 全部 7 个 |
| 4 周 | 11 月 4 日、11 月 1 日、10 月 25 日、10 月 18 日 | 10 月 25 日、10 月 18 日 |
| 6 个月 | 11 月 4 日、10 月 31 日、9 月 30 日、8 月 31 日、7 月 31 日、6 月 30 日 | 9 月 30 日、8 月 31 日、7 月 31 日、6 月 30 日 |
| 2 年 | 11 月 4 日、2025 年 12 月 31 日 | 2025 年 12 月 31 日 |

这样 765 份中保留 14 份。最旧的来自 2025 年 12 月 31 日，所以今天你可以回溯十个多月。由于去重，它们占用的空间只比一份完整备份加上其间的变化多一点点。

**年**值得再看一眼。它统计的是有备份的日历年，从当年开始算起，而今年最新的备份就是今天的。所以第一年不会给其他几项增加任何东西，第二年则加上前一年的最后一份备份。这也是规则能回溯的范围在一年中不断变化的原因。同样这些备份在各个预设下的情况：

| 预设 | 今天保留的备份 | 今天最旧的备份 | 一年中能回溯的范围 |
|---|---|---|---|
| **短** | 10 | 2026 年 9 月 30 日 | 1 到 2 个月 |
| **均衡** | 14 | 2025 年 12 月 31 日 | 早春约 4 个月，12 月 31 日正好一整年 |
| **长** | 30 | 2024 年 12 月 31 日 | 1 月 1 日为 1 年，12 月 31 日为 2 年 |

从**均衡**改成**短**会先询问，这是**减少保留前先询问**的作用。问题里会说明，图中的 40 份备份里新规则会移除多少份。这个数字来自示例，所以会随日期变化，也不是在统计你自己的备份。在这个例子的备份中，8 月 31 日、7 月 31 日、6 月 30 日和 2025 年 12 月 31 日会被去掉。**仍然保存**会应用规则，下一次清理就会把它们从该位置永久删除。

要让这个位置上的容器比其他分区保留得更久，请点击**按分区划分的规则**下的**更改规则**，选择**容器**，并在**容器的规则**里设置**自定义值**，例如 14 天、8 周、12 个月和 2 年。其他分区继续遵循位置的卡片，**恢复为目标的设置**会让容器回来。

### 登录凭据 {#sign-ins}

登录凭据是 BombVault 用于 S3 服务或 rest-server 的密钥或密码。登录凭据是一个列表，也就是**设置、目标**下的**凭据**卡片，每一行说明哪些存储位置使用它（**使用者**）。

- **添加位置时保存。** 添加目标会把你输入的密钥保存为一个凭据。同一服务的下一个位置可以在**已保存的凭据**下选它，而不用**新密钥**，之后对它的更改会应用到使用它的每个位置。
- **默认项。** 星标标出默认凭据。在没有选择凭据的地方使用它，例如手动输入的地址，或全新安装上的恢复。拉取源不会借用它。**设为默认**会把星标交给另一个。
- **编辑和测试。** 在这里或在位置的**凭据**卡片里，**编辑**会为这个凭据打开同一个窗口。**测试**会用你输入的内容登录每个使用它的位置，在保存任何东西之前。**保存**会存储它。
- **移除。** 只有在没有存储位置、拉取源或接收的仓库使用它，也没有旧备份需要它时，凭据才能被移除，而默认项只能最后一个移除。如果专属文件夹从一个用它登录的地方搬走，并把旧备份留在了那里，这些旧备份就需要它。BombVault 随后会说明是哪个地方。
- **更改位置的连接**绝不会改写其他位置共用的凭据。位置会得到自己的凭据，窗口事先会说明它的凭据是共用的。要在所有地方更改共用的那个，请在**凭据**卡片里编辑它。

![凭据卡片：每个已保存的凭据，以及使用它的内容，星标在默认项上。](assets/screenshots/storage/signins-dark.png#only-dark)
![凭据卡片：每个已保存的凭据，以及使用它的内容，星标在默认项上。](assets/screenshots/storage/signins-light.png#only-light)

这台服务器上的文件夹不需要凭据。SMB、WebDAV、SFTP、Storage Box 和云盘把它们的凭据放在 rclone 配置里，位置的 **rclone.conf** 卡片会显示它，所以它们不会出现在这个列表里。

### SMB、WebDAV 和其他 rclone 远端 {#smb-webdav}

Windows 或 Samba 共享，以及 WebDAV 服务器（Nextcloud、ownCloud、SharePoint 或其他任何一个），是**添加目标**里 **NAS 或服务器**下的服务商磁贴。填写主机和共享（SMB），或地址和服务器类型（WebDAV）、用户和密码，BombVault 会为你写好 rclone 的段。rclone 会在存储之前混淆密码。

对于没有磁贴涵盖的服务，**自定义 rclone 配置**下的 **Rclone** 磁贴接受从 rclone.conf 粘贴的远端。它们会加到 BombVault 已有的远端上，绝不会取代它们，并且加密保存。要把某个分区备份到其中一个，请把 `rclone:<remote>:<folder>` 填为该分区的异地仓库，例如 `rclone:nas:backups/bombvault`。共享或存储桶是第一个路径段，不是名称的一部分。

这比在 Unraid 上挂载共享更好：restic 建议不要把仓库放在已挂载的 CIFS 共享上，而这里什么都不用挂载。NFS 没有磁贴，因为 restic 和 rclone 都没有 NFS 后端。对于 NFS，请在主机上挂载导出，并把它当作本地文件夹使用。

### 移动与移除 {#move-remove}

- **移动**会把一个分区的副本连同它的整个历史搬到另一个存储位置。一切都留在旧的地方。BombVault 不会在那里删除任何东西。移动在后台运行，可能需要很久：本地磁盘之间每 100 GB 约 9 分钟，慢速链路上则要几个小时。运行期间概览会显示它。
- **移除目标**提供两种方式。**移除目标，保留备份**会停止往那里写入，并把备份留在原处。你以后可以在**恢复、从旧的备份文件夹**下读取它们。**移除目标并删除其中的备份**会先读取那里存了什么并列出来：哪些备份会被删除，其中哪些在别处都没有，以及哪些仓库会保留，原因是防删除保护拒绝、条目仍在直接备份到它们、另一个位置或分区在那里保存着它们的副本，或者无法读取它们。会失去唯一备份的条目会单独列出，并会被保留，除非你开启**同时删除这些**。你通过输入位置的名称来确认，删除在后台运行。
- 这适用于每种存储位置：多个分区使用的位置、为一个分区设置的目标、你设置的仓库，以及分区写入自己备份的文件夹。备份到被移除仓库的条目会重新跟随它们的分区，指向那里的分区默认设置也一样。分区的文件夹不能直接消失，因为每个分区都需要一个。窗口会询问分区搬到哪个文件夹，每个分区在其下保留自己的文件夹名。
- 删除存储位置上的备份不需要登录密码。设置了密码时，需要在实例本身登录。

### 示例：在 Backblaze B2 上做异地副本 {#example-s3}

容器和自我备份也应该存放在 Backblaze B2，这样服务器坏了不会把它们一起带走。同样的步骤适用于 Wasabi、Hetzner Object Storage 和大多数其他 S3 服务。

1. **在 B2 里，** 在离你较近的区域创建一个私有存储桶，例如 `tower-backups`。在 **Application Keys** 下创建一把有读写权限、仅限该存储桶的密钥，并记下它的密钥 ID 和应用密钥。B2 只显示一次应用密钥。把存储桶的生命周期设为只保留最后一个版本，否则 B2 会把清理掉的数据保留为隐藏版本并向你收费。
2. **服务商。** 在 BombVault 里打开**目标**，点击**添加目标**，在 **S3 服务**下选择 **Backblaze B2**。
3. **登录。** 把密钥 ID 填入**访问密钥 ID**，应用密钥填入**秘密访问密钥**。在**端点**下填写存储桶的端点，例如 `s3.eu-central-003.backblazeb2.com`，BombVault 会据此读取区域。把 `tower-backups` 填入**桶**，因为这把密钥只能打开一个存储桶。
4. **测试连接。** 它应该显示**已连接**并列出存储桶的文件夹。点击**新建文件夹**，命名为 `bombvault`。BombVault 会在其中为每个分区放一个文件夹，例如 `bombvault/containers`。
5. **保护。** 窗口会说明 B2 可以通过对象锁保留旧版本，而 BombVault 无法检查这一点。除非存储桶确实会拒绝删除，否则请保持**防删除保护（append-only）**关闭，这样 BombVault 可以按位置的保留规则清理。
6. **针对哪些分区。** 勾选**容器**和**自我备份**。自我备份带有你的设置，所以新安装可以把它们带回来。窗口会说明有多少条目，以及在已知时，第一次复制会带上多少历史。
7. 点击**保存目标**。

第一次复制在下一次备份之后运行。要现在就开始，请打开**设置、目标**，点击**异地副本**里该分区那一行的**立即复制**。状态栏会显示**正在异地复制**。第一次复制带着整个历史，所以 200 GB 通过 100 Mbit/s 的上行线路大约需要四个半小时。之后的复制只发送新增的部分。

为了让你的线路保持空闲，请打开位置的页面，在**复制**卡片里设置**上传限制 (KiB/s)**，例如 `5120`，显示为约 5.0 MB/s（41.9 Mbit/s）。顺便看一下同一页面上的**保留多久**。

要确认它起了作用，请看概览上的**保护状态**，其中**异地**变为**副本是最新的**，再看容器的**备份**标签页，它的快照现在把 `tower-backups` 列为第二个位置。然后在**设置、恢复**下再次点击**下载恢复工具包**，因为工具包会列出新的位置及其登录凭据。

**Cloudflare R2 的做法相同，** 用对象令牌代替密钥。粘贴 R2 控制台显示的、带着存储桶的 S3 地址，BombVault 会填好服务器和存储桶。

### 示例：自己运行的 rest-server {#example-rest-server}

append-only 模式的 rest-server 会拒绝删除，所以即使有人接管了你的服务器，它上面的副本也依然存在。第二台机器就够了，放在朋友家里或车库里都行。配对的 BombVault 可以替你设置，参见[接收服务器](#receiving-server)。要在任何 Docker 主机上手动运行：

```sh
docker run -d --name rest-server --restart unless-stopped \
  -p 8000:8000 \
  -v /mnt/user/backups/rest-server:/data \
  -e OPTIONS="--append-only --private-repos" \
  restic/rest-server
docker exec -it rest-server create_user bombvault
```

最后一行会询问密码，并把用户写入数据文件夹里的 `.htpasswd` 文件。

1. 在 BombVault 里点击**添加目标**，在 **NAS 或服务器**下选择 **rest-server**。
2. 输入把用户作为其文件夹的地址，例如 `http://192.168.2.20:8000/bombvault`，以及**用户名**和**密码**。点击**测试连接**。
3. 在**保护**里开启**防删除保护（append-only）**。BombVault 此后绝不会在那里清理，而是留给对方去做。
4. 勾选分区并点击**保存目标**。
5. 第一次复制完成后，打开位置的页面并点击**立即测试防删除保护**。BombVault 会尝试删除一个测试对象。卡片应该显示**上次：删除被拒绝**，概览上的**防删除保护**变为**已检查**。如果显示**上次：删除未被拒绝**，说明缺少 `--append-only`。

因为这里不会清理这份副本，请在分区窗口里设置**增长预算（GB，0 = 关闭）**（用**异地副本**里它那一行的**编辑**打开），这样在磁盘写满之前你就会收到提醒。使用自签名证书时，请看上面关于 `certs` 的说明。

## 专属文件夹 {#own-folder}

每个分区都有一个专属文件夹：它的备份首先写入的仓库。复制到其他存储位置，都是从那里发出的。新安装会把专属文件夹放在这台服务器上的 `/mnt/user/bombvault` 之下，它们合起来构成**本地**存储位置。

专属文件夹也可以放在你已有的存储位置里，例如 NAS、rest-server 或 S3 存储桶。这样分区就直接备份到那里，中间没有本地副本，专属文件夹遵循那个位置的登录凭据、防删除保护和带宽限制。每次备份后，BombVault 会按那个位置的**保留多久**卡片清理它，而分区在**按分区划分的规则**下自己的值优先于卡片。位置会在它的**专属文件夹**卡片里列出这个分区，**按分区划分的目标**把这个位置显示为分区的家。

### 移动专属文件夹 {#move-own-folder}

1. 打开要存放专属文件夹的存储位置，选择**用作专属文件夹**，或在它的**专属文件夹**卡片里选择**添加部分**。要一次移动多个分区，请在本地位置的**连接**卡片里，选择**此处的专属文件夹**旁边的**移动专属文件夹**。
2. 在**分区**下选择分区，在**移动到**下选择位置。**其他位置**可以填这台主机上的文件夹，或手动输入的远程仓库地址，并从你已保存的凭据中选一个登录凭据。
3. 阅读**将会发生什么**。它会为每个分区说明新备份去哪里、已经在新位置的副本是否会成为专属文件夹，以及哪些备份会先被复制过去。
4. **复制已有的备份**默认开启。关闭后，旧备份留在原地，但条目不再列出它们。恢复页面上的**从旧的备份文件夹**仍然可以用该文件夹的地址读取它们，如果是远程文件夹，还要用它的登录信息。
5. 选择**切换**。当新位置的**保留多久**卡片保留的备份比分区现在的规则少时，BombVault 会先询问：**要少保留吗？** 在这里，**在按分区划分的规则中保留该分区的当前值**会把现在的值一起带过去，**仍然保存**会继续进行，**返回**则让一切保持原样。当备份需要先复制时，BombVault 会复制它们，然后切换专属文件夹。如果它们已经在那里，它会在切换之前检查它们。

移动之后，新备份会去往移动后的专属文件夹，即使是关闭了**本地**、直接备份到某个副本的分区也一样。已经在新位置的副本会成为专属文件夹，往那里的复制随之结束。如果那份副本保留某些备份的时间比分区的保留规则更长，分区会保留任一规则所保留的内容，所以其中没有一份会丢失。

当移动无法进行时，窗口会在**将会发生什么**下面的方框里说明原因。如果只是复制旧备份挡了路，关闭**复制已有的备份**就可以让专属文件夹不带它们移动。

分区始终需要一个专属文件夹。移除存放它的存储位置时，会询问分区要搬到哪个文件夹，参见[移动与移除](#move-remove)。新备份绕过的专属文件夹（因为分区直接备份到副本），在位置列出使用者的地方会标上**（关闭）**。

![移动专属文件夹的窗口，"将会发生什么"已为一个分区填好。](assets/screenshots/storage/move-own-folder-dark.png#only-dark)
![移动专属文件夹的窗口，"将会发生什么"已为一个分区填好。](assets/screenshots/storage/move-own-folder-light.png#only-light)

#### 示例：容器搬到 NAS {#example-own-folder}

缓存池快满了，而你有一个名为 `nas` 的存储位置，是第二台机器上的 SMB 共享。容器分区在这台服务器上的专属文件夹里有 61 份备份，并复制到 Backblaze B2。

1. 打开**目标**，然后是 `nas`，点击**用作专属文件夹**。
2. 在**分区**下勾选**容器**。
3. 阅读**将会发生什么**。它说明容器的新备份会去 `nas` 上的文件夹，本地的 61 份备份会先复制到那里，复制仍会继续发往 Backblaze B2，保护、带宽限制和增长警报都取自 `nas`。
4. 保持**复制已有的备份**开启，然后点击**切换**。

BombVault 在后台复制备份，然后切换专属文件夹。`nas` 页面会在**专属文件夹**下列出容器，跟随其分区的条目把 `nas` 显示为它的家，下一次备份就落在那里，发往 B2 的复制则从 `nas` 发出。从现在起，由 `nas` 的**保留多久**卡片来清理这个文件夹。这台服务器上的旧文件夹留在原处，BombVault 不会在那里删除任何东西。

### 手动输入远程地址 {#remote-primary-repositories}

本地位置的**连接**卡片仍然接受分区专属文件夹的远程地址：分区旁边的**更改**会打开一个带有**本地 / 远程**开关的窗口。**远程**接受 restic 地址，例如 `s3:...`、`rest:http://host:8000/repo`、`sftp:user@host:/repo` 或 `rclone:remote:bucket/path`，而**远程主仓库安全设置**会增加连接测试、上传和下载限制、带有与异地位置相同防篡改测试的 append-only 保护，以及增长预算警报。

这样的地址使用默认凭据登录。当它恰好是你已有的某个存储位置为该分区保留的文件夹时，它会自动跟随那个位置，包括该位置的卡片和它的**可用**开关，除非它的登录方式不同，或者它是 append-only 而那个位置不是。此前清理这个文件夹的规则，会作为该分区自己的规则留在**按分区划分的规则**下。当它位于该位置的另一个文件夹里时，该位置的页面会在**已在此目标下**下列出这个分区，接管它会让它使用该位置的登录凭据、存储类别和防删除保护。用**用作专属文件夹**把专属文件夹搬进存储位置更简单，因为窗口会在改动任何东西之前检查已有的备份。

## 按条目放置 {#placement}

条目设置标签页上的**计划和目标**卡片有一排按钮：**本地**，以及分区的每个异地存储位置各一个。点亮的按钮会获得条目的备份。

- **本地**点亮时，条目会写入**存放于**下显示的仓库，并复制到其他每个点亮的位置。把一个位置熄灭，它就不会再从这个条目得到新的东西。只有本地则不向任何地方复制，适合已经有第二份副本的数据，例如本身就在 NAS 上的共享。
- **本地**熄灭时，条目会直接写入第一个点亮位置的直接仓库，并从那里复制到其他点亮的位置。第一次时，会有一个对话框创建那个直接仓库。
- 总会留着一个按钮亮着，因为备份需要有地方去。要把条目排除在备份之外，请使用**不备份**。

BombVault 绝不会在仓库之间移动备份。跟随其分区的条目会随分区默认设置的更改而变：它的下一次备份落在新的位置，已有的备份留在原处。在条目本身上选择的位置，从它的第一次备份起就固定了。设置标签页上的**仓库**卡片会写明它。复制则可以随时更改。不再从条目得到东西的位置保留它已有的副本，并在该分区下一次异地运行时，按它自己的保留规则修剪。append-only 的位置无法从这里删除。

条目离开的位置会保留它的备份。在条目的**备份**标签页和**恢复**里，它显示为**仅旧备份**，恢复仍然可以从那里读取，那里的清理也不会动这些备份。

**遵循默认**会让有自己选择的条目回到它的分区。它会先询问，说明之后新备份去哪里，并点出每个位置会停止得到什么，以及下一次运行会上传什么。

在这一排按钮下面，卡片说明条目去哪里，以及实际上有什么：有多少个站点保存了它、每个位置上次是什么时候看到的，以及是否满足 3-2-1。站点是拥有原始数据的服务器、每个异地位置，以及每个标有**场所之外**的仓库。BombVault 检查副本和站点，不检查 3-2-1 中"两种介质"的部分。

### 按分区的默认设置 {#placement-defaults}

目标页面上的**按分区划分的目标**卡片，把每个分区的默认设置画成一张 3-2-1 流程图。从分区到存储位置的每一条线都是一个开关，包括**本地**，每个分区都是如此，闪存、ZFS 数据集和自我备份也一样。点击一条线或一个点会立即切换它，虚线表示关闭。只有关闭某个分区的**本地**时才会先询问，使用与默认卡片相同的对话框，因为这样分区就会直接备份到副本。**取消**会让一切保持原样。**图 / 开关**以按钮行的形式显示同样的内容。开关决定新备份去哪里。没有自己选择的条目，以及 Compose 堆栈的项目文件夹，会立即跟随，所以它们的下一次备份去往新的位置。已经存储的备份留在原处，仍然可以从那里恢复。闪存、ZFS 数据集和自我备份备份到它们的本地文件夹，并从那份备份复制到异地。它们到**本地**的线也可以关闭。这样它们的备份会直接去往它们的异地位置，而带副本、没有任何位置的 ZFS 条目只发送它的副本。

**本地**关闭、只开启异地位置时，分区直接备份到它们，BombVault 自己在那里选择仓库。容器、虚拟机和文件夹集会去往第一个开启的位置的直接仓库（见下文），并从那里复制到其他位置。闪存、ZFS 数据集和自我备份把每份备份写入每个开启的位置，每个位置按自己的保留规则保留它们。

每一条线都关闭的分区会显示**未备份**。它的条目得不到备份，并算作未受保护。

在自己页面上选择了存储位置的条目会保留它们。流程图会说明一个分区里有多少这样的条目，例如**2 个条目不同**，并带你过去：只有一个时带到条目的设置标签页，有多个时带到一个列出各自备份去向的列表。那里的**遵循默认**会让条目回来。

新的异地位置会接收每个没有设为本地的条目。添加它的窗口会说明有多少条目，以及在已知时有多少历史。

### 直接仓库 {#direct-repositories}

直接仓库是条目直接备份到异地位置的地方。BombVault 把它放在位置的文件夹旁边，名称后加 `-direct`，或者当位置位于它的存储桶、远端或 rest-server 用户的根部时，放在其内按分区命名的文件夹里，例如 `containers-direct`。在目标页面的流程图里，它会不经询问就创建。为单个条目关闭本地，使得一个没有直接仓库的位置成为它的家时，会打开一个对话框，里面有建议的位置，例如 `s3:https://s3.eu-central-003.backblazeb2.com/bucket/containers-direct`，以及一个什么都不创建的连接测试。**创建并使用**会创建仓库并让条目指向它。直接仓库没有自己的设置。它遵循其位置的开关、登录凭据、存储类别、限制、append-only 设置和保留规则，并随之变化。位置的页面在**直接备份到这里**下列出它，带有直接备份到它的每个分区以及有多少条目。不再有任何东西备份到的仓库会在那里这样说明，并且可以被移除，它所在位置的备份会保留。当位置的新密钥无法打开它时，直接仓库会保留它已有的密钥，保存时会这样说明。直接仓库上的条目会从那里复制到其他点亮的位置，绝不会复制到该仓库所属的位置。它的快照带有标签 `bv:direct`，每一轮其他的保留处理都会保留它们，所以与位置断开了链接的直接仓库绝不会按本地规则老化。B2 通过它的 S3 端点访问，把密钥 ID 和应用密钥作为 S3 密钥输入。仅限于位置自己文件夹的密钥无法访问它旁边的文件夹，所以请把密钥限制在上一级文件夹。

### 场所之外 {#off-the-premises}

存储位置或仓库可以标记为**场所之外**。远程的一开始就带着这个标记。对同一栋楼里的 rest-server，请把它关掉。这个标记只用来在卡片上统计站点和 3-2-1，不改变任何复制。

ZFS 副本是场所之外的一份拷贝，但不是带历史的备份。它只保留你设置的快照，旧版本和单个文件仍然来自备份。它通过 SSH 从一台 ZFS 服务器直接发往另一台，发往 ZFS 服务器，或配对实例的接收端点。配对的组只负责传递请求。参见[副本](zfs-datasets.md#replica)。

### 重建之后 {#after-a-rebuild}

复制的选择保存在 BombVault 自己的设置里。通过**发现备份**或没有恢复设置的应急向导重建之后，它们就没有了，把一切都复制出去，会把你排除的条目再次发往 B2。如果一个从未从这个数据库做过异地复制的分区，在某个存储位置找到了自己的备份，或在它的专属文件夹里找到了更旧的备份，情况也一样，例如在使用同一个 `APP_KEY` 的早先安装的备份之上添加了一个位置之后。这时该分区的异地副本会等待你的决定。

概览上的**需要处理**，以及该分区复制到的每个存储位置的页面，都会询问这些备份是不是此服务器自己的。**接收为此服务器自己的备份**会确认该分区的默认设置，它的复制从下一轮起再次运行。**先检查规则**会带你到**按分区划分的目标**里该分区的那一行，在那里你能看到每个条目去往哪里，并可以在条目的页面上重新设置丢失的规则。在你点击**接收为此服务器自己的备份**之前，复制会一直在那里等待。这个按钮会先显示下一次运行要复制什么，以及没有条目的备份中的名称，你可以把它们排除。每个等待中的条目的最新备份会在它的运行记录里说明这一点，并附上通往这个决定的链接，开启通知时还会发出通知。导入设置文件会带回规则和默认设置，但不会替你做决定。

## 防删除保护（append-only） {#delete-protection-append-only}

为异地存储位置开启防删除保护，这样勒索软件或被攻破的主机就无法删除或改写你的备份。对方（以 `--append-only` 模式运行的 `restic/rest-server`）**强制执行**它。BombVault 只**验证**它，绝不会仅凭配置声明就显示绿色。这台服务器上的文件夹无法拒绝删除，因为控制 BombVault 的人也控制这个文件夹，所以本地位置不提供这个开关。

这个开关属于存储位置：复制到那里的分区从位置取得它，所以请在**目标**下位置的页面上开启它。计划的**检查删除保护**只在有分区复制到开启了该开关的位置时才运行。对方必须用 `--append-only` 启动。使用 `restic/rest-server` 镜像时，在 TrueNAS 上和在任何其他 Docker 主机上一样，这要写进 `OPTIONS` 变量。

有些地方根本无法拒绝删除，例如 OneDrive 这样的云盘。如果你有意把副本放在那里，请在位置的页面上开启**在没有防删除保护的情况下接受**。这样，对于只复制到已接受位置的分区，概览会把缺少的防删除保护显示为已接受的风险：灰色圆环而不是琥珀色圆点，分区的颜色由它的其他检查决定。其他一切都不变：那里的备份仍然可以被删除，BombVault 仍然按位置的保留规则清理它们，一旦开启了防删除保护，这个开关就会消失。搬到另一个位置的副本会失去这种接受。开启防删除保护也会清除它。

通往 append-only 副本最快的途径，是带有[接收服务器](#receiving-server)的配对 BombVault：它会替你以 append-only 模式运行 rest-server。

在[共享仓库](#shared-repository)里，这一点适用于成员，但不适用于保存仓库的那台服务器。那台服务器直接访问文件夹，并在那里遗忘和清理备份。

!!! note "在 `/locks/` 下成功删除是预期之内的"
    append-only 并不意味着永远不能删除任何东西。restic 必须获取和释放它自己的锁，所以 `/locks/` 在设计上保持可写、可删除。快照以及它们背后的数据（也就是勒索软件会去攻击的东西）无法被删除。如果你自己探测对方，在 `/locks/` 下成功的删除是正确的行为，不是保护的漏洞。

!!! warning "append-only 仓库绝不会在这台机器上被清理"
    append-only 位置绝不会从这里清理旧快照。清理是对方的工作。请为它设置**增长预算警报**，这样在仓库大小失控之前你会得到提醒。

## 防篡改测试 {#tamper-test}

BombVault 会定期通过实际尝试对异地仓库发起删除来证明 append-only 的保证，目标是一个不存在的对象。位置页面上的**立即测试防删除保护**可以按需运行它，**设置、验证、自动检查**下的**检查删除保护**则按计划运行它。

关闭**检查删除保护**不会掩盖缺口。从未测试过的、有防删除保护的位置会显示"未证明，它的检查已关闭"，而没有防删除保护的位置无论如何都显示"无"。

已关闭的副本不会被测试，位置会这样说明。连接测试仍然会运行，因为它只读取，所以可以在开启副本之前先检查它。

- **被拒绝**表示受保护。
- **被接受**表示未受保护。
- **无结论**的结果（服务器无法访问、认证错误）绝不会翻转已存储的结论。

真正的从受保护变为未受保护，只会触发一次警报。

## DR 演练 {#dr-drills}

BombVault 提供两个层次的证明，表明你的备份确实可以恢复，而不只是存在。

- **恢复验证演练（本地）。** BombVault 定期运行 `restic check --read-data-subset`（有边界，绝不会是占满磁盘的完整恢复）。频率在**设置、验证、自动检查**下，同一磁贴上的**检查备份**卡片显示结果。
- **测试恢复（异地）。** BombVault 把一个真实目标从异地仓库恢复到一个封闭的沙盒中，逐文件、逐字节地验证，然后清理。这证明你可以从异地恢复，而不只是证明仓库有应答。

概览上的**保护状态**卡片会按分区把它汇总为四项检查：这台服务器上最新的备份、一份异地副本、那里的防删除保护，以及从那里做的测试恢复。点击一个分区会显示详情，卡片只在事实经过验证时才变绿。你在没有防删除保护的情况下接受的位置，在那里算作已接受的风险，而不是警告。

## 配对实例 {#pairing}

多个 BombVault 作为一个组一起工作：它们互相显示保护状态，互相承担角色，也可以互相保管密钥。实例用十二个单词加入组。

![配对页面和它的三张步骤卡片。](assets/screenshots/offsite/pairing-dark.png#only-dark)
![配对页面和它的三张步骤卡片。](assets/screenshots/offsite/pairing-light.png#only-light)

在第一个实例上打开**设置、配对**并点击**生成口令**。三张步骤卡片会展示流程。十二个单词会出现在一个带**复制**按钮的窗口里。在其他每个实例上打开同一个地方，点击**输入口令**，粘贴或输入它们，或者在那个窗口里点击**粘贴**。输入时，不在单词表里的词会带着它的位置被点出来，最后一个词带有校验和，所以输错或调换的词会在配对之前就被发现。只在一个实例上生成口令：两个都生成口令的实例会形成两个独立的组。如果一分钟内没有人出现，页面提供两个办法：再次显示单词，到另一边输入，或者输入另一个实例的单词，一步加入它的组。没有登录密码也可以配对，但请设置一个：没有的话，任何能打开网页界面的人都能读到这些单词，并通过组请求角色，而这些角色会交出组内实例的 restic 密码。在设置密码之前，配对卡片会这样提示。有密码时，再次显示口令需要输入密码。**退出组**会让一个实例再次离开。配对页面上的**实例**卡片列出组的成员。谁为谁做什么的图在实例页面上。

光有这些单词，谁也进不来。新的实例或手机会在**实例**卡片里等待，直到你在一个已经在组里的实例上点击**批准**，你的决定会传到所有能联系上的实例。把旁边显示的密钥和新实例在它自己的配对页面上显示的密钥比对一下。**拒绝**会把它永远挡在外面。两个新实例配对时，每一个都会把对方列为等待中，所以要在两边都批准。在这之前就已配对的成员保持批准状态。不过仍然要把这些单词当作密码对待：谁拿到它们，谁就能申请加入。

**成员如何互相找到。** 每个实例在你登录的那一刻，从你的浏览器得知自己在网络上的地址。在同一网络上，成员通过多播宣告该地址并直接通信，而在多播无法穿过容器网络的地方（例如 Docker 默认的 bridge），实例会改用只有组成员才能应答的签名调用，在自己的子网里搜索其他成员，所以不用中继，配对仍然在几秒钟内完成。配对始终通过十二个单词完成，也没有用于填写地址的输入框。不同网络上的实例通过中继，在同一页面上**中继**卡片里四选一的一行中选择。每种形式都配有一幅图：

- **项目中继**（默认）：`parleyport.halleluja.design`，KnightLoader 也使用的中继。无需设置。
- **自建中继**：来自 Unraid Community Apps 的 [**ParleyPort**](https://github.com/junkerderprovinz/parleyport) 容器（也在**设置、应用**下）。在每个要使用它的实例上输入它的地址。
- **BombVault 实例**：你已经可以从外部访问的某个实例，开启**作为中继运行**。这个实例随后在它自己地址的 `/relay/connect` 应答，位于它已有的反向代理和证书之后，并且只放行你的组。在每个要使用它的实例上输入它的地址。
- **不用中继**：成员在同一网络上自动找到彼此，别处则不会。

**中继能看到什么。** 四种形式旁边同名的按钮会为你选择的形式显示这一点。成员之间的每次调用都用 AES-256-GCM 封存，密钥由十二个单词派生，而这个密钥绝不会离开你的实例。中继只知道一个对连接分组的哈希、一条消息是发给哪个实例的、有多大以及何时经过。本地网络上的直接调用以同样的方式封存，并且也有签名，所以一切都不依赖实例提供的自签名证书。交出东西的调用（角色回答、restic 密码、接收端登录、密钥托管），还会用发送它们的成员自己的密钥签名，这把密钥在第一次见到时被固定。参见[安全模型](configuration.md#security-model)。

**什么会在组里传递。** 实例页面上的保护状态、立即检查某个分区的请求、角色请求及其回答、存储提议，以及在角色被允许之后接收端或拉取端所需要的东西：另一个实例的仓库位置和它的 restic 密码。备份数据从不经过这里，它仍然直接发往 restic 后端。APP_KEY 也不会：restic 密码只能打开那个实例的仓库，而不能打开它存储的密钥、会话或取回码。

**配对之前的条目。** 用舰队令牌添加的实例，以及用另一个实例的 APP_KEY 设置的接收仓库和拉取源，在更新后会保留，并标记为**重新配对**。它们继续工作：BombVault 在第一次启动时，会把每个存储的 APP_KEY 替换为由它派生的 restic 密码。把两个实例配对，然后编辑条目并选择它的实例。在此之前，这样的条目会放在实例页面上的**无实例**卡片里。

唯一仍然需要手动输入 APP_KEY 的地方是[从旧的备份文件夹](#restore-from-another-bombvault-repo)，适用于另一个实例已经没了、无法在组里应答的情况。

## 堡垒 {#fortress}

堡垒用一句十二个单词的口令，把 BombVault 和同一家族的其他应用聚在一起，例如 ShipLog、TowerTorch、FireSquire 和 TollRoll。任何已经在堡垒里的应用都能把口令显示给你。打开**设置、配对**，在**堡垒**下输入这些单词，BombVault 就加入了。和它配对的实例和手机会一起跟过来，不需要重新配对，暂时不在的设备回来后也会跟上。旧的配对会一直开放，直到所有设备都跟过来，最长 30 天。之后仍然缺席的设备会在配对页面和应用里列出名字，这样你可以在它上面输入堡垒口令，或者把它移除。

- **服务器名称**：其他应用在这台服务器上找到 BombVault 所用的名字。留空时就是实例的名称。
- **许可**：一个应用在另一个应用那里能做的每件事都有自己的开关，例如查看上次备份何时成功、请求备份一个容器或浏览备份。它们一开始全部打开。
- **显示口令**会在你输入密码后，把单词显示在二维码旁边。**更改**会给堡垒换一句新口令，它会传到所有能联系上的应用和实例。旧口令在 30 天内仍然有效，配对页面会列出这次更改没有送达的设备。**退出**会把 BombVault 移出堡垒。

**其他应用会做什么。** ShipLog 在更新一个容器之前会请求为它做一次备份，而 BombVault 会把 ShipLog 所管容器的更新交给 ShipLog，所以这些容器的**备份成功后更新**开关保持关闭。TowerTorch 在维护运行之前请求备份，FireSquire 会检查闪存上次备份是什么时候。另一个备份正在运行时，请求会等待。TollRoll 在 Unraid 仪表盘上的磁贴里显示 BombVault。其他应用通过 `GET /api/fortress/v1/status` 和 `GET /api/fortress/v1/log` 读取 BombVault 的状态，API 令牌或已登录的浏览器也可以读取。

**应用自己的备份。** 在 BombVault 备份一个能给自己做备份的应用的容器之前，它会先取来这个应用自己的备份，保存在该容器的仓库里，但前提是这个仓库已加密。这份备份会出现在容器的备份列表里，带有应用的名字和下载按钮，随容器的备份一起老化，和它们一起送到异地，也和它们一起删除。打开**把备份还给应用**后，**还给**会把它重新交给应用，替换应用现在持有的内容。这个开关默认关闭，直到你打开它。

## 实例和角色 {#roles}

**实例**页面（一个可以固定到侧边栏的设置磁贴）把组显示为一张谁为谁做什么的网，这个实例一张卡片，其他每个成员、Android 手机和 ZFS 服务器各一张卡片。右下角的**配对**通往配对页面。哪些部分开启，在**设置、实例、多台服务器**下设置：**实例**、**接收端**和**拉取**。

![实例页面：把组画成一张网，每个实例一张带角色磁贴的卡片，其中一个是不活跃的。](assets/screenshots/offsite/instances-dark.png#only-dark)
![实例页面：把组画成一张网，每个实例一张带角色磁贴的卡片，其中一个是不活跃的。](assets/screenshots/offsite/instances-light.png#only-light)

每张卡片以磁贴的形式显示成员的保护状态和它的角色。角色是一个实例为另一个实例做的事：

- **接收端**把这台服务器的异地副本保存在 append-only 模式的 rest-server 里。这台服务器在每次备份之后发送，即使有人接管了它，也无法在那里删除任何东西。
- **拉取端**按它自己的计划拉取这台服务器的备份。这台服务器不必为此处于唤醒状态。进行拉取的实例需要先开启**拉取**，才能允许这个请求。
- **ZFS 服务器**接收这台服务器的 ZFS 副本。每个 ZFS 条目在它的设置里的**副本**下选择它。
- **密钥保管端**保管这台服务器的恢复工具包的一份封存副本。参见[密钥保管端](#key-keeper)。

开启角色会发送一个请求，在另一个实例上的人点击**允许**之前，什么都不会开始。请求会在那个实例的卡片上显示为一个徽章，它的**详情**里列出它，带有**允许**和**拒绝**。已允许的角色可以随时在那里撤销。网里的虚线是仍在等待的角色。BombVault 9.x 上的实例无法应答请求，所以角色一开启在那里就生效，而来自 9.x 实例的请求则在这里等待**允许**。

卡片上的**详情**会打开其余内容：该成员的接收仓库和拉取源、存储提议、监控、**移除**和**忘记密钥**。

卡片下方，有接收服务器的机器上的**共享仓库**卡片，以及成员上的**加入的共享仓库**卡片，都属于[共享仓库](#shared-repository)。

成员可以通过组向另一个成员提供自己的异地存储。另一位管理员在该成员的**详情**里看到提议，并接受或拒绝它。接受会创建一个已保存的凭据和一个普通的存储位置，经过与你手动输入的位置相同的检查。因为提议里给出的配置方案是一个 append-only 的 rest-server，这个位置创建时就开启了防删除保护，所以**保留多久**在那里不适用。每个提议都有自己的登录信息和文件夹，所以再次提供某个分区，无论给同一个成员还是另一个成员，都不会影响第一个伙伴的副本：在 `.htpasswd` 里添加新的一行，并让服务器继续运行。通过这种方式传递的只有连接信息，绝不是备份数据。**立即检查**会请求成员验证某个分区的仓库。页面上没有任何东西可以在另一台机器上启动备份、恢复或删除任何东西。

已关机的实例和应用已关闭的手机，会把它们的卡片保留为灰色的**不活跃**，并写明最后一次看到它们的时间，在网里显示为暗淡，直到你**移除**它们。这台服务器刚启动之后，这样的卡片会显示**检查中**，直到组恢复。无论开启了哪些部分，这样的卡片上都可以**移除**，它还会结束该成员未完成的请求、闲置的 ZFS 接收槽和等待中的密钥请求。配对页面上的**实例**卡片也把这些成员列为**不活跃**。

## 接收端和拉取端 {#receiver}

在**接收**另一个 BombVault 的 append-only 副本的机器上，接收的仓库让你在接收硬件上获得独立的只读监控，这样对方那一端悄悄发生的故障不会被忽略。在**设置、实例**下开启**接收端**，然后在实例页面上打开发送实例的**详情**，添加接收的仓库（只读，用发送实例的 restic 密码打开，这个密码通过[配对的组](#pairing)得到）。你会得到：

- **按来源的清单**，让你能确切地看到哪些容器、虚拟机和文件夹集已经到达。发送实例在有[自己的主机](#backup-host)之前做的备份，也算在同一个来源里。
- 每个来源的**最后接收**，让你知道每个有多新。
- 在接收硬件上运行的**独立 `restic check`**，这样完整性是在数据真正所在的地方验证的，而不只是在发送端。
- **失联开关：** 当某个来源在你设置的时间窗口内停止发送时发出警报。它每天检查一次，在 09:15。无论检查计划怎么设，仓库完全无法读取时，以及添加之后过了整整一个时间窗口仍什么都没到达时，你也会收到一次警报。在发送方第一次复制之前添加的仓库，在那之前都没问题。
- **完整性警报：** 接收端的检查失败时发出警报。无法打开仓库的检查说明不了完整性，所以它不留下结论，并在第二天同一时间再试一次。

位于另一台服务器上的仓库需要那台服务器的登录信息：把它保存为[凭据](#sign-ins)，然后在对话框的**凭据**下选择它。

接收端是严格只读的。它绝不会写入接收的仓库，所以绝不会破坏发送端所依赖的 append-only 保证。

拉取端则反过来：开启**拉取**之后，实例按自己的计划读取另一个成员的备份，放进为每个来源准备的自己的仓库，所以它们绝不会算作这台机器自己的备份。它的来源也在该成员的详情里：仓库位置、它保存哪种备份，以及多久拉取一次。restic 密码通过组传来，绝不是 APP_KEY，对方无需再设置任何东西，也不必处于运行状态。来源只会被读取，各方保留自己的登录凭据。拉取在计划规定的日期和时间运行，新的来源也会等到那个时间。**立即拉取**不用等。因为这台机器关机而错过的拉取，会在它恢复后运行。失败的拉取会在第二天同一时间再试，按周的计划也一样，失败的拉取会显示在活动日志里，并发送一次警报，直到拉取再次成功。`rclone:` 来源会被拒绝，因为 rclone 会用这个实例的远端去访问它。

拉取的副本只会增长。BombVault 只往里面添加，既不清理也不检查它，所以来源早已丢弃的内容会一直留在这里，直到你删除这个文件夹，存储位置页面也不把它计算在内。它位于分区专属文件夹里的 `pulled/<source id>`，当那个文件夹搬走时，副本留在原处，之后的拉取会在那里继续，而不是把一切重新复制一遍。如果你删除它，下一次拉取会在分区那时的专属文件夹里从头开始。

### 接收服务器 {#receiving-server}

接收的机器也可以运行其他实例复制到的 rest-server。它在你第一次允许要求它的**接收端**请求时设置：窗口说明需要一个接收服务器，并询问共享上的一个文件夹（用**新建文件夹**创建一个）和端口（除非另一个容器占用，否则是 8000）。然后 BombVault 会：

1. 如果已经存在名为 `rest-server` 的容器，或另一个容器占用了端口，就拒绝，
2. 拉取 `restic/rest-server`，并通过 Docker 套接字以 append-only 模式启动它，使用私有仓库和文件夹里的登录文件，
3. 把它的 Unraid 模板写到闪存上，这样容器在 Docker 标签页里仍然可以编辑，或者在闪存无法访问时把模板作为下载提供，
4. 对它运行防篡改测试，并显示它是否拒绝删除。

你的组里的实例随后会在服务商里的**来自你的组**下找到这台服务器，以接收的机器命名，**接收端**角色把它作为安全的选择提供。每个实例在第一次使用这台服务器时得到自己的登录，并且只写入那里属于自己的文件夹。在**设置、实例**下开启**接收端**后，这个实例的卡片上的**接收服务器**会再次打开这台服务器。它的窗口在**持有登录信息的伙伴**下列出登录，**撤销登录信息**会收回其中一个。该实例已经复制的内容会留在文件夹里。设置时还会创建一个**组外登录信息**，窗口会显示一次它的密码。

只通过中继到达接收机器的实例无法使用这台服务器，因为中继不传递备份。请先在配对页面上添加接收机器的地址。当 BombVault 运行在它自己的 IP 地址上（例如在 br0 上）时，请填写**给伙伴使用的地址**，因为服务器监听的是主机的地址。

接收的机器还可以为组保存一个[共享仓库](#shared-repository)。

## 共享仓库 {#shared-repository}

组里的几台服务器可以一起复制到同一个 restic 仓库。它们共有的数据，比如同样的文件夹集或同样的 appdata，在那里只存一份，所以和每台服务器各用一个仓库相比，它们加起来需要的空间更少。

组里的一台服务器保存这个仓库，本页称它为保存方。只有保存方会在那里遗忘旧备份并进行清理。其他服务器是成员：它们通过第二个以 append-only 模式运行的 rest-server 访问仓库，只能往里添加。每台服务器都写在[自己的主机](#backup-host)下，所以即使两台服务器有同名的条目，备份也不会混在一起。

需要的条件：

- 一个[配对的组](#pairing)，
- 保存方和每个成员都开启了**加密备份**，因为每台服务器都会得到自己的 restic 密钥，
- 保存方上有一台成员能访问到的[接收服务器](#receiving-server)。如果 BombVault 运行在它自己的 IP 地址上，请先在接收服务器的窗口里填写**给伙伴使用的地址**。

一台服务器最多保存一个共享仓库。

### 设置 {#shared-set-up}

接收服务器运行后，这台机器的**实例**页面会在实例下方显示一张**共享仓库**卡片。点击**设置共享仓库**，在空间充足的共享上选一个**共享仓库文件夹**，除非另一个容器占用，否则**端口**保持 8001，然后点击**设置并启动**。BombVault 接着会：

1. 如果已经存在名为 `rest-server-shared` 的容器，或另一个容器占用了该端口，就拒绝，
2. 在其中的 `shared` 文件夹里用这台服务器的密码创建仓库，
3. 以 `rest-server-shared` 的名字启动 `restic/rest-server`，使用 append-only 模式，登录文件放在文件夹里，
4. 在 Unraid 上把它的模板写到闪存上，这样容器在 Docker 标签页里仍然可以编辑，
5. 对它运行防篡改测试。卡片上的**重新检查**会再运行一次。

卡片列出**成员**，每个成员附带它的密钥和最近一次备份，还有加入申请，以及每个成员的**移除**。

### 加入 {#shared-join}

在想要加入的服务器上，打开**添加目标**。在**来自你的组**下，保存方会再出现一次，显示为它的名字加上**上的共享仓库**。选中它会向保存方发出申请，申请会显示在保存方的**共享仓库**卡片上，带有**允许**和**拒绝**。

点击**允许**后，保存方通过组发出一个一次性密钥和第二个 rest-server 的登录信息。成员用它添加自己的 restic 密钥，随后保存方删除这个一次性密钥。一天内没有完成的成员会再次失去一次性密钥和登录信息，可以重新申请。如果保存方没能把答复送到成员那里，卡片上会出现**再通知一次**。

保存方会拒绝还没有写在自己主机下的服务器，也就是运行旧版本的服务器，以及另一个成员已经在用同一个主机写入的服务器。两台服务器共用一个 `APP_KEY` 时，它们的主机也相同。

成员加入后，**目标**下会出现一个名为 **Shared with** 加上保存方名字的位置，所有分区都处于关闭状态。在这个位置的页面上开启要复制到那里的分区。这个位置带有防删除保护，没有自己的保留规则，因为只有保存方会在那里遗忘。只有成员自己主机下的备份会进到那里，所以主机 `bombvault` 下较早的备份会留在原处。

保存方也可以把自己的备份复制进去：它卡片上的**也把这台服务器的备份复制进去**会在保存方上同样添加这个位置。对保存方来说，这份副本就在它自己的磁盘上，那里也没有任何东西阻止它删除，所以算不上异地副本。

### 谁来整理，什么时候 {#shared-upkeep}

只有保存方会遗忘和清理。它的设置在**接收服务器**窗口的**共享仓库**部分，这个窗口从实例页面上保存方自己的卡片打开：

- **整理时间窗口**设定清理什么时候运行，每天或每周。在你修改之前，它在每周日 03:00 开始，**窗口长度（小时）**为 6。
- **清理可留下的未用空间（%）**默认是 5。值越高，重新打包越少，清理完成得越快。
- **清理后读回的数据（%）**默认是 5。每次清理后，保存方都会检查仓库，并读回这一比例的数据。
- **保留多久**对每个分区沿用保存方的异地规则，**设置单独的规则**可以给共享仓库设一个自己的规则。每台服务器的备份各自老化。
- **立即整理**会先通知成员，然后马上遗忘、清理并检查。

在时间窗口之外，保存方每天遗忘一次，空间在下一次清理时回来。清理前，保存方会通知成员，在窗口关闭前，成员不会向仓库复制任何内容。仍在复制的成员最多有半小时来完成，否则清理会推迟到下一个窗口。落在窗口里的复制会等待，在活动日志和成员的卡片上显示为已推迟，下一轮会补上。

保存方拿不准的时候，会多保留一些。成员因为[异常](anomalies.md)而保留的条目会保留全部备份，说不清自己保留了什么的成员，这一次会保留全部备份，而组里没有任何服务器写入的主机下的备份永远不会被遗忘。窗口还会显示空间：仓库占用多少，各服务器分开存放需要多少，以及因此省下多少。这些数字在每次整理时更新。

### 成员看到什么 {#shared-members}

在成员上，实例页面有一张**加入的共享仓库**卡片，列出这台服务器复制进去或申请加入的每个共享仓库，以及申请的状态：**等待同意**、**正在加入**、**已加入**、**已被拒绝**、**已过期**或**不是成员**。对于已经加入的仓库，卡片会显示**清理方**、**下次整理**、列出其他成员的**共同成员**、**最近一次复制到这里**，以及仓库占用和节省的空间。

### 退出 {#shared-leave}

成员卡片上的**退出**会让服务器离开：保存方删除它的密钥和登录信息，它在那里的位置会被关闭。保存方卡片上的**移除**则从另一边把成员移出。无论哪种方式，服务器的备份都会留在仓库里，并按保存方的规则老化。在保存方上，它们列在**已退出的服务器**下，在**丢弃备份**里输入服务器的名字后，会遗忘它的全部备份。下一个整理时间窗口会把空间还回来。

### 其他服务器的备份 {#shared-restore}

每台服务器都能在条目的**备份**标签页里找到自己在共享仓库中的备份，和其他副本一样。其他成员的备份在恢复页面的[其他服务器](restore.md#other-servers)下。

### 应急之后 {#shared-emergency}

[恢复工具包](#recovery-kit)里有一章 **Shared repositories**。它列出每个共享仓库及其保存方、复制到那里的分区、其他成员及其主机，以及一条带有这台服务器主机的 `restic snapshots` 命令。保存方的工具包还写明了它的 rest-server 的端口、文件夹和登录信息。

在应急向导中，这个仓库会出现在位置之中，显示为保存方的名字加上**上的共享仓库**。接管了某个成员密钥的新安装会在同一个主机下写入，因为主机来自密钥。它会找回自己在共享仓库里的位置，并且在那里只列出和恢复自己的备份。

接管了保存方密钥的新安装会取代它保存这个仓库。它像以前一样让旧备份老化并进行整理，并在同一个文件夹上重新启动 rest-server。请把它重新和组配对，在**实例**下设置它的接收服务器，并在接收服务器的窗口里重新设定规则，因为规则不在工具包里。组能联系到成员后，新的保存方会自己通知它们。每个成员会先核实：它往仓库里添加一个一次性的密钥，只有位于仓库文件夹所在服务器上的一方才能删除它，等这个密钥消失后，成员就改跟新的保存方。如果新的保存方在另一个地址上应答，每个成员会在那里用自己的密钥和登录信息做这项核实，确认找到的是同一个仓库，然后才把自己的存储位置改到新地址。在此之前，它会继续复制到旧地址，它的卡片也会说明原因。这类核实留下的密钥，保存方会在下一次整理时删除。

如果旧的保存方仍在运行，它的卡片会说明现在由另一台服务器保存这个仓库。**收回**会让它重新成为保存方，用于工具包被误在第二台服务器上接管的情况。

### 限制 {#shared-limits}

- **每个密钥都能读取全部内容。** restic 仓库的所有密钥都打开同一个主密钥，所以每个成员都能读取其他成员的备份。容器和虚拟机的定义仍用每台服务器自己的密钥封存，所以另一台服务器的容器和虚拟机只能作为文件恢复。曾经有过访问权限的服务器可能已经读到了主密钥，所以移除它并不能把它永久挡在外面。只有新建仓库才能做到。
- **保存方可以删除。** 成员在那里什么都删除不了，但保存方直接访问文件夹，会遗忘并清理每个成员的备份。保存方上的一次失误或被入侵，会波及所有成员。
- **损坏会波及每台服务器。** 一个损坏的数据包，对所有用到它的服务器备份来说都会缺失，所以共享仓库不能代替第二份副本。
- **只在接收服务器上。** S3、SFTP 和其他位置无法限制成员只能添加，所以 BombVault 只在接收服务器上提供共享仓库。
- **只作为复制目标。** 分区自己的文件夹不能放在共享仓库里，因为每次清理都会拖住所有服务器的备份。
- **较早的历史留在原处。** 只有每台服务器自己主机下的备份会进去，其他仓库里的内容不会被搬过来。

## 示例：配对两台 Unraid 机器 {#worked-example-two-unraid-boxes-end-to-end}

这是上面各部分的一个完整设置，因为看过它们组装起来之后，自己组装会容易些。

两台机器：**TOWER** 运行容器并推送备份。**VAULT** 接收它们并强制执行 append-only。请换成你自己的名称、地址和共享路径。

**1. 把两台机器配对。** 在 TOWER 上打开**设置、配对**，点击**生成口令**，并在 VAULT 的**输入口令**下输入这十二个单词。请先在两台上都设置登录密码。

**2. 在 TOWER 上，请求 VAULT 作为接收端。** 在实例页面上，开启 VAULT 卡片上的**接收端**，选择分区，并把 **VAULT 的接收服务器**选为位置，然后发送请求。

**3. 在 VAULT 上，允许它。** VAULT 的实例页面会在 TOWER 的卡片上显示这个请求。点击**允许**。第一次时，VAULT 会询问它的接收服务器所用的文件夹，例如 `user/appdata/rest-server`，以 append-only 模式启动 rest-server，并对它运行防篡改测试。

**4. 回到 TOWER。** 从那时起，TOWER 在每次备份之后复制到 VAULT，新的存储位置会连同它的防删除保护一起出现在 TOWER 的目标页面上。

防篡改测试的回答：

| 结果 | 发生了什么 |
| --- | --- |
| **受保护** | VAULT 拒绝了删除。这是唯一通过的状态。 |
| **未受保护** | VAULT 接受了删除。缺少 `--append-only`，或它被移除了。 |
| **无结论** | 两者都不是。通常是 URL 不是 restic 自己使用的那个，或凭据变了。不记录任何东西，也不触发警报。 |

**5. 如果你愿意，观察到达的东西。** 在 VAULT 的**设置、实例**下开启**接收端**，打开 TOWER 的**详情**并添加接收的仓库：点击对话框列出的位置之一。VAULT 通过组得到 TOWER 的 restic 密码，而且因为这个位置就在 VAULT 自己的接收服务器上，它会直接读取那个文件夹。没有人输入密钥或登录信息。

**6. 让它成为双向的。** 在另一个方向重复这些步骤：VAULT 请求 TOWER 作为它的接收端。这样每台机器都为对方强制执行 append-only，谁也删不掉对方的备份。

手动运行的 rest-server 也可以：用**添加目标**把它添加为 rest-server，使用它的 `.htpasswd` 里的用户和密码，并开启防删除保护。请在它的选项里保留 `--append-only`。没有它，对方又变回了普通共享。

!!! warning "本地路径是容器内的路径"
    在 BombVault 要求这台服务器上的文件夹时，请输入相对于主机挂载的路径，例如 `user/appdata/rest-server/bombvault-containers`，而不是 `/mnt/user/appdata/...`。BombVault 在容器里运行，主机的 `/mnt` 挂载在别处。绝对的主机路径在容器里不存在。如果你粘贴了一个，BombVault 会告诉你应该改用的相对路径。

## 应急向导 {#emergency}

**应急向导**会找回已经消失或重新搭建的服务器。它从**恢复**页面的**紧急**下启动，也可以从新安装的欢迎页上的**从备份恢复**启动。它分四步：**访问**、**设置**、**选择**和**恢复**。

1. **访问。** 让 BombVault 看到旧备份的密钥，有三种方式：
    - **上传恢复工具包**：你在设置时下载的文件。里面有密钥和每个存储位置，BombVault 会据此填好其余部分。用 age 封存的工具包会询问它所封存对应的身份。它只使用一次，不会保存。
    - **通过组**：你的组里的某个实例把密钥作为托管副本保管。你需要组的十二个单词、你的取回码，以及那个实例上的一个人。参见[密钥保管端](#key-keeper)。
    - **输入密钥**：旧服务器的 `APP_KEY`，以及它的备份在哪里。

    BombVault 随后会在每个存储位置上尝试这个密钥，并为每一个说明它是可读取、未找到、被另一个密钥锁定、无法访问，还是仍然缺少登录凭据。此时还没有保存任何东西，密钥只在内存中保留有限的时间。**接管密钥**会让这台服务器从现在起用那个密钥写入备份。**撤销接管**会回到它自己的密钥，直到第一次备份运行为止。已经有自己备份的服务器会拒绝接管，并指向[从旧的备份文件夹](#restore-from-another-bombvault-repo)。**保存凭据**会保存工具包为远程存储位置携带的登录凭据，并在要替换这台服务器已有的登录凭据之前先询问。
2. **设置。** **恢复设置**会从最新的自我备份恢复 BombVault 自己的设置：存储位置、登录凭据、计划和规则。BombVault 会通过 Docker 套接字重启来应用它们，所以正在使用的设置数据库绝不会在句柄打开的情况下被覆盖，向导随后会自己继续。这台服务器的登录保持不变：你继续用现在使用的密码登录。旧服务器存储的、无法接管的密钥会被列出，这样你可以再次输入。恢复会结束所有会话并移除通行密钥，所以之后请重新设置它们。
3. **选择。** BombVault 会查看你的备份，并列出它找到的容器、虚拟机、文件夹集和 ZFS 数据集。所有地方都预先选中最新的快照。这台服务器上仍然有的东西一开始是关闭的，因为恢复会替换它。文件夹集在重建之后不再知道它们来自哪里，所以它们会放进你选择的文件夹。
4. **恢复。** 所有选中的东西一次性恢复，如果你想自己启动每个容器和虚拟机，可以让它们保持停止，这在彻底丢失之后最安全。之后请下载新的恢复工具包：旧的属于以前的安装。

工具包里的共享仓库会出现在位置之中，显示为保存它的服务器的名字加上**上的共享仓库**，向导在那里只列出这台服务器自己的备份。参见[应急之后](#shared-emergency)。

![应急向导的第一步，有三种进入方式。](assets/screenshots/offsite/emergency-dark.png#only-dark)
![应急向导的第一步，有三种进入方式。](assets/screenshots/offsite/emergency-light.png#only-light)

### 示例：用恢复工具包装好一台新服务器 {#example-emergency}

服务器 TOWER 连同它的磁盘一起坏了。它上面有 23 个容器和 2 台虚拟机，并把它们和它的自我备份复制到了 Backblaze B2。你在密码管理器里有 `bombvault-recovery-kit.md`，还有一台装了 Unraid 的新机器。它旧的 `APP_KEY` 没了，而你不需要它。

1. **安装 BombVault** 到新机器上，并像任何新安装那样给它一个新的 `APP_KEY`。如果你想把虚拟机找回来，请在**设置、集成、主机 SSH** 下设置虚拟机链路，因为虚拟机恢复需要它。
2. **启动向导。** 在**欢迎使用 BombVault** 上选择**从备份恢复**。在恢复页面的**紧急**下选择**启动应急向导**。
3. **访问。** 选择**上传恢复工具包**并放入文件。BombVault 会在每个存储位置上尝试它的密钥，并说明，例如 **Recovery kit read. Its key opens 0 of 2 storage locations.** 本地文件夹显示**未找到**，因为磁盘坏了，Backblaze B2 显示**缺少凭据**。
4. **保存凭据。** 工具包带有每个位置的登录凭据。点击**保存凭据**，位置会被再次尝试，所以 Backblaze B2 现在显示**可读取**。10.5 之前生成的工具包只带有默认凭据。如果某个位置仍然显示**缺少凭据**，请在**填写缺少的凭据**下输入它的凭据，然后点击**重新尝试目标**。
5. **接管密钥。** 这台服务器现在用旧的密钥写入备份，所以新的备份与旧的能衔接。它在模板里仍保留自己的 `APP_KEY`。**撤销接管**在第一次备份运行之前都有效。
6. **设置。** 这一步打开时，已经选中密钥找到自我备份的那个位置，这里是 B2，地址也已填好。选择**恢复设置**，它会从那里读取最新的自我备份。BombVault 重启来应用它，向导自己继续。你的存储位置、计划和规则回来了，你继续用这台服务器的密码登录。再次输入向导列出的密钥，例如通知设置。
7. **选择。** 本地什么都没剩下时，**备份在哪里？**会默认选中异地副本。BombVault 会读取每个位置，所以一个失效的位置不会挡住其他位置。它列出 23 个容器和 2 台虚拟机，并从存有各自最新快照的位置恢复每一个。
8. **恢复。** 开启**之后保持停止**，这在彻底丢失之后最安全，然后开始。**将会发生什么**说明会恢复什么。结果那一行会显示，例如 **25 restored, 0 failed. Start them under Backups when needed.**
9. **完成。** 先启动你的数据库，再启动使用它们的应用。打开**设置、恢复**并下载新的恢复工具包，因为旧的属于以前的安装。检查概览上的**需要处理**，等一切正常后运行一次**立即备份全部**。

如果自我备份也不见了，这一步会默认选中**跳过，我没有自我备份**，并说明这一点。这样存储位置只来自工具包，你要重新设置计划和规则，异地副本会等待，直到你把它们的备份接收为此服务器自己的备份，参见[重建之后](#after-a-rebuild)。**选择**仍会列出异地副本里存有的内容。文件夹集会恢复到你选的文件夹里。容器和虚拟机会在**只有文件可以恢复**下，作为普通文件恢复到一个文件夹里，因为它们的定义存放在本地仓库旁边和自我备份里，而异地副本两者都没有。

!!! tip "有计划的迁移与灾难"
    应急向导从备份中恢复 BombVault 自己的设置。对于*有计划的*搬到新机器，你可以改为用**导出 / 导入设置**卡片（一个可携带的 JSON 文件）直接带上你的配置。参见[配置](configuration.md#portable-settings-export-and-import)。

### 从旧的备份文件夹 {#restore-from-another-bombvault-repo}

恢复页面**其他来源**下的**从旧的备份文件夹**，会用*另一个* BombVault 实例的恢复工具包或输入的 `APP_KEY`，在一次性的只读会话里，打开那个实例的仓库（挂载在 `/mnt` 之下的共享，或远程地址）。浏览存放在那里的容器、虚拟机、文件夹集和 ZFS 数据集，选一个快照并恢复它，恢复出来的对象就成为普通的本地容器、虚拟机或文件夹集。绝不会往另一个仓库写入任何东西，你自己的备份设置也保持不变（会话存在于内存中，会自己过期）。把容器从服务器 A 搬到服务器 B，不意味着要改指你的设置，之后又改回来。这个窗口是一次性的：它打开一个会话，恢复你选的东西，然后忘记另一个实例。如果你想要的是长期的安排，也就是这台机器按计划把另一个实例的快照拉取到它自己的仓库里，那就是实例页面上的**拉取端**角色。

### 这台服务器拉取的内容 {#restore-what-was-fetched}

这台服务器拉取过的每个来源，在恢复页面的**其他来源**下都有自己的一行**从 … 获取**。拉取的副本是用这台服务器自己的密钥锁定的，而不是来源的密钥，所以不会询问任何东西：来源的密钥打不开它。文件夹集和 ZFS 数据集会恢复到你选的文件夹里。容器和虚拟机会作为普通文件恢复到一个文件夹里，因为拉取带来的是快照，而不是定义。要重新创建它们，请在应急向导里使用来源的恢复工具包和自我备份。

网络在这台服务器上不存在的容器，例如普通 Docker 主机上的 Unraid `br0` 网络，会在它的行下面显示一个网络选择器。BombVault 会在你选的网络上创建它，连同它的其他网络。固定的 IP 和 MAC 地址属于旧的网络，会被丢弃，新的网络会重新分配它们。

## 密钥保管端 {#key-keeper}

密钥保管端是你的组里保管这台服务器恢复工具包的一份封存副本的实例。它自己无法打开这份副本。如果这台服务器丢失，加入你的组的新安装会向保管端要这份副本，并用你的取回码打开它。

![取回码窗口：二十个字符，分四组，只显示一次。](assets/screenshots/offsite/recovery-code-dark.png#only-dark)
![取回码窗口：二十个字符，分四组，只显示一次。](assets/screenshots/offsite/recovery-code-light.png#only-light)

1. 在实例页面上，开启应该保管它的那个实例卡片上的**密钥保管端**，然后选择**托管**。托管需要登录密码。
2. 这台服务器会显示一次**取回码**：二十个字母和数字，分四组，每组五个。把它写下来，并用**我已记下取回码**确认。这台服务器不保存这个代码，只保存为它封存一份托管副本所需要的东西。
3. 保管端现在持有这份托管副本，工具包变化时这台服务器会更新它。这个实例的卡片上的**托管副本**会列出**这台服务器的托管副本**，带有每个保管端及其状态，还有其他实例的**这台服务器保管的托管副本**。**生成新取回码**会替换代码。每个保管端在收到新的托管副本时切换到新的代码。

到了那一天，你需要三样东西：你的组的十二个单词、取回码，以及保管端界面的访问权限，那里必须有人点击**允许**。在应急向导里选择**通过组**，选择托管副本，请求它，并输入取回码。代码在新的服务器上使用，不会发给保管端。在保管端上，请求会显示在**托管副本**下，带有是谁在请求、那个实例以前是否在那里出现过，以及它请求了多少次。**允许**会交出封存的副本，允许需要登录密码。新的安装在允许之后有 30 分钟来取走它，没有人回应的请求一天后失效，请求太频繁的实例必须等待一小时。

没有这个代码，任何人都无法打开这份副本，包括保管端。如果代码丢了，请趁这台服务器还在运行时生成新的。如果服务器已经没了，恢复工具包和输入的 APP_KEY 仍然有效。保管端可以随时删除一份托管副本，所有者随后必须再次请求。

## 恢复工具包 {#recovery-kit}

这是让灾难恢复在没有正在运行的 BombVault 时仍然可行的东西。

**设置、恢复**下**应对紧急情况**卡片里的**下载恢复工具包**会给你**密钥**、**派生的 restic 密码**、每个**存储位置**以及每个分区的仓库、新安装访问它们所需要的登录凭据，以及**确切的 restic 命令**，这样你可以在任何机器上直接用 restic 命令行恢复。它需要登录密码。即使关闭了加密，工具包也会打印密钥，因为容器和虚拟机的定义始终用它封存。接管之后，它会打印接管的备份密钥和这台服务器的 APP_KEY，新安装只在恢复设置时才需要后者。概览上的**保存你的恢复工具包**卡片会一直提醒你，直到你把它保存好。

!!! danger "把恢复工具包存放在服务器之外"
    工具包里有解密你的备份的密钥。请把它放在安全的、和服务器分开的地方（密码管理器、保险柜里的打印件）。如果你同时丢了 BombVault 和 `APP_KEY`，又没有恢复工具包和密钥托管，你的加密备份就无法恢复。

!!! warning "最新的快照不一定是该恢复的那个"
    自 restic 0.17 起，`restic snapshots` 会显示每个快照的大小。数据丢失之后，最新的快照可能是被清空的那个，所以不要恢复比之前的小得多的快照。勒索软件之后，它可能是大小正常、但已被加密的那个。如果 BombVault 还在运行，请先看它的**异常**页面：它会点出最后一份好的备份，恢复窗口会预先选中它。恢复不需要 BombVault 的任何异常数据，保留暂停也只会保留更多的快照。

### 服务器备份的主机 {#backup-host}

每台服务器都把备份写在自己的 restic 主机下：`bv-` 加上由备份密钥算出的十二个字符，例如 `bv-3f9a0c41d2e7`。服务器有主机之前的备份带有主机 `bombvault`。工具包写明了这台服务器的主机，其中的命令用 `--host` 把两者都传进去，所以 `latest` 绝不会选中另一台服务器写进同一个仓库的备份。接管了另一台服务器备份的服务器，会继续使用那台服务器的主机，因为主机来自密钥。对于这台服务器复制进去或保存的每个[共享仓库](#shared-repository)，工具包的 **Shared repositories** 一章会写明那里的其他服务器及其主机。

### 封存工具包 {#sealing-the-kit}

如果你在**设置、系统**下开启了**使用 age 加密导出**，工具包也会被它封存，并下载为 `bombvault-recovery-kit.md.age`。它是 ASCII 封装的，而不是二进制的，所以仍然是纯文本：粘贴到密码管理器或打印的方式和以前完全一样，没有你的密钥则无法读取其内容。

!!! warning "不要把 age 密钥存放在工具包里"
    打开封存的工具包需要你的 age **私**钥。请把它放在不依赖工具包本身的地方，否则你要恢复的就变成了两样东西，而不是一样。当工具包存放在你无法完全控制的地方（共享的密码管理器、云笔记、办公室里的打印件）时，封存是值得的。放在你自己保险柜里的工具包已经受到保险柜的保护。

    开启加密但没有配置可用的收件人时，下载会被直接拒绝。BombVault 绝不会退而求其次，把主密钥明文交出。

### 手边没有工具包时 {#if-you-do-not-have-the-kit-to-hand}

密码不保存在任何地方，它是由备份的密钥**计算**出来的，所以你只需要密钥和一个 shell，就能自己重现它：

```sh
printf 'bombvault:restic-repo'   | openssl dgst -sha256 -mac HMAC -macopt hexkey:$APP_KEY -r   | cut -d' ' -f1
```

这是对固定字符串 `bombvault:restic-repo` 做 HMAC-SHA256，用十六进制 `APP_KEY` 的原始字节作密钥，输出 64 个小写十六进制字符。同样的值在工具包里，列为派生的 restic 密码。这是为工具包不在你身边的那一天准备的。在接管了另一台服务器备份的服务器上，请使用接管的备份密钥，也就是那台服务器旧的 APP_KEY。

[主机](#backup-host)来自同一个密钥和字符串 `bombvault:host`：`bv-` 加上这些字符中的前十二个。

```sh
echo "bv-$(printf 'bombvault:host' | openssl dgst -sha256 -mac HMAC -macopt hexkey:$APP_KEY -r | cut -c1-12)"
```

!!! warning "对于接收的仓库，请使用发送实例的密钥"
    通过异地副本到达这里的仓库，是由发送它的那台机器用**它的**密钥创建的。用接收机器的密钥派生，得到的密码会被 restic 拒绝，这看起来恰恰像仓库损坏，其实不是。这就是对接收的仓库运行 `restic check` 时一再要求输入密码的常见原因。

因为恢复定义存放在每个仓库**内部**（`<repo>/def`、`<repo>/vm-def`），复制出来的仓库文件夹是完全自包含的，所以工具包加上仓库就是裸机恢复所需要的一切。异地副本和拉取的副本只有快照而没有定义：它们能还回文件，容器或虚拟机则要从自我备份重新创建。

## 取回数据库转储 {#database-dumps}

数据库转储是容器仓库里单独的恢复点，带有标签 `dbdump:<container>`，包含单个文件 `/dbdump/<container>.sql`。BombVault 在容器的**备份**标签页上列出、下载和导入它们。下面是只用 restic 的同样步骤，为 BombVault 不在的那一天准备。

```sh
restic -r <repo> snapshots --host <host> --host bombvault --tag dbdump:<container>
restic -r <repo> dump --host <host> --host bombvault --tag dbdump:<container> latest /dbdump/<container>.sql > <container>.sql
```

`<host>` 是恢复工具包里列出的服务器[主机](#backup-host)。

每个转储上的标签 `dbversion:` 和 `dbname:` 说明它来自哪个服务器版本，以及它包含哪些数据库。完整的文件以 `-- PostgreSQL database cluster dump complete` 或 `-- Dump completed` 结尾。

把它导入到相同或更新版本（PostgreSQL），或相同主版本（MySQL 和 MariaDB）的容器里，这个容器要用空的数据文件夹启动一次，让它初始化。主机不需要数据库客户端，容器里有：

```sh
docker exec -i <container> sh -c 'exec psql -X -U "${POSTGRES_USER:-postgres}" -d postgres' < <container>.sql
docker exec -i <container> sh -c 'exec mariadb -uroot -p"$MARIADB_ROOT_PASSWORD"' < <container>.sql
docker exec -i <container> sh -c 'exec mysql -uroot -p"$MYSQL_ROOT_PASSWORD"' < <container>.sql
```

要从完整转储中只取一个数据库，MySQL 和 MariaDB 在客户端命令上接受 `--one-database <name>`。PostgreSQL 的转储每个数据库有一段，每段以一行 `\connect <name>` 开头：把那一段复制到它自己的文件里，创建数据库之后用 `-d <name>` 导入。

!!! warning "root 转储带有服务器的用户"
    以 root 身份做的完整 MySQL 或 MariaDB 转储包含 `mysql` 系统数据库，所以导入它会把新服务器的账户（包括 root 的密码）替换为转储中的那些。在 PostgreSQL 上，容器创建的用户出现 `role ... already exists` 是预期之内的，无害。
