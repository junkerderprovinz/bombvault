# البدء

تأخذك هذه الصفحة من جهاز Unraid جديد إلى أول نسخة احتياطية لك.

## المتطلبات

| المتطلب | ملاحظات |
|---|---|
| **Unraid 6.12+** | الإصدارات الأقدم غير مُختبَرة. Unraid هو الهدف الأساسي، لكن BombVault يعمل أيضًا على مضيف Docker عادي وعلى TrueNAS Scale (راجع [مضيف Docker عام](#generic-docker-host)). |
| **موقع مستودع restic** | مسار محلي (يُنصح به: مصفوفتك أو الكاش)، أو SMB، أو NFS، أو أي خلفية rclone. |
| **مقبس Docker** | يركّبه القالب تلقائياً (`/var/run/docker.sock`). |
| **Unraid flash** (`/boot`) | يركّبه القالب بالكامل تلقائياً (`/boot` إلى `/host/boot`). يشغّل نسخ الفلاش الاحتياطي ويتيح لحاوية مُستعادة أن تظهر من جديد كتطبيق Unraid عادي وقابل للتحرير. |
| **KVM VMs** (اختياري) | يتحدث نسخ الـ VM الاحتياطي إلى libvirt عبر SSH، دون تركيب libvirt. يُعدّ تحت **الإعدادات، التكاملات، SSH المضيف** (راجع [الإعدادات](configuration.md)). |
| **مجموعات بيانات ZFS** (اختياري) | اتصال SSH نفسه الذي تستخدمه نسخ الـ VM الاحتياطية، و`zfs` على المضيف، وHost Data مربوطًا كـ `/mnt` بوضع الوصول Read/Write - Slave، وهو الافتراضي في القالب. راجع [مجموعات بيانات ZFS](zfs-datasets.md). |
| **تطبيق Android** (اختياري) | Android 10 أو أحدث، مقترنًا بخوادم على الإصدار 9.7.0 أو أحدث. راجع [تطبيق Android](android.md). |

## التثبيت على Unraid

أسهل مسار هو **Community Applications**.

1. افتح تبويب **Apps** في Unraid.
2. ابحث عن **BombVault**.
3. انقر **Install**، واضبط المتغيرات المطلوبة (أدناه)، وطبّق.

!!! tip "تثبيت القالب يدوياً"
    إذا كنت تفضّل إضافة القالب يدوياً:

    1. اذهب إلى **Docker, Add Container, Template repositories** وأضف:
       ```
       https://github.com/junkerderprovinz/unraid-apps
       ```
    2. ابحث عن **BombVault** في Templates.
    3. اضبط المتغيرات المطلوبة وانقر **Apply**.

## مضيف Docker عام {#generic-docker-host}

لست على Unraid؟ يعمل BombVault أيضًا كحاوية عادية على أي مضيف Docker (وهذا أيضًا ما يسند دعم الحاويات على TrueNAS Scale، قبل أن يكون له مدخل خاص في كتالوج التطبيقات هناك).

1. احصل من المستودع على الملف [`deploy/docker-compose.generic.yml`](https://github.com/junkerderprovinz/bombvault/blob/main/deploy/docker-compose.generic.yml) الجاهز للتحرير.
2. اضبط `APP_KEY` (انظر أدناه) ووجّه وحدة Host Data إلى جذر بياناتك الحقيقي. تعليقات الملف تشرح الأمرين.
3. `docker compose up -d`، ثم افتح `https://<ip-المضيف>:3443/`.

ما الذي يختلف عن Unraid:

- **لا يوجد قسم Flash.** لا توجد ذاكرة إقلاع لالتقاطها أو استعادتها، لذا لا عمل لقسم Flash هنا. بدلًا من ذلك تعرض **إضافة** في صفحة النسخ الاحتياطية **إعدادات النظام** كاقتراح مجلد: مجموعة مجلدات `/etc` مبدئية تُراجع وتُعدَّل قبل الحفظ.
- **لا توجد إشعارات Unraid الأصلية.** قنوات الإشعارات الخاصة بـ BombVault (webhook، تنبيهات فشل النسخ خارج الموقع وغيرها) تعمل كالمعتاد؛ ويُتخطّى فقط الإرسال الخاص بنظام إشعارات Unraid، إذ لا وجود لمثل هذا النظام هنا.
- **نسخ الأجهزة الافتراضية اختياري ويحتاج مضيف libvirtd منفصلًا يمكن بلوغه عبر SSH.** انظر الكتلة المعلّقة في ملف compose. المضيف العام لا يحمل في ذاته أي مدير للأجهزة الافتراضية.
- **لا توجد أداة للوحة Dashboard.** BombVault Widget إضافة لـ Unraid، لذا تُتخطّى هذه الخطوة أيضًا.
- **العثور على بيانات الحاوية.** من دون اصطلاح `appdata` في Unraid، يُعثر على مجلد بيانات الحاوية من المقاطع الواردة في `DATA_ROOT_SEGMENTS`، ومن وحدات Docker المسمّاة، ومن مجلد العمل لمشروع Compose، ومن التسمية `bombvault.data` (راجع [اكتشاف مصادر النسخ الاحتياطي](configuration.md#backup-source-detection)). لا تصل الوحدات المسمّاة والإعداد المسبق `/etc` إلا إلى المسارات داخل تركيب Host Data، لذا وجّه Host Data إلى مجلد أب مشترك يشمل أيضًا جذر بيانات Docker.
- **`PLATFORM`.** اضبطه على `generic` أو `truenas`. إن تُرك غير مضبوط، يتعرّف BombVault على Unraid من علامته الخاصة على تركيب الفلاش ويعامل أي شيء آخر كمضيف عام، وتُتخطّى الخطوات الخاصة بـ Unraid بدلًا من تجربتها وفشلها.

يسلك **TrueNAS Scale** طريق compose نفسه؛ وقد أُعدّ إدخال للكتالوج في المستودع لكنه لم يُقدَّم بعد. يحتاج نسخ الـ VM الاحتياطي هناك إلى `LIBVIRT_URI`، لأن libvirtd في TrueNAS يستمع على مقبس خاص به (`/run/truenas_libvirt/libvirt-sock`) لا تستطيع متغيرات `LIBVIRT_*` الثلاثة التعبير عنه (راجع [الإعدادات](configuration.md)). إلى أي مدى ثبت ذلك: جرى نسخ zvol احتياطيًا على جهاز TrueNAS Scale حقيقي، على zvol متصل بـ VM عامل، ونقلته `zfs snapshot` و`zfs send` وrestic و`zfs receive` ذهابًا وإيابًا فعاد مطابقًا بايتًا ببايت. لم تُجرَ بعد استعادة كاملة يقودها BombVault نفسه على عتاد TrueNAS، وكان ذلك الـ zvol متناثرًا (sparse)، لذا لم تُختبر الإنتاجية مع حجم كبير من الجيجابايتات. جرّب استعادة هناك قبل أن تعتمد عليه.

## الإعداد المطلوب الوحيد

المتغير الوحيد الذي يجب عليك ضبطه هو `APP_KEY`، وهو سر سداسي عشري بحجم 32 بايت (64 حرفاً سداسياً عشرياً) يُستخدم لاشتقاق كلمة مرور مستودع restic.

أنشئ واحداً على أي جهاز:

```bash
openssl rand -hex 32
```

الصق النتيجة في حقل `APP_KEY` في القالب (Unraid)، أو في متغير البيئة `APP_KEY` في `docker-compose.yml` (مضيف Docker عام).

!!! danger "لا تفقد APP_KEY الخاص بك"
    فقدان `APP_KEY` يجعل نسخك الاحتياطية المشفّرة غير قابلة للاسترداد. يُحفظ في مكان آمن ومنفصل عن الخادم. بمجرد تشغيل BombVault تُضبط كلمة مرور لتسجيل الدخول وتُنزَّل **حقيبة الاستعادة** تحت **الإعدادات، استعادة** (راجع [النسخ خارج الموقع والتعافي](offsite-recovery.md#recovery-kit)). تحوي المفتاح وكل وجهة وأوامر restic.

يركّب القالب أيضاً مقبس Docker والفلاش (`/boot`) وجذر **Host Data** (`/mnt`) نيابةً عنك. تعيش *مصادر* النسخ الاحتياطي و*وجهاته* كلاهما ضمن Host Data. للمرجع الكامل للمتغيرات وإعداد النسخ خارج الموقع، راجع [الإعدادات](configuration.md).

## التشغيل الأول

![نظرة عامة بعد أول نسخة احتياطية: ما يحتاج إلى اهتمام، وحماية كل قسم، والوجهات، والسجل.](assets/screenshots/dashboard.png)

*نظرة عامة بعد أول نسخة احتياطية: ما يحتاج إلى اهتمام، وحماية كل قسم، والوجهات، والسجل.*

1. تُفتح واجهة الويب على `https://<your-unraid-ip>:3443` (شهادة موقّعة ذاتياً بشكل افتراضي). يفتح التثبيت الجديد على **مرحبًا في BombVault**، التي تسرد ما وجده BombVault على الخادم.
2. يُختار **هيا بنا**. تعرض نظرة عامة بعدها بطاقة **الخطوات الأولى** بثلاث خطوات:
    1. **اختيار الأقسام**: تفعيل ما ينسخه BombVault احتياطياً (Containers وVMs وFlash والمجلدات ومجموعات بيانات ZFS والنسخ الذاتي). يفتح **اختيار** قائمة عناصر القسم، حيث يستبعد **إيقاف الجدول مؤقتًا** عنصراً. الأقسام المفعّلة هنا تعمل كل ليلة، ويمكن تغيير ذلك تحت **الإعدادات، الجدول الزمني**.
    2. **إضافة وجهة**: إلى أين تذهب النسخ الاحتياطية. يكفي مجلد محلي للبدء. والأكثر أماناً وجهة ثانية خارج المقر، مثل Storage Box أو Backblaze B2. المستودعات المحلية تكون افتراضياً `/mnt/user/bombvault/{container,vms,flash,config,files,zfs}` وتُنشأ عند أول نسخة احتياطية.
    3. **أول نسخة احتياطية**: بعدها تعمل تلقائياً كل ليلة.
3. تُفتح **النسخ الاحتياطية** لرؤية كل العناصر في قائمة واحدة. يبدأ **نسخ كل شيء احتياطيًا الآن** تشغيلاً على كل الأقسام المفعّلة، وينسخ **نسخ احتياطي الآن** في صفحة عنصر ما ذلك العنصر وحده.

سبق استخدام BombVault؟ تفتح **الاستعادة من نسخة احتياطية** في صفحة الترحيب صفحة الاستعادة، حيث يعيد **معالج الطوارئ** إعدادات خادم مفقود وحاوياته وVMs ومجلداته. راجع [النسخ خارج الموقع والتعافي](offsite-recovery.md#emergency).

!!! tip "اختياري: اختر ترتيب النسخ الاحتياطي"
    إذا كان يجب دائماً نسخ بعض الحاويات احتياطياً قبل غيرها (مثلاً قاعدة بيانات قبل التطبيق الذي يستخدمها)، تُفتح بطاقة **الترتيب** تحت **الإعدادات، الجدول الزمني** وتُسحب الحاويات إلى التسلسل المطلوب. تتبعه عندئذٍ عمليات التشغيل المجدولة والنسخة الكاملة؛ وأي شيء يُترك غير مرتَّب يُنسخ احتياطياً بالأكثر تأخّراً أولاً.

!!! note "فحص تكامل المضيف"
    تستطلع بطاقة **تكامل المضيف** في نظرة عامة كل نقطة تركيب وواجهة سطر أوامر (مقبس Docker، libvirt، restic، qemu-img، rclone) وتبلّغ عن أي أجزاء ناقصة، حتى يمكن التأكد من أن الحاوية موصولة بشكل صحيح قبل الاعتماد عليها. وتنتظر تحت **تخصيص** إلى أن تُضاف.

## التنقل في الواجهة {#navigation}

![الإعدادات كبلاطات، وبجانبها بطاقات البلاطة المختارة. كل تغيير يُكتب فور إجرائه.](assets/screenshots/settings.png)

*الإعدادات كبلاطات، وبجانبها بطاقات البلاطة المختارة. كل تغيير يُكتب فور إجرائه.*

في الشريط الجانبي خمسة عناصر: **نظرة عامة**، و**الحالات الشاذة** (ما دام اكتشاف الحالات الشاذة مفعّلًا)، و**النسخ الاحتياطية**، و**الاستعادة**، وتحت **تسجيل الخروج** الإعدادات. يطفو الإجراء الرئيسي للصفحة في أسفل اليمين، ويضم **المزيد** الإجراءات النادرة. وعلى الهاتف يضم الشريط نظرة عامة والنسخ الاحتياطية والاستعادة والإعدادات، ويضم **المزيد** الباقي.

- **النسخ الاحتياطية** تسرد كل حاوية وVM ومجموعة مجلدات والفلاش وكل مجموعة بيانات ZFS والنسخ الذاتي كعناصر. تختار البلاطات فوق القائمة نوعاً، ويضيّق **عوامل التصفية** و**ترتيب** و**بحث** النتائج. لكل عنصر صفحة خاصة بثلاثة تبويبات: **النسخ الاحتياطية** و**الإعدادات** و**السلامة**.
- **الاستعادة** صفحة واحدة لكل شيء: يُختار قسم، ويُبحث عن عنصر، وتُختار نسخة احتياطية. ومن هنا أيضاً يبدأ معالج الطوارئ والمصادر الأخرى.
- **الإعدادات** أربع عشرة بلاطة: عام، المظهر، الجدول الزمني، الوجهات، استعادة، الإشعارات، تحقق، الأمان، المثيلات، الاقتران، التكاملات، التطبيقات، النظام، معلومات. يبحث `/` أو Ctrl+K فيها كلها، وبالأسماء التي كانت للصفحات في الإصدارات السابقة أيضاً. تُسحب البلاطات إلى ترتيب خاص تحت **المظهر**.
- **الوجهات** و**المثيلات** بلاطتا إعدادات لهما صفحتان خاصتان. يثبّتهما **العرض أيضًا في الشريط الجانبي** على بلاطتهما في الشريط الجانبي.

لا زر حفظ في أي مكان ولا شيء ينفتح عند النقر: للأمور النادرة بطاقة خاصة أو نافذة، والشروح في فقاعات (i). بعد التحديث تعلّم نقاط خضراء ما تغيّر. ينقرها المرء فتختفي، وتسرد **الإعدادات، معلومات، الجديد** كل تغيير مع **الانتقال إلى هناك**.

## البناء من الكود المصدري {#build-from-source}

BombVault ملف تنفيذي ثابت واحد مكتوب بـ Go، يقدّم واجهة JSON API وواجهة React مضمَّنة. ابنِ الواجهة أولًا، ثم شغّل الملف التنفيذي:

```bash
npm --prefix web ci
npm --prefix web run build     # يكتب web/dist الذي يضمّنه الملف التنفيذي
export APP_KEY=$(openssl rand -hex 32)
go test ./...                  # اختبارات الوحدات والتكامل، مع دورة restic حقيقية ذهابًا وإيابًا
golangci-lint run ./...
go run ./cmd/bombvault         # يقدّم https://localhost:3443 بشهادة موقّعة ذاتيًا
```

بناء الواجهة مطلوب أيضًا لـ `go run`. لا يتتبع المستودع تحت `web/dist` إلا ملف علامة فارغًا، لذا من دون `npm --prefix web run build` لا يضمّن الملف التنفيذي شيئًا ويجيب بـ `500 SPA index not found`، وهذا متوقع. لا يمكن اختبار Docker وlibvirt وUnraid في CI، لذا تُفحص نقاط التركيب وrestic واتصال SSH الخاص بالـ VM على مضيف حقيقي باستخدام بطاقة **تكامل المضيف** في نظرة عامة (أو `GET /api/spike`) قبل فتح pull request.
