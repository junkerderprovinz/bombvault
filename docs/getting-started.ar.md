# البدء

تقودك هذه الصفحة من جهاز Unraid جديد إلى أول نسخة احتياطية.

## المتطلبات {#requirements}

| المتطلب | ملاحظات |
|---|---|
| **Unraid 6.12+** | لم تُختبر الإصدارات الأقدم. الهدف الرئيسي هو Unraid، لكن BombVault يعمل أيضًا على مضيف Docker عادي وعلى TrueNAS Scale (راجع [مضيف Docker عام](#generic-docker-host) و[TrueNAS SCALE](#truenas)). |
| **موقع مستودع restic** | مسار محلي (يُنصح بالمصفوفة أو الكاش)، أو SMB، أو NFS، أو أي واجهة خلفية لـ rclone. |
| **مقبس Docker** | يركّبه القالب تلقائيًا (`/var/run/docker.sock`). |
| **فلاش Unraid** (`/boot`) | يركّبه القالب كاملًا تلقائيًا (`/boot` إلى `/host/boot`). يشغّل نسخ الفلاش ويتيح لحاوية مستعادة أن تظهر من جديد كتطبيق Unraid عادي قابل للتحرير. |
| **أجهزة KVM الافتراضية** (اختياري) | يتحدث نسخ الأجهزة الافتراضية إلى libvirt عبر SSH، دون تركيب libvirt. اضبطه ضمن **الإعدادات، التكاملات، SSH المضيف** (راجع [التهيئة](configuration.md)). |
| **مجموعات بيانات ZFS** (اختياري) | اتصال SSH نفسه الخاص بنسخ الأجهزة الافتراضية، و`zfs` على المضيف، وHost Data مربوط بـ `/mnt` بوضع الوصول Read/Write - Slave، وهو الافتراضي في القالب. راجع [مجموعات بيانات ZFS](zfs-datasets.md). |
| **تطبيق Android** (اختياري) | Android 10 أو أحدث، مقترن بخوادم بالإصدار 9.7.0 أو أحدث. راجع [تطبيق Android](android.md). |

## التثبيت على Unraid {#install-on-unraid}

أسهل طريق هو **Community Applications**.

1. افتح تبويب **Apps** في Unraid.
2. ابحث عن **BombVault**.
3. اضغط **Install**، واضبط المتغيرات المطلوبة (أدناه)، ثم طبّق.

!!! tip "تثبيت القالب يدويًا"
    إذا كنت تفضل إضافة القالب يدويًا:

    1. اذهب إلى **Docker, Add Container, Template repositories** وأضف:
       ```
       https://github.com/junkerderprovinz/unraid-apps
       ```
    2. ابحث عن **BombVault** في القوالب.
    3. اضبط المتغيرات المطلوبة واضغط **Apply**.

## مضيف Docker عام {#generic-docker-host}

لست على Unraid؟ يعمل BombVault أيضًا كحاوية عادية على أي مضيف Docker. لـ TrueNAS SCALE خطواته الخاصة تحت [TrueNAS SCALE](#truenas).

1. احصل من المستودع على الملف الجاهز للتحرير [`deploy/docker-compose.generic.yml`](https://github.com/junkerderprovinz/bombvault/blob/main/deploy/docker-compose.generic.yml).
2. اضبط `APP_KEY` (انظر أدناه) ووجّه وحدة تخزين Host Data إلى جذر بياناتك الفعلي. تشرح التعليقات في الملف الأمرين.
3. نفّذ `docker compose up -d`، ثم افتح `https://<host-ip>:3443/`.

ما الذي يختلف عن Unraid:

- **لا قسم Flash.** لا توجد USB إقلاع لنسخها أو استعادتها، فلا عمل لقسم Flash هنا. بدلًا من ذلك، حين يصل Host Data إلى `/etc` على المضيف، يقدّم **إضافة** في صفحة النسخ الاحتياطية **إعدادات النظام** كاقتراح مجلد: مجموعة مجلدات `/etc` ابتدائية تراجعها وتعدّلها قبل الحفظ.
- **لا إشعارات أصلية لـ Unraid.** تعمل قنوات الإشعارات الداخلية في BombVault (webhook وتنبيهات فشل النسخ خارج الموقع وغيرها) كالمعتاد. يُتخطى فقط الإرسال إلى نظام الإشعارات الأصلي في Unraid، لأنه لا يوجد نظام كهذا للإرسال إليه.
- **نسخ الأجهزة الافتراضية اختياري ويحتاج إلى مضيف libvirtd منفصل يمكن الوصول إليه عبر SSH.** راجع الكتلة المعلّقة في ملف compose. لا يوجد مدير أجهزة افتراضية مضمّن في مضيف Docker عام.
- **لا بلاطة للوحة التحكم.** TollRoll إضافة لـ Unraid، فتُتخطى تلك الخطوة أيضًا.
- **العثور على بيانات حاوية.** بدون عُرف `appdata` في Unraid، يُعثر على مجلد بيانات الحاوية من المقاطع في `DATA_ROOT_SEGMENTS` وأحجام Docker المسماة والدليل العامل لمشروع Compose والوسم `bombvault.data` (راجع [اكتشاف مصدر النسخ الاحتياطي](configuration.md#backup-source-detection)). لا تصل الأحجام المسماة وإعداد `/etc` المسبق إلا إلى المسارات داخل تركيب Host Data، لذا وجّه Host Data إلى سلف مشترك يغطي أيضًا جذر بيانات Docker.
- **`PLATFORM`.** اضبطه على `generic` أو `truenas`. إذا تُرك بلا ضبط، يكتشف BombVault Unraid بعلامته الخاصة على تركيب الفلاش ويعامل أي شيء آخر كعام، وتُتخطى الخطوات الخاصة بـ Unraid بدلًا من تجربتها وفشلها.

### TrueNAS SCALE {#truenas}

BombVault ليس في فهرس تطبيقات TrueNAS بعد، لذا ثبّته كتطبيق مخصص: **Apps, Discover Apps**، ثم **Install via YAML** في القائمة بجانب **Custom App**. يضبط YAML أدناه الأشياء نفسها التي يضبطها إدخال الفهرس في مجلد `truenas-apps` من المستودع. استبدل `tank` بمجمّعك واملأ `APP_KEY` كما يصف القسم التالي.

```yaml
services:
  bombvault:
    image: junkerderprovinz/bombvault:latest
    hostname: bombvault
    restart: unless-stopped
    cap_drop: [ALL]
    cap_add: [CHOWN, DAC_OVERRIDE, FOWNER, SETGID, SETPCAP, SETUID, SYS_CHROOT]
    environment:
      APP_KEY: ""
      PLATFORM: truenas
      HOST_SOURCE_ROOT: /mnt/tank
      HOST_MOUNT_ROOT: /mnt/tank
      # For VM backups:
      # LIBVIRT_URI: qemu+ssh://root@<truenas-ip>/system?socket=/run/truenas_libvirt/libvirt-sock
    volumes:
      - /mnt/tank/apps/bombvault:/config
      - /var/run/docker.sock:/var/run/docker.sock
      - type: bind
        source: /mnt/tank
        target: /mnt/tank
        bind:
          propagation: rslave
    ports:
      - "30528:3443"
```

ثم افتح `https://<truenas-ip>:30528/`. ما هو مسرود تحت [ما الذي يختلف عن Unraid](#generic-docker-host) ينطبق هنا أيضًا، وعلى TrueNAS:

- **القدرات (capabilities).** يحتاج BombVault إلى السبع المذكورة أعلاه. تفشل نسخ الأجهزة الافتراضية بدون `SETPCAP`، وبدون `SYS_CHROOT` تُوقف كل حاوية طوال نسخها بدل قراءتها من لقطة.
- **Host Data** مسار مضيف على مجموعة بيانات، هنا `/mnt/tank`، مركّب على المسار نفسه داخل التطبيق. لذلك يسمّيه `HOST_SOURCE_ROOT` و`HOST_MOUNT_ROOT` معًا. يمرّر `rslave` التركيبات التي يجريها المضيف لاحقًا، وتحتاج إليها نسخ مجموعات بيانات ZFS.
- **البيانات في ixVolume لا تُنسخ.** يحتفظ تطبيق وحدة تخزينه ixVolume ببياناته تحت `/mnt/.ix-apps`، خارج Host Data. ينسخ BombVault تعريف التطبيق فقط، ويسمّي التشغيل المجلدات التي تركها. لكل تطبيق تريد نسخ بياناته اختر تخزين **Host Path** على مجموعة بيانات تحت Host Data.
- **نسخ الأجهزة الافتراضية ومجموعات بيانات ZFS** تصل إلى TrueNAS عبر SSH بصفة root. فعّل خدمة SSH تحت **System, Services**، وأضف المفتاح العام من **الإعدادات، التكاملات، SSH المضيف** إلى المستخدم root تحت **Credentials, Users**. تحتاج نسخ الأجهزة الافتراضية أيضًا إلى `LIBVIRT_URI` كما سبق، لأن libvirtd في TrueNAS يستمع على مقبس خاص. وإن لم يُضبط `LIBVIRT_URI` ولا `LIBVIRT_HOST`، يستخدم BombVault البوابة الافتراضية للتطبيق كمضيف، لأن `host.docker.internal` لا يُحلّ في تطبيق TrueNAS. تغطي [دليل نسخ الأجهزة الافتراضية](vm-backup-ssh-setup.md#truenas-scale) التفاصيل، بما فيها الأجهزة على zvol.
- **النسخة المتماثلة لـ ZFS تستخدم مفتاحًا مختلفًا.** تسجّل النسخة المتماثلة على خادم ZFS ثانٍ الدخول بالمفتاح الذي تعرضه نافذة النسخة المتماثلة، لا بمفتاح SSH المضيف. أضف ذلك على الخادم المستقبِل.
- **التطبيق المحذوف يعود على خطوتين.** أعد تثبيته في TrueNAS بالاسم نفسه أولًا، وهذا ينشئ شبكته من جديد، ثم استعد بياناته في BombVault. حتى ذلك الحين يبلّغ فحص الاستعادة عن الشبكة الناقصة وترفض الاستعادة قبل أن تغيّر شيئًا.
- **بجانب الأصل** ينشئ حاوية Docker عادية. تعمل، لكن شاشة Apps في TrueNAS لا تسردها.
- **تفريغات قواعد البيانات** تعمل على تركيبات مجموعات البيانات. استيراد إلى مجلد بيانات هو نفسه مجموعة بيانات يبدّل المحتوى القديم إلى مجلد بجانبه، لذا تحتاج مجموعة البيانات التي فوقه إلى مكان له.

### ZimaOS وCasaOS ومضيفات أخرى {#other-hosts}

- **ZimaOS وCasaOS:** أضف [متجر المجتمع](https://github.com/junkerderprovinz/zimaos-apps#install) وثبّت BombVault منه. يعمل هناك كـ `PLATFORM=generic` مع Host Data على `/DATA`. يحفظ ZimaOS بيانات التطبيقات في `/DATA/AppData/<app>`، ويجدها BombVault بنفسه لأن `DATA_ROOT_SEGMENTS` يطابق `appdata` بأي حالة أحرف.
- **MOS:** ثبّت BombVault من [MOS Hub](https://mos-official.net/apps.html?search=BombVault). يعمل هناك كـ `PLATFORM=generic` مع Host Data على `/mnt/cache`.
- **Synology:** في Container Manager أنشئ مشروعًا من ملف compose (DSM 7.2 أو أحدث).
- **Proxmox:** شغّله في جهاز افتراضي أو حاوية LXC فيها Docker.

بدون تعليقات يكون ملف compose العام قصيرًا. استبدل `./data` بمجلد المضيف الذي يحمل بيانات حاوياتك، واضبط `HOST_SOURCE_ROOT` على المسار نفسه، واملأ `APP_KEY`:

```yaml
services:
  bombvault:
    image: junkerderprovinz/bombvault:latest
    restart: unless-stopped
    hostname: bombvault
    container_name: bombvault
    volumes:
      - ./config:/config
      - /var/run/docker.sock:/var/run/docker.sock
      - ./data:/host/user
    environment:
      APP_KEY: ""
      PLATFORM: generic
      HOST_SOURCE_ROOT: /host/user
    ports:
      - "3443:3443"
```

لنسخ أحجام Docker المسماة أيضًا، ركّب مجلدًا يحمل بياناتك وجذر بيانات Docker معًا (`docker info -f '{{.DockerRootDir}}'`، وهو عادةً `/var/lib/docker`)، كما يركّب قالب Unraid كل `/mnt`.

## الإعداد الوحيد المطلوب {#the-one-required-setting}

المتغير الوحيد الذي يجب ضبطه هو `APP_KEY`، سر من 32 بايتًا بالنظام الست عشري (64 رمزًا ست عشريًا) يُشتق منه كلمة مرور مستودع restic.

أنشئ واحدًا على أي حاسوب:

```bash
openssl rand -hex 32
```

الصق النتيجة في الحقل `APP_KEY` في القالب (Unraid)، أو في متغير البيئة `APP_KEY` في `docker-compose.yml` (مضيف Docker عام).

!!! danger "لا تفقد APP_KEY"
    فقدان `APP_KEY` يجعل نسخك الاحتياطية المشفرة غير قابلة للاسترداد. احفظه في مكان آمن منفصل عن الخادم. بعد أن يعمل BombVault، اضبط كلمة مرور دخول ونزّل **حقيبة الاستعادة** ضمن **الإعدادات، استعادة** (راجع [خارج الموقع والاستعادة](offsite-recovery.md#recovery-kit)). فيها المفتاح وكل وجهة وأوامر restic.

يركّب القالب أيضًا مقبس Docker والفلاش (`/boot`) وجذر **Host Data** (`/mnt`) لك. مصادر النسخ الاحتياطي ووجهاتها كلاهما يقع تحت Host Data. للمرجع الكامل للمتغيرات وإعداد النسخ خارج الموقع راجع [التهيئة](configuration.md).

## التشغيل الأول {#first-run}

![صفحة الترحيب في تثبيت جديد، مع ما وجده BombVault على الخادم.](assets/screenshots/getting-started/welcome-dark.png#only-dark)
![صفحة الترحيب في تثبيت جديد، مع ما وجده BombVault على الخادم.](assets/screenshots/getting-started/welcome-light.png#only-light)

1. افتح واجهة الويب على `https://<your-unraid-ip>:3443` (شهادة موقّعة ذاتيًا جاهزة من الصندوق). يُفتح التثبيت الجديد على **مرحبًا في BombVault** الذي يسرد ما وجده BombVault على الخادم.
2. اختر **هيا بنا**. تعرض النظرة العامة حينئذ بطاقة **الخطوات الأولى** بثلاث خطوات:
    1. **اختيار الأقسام**: فعّل ما ينسخه BombVault (الحاويات، VMs، Flash، المجلدات، مجموعات بيانات ZFS، النسخ الذاتي). يفتح **اختيار** قائمة عناصر قسم، حيث يتركها **إيقاف الجدول مؤقتًا** خارجًا. الأقسام التي تفعّلها هنا تعمل كل ليلة، وهو ما تغيّره ضمن **الإعدادات، الجدول الزمني**.
    2. **إضافة وجهة**: مكان ثانٍ للنسخ. لكل قسم مجلد على هذا الخادم بالفعل، `/mnt/user/bombvault/{container,vms,flash,config,files,zfs}`، يُنشأ في أول نسخة. الأكثر أمانًا وجهة ثانية خارج المقر، مثل Storage Box أو Backblaze B2.
    3. **أول نسخة احتياطية**: بعد ذلك تجري وحدها كل ليلة. تبقى البطاقة إلى أن تنتهي أول نسخة.
3. افتح **النسخ الاحتياطية** لرؤية كل عنصر في قائمة واحدة. **نسخ كل شيء احتياطيًا الآن** يبدأ مرورًا على كل قسم مفعّل، و**نسخ احتياطي الآن** في صفحة عنصر ينسخ ذلك العنصر وحده.

![بطاقة الخطوات الأولى بخطواتها الثلاث، والثانية مفتوحة.](assets/screenshots/getting-started/first-steps-dark.png#only-dark)
![بطاقة الخطوات الأولى بخطواتها الثلاث، والثانية مفتوحة.](assets/screenshots/getting-started/first-steps-light.png#only-light)

استخدمت BombVault من قبل؟ **الاستعادة من نسخة احتياطية** في صفحة الترحيب تفتح صفحة الاستعادة، حيث يعيد **معالج الطوارئ** إعدادات خادم مفقود وحاوياته وأجهزته الافتراضية ومجلداته. راجع [خارج الموقع والاستعادة](offsite-recovery.md#emergency).

!!! tip "اختياري: اختر ترتيبًا للنسخ"
    إذا كان ينبغي أن تُنسخ بعض الحاويات دائمًا قبل غيرها (مثلًا قاعدة بيانات قبل التطبيق الذي يستخدمها)، فافتح بطاقة **الترتيب** ضمن **الإعدادات، الجدول الزمني** واسحبها إلى التسلسل الذي تريده. تتبعه حينئذ التشغيلات المجدولة والنسخة الشاملة. وأي شيء تتركه بلا ترتيب يُنسخ الأكثر تأخرًا أولًا.

## مثال: أول نسخة احتياطية لحاوية، من البداية إلى النهاية {#example-first-backup}

يمرّ هذا على جهاز Unraid جديد فيه بضع حاويات، منها `plex`، إلى أن تنتهي أول نسخة وتعرف أين تجدها. يستغرق نحو عشر دقائق بالإضافة إلى وقت أول نسخة.

1. **ثبّت.** في تبويب **Apps** في Unraid ابحث عن **BombVault** واضغط **Install**.
2. **اضبط المفتاح.** على حاسوب نفّذ `openssl rand -hex 32` والصق الرموز الأربعة والستين في حقل `APP_KEY` في القالب. احتفظ بنسخة في مدير كلمات المرور الآن، قبل أي شيء آخر. اضغط **Apply**.
3. **افتحه.** اذهب إلى `https://<your-unraid-ip>:3443` واقبل الشهادة الموقّعة ذاتيًا. يسرد **مرحبًا في BombVault** ما وجده، مثل 12 حاوية وجهازين افتراضيين ومحرك الفلاش.
4. **هيا بنا.** تُفتح النظرة العامة ببطاقة **الخطوات الأولى**.
5. **اختيار الأقسام.** **الحاويات** مفعّلة من البداية. فعّل ما تريد غيرها، مثل **Flash**. يفتح **اختيار** قائمة الحاويات التي وجدها، حيث يترك **إيقاف الجدول مؤقتًا** واحدة خارجًا، مثل حاوية اختبار لا تهمك. تعمل الأقسام المفعّلة كل ليلة ضمن النسخة الشاملة.
6. **إضافة وجهة.** لكل قسم مجلده الخاص على هذا الخادم تحت `/mnt/user/bombvault`، فلأول نسخة مكان تذهب إليه. تضيف هذه الخطوة مكانًا ثانيًا، والأكثر أمانًا منه خارج المقر. يمكنك فعل ذلك الآن بـ [مثال S3](offsite-recovery.md#example-s3)، أو العودة إليه بعد انتهاء أول نسخة. تبقى البطاقة إلى ذلك الحين.
7. **أول نسخة احتياطية.** افتح **النسخ الاحتياطية** واضغط **نسخ كل شيء احتياطيًا الآن**، أو انتظر الليل. تتحول الحلقة في رأس الحالة إلى حلقة تقدم وتعدّ العناصر، مثل **النسخ الاحتياطي جارٍ الآن: 3 من 12**. تُوقف كل حاوية بينما تُقرأ بياناتها وتبدأ من جديد بعد ذلك مباشرة. والحاوية التي تقع بياناتها على ZFS تتوقف فقط ثواني اللقطة. تقرأ أول نسخة كل شيء، لذا فهي أطول نسخة. والتالية تخزّن ما تغيّر فقط.
8. **تحقق.** حين تقول الحلقة **تم نسخ كل شيء احتياطيًا**، افتح **التاريخ** في النظرة العامة: لكل حاوية سطر أخضر في **عمليات التشغيل**. افتح **النسخ الاحتياطية**، وانقر `plex` وانظر إلى تبويب **النسخ الاحتياطية** له: لقطة أولى موجودة، و**محلي** هو المكان الذي يحتفظ بها. بعد دقائق يعرض تبويب **تحقق** فحص الاستعادة الذي استعاد عينة من النسخة وقرأها ثانية.
9. **احمِ المفتاح.** افتح **الإعدادات، الأمان** واضبط كلمة مرور دخول. ثم افتح **الإعدادات، استعادة** واضغط **تنزيل حقيبة الاستعادة** في **للطوارئ**. احتفظ بالملف خارج الخادم، بجانب نسخة `APP_KEY` من الخطوة 2. يختفي تذكير **حفظ حقيبة الاستعادة** في النظرة العامة حين تضغط **حفظتها بأمان**.

منذ الآن تُنسخ الحاويات كل ليلة. خطوات تالية جيدة بهذا الترتيب: [وجهة خارج الموقع](offsite-recovery.md#example-s3)، حتى لا يأخذ خادم ميت النسخ معه، ثم [الإشعارات](notifications.md)، ليصلك أي فشل، ثم نظرة على [الجداول](schedules.md) إن لم يناسبك 03:00.

![رأس الحالة أثناء تشغيل أول نسخة، مع حلقة التقدم ومحطاتها.](assets/screenshots/getting-started/status-ring-dark.png#only-dark)
![رأس الحالة أثناء تشغيل أول نسخة، مع حلقة التقدم ومحطاتها.](assets/screenshots/getting-started/status-ring-light.png#only-light)

!!! note "فحص تكامل المضيف"
    تفحص بطاقة **تكامل المضيف** في النظرة العامة كل تركيب وكل أداة سطر أوامر (مقبس Docker وlibvirt وrestic وqemu-img وrclone) وتبلّغ عن أي نقص، فتتأكد من أن الحاوية موصولة صحيحًا قبل أن تعتمد عليها. وهي تنتظر تحت **تخصيص** إلى أن تضيفها.

## التنقل {#navigation}

![الإعدادات كبلاطات، وبطاقات البلاطة المختارة بجانبها. يُكتب كل تغيير فور إجرائه.](assets/screenshots/getting-started/settings-rail-dark.png#only-dark)
![الإعدادات كبلاطات، وبطاقات البلاطة المختارة بجانبها. يُكتب كل تغيير فور إجرائه.](assets/screenshots/getting-started/settings-rail-light.png#only-light)

للشريط الجانبي خمسة إدخالات: **نظرة عامة** و**الحالات الشاذة** (ما دام اكتشاف الحالات الشاذة مفعّلًا) و**النسخ الاحتياطية** و**الاستعادة**، وتحت **تسجيل الخروج** **الإعدادات**. يطفو الإجراء الرئيسي للصفحة أسفل اليمين، ويضم **المزيد** النادرة. وعلى الهاتف يضم الشريط نظرة عامة والنسخ الاحتياطية والاستعادة والإعدادات، وفي **المزيد** البقية.

تستخدم الصفحات والإعدادات عرض النافذة كله. تحتفظ النافذة بأزرارها في أسفلها، والزر الذي يتقدم إلى الأمام على اليمين. وعلى الهاتف، يُبقي الأسفل الذي فيه أكثر من ثلاثة أزرار المخرج والإجراء الرئيسي ويضع الباقي تحت **المزيد**.

![على الهاتف، الشريط في الأسفل مع فتح «المزيد».](assets/screenshots/getting-started/phone-more-dark.png#only-dark)
![على الهاتف، الشريط في الأسفل مع فتح «المزيد».](assets/screenshots/getting-started/phone-more-light.png#only-light)

- **نظرة عامة** تعرض هل نُسخ كل شيء احتياطيًا وما الذي يحتاج إليك. راجع [نظرة عامة](overview.md).
- **النسخ الاحتياطية** تسرد كل حاوية وجهاز افتراضي ومجموعة مجلدات ومحرك الفلاش وكل مجموعة بيانات ZFS والنسخ الذاتي كعناصر. تختار البلاطات فوق القائمة نوعًا، و**عوامل التصفية** و**ترتيب** و**بحث** تضيّقها. لكل عنصر صفحة خاصة بثلاثة تبويبات: **النسخ الاحتياطية** و**الإعدادات** و**تحقق**. يقود زر رجوع إلى يسار أيقونة العنصر إلى القائمة. راجع [النسخ الاحتياطية والعناصر](backups.md).
- **الاستعادة** صفحة واحدة لكل شيء: اختر قسمًا، وابحث عن عنصر، واختر نسخة. ويبدأ معالج الطوارئ والمصادر الأخرى من هنا أيضًا. راجع [الاستعادة](restore.md).
- **الإعدادات** أربع عشرة بلاطة: عام والمظهر والجدول الزمني والوجهات والاستعادة والإشعارات وتحقق والأمان والمثيلات والاقتران والتكاملات والتطبيقات والنظام ومعلومات. راجع [الإعدادات](settings.md). اضغط `/` أو Ctrl+K للبحث في كلها، وبالأسماء التي كانت للصفحات في الإصدارات السابقة أيضًا. اسحب البلاطات إلى ترتيبك الخاص تحت **المظهر**. وحيث يضيّق عمود من البلاطات بجانب الصفحة عليها، كما في نافذة بعرض نحو 1200 بكسل، تتحول البلاطات إلى شريط فوق الصفحة يُمرَّر أفقيًا. ويعرض الهاتف الشريط نفسه.
- **الوجهات** و**المثيلات** بلاطتا إعدادات لهما صفحتان خاصتان. **العرض أيضًا في الشريط الجانبي** على بلاطتهما يثبّتهما في الشريط الجانبي.

لا زر حفظ لأي شيء ولا شيء ينطوي: للنادر بطاقة خاصة أو نافذة، والشروح في فقاعات (i). بعد تحديث تُفتح نافذة وحدها ببطاقة لكل إصدار منذ إصدارك الأخير، وتعلّم النقاط الخضراء ما تغيّر. النقر يخفي النقطة. **جديد** في بطاقة الإصدار ضمن **الإعدادات، معلومات** يعدّ ما لم تَرَه بعد ويفتح تلك النافذة ثانية، مع ملاحظات كل إصدار وتغييراته مع **الانتقال إلى هناك**.

## البناء من المصدر {#build-from-source}

BombVault ملف ثنائي Go ساكن واحد يخدم JSON API وواجهة React مضمّنة. ابنِ الواجهة أولًا، ثم شغّل الملف الثنائي:

```bash
npm --prefix web ci
npm --prefix web run build     # writes web/dist, which the binary embeds
export APP_KEY=$(openssl rand -hex 32)
go test ./...                  # unit and integration tests, with a real restic round trip
golangci-lint run ./...
go run ./cmd/bombvault         # serves https://localhost:3443 with a self-signed certificate
```

بناء الواجهة مطلوب لـ `go run` أيضًا. يتتبع المستودع علامة فارغة فقط تحت `web/dist`، فبدون `npm --prefix web run build` لا يضمّن الملف الثنائي شيئًا ويجيب `500 SPA index not found`، وهذا متوقع. لا يمكن اختبار Docker وlibvirt وUnraid في CI، لذا افحص التركيبات وrestic واتصال SSH للأجهزة الافتراضية على مضيف حقيقي بواسطة بطاقة **تكامل المضيف** في النظرة العامة (أو `GET /api/spike`) قبل أن تفتح pull request.

## الخطوات التالية {#next-steps}

- أضف وجهة أو أكثر خارج المقر (يمكن لكل قسم النسخ إلى عدة وجهات معًا) واحفظ حقيبة الاستعادة كما هو موصوف تحت **[خارج الموقع والاستعادة](offsite-recovery.md)**. يشرح [مثال S3](offsite-recovery.md#example-s3) واحدة خطوة بخطوة.
- تأكد من وصول أي فشل إليك عبر **[الإشعارات](notifications.md)**.
- تحقق من أوقات التشغيل تحت **[الجداول](schedules.md)**.
- ضع كل خادم في مجموعتك على هاتفك بـ **[تطبيق Android](android.md)**.
- تمرّ **[الأمثلة خطوة بخطوة](guides.md)** على المهام الشائعة، وتسرد **[الميزات](features.md)** كل ما يفعله BombVault.
- تستنسخ إعدادًا أو تنتقل إلى جهاز جديد؟ انقل إعداداتك كلها ببطاقة **تصدير / استيراد الإعدادات**. راجع [التهيئة](configuration.md#portable-settings-export-and-import).
- واجهت عقبة؟ راجع **[استكشاف الأخطاء](troubleshooting.md)**.
