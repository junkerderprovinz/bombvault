# นอกสถานที่และการกู้คืน

!!! note "สำเนานอกสถานที่รอหลังการสร้างใหม่"
    เมื่อตัวช่วยฉุกเฉินหรือ **ค้นหาการสำรองข้อมูล** สร้างรายการขึ้นใหม่โดยไม่มีการตั้งค่าเดิม สำเนานอกสถานที่ของส่วนเหล่านั้นจะหยุดชั่วคราวจนกว่าจะยืนยันค่าเริ่มต้นของมัน ดู [หลังการสร้างใหม่](#after-a-rebuild)

ข้อมูลสำรองในเครื่องปกป้องคุณจาก container ที่หายหรือการอัปเดตที่เสีย สำเนานอกสถานที่และชุดกู้คืนที่ทดสอบแล้วปกป้องคุณจากการสูญเสียทั้งเครื่อง แรนซัมแวร์ หรือไฟไหม้ หน้านี้ครอบคลุมปลายทางและสำเนานอกสถานที่ การทำให้สำเนากันการแทรกแซง การพิสูจน์ว่ากู้คืนได้ การจับคู่หลายเซิร์ฟเวอร์ และการนำทุกอย่างกลับมาเมื่อ BombVault เองหายไป

## สำเนานอกสถานที่ {#off-site-copies}

เก็บข้อมูลสำรองในเครื่องที่เร็วไว้และเพิ่มปลายทางนอกสถานที่หนึ่งแห่งหรือมากกว่า BombVault คัดลอกสแนปช็อตใหม่ไปที่นั่นด้วย `restic copy` แบบทำเท่าที่ทำได้ ปัญหานอกสถานที่จึงไม่ทำให้การสำรองในเครื่องล้มเหลว ในรูปแบบนี้รีพอสิทอรีในเครื่องเป็นหลักและรีพอสิทอรีนอกสถานที่เป็นสำเนา แต่รีพอสิทอรีหลักของส่วนไม่จำเป็นต้องอยู่ในเครื่องเลย ดู [ที่เก็บหลักระยะไกล](#remote-primary-repositories) ด้านล่างสำหรับการสำรองตรงไปที่ S3, rest-server และอื่น ๆ แทนที่จะคัดลอกไปที่นั่น

- **หลายปลายทางต่อส่วน** แต่ละส่วน (containers, VMs, flash, สำรองข้อมูลตัวเอง, โฟลเดอร์ และชุดข้อมูล ZFS) คัดลอกไปยังหลายปลายทางนอกสถานที่พร้อมกันได้ เช่นเก็บ rest-server บนเครื่องของเพื่อนกับบักเก็ต S3 ควบคู่กัน การ์ด **ปลายทางแยกตามส่วน** บนหน้าปลายทางเปิดหรือปิดแต่ละเส้นจากส่วนไปยังปลายทาง
- **การคัดลอกรันเมื่อไร** การ์ด **คัดลอก** ของปลายทางกำหนด **คัดลอกเมื่อไร**: **หลังการสำรองข้อมูลทุกครั้ง** หรือตามแผนของตัวเองที่รวบรวมสแนปช็อตแล้วคัดลอกตามเวลาที่กำหนด ใต้ **การตั้งค่า, ตารางเวลา, สำเนานอกสถานที่รายโดเมน** ปุ่ม **ข้อยกเว้น** ให้ส่วนหนึ่งมีแผนคัดลอกของตัวเอง **จำลองตอนนี้** ในการ์ดสำเนานอกสถานที่ของส่วนใต้ **การตั้งค่า, ปลายทาง** เริ่มการคัดลอกตามต้องการ
- **การเก็บรักษา** กำหนดต่อปลายทางใต้ **เก็บไว้นานแค่ไหน** คุณจึงเก็บสำเนานอกสถานที่ไว้นานกว่าเป็นที่เก็บถาวรได้ สำเนาในช่องนอกสถานที่ของส่วนเป็นไปตามการ์ด **การเก็บรักษานอกสถานที่** ใต้ **การตั้งค่า, ปลายทาง** ปล่อยให้เป็นศูนย์ทั้งหมดเพื่อไม่ตัดสแนปช็อตนอกสถานที่โดยอัตโนมัติ
- **ขีดจำกัดแบนด์วิดท์** (**แบนด์วิดท์นอกสถานที่** ใต้ **การตั้งค่า, ปลายทาง** หรือการ์ด **คัดลอก** ของปลายทาง) จำกัดอัตราการอัปโหลด/ดาวน์โหลดของ restic เพื่อไม่ให้การคัดลอกทำให้ WAN ของคุณเต็ม
- ขณะที่การคัดลอกรันอยู่ ส่วนหัวสถานะของภาพรวมจะบอกว่า **กำลังคัดลอกนอกสถานที่** เป็นตัวบ่งชี้การทำงาน ไม่ใช่แถบเปอร์เซ็นต์ เพราะ `restic copy` ไม่เปิดเผยความคืบหน้าที่เครื่องอ่านได้

!!! note "กู้คืนจากที่ใดก็ได้"
    ทุกรายการแสดงข้อมูลสำรองของมันเป็นเส้นเวลาเดียวข้ามทุกที่ที่มีข้อมูลสำรองอยู่ บนแท็บ **การสำรองข้อมูล** ข้อมูลสำรองที่คัดลอกไป B2 ปรากฏครั้งเดียว ทำเครื่องหมายทุกที่ที่เก็บมันไว้ การกู้คืนใช้ที่แรกที่เข้าถึงได้ เริ่มจากรีพอสิทอรีที่รายการถูกเขียนลง และคุณเลือกที่อื่นต่อสแนปช็อตได้ ปลายทางนอกสถานที่ถูกอ่านเมื่อคุณคลิก **ตรวจสอบ** เท่านั้น เพราะการแสดงรายการที่จัดเก็บบนคลาวด์ใช้เวลา การลบที่ที่หนึ่งจะตรวจที่อื่นก่อนและบอกว่าเป็นสำเนาสุดท้ายหรือไม่

## ปลายทาง {#destinations}

ปลายทางคือที่ที่ข้อมูลสำรองไป: โฟลเดอร์ในเครื่อง แชร์ เซิร์ฟเวอร์ของคุณเอง หรือบริการคลาวด์ ตั้งค่าครั้งเดียวแล้วใช้กับทุกส่วน เปิด **ปลายทาง** จากไทล์การตั้งค่าของมัน หรือเปิด **แสดงในแถบด้านข้างด้วย** ที่นั่นเพื่อปักหมุด

**เพิ่มปลายทาง** เปิดหน้าต่างสี่ขั้นตอน:

1. **ผู้ให้บริการ** ทุกบริการแสดงพร้อมโลโก้ มีช่องค้นหาด้านบน แบ่งเป็นกลุ่ม: บริการที่จัดเก็บที่มีบักเก็ต S3 (Backblaze B2, Wasabi, Cloudflare R2, Hetzner Object Storage, Amazon S3 และอื่น ๆ) เซิร์ฟเวอร์ S3 ของคุณเอง (Garage, SeaweedFS, RustFS, Silo, Ceph, JuiceFS, Versity S3 Gateway) เซิร์ฟเวอร์และแชร์ของคุณเอง (rest-server, Hetzner Storage Box, SFTP, SMB, WebDAV, พาธที่เมานต์) ที่จัดเก็บบนคลาวด์ (OneDrive, Google Drive, Dropbox, pCloud, Nextcloud และที่เหลือที่ rclone รองรับ) และเซิร์ฟเวอร์รับข้อมูลของกลุ่มคุณ แต่ละอันบอกว่าเหมาะกับข้อมูลสำรองแค่ไหน: ไดรฟ์คลาวด์ช้าลงเมื่อมีคำขอมาก การสำรองครั้งแรกและการตัดทิ้งจึงใช้เวลานานกว่าที่นั่น
2. **ลงชื่อเข้าใช้** ช่องขึ้นอยู่กับบริการ: คีย์เข้าถึงสำหรับ S3 ผู้ใช้และรหัสผ่านสำหรับ WebDAV และ SMB รหัสผ่านแอปในที่ที่การลงชื่อเข้าใช้สองขั้นตอนบล็อกรหัสปกติ คีย์ SSH สาธารณะของ BombVault สำหรับ SFTP และ Storage Box หรือโทเค็นสำหรับบริการที่ลงชื่อเข้าใช้ผ่านเบราว์เซอร์ สำหรับบริการเหล่านั้น หน้าต่างแสดงคำสั่ง `rclone authorize` ให้รันบนคอมพิวเตอร์ที่มีเบราว์เซอร์ โทเค็นที่มันพิมพ์ออกมาใส่ในช่อง **ทดสอบ** ตรวจการลงชื่อเข้าใช้ก่อนบันทึกอะไร จากนั้นหน้าต่างแสดงโฟลเดอร์บนปลายทาง พร้อม **โฟลเดอร์ใหม่** สำหรับสร้างและพื้นที่ว่างที่บริการรายงาน โฟลเดอร์ว่างปลอดภัยที่สุด BombVault ใส่หนึ่งโฟลเดอร์ต่อส่วนไว้ข้างใน
3. **การป้องกัน** หน้าต่างบอกตรง ๆ ว่าบริการทำอะไรได้ rest-server ในโหมด append-only ปฏิเสธการลบ และการทดสอบการแทรกแซงตรวจสิ่งนั้น บักเก็ต S3 เก็บเวอร์ชันเก่าได้ด้วย versioning และ object lock ซึ่ง BombVault ยังตรวจไม่ได้ ไดรฟ์คลาวด์ปฏิเสธการลบไม่ได้เลย: ใครที่เข้าเซิร์ฟเวอร์ได้ก็เข้าสำเนานั้นได้ด้วย เปิด **การป้องกันการลบ (append-only)** เฉพาะที่ฝั่งไกลปฏิเสธการลบจริง ๆ BombVault ก็จะไม่ตัดทิ้งที่นั่นเลย **สำหรับกรณีฉุกเฉิน** บอกว่าชุดกู้คืนมีอะไรสำหรับปลายทางนี้
4. **สำหรับส่วนใด** เลือกส่วนที่สำรองมาที่นี่ การคัดลอกครั้งแรกนำประวัติทั้งหมดมาด้วย รายการที่เลือกปลายทางของตัวเองจะไม่ได้ปลายทางใหม่เอง และหน้าต่างระบุชื่อรายการเหล่านั้น

บริการ S3 รันผ่านแบ็กเอนด์ S3 ของ restic เอง ซึ่งทำให้คลาสพื้นที่จัดเก็บและ object lock ใช้ได้ บริการอื่นทั้งหมดรันผ่าน rclone ที่ BombVault แถมมา และรีโมตของมันปรากฏในการ์ด **นอกสถานที่ (rclone)** ใต้ **การตั้งค่า, ปลายทาง** การส่งออกการตั้งค่าพาปลายทางไปด้วย และถ้ารวมข้อมูลรับรองก็พาการลงชื่อเข้าใช้ของมันไปด้วย

แต่ละปลายทางมีหน้าของตัวเอง:

- **การเชื่อมต่อ** พร้อมชื่อ สวิตช์ **พร้อมใช้งาน** (ปิดหมายถึง BombVault ไม่เขียนที่นี่อีก และรายการที่สำรองที่นี่ล้มเหลวพร้อมข้อความชัดเจนแทนที่จะไปลงที่อื่น) โฟลเดอร์ การบีบอัด คลาสพื้นที่จัดเก็บ และ **นอกสถานที่** **เปลี่ยนการเชื่อมต่อ** ทดสอบและบันทึกที่อยู่หรือการลงชื่อเข้าใช้ใหม่
- **ข้อมูลรับรอง**: ชุดที่ใช้ร่วมกันหรือชุดของตัวเอง
- **การป้องกันการลบ** พร้อม **ทดสอบการป้องกันการลบตอนนี้** และใครตัดทิ้งสำเนานี้
- **คัดลอก**: คัดลอกเมื่อไร และขีดจำกัดการอัปโหลดและดาวน์โหลด
- **เก็บไว้นานแค่ไหน**: **สั้น**, **สมดุล**, **ยาว** หรือ **ค่าที่กำหนดเอง** พร้อมเส้นเวลาว่ากฎเก็บข้อมูลสำรองชุดใดไว้ **ถามก่อนเก็บน้อยลง** ถามก่อนที่กฎสั้นลงจะลบข้อมูลสำรองที่มีสำเนาเดียวอยู่ที่นี่
- **กฎแยกตามส่วน**: รีพอสิทอรี การเก็บรักษา หรือการบีบอัดของส่วนหนึ่งที่ปลายทางนี้ **เปลี่ยนกฎ** เปิดกฎเหล่านั้น และ **คืนค่าตามปลายทาง** นำส่วนกลับมา
- **อยู่ใต้ปลายทางแล้ว**: ส่วนที่ที่อยู่ซึ่งพิมพ์เองอยู่ในโฟลเดอร์ของปลายทางนี้ การรับช่วงปล่อยรีพอสิทอรีไว้ที่เดิม การลงชื่อเข้าใช้ คลาสพื้นที่จัดเก็บ และการป้องกันการลบมาจากปลายทางหลังจากนั้น BombVault ตรวจก่อนว่าการลงชื่อเข้าใช้ของปลายทางเปิดรีพอสิทอรีได้ และปฏิเสธที่จะวางรีพอสิทอรี append-only ใต้ปลายทางที่ไม่ใช่ append-only
- ภาชนะที่แสดงว่าปลายทางเต็มแค่ไหน พร้อมเครื่องหมายว่าเต็มที่ไหนและเหลือกี่สัปดาห์ตามอัตราการเติบโตของไม่กี่สัปดาห์ที่ผ่านมา ปลายทางที่ไม่รายงานขนาดจะแสดง **ไม่ทราบขนาด**

เซิร์ฟเวอร์รับข้อมูลที่อินสแตนซ์อื่นในกลุ่มของคุณรันอยู่ ปรากฏในกลุ่มผู้ให้บริการเป็น **จากกลุ่มของคุณ** ดู [เซิร์ฟเวอร์รับข้อมูล](#receiving-server)

### การย้ายและการนำออก {#move-remove}

- **ย้าย** นำสำเนาของส่วนหนึ่งพร้อมประวัติทั้งหมดไปยังปลายทางอื่น ทุกอย่างอยู่ที่เดิม BombVault ไม่ลบอะไรที่นั่น การย้ายรันในเบื้องหลังและอาจใช้เวลานาน: ประมาณ 9 นาทีต่อ 100 GB ระหว่างดิสก์ในเครื่อง หลายชั่วโมงผ่านลิงก์ที่ช้า ภาพรวมแสดงมันขณะรัน
- **ลบปลายทาง** มีสองทาง **ลบปลายทางแต่เก็บข้อมูลสำรอง** หยุดเขียนที่นั่นและปล่อยข้อมูลสำรองไว้ คุณอ่านได้ภายหลังที่ **กู้คืน, จากโฟลเดอร์สำรองข้อมูลเก่า** **ลบปลายทางและลบข้อมูลสำรองที่นั่น** อ่านสิ่งที่เก็บไว้ที่นั่นก่อนและแสดงรายการ: ข้อมูลสำรองชุดใดจะหายไป ชุดใดไม่มีที่อื่น และรีพอสิทอรีใดคงอยู่เพราะการป้องกันการลบปฏิเสธ รายการยังสำรองตรงมาที่มัน ปลายทางหรือส่วนอื่นเก็บสำเนาไว้ที่นั่น หรืออ่านไม่ได้ รายการที่จะเสียข้อมูลสำรองชุดเดียวของมันถูกแสดงแยกและคงไว้เว้นแต่คุณติ๊ก **ลบรายการเหล่านี้ด้วย** คุณยืนยันด้วยการพิมพ์ชื่อปลายทาง และการลบรันในเบื้องหลัง
- การลบข้อมูลสำรองที่ปลายทางต้องมีรหัสผ่านเข้าสู่ระบบและการเข้าสู่ระบบที่อินสแตนซ์นั้น หากไม่มีรหัสผ่าน ปลายทางก็ยังลบออกได้ เพียงลบข้อมูลสำรองของมันจากที่นี่ไม่ได้

## การจัดวางต่อรายการ {#placement}

การ์ด **ตารางเวลาและปลายทาง** บนแท็บการตั้งค่าของรายการมีแถวปุ่ม: **ในเครื่อง** และหนึ่งปุ่มต่อปลายทางนอกสถานที่ของส่วน ปุ่มที่สว่างได้รับข้อมูลสำรองของรายการ

- เมื่อ **ในเครื่อง** สว่าง รายการถูกเขียนลงรีพอสิทอรีที่แสดงใต้ **จัดเก็บที่** และคัดลอกไปยังทุกปลายทางอื่นที่สว่าง ทำให้ปลายทางมืดแล้วมันจะไม่ได้อะไรใหม่จากรายการนี้ ในเครื่องอย่างเดียวไม่คัดลอกไปที่ไหนเลย ซึ่งเหมาะกับข้อมูลที่มีสำเนาที่สองอยู่แล้ว เช่นแชร์ที่อยู่บน NAS
- เมื่อ **ในเครื่อง** มืด รายการถูกเขียนตรงไปยังรีพอสิทอรีโดยตรงของปลายทางแรกที่สว่างและคัดลอกจากที่นั่นไปยังปลายทางอื่นที่สว่าง ครั้งแรก หน้าต่างจะสร้างรีพอสิทอรีโดยตรงนั้น
- ปุ่มหนึ่งยังคงสว่าง เพราะข้อมูลสำรองต้องมีที่ไป หากต้องการเว้นรายการจากการสำรอง ใช้ **ไม่สำรองข้อมูล**

ตำแหน่งถูกตรึงตั้งแต่การสำรองครั้งแรกของรายการ เพราะ BombVault ไม่เคยย้ายข้อมูลสำรองระหว่างรีพอสิทอรี การ์ด **คลัง** บนแท็บการตั้งค่าระบุชื่อมัน สำเนาเปลี่ยนได้ทุกเมื่อ ปลายทางที่ไม่ได้รับรายการอีกยังเก็บสำเนาที่มีอยู่และตัดตามการเก็บรักษาของมันเองในการรันนอกสถานที่ครั้งถัดไปของส่วน ปลายทาง append-only ลบไม่ได้

ใต้แถว การ์ดบอกว่ารายการไปที่ไหนและมีอะไรอยู่จริง: มีกี่แห่งเก็บมัน เห็นแต่ละปลายทางล่าสุดเมื่อใด และ 3-2-1 ครบหรือไม่ แห่งหนึ่งคือเซิร์ฟเวอร์ที่มีข้อมูลต้นฉบับ แต่ละปลายทางนอกสถานที่ และแต่ละรีพอสิทอรีที่ทำเครื่องหมาย **นอกสถานที่** BombVault ตรวจสำเนาและที่ตั้ง ไม่ได้ตรวจส่วน "สองสื่อ" ของ 3-2-1

### ค่าเริ่มต้นต่อส่วน {#placement-defaults}

การ์ด **ปลายทางแยกตามส่วน** บนหน้าปลายทางคือค่าเริ่มต้นของทุกส่วน ในกราฟทุกเส้นคือหนึ่งสำเนา คลิกเส้นหรือจุดเพื่อเปิดหรือปิด เส้นประคือปิด **กราฟ / สวิตช์** แสดงสิ่งเดียวกันเป็นแถวปุ่ม สำเนามีผลทันทีกับทุกรายการที่ไม่มีตัวเลือกของตัวเอง และกับโฟลเดอร์โปรเจกต์ของ Compose stack ปลายทางใช้กับรายการใหม่ที่การสำรองครั้งแรก การเปลี่ยนไม่ย้ายข้อมูลสำรอง ก่อนบันทึก BombVault ระบุชื่อทุกปลายทางที่ได้หรือเสียรายการและนั่นหมายถึงกี่สแนปช็อต

รายการที่สำรองไปที่อื่นนอกจากส่วนของตัวเองอยู่ในการ์ด **การเลือกเอง** แต่ละรายการมี **ใช้ตามค่าเริ่มต้น** ข้อมูลสำรองใหม่ไปยังปลายทางของส่วน และข้อมูลก่อนหน้าอยู่ที่เดิม

ปลายทางนอกสถานที่ใหม่ได้รับทุกรายการที่ไม่ได้ตั้งเป็นในเครื่อง หน้าต่างที่เพิ่มมันบอกว่ามีกี่รายการและ ถ้าทราบ มีประวัติเท่าไร

### รีพอสิทอรีโดยตรง

การปิดในเครื่องสำหรับรายการ เพื่อให้ปลายทางที่ไม่มีรีพอสิทอรีโดยตรงเป็นที่อยู่ของมัน เปิดหน้าต่างที่มีตำแหน่งที่แนะนำอยู่ข้าง ๆ เช่น `s3:https://s3.eu-central-003.backblazeb2.com/bucket/containers-direct` และการทดสอบการเชื่อมต่อที่ไม่สร้างอะไร **สร้างและใช้งาน** สร้างรีพอสิทอรีและชี้รายการไปที่มัน รีพอสิทอรีโดยตรงรับคีย์ คลาสพื้นที่จัดเก็บ ขีดจำกัด การตั้งค่า append-only และการเก็บรักษาของปลายทาง และเปลี่ยนตามไปด้วย การ์ดคลังแสดงแบบอ่านอย่างเดียว เมื่อคีย์ใหม่ของปลายทางเปิดมันไม่ได้ รีพอสิทอรีโดยตรงคงคีย์ที่มีอยู่ และการบันทึกบอกเรื่องนี้ รายการบนรีพอสิทอรีโดยตรงถูกคัดลอกจากที่นั่นไปยังปลายทางอื่นที่สว่าง ไม่เคยไปยังปลายทางที่รีพอสิทอรีนั้นสังกัด สแนปช็อตของมันมีแท็ก `bv:direct` และการเก็บรักษารอบอื่นทั้งหมดคงไว้ ดังนั้นรีพอสิทอรีโดยตรงที่ขาดการเชื่อมกับปลายทางของมันจะไม่แก่ตามกฎในเครื่องเลย B2 เข้าถึงผ่านปลายทาง S3 โดยกรอก ID คีย์และคีย์แอปพลิเคชันเป็นข้อมูลรับรอง S3 คีย์ที่จำกัดเฉพาะโฟลเดอร์ของปลายทางเองเข้าถึงโฟลเดอร์ข้าง ๆ ไม่ได้ ให้จำกัดคีย์ที่โฟลเดอร์ระดับบนแทน

### นอกสถานที่

ปลายทางหรือรีพอสิทอรีที่ตั้งชื่อทำเครื่องหมาย **นอกสถานที่** ได้ ที่อยู่ระยะไกลเริ่มด้วยเครื่องหมาย ปิดมันสำหรับ rest-server ในอาคารเดียวกัน เครื่องหมายนับเฉพาะที่ตั้งและ 3-2-1 บนการ์ด มันไม่เปลี่ยนสำเนาใด ๆ

เรพลิกา ZFS คือสำเนานอกสถานที่ แต่ไม่ใช่ข้อมูลสำรองที่มีประวัติ มันเก็บเฉพาะสแนปช็อตที่คุณตั้ง และเวอร์ชันเก่ากับไฟล์เดี่ยวยังมาจากข้อมูลสำรอง มันไปจากเซิร์ฟเวอร์ ZFS เครื่องหนึ่งตรงไปอีกเครื่อง ผ่าน SSH ไปยังเซิร์ฟเวอร์ ZFS หรือจุดรับของอินสแตนซ์ที่จับคู่ กลุ่มการจับคู่ส่งเฉพาะคำขอ ดู [เรพลิกา](zfs-datasets.md#replica)

### หลังการสร้างใหม่ {#after-a-rebuild}

ตัวเลือกการคัดลอกอยู่ในการตั้งค่าของ BombVault เอง หลังการสร้างใหม่ผ่าน **ค้นหาการสำรองข้อมูล** หรือตัวช่วยฉุกเฉินโดยไม่กู้การตั้งค่า ตัวเลือกเหล่านั้นหายไป และการคัดลอกทุกอย่างจะส่งรายการที่คุณเว้นไว้ไป B2 อีก สำเนานอกสถานที่ของทุกส่วนที่สร้างใหม่จึงหยุดชั่วคราว ภาพรวมบอกเรื่องนี้ และการ์ด **ปลายทางแยกตามส่วน** เสนอ **ยืนยันค่าเริ่มต้น** พร้อมตัวอย่างสิ่งที่การรันครั้งถัดไปจะคัดลอกและชื่อในข้อมูลสำรองที่ไม่มีรายการ ซึ่งเว้นไว้ได้ที่นั่น มีเพียงการยืนยันที่ยุติการหยุด การนำเข้าไฟล์การตั้งค่านำกฎและค่าเริ่มต้นกลับมาแต่ไม่ยุติการหยุด

## ที่เก็บหลักระยะไกล {#remote-primary-repositories}

พาธของส่วนเองไม่ได้จำกัดเฉพาะโฟลเดอร์ในเครื่อง: ชี้ตรงไปที่รีโมต restic (`s3:...`, `rest:http://host:8000/repo`, `sftp:user@host:/repo`, `rclone:remote:bucket/path`) แล้ว BombVault สำรองตรงไปที่นั่นโดยไม่มีสำเนาในเครื่องแยกและไม่มีขั้นตอนคัดลอก นี่เป็นรูปแบบต่างจากสำเนานอกสถานที่ข้างต้น: ที่นั่นรีพอสิทอรีในเครื่องเป็นหลักและรีพอสิทอรีนอกสถานที่เป็นที่เก็บถาวรแบบทำเท่าที่ทำได้ ที่นี่รีพอสิทอรีระยะไกล**คือ**ตัวหลักและเป็นสำเนาเดียว เว้นแต่คุณคัดลอกส่วนนั้นไปยังปลายทางอื่นด้วย

พาธของแต่ละส่วน (Containers, VMs, Flash, สำรองข้อมูลตัวเอง, โฟลเดอร์, ชุดข้อมูล ZFS) ตั้งบนหน้าของปลายทาง **โฟลเดอร์ในเครื่อง**: **เปลี่ยน** ข้างส่วนในการ์ด **การเชื่อมต่อ** เปิดหน้าต่างที่มีสวิตช์ **ในเครื่อง / ระยะไกล**:

- **ในเครื่อง** แสดงตัวเรียกดูโฟลเดอร์ที่คุ้นเคย
- **ระยะไกล** สลับเป็นช่อง URL ธรรมดาและการตั้งค่าการเชื่อมต่อที่ปลายทางนอกสถานที่ใช้ ตั้งค่าไว้สำหรับตัวหลักนี้แทน จากที่นั่นคุณได้:
    - **การทดสอบการเชื่อมต่อ** กับพาธจริง ก่อนที่คุณจะพึ่งพามัน
    - **ขีดจำกัดแบนด์วิดท์** (อัปโหลด/ดาวน์โหลด) เพื่อให้การสำรองตามตารางเวลาไปยังที่เก็บหลักระยะไกลไม่ทำให้ WAN ของคุณเต็ม: แฟล็ก restic `--limit-upload`/`--limit-download` เดียวกับที่สำเนานอกสถานที่ใช้ นำมาใช้กับการสำรองเอง
    - **การป้องกัน append-only** ตรวจสอบด้วยการทดสอบการแทรกแซงเชิงรุกเดียวกัน (โพรบ DELETE จริงไปยังฝั่งไกล) ที่ปลายทางนอกสถานที่ได้รับ เมื่อเปิด BombVault ปฏิเสธที่จะตัดทิ้งรีพอสิทอรีเอง เพราะไม่มีสำเนาในเครื่องแยกอยู่เบื้องหลัง และข้อมูลรับรองบนเครื่องนี้ต้องลบสำเนาเดียวของข้อมูลสำรองไม่ได้
    - **สัญญาณเตือนงบประมาณการเติบโต** สุ่มจากแนวโน้มขนาดรีพอสิทอรีเดียวกับที่การ์ดที่จัดเก็บติดตามอยู่แล้ว

ไม่มีอะไรข้างต้นเป็นสิ่งจำเป็น: พาธระยะไกลที่พิมพ์เองโดยไม่มีการตั้งค่าความปลอดภัยที่บันทึกไว้จะสำรองแบบไม่จำกัด ตัดทิ้งได้ และไม่มีสัญญาณเตือนงบประมาณ การตั้งค่าความปลอดภัยมีไว้เมื่อคุณต้องการการป้องกันที่สำเนานอกสถานที่ได้รับ โดยไม่ต้องมีปลายทางแยกเพียงเพื่อสิ่งนั้น

!!! note "ข้อมูลรับรองคลาวด์/REST ใช้ร่วมกัน"
    ที่เก็บหลักระยะไกลยืนยันตัวตนด้วยข้อมูลรับรองคลาวด์ที่ใช้ร่วมกันใต้ **การตั้งค่า, ปลายทาง** ไม่มีที่เก็บข้อมูลรับรองแยกสำหรับรีพอสิทอรีหลัก

### SMB และ WebDAV โดยไม่ต้องเมานต์บนโฮสต์ {#smb-webdav}

การ์ด **นอกสถานที่ (rclone)** ใต้ **การตั้งค่า, ปลายทาง** มีแบบฟอร์มสำหรับแชร์ Windows หรือ Samba และเซิร์ฟเวอร์ WebDAV (Nextcloud, ownCloud, SharePoint หรืออื่น ๆ) กรอกชื่อสั้น โฮสต์และแชร์ (SMB) หรือ URL และชนิดเซิร์ฟเวอร์ (WebDAV) ผู้ใช้และรหัสผ่าน แล้ว BombVault เขียนส่วน rclone ให้ rclone ทำให้รหัสผ่านอ่านไม่ออกเองก่อนเก็บ การเพิ่มด้วยชื่อที่มีอยู่แล้วจะแทนที่ส่วนนั้นแทนที่จะเพิ่มส่วนที่สอง **เพิ่มปลายทาง** เสนอ SMB และ WebDAV เป็นผู้ให้บริการด้วยช่องเดียวกัน

แบบฟอร์มตอบด้วยปลายทางที่เสร็จแล้ว เช่น `rclone:nas:backups` ใช้เป็นพาธของส่วนหรือปลายทางและเพิ่มโฟลเดอร์ย่อยถ้าต้องการ (`rclone:nas:backups/bombvault`) แชร์คือส่วนแรกของพาธ ไม่ใช่ส่วนของชื่อ

นี่เป็นทางที่ดีกว่าการเมานต์แชร์บน Unraid: restic ไม่แนะนำให้เก็บรีพอสิทอรีบนแชร์ CIFS ที่เมานต์ และที่นี่ไม่ได้เมานต์อะไร NFS ไม่อยู่ในแบบฟอร์มเพราะทั้ง restic และ rclone ไม่มีแบ็กเอนด์ NFS สำหรับ NFS ให้เมานต์ export บนโฮสต์แล้วใช้เป็นโฟลเดอร์ในเครื่อง

## การป้องกันการลบ (append-only)

เปิดการป้องกันการลบสำหรับปลายทางนอกสถานที่ เพื่อไม่ให้แรนซัมแวร์หรือโฮสต์ที่ถูกบุกรุกลบหรือเขียนทับข้อมูลสำรองของคุณ ฝั่งไกล (`restic/rest-server` ที่รันในโหมด `--append-only`) **บังคับใช้** BombVault เพียง**ตรวจสอบ**และไม่เคยแสดงสีเขียวจากคำกล่าวอ้างในการตั้งค่าอย่างเดียว โฟลเดอร์บนเซิร์ฟเวอร์นี้ปฏิเสธการลบไม่ได้ เพราะใครควบคุม BombVault ก็ควบคุมโฟลเดอร์ด้วย ปลายทางในเครื่องจึงไม่มีสวิตช์นี้

ทางที่เร็วที่สุดสู่สำเนา append-only คือ BombVault ที่จับคู่กันซึ่งมี[เซิร์ฟเวอร์รับข้อมูล](#receiving-server): มันรัน rest-server ให้คุณในโหมด append-only

!!! note "การลบที่สำเร็จใต้ `/locks/` เป็นเรื่องที่คาดไว้"
    Append-only ไม่ได้หมายความว่าลบอะไรไม่ได้เลย restic ต้องรับและปล่อยล็อกของตัวเอง `/locks/` จึงเขียนและลบได้โดยการออกแบบ สแนปช็อตและข้อมูลที่อยู่เบื้องหลัง ซึ่งเป็นสิ่งที่แรนซัมแวร์จะมุ่งเป้า ลบไม่ได้ หากคุณทดสอบฝั่งไกลเอง การลบที่สำเร็จใต้ `/locks/` เป็นพฤติกรรมที่ถูกต้องและไม่ใช่ช่องโหว่ในการป้องกัน

!!! warning "รีพอสิทอรี append-only ไม่เคยถูกตัดทิ้งจากเครื่องนี้"
    ปลายทาง append-only ไม่ตัดสแนปช็อตเก่าจากที่นี่เลย การตัดทิ้งเป็นหน้าที่ของฝั่งไกล ตั้ง **สัญญาณเตือนงบประมาณการเติบโต** ให้มันเพื่อรับการเตือนก่อนที่ขนาดรีพอสิทอรีจะบานปลาย

## การทดสอบการแทรกแซง

BombVault พิสูจน์การรับประกัน append-only เป็นระยะโดยพยายามลบจริงกับรีพอสิทอรีนอกสถานที่ เล็งที่วัตถุที่ไม่มีอยู่ **ทดสอบการป้องกันการลบตอนนี้** บนหน้าของปลายทางรันตามต้องการ และ **ตรวจสอบการป้องกันการลบ** ใต้ **การตั้งค่า, ยืนยัน, การตรวจสอบอัตโนมัติ** รันตามตารางเวลา

- **ถูกปฏิเสธ** หมายถึงได้รับการป้องกัน
- **ถูกยอมรับ** หมายถึงไม่ได้รับการป้องกัน
- ผลที่**สรุปไม่ได้** (เซิร์ฟเวอร์เข้าถึงไม่ได้ ข้อผิดพลาดการยืนยันตัวตน) ไม่เคยพลิกคำตัดสินที่เก็บไว้

การพลิกจากได้รับการป้องกันเป็นไม่ได้รับการป้องกันจริงจะส่งการเตือนเพียงครั้งเดียว

## การซ้อม DR

BombVault เสนอการพิสูจน์สองระดับว่าข้อมูลสำรองของคุณกู้คืนได้จริง ไม่ใช่แค่มีอยู่

- **การซ้อมตรวจสอบการกู้คืน (ในเครื่อง)** BombVault รัน `restic check --read-data-subset` เป็นระยะ (มีขอบเขต ไม่ใช่การกู้คืนเต็มที่ทำให้ดิสก์เต็ม) รอบอยู่ใต้ **การตั้งค่า, ยืนยัน, การตรวจสอบอัตโนมัติ** และการ์ด **ตรวจสอบข้อมูลสำรอง** บนไทล์เดียวกันแสดงผล
- **การกู้คืนทดลอง (นอกสถานที่)** BombVault กู้คืนเป้าหมายจริงจากรีพอสิทอรีนอกสถานที่ลงแซนด์บ็อกซ์ที่แยกออก ตรวจสอบทีละไฟล์และทีละไบต์ แล้วทำความสะอาด นี่พิสูจน์ว่าคุณกู้คืนจากนอกสถานที่ได้ ไม่ใช่แค่รีพอสิทอรีตอบสนอง

การ์ด **สถานะการป้องกัน** บนภาพรวมสรุปสิ่งนี้ต่อส่วนเป็นการตรวจสี่อย่าง: ข้อมูลสำรองปัจจุบันบนเซิร์ฟเวอร์นี้ สำเนานอกสถานที่ การป้องกันการลบที่นั่น และการกู้คืนทดลองจากที่นั่น การคลิกที่ส่วนแสดงรายละเอียด และการ์ดเป็นสีเขียวเฉพาะเมื่อมีข้อเท็จจริงที่ตรวจสอบแล้ว

## การจับคู่อินสแตนซ์ {#pairing}

BombVault หลายเครื่องทำงานร่วมกันเป็นกลุ่ม: แสดงสถานะการป้องกันของกันและกัน รับบทบาทให้กัน และเก็บคีย์ของกันและกันได้ อินสแตนซ์เข้าร่วมกลุ่มด้วยคำสิบสองคำ

บนอินสแตนซ์แรก เปิด **การตั้งค่า, การจับคู่** แล้วกด **สร้างวลี** การ์ดสามขั้นตอนแสดงวิธีทำ คำสิบสองคำปรากฏในหน้าต่างพร้อมปุ่ม **คัดลอก** บนทุกอินสแตนซ์อื่น เปิดที่เดียวกัน กด **ป้อนวลี** แล้ววางหรือพิมพ์ หรือกด **วาง** ในหน้าต่างนั้น คำที่ไม่อยู่ในรายการจะถูกระบุพร้อมตำแหน่งขณะที่คุณพิมพ์ และคำสุดท้ายมีเช็กซัม คำที่พิมพ์ผิดหรือสลับจึงถูกจับได้ก่อนจะจับคู่อะไร สร้างวลีบนอินสแตนซ์เดียวเท่านั้น: สองอินสแตนซ์ที่ต่างสร้างวลีเองจะเป็นสองกลุ่มแยกกัน หากไม่มีใครปรากฏภายในหนึ่งนาที หน้ามีสองทางออก: แสดงคำอีกครั้งเพื่อป้อนที่นั่น หรือป้อนคำของอินสแตนซ์อื่นและเข้าร่วมกลุ่มของมันในขั้นตอนเดียว การจับคู่ทำงานได้โดยไม่มีรหัสผ่านเข้าสู่ระบบ แต่ควรตั้งไว้: หากไม่มี ใครก็ตามที่เปิดเว็บอินเทอร์เฟซได้อ่านคำเหล่านั้นได้ และผ่านกลุ่มขอบทบาทที่ส่งมอบรหัสผ่าน restic ของอินสแตนซ์ในกลุ่มได้ การ์ดการจับคู่บอกเรื่องนี้จนกว่าจะตั้งรหัสผ่าน เมื่อมีรหัสผ่าน การแสดงวลีอีกครั้งจะขอรหัสผ่าน **ออกจากกลุ่ม** นำอินสแตนซ์ออกอีกครั้ง

ใครก็ตามที่รู้คำเหล่านี้เข้าร่วมกลุ่มได้ จึงปฏิบัติต่อมันเหมือนรหัสผ่าน

**สมาชิกติดต่อกันอย่างไร** แต่ละอินสแตนซ์เรียนรู้ที่อยู่ของตัวเองบนเครือข่ายจากเบราว์เซอร์ของคุณทันทีที่คุณลงชื่อเข้าใช้ แสดงใต้ **ที่อยู่ที่รู้จัก** บนหน้าการจับคู่พร้อมที่อยู่ที่อินสแตนซ์พบเอง แก้ที่นั่นหากมี reverse proxy หรือพอร์ตผิดปกติอยู่ด้านหน้า บนเครือข่ายเดียวกัน สมาชิกประกาศที่อยู่นั้นด้วยมัลติคาสต์และคุยกันโดยตรง และในที่ที่มัลติคาสต์ข้ามเครือข่ายคอนเทนเนอร์ไม่ได้ เช่นบริดจ์เริ่มต้นของ Docker อินสแตนซ์จะค้นซับเน็ตของตัวเองหาตัวอื่นด้วยการเรียกที่ลงนามซึ่งมีเพียงสมาชิกกลุ่มตอบได้ การจับคู่จึงเสร็จในไม่กี่วินาทีโดยไม่ต้องมีรีเลย์ หากไม่พบอะไร **หาไม่เจอหรือไม่** รับที่อยู่หนึ่งแห่งที่พิมพ์เอง สำหรับซับเน็ตอื่นหรือพอร์ตที่ไม่ใช่มาตรฐาน อินสแตนซ์บนเครือข่ายต่างกันผ่านรีเลย์ ซึ่งเลือกบนหน้าเดียวกัน แต่ละรูปแบบทั้งสี่มีภาพประกอบ:

- **รีเลย์ของโปรเจกต์** (ค่าเริ่มต้น): `parleyport.halleluja.design` ซึ่งเป็นรีเลย์ที่ KnightLoader ใช้ด้วย ไม่ต้องตั้งค่าอะไร
- **รีเลย์ของตัวเอง**: container [**ParleyPort**](https://github.com/junkerderprovinz/parleyport) จาก Unraid Community Apps (อยู่ใต้ **การตั้งค่า, แอป** ด้วย) หรืออินสแตนซ์ของคุณที่เข้าถึงจากภายนอกได้อยู่แล้วโดยเปิด **ทำหน้าที่เป็นรีเลย์** อินสแตนซ์นั้นตอบที่ `/relay/connect` บนที่อยู่ของตัวเอง หลัง reverse proxy และใบรับรองที่มีอยู่แล้ว และให้เข้าเฉพาะกลุ่มของคุณ ป้อนที่อยู่ของรีเลย์บนทุกอินสแตนซ์ที่ควรใช้มัน
- **ไม่มีรีเลย์**: สมาชิกพบกันโดยอัตโนมัติบนเครือข่ายเดียวกัน และไม่ที่ไหนอีก

**รีเลย์เห็นอะไร** ทุกการเรียกระหว่างสมาชิกถูกปิดผนึกด้วย AES-256-GCM ภายใต้คีย์ที่ได้จากคำสิบสองคำ และคีย์นั้นไม่ออกจากอินสแตนซ์ของคุณเลย รีเลย์รู้แฮชที่จัดกลุ่มการเชื่อมต่อ ข้อความนั้นสำหรับอินสแตนซ์ใด ขนาดเท่าไร และผ่านเมื่อใด การเรียกตรงบนเครือข่ายภายในถูกปิดผนึกแบบเดียวกันและลงนามด้วย ดังนั้นไม่มีอะไรขึ้นกับใบรับรองแบบ self-signed ที่อินสแตนซ์ให้บริการ การเรียกที่ส่งมอบบางอย่าง (คำตอบบทบาท รหัสผ่าน restic การเข้าสู่ระบบของผู้รับ สำเนาคีย์ที่ฝากไว้) ถูกลงนามด้วยคีย์ของสมาชิกที่ส่งด้วย ปักหมุดเมื่อเห็นครั้งแรก ดู [โมเดลความปลอดภัย](configuration.md#security-model)

**อะไรเดินทางผ่านกลุ่ม** สถานะการป้องกันบนหน้าอินสแตนซ์ คำขอให้ตรวจหนึ่งส่วนตอนนี้ คำขอบทบาทและคำตอบ ข้อเสนอที่จัดเก็บ และสิ่งที่ตัวรับหรือตัวดึงต้องใช้เมื่อบทบาทได้รับอนุญาต: ตำแหน่งรีพอสิทอรีของอินสแตนซ์อื่นและรหัสผ่าน restic ของมัน ข้อมูลสำรองไม่เคยเดินทาง มันยังไปตรงที่แบ็กเอนด์ restic APP_KEY ก็ไม่: รหัสผ่าน restic เปิดรีพอสิทอรีของอินสแตนซ์นั้นและไม่มีอย่างอื่น ไม่ใช่ความลับที่เก็บไว้ เซสชัน หรือรหัสกู้คืน

**รายการก่อนการจับคู่** อินสแตนซ์ที่เพิ่มด้วยโทเค็นฟลีต และรีพอสิทอรีที่รับมาและแหล่งดึงที่ตั้งด้วย APP_KEY ของอินสแตนซ์อื่น คงอยู่หลังการอัปเดตและทำเครื่องหมาย **จับคู่ใหม่** มันยังทำงานต่อ: ตอนเริ่มครั้งแรก BombVault แทนที่ APP_KEY ที่เก็บไว้ทุกตัวด้วยรหัสผ่าน restic ที่ได้จากมัน จับคู่ทั้งสองอินสแตนซ์ จากนั้นแก้ไขรายการและเลือกอินสแตนซ์ของมัน จนถึงตอนนั้นรายการเช่นนี้อยู่ในการ์ด **ไม่มีอินสแตนซ์** บนหน้าอินสแตนซ์

ที่เดียวที่ยังรับ APP_KEY ที่พิมพ์เองคือ [จากโฟลเดอร์สำรองข้อมูลเก่า](#restore-from-another-bombvault-repo) สำหรับกรณีที่อินสแตนซ์อื่นหายไปและตอบในกลุ่มไม่ได้

## อินสแตนซ์และบทบาท {#roles}

หน้า **อินสแตนซ์** (ไทล์การตั้งค่าที่ปักหมุดที่แถบด้านข้างได้) แสดงกลุ่มเป็นเครือข่ายว่าใครทำอะไรให้ใคร การ์ดสำหรับอินสแตนซ์นี้และการ์ดสำหรับสมาชิกอื่นทุกราย โทรศัพท์ Android และเซิร์ฟเวอร์ ZFS **จับคู่อินสแตนซ์** ลอยอยู่มุมขวาล่าง ส่วนใดเปิดอยู่ตั้งใต้ **การตั้งค่า, อินสแตนซ์, หลายเซิร์ฟเวอร์**: **อินสแตนซ์**, **ตัวรับ** และ **ดึง**

แต่ละการ์ดแสดงสถานะการป้องกันของสมาชิกและบทบาทเป็นไทล์ บทบาทคือสิ่งที่อินสแตนซ์หนึ่งทำให้อีกอินสแตนซ์:

- **ตัวรับ** เก็บสำเนานอกสถานที่ของเซิร์ฟเวอร์นี้ใน rest-server โหมด append-only เซิร์ฟเวอร์นี้ส่งหลังการสำรองทุกครั้งและลบอะไรที่นั่นไม่ได้ แม้มีคนยึดมันไป
- **ตัวดึง** ดึงข้อมูลสำรองของเซิร์ฟเวอร์นี้ตามตารางเวลาของตัวเอง เซิร์ฟเวอร์นี้ไม่ต้องตื่นอยู่เพื่อสิ่งนี้
- **เซิร์ฟเวอร์ ZFS** รับเรพลิกา ZFS ของเซิร์ฟเวอร์นี้ แต่ละรายการ ZFS เลือกมันใต้ **เรพลิกา** ในการตั้งค่าของมัน
- **ผู้เก็บคีย์** เก็บสำเนาที่ปิดผนึกของชุดกู้คืนของเซิร์ฟเวอร์นี้ ดู [ผู้เก็บคีย์](#key-keeper)

การเปิดบทบาทส่งคำขอ และไม่มีอะไรเริ่มจนกว่าจะมีคนบนอินสแตนซ์อีกฝั่งกด **อนุญาต** คำขอแสดงบนการ์ดของอินสแตนซ์นั้นเป็นป้าย และ **รายละเอียด** ของมันแสดงรายการพร้อม **อนุญาต** และ **ปฏิเสธ** บทบาทที่อนุญาตแล้วเพิกถอนได้ที่นั่นทุกเมื่อ เส้นประในเครือข่ายคือบทบาทที่ยังรออยู่ อินสแตนซ์บน BombVault 9.x ตอบคำขอไม่ได้ บทบาทจึงทำงานทันทีที่คุณเปิด และคำขอจากอินสแตนซ์ 9.x รอ **อนุญาต** ที่นี่

**รายละเอียด** บนการ์ดเปิดส่วนที่เหลือ: รีพอสิทอรีที่รับมาและแหล่งดึงของสมาชิกนั้น ข้อเสนอที่จัดเก็บ การเฝ้าติดตาม **ลบ** และ **ลืมคีย์**

บนเครื่องที่**รับ**สำเนา append-only จาก BombVault อีกเครื่อง รีพอสิทอรีที่รับมาให้การเฝ้าติดตามอิสระแบบอ่านอย่างเดียวบนฮาร์ดแวร์ฝั่งรับ ความล้มเหลวเงียบ ๆ ที่ปลายทางไกลจึงไม่ผ่านไปโดยไม่มีใครรู้ เปิด **ตัวรับ** ใต้ **การตั้งค่า, อินสแตนซ์** แล้วเปิด **รายละเอียด** ของอินสแตนซ์ที่ส่งบนหน้าอินสแตนซ์ และเพิ่มรีพอสิทอรีที่รับมา (อ่านอย่างเดียว เปิดด้วยรหัสผ่าน restic ของอินสแตนซ์ที่ส่ง ซึ่งได้รับผ่าน[กลุ่มการจับคู่](#pairing)) คุณจะได้:

- **รายการตามต้นทาง** เพื่อให้เห็นว่า containers, VMs และชุดโฟลเดอร์ใดมาถึงแล้วอย่างแน่นอน
- **รับล่าสุด** ต่อต้นทาง เพื่อให้รู้ว่าแต่ละอันสดแค่ไหน
- **`restic check` อิสระ** ที่รันบนฮาร์ดแวร์ฝั่งรับ เพื่อให้ตรวจความสมบูรณ์ในที่ที่ข้อมูลอยู่จริง ไม่ใช่เฉพาะที่ผู้ส่ง
- **สวิตช์คนตาย:** การเตือนเมื่อต้นทางหยุดส่งภายในช่วงเวลาที่คุณตั้ง
- **การเตือนความสมบูรณ์:** การเตือนเมื่อการตรวจฝั่งรับล้มเหลว

ตัวรับเป็นแบบอ่านอย่างเดียวโดยเคร่งครัด มันไม่เขียนลงรีพอสิทอรีที่รับมาเลย จึงไม่มีทางทำลายการรับประกัน append-only ที่ผู้ส่งพึ่งพา

ตัวดึงทำงานย้อนกลับ: เมื่อเปิด **ดึง** อินสแตนซ์อ่านข้อมูลสำรองของสมาชิกอื่นเข้ารีพอสิทอรีของตัวเองตามตารางเวลาของตัวเอง แหล่งของมันอยู่ในรายละเอียดของสมาชิกนั้นด้วย

### เซิร์ฟเวอร์รับข้อมูล {#receiving-server}

เครื่องรับยังรัน rest-server ที่ตัวอื่นคัดลอกมาได้ด้วย ตั้งค่าเมื่อคุณอนุญาตคำขอ **ตัวรับ** ที่ขอมันครั้งแรก: หน้าต่างบอกว่าเซิร์ฟเวอร์ต้องมีเซิร์ฟเวอร์รับข้อมูลและขอโฟลเดอร์บนแชร์ พร้อม **โฟลเดอร์ใหม่** สำหรับสร้าง และพอร์ต (8000 เว้นแต่ container อื่นใช้) BombVault จะ:

1. ปฏิเสธหากมี container ชื่อ `rest-server` อยู่แล้วหรือ container อื่นถือพอร์ตอยู่;
2. ดึง `restic/rest-server` และเริ่มผ่าน Docker socket ในโหมด append-only พร้อมรีพอสิทอรีส่วนตัวและไฟล์ล็อกอินในโฟลเดอร์;
3. เขียนเทมเพลต Unraid ของมันลงแฟลชไดรฟ์ เพื่อให้ container แก้ไขได้ในแท็บ Docker หรือเสนอเทมเพลตให้ดาวน์โหลดเมื่อเข้าถึงแฟลชไดรฟ์ไม่ได้;
4. รันการทดสอบการแทรกแซงกับมันและแสดงว่ามันปฏิเสธการลบหรือไม่

อินสแตนซ์ในกลุ่มของคุณพบเซิร์ฟเวอร์ในกลุ่มผู้ให้บริการใต้ **จากกลุ่มของคุณ** ตั้งชื่อตามเครื่องรับ และบทบาท **ตัวรับ** เสนอมันเป็นตัวเลือกที่ปลอดภัย แต่ละอินสแตนซ์ได้การลงชื่อเข้าใช้ของตัวเองครั้งแรกที่ใช้เซิร์ฟเวอร์ และเขียนเฉพาะในโฟลเดอร์ของตัวเองที่นั่น เมื่อเปิด **ตัวรับ** ใต้ **การตั้งค่า, อินสแตนซ์** **เซิร์ฟเวอร์รับข้อมูล** บนการ์ดของอินสแตนซ์นี้เปิดเซิร์ฟเวอร์อีกครั้ง หน้าต่างแสดงการลงชื่อเข้าใช้ใต้ **พาร์ตเนอร์ที่มีการลงชื่อเข้าใช้** และ **เพิกถอนการลงชื่อเข้าใช้** นำออกหนึ่งอัน สิ่งที่อินสแตนซ์นั้นคัดลอกไปแล้วอยู่ในโฟลเดอร์ต่อไป การตั้งค่ายังสร้าง **การลงชื่อเข้าใช้นอกกลุ่ม** หนึ่งอัน ซึ่งหน้าต่างแสดงรหัสผ่านครั้งเดียว

อินสแตนซ์ที่เข้าถึงเครื่องรับได้ผ่านรีเลย์เท่านั้นใช้เซิร์ฟเวอร์ไม่ได้ เพราะรีเลย์ไม่ส่งข้อมูลสำรอง เพิ่มที่อยู่ของเครื่องรับบนหน้าการจับคู่ก่อน เมื่อ BombVault รันบนที่อยู่ IP ของตัวเอง (บน br0 เป็นต้น) กรอก **ที่อยู่สำหรับพาร์ตเนอร์** เพราะเซิร์ฟเวอร์ฟังที่ที่อยู่ของโฮสต์

## ตัวอย่างครบวงจร: Unraid สองเครื่อง ตั้งแต่ต้นจนจบ

ทั้งหมดข้างต้นอธิบายชิ้นส่วน นี่คือการตั้งค่าที่สมบูรณ์หนึ่งชุด เพราะชิ้นส่วนประกอบง่ายกว่าเมื่อเคยเห็นที่ประกอบแล้วหนึ่งครั้ง

สองเครื่อง: **TOWER** รัน containers และส่งข้อมูลสำรอง **VAULT** รับและบังคับ append-only แทนที่ด้วยชื่อ ที่อยู่ และพาธแชร์ของคุณเอง

**1. จับคู่สองเครื่อง** บน TOWER เปิด **การตั้งค่า, การจับคู่** กด **สร้างวลี** และป้อนคำสิบสองคำบน VAULT ที่ **ป้อนวลี** ตั้งรหัสผ่านเข้าสู่ระบบบนทั้งสองก่อน

**2. บน TOWER ขอให้ VAULT เป็นตัวรับ** บนหน้าอินสแตนซ์ เปิด **ตัวรับ** บนการ์ดของ VAULT เลือกส่วนและ **เซิร์ฟเวอร์รับข้อมูลของ VAULT** เป็นที่ แล้วส่งคำขอ

**3. บน VAULT อนุญาต** หน้าอินสแตนซ์ของ VAULT แสดงคำขอบนการ์ดของ TOWER กด **อนุญาต** ครั้งแรก VAULT ขอโฟลเดอร์สำหรับเซิร์ฟเวอร์รับข้อมูลของมัน เช่น `user/appdata/rest-server` เริ่ม rest-server ในโหมด append-only และรันการทดสอบการแทรกแซงกับมัน

**4. กลับมาที่ TOWER** จากนั้น TOWER คัดลอกไป VAULT หลังการสำรองทุกครั้ง และปลายทางใหม่ปรากฏบนหน้าปลายทางของ TOWER พร้อมการป้องกันการลบของมัน

สิ่งที่การทดสอบการแทรกแซงตอบ:

| ผล | เกิดอะไรขึ้น |
| --- | --- |
| **ได้รับการป้องกัน** | VAULT ปฏิเสธการลบ นี่คือสถานะที่ผ่านเพียงอย่างเดียว |
| **ไม่ได้รับการป้องกัน** | VAULT ยอมรับการลบ `--append-only` ขาดหายหรือถูกนำออก |
| **สรุปไม่ได้** | ไม่ใช่ทั้งสองอย่าง โดยปกติ URL ไม่ใช่ตัวที่ restic เองใช้ หรือข้อมูลรับรองเปลี่ยน ไม่มีการบันทึกและไม่มีการเตือน |

**5. ดูสิ่งที่มาถึง ถ้าต้องการ** เปิด **ตัวรับ** ใต้ **การตั้งค่า, อินสแตนซ์** บน VAULT เปิด **รายละเอียด** ของ TOWER และเพิ่มรีพอสิทอรีที่รับมา VAULT ได้รหัสผ่าน restic ของ TOWER ผ่านกลุ่ม ไม่มีใครพิมพ์คีย์

**6. ทำให้เป็นสองทาง** ทำซ้ำขั้นตอนในทิศทางตรงข้าม: VAULT ขอให้ TOWER เป็นตัวรับของมัน แต่ละเครื่องบังคับ append-only ให้อีกเครื่อง และไม่มีเครื่องใดลบข้อมูลสำรองของอีกเครื่องได้

rest-server ที่รันด้วยมือก็ใช้ได้: เพิ่มด้วย **เพิ่มปลายทาง** เป็น rest-server พร้อมผู้ใช้และรหัสผ่านจาก `.htpasswd` ของมัน และเปิดการป้องกันการลบ คง `--append-only` ไว้ในตัวเลือกของมัน หากไม่มี ฝั่งไกลก็กลับเป็นแชร์ธรรมดา

!!! warning "พาธในเครื่องคือพาธภายใน container"
    เมื่อ BombVault ขอโฟลเดอร์บนเซิร์ฟเวอร์นี้ ให้ป้อนเทียบกับจุดเมานต์ของโฮสต์ เช่น `user/appdata/rest-server/bombvault-containers` ไม่ใช่ `/mnt/user/appdata/...` BombVault รันใน container ซึ่ง `/mnt` ของโฮสต์เมานต์ไว้ที่อื่น พาธสัมบูรณ์ของโฮสต์ไม่มีอยู่ข้างใน หากคุณวางพาธเช่นนั้น BombVault จะบอกพาธสัมพัทธ์ที่ควรใช้แทน

## ตัวช่วยฉุกเฉิน {#emergency}

**ตัวช่วยฉุกเฉิน** นำเซิร์ฟเวอร์ที่หายไปหรือตั้งค่าใหม่กลับมา เริ่มที่หน้า **การกู้คืน** ใต้ **ฉุกเฉิน** และจาก **กู้คืนจากข้อมูลสำรอง** บนหน้าต้อนรับของการติดตั้งใหม่ ทำงานในสี่ขั้นตอน: **การเข้าถึง**, **การตั้งค่า**, **การเลือก** และ **การกู้คืน**

1. **การเข้าถึง** แสดงคีย์ของข้อมูลสำรองเก่าให้ BombVault ด้วยหนึ่งในสามวิธี:
    - **อัปโหลดชุดกู้คืน**: ไฟล์ที่คุณดาวน์โหลดระหว่างการตั้งค่า มีคีย์และทุกปลายทาง และ BombVault เติมส่วนที่เหลือจากมัน ชุดที่ปิดผนึกด้วย age ขอ identity ที่ใช้ปิดผนึก ใช้ครั้งเดียวและไม่เก็บ
    - **ผ่านกลุ่ม**: อินสแตนซ์ในกลุ่มของคุณเก็บคีย์เป็นสำเนาที่ฝากไว้ คุณต้องมีคำสิบสองคำของกลุ่ม รหัสปลดล็อกของคุณ และคนที่อินสแตนซ์นั้น ดู [ผู้เก็บคีย์](#key-keeper)
    - **พิมพ์คีย์**: `APP_KEY` ของเซิร์ฟเวอร์เก่า และที่ที่ข้อมูลสำรองของมันอยู่

    จากนั้น BombVault ลองคีย์กับทุกปลายทางและบอกแต่ละแห่งว่าอ่านได้ ไม่พบ ล็อกด้วยคีย์อื่น เข้าถึงไม่ได้ หรือยังขาดการลงชื่อเข้าใช้ ยังไม่มีอะไรถูกบันทึก และคีย์อยู่ในหน่วยความจำเพียงช่วงเวลาจำกัด **รับช่วงคีย์** ทำให้เซิร์ฟเวอร์นี้เขียนข้อมูลสำรองด้วยคีย์นั้นนับจากนี้ **ยกเลิกการรับช่วง** กลับไปใช้คีย์ของตัวเองจนกว่าการสำรองครั้งแรกจะรัน เซิร์ฟเวอร์ที่มีข้อมูลสำรองของตัวเองอยู่แล้วปฏิเสธการรับช่วงและชี้ไปที่ [จากโฟลเดอร์สำรองข้อมูลเก่า](#restore-from-another-bombvault-repo) **บันทึกข้อมูลรับรอง** เก็บการลงชื่อเข้าใช้ที่ชุดกู้คืนมีสำหรับปลายทางระยะไกล และถามก่อนแทนที่การลงชื่อเข้าใช้ที่เซิร์ฟเวอร์นี้มีอยู่แล้ว
2. **การตั้งค่า** **นำการตั้งค่ากลับมา** กู้คืนการตั้งค่าของ BombVault เองจากการสำรองข้อมูลตัวเองล่าสุด: ปลายทาง ข้อมูลรับรอง ตารางเวลา และกฎ BombVault รีสตาร์ทเพื่อใช้ ผ่าน Docker socket ฐานข้อมูลการตั้งค่าที่ใช้งานอยู่จึงไม่ถูกเขียนทับขณะมี handle เปิดอยู่ และตัวช่วยทำต่อเองหลังจากนั้น การเข้าสู่ระบบของเซิร์ฟเวอร์นี้คงอยู่: คุณยังเข้าสู่ระบบด้วยรหัสผ่านที่ใช้ตอนนี้ ความลับที่เซิร์ฟเวอร์เก่าเก็บไว้และรับช่วงไม่ได้จะถูกแสดงรายการ เพื่อให้คุณป้อนใหม่ได้
3. **การเลือก** BombVault ค้นผ่านข้อมูลสำรองของคุณและแสดง containers, VMs, ชุดโฟลเดอร์ และชุดข้อมูล ZFS ที่พบ สแนปช็อตล่าสุดถูกเลือกไว้ก่อนทุกที่ สิ่งที่เซิร์ฟเวอร์นี้ยังมีเริ่มด้วยสถานะปิด เพราะการกู้คืนจะแทนที่มัน ชุดโฟลเดอร์ไม่รู้แล้วว่ามาจากที่ไหนหลังการสร้างใหม่ จึงไปที่โฟลเดอร์ที่คุณเลือก
4. **การกู้คืน** ทุกอย่างที่เลือกกลับมาในคราวเดียว ปล่อยให้หยุดไว้ถ้าคุณต้องการเริ่มแต่ละ container และ VM เอง ซึ่งปลอดภัยที่สุดหลังสูญเสียทั้งหมด หลังจากนั้นดาวน์โหลดชุดกู้คืนใหม่: ชุดเก่าเป็นของการติดตั้งก่อนหน้า

!!! tip "การย้ายตามแผนเทียบกับภัยพิบัติ"
    ตัวช่วยฉุกเฉินกู้คืนการตั้งค่าของ BombVault เองจากข้อมูลสำรอง สำหรับการย้าย*ตามแผน*ไปเครื่องใหม่ คุณนำการตั้งค่าไปตรง ๆ ด้วยการ์ด **ส่งออก / นำเข้าการตั้งค่า** แทนได้ (ไฟล์ JSON แบบพกพา) ดู [Configuration](configuration.md#portable-settings-export-and-import)

### จากโฟลเดอร์สำรองข้อมูลเก่า {#restore-from-another-bombvault-repo}

**จากโฟลเดอร์สำรองข้อมูลเก่า** ใต้ **แหล่งอื่น** บนหน้าการกู้คืนเปิดรีพอสิทอรีของอินสแตนซ์ BombVault *อื่น* (แชร์ที่เมานต์ใต้ `/mnt` หรือที่อยู่ระยะไกล) ด้วยชุดกู้คืนของอินสแตนซ์นั้นหรือ `APP_KEY` ที่พิมพ์เอง ในเซสชันครั้งเดียวแบบอ่านอย่างเดียว เรียกดู containers, VMs, ชุดโฟลเดอร์ และชุดข้อมูล ZFS ที่เก็บอยู่ที่นั่น เลือกสแนปช็อตแล้วกู้คืน และวัตถุที่กู้คืนกลายเป็น container, VM หรือชุดโฟลเดอร์ในเครื่องปกติ ไม่มีอะไรถูกเขียนลงรีพอสิทอรีอื่นเลย และการตั้งค่าการสำรองของคุณเองไม่ถูกแตะ (เซสชันอยู่ในหน่วยความจำและหมดอายุเอง) การย้าย container จากเซิร์ฟเวอร์ A ไป B ไม่ต้องชี้การตั้งค่าของคุณใหม่แล้วย้อนกลับ หน้าต่างนี้ใช้ครั้งเดียว: เปิดเซสชัน กู้คืนสิ่งที่เลือก และลืมอินสแตนซ์อื่น หากต้องการการจัดการถาวร ที่เครื่องนี้ดึงสแนปช็อตของอินสแตนซ์อื่นเข้ารีพอสิทอรีของตัวเองตามตารางเวลา นั่นคือบทบาท **ตัวดึง** บนหน้าอินสแตนซ์

Container ที่เครือข่ายของมันไม่มีอยู่บนเซิร์ฟเวอร์นี้ เช่นเครือข่าย Unraid `br0` บนโฮสต์ Docker ธรรมดา จะแสดงตัวเลือกเครือข่ายใต้แถวของมัน BombVault สร้างมันบนเครือข่ายที่คุณเลือก พร้อมเครือข่ายอื่นของมัน IP คงที่และที่อยู่ MAC เป็นของเครือข่ายเก่าและถูกทิ้ง เครือข่ายใหม่จึงกำหนดให้เอง

## ผู้เก็บคีย์ {#key-keeper}

ผู้เก็บคีย์คืออินสแตนซ์ในกลุ่มของคุณที่ถือสำเนาที่ปิดผนึกของชุดกู้คืนของเซิร์ฟเวอร์นี้ มันเปิดสำเนาเองไม่ได้ หากเซิร์ฟเวอร์นี้หายไป การติดตั้งใหม่ที่เข้าร่วมกลุ่มของคุณขอสำเนาจากผู้เก็บและเปิดด้วยรหัสปลดล็อกของคุณ

1. บนหน้าอินสแตนซ์ เปิด **ผู้เก็บคีย์** บนการ์ดของอินสแตนซ์ที่ควรเก็บ และเลือก **ฝากสำเนา** การฝากต้องมีรหัสผ่านเข้าสู่ระบบ
2. เซิร์ฟเวอร์นี้แสดง **รหัสปลดล็อก** ครั้งเดียว: ตัวอักษรและตัวเลขยี่สิบตัวในสี่กลุ่มกลุ่มละห้า จดไว้และยืนยันด้วย **จดรหัสไว้แล้ว** เซิร์ฟเวอร์นี้ไม่เก็บรหัส เก็บเฉพาะสิ่งที่ต้องใช้ปิดผนึกสำเนาที่ฝากสำหรับมัน
3. ผู้เก็บถือสำเนาที่ฝากไว้แล้ว และเซิร์ฟเวอร์นี้ต่ออายุเมื่อชุดกู้คืนเปลี่ยน **สำเนาที่ฝากไว้** บนการ์ดของอินสแตนซ์นี้แสดง **สำเนาที่ฝากไว้ของเซิร์ฟเวอร์นี้** พร้อมผู้เก็บแต่ละรายและสถานะ และ **สำเนาที่ฝากไว้ซึ่งเซิร์ฟเวอร์นี้เก็บ** สำหรับรายอื่น **สร้างรหัสใหม่** แทนที่รหัส ผู้เก็บแต่ละรายเปลี่ยนไปใช้รหัสใหม่เมื่อได้รับสำเนาที่ฝากใหม่

ในวันนั้นคุณต้องมีสามอย่าง: คำสิบสองคำของกลุ่ม รหัสปลดล็อก และการเข้าถึงอินเทอร์เฟซของผู้เก็บ ที่ต้องมีคนกด **อนุญาต** ในตัวช่วยฉุกเฉิน เลือก **ผ่านกลุ่ม** เลือกสำเนาที่ฝาก ขอมัน และพิมพ์รหัสปลดล็อก รหัสถูกใช้บนเซิร์ฟเวอร์ใหม่และไม่ถูกส่งไปที่ผู้เก็บ บนผู้เก็บ คำขอแสดงใต้ **สำเนาที่ฝากไว้** พร้อมว่าใครขอ เคยเห็นอินสแตนซ์นั้นที่นั่นมาก่อนหรือไม่ และขอบ่อยแค่ไหน **อนุญาต** ส่งมอบสำเนาที่ปิดผนึก และการอนุญาตต้องมีรหัสผ่านเข้าสู่ระบบ การติดตั้งใหม่มี 30 นาทีหลังอนุญาตเพื่อรับสำเนา คำขอที่ไม่มีใครตอบหมดอายุหลังหนึ่งวัน และอินสแตนซ์ที่ขอบ่อยเกินไปต้องรอหนึ่งชั่วโมง

หากไม่มีรหัส ไม่มีใครเปิดสำเนาได้ รวมถึงผู้เก็บ หากรหัสหาย ให้สร้างใหม่ขณะที่เซิร์ฟเวอร์นี้ยังรันอยู่ หากเซิร์ฟเวอร์หายไปแล้ว ชุดกู้คืนและ APP_KEY ที่พิมพ์เองยังใช้ได้ ผู้เก็บลบสำเนาที่ฝากได้ทุกเมื่อ และเจ้าของต้องขออีกครั้ง

## ชุดกู้คืน {#recovery-kit}

นี่คือส่วนที่ทำให้การกู้คืนจากภัยพิบัติเป็นไปได้แม้ไม่มี BombVault ที่รันอยู่

**ดาวน์โหลดชุดกู้คืน** ในการ์ด **สำหรับกรณีฉุกเฉิน** ใต้ **การตั้งค่า, กู้คืน** ให้ **คีย์** **รหัสผ่าน restic ที่ได้มา** ทุก**ปลายทาง**พร้อมรีพอสิทอรีของแต่ละส่วน การลงชื่อเข้าใช้ที่การติดตั้งใหม่ต้องใช้เพื่อเข้าถึง และ**คำสั่ง restic ที่แน่นอน** เพื่อให้กู้คืนตรงด้วย restic CLI บนเครื่องใดก็ได้ ต้องมีรหัสผ่านเข้าสู่ระบบ ชุดพิมพ์คีย์แม้ปิดการเข้ารหัส เพราะคำจำกัดความของ container และ VM ถูกปิดผนึกด้วยมันเสมอ หลังการรับช่วง ชุดพิมพ์คีย์ข้อมูลสำรองที่รับช่วงมาและ APP_KEY ของเซิร์ฟเวอร์นี้ ซึ่งการติดตั้งใหม่ต้องใช้เพื่อนำการตั้งค่ากลับมาเท่านั้น การ์ด **บันทึกชุดกู้คืนของคุณ** บนภาพรวมเตือนจนกว่าคุณจะเก็บไว้

!!! danger "เก็บชุดกู้คืนไว้นอกเซิร์ฟเวอร์"
    ชุดนี้มีความลับที่ถอดรหัสข้อมูลสำรองของคุณ เก็บไว้ในที่ปลอดภัยและแยกจากเซิร์ฟเวอร์ (ตัวจัดการรหัสผ่าน สำเนาพิมพ์ในตู้เซฟ) หากคุณสูญเสียทั้ง BombVault และ `APP_KEY` โดยไม่มีชุดกู้คืนและไม่มีสำเนาคีย์ที่ฝากไว้ ข้อมูลสำรองที่เข้ารหัสของคุณจะกู้คืนไม่ได้

!!! warning "สแนปช็อตล่าสุดไม่ใช่อันที่ควรกู้คืนเสมอไป"
    ตั้งแต่ restic 0.17 `restic snapshots` แสดงขนาดของแต่ละสแนปช็อต หลังข้อมูลสูญหาย สแนปช็อตล่าสุดอาจเป็นอันที่ว่างเปล่า อย่ากู้คืนสแนปช็อตที่เล็กกว่าก่อนหน้ามาก หลังแรนซัมแวร์อาจเป็นอันที่ถูกเข้ารหัสในขนาดปกติ หาก BombVault ยังรันอยู่ ตรวจหน้า **ความผิดปกติ** ก่อน: มันระบุข้อมูลสำรองที่ดีล่าสุด และหน้าต่างการกู้คืนเลือกอันนั้นไว้ก่อน การกู้คืนไม่ต้องใช้ข้อมูลความผิดปกติของ BombVault และการหยุดการเก็บรักษาเพียงเก็บสแนปช็อตเพิ่ม

### การปิดผนึกชุดกู้คืน

หากคุณเปิด **เข้ารหัสการส่งออกด้วย age** ใต้ **การตั้งค่า, ระบบ** ชุดกู้คืนก็ถูกปิดผนึกด้วยเช่นกันและดาวน์โหลดเป็น `bombvault-recovery-kit.md.age` เป็น ASCII-armored ไม่ใช่ไบนารี จึงยังเป็นข้อความธรรมดา: การวางลงตัวจัดการรหัสผ่านหรือพิมพ์ออกใช้ได้เหมือนเดิม เพียงแต่เนื้อหาอ่านไม่ได้หากไม่มีคีย์ของคุณ

!!! warning "อย่าเก็บคีย์ age ไว้ในชุดกู้คืน"
    คุณต้องมีคีย์ **ส่วนตัว** age เพื่อเปิดชุดที่ปิดผนึก เก็บไว้ในที่ที่ไม่พึ่งพาตัวชุดเอง มิฉะนั้นคุณจะมีสองอย่างให้กู้คืนแทนที่จะเป็นอย่างเดียว การปิดผนึกคุ้มค่าเมื่อเก็บชุดไว้ในที่ที่คุณควบคุมไม่เต็มที่ (ตัวจัดการรหัสผ่านที่ใช้ร่วมกัน โน้ตบนคลาวด์ สำเนาพิมพ์ในสำนักงาน) ชุดในตู้เซฟของคุณเองได้รับการปกป้องโดยตู้เซฟอยู่แล้ว

    เมื่อเปิดการเข้ารหัสและไม่ได้ตั้งผู้รับที่ใช้ได้ การดาวน์โหลดจะถูกปฏิเสธทันที BombVault ไม่เคยถอยไปส่งมอบคีย์หลักแบบข้อความธรรมดา

### หากคุณไม่มีชุดกู้คืนอยู่ใกล้มือ

รหัสผ่านไม่ถูกเก็บที่ใดเลย มัน**ถูกคำนวณ**จากคีย์ของข้อมูลสำรอง คุณจึงสร้างซ้ำเองได้ด้วยคีย์และเชลล์เท่านั้น:

```sh
printf 'bombvault:restic-repo'   | openssl dgst -sha256 -mac HMAC -macopt hexkey:$APP_KEY -r   | cut -d' ' -f1
```

นี่คือ HMAC-SHA256 บนสตริงคงที่ `bombvault:restic-repo` ใช้ไบต์ดิบของ `APP_KEY` ฐานสิบหกเป็นคีย์ พิมพ์เป็นอักขระฐานสิบหกตัวพิมพ์เล็ก 64 ตัว ค่าเดียวกันอยู่ในชุดกู้คืน ระบุเป็นรหัสผ่าน restic ที่ได้มา นี่สำหรับวันที่ชุดกู้คืนอยู่ในที่ที่คุณไม่ได้อยู่ บนเซิร์ฟเวอร์ที่รับช่วงข้อมูลสำรองของอีกเครื่อง ใช้คีย์ข้อมูลสำรองที่รับช่วงมา ซึ่งคือ APP_KEY เดิมของเซิร์ฟเวอร์นั้น

!!! warning "สำหรับรีพอสิทอรีที่รับมา ให้ใช้คีย์ของอินสแตนซ์ที่ส่ง"
    รีพอสิทอรีที่มาถึงที่นี่ผ่านสำเนานอกสถานที่ถูกสร้างโดยเครื่องที่ส่งมาด้วยคีย์ของ**มัน** การสร้างจากคีย์ของเครื่องรับให้รหัสผ่านที่ restic จะปฏิเสธ ซึ่งดูเหมือนรีพอสิทอรีเสียหายทุกประการแต่ไม่ใช่ นี่คือเหตุผลปกติที่ `restic check` บนรีพอสิทอรีที่รับมาขอรหัสผ่านซ้ำแล้วซ้ำอีก

เนื่องจากคำจำกัดความการกู้คืนอยู่**ภายใน**แต่ละรีพอสิทอรี (`<repo>/def`, `<repo>/vm-def`) โฟลเดอร์รีพอสิทอรีที่คัดลอกจึงครบในตัวเอง ชุดกู้คืนบวกรีพอสิทอรีจึงเป็นทุกอย่างที่การกู้คืนบนเครื่องเปล่าต้องใช้

## การนำดัมป์ฐานข้อมูลกลับมา {#database-dumps}

ดัมป์ฐานข้อมูลเป็นจุดกู้คืนของตัวเองในรีพอสิทอรีของ containers ติดแท็ก `dbdump:<container>` มีไฟล์เดียว `/dbdump/<container>.sql` BombVault แสดงรายการ ดาวน์โหลด และนำเข้าบนแท็บ **การสำรองข้อมูล** ของ container ด้านล่างคือขั้นตอนเดียวกันด้วย restic อย่างเดียว สำหรับวันที่ไม่มี BombVault

```sh
restic -r <repo> snapshots --tag dbdump:<container>
restic -r <repo> dump --tag dbdump:<container> latest /dbdump/<container>.sql > <container>.sql
```

แท็ก `dbversion:` และ `dbname:` บนแต่ละดัมป์บอกว่ามาจากเซิร์ฟเวอร์เวอร์ชันใดและมีฐานข้อมูลใดบ้าง ไฟล์ที่สมบูรณ์ลงท้ายด้วย `-- PostgreSQL database cluster dump complete` หรือ `-- Dump completed`

นำเข้าไปยัง container เวอร์ชันเดียวกันหรือใหม่กว่า (PostgreSQL) หรือเวอร์ชันหลักเดียวกัน (MySQL และ MariaDB) ที่เริ่มหนึ่งครั้งด้วยโฟลเดอร์ข้อมูลว่างเพื่อให้เริ่มต้น โฮสต์ไม่ต้องมีไคลเอนต์ฐานข้อมูล container มีอยู่แล้ว:

```sh
docker exec -i <container> sh -c 'exec psql -X -U "${POSTGRES_USER:-postgres}" -d postgres' < <container>.sql
docker exec -i <container> sh -c 'exec mariadb -uroot -p"$MARIADB_ROOT_PASSWORD"' < <container>.sql
docker exec -i <container> sh -c 'exec mysql -uroot -p"$MYSQL_ROOT_PASSWORD"' < <container>.sql
```

สำหรับฐานข้อมูลเดียวจากดัมป์เต็ม MySQL และ MariaDB รับ `--one-database <ชื่อ>` ในคำสั่งไคลเอนต์ ดัมป์ PostgreSQL มีหนึ่งส่วนต่อฐานข้อมูล แต่ละส่วนขึ้นต้นด้วยบรรทัด `\connect <ชื่อ>`: คัดลอกส่วนนั้นลงไฟล์ของมันเองและนำเข้าด้วย `-d <ชื่อ>` หลังสร้างฐานข้อมูล

!!! warning "ดัมป์ระดับ root พาผู้ใช้ของเซิร์ฟเวอร์มาด้วย"
    ดัมป์ MySQL หรือ MariaDB เต็มที่ทำในฐานะ root มีฐานข้อมูลระบบ `mysql` การนำเข้าจึงแทนที่บัญชีของเซิร์ฟเวอร์ใหม่ รวมถึงรหัสผ่าน root ด้วยของในดัมป์ บน PostgreSQL `role ... already exists` สำหรับผู้ใช้ที่ container สร้างเป็นเรื่องคาดไว้และไม่เป็นอันตราย
