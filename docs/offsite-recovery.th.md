# นอกสถานที่และการกู้คืน

!!! note "สำเนานอกสถานที่หยุดรอหลังการสร้างใหม่"
    เมื่อตัวช่วยฉุกเฉินหรือ **ค้นหาการสำรองข้อมูล** สร้างรายการขึ้นใหม่โดยไม่มีการตั้งค่าเดิม สำเนานอกสถานที่ของส่วนเหล่านั้นจะหยุดจนกว่าจะยืนยันค่าเริ่มต้นของมัน ดู [หลังสร้างใหม่](#after-a-rebuild)

การสำรองในเครื่องปกป้องคุณจากคอนเทนเนอร์ที่หายหรือการอัปเดตที่พัง สำเนานอกสถานที่และชุดกู้คืนที่ทดสอบแล้วปกป้องคุณจากทั้งกล่อง แรนซัมแวร์ หรือไฟไหม้ หน้านี้ครอบคลุมปลายทางที่จัดเก็บและสำเนานอกสถานที่ การทำให้สำเนาแก้ไขไม่ได้ การพิสูจน์ว่าคุณกู้คืนได้ การจับคู่หลายเซิร์ฟเวอร์ และการนำทุกอย่างกลับมาเมื่อ BombVault เองหายไป

## สำเนานอกสถานที่ {#off-site-copies}

เก็บการสำรองในเครื่องที่เร็วไว้ แล้วเพิ่มปลายทางที่จัดเก็บนอกสถานที่หนึ่งแห่งหรือมากกว่า BombVault คัดลอกสแนปช็อตใหม่ไปที่นั่นด้วย `restic copy` แบบ best-effort ปัญหานอกสถานที่จึงไม่ทำให้การสำรองในเครื่องล้มเหลว ในรูปแบบนี้แต่ละส่วนเขียนลงโฟลเดอร์ของตัวเองก่อน และที่เก็บนอกสถานที่เป็นสำเนา โฟลเดอร์ของตัวเองไม่ต้องอยู่บนเซิร์ฟเวอร์นี้: ดู [โฟลเดอร์ของตัวเองของส่วน](#own-folder) สำหรับการเก็บไว้ในปลายทางอย่าง S3 หรือ rest-server

- **หลายปลายทางต่อส่วน** แต่ละส่วน (คอนเทนเนอร์ VM แฟลช สำรองข้อมูลตัวเอง โฟลเดอร์ และชุดข้อมูล ZFS) คัดลอกไปยังปลายทางนอกสถานที่หลายแห่งพร้อมกันได้ คุณจึงเก็บ เช่น rest-server บนกล่องของเพื่อนกับบักเก็ต S3 คู่กันได้ การ์ด **ปลายทางแยกตามส่วน** บนหน้าปลายทางที่จัดเก็บเปิดหรือปิดทุกบรรทัดจากส่วนไปยังปลายทาง
- **การคัดลอกรันเมื่อไร** การ์ด **คัดลอก** ของปลายทางตั้ง **คัดลอกเมื่อไร**: **หลังสำรองทุกครั้ง** หรือตามกำหนดการของตัวเองที่รวบรวมสแนปช็อตและคัดลอกตามเวลาที่กำหนด ใต้ **การตั้งค่า, ตารางเวลา, สำเนานอกสถานที่รายส่วน** **ข้อยกเว้น** ให้ส่วนหนึ่งมีกำหนดการคัดลอกของตัวเอง
- **การ์ดสำเนานอกสถานที่** ใต้ **การตั้งค่า, ปลายทางที่จัดเก็บ** ทุกส่วนที่มีสำเนานอกสถานที่มีแถวใน **สำเนานอกสถานที่** พร้อม **ทดสอบการเชื่อมต่อ**, **จำลองตอนนี้** เพื่อเริ่มการคัดลอกตามสั่ง และ **ตั้งค่า** หรือ **แก้ไข** การตั้งค่าการคัดลอกที่เหลือของส่วนเปิดในหน้าต่างของมันจากตรงนั้น
- **การเก็บรักษา** ตั้งต่อปลายทางที่ **เก็บไว้นานแค่ไหน** คุณจึงเก็บสำเนานอกสถานที่ไว้นานกว่าเป็นที่เก็บถาวรได้ สำเนาในช่องนอกสถานที่ของส่วนทำตามมันเหมือนสำเนาอื่น และส่วนหนึ่งเก็บค่าของตัวเองได้ใต้ **กฎแยกตามส่วน** ศูนย์ทั้งหมดไม่ตัดสแนปช็อตนอกสถานที่เลย ดู [เก็บไว้นานแค่ไหน](#keep)
- **ขีดจำกัดแบนด์วิดท์** (**แบนด์วิดท์นอกสถานที่** ใต้ **การตั้งค่า, ปลายทางที่จัดเก็บ** หรือการ์ด **คัดลอก** ของปลายทาง) จำกัดอัตราอัปโหลด/ดาวน์โหลดของ restic เพื่อให้การคัดลอกไม่กินเต็ม WAN ของคุณ กรอกเป็น KiB/s ซึ่งเป็นหน่วยที่ restic รับ และแต่ละช่องแสดงอัตราเดียวกันเป็น MB/s และ Mbit/s ขณะที่คุณพิมพ์: 2048 อ่านเป็นราว 2.0 MB/s (16.8 Mbit/s)
- **การบีบอัด** เป็น **ปิด**, **อัตโนมัติ** (ค่าเริ่มต้นของ restic) หรือ **สูงสุด** ตั้งที่แต่ละปลายทาง และสำหรับหนึ่งส่วนก็ตั้งใต้กฎของมันที่นั่น การสำรอง การคัดลอก และ prune เขียนด้วยค่านี้ และชุดกู้คืนระบุไว้ restic ธรรมดาจึงเขียนต่อแบบเดียวกันได้
- **สตรีมมิงมาก่อน** ขณะที่มีเซิร์ฟเวอร์สื่ออย่าง Plex, Jellyfin หรือ Emby สตรีมอยู่ การคัดลอกอัปโหลดที่ขีดจำกัดต่ำกว่า และกลับสู่ปกติไม่กี่นาทีหลังสตรีมจบ การ์ด **สตรีมมิง** บนหน้าปลายทางที่จัดเก็บมี **ชะลอสำเนานอกสถานที่ขณะสตรีม**, **เซิร์ฟเวอร์สื่อ** (คอนเทนเนอร์ที่มี Plex, Jellyfin หรือ Emby ในชื่อ image จนกว่าคุณจะเลือก), **สตรีมเมื่อเกิน (Mbit/s)**, **ขีดจำกัดการอัปโหลดขณะสตรีม (KiB/s)** และ **กลับสู่ปกติหลังจาก (นาที)** BombVault อ่านทราฟฟิกจาก Docker เซิร์ฟเวอร์สื่อบนเครือข่ายโฮสต์จึงวัดไม่ได้ REST, S3, B2, Azure, Google Cloud, Swift และ rclone ผ่าน HTTP ชะลอลงกลางการคัดลอก SFTP และโฟลเดอร์ในเครื่องหรือที่เมานต์ใช้ขีดจำกัดที่ต่ำกว่าในขั้นคัดลอกถัดไป
- **พื้นที่จัดเก็บแบบเย็น (S3)** ปลายทาง S3 ใช้ **คลาสการจัดเก็บ** ที่ถูกกว่าแต่ restic ยังอ่านได้ทันที เช่น Standard-IA, One Zone-IA, Intelligent-Tiering หรือ Glacier Instant Retrieval ได้ Glacier Flexible Retrieval และ Deep Archive ถูกตัดออก เพราะ restic กู้คืนจากมันไม่ได้ rclone remote ตั้งคลาสของมันในการกำหนดค่า rclone
- **งบประมาณการเติบโต** **งบประมาณการเติบโต (GB, 0 = ปิด)** ในหน้าต่างการคัดลอกของส่วนส่งสัญญาณเตือนเมื่อที่เก็บโตเกินขนาดนั้น มันไม่ลบอะไรเลย จึงเหมาะกับสำเนา append-only ที่ไม่มีอะไร prune จากที่นี่
- ขณะที่การคัดลอกรัน ส่วนหัวสถานะของภาพรวมบอก **กำลังคัดลอกไปนอกสถานที่** เป็นตัวบอกว่ากำลังทำงาน ไม่ใช่แถบเปอร์เซ็นต์ เพราะ `restic copy` ไม่เปิดความคืบหน้าที่เครื่องอ่านได้

!!! note "กู้คืนจากที่ไหนก็ได้"
    ทุกรายการลิสต์ข้อมูลสำรองของมันเป็นไทม์ไลน์เดียวข้ามทุกที่ที่มีข้อมูลสำรอง บนแท็บ **การสำรองข้อมูล** ของมัน การสำรองที่คัดลอกไป B2 ปรากฏหนึ่งครั้ง ทำเครื่องหมายทุกที่ที่เก็บมัน การกู้คืนใช้ที่แรกที่เข้าถึงได้ เริ่มจากที่เก็บที่รายการเขียนลงไป และคุณเลือกที่อื่นต่อสแนปช็อตได้ ปลายทางนอกสถานที่ถูกอ่านเมื่อคุณคลิก **ตรวจสอบ** เท่านั้น เพราะการลิสต์ที่จัดเก็บบนคลาวด์ใช้เวลา การลบที่ที่เดียวตรวจที่อื่นก่อนและบอกว่าเป็นสำเนาสุดท้ายหรือไม่ ดู [การกู้คืน](restore.md)

## ปลายทางที่จัดเก็บ {#destinations}

ปลายทางที่จัดเก็บคือที่ที่ข้อมูลสำรองไป: โฟลเดอร์ในเครื่อง share เซิร์ฟเวอร์ของคุณเอง หรือบริการคลาวด์ ตั้งค่าครั้งเดียวแล้วใช้กับทุกส่วน เปิด **ปลายทาง** จากไทล์การตั้งค่าของมัน หรือเปิด **แสดงในแถบด้านข้างด้วย** ที่นั่นเพื่อปักหมุด

![หน้าปลายทางที่จัดเก็บ: รายการปลายทางและโฟลว์ว่าส่วนไหนไปที่ไหน](assets/screenshots/storage/locations-dark.png#only-dark)
![หน้าปลายทางที่จัดเก็บ: รายการปลายทางและโฟลว์ว่าส่วนไหนไปที่ไหน](assets/screenshots/storage/locations-light.png#only-light)

**เพิ่มปลายทาง** เปิดหน้าต่างสี่ขั้น

1. **ผู้ให้บริการ** ทุกบริการลิสต์พร้อมโลโก้ มีช่องค้นหาที่มุมขวาบนของหน้าต่าง เป็นกลุ่ม: **ในเครื่อง** สำหรับดิสก์หรือ share ที่ต่อกับเซิร์ฟเวอร์นี้ **NAS หรือเซิร์ฟเวอร์** (rest-server, Hetzner Storage Box, SFTP, SMB, WebDAV และอื่น ๆ) **บริการ S3** (Backblaze B2, Wasabi, Cloudflare R2, Hetzner Object Storage, Amazon S3 และอื่น ๆ) เซิร์ฟเวอร์ S3 ของคุณเอง (Garage, SeaweedFS, RustFS, Silo, Ceph, JuiceFS, Versity S3 Gateway) **พื้นที่จัดเก็บบนคลาวด์** (OneDrive, Google Drive, Dropbox, pCloud, Nextcloud และที่เหลือที่ rclone รองรับ) และ **จากกลุ่มของคุณ** ซึ่งเป็นเซิร์ฟเวอร์รับของกลุ่มคุณ แต่ละอันบอกว่าเหมาะกับการสำรองแค่ไหน: ไดรฟ์คลาวด์ช้าลงเมื่อมีคำขอมาก การสำรองครั้งแรกและการ prune จึงใช้เวลานานกว่าที่นั่น สำหรับบริการที่ไม่มีไทล์ ไทล์ **Rclone** ใต้ **การกำหนดค่า rclone ของคุณเอง** รับ remote ที่วางจาก rclone.conf
2. **ลงชื่อเข้าใช้** ฟิลด์ขึ้นกับบริการ: access key สำหรับ S3 ผู้ใช้และรหัสผ่านสำหรับ WebDAV และ SMB รหัสผ่านแอปที่การลงชื่อเข้าใช้สองขั้นตอนบล็อกรหัสผ่านปกติ กุญแจสาธารณะ SSH ของ BombVault สำหรับ SFTP และ Storage Box หรือโทเค็นสำหรับบริการที่ลงชื่อเข้าใช้ผ่านเบราว์เซอร์ สำหรับกลุ่มหลัง หน้าต่างแสดงคำสั่ง `rclone authorize` ให้รันบนคอมพิวเตอร์ที่มีเบราว์เซอร์ และโทเค็นที่มันพิมพ์ใส่ในช่อง ที่ที่คุณมี [ข้อมูลรับรองที่บันทึกไว้](#sign-ins) สำหรับบริการอยู่แล้ว **ข้อมูลรับรองที่บันทึกไว้** เลือกมันแทน **คีย์ใหม่** **ทดสอบการเชื่อมต่อ** ตรวจการลงชื่อเข้าใช้ก่อนบันทึกอะไร จากนั้นหน้าต่างลิสต์โฟลเดอร์บนปลายทาง พร้อม **โฟลเดอร์ใหม่** เพื่อสร้างหนึ่งอัน และพื้นที่ว่างที่บริการรายงาน โฟลเดอร์ว่างปลอดภัยที่สุด BombVault ใส่หนึ่งโฟลเดอร์ต่อส่วนในนั้น
3. **การป้องกัน** หน้าต่างบอกตรง ๆ ว่าบริการทำอะไรได้ rest-server ในโหมด append-only ปฏิเสธการลบ และการทดสอบการแก้ไขข้อมูลตรวจเรื่องนั้น บักเก็ต S3 เก็บเวอร์ชันเก่าได้ด้วย versioning และ object lock ซึ่ง BombVault ยังตรวจไม่ได้ ไดรฟ์คลาวด์ปฏิเสธการลบไม่ได้เลย: ใครเข้าเซิร์ฟเวอร์ได้ก็เข้าสำเนานั้นได้ด้วย เปิด **การป้องกันการลบ (append-only)** เฉพาะที่ที่ฝั่งไกลปฏิเสธการลบจริง ๆ BombVault ก็ไม่ prune ที่นั่นเลย **เผื่อกรณีฉุกเฉิน** บอกว่าชุดกู้คืนเก็บอะไรสำหรับปลายทางนี้
4. **สำหรับส่วนใด** เลือกส่วนที่สำรองมาที่นี่ การคัดลอกครั้งแรกนำประวัติทั้งหมดไปด้วย รายการที่เลือกปลายทางของตัวเองจะไม่ได้ปลายทางใหม่เอง และหน้าต่างระบุชื่อพวกมัน

บางบริการขอเพิ่มอีกเล็กน้อยตอนลงชื่อเข้าใช้

- **SFTP และ Storage Box** **เพิ่มคีย์** วางกุญแจสาธารณะของ BombVault บนเซิร์ฟเวอร์ด้วย **รหัสผ่านของบัญชี** ซึ่งใช้สำหรับการลงชื่อเข้าใช้ครั้งเดียวนั้นและไม่เก็บไว้ที่ไหน คำสั่งสำหรับทำด้วยมือแสดงใต้มัน การทดสอบแสดง **คีย์ของเซิร์ฟเวอร์** พร้อมลายนิ้วมือ BombVault จำมันและปฏิเสธเซิร์ฟเวอร์ถ้าภายหลังแสดงอันที่ต่างออกไป
- **คีย์ S3 สำหรับบักเก็ตเดียว** เช่นโทเค็นออบเจกต์ของ Cloudflare R2 หรือคีย์ AWS ที่จำกัดขอบเขต อาจลิสต์บักเก็ตอื่นไม่ได้ พิมพ์บักเก็ตลงใน **Bucket** แล้วการทดสอบและรายการโฟลเดอร์จะเปิดบักเก็ตนั้น
- **ภูมิภาคและที่อยู่ S3** ภูมิภาคอ่านจาก endpoint ที่ระบุมัน (AWS, Backblaze B2, Hetzner, Scaleway, OVH, Wasabi) Garage เริ่มด้วยภูมิภาคเริ่มต้นของตัวเอง และ IDrive e2 ขอ endpoint ที่แดชบอร์ดแสดง ที่อยู่ที่วางพร้อมบักเก็ตติดมา แบบที่แดชบอร์ด R2 แสดง จะกรอกเซิร์ฟเวอร์และบักเก็ตให้ บักเก็ตที่สร้างจากตัวเรียกดูโฟลเดอร์ไปอยู่ในภูมิภาคที่ฟอร์มระบุ
- **คลาสการจัดเก็บ** ตัวเลือกเสนอเฉพาะคลาสที่บริการรับ และ **การตั้งค่าเพิ่มเติม** แสดงเฉพาะตัวเลือกที่กำหนดรูปร่างบักเก็ตใหม่
- **Google Drive และ OneDrive** ข้อมูลที่ถูก prune ถูกลบถาวรแทนที่จะไปถังขยะหรือ recycle bin ซึ่งจะยังนับกับโควตา ไดรฟ์ที่แชร์ของ Google อยู่ใต้ **การตั้งค่าเพิ่มเติม**
- **เซิร์ฟเวอร์ SMB ที่ไม่ลิสต์ share ของตัวเอง** รับชื่อหนึ่งอันใต้ **แชร์** และการทดสอบเปิด share นั้นโดยตรง
- **FTP** ขอ **การเข้ารหัส** ของมัน: **ไม่มี**, **TLS แบบชัดแจ้ง (FTPES)** หรือ **TLS แบบโดยนัย (FTPS, พอร์ต 990)**
- **OneDrive และ Zoho WorkDrive** เมื่อการลงชื่อเข้าใช้เปิดหลายไดรฟ์หรือเวิร์กสเปซ หน้าต่างถามว่าข้อมูลสำรองไปที่อันไหน
- **rest-server ที่มีใบรับรองเซ็นเอง** วางใบรับรองเป็นไฟล์ PEM ในโฟลเดอร์ `certs` ของโฟลเดอร์ข้อมูลของ BombVault (`/config/certs` ในคอนเทนเนอร์ `appdata/bombvault/certs` บน Unraid) การสำรอง การคัดลอก และการทดสอบการป้องกันการลบจะเชื่อถือมันโดยไม่ต้องรีสตาร์ท

บริการ S3 ทำงานผ่านแบ็กเอนด์ S3 ของ restic เอง ซึ่งทำให้คลาสการจัดเก็บและ object lock ใช้ได้ restic เข้าถึง rest-server โดยตรง บริการอื่นทั้งหมดทำงานผ่าน rclone ที่ BombVault แถมมา และส่วนของการกำหนดค่า rclone ของมันแสดงในการ์ด **rclone.conf** บนหน้าของปลายทาง โดยซ่อนความลับ การส่งออกการตั้งค่ามีปลายทางที่จัดเก็บ และเมื่อรวมข้อมูลรับรองก็มีการลงชื่อเข้าใช้ของมันด้วย

การบันทึกปลายทางที่มีข้อมูลสำรองของคอนเทนเนอร์ VM หรือโฟลเดอร์อยู่แล้ว เช่นอันที่คุณเคยลบแล้วเพิ่มใหม่ จะเพิ่มมันให้ส่วนเหล่านั้นเป็นสำเนาที่ยังไม่ติ๊ก ไม่มีอะไรถูกคัดลอกไปที่นั่นจนกว่าคุณจะติ๊ก แต่ **กู้คืน** เสนอข้อมูลสำรองเก่าทันที

โฟลเดอร์บนเซิร์ฟเวอร์นี้เรียกว่า **ในเครื่อง** ทุกที่: บนหน้าที่จัดเก็บ ในโฟลว์ บนรายการ และบนการกู้คืน เมื่อมีหลายโฟลเดอร์บนเซิร์ฟเวอร์นี้ แต่ละอันใช้ชื่อของตัวเอง ปลายทางที่ช่องนอกสถานที่ของส่วนตั้งขึ้นมีชื่อตามที่ของมัน คือโฟลเดอร์สุดท้ายของที่อยู่ หรือถ้าไม่มี ก็เซิร์ฟเวอร์ของมัน และได้หมายเลขเมื่อมีปลายทางอื่นใช้ชื่อนั้นอยู่แล้ว ทุกปลายทางเปลี่ยนชื่อได้ในช่อง **ชื่อ** ของการ์ด **การเชื่อมต่อ** รวมถึงโฟลเดอร์บักเก็ตที่หลายส่วนใช้ร่วมกันและสำเนาที่ช่องนอกสถานที่ของส่วนอธิบาย และชื่อที่คุณตั้งจะอยู่ต่อ เมื่อมีสองปลายทางชื่อเดียวกันอยู่เคียงกัน แต่ละอันมีเซิร์ฟเวอร์หรือโฟลเดอร์ของมันกำกับ

### หน้าของปลายทางที่จัดเก็บ {#location-page}

ทุกปลายทางที่จัดเก็บมีหน้าของตัวเอง แสดงเฉพาะการ์ดที่ใช้กับปลายทางนั้น ตามลำดับนี้

![หน้าของปลายทางที่จัดเก็บ: โฟลเดอร์ของตัวเอง การเชื่อมต่อ และข้อมูลรับรอง](assets/screenshots/storage/location-page-dark.png#only-dark)
![หน้าของปลายทางที่จัดเก็บ: โฟลเดอร์ของตัวเอง การเชื่อมต่อ และข้อมูลรับรอง](assets/screenshots/storage/location-page-light.png#only-light)

- **โฟลเดอร์ของตัวเอง**: ส่วนที่เขียนข้อมูลสำรองลงที่นี่ก่อน ข้อมูลรับรอง การป้องกัน และขีดจำกัดของปลายทางนี้ใช้กับพวกมัน **ใช้เป็นโฟลเดอร์ของตัวเอง** ย้ายโฟลเดอร์ของตัวเองของอีกหลายส่วนมาที่นี่ และ **เปลี่ยน** ย้ายหนึ่งส่วนออกไปอีก ดู [โฟลเดอร์ของตัวเองของส่วน](#own-folder)
- **สำรองข้อมูลมาที่นี่โดยตรง**: แต่ละส่วนที่รายการของมันสำรองตรงมาที่นี่แทนโฟลเดอร์ของตัวเอง และมีกี่รายการ ที่เก็บโดยตรงแบบนั้นรับการตั้งค่าทั้งหมดจากปลายทางนี้ อันที่ไม่มีอะไรสำรองมาแล้วจะบอกไว้ และ **ลบ** เอามันออกจากรายการ ข้อมูลสำรองที่ที่มันอยู่ยังคงอยู่ ดู [ที่เก็บโดยตรง](#direct-repositories)
- **การเชื่อมต่อ**: **ชื่อ** สวิตช์ **พร้อมใช้งาน** (ปิดหมายถึง BombVault ไม่เขียนที่นี่อีก และรายการที่สำรองมาที่นี่ล้มเหลวพร้อมข้อความที่ชัดเจนแทนที่จะไปลงที่อื่น) โฟลเดอร์ **การบีบอัด** **คลาสการจัดเก็บ** และ **นอกสถานที่ตั้ง** บนปลายทาง **ในเครื่อง** มันลิสต์โฟลเดอร์ของแต่ละส่วนใต้ **โฟลเดอร์ของตัวเองที่นี่** **เปลี่ยนการเชื่อมต่อ** ทดสอบและบันทึกที่อยู่หรือการลงชื่อเข้าใช้ใหม่ เมื่อที่อื่นลงชื่อเข้าใช้ด้วยข้อมูลรับรองที่บันทึกไว้เดียวกัน หน้าต่างบอกไว้ และการเปลี่ยนที่นี่ให้ปลายทางนี้มีข้อมูลรับรองของตัวเองแทนที่จะเขียนทับอันที่ใช้ร่วม
- **ข้อมูลรับรอง**: ใช้ข้อมูลรับรองที่บันทึกไว้อันไหน (**ลงชื่อเข้าใช้ด้วย**) ปลายทางอื่นอันไหนใช้ด้วย (**ใช้โดยอีก**) และ **แก้ไข** ซึ่งเปิดหน้าต่างข้อมูลรับรอง ดู [ข้อมูลรับรอง](#sign-ins)
- **rclone.conf**: ส่วนของการกำหนดค่า rclone ของปลายทางนี้ สำหรับปลายทางที่ทำงานผ่าน rclone
- **การป้องกันการลบ** พร้อม **การป้องกันการลบ (append-only)**, **ยอมรับโดยไม่มีการป้องกันการลบ**, **ทดสอบการป้องกันการลบตอนนี้** และ **ใครพรูน** ซึ่งบอกว่า BombVault prune สำเนาและโฟลเดอร์ของตัวเองที่นี่ ตามการ์ด **เก็บไว้นานแค่ไหน** ของปลายทางนี้หรือค่าของส่วนนั้นเองใน **กฎแยกตามส่วน** หรือปล่อยให้ฝั่งไกลทำ โฟลเดอร์ในเครื่องแสดงการ์ดนี้เฉพาะเมื่อมีการป้องกันที่คุณปิดได้ ดู [การป้องกันการลบ](#delete-protection-append-only)
- **คัดลอก**: **คัดลอกเมื่อไร** และ **ขีดจำกัดการอัปโหลด (KiB/s)** กับ **ขีดจำกัดการดาวน์โหลด (KiB/s)** ปลายทางที่มีแต่โฟลเดอร์ของตัวเองและไม่มีสำเนาแสดงขีดจำกัดเป็นการ์ดชื่อ **แบนด์วิดท์**
- **เก็บไว้นานแค่ไหน**: **สั้น**, **สมดุล**, **ยาว** หรือ **ค่าที่กำหนดเอง** พร้อมไทม์ไลน์ว่ากฎเก็บการสำรองอันไหน ดู [เก็บไว้นานแค่ไหน](#keep)
- **อยู่ใต้ปลายทางนี้อยู่แล้ว**: ส่วนที่ที่อยู่ซึ่งพิมพ์เองอยู่ในโฟลเดอร์ของปลายทางนี้ การรับช่วงหนึ่งอันปล่อยที่เก็บไว้ที่เดิม จากนั้นข้อมูลรับรอง คลาสการจัดเก็บ และการป้องกันการลบมาจากปลายทาง BombVault ตรวจก่อนว่าข้อมูลรับรองของปลายทางเปิดที่เก็บได้ และปฏิเสธที่จะวางที่เก็บ append-only ใต้ปลายทางที่ไม่ใช่ append-only
- **กฎแยกตามส่วน**: ที่เก็บ การเก็บรักษา หรือการบีบอัดของส่วนหนึ่งเองที่ปลายทางนี้ **เปลี่ยนกฎ** เปิดมัน และ **คืนค่าตามปลายทาง** นำส่วนหนึ่งกลับ ข้อมูลรับรอง แบนด์วิดท์ และเวลาที่การคัดลอกรันมาจากปลายทางเสมอ
- ภาชนะที่แสดงว่าปลายทางเต็มแค่ไหน พร้อมเครื่องหมายที่ที่มันเต็ม และเหลืออีกกี่สัปดาห์ด้วยอัตราโตของไม่กี่สัปดาห์ล่าสุด ปลายทางที่ไม่รายงานขนาดบอก **ไม่ทราบขนาด**

**ย้าย** และ **ลบปลายทาง** อยู่ในการกระทำของหน้า อธิบายใต้ [ย้ายและลบ](#move-remove)

ปลายทางระยะไกลที่เคยมีข้อมูลสำรองแล้วจู่ ๆ ไม่มีที่เก็บ เช่น rest-server ที่ดิสก์ไม่ได้เมานต์ จะไม่ได้ที่เก็บใหม่ที่ว่างเปล่าขึ้นมาเอง หน้าของมันบอกไว้ทันทีที่การสำรองหรือการคัดลอกพบว่าที่เก็บหาย เมานต์ดิสก์อีกครั้ง ถ้าคุณล้างที่เก็บเดิมโดยตั้งใจ **สร้างที่เก็บข้อมูลใหม่ตรงนี้** เริ่มใหม่ สำหรับทุกส่วนของปลายทางและที่เก็บของมันพร้อมกัน

เซิร์ฟเวอร์รับที่อินสแตนซ์อื่นของกลุ่มคุณรันปรากฏในบรรดาผู้ให้บริการเป็น **จากกลุ่มของคุณ** ดู [เซิร์ฟเวอร์รับ](#receiving-server)

BombVault ตรวจปลายทางที่จัดเก็บของมันทุกครั้งที่เริ่ม มันแก้สิ่งที่ไม่ต้องการการตัดสินใจจากคุณ เช่นลิงก์ไปยังสำเนาหรือที่เก็บที่หายไป สำเนาบนโฟลเดอร์ของตัวเองของส่วน หรือที่เก็บโดยตรงที่สำเนาของมันหายไป และเขียนบรรทัดในบันทึกสำหรับการแก้แต่ละครั้ง สิ่งที่ไม่มีวิธีแก้ที่ปลอดภัยจะถูกบันทึกเท่านั้น

### เก็บไว้นานแค่ไหน {#keep}

ข้อมูลสำรองถูกเก็บนานแค่ไหนตั้งต่อปลายทางที่จัดเก็บ ในการ์ด **เก็บไว้นานแค่ไหน** ของมัน กฎครอบคลุมสำเนาที่ปลายทางนั้นและโฟลเดอร์ของตัวเองที่อยู่ที่นั่น รวมปลายทาง **ในเครื่อง** ส่วนหนึ่งเก็บค่าของตัวเองที่ปลายทางหนึ่งได้ใต้ **กฎแยกตามส่วน** และค่าเหล่านั้นชนะการ์ดของปลายทางสำหรับส่วนนั้น

กฎเก็บการสำรองหนึ่งอันต่อวัน สัปดาห์ เดือน และปี ย้อนหลังเท่าที่คุณตั้ง และล้างส่วนที่เหลือหลังการสำรองหรือการคัดลอกแต่ละครั้ง

| ค่าสำเร็จรูป | การสำรองล่าสุด | วัน | สัปดาห์ | เดือน | ปี |
|---|---|---|---|---|---|
| **สั้น** | 0 | 7 | 4 | 3 | 0 |
| **สมดุล** | 0 | 7 | 4 | 6 | 2 |
| **ยาว** | 0 | 14 | 8 | 12 | 3 |

**ค่าที่กำหนดเอง** ตั้งทั้งห้าจำนวนเอง 0 ปิดจำนวนนั้น และกฎที่ทุกจำนวนเป็น 0 เก็บทุกอย่าง จุดในการ์ดแสดงว่ากฎเก็บอันไหนจากการสำรองตัวอย่าง 40 อัน ใหม่สุดอยู่ขวาสุด ตัวอย่างเหมือนกันสำหรับทุกปลายทาง เพราะภาพถูกวาดก่อนที่ BombVault จะอ่านข้อมูลสำรองที่นั่น ตัวอย่างนับย้อนจากวันนี้ จำนวนจุดที่เหลือจึงเปลี่ยนไปตามวันที่

**ถามก่อนเก็บน้อยลง** เปิดอยู่โดยค่าเริ่มต้น ถามก่อนบันทึกการเปลี่ยนแปลงที่เก็บการสำรองน้อยลง และบอกว่ากฎใหม่ลบการสำรองตัวอย่าง 40 อันไปกี่อัน ใช้กับทุกปลายทางที่จัดเก็บ **คืนค่าตามปลายทาง** ใต้ **กฎแยกตามส่วน** ถามคำถามเดียวกัน

ปลายทางที่มีการป้องกันการลบจะไม่ถูก prune จากกล่องนี้ ฝั่งไกลของมันเก็บหรือทิ้งข้อมูลสำรองเก่าตามกฎของตัวเอง ขณะที่รายการมีความผิดปกติระดับร้ายแรงที่เปิดอยู่เกี่ยวกับข้อมูลที่หายไป การเก็บรักษาเก็บข้อมูลสำรองเก่าของรายการนั้นไว้จนกว่าคุณจะยืนยัน ดู [ความผิดปกติ](anomalies.md)

ถ้าจะดูว่ารอบถัดไปจะลบอะไรจริง ๆ เปิด **ดูตัวอย่าง** ใต้ **การตั้งค่า, ปลายทางที่จัดเก็บ** มันลิสต์ **สิ่งที่รอบถัดไปจะลบออก** ต่อที่เก็บและต่อรายการ พร้อมระบุชื่อจุดกู้คืน มันไม่ถือล็อกและไม่เปลี่ยนอะไร

#### ตัวอย่าง: สิ่งที่สมดุลเก็บไว้ {#example-retention}

คอนเทนเนอร์ถูกสำรองทุกคืนเวลา 03:00 ตั้งแต่ 1 ตุลาคม 2024 ดังนั้นในวันพุธที่ 4 พฤศจิกายน 2026 มันมีการสำรอง 765 ครั้ง ปลายทางที่จัดเก็บของมันตั้งเป็น **สมดุล**: 7 วัน 4 สัปดาห์ 6 เดือน และ 2 ปี

แต่ละจำนวนเก็บการสำรองใหม่สุดของวัน สัปดาห์ เดือน หรือปีของมัน และการสำรองที่หลายจำนวนเลือกตรงกันจะถูกเก็บครั้งเดียว สัปดาห์นับจากวันจันทร์ถึงวันอาทิตย์

|---|---|---|

| 4 สัปดาห์ | 4 พ.ย., 1 พ.ย., 25 ต.ค., 18 ต.ค. | 25 ต.ค., 18 ต.ค. |

**ปี** ควรดูอีกครั้ง มันนับปีปฏิทินที่มีการสำรอง โดยเริ่มจากปีปัจจุบัน และการสำรองใหม่สุดของปีนี้คืออันของวันนี้ ปีแรกจึงไม่เพิ่มอะไรให้จำนวนอื่น และปีที่สองเพิ่มการสำรองสุดท้ายของปีก่อนหน้า นี่คือเหตุผลที่ระยะย้อนกลับของกฎเปลี่ยนไปตลอดปี การสำรองชุดเดียวกันใต้ค่าสำเร็จรูปแต่ละแบบ

การเปลี่ยนจาก **สมดุล** เป็น **สั้น** ถามก่อน เพราะ **ถามก่อนเก็บน้อยลง** คำถามบอกว่ากฎใหม่จะลบการสำรองออกกี่ชุดจาก 40 ชุดในภาพ ตัวเลขนั้นมาจากตัวอย่าง จึงเปลี่ยนไปตามวันที่และไม่ได้นับการสำรองของคุณเอง ในการสำรองของตัวอย่างนี้ 31 สิงหาคม 31 กรกฎาคม 30 มิถุนายน และ 31 ธันวาคม 2025 จะถูกลบ **บันทึกต่อไป** ใช้กฎ และ prune ครั้งถัดไปลบพวกมันจากปลายทางนั้นถาวร

ถ้าจะเก็บคอนเทนเนอร์นานกว่าส่วนอื่นที่ปลายทางนี้ กด **เปลี่ยนกฎ** ใต้ **กฎแยกตามส่วน** เลือก **คอนเทนเนอร์** และตั้ง **ค่าที่กำหนดเอง** ใน **กฎสำหรับคอนเทนเนอร์** เช่น 14 วัน 8 สัปดาห์ 12 เดือน และ 2 ปี ส่วนอื่นยังตามการ์ดของปลายทาง และ **คืนค่าตามปลายทาง** นำคอนเทนเนอร์กลับ

### ข้อมูลรับรอง {#sign-ins}

ข้อมูลรับรองคือคีย์หรือรหัสผ่านที่ BombVault ใช้สำหรับบริการ S3 หรือ rest-server ข้อมูลรับรองเป็นรายการเดียว คือการ์ด **ข้อมูลรับรอง** ใต้ **การตั้งค่า, ปลายทางที่จัดเก็บ** และแต่ละแถวบอกว่าปลายทางไหนใช้มัน (**ใช้โดย**)

- **บันทึกตอนคุณเพิ่มปลายทาง** เพิ่มปลายทางบันทึกคีย์ที่คุณพิมพ์เป็นข้อมูลรับรอง ปลายทางถัดไปที่บริการเดียวกันเลือกมันได้ใต้ **ข้อมูลรับรองที่บันทึกไว้** แทน **คีย์ใหม่** และการเปลี่ยนมันภายหลังมีผลกับทุกปลายทางที่ใช้มัน
- **ค่าเริ่มต้น** ดาวทำเครื่องหมายข้อมูลรับรองเริ่มต้น ใช้ทุกที่ที่ไม่ได้เลือกข้อมูลรับรอง เช่นที่อยู่ที่พิมพ์เอง แหล่ง pull หรือการกู้คืนบนการติดตั้งใหม่ **ตั้งเป็นค่าเริ่มต้น** ให้ดาวกับอันอื่น
- **แก้ไขและทดสอบ** **แก้ไข** ที่นี่หรือในการ์ด **ข้อมูลรับรอง** ของปลายทาง เปิดหน้าต่างเดียวสำหรับข้อมูลรับรอง **ทดสอบ** ลงชื่อเข้าใช้ทุกปลายทางที่ใช้มันด้วยสิ่งที่คุณพิมพ์ ก่อนบันทึกอะไร **บันทึก** เก็บมัน
- **การลบ** ข้อมูลรับรองลบได้เมื่อไม่มีปลายทางหรือแหล่ง pull ใดใช้มันเท่านั้น และค่าเริ่มต้นไปได้เฉพาะเมื่อเป็นอันสุดท้าย แถวจะบอกว่ายังมีอะไรใช้มันอยู่
- **การเปลี่ยนการเชื่อมต่อของปลายทาง** ไม่เคยเขียนทับข้อมูลรับรองที่ที่อื่นใช้ร่วม ปลายทางจะได้ข้อมูลรับรองของตัวเองแทน และหน้าต่างบอกล่วงหน้าว่าข้อมูลรับรองของมันถูกใช้ร่วม ถ้าจะเปลี่ยนอันที่ใช้ร่วมทุกที่ ให้แก้ไขในการ์ด **ข้อมูลรับรอง**

![การ์ดข้อมูลรับรอง: แต่ละข้อมูลรับรองที่บันทึกไว้พร้อมสิ่งที่ใช้มัน และดาวที่ค่าเริ่มต้น](assets/screenshots/storage/signins-light.png#only-light)

โฟลเดอร์บนเซิร์ฟเวอร์นี้ไม่ต้องใช้ข้อมูลรับรอง SMB, WebDAV, SFTP, Storage Box และไดรฟ์คลาวด์เก็บของตัวเองในการกำหนดค่า rclone ซึ่งการ์ด **rclone.conf** ของปลายทางแสดง จึงไม่ปรากฏในรายการนี้

### SMB, WebDAV และ rclone remote อื่น {#smb-webdav}

share ของ Windows หรือ Samba และเซิร์ฟเวอร์ WebDAV (Nextcloud, ownCloud, SharePoint หรืออื่น ๆ) เป็นไทล์ผู้ให้บริการใน **เพิ่มปลายทาง** ใต้ **NAS หรือเซิร์ฟเวอร์** กรอกโฮสต์และ share (SMB) หรือที่อยู่และชนิดเซิร์ฟเวอร์ (WebDAV) ผู้ใช้ และรหัสผ่าน แล้ว BombVault เขียนส่วน rclone ให้คุณ rclone ทำให้รหัสผ่านอ่านไม่ออกก่อนเก็บ

สำหรับบริการที่ไม่มีไทล์ ไทล์ **Rclone** ใต้ **การกำหนดค่า rclone ของคุณเอง** รับ remote ที่วางจาก rclone.conf พวกมันถูกเพิ่มเข้ากับ remote ที่ BombVault มีอยู่แล้วและไม่เคยแทนที่ และเก็บแบบเข้ารหัส ถ้าจะสำรองส่วนหนึ่งไปยังอันใดอันหนึ่ง ให้กรอก `rclone:<remote>:<folder>` เป็นที่เก็บนอกสถานที่ของส่วนนั้น เช่น `rclone:nas:backups/bombvault` share หรือบักเก็ตคือส่วนแรกของพาธ ไม่ใช่ส่วนของชื่อ

นี่เป็นทางที่ดีกว่าการเมานต์ share บน Unraid: restic แนะนำไม่ให้เก็บที่เก็บบน share CIFS ที่เมานต์ และที่นี่ไม่มีอะไรถูกเมานต์ NFS ไม่มีไทล์เพราะทั้ง restic และ rclone ไม่มีแบ็กเอนด์ NFS สำหรับ NFS ให้เมานต์ export บนโฮสต์และใช้เป็นโฟลเดอร์ในเครื่อง

### ย้ายและลบ {#move-remove}

- **ย้าย** นำสำเนาของส่วนหนึ่งไปยังปลายทางอื่นพร้อมประวัติทั้งหมด ทุกอย่างอยู่ที่เดิม BombVault ไม่ลบอะไรที่นั่น การย้ายรันเบื้องหลังและอาจใช้เวลานาน: ราว 9 นาทีต่อ 100 GB ระหว่างดิสก์ในเครื่อง และหลายชั่วโมงผ่านสายที่ช้า ภาพรวมแสดงมันขณะรัน
- **ลบปลายทาง** มีสองทาง **ลบปลายทางแต่เก็บข้อมูลสำรอง** หยุดเขียนที่นั่นและปล่อยข้อมูลสำรองไว้ คุณอ่านมันทีหลังได้ใต้ **การกู้คืน, จากโฟลเดอร์สำรองข้อมูลเก่า** **ลบปลายทางและลบข้อมูลสำรองที่นั่น** อ่านก่อนว่าเก็บอะไรไว้ที่นั่นและลิสต์: การสำรองอันไหนจะไป อันไหนไม่มีที่อื่น และที่เก็บไหนอยู่ต่อเพราะการป้องกันการลบปฏิเสธ รายการยังสำรองตรงมาที่มัน ปลายทางหรือส่วนอื่นเก็บสำเนาไว้ที่นั่น หรืออ่านไม่ได้ รายการที่จะเสียข้อมูลสำรองอันเดียวของมันถูกลิสต์แยกและถูกเก็บไว้ เว้นแต่คุณเปิด **ลบรายการเหล่านี้ด้วย** คุณยืนยันด้วยการพิมพ์ชื่อของปลายทาง และการลบรันเบื้องหลัง
- ใช้ได้กับปลายทางที่จัดเก็บทุกชนิด: อันที่หลายส่วนใช้ ปลายทางที่ตั้งขึ้นสำหรับหนึ่งส่วน ที่เก็บที่คุณตั้งไว้ และโฟลเดอร์ที่ส่วนหนึ่งเขียนข้อมูลสำรองของตัวเองลงไป รายการที่สำรองไปยังที่เก็บที่ถูกลบจะกลับไปตามส่วนของมัน และค่าเริ่มต้นของส่วนที่ชี้ไปที่นั่นก็เช่นกัน โฟลเดอร์ของส่วนจะหายไปเฉย ๆ ไม่ได้ เพราะทุกส่วนต้องมีหนึ่งอัน หน้าต่างถามโฟลเดอร์ที่ส่วนต่าง ๆ จะย้ายไป และแต่ละส่วนเก็บชื่อโฟลเดอร์ของตัวเองใต้มัน
- การลบข้อมูลสำรองที่ปลายทางที่จัดเก็บต้องมีรหัสผ่านเข้าสู่ระบบและการลงชื่อเข้าใช้ที่อินสแตนซ์ ถ้าไม่มีรหัสผ่านก็ยังลบปลายทางได้ เพียงแต่ลบข้อมูลสำรองจากที่นี่ไม่ได้

### ตัวอย่าง: สำเนานอกสถานที่บน Backblaze B2 {#example-s3}

คอนเทนเนอร์และการสำรองตัวเองควรอยู่ที่ Backblaze B2 ด้วย เพื่อไม่ให้เซิร์ฟเวอร์ที่พังพามันไปด้วย ขั้นตอนเดียวกันใช้ได้กับ Wasabi, Hetzner Object Storage และบริการ S3 ส่วนใหญ่

1. **ใน B2** สร้างบักเก็ตส่วนตัว เช่น `tower-backups` ในภูมิภาคใกล้คุณ ใต้ **Application Keys** สร้างคีย์ที่อ่านและเขียนได้ จำกัดที่บักเก็ตนั้น และจด key ID กับ application key B2 แสดง application key ครั้งเดียว ตั้ง lifecycle ของบักเก็ตให้เก็บเฉพาะเวอร์ชันล่าสุด ไม่เช่นนั้น B2 เก็บข้อมูลที่ถูก prune เป็นเวอร์ชันซ่อนและคิดเงินคุณ
2. **ผู้ให้บริการ** ใน BombVault เปิด **ปลายทาง** กด **เพิ่มปลายทาง** และเลือก **Backblaze B2** ใต้ **บริการ S3**
3. **ลงชื่อเข้าใช้** กรอก key ID เป็น **ID คีย์การเข้าถึง** และ application key เป็น **คีย์การเข้าถึงลับ** กรอก endpoint ของบักเก็ตใต้ **เอนด์พอยต์** เช่น `s3.eu-central-003.backblazeb2.com` และ BombVault อ่านภูมิภาคจากมัน พิมพ์ `tower-backups` ลงใน **Bucket** เพราะคีย์นี้เปิดได้บักเก็ตเดียว
4. **ทดสอบการเชื่อมต่อ** ควรบอก **เชื่อมต่อแล้ว** และลิสต์โฟลเดอร์ของบักเก็ต กด **โฟลเดอร์ใหม่** และตั้งชื่อ `bombvault` BombVault ใส่หนึ่งโฟลเดอร์ต่อส่วนในนั้น เช่น `bombvault/containers`
5. **การป้องกัน** หน้าต่างอธิบายว่า B2 เก็บเวอร์ชันเก่าได้ด้วย object lock และ BombVault ตรวจเรื่องนี้ไม่ได้ ปล่อย **การป้องกันการลบ (append-only)** ไว้ปิด เว้นแต่บักเก็ตปฏิเสธการลบจริง เพื่อให้ BombVault prune ตามกฎการเก็บของปลายทางได้
6. **สำหรับส่วนใด** ติ๊ก **คอนเทนเนอร์** และ **สำรองข้อมูลตัวเอง** การสำรองตัวเองเก็บการตั้งค่าของคุณ การติดตั้งใหม่จึงนำมันกลับมาได้ หน้าต่างบอกว่ามีกี่รายการ และถ้ารู้ การคัดลอกครั้งแรกนำประวัติมาเท่าไร
7. กด **บันทึกปลายทาง**

การคัดลอกครั้งแรกรันหลังการสำรองครั้งถัดไป ถ้าจะเริ่มตอนนี้ เปิด **การตั้งค่า, ปลายทางที่จัดเก็บ** แล้วกด **จำลองตอนนี้** ในแถวของส่วนใน **สำเนานอกสถานที่** ส่วนหัวสถานะบอก **กำลังคัดลอกไปนอกสถานที่** การคัดลอกครั้งแรกนำประวัติทั้งหมดไป ดังนั้น 200 GB ผ่านอัปลิงก์ 100 Mbit/s ใช้เวลาราวสี่ชั่วโมงครึ่ง การคัดลอกครั้งต่อไปส่งเฉพาะสิ่งใหม่

เพื่อให้สายของคุณว่าง เปิดหน้าของปลายทางและตั้ง **ขีดจำกัดการอัปโหลด (KiB/s)** ในการ์ด **คัดลอก** เช่น `5120` ซึ่งอ่านเป็นราว 5.0 MB/s (41.9 Mbit/s) ตรวจ **เก็บไว้นานแค่ไหน** ในหน้าเดียวกันด้วยขณะอยู่ที่นั่น

ถ้าจะดูว่าสำเร็จ ดู **สถานะการป้องกัน** บนภาพรวม ซึ่ง **นอกสถานที่** เปลี่ยนเป็น **copy up to date** และแท็บ **การสำรองข้อมูล** ของคอนเทนเนอร์ ซึ่งสแนปช็อตของมันตอนนี้ระบุ `tower-backups` เป็นที่ที่สอง จากนั้นกด **ดาวน์โหลดชุดกู้คืน** อีกครั้งใต้ **การตั้งค่า, การกู้คืน** เพราะชุดกู้คืนลิสต์ปลายทางใหม่และการลงชื่อเข้าใช้ของมัน

**Cloudflare R2 ทำแบบเดียวกัน** โดยใช้โทเคนออบเจกต์แทนคีย์ วางที่อยู่ S3 ที่แดชบอร์ด R2 แสดงพร้อมบักเก็ต แล้ว BombVault กรอกเซิร์ฟเวอร์และบักเก็ตให้

### ตัวอย่าง: rest-server ที่คุณรันเอง {#example-rest-server}

rest-server ในโหมด append-only ปฏิเสธการลบ สำเนาบนมันจึงอยู่รอดแม้มีคนยึดเซิร์ฟเวอร์ของคุณ กล่องตัวที่สอง ที่บ้านเพื่อนหรือในโรงรถ ก็พอ BombVault ที่จับคู่ตั้งค่านี้ให้คุณได้ ดู [เซิร์ฟเวอร์รับ](#receiving-server) ถ้าจะรันด้วยมือบนโฮสต์ Docker ใดก็ได้

```sh
docker run -d --name rest-server --restart unless-stopped \
  -p 8000:8000 \
  -v /mnt/user/backups/rest-server:/data \
  -e OPTIONS="--append-only --private-repos" \
  restic/rest-server
docker exec -it rest-server create_user bombvault
```

บรรทัดสุดท้ายขอรหัสผ่านและเขียนผู้ใช้ลงไฟล์ `.htpasswd` ในโฟลเดอร์ข้อมูล

1. ใน BombVault กด **เพิ่มปลายทาง** และเลือก **rest-server** ใต้ **NAS หรือเซิร์ฟเวอร์**
2. กรอกที่อยู่พร้อมผู้ใช้เป็นโฟลเดอร์ของมัน เช่น `http://192.168.2.20:8000/bombvault` และ **ชื่อผู้ใช้** กับ **รหัสผ่าน** กด **ทดสอบการเชื่อมต่อ**
3. ใน **การป้องกัน** เปิด **การป้องกันการลบ (append-only)** BombVault จึงไม่ prune ที่นั่นเลยและปล่อยให้ฝั่งไกลทำ
4. ติ๊กส่วนต่าง ๆ แล้วกด **บันทึกปลายทาง**
5. เมื่อสำเนาแรกอยู่ที่นั่นแล้ว เปิดหน้าของปลายทางและกด **ทดสอบการป้องกันการลบตอนนี้** BombVault พยายามลบออบเจกต์ทดสอบ การ์ดควรบอก **Last: delete refused** และ **การป้องกันการลบ** บนภาพรวมเปลี่ยนเป็น **checked** ถ้ามันบอก **Last: delete not refused** แสดงว่าขาด `--append-only`

เพราะไม่มีอะไร prune สำเนานี้จากที่นี่ ให้ตั้ง **งบประมาณการเติบโต (GB, 0 = ปิด)** ในหน้าต่างของส่วน ซึ่งเปิดด้วย **แก้ไข** ในแถวของมันใน **สำเนานอกสถานที่** คุณจะได้รู้ก่อนดิสก์เต็ม ถ้ามีใบรับรองที่เซ็นเอง ดูหมายเหตุเรื่อง `certs` ข้างบน

## โฟลเดอร์ของตัวเองของส่วน {#own-folder}

ทุกส่วนมีโฟลเดอร์ของตัวเอง: ที่เก็บที่ข้อมูลสำรองถูกเขียนลงก่อน สำเนาไปยังปลายทางอื่นออกไปจากที่นั่น การติดตั้งใหม่เก็บโฟลเดอร์ของตัวเองไว้บนเซิร์ฟเวอร์นี้ ใต้ `/mnt/user/bombvault` และรวมกันเป็นปลายทางที่จัดเก็บ **ในเครื่อง**

โฟลเดอร์ของตัวเองอยู่ในปลายทางที่คุณมีอยู่แล้วได้ด้วย เช่น NAS, rest-server หรือบักเก็ต S3 ส่วนนั้นจะสำรองไปที่นั่นโดยตรง โดยไม่มีสำเนาในเครื่องคั่นกลาง และโฟลเดอร์ของตัวเองทำตามข้อมูลรับรอง การป้องกันการลบ และขีดจำกัดแบนด์วิดท์ของปลายทางนั้น BombVault prune โฟลเดอร์นี้หลังการสำรองแต่ละครั้งตามการ์ด **เก็บไว้นานแค่ไหน** ของปลายทาง และค่าของส่วนนั้นเองใน **กฎแยกตามส่วน** มีผลเหนือการ์ด ปลายทางลิสต์ส่วนนั้นในการ์ด **โฟลเดอร์ของตัวเอง** ของมัน และ **ปลายทางแยกตามส่วน** แสดงปลายทางนั้นเป็นบ้านของส่วน

### ย้ายโฟลเดอร์ของตัวเอง {#move-own-folder}

1. เปิดปลายทางที่จัดเก็บที่ควรเก็บโฟลเดอร์ของตัวเอง แล้วเลือก **ใช้เป็นโฟลเดอร์ของตัวเอง** หรือ **เพิ่มส่วน** ในการ์ด **โฟลเดอร์ของตัวเอง** ถ้าจะย้ายหลายส่วนพร้อมกัน เลือก **ย้ายโฟลเดอร์ของตัวเอง** ข้าง **โฟลเดอร์ของตัวเองที่นี่** ในการ์ด **การเชื่อมต่อ** ของปลายทาง Local
2. เลือกส่วนใต้ **ส่วน** และที่ใต้ **ย้ายไปที่** **ที่อื่น** รับโฟลเดอร์บนโฮสต์นี้หรือที่อยู่ของที่เก็บระยะไกลที่พิมพ์เอง พร้อมข้อมูลรับรองจากที่คุณบันทึกไว้
3. อ่าน **สิ่งที่จะเกิดขึ้น** สำหรับแต่ละส่วนมันบอกว่าข้อมูลสำรองใหม่ไปที่ไหน สำเนาที่อยู่ที่ที่ใหม่แล้วจะกลายเป็นโฟลเดอร์ของตัวเองหรือไม่ และข้อมูลสำรองไหนถูกคัดลอกไปก่อน
4. **คัดลอกข้อมูลสำรองที่ทำไว้แล้ว** เปิดอยู่โดยค่าเริ่มต้น เมื่อปิด ข้อมูลสำรองเก่าอยู่ที่เดิมและยังกู้คืนจากที่นั่นได้
5. เลือก **สลับ** เมื่อการ์ด **เก็บไว้นานแค่ไหน** ของที่ใหม่เก็บน้อยกว่ากฎของส่วนนั้นในตอนนี้ BombVault จะถามก่อนว่า **เก็บน้อยลงใช่ไหม** ในคำถามนั้น ตัวเลือก **คงค่าปัจจุบันของส่วนนั้นไว้ใน กฎแยกตามส่วน** จะพาค่าปัจจุบันไปด้วย **บันทึกต่อไป** จะทำต่อ และ **ย้อนกลับ** จะปล่อยทุกอย่างไว้ตามเดิม เมื่อต้องคัดลอกข้อมูลสำรองก่อน BombVault คัดลอกแล้วจึงสลับโฟลเดอร์ของตัวเอง เมื่อมันอยู่ที่นั่นแล้ว มันตรวจก่อนสลับ

หลังการย้าย ข้อมูลสำรองใหม่ไปที่โฟลเดอร์ของตัวเองที่ย้ายแล้ว รวมถึงส่วนที่ปิด **ในเครื่อง** และสำรองตรงไปยังสำเนา สำเนาที่อยู่ที่ที่ใหม่อยู่แล้วกลายเป็นโฟลเดอร์ของตัวเอง และการคัดลอกไปที่นั่นสิ้นสุด ที่ที่สำเนานั้นเก็บข้อมูลสำรองบางอันนานกว่ากฎการเก็บของส่วน ส่วนนั้นเก็บสิ่งที่กฎใดกฎหนึ่งเก็บ จึงไม่มีอันไหนหาย

เมื่อการย้ายทำต่อไม่ได้ หน้าต่างบอกเหตุผลในกล่องใต้ **สิ่งที่จะเกิดขึ้น** เมื่อมีแค่การคัดลอกข้อมูลสำรองเก่าเป็นอุปสรรค การปิด **คัดลอกข้อมูลสำรองที่ทำไว้แล้ว** ให้โฟลเดอร์ของตัวเองย้ายโดยไม่มีมัน

ส่วนต้องมีโฟลเดอร์ของตัวเองเสมอ การลบปลายทางที่เก็บมันถามโฟลเดอร์ที่ส่วนจะย้ายไป ดู [ย้ายและลบ](#move-remove) โฟลเดอร์ของตัวเองที่ข้อมูลสำรองใหม่เลี่ยง เพราะส่วนสำรองตรงไปยังสำเนา จะทำเครื่องหมาย **(ปิด)** ในที่ที่ปลายทางลิสต์ว่าใครใช้มัน

#### ตัวอย่าง: คอนเทนเนอร์ย้ายไป NAS {#example-own-folder}

พูลแคชกำลังเต็ม และคุณมีปลายทางที่จัดเก็บชื่อ `nas` ซึ่งเป็น share SMB บนกล่องตัวที่สอง ส่วนคอนเทนเนอร์มีการสำรอง 61 ครั้งในโฟลเดอร์ของตัวเองบนเซิร์ฟเวอร์นี้ และคัดลอกไปยัง Backblaze B2

1. เปิด **ปลายทาง** แล้ว `nas` และกด **ใช้เป็นโฟลเดอร์ของตัวเอง**
2. ติ๊ก **คอนเทนเนอร์** ใต้ **ส่วน**
3. อ่าน **สิ่งที่จะเกิดขึ้น** มันบอกว่าข้อมูลสำรองใหม่ของคอนเทนเนอร์ไปที่โฟลเดอร์บน `nas` ว่าข้อมูลสำรอง 61 ครั้งใน Local ถูกคัดลอกไปที่นั่นก่อน ว่าการคัดลอกไป Backblaze B2 ดำเนินต่อ และว่าการป้องกัน ขีดจำกัดแบนด์วิดท์ และสัญญาณเตือนการเติบโตมาจาก `nas`
4. คง **คัดลอกข้อมูลสำรองที่ทำไว้แล้ว** ไว้เปิดและกด **สลับ**

BombVault คัดลอกข้อมูลสำรองเบื้องหลังแล้วสลับโฟลเดอร์ของตัวเอง หน้า `nas` ลิสต์คอนเทนเนอร์ใต้ **โฟลเดอร์ของตัวเอง** รายการที่ตามส่วนของมันระบุ `nas` เป็นบ้านของมัน และการสำรองครั้งถัดไปลงที่นั่น โดยการคัดลอกไป B2 ออกไปจาก `nas` จากนี้ไปการ์ด **เก็บไว้นานแค่ไหน** ของ `nas` จะ prune โฟลเดอร์นี้ โฟลเดอร์เก่าบนเซิร์ฟเวอร์นี้อยู่ที่เดิม และ BombVault ไม่ลบอะไรที่นั่น

### พิมพ์ที่อยู่ระยะไกลเอง {#remote-primary-repositories}

การ์ด **การเชื่อมต่อ** ของปลายทาง Local ยังรับที่อยู่ระยะไกลสำหรับโฟลเดอร์ของตัวเองของส่วนได้: **เปลี่ยน** ข้างส่วนเปิดหน้าต่างที่มีสวิตช์ **ในเครื่อง / ระยะไกล** **ระยะไกล** รับที่อยู่ restic เช่น `s3:...`, `rest:http://host:8000/repo`, `sftp:user@host:/repo` หรือ `rclone:remote:bucket/path` และ **การตั้งค่าความปลอดภัยของที่เก็บหลักระยะไกล** เพิ่มการทดสอบการเชื่อมต่อ ขีดจำกัดอัปโหลดและดาวน์โหลด การป้องกัน append-only พร้อมการทดสอบการแก้ไขข้อมูลเดียวกับที่ปลายทางนอกสถานที่ได้ และสัญญาณเตือนงบประมาณการเติบโต

ที่อยู่แบบนั้นลงชื่อเข้าใช้ด้วยข้อมูลรับรองเริ่มต้น เมื่ออยู่ในโฟลเดอร์ของปลายทางที่จัดเก็บที่คุณมี หน้าของปลายทางนั้นลิสต์ส่วนใต้ **อยู่ใต้ปลายทางนี้อยู่แล้ว** และการรับช่วงให้มันได้ข้อมูลรับรอง คลาสการจัดเก็บ และการป้องกันการลบของปลายทาง การย้ายโฟลเดอร์ของตัวเองเข้าปลายทางที่จัดเก็บด้วย **ใช้เป็นโฟลเดอร์ของตัวเอง** เป็นวิธีที่ง่ายกว่า เพราะหน้าต่างตรวจข้อมูลสำรองที่ทำไว้แล้วก่อนเปลี่ยนอะไร

## การวางต่อรายการ {#placement}

การ์ด **ตารางเวลาและปลายทาง** บนแท็บการตั้งค่าของรายการมีแถวปุ่ม: **ในเครื่อง** และหนึ่งปุ่มต่อปลายทางนอกสถานที่ของส่วน ปุ่มที่สว่างได้ข้อมูลสำรองของรายการ

- เมื่อ **ในเครื่อง** สว่าง รายการถูกเขียนลงที่เก็บที่แสดงใต้ **จัดเก็บที่** และคัดลอกไปยังทุกปลายทางที่สว่าง ทำให้ปลายทางมืดแล้วมันจะไม่ได้อะไรใหม่จากรายการนี้ ในเครื่องอย่างเดียวไม่คัดลอกไปไหน เหมาะกับข้อมูลที่มีสำเนาที่สองอยู่แล้ว เช่น share ที่อยู่บน NAS
- เมื่อ **ในเครื่อง** มืด รายการถูกเขียนตรงไปยังที่เก็บโดยตรงของปลายทางที่สว่างอันแรก และคัดลอกจากที่นั่นไปยังอันอื่นที่สว่าง ครั้งแรก กล่องสร้างที่เก็บโดยตรงนั้น
- ต้องเหลือหนึ่งปุ่มสว่างไว้ เพราะการสำรองต้องมีที่ไป ถ้าจะเว้นรายการจากการสำรอง ใช้ **ไม่สำรองข้อมูล**

BombVault ไม่เคยย้ายข้อมูลสำรองระหว่างที่เก็บ รายการที่ตามส่วนของมันไปด้วยเมื่อค่าเริ่มต้นของส่วนเปลี่ยน: การสำรองครั้งถัดไปลงที่ใหม่ และข้อมูลสำรองที่มีอยู่อยู่ที่เดิม ปลายทางที่เลือกบนรายการเองคงที่ตั้งแต่การสำรองครั้งแรก การ์ด **รีพอสิทอรี** บนแท็บการตั้งค่าระบุชื่อมัน สำเนาเปลี่ยนได้ทุกเมื่อ ปลายทางที่ไม่ได้รับรายการอีกต่อไปเก็บสำเนาที่มีอยู่และตัดตามการเก็บรักษาของตัวเองในการรันนอกสถานที่ครั้งถัดไปของส่วน ปลายทางแบบ append-only ลบจากมันไม่ได้

ที่ที่รายการจากมายังเก็บข้อมูลสำรองของมันไว้ บนแท็บ **การสำรองข้อมูล** ของรายการและบน **การกู้คืน** มันแสดงเป็น **เฉพาะข้อมูลสำรองเก่า** กู้คืนอ่านจากมันได้ และ prune ที่นั่นปล่อยข้อมูลสำรองเหล่านั้นไว้

**ใช้ตามค่าเริ่มต้น** นำรายการที่มีตัวเลือกของตัวเองกลับไปตามส่วนของมัน มันถามก่อน บอกว่าข้อมูลสำรองใหม่จะไปที่ไหนหลังจากนั้น และระบุว่าแต่ละปลายทางจะเลิกได้รับอะไรและการรันครั้งถัดไปจะอัปโหลดอะไร

ใต้แถวปุ่ม การ์ดบอกว่ารายการไปที่ไหนและมีอะไรอยู่ที่นั่นจริง: กี่ไซต์ถือมัน เห็นแต่ละปลายทางครั้งล่าสุดเมื่อไร และบรรลุ 3-2-1 หรือไม่ ไซต์คือเซิร์ฟเวอร์ที่มีข้อมูลต้นฉบับ ปลายทางนอกสถานที่แต่ละแห่ง และที่เก็บทุกอันที่ทำเครื่องหมาย **นอกสถานที่ตั้ง** BombVault ตรวจสำเนาและไซต์ มันไม่ตรวจส่วน "สองสื่อ" ของ 3-2-1

### ค่าเริ่มต้นรายส่วน {#placement-defaults}

การ์ด **ปลายทางแยกตามส่วน** บนหน้าปลายทางที่จัดเก็บวาดค่าเริ่มต้นของทุกส่วนเป็นโฟลว์ 3-2-1 ทุกเส้นจากส่วนไปยังปลายทางเป็นสวิตช์ รวม **ในเครื่อง** สำหรับทุกส่วน รวมแฟลชไดรฟ์ ชุดข้อมูล ZFS และการสำรองตัวเองด้วย คลิกที่เส้นหรือจุดเพื่อสลับทันที และเส้นประคือปิด เฉพาะการปิด **ในเครื่อง** ของส่วนเท่านั้นที่ถามก่อน ในกล่องเดียวกับการ์ดค่าเริ่มต้น เพราะส่วนนั้นจะสำรองตรงไปยังสำเนา **ยกเลิก** ปล่อยทุกอย่างตามเดิม **กราฟ / สวิตช์** แสดงสิ่งเดียวกันเป็นแถวของปุ่ม สวิตช์กำหนดว่าข้อมูลสำรองใหม่ไปที่ไหน รายการที่ไม่มีตัวเลือกของตัวเอง และโฟลเดอร์โปรเจกต์ของสแตก Compose ตามไปทันที การสำรองครั้งถัดไปของพวกมันจึงไปที่ใหม่ ข้อมูลสำรองที่เก็บไว้แล้วอยู่ที่เดิมและยังกู้คืนจากที่นั่นได้ แฟลช ชุดข้อมูล ZFS และการสำรองตัวเองสำรองไปยังโฟลเดอร์ในเครื่องของพวกมันและคัดลอกนอกสถานที่จากการสำรองนั้น เส้นของพวกมันไปยัง **ในเครื่อง** ปิดได้ด้วย ข้อมูลสำรองของพวกมันก็ไปตรงยังปลายทางนอกสถานที่ และรายการ ZFS ที่มีเรพลิกาและไม่มีปลายทางเลยส่งเฉพาะเรพลิกา

เมื่อ **ในเครื่อง** ปิดและเปิดเฉพาะปลายทางนอกสถานที่ ส่วนนั้นสำรองตรงไปยังพวกมัน และ BombVault เลือกที่เก็บที่นั่นเอง คอนเทนเนอร์ VM และชุดโฟลเดอร์ไปยังที่เก็บโดยตรงของปลายทางแรกที่เปิด อธิบายด้านล่าง และถูกคัดลอกจากที่นั่นไปยังอันอื่น แฟลชไดรฟ์ ชุดข้อมูล ZFS และการสำรองตัวเองเขียนทุกการสำรองลงทุกปลายทางที่เปิด และแต่ละปลายทางเก็บมันตามการเก็บรักษาของตัวเอง

ส่วนที่ทุกเส้นปิดบอก **ไม่ได้สำรองข้อมูล** รายการของมันไม่ได้รับการสำรองและนับว่ายังไม่ได้ป้องกัน

รายการที่เลือกปลายทางของตัวเองบนหน้าของมันเก็บตัวเลือกนั้นไว้ โฟลว์บอกว่าในส่วนหนึ่งมีกี่อัน เช่น **2 entries differ** และพาไปหาพวกมัน: ไปแท็บการตั้งค่าของรายการเมื่อมีอันเดียว ไปรายการที่แสดงว่าแต่ละอันสำรองที่ไหนเมื่อมีหลายอัน **ใช้ตามค่าเริ่มต้น** ที่นั่นนำรายการกลับ

ปลายทางนอกสถานที่ใหม่รับทุกรายการที่ไม่ได้ตั้งเป็น Local หน้าต่างที่เพิ่มมันบอกว่ามีกี่รายการ และถ้ารู้ ประวัติเท่าไร

### ที่เก็บโดยตรง {#direct-repositories}

ที่เก็บโดยตรงคือที่ที่รายการสำรองตรงไปยังปลายทางนอกสถานที่ BombVault วางมันข้างโฟลเดอร์ของปลายทางโดยเติม `-direct` ที่ชื่อ หรือเมื่อปลายทางอยู่ที่รากของบักเก็ต remote หรือผู้ใช้ rest-server ของมัน ก็วางในโฟลเดอร์ข้างในที่ตั้งชื่อตามส่วน เช่น `containers-direct` ในโฟลว์บนหน้าปลายทางที่จัดเก็บ มันถูกสร้างโดยไม่ถาม การปิด Local สำหรับรายการเดียว เพื่อให้ปลายทางที่ไม่มีที่เก็บโดยตรงกลายเป็นบ้านของมัน เปิดกล่องพร้อมปลายทางที่เสนอ เช่น `s3:https://s3.eu-central-003.backblazeb2.com/bucket/containers-direct` และการทดสอบการเชื่อมต่อที่ไม่สร้างอะไร **สร้างและใช้งาน** สร้างที่เก็บและชี้รายการไปที่มัน ที่เก็บโดยตรงไม่มีการตั้งค่าของตัวเอง มันตามสวิตช์ ข้อมูลรับรอง คลาสการจัดเก็บ ขีดจำกัด การตั้งค่า append-only และการเก็บรักษาของปลายทาง และเปลี่ยนไปพร้อมกัน หน้าของปลายทางลิสต์มันใต้ **สำรองข้อมูลมาที่นี่โดยตรง** พร้อมแต่ละส่วนที่สำรองตรงมาที่มันและมีกี่รายการ อันที่ไม่มีอะไรสำรองมาแล้วจะบอกไว้ที่นั่นและลบได้ และข้อมูลสำรองที่ที่มันอยู่คงอยู่ เมื่อคีย์ใหม่ของปลายทางเปิดมันไม่ได้ ที่เก็บโดยตรงเก็บคีย์ที่มีไว้ และการบันทึกบอกไว้ รายการบนที่เก็บโดยตรงถูกคัดลอกจากที่นั่นไปยังปลายทางอื่นที่เปิด ไม่เคยไปยังปลายทางที่ที่เก็บนั้นเป็นของ สแนปช็อตของมันมีแท็ก `bv:direct` และการเก็บรักษาทุกรอบอื่นเก็บมันไว้ ที่เก็บโดยตรงที่เสียลิงก์ไปยังปลายทางจึงไม่เคยหมดอายุตามกฎในเครื่อง เข้าถึง B2 ผ่าน endpoint S3 ของมัน โดยกรอก key ID และ application key เป็นคีย์ S3 คีย์ที่จำกัดอยู่ที่โฟลเดอร์ของปลายทางเองเข้าถึงโฟลเดอร์ข้าง ๆ ไม่ได้ ให้จำกัดคีย์ที่โฟลเดอร์ข้างบนแทน

### นอกสถานที่ตั้ง {#off-the-premises}

ปลายทางที่จัดเก็บหรือที่เก็บทำเครื่องหมาย **นอกสถานที่ตั้ง** ได้ อันที่เป็นระยะไกลเริ่มต้นด้วยเครื่องหมายนี้ ปิดมันสำหรับ rest-server ในอาคารเดียวกัน เครื่องหมายนับไซต์และ 3-2-1 บนการ์ดเท่านั้น มันไม่เปลี่ยนสำเนาใดเลย

เรพลิกา ZFS เป็นสำเนานอกสถานที่ แต่ไม่ใช่การสำรองที่มีประวัติ มันเก็บเฉพาะสแนปช็อตที่คุณตั้ง และเวอร์ชันเก่าและไฟล์เดี่ยวยังมาจากการสำรอง มันไปจากเซิร์ฟเวอร์ ZFS ตัวหนึ่งตรงไปอีกตัว ผ่าน SSH ไปยังเซิร์ฟเวอร์ ZFS หรือไปยัง endpoint รับของอินสแตนซ์ที่จับคู่ กลุ่มจับคู่แค่ส่งคำขอ ดู [เรพลิกา](zfs-datasets.md#replica)

### หลังสร้างใหม่ {#after-a-rebuild}

ตัวเลือกการคัดลอกอยู่ในการตั้งค่าของ BombVault เอง หลังการสร้างใหม่ผ่าน **ค้นหาการสำรองข้อมูล** หรือตัวช่วยฉุกเฉินโดยไม่กู้คืนการตั้งค่า มันหายไป และการคัดลอกทุกอย่างจะส่งรายการที่คุณเว้นไว้ไป B2 อีกครั้ง สำเนานอกสถานที่ของทุกส่วนที่สร้างใหม่จึงหยุด ภาพรวมบอกไว้ และการ์ด **ปลายทางแยกตามส่วน** เสนอ **ยืนยันค่าเริ่มต้น** พร้อมตัวอย่างสิ่งที่การรันครั้งถัดไปจะคัดลอกและชื่อในข้อมูลสำรองที่ไม่มีรายการ ซึ่งคุณเว้นได้ที่นั่น มีเพียงการยืนยันเท่านั้นที่จบการหยุด การนำเข้าไฟล์การตั้งค่านำกฎและค่าเริ่มต้นกลับมา แต่ไม่จบการหยุด

## การป้องกันการลบ (append-only) {#delete-protection-append-only}

เปิดการป้องกันการลบสำหรับปลายทางนอกสถานที่ เพื่อให้แรนซัมแวร์หรือโฮสต์ที่ถูกบุกรุกลบหรือเขียนทับข้อมูลสำรองของคุณไม่ได้ ฝั่งไกล (`restic/rest-server` ที่รันในโหมด `--append-only`) **บังคับ** มัน BombVault **ตรวจสอบ** มันเท่านั้น และไม่เคยแสดงสีเขียวจากการอ้างการกำหนดค่าอย่างเดียว โฟลเดอร์บนเซิร์ฟเวอร์นี้ปฏิเสธการลบไม่ได้ เพราะใครควบคุม BombVault ก็ควบคุมโฟลเดอร์ด้วย ปลายทางในเครื่องจึงไม่เสนอสวิตช์

สวิตช์เป็นของปลายทางที่จัดเก็บ: ส่วนที่คัดลอกไปที่นั่นรับมันจากปลายทาง จึงเปิดจากหน้าของปลายทางใต้ **ปลายทาง** **ตรวจสอบการป้องกันการลบ** ตามกำหนดรันเฉพาะขณะที่ส่วนหนึ่งคัดลอกไปยังปลายทางที่เปิดสวิตช์ ฝั่งไกลต้องเริ่มด้วย `--append-only` กับ image `restic/rest-server` บน TrueNAS เหมือนบนโฮสต์ Docker อื่น นั่นไปอยู่ในตัวแปร `OPTIONS`

บางที่ปฏิเสธการลบไม่ได้เลย เช่นไดรฟ์คลาวด์อย่าง OneDrive ถ้าคุณเก็บสำเนาไว้ที่นั่นโดยตั้งใจ ให้เปิด **ยอมรับโดยไม่มีการป้องกันการลบ** บนหน้าของปลายทาง ภาพรวมจะแสดงการขาดการป้องกันการลบของส่วนที่คัดลอกไปยังปลายทางที่ยอมรับแล้วเท่านั้นเป็นความเสี่ยงที่ยอมรับ เป็นวงสีเทาแทนจุดสีเหลืองอำพัน และสีของส่วนตามการตรวจอื่น ไม่มีอะไรอย่างอื่นเปลี่ยน: ข้อมูลสำรองที่นั่นยังลบได้ BombVault ยัง prune มันตามกฎการเก็บของปลายทาง และสวิตช์หายไปเมื่อเปิดการป้องกันการลบ สำเนาที่ย้ายไปที่อื่นเสียการยอมรับ การเปิดการป้องกันการลบก็ล้างมันเช่นกัน

ทางที่เร็วที่สุดสู่สำเนา append-only คือ BombVault ที่จับคู่พร้อม [เซิร์ฟเวอร์รับ](#receiving-server): มันรัน rest-server ให้คุณในโหมด append-only

!!! note "การลบที่สำเร็จใต้ `/locks/` เป็นเรื่องที่คาดไว้"
    append-only ไม่ได้หมายความว่าไม่มีอะไรลบได้เลย restic ต้องรับและปล่อยล็อกของตัวเอง `/locks/` จึงเขียนและลบได้โดยออกแบบ สแนปช็อตและข้อมูลที่อยู่เบื้องหลัง ซึ่งเป็นสิ่งที่แรนซัมแวร์จะไล่ตาม ลบไม่ได้ ถ้าคุณตรวจฝั่งไกลเอง การลบที่สำเร็จใต้ `/locks/` เป็นพฤติกรรมที่ถูกต้อง ไม่ใช่ช่องโหว่ในการป้องกัน

!!! warning "ที่เก็บ append-only ไม่เคยถูก prune จากกล่องนี้"
    ปลายทาง append-only ไม่เคย prune สแนปช็อตเก่าจากที่นี่ การ prune เป็นงานของฝั่งไกล ตั้ง **สัญญาณเตือนงบประมาณการเติบโต** ให้มัน คุณจะได้รับแจ้งก่อนขนาดที่เก็บบานปลาย

## การทดสอบการแก้ไขข้อมูล {#tamper-test}

BombVault พิสูจน์การรับประกัน append-only เป็นระยะด้วยการพยายามลบกับที่เก็บนอกสถานที่จริง ๆ โดยเล็งไปที่ออบเจกต์ที่ไม่มีอยู่ **ทดสอบการป้องกันการลบตอนนี้** บนหน้าของปลายทางรันตามสั่ง และ **ตรวจสอบการป้องกันการลบ** ใต้ **การตั้งค่า, ยืนยัน, การตรวจสอบอัตโนมัติ** รันตามกำหนด

การปิด **ตรวจสอบการป้องกันการลบ** ไม่ซ่อนช่องว่าง ปลายทางที่มีการป้องกันการลบแต่ไม่เคยทดสอบจะอ่านว่า "not proven, its check is off" และปลายทางที่ไม่มีการป้องกันการลบอ่านว่า "none" ไม่ว่าจะอย่างไร

สำเนาที่ปิดอยู่ไม่ถูกทดสอบ และปลายทางบอกไว้ การทดสอบการเชื่อมต่อยังรันบนมัน เพราะมันอ่านอย่างเดียว สำเนาจึงตรวจได้ก่อนเปิด

- **Refused** หมายถึงได้รับการป้องกัน
- **Accepted** หมายถึงไม่ได้รับการป้องกัน
- ผล **สรุปไม่ได้** (เซิร์ฟเวอร์เข้าไม่ถึง ข้อผิดพลาดการยืนยันตัวตน) ไม่เคยพลิกคำตัดสินที่เก็บไว้

การพลิกจากได้รับการป้องกันเป็นไม่ได้รับการป้องกันจริง ๆ ส่งการเตือนหนึ่งครั้ง

## การซ้อม DR {#dr-drills}

BombVault เสนอการพิสูจน์สองระดับว่าข้อมูลสำรองของคุณกู้คืนได้จริง ไม่ใช่แค่มีอยู่

- **การซ้อมตรวจสอบการกู้คืน (ในเครื่อง)** BombVault รัน `restic check --read-data-subset` เป็นระยะ (มีขอบเขต ไม่ใช่การกู้คืนเต็มที่ทำให้ดิสก์เต็ม) ความถี่อยู่ใต้ **การตั้งค่า, ยืนยัน, การตรวจสอบอัตโนมัติ** และการ์ด **ตรวจสอบข้อมูลสำรอง** บนไทล์เดียวกันแสดงผล
- **การทดสอบกู้คืน (นอกสถานที่)** BombVault กู้คืนเป้าหมายจริงจากที่เก็บนอกสถานที่ลงแซนด์บ็อกซ์ที่ปิดสนิท ตรวจทีละไฟล์และทีละไบต์ แล้วล้างทิ้ง นี่พิสูจน์ว่าคุณกู้คืนจากนอกสถานที่ได้ ไม่ใช่แค่ที่เก็บตอบสนอง

การ์ด **สถานะการป้องกัน** บนภาพรวมสรุปสิ่งนี้ต่อส่วนเป็นการตรวจสี่อย่าง: การสำรองล่าสุดบนเซิร์ฟเวอร์นี้ สำเนานอกสถานที่ การป้องกันการลบที่นั่น และการทดสอบกู้คืนจากที่นั่น คลิกที่ส่วนเพื่อดูรายละเอียด และการ์ดเป็นสีเขียวเฉพาะเมื่อมีข้อเท็จจริงที่ตรวจสอบแล้ว ปลายทางที่คุณยอมรับโดยไม่มีการป้องกันการลบนับที่นั่นเป็นความเสี่ยงที่ยอมรับ ไม่ใช่คำเตือน

## การจับคู่อินสแตนซ์ {#pairing}

BombVault หลายตัวทำงานร่วมกันเป็นกลุ่ม: แสดงสถานะการป้องกันของกันและกัน รับบทบาทให้กัน และเก็บคีย์ให้กันได้ อินสแตนซ์เข้าร่วมกลุ่มด้วยคำสิบสองคำ

![หน้าการจับคู่พร้อมการ์ดสามขั้น](assets/screenshots/offsite/pairing-dark.png#only-dark)
![หน้าการจับคู่พร้อมการ์ดสามขั้น](assets/screenshots/offsite/pairing-light.png#only-light)

บนอินสแตนซ์แรก เปิด **การตั้งค่า, การจับคู่** แล้วกด **สร้างวลี** การ์ดสามขั้นแสดงว่าทำอย่างไร คำสิบสองคำปรากฏในหน้าต่างพร้อมปุ่ม **คัดลอก** บนอินสแตนซ์อื่นทุกตัว เปิดที่เดียวกัน กด **ป้อนวลี** แล้ววางหรือพิมพ์ หรือกด **วาง** ในหน้าต่างนั้น คำที่ไม่อยู่ในรายการจะถูกระบุพร้อมตำแหน่งขณะที่คุณพิมพ์ และคำสุดท้ายมี checksum คำที่พิมพ์ผิดหรือสลับจึงถูกจับได้ก่อนที่จะจับคู่อะไร สร้างวลีบนอินสแตนซ์เดียวเท่านั้น: สองอินสแตนซ์ที่ต่างสร้างวลีจะเป็นสองกลุ่มแยกกัน ถ้าไม่มีใครปรากฏภายในหนึ่งนาที หน้ามีสองทางออก: แสดงคำอีกครั้งเพื่อไปป้อนที่อีกฝั่ง หรือป้อนคำของอินสแตนซ์อื่นและเข้าร่วมกลุ่มของมันในขั้นเดียว การจับคู่ใช้ได้โดยไม่มีรหัสผ่านเข้าสู่ระบบ แต่ควรตั้ง: ถ้าไม่มี ใครที่เปิดหน้าเว็บได้ก็อ่านคำและผ่านกลุ่มขอบทบาทที่ส่งรหัสผ่าน restic ของอินสแตนซ์ในนั้นได้ การ์ดการจับคู่บอกไว้จนกว่าจะตั้งรหัสผ่าน เมื่อมีรหัสผ่าน การแสดงวลีอีกครั้งจะขอมัน **ออกจากกลุ่ม** นำอินสแตนซ์ออก การ์ด **อินสแตนซ์** บนหน้าการจับคู่ลิสต์สมาชิกของกลุ่ม ภาพว่าใครทำอะไรให้ใครอยู่ที่หน้าอินสแตนซ์

ใครที่รู้คำก็เข้าร่วมกลุ่มได้ จึงปฏิบัติต่อมันเหมือนรหัสผ่าน

**สมาชิกเข้าถึงกันอย่างไร** แต่ละอินสแตนซ์เรียนรู้ที่อยู่ของตัวเองบนเครือข่ายจากเบราว์เซอร์ของคุณในขณะที่คุณลงชื่อเข้าใช้ ลิสต์ไว้ใต้ **ที่อยู่ที่รู้จัก** ในการ์ด **อินสแตนซ์นี้** บนหน้าการจับคู่ พร้อมอันที่อินสแตนซ์พบเอง แก้ไขที่นั่นถ้ามี reverse proxy หรือพอร์ตผิดปกติอยู่ข้างหน้า บนเครือข่ายเดียวกัน สมาชิกประกาศที่อยู่นั้นด้วย multicast และคุยกันโดยตรง และที่ที่ multicast ข้ามเครือข่ายคอนเทนเนอร์ไม่ได้ เช่น bridge เริ่มต้นของ Docker อินสแตนซ์จะค้นซับเน็ตของตัวเองหาตัวอื่นด้วยการเรียกที่เซ็นซึ่งมีแต่สมาชิกกลุ่มตอบได้แทน การจับคู่จึงเสร็จในไม่กี่วินาทีโดยไม่ต้องใช้รีเลย์ ถ้าไม่พบอะไร **หาไม่เจอหรือไม่** รับที่อยู่หนึ่งอันด้วยมือ สำหรับซับเน็ตอื่นหรือพอร์ตที่ไม่ใช่มาตรฐาน อินสแตนซ์บนเครือข่ายต่างกันผ่านรีเลย์ ซึ่งเลือกในแถวสี่แบบในการ์ด **รีเลย์** บนหน้าเดียวกัน แต่ละแบบมีภาพประกอบ

- **รีเลย์ของโครงการ** (ค่าเริ่มต้น): `parleyport.halleluja.design` รีเลย์ที่ KnightLoader ใช้ด้วย ไม่ต้องตั้งค่าอะไร
- **รีเลย์ของตัวเอง**: คอนเทนเนอร์ [**ParleyPort**](https://github.com/junkerderprovinz/parleyport) จาก Unraid Community Apps (อยู่ใต้ **การตั้งค่า, แอป** ด้วย) กรอกที่อยู่ของมันบนทุกอินสแตนซ์ที่ควรใช้
- **อินสแตนซ์ BombVault**: อินสแตนซ์ของคุณหนึ่งตัวที่เข้าถึงได้จากภายนอกอยู่แล้ว โดยเปิด **ทำหน้าที่เป็นรีเลย์** อินสแตนซ์นั้นตอบที่ `/relay/connect` ที่ที่อยู่ของตัวเอง หลัง reverse proxy และใบรับรองที่มันมีอยู่แล้ว และให้เข้าเฉพาะกลุ่มของคุณ กรอกที่อยู่ของมันบนทุกอินสแตนซ์ที่ควรใช้
- **ไม่ใช้รีเลย์**: สมาชิกพบกันเองอัตโนมัติบนเครือข่ายเดียวกัน และไม่มีที่อื่น

**สิ่งที่รีเลย์เห็น** ปุ่มชื่อเดียวกันข้างสี่แบบแสดงเรื่องนี้สำหรับแบบที่คุณเลือก ทุกการเรียกระหว่างสมาชิกถูกปิดผนึกด้วย AES-256-GCM ใต้คีย์ที่สร้างจากคำสิบสองคำ และคีย์นั้นไม่เคยออกจากอินสแตนซ์ของคุณ รีเลย์รู้แฮชที่จัดกลุ่มการเชื่อมต่อ ข้อความไปหาอินสแตนซ์ไหน ใหญ่แค่ไหน และผ่านเมื่อไร การเรียกตรงบนเครือข่ายภายในถูกปิดผนึกแบบเดียวกันและเซ็นด้วย จึงไม่มีอะไรขึ้นกับใบรับรองที่เซ็นเองที่อินสแตนซ์ให้บริการ การเรียกที่ส่งมอบบางอย่าง (คำตอบบทบาท รหัสผ่าน restic การเข้าสู่ระบบของตัวรับ การฝากคีย์) ยังเซ็นด้วยคีย์ของสมาชิกที่ส่ง ปักหมุดตอนเห็นครั้งแรก ดู [โมเดลความปลอดภัย](configuration.md#security-model)

**อะไรเดินทางผ่านกลุ่ม** สถานะการป้องกันบนหน้าอินสแตนซ์ คำขอให้ตรวจหนึ่งส่วนตอนนี้ คำขอบทบาทและคำตอบ ข้อเสนอที่จัดเก็บ และสิ่งที่ตัวรับหรือตัวดึงต้องใช้เมื่อบทบาทได้รับอนุญาต คือตำแหน่งที่เก็บของอินสแตนซ์อีกฝั่งและรหัสผ่าน restic ของมัน ข้อมูลสำรองไม่เคย มันยังไปตรงยังแบ็กเอนด์ restic APP_KEY ก็ไม่ใช่: รหัสผ่าน restic เปิดที่เก็บของอินสแตนซ์นั้นและไม่เปิดอย่างอื่น ไม่ใช่ความลับที่เก็บไว้ เซสชัน หรือรหัสกู้คืน

**รายการจากก่อนการจับคู่** อินสแตนซ์ที่เพิ่มด้วยโทเคน fleet และที่เก็บที่รับและแหล่ง pull ที่ตั้งด้วย APP_KEY ของอินสแตนซ์อื่น อยู่ต่อหลังการอัปเดตและทำเครื่องหมาย **จับคู่ใหม่** มันทำงานต่อ: ตอนเริ่มครั้งแรก BombVault แทนที่ APP_KEY ที่เก็บไว้แต่ละอันด้วยรหัสผ่าน restic ที่สร้างจากมัน จับคู่ทั้งสองอินสแตนซ์ แล้วแก้ไขรายการและเลือกอินสแตนซ์ของมัน จนถึงตอนนั้นรายการแบบนั้นอยู่ในการ์ด **ไม่มีอินสแตนซ์** บนหน้าอินสแตนซ์

ที่เดียวที่ยังรับ APP_KEY ด้วยมือคือ [จากโฟลเดอร์สำรองข้อมูลเก่า](#restore-from-another-bombvault-repo) สำหรับกรณีที่อินสแตนซ์อื่นหายไปและตอบในกลุ่มไม่ได้

## อินสแตนซ์และบทบาท {#roles}

หน้า **อินสแตนซ์** (ไทล์การตั้งค่าที่ปักหมุดไว้ในแถบด้านข้างได้) แสดงกลุ่มเป็นตาข่ายของใครทำอะไรให้ใคร การ์ดสำหรับอินสแตนซ์นี้ และการ์ดสำหรับสมาชิกอื่นทุกตัว โทรศัพท์ Android และเซิร์ฟเวอร์ ZFS **การจับคู่** ที่มุมขวาล่างพาไปหน้าการจับคู่ ส่วนไหนเปิดอยู่ตั้งที่ **การตั้งค่า, อินสแตนซ์, หลายเซิร์ฟเวอร์**: **อินสแตนซ์**, **ตัวรับ** และ **ดึง**

![หน้าอินสแตนซ์: กลุ่มเป็นตาข่าย และการ์ดต่ออินสแตนซ์พร้อมไทล์บทบาท หนึ่งในนั้นไม่ได้ใช้งาน](assets/screenshots/offsite/instances-dark.png#only-dark)
![หน้าอินสแตนซ์: กลุ่มเป็นตาข่าย และการ์ดต่ออินสแตนซ์พร้อมไทล์บทบาท หนึ่งในนั้นไม่ได้ใช้งาน](assets/screenshots/offsite/instances-light.png#only-light)

แต่ละการ์ดแสดงสถานะการป้องกันของสมาชิกและบทบาทของมันเป็นไทล์ บทบาทคือสิ่งที่อินสแตนซ์หนึ่งทำให้อีกตัว

- **ตัวรับ** เก็บสำเนานอกสถานที่ของเซิร์ฟเวอร์นี้ใน rest-server ในโหมด append-only เซิร์ฟเวอร์นี้ส่งหลังการสำรองทุกครั้งและลบอะไรที่นั่นไม่ได้ แม้มีคนยึดมัน
- **ตัวดึง** ดึงข้อมูลสำรองของเซิร์ฟเวอร์นี้ตามกำหนดการของตัวเอง เซิร์ฟเวอร์นี้ไม่ต้องตื่นอยู่
- **เซิร์ฟเวอร์ ZFS** รับเรพลิกา ZFS ของเซิร์ฟเวอร์นี้ แต่ละรายการ ZFS เลือกมันใต้ **เรพลิกา** ในการตั้งค่าของมัน
- **ผู้เก็บคีย์** เก็บสำเนาที่ปิดผนึกของชุดกู้คืนของเซิร์ฟเวอร์นี้ ดู [ผู้เก็บคีย์](#key-keeper)

การเปิดบทบาทส่งคำขอ และไม่มีอะไรเริ่มจนกว่าจะมีคนบนอินสแตนซ์อีกฝั่งกด **อนุญาต** คำขอแสดงบนการ์ดของอินสแตนซ์นั้นเป็นป้าย และ **รายละเอียด** ของมันลิสต์พร้อม **อนุญาต** และ **ปฏิเสธ** บทบาทที่อนุญาตแล้วเพิกถอนได้ที่นั่นทุกเมื่อ เส้นประในตาข่ายคือบทบาทที่ยังรออยู่ อินสแตนซ์บน BombVault 9.x ตอบคำขอไม่ได้ บทบาทจึงใช้งานที่นั่นทันทีที่คุณเปิด และคำขอจากอินสแตนซ์ 9.x รอ **อนุญาต** ที่นี่

**รายละเอียด** บนการ์ดเปิดส่วนที่เหลือ: ที่เก็บที่รับและแหล่ง pull ของสมาชิกนั้น ข้อเสนอที่จัดเก็บ การเฝ้าระวัง **ลบ** และ **ลืมคีย์**

สมาชิกเสนอที่จัดเก็บนอกสถานที่ของตัวเองให้สมาชิกอื่นผ่านกลุ่มได้ ผู้ดูแลอีกฝั่งเห็นข้อเสนอใน **รายละเอียด** ของสมาชิกและรับหรือปฏิเสธ การรับสร้างข้อมูลรับรองที่บันทึกไว้และปลายทางที่จัดเก็บธรรมดา หลังการตรวจแบบเดียวกับปลายทางที่คุณพิมพ์เอง มีเฉพาะรายละเอียดการเชื่อมต่อที่เดินทางแบบนี้ ไม่เคยเป็นข้อมูลสำรอง **ตรวจสอบตอนนี้** ขอให้สมาชิกตรวจที่เก็บของหนึ่งส่วน ไม่มีอะไรบนหน้านี้เริ่มการสำรอง กู้คืน หรือลบอะไรบนกล่องอื่น

อินสแตนซ์ที่ปิดอยู่และโทรศัพท์ที่ปิดแอปไว้ยังคงการ์ดของมันเป็น **ไม่ได้ใช้งาน** สีเทา พร้อมเวลาที่เห็นล่าสุด และอยู่ในตาข่ายแบบหรี่จนกว่าคุณจะ **ลบ** พวกมัน ทันทีหลังเซิร์ฟเวอร์นี้เริ่ม การ์ดแบบนั้นบอก **กำลังตรวจสอบ** จนกว่ากลุ่มจะกลับมา **ลบ** ใช้ได้บนการ์ดแบบนั้นไม่ว่าส่วนไหนเปิดอยู่ และมันยังจบคำขอที่เปิดอยู่ของสมาชิก ช่องรับ ZFS ที่ว่างอยู่ และคำขอคีย์ที่รออยู่ การ์ด **อินสแตนซ์** บนหน้าการจับคู่ลิสต์สมาชิกเหล่านี้เป็น **ไม่ได้ใช้งาน** ด้วย

## ตัวรับและตัวดึง {#receiver}

บนกล่องที่ **รับ** สำเนา append-only จาก BombVault ตัวอื่น ที่เก็บที่รับให้การเฝ้าระวังแบบอิสระอ่านอย่างเดียวบนฮาร์ดแวร์ที่รับ ความล้มเหลวเงียบ ๆ ที่ปลายทางจึงไม่ผ่านไปโดยไม่มีใครสังเกต เปิด **ตัวรับ** ใต้ **การตั้งค่า, อินสแตนซ์** แล้วเปิด **รายละเอียด** ของอินสแตนซ์ที่ส่งบนหน้าอินสแตนซ์ และเพิ่มที่เก็บที่รับ (อ่านอย่างเดียว เปิดด้วยรหัสผ่าน restic ของอินสแตนซ์ที่ส่ง ซึ่งได้มาผ่าน [กลุ่มการจับคู่](#pairing)) คุณจะได้

- **รายการแยกตามแหล่ง** คุณจึงเห็นชัดว่าคอนเทนเนอร์ VM และชุดโฟลเดอร์ไหนมาถึงแล้ว
- **รับล่าสุด** ต่อแหล่ง คุณจึงรู้ว่าแต่ละอันใหม่แค่ไหน
- **`restic check` อิสระ** ที่รันบนฮาร์ดแวร์ที่รับ ความสมบูรณ์จึงถูกตรวจที่ที่ข้อมูลอยู่จริง ไม่ใช่แค่ที่ผู้ส่ง
- **สวิตช์คนตาย:** สัญญาณเตือนเมื่อแหล่งหยุดส่งภายในช่วงที่คุณตั้ง
- **สัญญาณเตือนความสมบูรณ์:** สัญญาณเตือนเมื่อการตรวจฝั่งรับล้มเหลว

ตัวรับอ่านอย่างเดียวโดยเด็ดขาด มันไม่เคยเขียนลงที่เก็บที่รับ จึงไม่มีทางทำลายการรับประกัน append-only ที่ผู้ส่งพึ่งพา

ตัวดึงทำงานกลับทาง: เมื่อเปิด **ดึง** อินสแตนซ์อ่านข้อมูลสำรองของสมาชิกอื่นตามกำหนดการของตัวเอง ลงที่เก็บของตัวเองต่อแหล่ง พวกมันจึงไม่เคยนับเป็นข้อมูลสำรองของกล่องนี้ แหล่งของมันอยู่ในรายละเอียดของสมาชิกนั้นด้วย: ตำแหน่งที่เก็บ ชนิดของข้อมูลสำรองที่มัน เก็บ และดึงบ่อยแค่ไหน รหัสผ่าน restic มาผ่านกลุ่ม ไม่เคยเป็น APP_KEY และฝั่งไกลไม่ต้องตั้งอะไรเพิ่มและไม่ต้องรันอยู่ แหล่งถูกอ่านเท่านั้น และแต่ละฝั่งเก็บข้อมูลรับรองของตัวเอง แหล่ง `rclone:` ถูกปฏิเสธ เพราะ rclone จะเข้าถึงมันด้วย remote ของอินสแตนซ์นี้

### เซิร์ฟเวอร์รับ {#receiving-server}

กล่องที่รับยังรัน rest-server ที่คนอื่นคัดลอกมาได้ด้วย มันถูกตั้งขึ้นครั้งแรกที่คุณอนุญาตคำขอ **ตัวรับ** ที่ขอมัน: หน้าต่างบอกว่าเซิร์ฟเวอร์ต้องการเซิร์ฟเวอร์รับ และขอโฟลเดอร์บน share พร้อม **โฟลเดอร์ใหม่** เพื่อสร้างหนึ่งอัน และพอร์ต (8000 เว้นแต่คอนเทนเนอร์อื่นใช้อยู่) จากนั้น BombVault

1. ปฏิเสธถ้ามีคอนเทนเนอร์ชื่อ `rest-server` อยู่แล้ว หรือคอนเทนเนอร์อื่นถือพอร์ต
2. ดึง `restic/rest-server` และเริ่มมันผ่าน Docker socket ในโหมด append-only พร้อมที่เก็บส่วนตัวและไฟล์ล็อกอินในโฟลเดอร์
3. เขียนเทมเพลต Unraid ของมันลงแฟลชไดรฟ์ คอนเทนเนอร์จึงแก้ไขได้ในแท็บ Docker หรือเสนอเทมเพลตให้ดาวน์โหลดเมื่อเข้าถึงแฟลชไดรฟ์ไม่ได้
4. รันการทดสอบการแก้ไขข้อมูลกับมัน และแสดงว่ามันปฏิเสธการลบหรือไม่

อินสแตนซ์ในกลุ่มของคุณจึงพบเซิร์ฟเวอร์ในบรรดาผู้ให้บริการใต้ **จากกลุ่มของคุณ** ตั้งชื่อตามกล่องที่รับ และบทบาท **ตัวรับ** เสนอมันเป็นตัวเลือกที่ปลอดภัย แต่ละอินสแตนซ์ได้ล็อกอินของตัวเองครั้งแรกที่ใช้เซิร์ฟเวอร์ และเขียนเฉพาะในโฟลเดอร์ของตัวเองที่นั่น เมื่อเปิด **ตัวรับ** ใต้ **การตั้งค่า, อินสแตนซ์** **เซิร์ฟเวอร์รับข้อมูล** บนการ์ดของอินสแตนซ์นี้เปิดเซิร์ฟเวอร์อีกครั้ง หน้าต่างของมันลิสต์ล็อกอินใต้ **พาร์ตเนอร์ที่มีการลงชื่อเข้าใช้** และ **เพิกถอนการลงชื่อเข้าใช้** นำอันหนึ่งออก สิ่งที่อินสแตนซ์นั้นคัดลอกไปแล้วอยู่ในโฟลเดอร์ต่อ การตั้งค่ายังสร้าง **การลงชื่อเข้าใช้นอกกลุ่ม** หนึ่งอัน ซึ่งหน้าต่างแสดงรหัสผ่านครั้งเดียว

อินสแตนซ์ที่เข้าถึงกล่องที่รับผ่านรีเลย์เท่านั้นใช้เซิร์ฟเวอร์ไม่ได้ เพราะรีเลย์ไม่แบกข้อมูลสำรอง เพิ่มที่อยู่ของกล่องที่รับบนหน้าการจับคู่ก่อน เมื่อ BombVault รันบนที่อยู่ IP ของตัวเอง (บน br0 เป็นต้น) ให้กรอก **ที่อยู่สำหรับพาร์ตเนอร์** เพราะเซิร์ฟเวอร์ฟังที่ที่อยู่ของโฮสต์

## ตัวอย่าง: จับคู่กล่อง Unraid สองเครื่อง {#worked-example-two-unraid-boxes-end-to-end}

นี่คือการตั้งค่าครบหนึ่งชุดของส่วนต่าง ๆ ข้างบน เพราะประกอบง่ายขึ้นเมื่อเห็นมันประกอบแล้ว

สองกล่อง: **TOWER** รันคอนเทนเนอร์และผลักข้อมูลสำรอง **VAULT** รับและบังคับ append-only แทนที่ด้วยชื่อ ที่อยู่ และพาธ share ของคุณเอง

**1. จับคู่สองกล่อง** บน TOWER เปิด **การตั้งค่า, การจับคู่** กด **สร้างวลี** และกรอกคำสิบสองคำบน VAULT ใต้ **ป้อนวลี** ตั้งรหัสผ่านเข้าสู่ระบบบนทั้งสองก่อน

**2. บน TOWER ขอให้ VAULT เป็นตัวรับ** บนหน้าอินสแตนซ์ เปิด **ตัวรับ** บนการ์ดของ VAULT เลือกส่วนและ **เซิร์ฟเวอร์รับของ VAULT** เป็นที่ แล้วส่งคำขอ

**3. บน VAULT อนุญาต** หน้าอินสแตนซ์ของ VAULT แสดงคำขอบนการ์ดของ TOWER กด **อนุญาต** ครั้งแรก VAULT ขอโฟลเดอร์สำหรับเซิร์ฟเวอร์รับของมัน เช่น `user/appdata/rest-server` เริ่ม rest-server ในโหมด append-only และรันการทดสอบการแก้ไขข้อมูลกับมัน

**4. กลับที่ TOWER** จากนั้น TOWER คัดลอกไป VAULT หลังการสำรองทุกครั้ง และปลายทางที่จัดเก็บใหม่ปรากฏบนหน้าปลายทางที่จัดเก็บของ TOWER พร้อมการป้องกันการลบ

สิ่งที่การทดสอบการแก้ไขข้อมูลตอบ

| ผล | เกิดอะไรขึ้น |
| --- | --- |
| **protected** | VAULT ปฏิเสธการลบ นี่คือสถานะผ่านเพียงอย่างเดียว |
| **not protected** | VAULT ยอมรับการลบ `--append-only` ขาดไปหรือถูกลบ |
| **inconclusive** | ไม่ใช่ทั้งสอง มักเป็นเพราะ URL ไม่ใช่อันที่ restic ใช้เอง หรือข้อมูลรับรองเปลี่ยน ไม่มีอะไรถูกบันทึกและไม่มีการเตือน |

**5. เฝ้าดูสิ่งที่มาถึง ถ้าต้องการ** เปิด **ตัวรับ** ใต้ **การตั้งค่า, อินสแตนซ์** บน VAULT เปิด **รายละเอียด** ของ TOWER และเพิ่มที่เก็บที่รับ VAULT ได้รหัสผ่าน restic ของ TOWER ผ่านกลุ่ม ไม่มีใครพิมพ์คีย์

**6. ทำให้เป็นสองทาง** ทำขั้นตอนซ้ำในทิศทางตรงข้าม: VAULT ขอให้ TOWER เป็นตัวรับของมัน แต่ละกล่องก็บังคับ append-only ให้อีกกล่อง และไม่มีฝ่ายไหนลบข้อมูลสำรองของอีกฝ่ายได้

rest-server ที่คุณรันเองก็ใช้ได้: เพิ่มด้วย **เพิ่มปลายทาง** เป็น rest-server พร้อมผู้ใช้และรหัสผ่านจาก `.htpasswd` และเปิดการป้องกันการลบ คง `--append-only` ไว้ในตัวเลือกของมัน ถ้าไม่มี ฝั่งไกลก็เป็น share ธรรมดาอีกครั้ง

!!! warning "พาธในเครื่องคือพาธภายในคอนเทนเนอร์"
    ที่ที่ BombVault ขอโฟลเดอร์บนเซิร์ฟเวอร์นี้ ให้กรอกแบบสัมพัทธ์กับ mount ของโฮสต์ เช่น `user/appdata/rest-server/bombvault-containers` ไม่ใช่ `/mnt/user/appdata/...` BombVault รันในคอนเทนเนอร์ ซึ่ง `/mnt` ของโฮสต์ถูกเมานต์ที่อื่น พาธโฮสต์แบบเต็มไม่มีอยู่ข้างใน ถ้าคุณวางมัน BombVault บอกพาธสัมพัทธ์ที่ควรใช้แทน

## ตัวช่วยฉุกเฉิน {#emergency}

**ตัวช่วยฉุกเฉิน** นำเซิร์ฟเวอร์ที่หายไปหรือถูกตั้งค่าใหม่กลับมา เริ่มที่หน้า **การกู้คืน** ใต้ **ฉุกเฉิน** และจาก **กู้คืนจากข้อมูลสำรอง** บนหน้าต้อนรับของการติดตั้งใหม่ มันรันในสี่ขั้น: **การเข้าถึง**, **การตั้งค่า**, **การเลือก** และ **การกู้คืน**

1. **การเข้าถึง** แสดงคีย์ของข้อมูลสำรองเก่าให้ BombVault ในสามวิธี
    - **อัปโหลดชุดกู้คืน**: ไฟล์ที่คุณดาวน์โหลดตอนตั้งค่า มีคีย์และทุกปลายทางที่จัดเก็บ และ BombVault กรอกที่เหลือจากมัน ชุดที่ปิดผนึกด้วย age ขอ identity ที่ใช้ปิดผนึก ใช้ครั้งเดียวและไม่เก็บไว้
    - **ผ่านกลุ่ม**: อินสแตนซ์ของกลุ่มคุณเก็บคีย์เป็นสำเนาที่ฝากไว้ คุณต้องมีคำสิบสองคำของกลุ่ม รหัสกู้คืนของคุณ และคนที่อินสแตนซ์นั้น ดู [ผู้เก็บคีย์](#key-keeper)
    - **พิมพ์คีย์**: `APP_KEY` ของเซิร์ฟเวอร์เก่า และที่ที่ข้อมูลสำรองของมันอยู่

    จากนั้น BombVault ลองคีย์กับทุกปลายทางที่จัดเก็บและบอกสำหรับแต่ละอันว่า **อ่านได้**, **ไม่พบ**, ล็อกด้วยคีย์อื่น, เข้าถึงไม่ได้ หรือยัง **ไม่มีข้อมูลรับรอง** ยังไม่มีอะไรถูกบันทึก และคีย์อยู่ในหน่วยความจำเป็นเวลาจำกัด **รับช่วงคีย์** ทำให้เซิร์ฟเวอร์นี้เขียนข้อมูลสำรองด้วยคีย์นั้นตั้งแต่นี้ไป **ยกเลิกการรับช่วง** กลับไปใช้คีย์ของตัวเองจนกว่าการสำรองครั้งแรกจะรัน เซิร์ฟเวอร์ที่มีข้อมูลสำรองของตัวเองอยู่แล้วปฏิเสธการรับช่วงและชี้ไปที่ [จากโฟลเดอร์สำรองข้อมูลเก่า](#restore-from-another-bombvault-repo) แทน **บันทึกข้อมูลรับรอง** เก็บข้อมูลรับรองที่ชุดนำมาสำหรับปลายทางระยะไกล และถามก่อนที่จะแทนที่ข้อมูลรับรองที่เซิร์ฟเวอร์นี้มีอยู่แล้ว
2. **การตั้งค่า** **นำการตั้งค่ากลับมา** กู้คืนการตั้งค่าของ BombVault เองจากการสำรองตัวเองล่าสุด: ปลายทางที่จัดเก็บ ข้อมูลรับรอง ตารางเวลา และกฎ BombVault รีสตาร์ทเพื่อใช้มัน ผ่าน Docker socket ฐานข้อมูลการตั้งค่าที่ใช้งานอยู่จึงไม่ถูกเขียนทับขณะที่ยังเปิดอยู่ และตัวช่วยทำต่อเองหลังจากนั้น การเข้าสู่ระบบของเซิร์ฟเวอร์นี้อยู่ต่อ: คุณลงชื่อเข้าใช้ต่อด้วยรหัสผ่านที่ใช้ตอนนี้ ความลับที่เซิร์ฟเวอร์เก่าเก็บไว้ซึ่งรับช่วงไม่ได้ถูกลิสต์ไว้ คุณจึงกรอกใหม่ได้ การกู้คืนจบทุกเซสชันและลบพาสคีย์ จึงตั้งใหม่ทีหลัง
3. **การเลือก** BombVault ค้นผ่านข้อมูลสำรองของคุณและลิสต์คอนเทนเนอร์ VM ชุดโฟลเดอร์ และชุดข้อมูล ZFS ที่พบ สแนปช็อตใหม่สุดถูกเลือกไว้ล่วงหน้าทุกที่ สิ่งที่เซิร์ฟเวอร์นี้ยังมีอยู่เริ่มด้วยสถานะปิด เพราะการกู้คืนจะแทนที่มัน ชุดโฟลเดอร์ไม่รู้แล้วว่ามาจากไหนหลังการสร้างใหม่ จึงไปอยู่ในโฟลเดอร์ที่คุณเลือก
4. **การกู้คืน** ทุกอย่างที่เลือกกลับมาในครั้งเดียว ปล่อยให้หยุดไว้ถ้าคุณอยากเริ่มแต่ละคอนเทนเนอร์และ VM เอง ซึ่งปลอดภัยที่สุดหลังสูญเสียทั้งหมด หลังจากนั้นดาวน์โหลดชุดกู้คืนใหม่: อันเก่าเป็นของการติดตั้งก่อนหน้า

### ตัวอย่าง: เซิร์ฟเวอร์ใหม่จากชุดกู้คืน {#example-emergency}

เซิร์ฟเวอร์ TOWER ตายไปพร้อมดิสก์ มันเก็บคอนเทนเนอร์ 23 ตัวและ VM 2 ตัว และคัดลอกพวกมันกับการสำรองตัวเองไปยัง Backblaze B2 คุณมี `bombvault-recovery-kit.md` จากตัวจัดการรหัสผ่านและกล่องใหม่ที่ลง Unraid แล้ว `APP_KEY` เก่าของมันหายไป และคุณไม่ต้องใช้มัน

1. **ติดตั้ง BombVault** บนกล่องใหม่และให้ `APP_KEY` ใหม่ เหมือนการติดตั้งใหม่ทั่วไป ตั้งลิงก์ VM ที่ **การตั้งค่า, การเชื่อมต่อ, SSH ของโฮสต์** ถ้าอยากได้ VM กลับมา เพราะการกู้คืน VM ต้องใช้มัน
2. **เริ่มตัวช่วย** บน **ยินดีต้อนรับสู่ BombVault** เลือก **กู้คืนจากข้อมูลสำรอง** บนหน้าการกู้คืน เลือก **เริ่มตัวช่วยฉุกเฉิน** ใต้ **ฉุกเฉิน**
3. **การเข้าถึง** เลือก **อัปโหลดชุดกู้คืน** และวางไฟล์ BombVault ลองคีย์ของมันกับทุกปลายทางที่จัดเก็บและบอก เช่น **Recovery kit read. Its key opens 0 of 2 storage locations.** โฟลเดอร์ในเครื่องบอก **ไม่พบ** เพราะดิสก์ตาย และ Backblaze B2 บอก **ไม่มีข้อมูลรับรอง**
4. **บันทึกข้อมูลรับรอง** ชุดนำข้อมูลรับรองของปลายทางระยะไกลมาด้วย กด **บันทึกข้อมูลรับรอง** แล้วปลายทางจะถูกลองอีกครั้ง Backblaze B2 จึงบอก **อ่านได้**
5. **รับช่วงคีย์** เซิร์ฟเวอร์นี้เขียนข้อมูลสำรองด้วยคีย์เก่าแล้ว ข้อมูลสำรองใหม่จึงเข้ากับอันเก่า มันเก็บ `APP_KEY` ของตัวเองไว้ในเทมเพลต **ยกเลิกการรับช่วง** ใช้ได้จนกว่าการสำรองครั้งแรกจะรัน
6. **การตั้งค่า** เลือก **นำการตั้งค่ากลับมา** ซึ่งอ่านการสำรองตัวเองใหม่สุดจาก B2 BombVault รีสตาร์ทเพื่อใช้มัน และตัวช่วยทำต่อเอง ปลายทางที่จัดเก็บ ตารางเวลา และกฎของคุณกลับมา และคุณลงชื่อเข้าใช้ต่อด้วยรหัสผ่านของเซิร์ฟเวอร์นี้ กรอกความลับที่ตัวช่วยลิสต์ใหม่ เช่นการตั้งค่าการแจ้งเตือน
7. **การเลือก** ตั้ง **ข้อมูลสำรองอยู่ที่ไหน** เป็นสำเนานอกสถานที่ เพราะอันในเครื่องตายไปพร้อมเซิร์ฟเวอร์เก่า BombVault ลิสต์คอนเทนเนอร์ 23 ตัวและ VM 2 ตัวพร้อมสแนปช็อตใหม่สุดที่เลือกไว้ และคุณเลือกอันอื่นสำหรับตัวใดก็ได้
8. **การกู้คืน** เปิด **ให้หยุดไว้หลังจากนั้น** ซึ่งปลอดภัยที่สุดหลังสูญเสียทั้งหมด แล้วเริ่ม **สิ่งที่จะเกิดขึ้น** บอกว่าอะไรจะกลับมา บรรทัดผลอ่านว่า เช่น **25 restored, 0 failed. Start them under Backups when needed.**
9. **เสร็จสิ้น** เริ่มฐานข้อมูลก่อน แล้วค่อยแอปที่ใช้มัน เปิด **การตั้งค่า, การกู้คืน** และดาวน์โหลดชุดกู้คืนใหม่ เพราะอันเก่าเป็นของการติดตั้งก่อนหน้า ตรวจ **ต้องดูแล** บนภาพรวม และรัน **สำรองข้อมูลทั้งหมดเดี๋ยวนี้** หนึ่งครั้งเมื่อทุกอย่างใช้ได้

ถ้าการสำรองตัวเองก็ขาดไปด้วย ให้เลือก **ข้าม ฉันไม่มีข้อมูลสำรองการตั้งค่า** ปลายทางที่จัดเก็บมาจากชุดอย่างเดียว คุณตั้งตารางเวลาและกฎใหม่ และสำเนานอกสถานที่หยุดจนกว่าคุณจะยืนยันค่าเริ่มต้นของส่วน ดู [หลังสร้างใหม่](#after-a-rebuild)

!!! tip "การย้ายที่วางแผนไว้กับภัยพิบัติ"
    ตัวช่วยฉุกเฉินกู้คืนการตั้งค่าของ BombVault เองจากข้อมูลสำรอง สำหรับการย้ายไปกล่องใหม่ที่ *วางแผนไว้* คุณย้ายการกำหนดค่าตรง ๆ ด้วยการ์ด **ส่งออก / นำเข้าการตั้งค่า** (ไฟล์ JSON แบบพกพา) แทนได้ ดู [การกำหนดค่า](configuration.md#portable-settings-export-and-import)

### จากโฟลเดอร์สำรองข้อมูลเก่า {#restore-from-another-bombvault-repo}

**จากโฟลเดอร์สำรองข้อมูลเก่า** ใต้ **แหล่งอื่น** บนหน้าการกู้คืนเปิดที่เก็บของอินสแตนซ์ BombVault *อื่น* (share ที่เมานต์ใต้ `/mnt` หรือที่อยู่ระยะไกล) ด้วยชุดกู้คืนของอินสแตนซ์นั้นหรือ `APP_KEY` ที่พิมพ์ใส่ ในเซสชันแบบอ่านอย่างเดียวที่ใช้ครั้งเดียว เรียกดูคอนเทนเนอร์ VM ชุดโฟลเดอร์ และชุดข้อมูล ZFS ที่เก็บอยู่ที่นั่น เลือกสแนปช็อต แล้วกู้คืน และออบเจกต์ที่กู้คืนกลายเป็นคอนเทนเนอร์ VM หรือชุดโฟลเดอร์ในเครื่องปกติ ไม่มีอะไรถูกเขียนลงที่เก็บอีกฝั่งเลย และการตั้งค่าการสำรองของคุณเองไม่ถูกแตะ (เซสชันอยู่ในหน่วยความจำและหมดอายุเอง) การย้ายคอนเทนเนอร์จากเซิร์ฟเวอร์ A ไป B จึงไม่ต้องชี้การตั้งค่าของคุณใหม่แล้วย้อนกลับทีหลัง หน้าต่างนี้ใช้ครั้งเดียว: เปิดเซสชัน กู้คืนสิ่งที่คุณเลือก และลืมอินสแตนซ์อื่น ถ้าคุณต้องการการจัดการถาวรแทน ที่กล่องนี้ดึงสแนปช็อตของอินสแตนซ์อื่นมาลงที่เก็บของตัวเองตามกำหนดการ นั่นคือบทบาท **ตัวดึง** บนหน้าอินสแตนซ์

คอนเทนเนอร์ที่เครือข่ายของมันไม่มีบนเซิร์ฟเวอร์นี้ เช่นเครือข่าย `br0` ของ Unraid บนโฮสต์ Docker ธรรมดา แสดงตัวเลือกเครือข่ายใต้แถวของมัน BombVault สร้างมันบนเครือข่ายที่คุณเลือก พร้อมเครือข่ายอื่นของมัน IP คงที่และที่อยู่ MAC เป็นของเครือข่ายเก่าและถูกทิ้ง เครือข่ายใหม่จึงกำหนดให้

## ผู้เก็บคีย์ {#key-keeper}

ผู้เก็บคีย์คืออินสแตนซ์ของกลุ่มคุณที่เก็บสำเนาที่ปิดผนึกของชุดกู้คืนของเซิร์ฟเวอร์นี้ มันเปิดสำเนาเองไม่ได้ ถ้าเซิร์ฟเวอร์นี้สูญหายไป การติดตั้งใหม่ที่เข้าร่วมกลุ่มของคุณขอสำเนาจากผู้เก็บและเปิดด้วยรหัสกู้คืนของคุณ

![หน้าต่างรหัสกู้คืน: อักขระยี่สิบตัวในสี่กลุ่ม แสดงครั้งเดียว](assets/screenshots/offsite/recovery-code-dark.png#only-dark)
![หน้าต่างรหัสกู้คืน: อักขระยี่สิบตัวในสี่กลุ่ม แสดงครั้งเดียว](assets/screenshots/offsite/recovery-code-light.png#only-light)

1. บนหน้าอินสแตนซ์ เปิด **ผู้เก็บคีย์** บนการ์ดของอินสแตนซ์ที่ควรเก็บ และเลือก **ฝากสำเนา** การฝากต้องมีรหัสผ่านเข้าสู่ระบบ
2. เซิร์ฟเวอร์นี้แสดง **รหัสปลดล็อก** ครั้งเดียว: ตัวอักษรและตัวเลขยี่สิบตัวในสี่กลุ่มกลุ่มละห้า จดไว้และยืนยันด้วย **จดรหัสไว้แล้ว** เซิร์ฟเวอร์นี้ไม่เก็บรหัส มีแค่สิ่งที่ต้องใช้ปิดผนึกการฝากสำหรับมัน
3. ผู้เก็บถือสำเนาที่ฝากไว้แล้ว และเซิร์ฟเวอร์นี้ต่ออายุเมื่อชุดเปลี่ยน **สำเนาที่ฝากไว้** บนการ์ดของอินสแตนซ์นี้ลิสต์ **สำเนาที่ฝากไว้ของเซิร์ฟเวอร์นี้** พร้อมผู้เก็บแต่ละตัวและสถานะ และ **สำเนาที่ฝากไว้ซึ่งเซิร์ฟเวอร์นี้เก็บ** สำหรับตัวอื่น **สร้างรหัสใหม่** แทนที่รหัส ผู้เก็บแต่ละตัวเปลี่ยนไปใช้รหัสใหม่เมื่อได้สำเนาที่ฝากไว้ใหม่

ในวันนั้นคุณต้องมีสามอย่าง: คำสิบสองคำของกลุ่มคุณ รหัสกู้คืน และการเข้าถึงหน้าตาของผู้เก็บ ซึ่งมีคนต้องกด **อนุญาต** ในตัวช่วยฉุกเฉิน เลือก **ผ่านกลุ่ม** เลือกสำเนาที่ฝากไว้ ขอมัน และพิมพ์รหัสกู้คืน รหัสถูกใช้บนเซิร์ฟเวอร์ใหม่และไม่ถูกส่งไปผู้เก็บ บนผู้เก็บ คำขอแสดงใต้ **สำเนาที่ฝากไว้** พร้อมว่าใครขอ อินสแตนซ์นั้นเคยถูกเห็นที่นั่นมาก่อนหรือไม่ และขอบ่อยแค่ไหน **อนุญาต** ส่งมอบสำเนาที่ปิดผนึก และการอนุญาตต้องมีรหัสผ่านเข้าสู่ระบบ การติดตั้งใหม่มี 30 นาทีหลังอนุญาตเพื่อมารับ คำขอที่ไม่มีใครตอบหมดอายุหลังหนึ่งวัน และอินสแตนซ์ที่ขอบ่อยเกินไปต้องรอหนึ่งชั่วโมง

ถ้าไม่มีรหัส ไม่มีใครเปิดสำเนาได้ รวมถึงผู้เก็บ ถ้ารหัสหาย ให้สร้างอันใหม่ขณะที่เซิร์ฟเวอร์นี้ยังรันอยู่ ถ้าเซิร์ฟเวอร์หายไปแล้ว ชุดกู้คืนและ APP_KEY ที่พิมพ์ใส่ยังใช้ได้ ผู้เก็บลบสำเนาที่ฝากไว้ได้ทุกเมื่อ และเจ้าของต้องขออีกครั้ง

## ชุดกู้คืน {#recovery-kit}

นี่คือชิ้นที่ทำให้การกู้คืนจากภัยพิบัติเป็นไปได้แม้ไม่มี BombVault ที่รันอยู่

**ดาวน์โหลดชุดกู้คืน** ในการ์ด **สำหรับกรณีฉุกเฉิน** ใต้ **การตั้งค่า, การกู้คืน** ให้ **คีย์** **รหัสผ่าน restic ที่สร้างมา** ทุก **ปลายทางที่จัดเก็บ** พร้อมที่เก็บของแต่ละส่วน ข้อมูลรับรองที่การติดตั้งใหม่ต้องใช้เข้าถึงพวกมัน และ **คำสั่ง restic ที่แน่นอน** คุณจึงกู้คืนตรงด้วย restic CLI บนเครื่องใดก็ได้ ต้องมีรหัสผ่านเข้าสู่ระบบ ชุดพิมพ์คีย์แม้ปิดการเข้ารหัส เพราะคำจำกัดความของคอนเทนเนอร์และ VM ถูกปิดผนึกด้วยมันเสมอ หลังการรับช่วง มันพิมพ์คีย์ข้อมูลสำรองที่รับมาและ APP_KEY ของเซิร์ฟเวอร์นี้ ซึ่งการติดตั้งใหม่ต้องใช้เฉพาะเพื่อนำการตั้งค่ากลับมา การ์ด **บันทึกชุดกู้คืนของคุณ** บนภาพรวมเตือนจนกว่าคุณจะเก็บมัน

!!! danger "เก็บชุดกู้คืนนอกเซิร์ฟเวอร์"
    ชุดมีความลับที่ถอดรหัสข้อมูลสำรองของคุณ เก็บไว้ในที่ปลอดภัยและแยกจากเซิร์ฟเวอร์ (ตัวจัดการรหัสผ่าน สำเนาที่พิมพ์ไว้ในตู้เซฟ) ถ้าคุณเสียทั้ง BombVault และ `APP_KEY` โดยไม่มีชุดกู้คืนและไม่มีสำเนาคีย์ที่ฝากไว้ ข้อมูลสำรองที่เข้ารหัสของคุณจะกู้คืนไม่ได้

!!! warning "สแนปช็อตใหม่สุดไม่ใช่อันที่ควรกู้คืนเสมอไป"
    ตั้งแต่ restic 0.17 `restic snapshots` แสดงขนาดของแต่ละสแนปช็อต หลังข้อมูลหาย สแนปช็อตใหม่สุดอาจเป็นอันที่ถูกทำให้ว่าง จึงอย่ากู้คืนสแนปช็อตที่เล็กกว่าอันก่อนหน้ามาก หลังแรนซัมแวร์ มันอาจเป็นอันที่ถูกเข้ารหัสที่ขนาดปกติ ถ้า BombVault ยังรันอยู่ ให้ตรวจหน้า **ความผิดปกติ** ก่อน: มันระบุการสำรองล่าสุดที่ยังดี และหน้าต่างกู้คืนเลือกอันนั้นไว้ให้ การกู้คืนไม่ต้องใช้ข้อมูลความผิดปกติของ BombVault และการหยุดการเก็บรักษาแค่เก็บสแนปช็อตเพิ่ม

### ปิดผนึกชุด {#sealing-the-kit}

ถ้าคุณเปิด **เข้ารหัสการส่งออกด้วย age** ใต้ **การตั้งค่า, ระบบ** ชุดจะถูกปิดผนึกด้วยด้วย และดาวน์โหลดเป็น `bombvault-recovery-kit.md.age` มันเป็น ASCII-armored ไม่ใช่ไบนารี จึงยังเป็นข้อความธรรมดา: การวางลงตัวจัดการรหัสผ่านหรือพิมพ์ใช้ได้เหมือนเดิม เนื้อหาอ่านไม่ได้ถ้าไม่มีคีย์ของคุณ

!!! warning "อย่าเก็บคีย์ age ไว้ในชุด"
    คุณต้องใช้คีย์ **ส่วนตัว** age เพื่อเปิดชุดที่ปิดผนึก เก็บไว้ในที่ที่ไม่ขึ้นกับชุดเอง ไม่เช่นนั้นคุณจะมีสองสิ่งให้กู้คืนแทนที่จะเป็นหนึ่ง การปิดผนึกคุ้มเมื่อชุดถูกเก็บไว้ในที่ที่คุณควบคุมไม่เต็มที่ (ตัวจัดการรหัสผ่านที่ใช้ร่วมกัน โน้ตบนคลาวด์ สำเนาพิมพ์ในออฟฟิศ) ชุดในตู้เซฟของคุณเองได้รับการปกป้องด้วยตู้เซฟอยู่แล้ว

    เมื่อเปิดการเข้ารหัสแต่ไม่มีผู้รับที่ใช้ได้ การดาวน์โหลดจะถูกปฏิเสธเลย BombVault ไม่เคยถอยไปส่งมอบคีย์หลักแบบไม่เข้ารหัส

### ถ้าไม่มีชุดอยู่ใกล้มือ {#if-you-do-not-have-the-kit-to-hand}

รหัสผ่านไม่ได้ถูกเก็บไว้ที่ไหน มัน **ถูกคำนวณ** จากคีย์ของข้อมูลสำรอง คุณจึงสร้างซ้ำเองได้ด้วยแค่คีย์และเชลล์

```sh
printf 'bombvault:restic-repo'   | openssl dgst -sha256 -mac HMAC -macopt hexkey:$APP_KEY -r   | cut -d' ' -f1
```

นั่นคือ HMAC-SHA256 บนสตริงคงที่ `bombvault:restic-repo` โดยใช้ไบต์ดิบของ `APP_KEY` ฐานสิบหกเป็นกุญแจ พิมพ์เป็นอักขระฐานสิบหกตัวพิมพ์เล็ก 64 ตัว ค่าเดียวกันอยู่ในชุด ลิสต์เป็นรหัสผ่าน restic ที่สร้างมา นี่สำหรับวันที่ชุดอยู่ที่ที่คุณไม่ได้อยู่ บนเซิร์ฟเวอร์ที่รับช่วงข้อมูลสำรองของเครื่องอื่น ให้ใช้คีย์ข้อมูลสำรองที่รับมา ซึ่งคือ APP_KEY เก่าของเซิร์ฟเวอร์นั้น

!!! warning "สำหรับที่เก็บที่รับ ให้ใช้คีย์ของอินสแตนซ์ที่ส่ง"
    ที่เก็บที่มาถึงที่นี่ผ่านสำเนานอกสถานที่ถูกสร้างโดยเครื่องที่ส่ง ด้วยคีย์ **ของมัน** การสร้างจากคีย์ของกล่องที่รับให้รหัสผ่านที่ restic จะปฏิเสธ ซึ่งดูเหมือนที่เก็บเสียพอดีและไม่ใช่ นี่คือเหตุปกติที่ `restic check` บนที่เก็บที่รับขอรหัสผ่านซ้ำแล้วซ้ำอีก

เพราะคำจำกัดความสำหรับกู้คืนอยู่ **ข้างใน** แต่ละที่เก็บ (`<repo>/def`, `<repo>/vm-def`) โฟลเดอร์ที่เก็บที่คัดลอกจึงสมบูรณ์ในตัวเอง ชุดบวกที่เก็บคือทุกอย่างที่การกู้คืนแบบ bare-metal ต้องการ

## นำไฟล์ดัมป์ฐานข้อมูลกลับมา {#database-dumps}

ไฟล์ดัมป์ฐานข้อมูลเป็นจุดกู้คืนของตัวเองในที่เก็บคอนเทนเนอร์ ติดแท็ก `dbdump:<container>` เก็บไฟล์เดียว `/dbdump/<container>.sql` BombVault ลิสต์ ดาวน์โหลด และนำเข้าบนแท็บ **การสำรองข้อมูล** ของคอนเทนเนอร์ ด้านล่างคือขั้นตอนเดียวกันด้วย restic อย่างเดียว สำหรับวันที่ไม่มี BombVault

```sh
restic -r <repo> snapshots --tag dbdump:<container>
restic -r <repo> dump --tag dbdump:<container> latest /dbdump/<container>.sql > <container>.sql
```

แท็ก `dbversion:` และ `dbname:` บนแต่ละดัมป์บอกว่ามาจากเซิร์ฟเวอร์เวอร์ชันไหนและเก็บฐานข้อมูลอะไร ไฟล์ที่สมบูรณ์ลงท้ายด้วย `-- PostgreSQL database cluster dump complete` หรือ `-- Dump completed`

นำเข้าไปยังคอนเทนเนอร์เวอร์ชันเดียวกันหรือใหม่กว่า (PostgreSQL) หรือเมเจอร์เวอร์ชันเดียวกัน (MySQL และ MariaDB) ที่เริ่มหนึ่งครั้งด้วยโฟลเดอร์ข้อมูลว่างเพื่อให้มันเตรียมตัวเอง โฮสต์ไม่ต้องมีไคลเอนต์ฐานข้อมูล คอนเทนเนอร์มีอยู่แล้ว

```sh
docker exec -i <container> sh -c 'exec psql -X -U "${POSTGRES_USER:-postgres}" -d postgres' < <container>.sql
docker exec -i <container> sh -c 'exec mariadb -uroot -p"$MARIADB_ROOT_PASSWORD"' < <container>.sql
docker exec -i <container> sh -c 'exec mysql -uroot -p"$MYSQL_ROOT_PASSWORD"' < <container>.sql
```

สำหรับฐานข้อมูลเดียวจากดัมป์เต็ม MySQL และ MariaDB รับ `--one-database <name>` ในคำสั่งไคลเอนต์ ดัมป์ PostgreSQL มีหนึ่งส่วนต่อฐานข้อมูล แต่ละส่วนขึ้นต้นด้วยบรรทัด `\connect <name>`: คัดลอกส่วนนั้นลงไฟล์ของมันเองและนำเข้าด้วย `-d <name>` หลังสร้างฐานข้อมูล

!!! warning "ดัมป์ root มีผู้ใช้ของเซิร์ฟเวอร์ด้วย"
    ดัมป์ MySQL หรือ MariaDB เต็มที่ทำในฐานะ root มีฐานข้อมูลระบบ `mysql` การนำเข้าจึงแทนที่บัญชีของเซิร์ฟเวอร์ใหม่ รวมถึงรหัสผ่านของ root ด้วยบัญชีจากดัมป์ บน PostgreSQL `role ... already exists` สำหรับผู้ใช้ที่คอนเทนเนอร์สร้างเป็นเรื่องที่คาดไว้และไม่เป็นอันตราย
