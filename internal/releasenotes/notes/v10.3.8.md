BombVault 10.3.8 lets you rename every storage location, lets the trial restore pass on backups that contain hardlinks and links the app's new F-Droid listing.

## ✨ Added

- **BombVault is on F-Droid.** The Android app has its [F-Droid listing](https://f-droid.org/packages/bombvault.halleluja.design/) now, and **Settings, Apps** links it where the button said "Soon". The README and the documentation's [Android page](https://junkerderprovinz.github.io/bombvault/android/#install) link it too. F-Droid builds and signs the app itself, so a new release reaches it a few days later, and switching between the F-Droid app and the APK means uninstalling the other one first.
- **Every storage location can be renamed.** A folder that several sections share, such as one S3 bucket folder the backup paths point into, took its name from the folder's last part and offered no way to change it. The off-site copy a section's settings describe offered only its keep rules. Both now have a **Name** field on their page under **Storage locations**, like every other location. Thanks to @manilx for asking for it. ([#384](https://github.com/junkerderprovinz/bombvault/issues/384))

## 🐛 Fixed

- **A trial restore no longer fails on hardlinked files.** restic's restore size counts a file with several hardlinks only once, but the restore writes it under every name. So a backup with hardlinks came back with more bytes than restic reported, and the trial restore stopped with "verification mismatch" although every file was there. It now compares the restored files and bytes with the snapshot's file list, which counts every name too. Running containers never played a part, since the trial restore only compares the backup with itself. Thanks to @one4spl for testing 10.3.5 and reporting it. ([#379](https://github.com/junkerderprovinz/bombvault/issues/379))
