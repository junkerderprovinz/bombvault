BombVault 7.5.0 improves restoring from another BombVault and tidies the backup order card.

## Added

- **Restore a single subfolder or file from another BombVault's backup.** When you connect to another BombVault instance and restore one of its file sets, you can now choose "Pick a subfolder" and tick only the folders or files you want, instead of pulling back the whole set. This helps when a large set (for example your entire appdata) holds many stacks and you only need one of them back. Browse the backup's contents, tick what you want, pick a target folder, and BombVault restores just that selection into it. The restore stays read-only on the other repository, exactly like the whole-set restore, and leaving the default "Whole set" selected restores everything as before.

- **The backup order card collapses, and rows reorder by drag and drop.** On the Containers page the Backup order card can now be collapsed to get it out of the way when you have many containers (it remembers the state in your browser and shows a count while collapsed). You can also drag a row to move it, instead of clicking the up and down arrows repeatedly. The arrows stay for keyboard use.

## Fixed

- **A container restored from another BombVault no longer writes its appdata to a pool this server does not have.** When you recreate a container from another BombVault instance, its appdata was restored to the exact path the source server used. If the source kept appdata on a pool this server does not have (for example /mnt/zfs while this box only has the array), the restore wrote to a folder that did not belong there. BombVault now checks that each appdata location is on a real mounted pool or share on this server before the restore starts, and stops with a clear message if it is not, instead of writing to the wrong place. A normal /mnt/user/appdata restore is unaffected. Restoring appdata that lived on a differently named pool will be supported directly in a later update; for now BombVault refuses rather than restoring to the wrong location.

## Upgrading

Just pull the new image.
