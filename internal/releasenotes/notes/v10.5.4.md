BombVault 10.5.4 takes over your backup jobs from Duplicati and Duplicacy, finds a file by name in every backup, and gives each server a restic host of its own as the first step towards several servers sharing one repository.

## ✨ Added

- **Jobs from Duplicati or Duplicacy.** Under **Other sources** on the Restore page, **Jobs from Duplicati or Duplicacy** reads jobs exported from Duplicati, a Duplicacy CLI folder or the settings of Duplicacy Web, and turns each job into folder sets with its folders, exclusions, schedule and storage place. A preview shows what each job becomes before anything is created and notes what could not be taken over. New storage locations go into a `bombvault` subfolder of the old destination, so they never mix with the old backups. Thanks to @Revan335 for asking. ([#418](https://github.com/junkerderprovinz/bombvault/issues/418))
- **Find a file.** The Restore page has a **Find a file** card. It searches every backup of your containers, folder sets, ZFS datasets and the flash drive for a file name, lists each backup that holds the file with its date, size and place, and opens the restore window with just that file ticked. Each backup is read once, at the first place that has it. Off-site places are searched only when you switch them on, and then only for the backups no other place holds. The MCP server has a `search_files` tool for the same search.
- **System junk excludes.** A new folder set suggests leaving out `.DS_Store`, `Thumbs.db`, `desktop.ini`, `@eaDir`, `.Recycle.Bin`, `.Trash-*` and `*.tmp`, each with its own switch. An existing set stays as it is until you add them in its editor.
- **Connections per storage location.** A storage location on S3, B2, REST, SFTP, rclone or another network backend can set how many connections restic opens, from 1 to 32. Left empty, restic keeps its default of 5.

## ⚡ Improved

- **A host of its own for each server.** Backups carry a restic host made from the key of the backups, such as `bv-3f9a0c41d2e7`, instead of `bombvault` on every server. The first backup after the update builds on the last one, so nothing is read again, and the keep rules treat the old and new backups of an entry as one. The recovery kit names the host in its restic commands. Thanks to @Revan335 for the idea. ([#419](https://github.com/junkerderprovinz/bombvault/issues/419))

## 🐛 Fixed

- **Locks of a second server stay.** When two servers wrote to the same repository, clearing stale locks on one of them could remove the lock of a backup or prune still running on the other, because every container is named `bombvault`. BombVault now decides itself which lock is stale: one that has not been refreshed for 30 minutes, or one its own earlier run left behind. **Unlock** leaves a lock that is still being refreshed and says when it was last refreshed.
