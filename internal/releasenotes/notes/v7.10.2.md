BombVault 7.10.2 fixes the off-site "Test connection" check failing on a share whose SMB/CIFS mount enforces its own restrictive permission model, even when the actual repository is perfectly readable.

## 🐛 Fixed

- **Testing an off-site repository could fail with a raw "unable to create lock in backend: ... permission denied", even though the repository itself was fine.** The check restic runs to verify a repository opens (`restic cat config`) only skips taking a lock for the one-time cross-instance "restore from another BombVault" case — every other use, including the everyday Settings "Test connection" button, still tried to write a lock file for what is a strictly read-only read of a single object that is written once at repository creation and never changes again. On an off-site mount whose SMB/CIFS client enforces its own permission model independent of the real filesystem permissions on the far side, that unnecessary lock-file write could fail even when reading the repository itself would have succeeded. The probe is now unconditionally lock-free, the same way listing snapshots, stats, and diffs already are, removing the failure mode entirely rather than just explaining it better after the fact.
