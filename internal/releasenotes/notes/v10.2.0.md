BombVault 10.2.0 makes the cloud credentials one list of saved sign-ins with a default, lets a section's own folder move into a storage location you already have, and lets you remove any storage location. The storage settings are tidier too, every list shows its entries as rows, and card buttons sit at the bottom right.

## ✨ Added

- **Sign-ins are one list.** The shared cloud credentials and the extra credential sets are now saved sign-ins, shown under the storage locations with the locations that use each one. A star marks the default, which is used wherever no sign-in is picked, such as an address typed in by hand or a recovery on a fresh install, and **Make default** gives the star to another one. A sign-in is saved when you add a storage location, and Add storage location can also use a saved one instead of new keys. ([#358](https://github.com/junkerderprovinz/bombvault/issues/358))
- **Edit and test a sign-in in one window.** Edit opens a sign-in in the same window from the settings page and from a storage location's page. **Test** signs in to every storage location that uses it with what you typed, before anything is saved. A sign-in can be removed only when no storage location uses it, and the default goes only as the last one. ([#358](https://github.com/junkerderprovinz/bombvault/issues/358))
- **Move a section's own folder into a storage location.** One window moves the own folder of one or several sections into a storage location you already have, and the folder then follows that location's sign-in, protection and limits. Before you switch, it says for each section what happens: where new backups go, whether a copy that is already there becomes the own folder, and which backups are copied over first. A remote storage location lists the sections that keep their own backups there. ([#358](https://github.com/junkerderprovinz/bombvault/issues/358))
- **Remove any storage location.** Every storage location page has **Remove storage location**: keep the backups there, or delete them first once the window has listed what goes and which entries would lose their only backup. Entries that back up to a removed repository follow their section again. A section's folder can't just go, because every section needs one, so the window asks for the folder the sections move to and checks it like a folder typed into the settings. ([#353](https://github.com/junkerderprovinz/bombvault/issues/353))
- **Paste an rclone configuration in Add storage location.** The **Rclone** tile takes remotes from an rclone.conf. The rclone card on the storage settings page is gone, since SMB and WebDAV were already tiles of their own. ([#358](https://github.com/junkerderprovinz/bombvault/issues/358))
- **Replica only, no backup.** The replica card of a ZFS entry has a switch that turns off the own folder and the off-site storage locations of the ZFS section, so a run sends only the replica. Switching it off brings the own folder back. ([#356](https://github.com/junkerderprovinz/bombvault/issues/356))
- **One card per release in What's new.** After an update the window lists every release since the one you had, newest first, each with its notes and its changes and **Go there** where a page shows one. ([#354](https://github.com/junkerderprovinz/bombvault/issues/354))

## 🎨 Design

- **Settings, Storage locations lists your storage locations** and shows which section goes to which, as the Storage locations page does. ([#358](https://github.com/junkerderprovinz/bombvault/issues/358))
- **One card for the off-site copies.** Each section's off-site copy is a row with test, replicate and setup, instead of a card per section. The rest opens in the section's window, and the row's buttons follow the button labels setting. ([#358](https://github.com/junkerderprovinz/bombvault/issues/358))
- **Lists are rows.** Every list shows its entries as rows parted by a thin line, without a grey box behind them.
- **Card buttons sit at the bottom right.** Buttons that act on a whole card, such as Add storage location, are in the card's foot, as they are in a window.
- **A menu with one action is a button.** Where More would hold only one action, that action stands on its own.
- **Provider logos.** In Add storage location, Amazon S3, QingStor, Sia, RustFS, FileLu, Drime, Synology C2, Shade, 1Fichier and Rclone show their marks, and each tile lights up in its brand's colour under the pointer. A kind of storage without a brand lights up in black or white. premiumize.me is gone from the list, since it is a download service; a location set up with it keeps working.
- **The encryption picture follows its switch**, with sealed packs when backups are encrypted and readable ones when they are not, and it is wide and low, so the Encryption card is no longer the tallest on the page.
- **The compression selector** sits beside its label at the size of its three options.
- **Every Got it button has a check mark.**

## ⚡ Improved

- **One place for how long backups are kept.** The copy from a section's Off-site field follows the How long to keep card of its storage location like every other copy, and a section can have its own values there under Rules per section. The Off-site retention card is gone; the Retention tab points to the storage locations and keeps the preview. The update changes no copy's rules. ([#351](https://github.com/junkerderprovinz/bombvault/issues/351))
- **A local folder shows the delete protection card only when it has a protection** you can switch off.
- **The replica hint says how to get a replica without a backup.** ([#356](https://github.com/junkerderprovinz/bombvault/issues/356))
- **"This location lies inside another repository or target" says which one**, so you can find it and remove it. ([#358](https://github.com/junkerderprovinz/bombvault/issues/358))

## 🐛 Fixed

- **An off-site copy from S3 to S3 failed with "The Access Key Id you provided does not exist".** When a section's own folder was on one S3 server and its off-site copy went to another, the copy opened the own folder with the off-site server's key. Both ends sign in with their own keys now. ([#358](https://github.com/junkerderprovinz/bombvault/issues/358))
- **A removed storage location could block adding it again.** Clearing a section's Off-site field left a hidden row behind that removing the location missed, and it went on blocking the same place. Removing a location takes such rows along, rows the storage page does not list no longer block a location, and the update cleans up the leftovers. ([#358](https://github.com/junkerderprovinz/bombvault/issues/358))
- **A sign-in still in use could be lost when the list was saved.** A storage location that named it then signed in with the default keys without saying so. Such a save is refused now. ([#358](https://github.com/junkerderprovinz/bombvault/issues/358))
- **Saved sign-ins showed their secret as missing**, every one of them. ([#358](https://github.com/junkerderprovinz/bombvault/issues/358))
- **A location typed into an off-site window was lost** when the window was closed right after typing it. ([#358](https://github.com/junkerderprovinz/bombvault/issues/358))
- **The preview in Add storage location showed `s3:s3:http://...`** when the endpoint was typed with `s3:` in front. The saved location was always right. ([#358](https://github.com/junkerderprovinz/bombvault/issues/358))
- **The switches in the section graph were hard to tap on a narrow phone.** On a 320px screen their tap area was smaller than 24px.
- **Reset to the storage location asks before it keeps less.** On the How long to keep card it removed backups without the question that Ask before keeping less promises.
- **Container data under /DATA/AppData was not found.** ZimaOS keeps app data in AppData, and BombVault only matched appdata in lower case, so a backup there held the configuration and none of the folders. The name matches in any case now, still only as a whole name, and a restore writes the data back under the folder's own spelling.
- **A running ZFS replica had no line in the activity log** until it was done. It shows its progress now, as a backup does. ([#356](https://github.com/junkerderprovinz/bombvault/issues/356))
- **The widget showed a ZFS replica as a backup.** Every line names its section and reads the way the activity log puts it. ([#355](https://github.com/junkerderprovinz/bombvault/issues/355))
- **The new features of 10.1 had no green dots**, so every dot stayed grey after the update. They have them now, and every new feature of a release gets one. ([#354](https://github.com/junkerderprovinz/bombvault/issues/354))

## 🌐 Translations

## Upgrading

- **Nothing has to be changed.** At the first start the shared cloud credentials become a saved sign-in marked as the default, or the saved sign-in with the same keys takes the mark. Saved sign-ins with the same keys become one, and an own folder typed in under a storage location's folder, with the same keys, follows that location. Nothing signs in differently, and a note on the Sign-ins card says what the start did.
