BombVault 10.3.7 restores the files you pick into a folder without the folders above them.

## 🐛 Fixed

- **Picked files land directly in the target folder.** A file ticked in a container's restore window came back below its whole backup path, such as `host/user/user/appdata/dockhand/stacks/DXP6800/immich/compose.yaml`, and folder sets and ZFS datasets let two picks with the same name overwrite each other. Now a file comes back as just the file, a folder as the folder with its contents, and picks from different folders keep only their path below the folder they share, while **Replace original** is unchanged. Thanks to @manilx for reporting it. ([#383](https://github.com/junkerderprovinz/bombvault/issues/383))
