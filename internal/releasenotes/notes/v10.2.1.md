Backup processes can now be given a memory limit.

## ✨ Added

- **Memory limit per backup.** Settings, System, Performance has a new field, **Memory limit per backup (MiB)**. It sets a soft limit for each backup process, so a large backup slows down instead of being killed for running out of memory. 0 sets none, which is how backups ran before.

## 🐛 Fixed

- **A prune failed on an own folder in a bucket that holds no backups yet.** When a section's own folder moved to an S3 or REST storage location before anything was written there, for example ZFS that only replicates, the prune after every round failed with "repository does not exist". Prune, verify, unlock and the restore check now leave such a folder out, as they already did with an empty folder on this host. A bucket that held backups before and is empty now is still reported. ([#359](https://github.com/junkerderprovinz/bombvault/discussions/359))
