BombVault 10.3.4 lets a container's backup wait while somebody uses the app and try again on its own, instead of failing and waiting for you to press Try again.

## ✨ Added

- **A backup waits while the app is busy and tries again on its own.** A Pre-backup command that exits with code 75 defers the backup instead of failing it. The new **When the app is busy** card on a container's Settings tab sets how often it is tried again, an optional time window that may run past midnight, and how long it waits at most, then either gives up under Needs you or backs up anyway. The rest of the run goes on, the wait survives a restart, and you get one notice when it is deferred and one when it ends. ([#378](https://github.com/junkerderprovinz/bombvault/issues/378))
- **Ask Plex, Jellyfin or Emby before the backup.** The **Activity check** asks the media server whether anybody is watching, with Plex's own token from its Preferences.xml or an encrypted API key for Jellyfin and Emby. Paused sessions can stop counting after some minutes, and you choose whether a server that does not answer lets the backup run. BombVault asks the server directly and otherwise through curl or wget inside the container, which also reaches containers on br0 or macvlan. ([#378](https://github.com/junkerderprovinz/bombvault/issues/378))
- **Wait while the container sends data.** For apps without such a check, such as game servers or downloaders, a backup can wait while the container sent more than a rate you set within the last few minutes, read from Docker's own counters. ([#378](https://github.com/junkerderprovinz/bombvault/issues/378))
