Saving settings no longer deletes an additional off-site target.

## 🐛 Fixed

- **An additional off-site target survives a settings save.** If a domain's off-site field in Settings was empty while the domain still had an additional target, the next save of any setting deleted that target and wrote nothing to the log. Targets added from a mesh offer were lost the same way. Only the target with sort order 0 counts as a domain's primary now, and saving settings leaves the other targets alone.
- **Mesh targets move out of the primary's slot.** A target accepted from a mesh offer used to get sort order 0. The first start of this version moves such targets behind the domain's other targets, unless one points at the repository the off-site field names.
- **No second row for the same repository.** When you set a domain's off-site field to a repository that an additional target already uses, that target becomes the primary instead of getting a copy next to it.
- **A new target without a sort order goes last.** `POST /api/offsite/targets` places it after the domain's existing targets and refuses sort order 0, which belongs to the off-site field.

## Upgrading

A target that disappeared before this update does not come back on its own. Add it again under Settings, Off-site, Additional off-site targets.
