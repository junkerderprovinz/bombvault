## 🐛 Fixed

- **A folder mounted after BombVault started is no longer backed up empty.** Without mount propagation on Host Data, as in the TrueNAS app, a disk the host mounts later looks like an empty folder to BombVault, and the first backup of an app on it recorded success with no files. BombVault now checks such a folder through Docker and refuses the backup with a failed run that says to restart BombVault.

## ⚡ Improved

- **A note when Host Data has no mount propagation.** The startup log says so once, together with what it means for disks mounted later.
- **TrueNAS setup.** The custom app in the getting started guide uses port 30624 and explains why it keeps `rslave` on Host Data: ZFS dataset backups need it, and the catalog app can't offer them.
