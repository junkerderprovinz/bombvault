BombVault 7.9.0 rolls up the 7.8.1 and 7.8.2 fixes plus three off-site UX issues: a scary fatal error for a perfectly normal state, REST-only controls shown for rclone/s3, and unexplained retention values.

## 🐛 Fixed

- **A fresh remote off-site destination no longer shows a fatal error.** A reachable destination that simply hasn't been replicated to yet showed restic's raw "repository does not exist" as a red fatal error in the setup wizard and Settings. It now reports the same "reachable, not initialised" warning state the UI already had translated in all 26 languages, but never triggered. ([#130](https://github.com/junkerderprovinz/bombvault/issues/130))
- **The off-site setup wizard no longer shows REST-only controls for rclone or s3 destinations.** REST username/password fields, the append-only tamper-test button, the "maintenance window" retention option, and the far-side prune cron example were all shown regardless of the selected backend. All four are now gated on the actual configured backend, and the cron example uses your real repo URL for non-REST backends instead of a fabricated local path. ([#131](https://github.com/junkerderprovinz/bombvault/issues/131))
- **Retention values (Keep last/daily/weekly/monthly) are explained in place.** Neither the local nor the off-site retention card said what each field does, that the four rules combine with OR rather than adding up, that they apply per backed-up item, or that an immutable off-site destination is never pruned from here. Both cards now carry inline (i) info bubbles explaining all of it. ([#132](https://github.com/junkerderprovinz/bombvault/issues/132))
- **"Select files" no longer fails with a generic "Failed to load files".** A stale exclusive lock left behind by an earlier interrupted operation blocked the file-listing call the same way it could block a backup, but the file-listing path never got the self-heal the backups list already had. It now self-heals the same way, and clears the stale lock automatically instead of failing. ([#129](https://github.com/junkerderprovinz/bombvault/issues/129))
- **File-listing errors now show the real reason**, matching how the rest of the app already handles errors, instead of a generic message even when the server already sent back the specific cause.
- **Off-site rclone and cloud credentials are visible again in Simple mode.** The credential cards on Settings' Off-site tab were wrongly hidden behind Advanced mode, while the repo-path field right next to them has always been visible by default.
- **Off-site "Test connection" now shows the real reason it failed** instead of a generic "not reachable" no matter the actual cause (a bad rclone remote type, wrong credentials, an unreachable host).
- **The documentation button on the README now matches the "Buy me a coffee" button's size and colour.**
