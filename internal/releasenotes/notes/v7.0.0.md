BombVault 7.0.0 is a milestone release carrying a large wave of new work. Settings, schedules and repositories carry over untouched: this is a milestone number, not a breaking change.

## Added

- **Missed backups catch up automatically.** A home server that is off at night silently skips its scheduled backups. On start (about two minutes after boot, so the array and Docker are up), BombVault now checks every enabled domain and runs a missed backup right away instead of waiting a full cycle. It is a completely normal run, visible in the activity log with a "catching up" line. Enabled by default under Settings, Schedules; domains that have never run are left alone.
- **Overdue-backup watchdog.** A lightweight daily check sends a notification through your existing channels when a domain's last successful backup is older than twice its schedule period, the exact rule the dashboard uses. One message per incident, re-arming only after a successful backup. Enabled by default under Settings, Notifications.
- **Storage forecast.** Each domain on the Storage card shows weekly growth, free space on the repository volume, and, while growth continues, a projection like "Repo volume full in ~6 weeks", highlighted once it drops under eight weeks.
- **Exclusion assistant.** Next to each container's exclude list, a scanner finds well-known cache folders and any unusually large directory in the appdata; one click adds it to the excludes, which flow straight into the backup. Already-excluded folders are skipped; the scan is depth- and time-bounded.
- **Apprise notifications.** Point BombVault at your Apprise API container's notify endpoint to reach the 100+ services Apprise supports, from Telegram and Pushover to Signal and PagerDuty. It behaves exactly like the built-in channels, including the test button, the scheduled-run summary and the weekly digest.
- **Weekly digest.** An optional once-a-week summary through your existing notification channels: how many runs succeeded or failed, how much was backed up, whether every off-site copy is current, and the week's failures, as one message instead of a feed to check.
- **Everything in the activity log.** A live, docker-logs-style panel on the dashboard shows what BombVault is doing right now and what it did recently, streaming a real percentage for backups and restores. Off-site replication, retention prunes, integrity and disaster-recovery drills, tamper tests and the flash-ZIP export are all recorded as first-class runs, each with a locale-aware date and outcome, filterable by domain, type or free text. Clicking a day in the backup heatmap filters the log to that day.
- **On the Unraid dashboard, and embeddable elsewhere.** A native Unraid dashboard tile shows the live activity log with one-click install (the companion bombvault-widget plugin), and a lightweight, token-protected widget page embeds the same log into Homepage, Organizr or any iframe dashboard.
- **Selective restore for folder sets.** A snapshot's contents can be listed and only the ticked files or folders restored, into a folder you choose, mirroring the file-level restore containers already have.
- **Private container registries.** Post-backup image updates can pull from private or sponsor-gated registries (GHCR, Docker Hub, lscr.io, custom hosts); credentials are stored encrypted and never echoed back.
- **Cron schedules.** Every schedule can use a raw five-field cron expression, with live validation and a preview of the next run times, alongside the existing presets.

## Reliability and performance

- **Repository locks no longer break overnight jobs.** Lock collisions that used to fail retention, verify or backup are removed at the source; a stale lock left by an interrupted run is cleared and the check heals itself, a hung restic is reaped without a container restart, and the container hostname is pinned so a genuine orphan lock is recognised within seconds.
- **Identity-stable retention.** Retention is scoped to each item's stable tag with grouping disabled, so changing an item's backed-up paths no longer freezes pruning of its older snapshots; frozen snapshots from before are cleaned up automatically on the next backup or prune. A failed retention prune now raises a notification instead of silently letting the repo grow.
- **Off-site replication that finishes in minutes.** A scheduled run backs up every item first and replicates the whole domain once, opening the remote repository a single time per run instead of once per container; what used to take around twenty-two hours now finishes in minutes. "Replicate now" runs in the background so a long first copy no longer times out, and the restic index cache is persistent and size-limited so a restart no longer re-downloads it.
- **No item is starved.** Scheduled runs visit never-backed-up and least-recently-backed-up items first, and an overrunning run no longer overlaps the next over the same repository.
- **Honest error and status reporting.** Failed update checks are recorded as runs instead of vanishing into the server log, restore errors carry their real underlying causes, and the dashboard Errors tile reflects only items whose latest run failed, so it returns to zero once everything has since succeeded.

## Interface

- **One visual language across the whole app.** Cards, panels and dialogs separate through background shading rather than outline borders; tabs, mode pills, day chips and filter buttons are filled, the active one carrying your accent colour. Light mode is readable everywhere, using proper high-contrast counterparts from the IBM Carbon light palette, including the backup heatmap.
- **A modern, maintained front end.** The interface was rebuilt on the current front-end generation, and the "What's new" dialog retries instead of failing when it opens mid-restart.
- **Smaller refinements.** Compact VM snapshot lists that match the container list, an aligned Protection Status card whose long badges wrap inside their column, activity-log dates that follow your region rather than the UI language, and the folder-set domain renamed to "Folders" everywhere.

## Upgrading

Nothing to do. Your settings, schedules and repositories are untouched.
