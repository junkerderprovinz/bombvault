BombVault 7.10.1 fixes an off-site replica that a non-root SMB session couldn't read the contents of, even though the connection itself worked and the repository folder was visible.

## 🐛 Fixed

- **A local/mounted-share off-site copy stayed unreadable over SMB.** After copying to an off-site destination, BombVault healed file permissions on the *primary* repository only — restic itself creates a repository as root with `0700` directories and `0400` files, and the off-site copy never got the same treatment. Reading the copy back as root (as an NFS mount effectively does) worked fine, masking the problem; connecting as an ordinary user over SMB, where the remote share enforces its own permission check, showed the repository's folder names but denied access to everything inside them. Off-site copies are now healed to readable permissions the same way the primary repository already is, on every replication. An already-existing off-site copy made before this fix stays as it was created - reconnect once over NFS (or over the original connection type used to create it) and let a replication run, or fix it directly on the remote side with `chmod -R a+rX` on the repository folder, and it will read correctly from then on.
