BombVault 7.3.1 is a bug-fix release.

## Fixed

- **"Backup path is not mounted yet" no longer sticks on a disk that is actually mounted.** BombVault protects you from re-initialising an empty repository over a backup share that has not mounted yet, which would shadow your real backups once the share reappears. That guard could latch permanently: once a repository had been established at a path, a later run that found the repository missing always reported "backup path is not mounted yet" and refused to proceed, even when the disk was in fact mounted and writable, and a restart did not clear it. This bit first backups to an Unassigned Devices disk in particular, because such a disk mounts after the container starts and can briefly shadow an earlier repository. BombVault now checks whether the destination is genuinely mounted (via the container's own mount table) before refusing: when the disk is mounted it clears the stale marker and re-creates the repository on the live disk, and only when the destination is truly absent does it still hold back, so the protection against shadowing real backups is unchanged.

## Upgrading

Just pull the new image. If BombVault was stuck on "backup path is not mounted yet" for a repository on a disk that is actually mounted, the next backup clears the stale state and creates the repository, so it recovers on its own.
