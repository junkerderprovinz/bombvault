BombVault 10.4.0 lets a scheduled backup wait while somebody uses the app, keeps the newest ZFS replica snapshots on the source too, and is on F-Droid. Every storage location can be renamed, and after an own folder moves to another storage location, new backups go there and the storage pages show where everything is. It also ships restic 0.19.1 and rclone 1.75.2 and follows GlimStone 3.8.0.

## ✨ Added

- **A scheduled backup waits while the app is busy and tries again on its own.** A Pre-backup command that exits with code 75 defers it instead of failing it. The **When the app is busy** card on a container's Settings tab sets how often it is tried again, an optional time window that may run past midnight, and how long it waits at most, then it gives up under Needs you or backs up anyway. The rest of the run goes on, the wait survives a restart, and you get one notice when it waits and one when it ends. A backup you start yourself always runs right away. ([#378](https://github.com/junkerderprovinz/bombvault/issues/378))
- **Ask Plex, Jellyfin or Emby before a scheduled backup.** The **Activity check** asks the media server whether anybody is watching, with Plex's own token from its Preferences.xml or an encrypted API key for Jellyfin and Emby. Paused sessions can stop counting after some minutes, and you choose whether a server that does not answer lets the backup run. BombVault asks the server directly and otherwise through curl or wget inside the container, which also reaches containers on br0 or macvlan. ([#378](https://github.com/junkerderprovinz/bombvault/issues/378))
- **Wait while the container sends data.** For apps without such a check, such as game servers or downloaders, a scheduled backup can wait while the container sent more than a rate you set within the last few minutes, read from Docker's own counters. ([#378](https://github.com/junkerderprovinz/bombvault/issues/378))
- **Keep replica snapshots on the source too.** The Replica card of a ZFS entry has a field **Keep on this server**. It sets how many of the newest replica snapshots stay on the source after each replica, next to the ones the target keeps. Their files can be read or copied right away from `.zfs/snapshot` or a clone. Rolling a dataset back to an older one needs `zfs release` on the newest first, and the copy on the target then goes back to the newest snapshot both sides still share, which the failed replica names. The documentation has the commands. 0 or 1 keeps only the newest. ([#359](https://github.com/junkerderprovinz/bombvault/discussions/359))
- **BombVault is on F-Droid.** The Android app has its [F-Droid listing](https://f-droid.org/packages/bombvault.halleluja.design/), and **Settings, Apps** links it where the button said "Soon". The README and the documentation's [Android page](https://junkerderprovinz.github.io/bombvault/android/#install) link it too. F-Droid builds and signs the app itself, so a new release reaches it a few days later, and switching between the F-Droid app and the APK means uninstalling the other one first.
- **Every storage location can be renamed.** A folder that several sections share, such as one S3 bucket folder the backup paths point into, took its name from the folder's last part and offered no way to change it. The off-site copy a section's settings describe offered only its keep rules. Both have a **Name** field on their page under **Storage locations**, like every other location. Thanks to @manilx for asking for it. ([#384](https://github.com/junkerderprovinz/bombvault/issues/384))
- **The overview's cards rock while you arrange them.** While **Customize** is on, every card tilts a little, out of step with the others, so you can tell it can be moved. The card under the pointer holds still, and nothing moves with animations off or under reduced motion.
- **Labels shows a symbol for each choice.** The four choices under **Settings, Look, Labels** carry a glyph, as Corners and Animation do. On a phone they sit two to a row.

## ⚡ Improved

- **Bandwidth limits also read in MB/s and Mbit/s.** You still enter them in KiB/s, the unit restic takes, so the values you set keep working. Next to each field the same rate appears in bytes and in bits while you type: 2048 reads as ≈ 2.0 MB/s (16.8 Mbit/s), which you can hold against the speed your provider quotes. This covers the off-site bandwidth, the upload limit while streaming, **Busy from** on a container's **When the app is busy** card, a pull source's download limit and a storage location's own limits. Thanks to @one4spl for asking. ([#380](https://github.com/junkerderprovinz/bombvault/issues/380))
- **Dropdowns answer the keyboard like a select.** With a dropdown focused, typing the first letters of an entry picks it, even while the list is closed. Home and End jump to either end of an open list, and after a pick or Escape the focus is back on the field. A tick marks the current entry, and the mouse wheel still steps through a focused field. The language picker works the same way, flags and all.
- **A busy button tells a screen reader that it is working** instead of only showing its spinner.
- **A direct repository is listed with its storage location.** A storage location's page shows under **Backs up straight here** each section that backs up straight to it and how many entries do. Such a repository has no settings of its own: it follows its location's switch and settings, and the update gives each one its location's settings again, with append-only on if either side had it. One that nothing backs up to any more says so and can be removed there. The backups at its place stay. ([#396](https://github.com/junkerderprovinz/bombvault/issues/396))
- **The Repositories card is calmer.** It lists the repositories made there, one row each, and a row opens the repository's own page with append-only, compression, availability and removal. ([#396](https://github.com/junkerderprovinz/bombvault/issues/396))
- **Switching Local off asks first.** Under **Storage locations per section**, switching Local off made the first lit copy the section's home through a direct repository it set up without a word. It opens the same dialog as the default card, and Cancel leaves everything as it was. ([#396](https://github.com/junkerderprovinz/bombvault/issues/396))
- **An entry leads to its section's setting.** **Follows the default** and **Copies follow the default** on an entry's Settings tab open **Storage locations per section**, where one choice covers every entry of the section, the ones you have and the ones you add later. ([#396](https://github.com/junkerderprovinz/bombvault/issues/396))
- **A storage location added again shows its old backups.** When you save a storage location that holds backups of containers, VMs or folders, it is added to those sections as an unticked copy. Nothing is copied there until you tick it, but **Restore** offers the old backups right away. ([#396](https://github.com/junkerderprovinz/bombvault/issues/396))
- **BombVault checks its storage locations at every start.** It goes through the whole storage location model and puts right what needs no decision from you: links to copies or repositories that are gone, a copy or off-site field on a section's own folder, and a direct repository whose copy is gone. Each fix gets a line in the log, the update's own clean-up included, and what has no safe fix is only logged. ([#396](https://github.com/junkerderprovinz/bombvault/issues/396))
- **A refused location says why in your language.** Every refusal of a storage location, repository or folder comes as a sentence in the language you use, and a full host path names the path to enter instead. A settings import names each problem the same way, with the row of the file it is about. ([#396](https://github.com/junkerderprovinz/bombvault/issues/396))
- **A location is checked before you are asked about it.** A copy, an off-site field or a mesh offer at a place BombVault refuses is turned down right away, instead of after a question about its first run. ([#396](https://github.com/junkerderprovinz/bombvault/issues/396))

## 🐛 Fixed

- **New backups follow a moved own folder.** With Local switched off, a section backs up straight to one of its copies. After its own folder moved to another storage location it kept doing that, so the new folder stayed empty although the move window said new backups would go there. Moving the own folder makes it the section's home again and keeps the copy. Thanks to @manilx for the patient reports and the screenshots of every step, which made this and the others below easy to follow. ([#396](https://github.com/junkerderprovinz/bombvault/issues/396))
- **An own folder in a storage location counts as the section's home.** **Storage locations per section** was missing, and the window that adds a storage location listed no section to tick, so nothing was ever copied to the new location. ([#396](https://github.com/junkerderprovinz/bombvault/issues/396))
- **An entry calls its home by name.** The placement bar said Local for an own folder in a storage location and offered the same location a second time as a copy. It shows the location's name, offers it once, and BombVault turns down a copy onto a section's own folder, which would have failed on every run. ([#396](https://github.com/junkerderprovinz/bombvault/issues/396))
- **"Used by" says off for an own folder that new backups go past**, the way it does for one that is switched off. ([#396](https://github.com/junkerderprovinz/bombvault/issues/396))
- **A replication with nothing new to copy says so.** The activity log reads "Off-site replication found nothing new to copy" instead of a success that took one second. ([#396](https://github.com/junkerderprovinz/bombvault/issues/396))
- **A settings import skips links that are gone.** A removed storage location left its id behind among a section's unticked copies, so saving that section's default failed with "that is not an off-site target of this domain", and so did importing an export of it. Removing a location takes its id along, the update clears the ones left behind, and an import leaves out links to targets or repositories that no longer exist and says which. ([#396](https://github.com/junkerderprovinz/bombvault/issues/396))
- **A copy on a section's own folder is gone.** A section could have a copy at the place its own folder lies, so an entry listed that place twice and every copy there failed. The update removes such copies, and moving an own folder clears an off-site field that names its new place. ([#396](https://github.com/junkerderprovinz/bombvault/issues/396))
- **An own folder and a copy of the same section keep apart.** A settings save could point a section's off-site field at its own folder or put the own folder where one of the section's copies lies, and the section then copied its backups onto themselves on every run. Both are refused, and the refusal says where to go instead. A copy that was switched off along with its off-site field makes room for the own folder once the section's key opens the repository there, and its backups stay as the own folder's. ([#396](https://github.com/junkerderprovinz/bombvault/issues/396))
- **A mesh offer goes through the location check.** Accepting a storage location another BombVault offered set it up wherever the offer said, even on a section's own folder or inside another location. It is held to the same check as a location you type in. ([#396](https://github.com/junkerderprovinz/bombvault/issues/396))
- **A moved own folder causes no false alarms.** After an own folder moved without its older backups, the restore check of the first backup looked for it in the new folder, failed and sent a notice, and comparing a finding's backups showed restic's error. The restore check waits for the next backup, and a finding compares its backups in the folder that holds both, the own folders a section left included, or says plainly why it cannot. ([#396](https://github.com/junkerderprovinz/bombvault/issues/396))
- **What you do right after a backup goes through.** The restore check that follows a first backup held its section for a few seconds, so moving an own folder or removing a storage location then was turned down with "A backup is running". The check steps aside for anything you start and runs again afterwards, and a section that is really busy names the backup, copy, restore or check that holds it. ([#396](https://github.com/junkerderprovinz/bombvault/issues/396))
- **A confirmed default stays confirmed.** A copy that was listing its new storage location could pause a section's default a moment after you had confirmed it. A default you confirm stays confirmed, and starting a copy of a paused section says why nothing was started instead of reporting a start that never ran. ([#396](https://github.com/junkerderprovinz/bombvault/issues/396))
- **A message stays clear of a window's buttons.** On a phone a long message sat on top of the buttons of an open window until it went away. It rises above them while the window is open.
- **A list opens on every click.** A dropdown, the time picker or the colour picker could close again right after opening when the page had just scrolled, so the click seemed to do nothing. They close on a scroll only when it moves them away from their field.
- **A container without data says so.** A container that has no data under Host Data keeps only its definition, yet its history showed a bar for every run and marked one as the recommended snapshot. The history counts snapshots only, the entry says right away that it keeps only the definition, and a day of a few bytes no longer fills the chart. ([#396](https://github.com/junkerderprovinz/bombvault/issues/396))
- **Picked files land directly in the target folder.** A file ticked in a container's restore window came back below its whole backup path, such as `host/user/user/appdata/dockhand/stacks/DXP6800/immich/compose.yaml`, and folder sets and ZFS datasets let two picks with the same name overwrite each other. A file comes back as just the file, a folder as the folder with its contents, and picks from different folders keep only their path below the folder they share, while **Replace original** is unchanged. Thanks to @manilx for reporting it. ([#383](https://github.com/junkerderprovinz/bombvault/issues/383))
- **An orange line in the log says why it is orange.** A backup that went through but left something out, such as data outside Host Data or files it could not read, turned its line orange without a word. The line names what was left out and the folders or files behind it, every note of the run in your language. ([#377](https://github.com/junkerderprovinz/bombvault/issues/377))
- **Data outside Host Data warns only where it matters.** Anonymous Docker volumes, the folders with a 64-character name under `/var/lib/docker/volumes` that usually hold a cache, cause no warning, while named volumes and other folders outside Host Data still do. An exclude line with the folder's path inside the container, a folder above it or the host path the warning shows turns the warning off, and the **Backup folders** card lists volumes next to bind mounts with both paths. ([#377](https://github.com/junkerderprovinz/bombvault/issues/377))
- **An exclude line can no longer empty a backup.** A line of `/`, `*` or `/**`, or one that named a backed-up folder or a folder above it, such as `/host/user` where Host Data sits inside BombVault, or `/config` when that whole volume is backed up, went to restic as typed. The backup then kept nothing but empty folders and still reported success. Containers, folder sets and ZFS datasets ignore such a line, and the preview under the field says it would exclude everything. To leave a whole folder out, untick it under **Backup folders**.
- **The exclude previews say what the backup does.** On a phone the warning under a long exclude line keeps its width instead of shrinking to a column one word wide. The ZFS preview warns about a line that names part of the snapshot path the backup reads, such as `.zfs`, `snapshot` or `bombvault-*`, which the backup ignores because it would leave a whole dataset out, and it counts the files of a child dataset once instead of twice.
- **A trial restore passes when every file came back.** It stopped on ownership and `trusted.*` attributes the `/mnt/user` share refuses, and on files with several hardlinks, which restic counts once but restores under every name, although nothing was missing. It compares the restored files and bytes with the snapshot's file list, so only a real difference fails it. Thanks to @one4spl for finding the line and for testing. ([#379](https://github.com/junkerderprovinz/bombvault/issues/379))
- **A link to a card that loads late finds it.** A settings link to a card that reads a list first said the card was not on screen. It waits up to three seconds for it.
- **A mail subject with umlauts arrives intact.** The subject of a notification mail is encoded, so mail programs show it as written.
- **A port out of range falls back to the default.** A `PORT` or `HTTPS_PORT` outside 1 to 65535 is logged and replaced by 3000 or 3443, so a typo in the template still brings the web interface up.

## 🎨 Design

- **GlimStone 3.8.0.** The interface follows the latest release of its design language, and the Version card on the Info page says so. Buttons wear the glyph of what they do: trying again, reading a file in or writing one out, confirming, declining, applying and undoing each have one of their own, the passkey sign-in wears the key, Unlink a broken link, and What's new a gift behind its dot. Version numbers read without their "v", the back button stands as tall as the buttons beside it, and a progress bar redraws only itself while it moves.
- **Enterprise File Fabric has a mark of its own.** In the list of providers it shows the storage symbol instead of the plain cloud that stands in for a missing logo.

## 🔒 Security

- **restic 0.19.1 and rclone 1.75.2.** Both come up to their newest release, which takes the two critical findings the image scanner reported for restic out of the image. The build checks both downloads against the checksums each project signs before anything is installed.
- **Notification mails keep their headers to themselves.** A line break in a notification's title, sender or recipient can no longer start a header of its own in the mail.
