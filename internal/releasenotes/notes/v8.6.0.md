The login window was asked a direct question: is it safe to expose through a reverse proxy? Reading the code turned up three answers worth acting on, and this release acts on all three and adds a second factor. It also folds in everything from 8.5.1 through 8.5.5: a backup round that measured its repository once per container, settings that never survived a cleared browser, and a handful of messages that named the wrong cause.

## ✨ Added

- **Two-factor authentication** (Settings, Two-factor authentication). A time code from an authenticator app on top of the password. Scan the QR code, type one code to prove the app works, and write down the eight single-use recovery codes that appear once. The shared secret is stored encrypted with your `APP_KEY`, so a copied database cannot generate codes. Turning it off again needs a current code, so a session left open on somebody else's screen cannot quietly remove it.
- **`TRUSTED_PROXY`**, the address or range your reverse proxy connects from. Without it the login throttle sees only the proxy and counts every visitor in one bucket, which means an attacker's five failures a minute lock you out of your own instance. Naming the proxy restores per-client counting. It stays off by default, because a forwarded-for header believed from anybody would let a caller pick their own bucket, which is worse than no throttle at all.
- **The number field takes the mouse wheel while it has focus.** Once the browser's own arrows are gone a number has three ways in: typing, the arrow keys and the two steppers. The wheel is the fourth, and it is the one people reach for on a value they are dialling in rather than typing. Focus is the condition on purpose: a field that answers the wheel on hover changes values somebody was only scrolling past, which is exactly why browsers removed that behaviour from the native widget in the first place. The page no longer scrolls at the same time either, so the field cannot slide out from under the pointer mid-adjustment.
- **A second button height, for the one control a page is about.** There was one height until now, and it is right for every button standing in a row of fields, which is almost all of them. It could not answer the button a page exists for. Raising the single height instead would have put every control in the app out of line with every field beside it to solve a problem two controls have.
- **A confirmation window can now ask one thing alongside its question**, for the case where an action needs an answer to something before it runs. Without it, an app either builds a second confirmation window of its own or asks afterwards, which is a second question about an action already taken.

## 🔒 Security

- **A login password must now be at least twelve characters.** There was no minimum at all: `1234` was accepted, and at five attempts a minute a four-digit PIN falls in under two days. The rule applies when setting a password, never when checking one, so an instance with a shorter password keeps working and its owner is asked to change it rather than shut out by an upgrade.
- **Passwords are stored with Argon2id instead of a bare HMAC.** The old scheme was fast on purpose, and the only thing standing between a copied `/config` and the password was the secrecy of `APP_KEY`, which lives in that same directory. Each guess now costs memory and time. The `APP_KEY` pepper is kept, so a database without the key is still worth nothing. Existing hashes are upgraded in place on the next successful sign-in; nobody has to do anything.
- Hashing is capped at two concurrent verifications, so making the door expensive cannot become a way to exhaust a container's memory.
- **The Fleet token is no longer accepted in the address, only in a header** ([#198](https://github.com/junkerderprovinz/bombvault/issues/198)). Nothing ever sent it the other way: BombVault's own peer polling and its storage offers have always used the header. What the address form did do was give the token one way to end up somewhere nobody controls, because a reverse proxy writes the full address into its log.
- **The dashboard widget no longer repeats its token on every refresh.** The token still appears once, in the address you paste into your dashboard, because an embedded frame cannot do otherwise. Everything the widget fetches after that carries it in a header instead. Previously the widget wrote its token into the proxy log once per refresh, for as long as the dashboard stayed open.
- Encrypting these tokens would not have helped and is worth saying plainly: the connection is already encrypted, and a scrambled token handed to a browser is simply the new password. The fix is to keep it out of addresses, which is what this does.

## 🎨 Design

- **The sidebar narrows when it shows only symbols** ([#178](https://github.com/junkerderprovinz/bombvault/issues/178)). Glyph mode drops the rail to 6rem with a smaller mark. The other three label modes keep their width, Reactive included: it slides each row's words back in *inside* the row and keeps them on the active row, so a narrow rail would clip the one row that has to stay readable.
- **The "update after successful backup" toggle says what it leaves behind** ([#193](https://github.com/junkerderprovinz/bombvault/issues/193)). The untagged image Unraid lists as an orphan is the normal residue of a successful update, and it is what makes a rollback cheap. The toggle says so now, and names **Settings → Paths & Storage → Image Cleanup & Update Status**, which has a switch for deleting it.
- **The backup CPU cap says what it does not do** ([#189](https://github.com/junkerderprovinz/bombvault/issues/189)). It limits how much runs at once, not how many threads `top` or `btop` lists: restic always keeps more than the cap, most of them waiting on the disk.
- **The confirmation window loses its two divider lines.** A rule under the title and another above the buttons is hierarchy drawn with borders, which is the thing this app's design language exists to avoid, and it had survived in the one window the language ships itself.
- **Its close button is optional now.** Two controls that do the same thing, one of them where a window's close button lives, read as a choice between two answers rather than as one answer offered twice.
- **The confirm button can carry its own mark**, for an action whose label is composed rather than named, which previously left it as words alone beside a cancel button that had one.
- **The interface is built against GlimStone 1.7.5**, up from 1.6.0. The number on the About card had come to say the opposite of what it is for: the engines had moved on without it. Audited entry by entry rather than adopted wholesale, and most of the list was already here, because this app is where several of those rules were found in the first place.

## 🐛 Fixed

- **Notifications shipped muted, and the Test button said otherwise** ([#195](https://github.com/junkerderprovinz/bombvault/issues/195)). A fresh install had no notification policy stored at all, and no policy was treated as "never". The Test button sends regardless, so it arrived and looked like proof. Somebody could set up a channel, test it, see it work, and never be told that backups had stopped. Not choosing now means being told when something fails; choosing "never" on purpose still means never.
- **A container backup takes the container offline, and nothing said so** ([#197](https://github.com/junkerderprovinz/bombvault/issues/197)). That is how the data stays consistent and it is not changing, but pressing Back up on a media server in the afternoon should not be a surprise. It is said once, before the first container backup, and then never again.
- **The Recovery wizard now names the folders it read** ([#196](https://github.com/junkerderprovinz/bombvault/issues/196)). It asks for an off-site repository in one step and then reads each domain's own backup path in the next, which is usually somewhere else, and in a disaster that folder is empty. An empty answer about an unnamed folder reads as "my backups are gone". With the path beside it, it reads as "it looked in the wrong place", which is both true and something you can fix.
- **A round ran one repo-size measurement per container** ([#189](https://github.com/junkerderprovinz/bombvault/issues/189)). The 20-hour throttle asks when the last measurement was by reading the row a measurement writes when it *finishes*, so while the first one walked the repo every following container passed the throttle and started its own. Each is three restic runs, all with `--no-lock`, which is why nothing ever blocked and nothing reached the log. Reported as a box pinned at 90-100% CPU for a whole round with nine concurrent restic processes, and the CPU cap could not help because it applies per restic process. A round measures once now, at the end, and an in-flight guard makes measurements impossible to stack up on any path, the dashboard's own polling included.
- **The growth-budget check on a remote primary measured the same thing again**, synchronously and with no throttle at all, once per container. It reads a single number and now costs one `stats --mode raw-data` instead of a full three-run sample.
- **A received repository could be checked twice at once.** The scheduled integrity check is gated on when the previous one *finished*, and the manual check button beside it had no gate at all, so a second click or a manual check landing on the nightly sweep started a second `restic check` on the same repository, re-reading pack data wherever a read-data percent is configured. One check at a time per repository now, and the button says a check is already running instead of starting another.
- **The restic cache could be trimmed several times over.** The trim rides a hook that fires once per scheduled item rather than once per night, so containers on their own cadences firing in the same minute each measured the whole cache and evicted enough to make it fit. The rule that spares the most recently used repo cache protects exactly one, while a round can have a local, an off-site and a received cache live at once.
- **On an instance with a password, the stored settings never reached the browser at all** ([#191](https://github.com/junkerderprovinz/bombvault/issues/191)). The look is fetched from the server as the page starts, and on a locked instance that happens while the login screen is up, where the request is refused like every other one. Signing in then shows the interface without reloading the page, so nothing asked again. Since clearing site data also clears the session, every attempt went through a sign-in, and the settings sat on the server untouched while the browser showed defaults. The look is fetched again the moment you are signed in.
- **A cleared browser could wipe the look it was meant to restore.** Saving display settings replaced the whole set every time, and a browser sends what it has, not what it should have. A page still running in a tab whose site data had just been cleared therefore published its own emptiness on the next change, and the other settings were gone on the server as well. Each setting is merged on its own now, and a browser with nothing to say no longer says anything.
- **The settings arrived but the page still showed defaults.** Restoring the look ended in a page reload, because the language and the advanced view are read once when the interface starts. That reload was allowed only once per tab, as a safeguard against reloading in circles, and a tab that was restored or that stayed open while its site data was cleared had already used it up. Each setting is applied where it stands now, so nothing has to reload and nothing can be skipped.
- Whether a Fleet peer card shows its scorecard is kept with the rest of the look, so it also survives a new browser.
- **A refused repository was reported as "reachable, not initialized"** ([#192](https://github.com/junkerderprovinz/bombvault/issues/192)). restic prefixes `unable to open config file` onto a 401 exactly as onto a missing repository, and BombVault believed the prefix instead of the status code. A 401 or 403 now reports as refused.
- **A rest-server refusing your credentials now says which of the two mistakes it is** ([#194](https://github.com/junkerderprovinz/bombvault/issues/194)). Both causes were known and written down where only a maintainer would read them, while the message on screen was the bare `401 Unauthorized` the transport hands over. It names them now: the first path segment of the repository URL has to be the htpasswd user when the server runs with `--private-repos`, and a repository can be reaching for the shared credentials rather than the set that was filled in for it. It also points at the two-box walkthrough in the off-site documentation, which exists and is not easy to find from where somebody starts.
- **The number field's steppers sat at the edge of the row instead of the edge of the field.** The wrapper holding the two arrows was sized by its parent rather than by its content, and a labelled field is a column, so a narrow number box in a full-width column produced a full-width wrapper with the arrows at the far right and the field alone on the left. The rule has said "a stepper is part of the field, not a control next to it" for a long time and the stylesheet agreed with it; the screen did not.
- **The motion setting now reaches ordinary transitions, not only the entrances.** The three-way switch changed page and toast animations and left every hover, colour fade and open or close running at the framework's default, which is the same complaint the switch exists to answer, one layer down.
