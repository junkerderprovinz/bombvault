BombVault 10.3.3 stops warning about anonymous Docker volumes and shows every folder it cannot reach where you would look for it.

## 🐛 Fixed

- **Anonymous Docker volumes no longer turn backups orange.** A folder an image declares and nobody mapped ends up as a volume with a 64-character name under `/var/lib/docker/volumes`, and it usually holds a cache. A backup with one stays green again. Named volumes and other folders outside Host Data still get the warning. ([#377](https://github.com/junkerderprovinz/bombvault/issues/377))
- **The Backup folders card lists what BombVault cannot reach, and the host path works as an exclude.** Volumes show up next to bind mounts, each with its path inside the container and its host path and the note that it can't be backed up, and an anonymous one says it causes no warning. To silence a warning, an exclude line can name either path, including the host path the warning shows, such as `/var/lib/docker/volumes/<name>/_data`. The preview confirms it, and the line never goes to restic. ([#377](https://github.com/junkerderprovinz/bombvault/issues/377))
