Databases are dumped before every backup, ZFS datasets are a backup type of their own, and BombVault tells you when a backup looks wrong, not only when it fails. You can also see what the next retention run would delete and what no backup covers. An AI assistant can read your backup status and start a backup through the built-in MCP server, with a key of its own or, for ChatGPT and Claude on claude.ai, by signing in through OAuth. The major number is for the size of the release: settings, schedules and repositories carry over as they are.

## ✨ Added

### Automatic database dumps

- **Recognised databases are dumped before each backup.** PostgreSQL, MySQL and MariaDB containers (the official images, PostGIS, TimescaleDB, pgvector, pgautoupgrade, Immich's database images, linuxserver, yobasystems and jc21 MariaDB, Oracle's mysql-server) get a full SQL dump from the running server. It streams straight into the repository as a restore point of its own and is never written to a disk.
- **On by default.** Switch it off per container on its card on the **Containers** page, with the label `bombvault.dbdump=false`, or for all containers under **Settings, General, Automatic database dumps**. A container that only looks like a database gets the same switch, off until you turn it on.
- **A failed dump never fails the backup.** It shows up as a failed "Database dump" run with its reason and a hint, counts on the dashboard, the coverage card, the Unraid widget and the metrics, and sends a notification.
- **No password leaves the container.** The dump reads the container's own variables inside it, including `_FILE` secrets and linuxserver's `FILE__` variables.
- **A cut-off dump never becomes a restore point.** restic keeps it only when the dump tool exited cleanly, the end marker is there and the stored size matches.
- **BombVault never loads a dump back by itself.** In the container's **Backups** panel, download one as `.sql` or `.sql.gz`, save it to a folder, or import it into a freshly started database, which keeps the old data folder beside it.
- **`DB_DUMP_MAX_HOURS`** (6 by default) limits one dump. A dump that stops making progress is cut earlier.

### ZFS datasets

- **A ZFS page in the sidebar.** Pick a dataset from the server's list and it is backed up with every dataset below it, all read from one ZFS snapshot. New child datasets join by themselves, and you can leave single ones out.
- **Stored like a folder.** Each dataset is read from the snapshot and stored with restic, so unchanged data is not stored twice and single files come back on their own. BombVault never uses `zfs send`.
- **Short downtime.** Name containers to stop only for the snapshot instant, or run a command before it. They are back within seconds.
- **Restores never roll back.** Restore one dataset into its place, into a folder, or only the files you pick. Before writing into a dataset BombVault takes a ZFS safety snapshot (on by default), which stays until you delete it on the page.
- **Nothing is skipped silently.** A dataset that cannot be read is named on the run, on the item and on the coverage card. A volume a VM uses is backed up with that VM.
- **Everywhere the other types are:** schedules, per-item repositories, retention, off-site copies, drills, Backup Everything, coverage, metrics, notifications, anomaly detection, the support bundle, the recovery kit and the **Recovery** page.

### Anomalies

- **Every backup is compared with its own history.** That covers containers, VMs, folder sets, database dumps, ZFS datasets (dataset by dataset), the flash drive and the self-backup. BombVault reports much more new data than usual, most of the data stored again, a source or dump that is suddenly almost empty or much smaller, far fewer files, a much slower run, repeated or intermittent failures, a restore check that stopped passing, and a disk that will be full soon.
- **Old backups are kept when data is lost.** When a source shrinks sharply or one backup stores most of the data again, retention keeps that item's old backups until you acknowledge the anomaly, so an emptied or encrypted folder cannot push the good backups out one night at a time. The anomaly links to the last good backup.
- **Where you see it:** the **Anomalies** page right under Dashboard, a dashboard card, a badge on every item and run, and a notification for critical findings, once per episode. Sensitivity (Strict, Balanced, Permissive) and the lowest severity that notifies are set under **Settings, Integrity, Anomalies**, and each item can override them.
- **Existing installs do not start from zero.** Sizes, file counts and durations are read once from what restic 0.17 already stores. An item learns from 10 backups, while an almost empty source, a rewrite of most of the data and failures are checked from the first.

### Knowing what your backups do

- **What the next retention run would remove.** The retention cards under **Settings, Paths & Storage** and **Settings, Off-site** have a button that lists, per repository and item, what the next run would delete. It changes nothing and works while a backup runs.
- **Not backed up.** A dashboard card names every container, VM and folder no automatic backup covers, with the reason and the switch that closes the gap. A backup type you switched off is not counted.
- **Support bundle.** **Download diagnostics** under **Settings, System, Export / import settings** makes a redacted ZIP for a bug report: the host check, your configuration without secrets, recent runs, the schedule, the recent log, the dump state, the ZFS items and the open anomalies. It needs a login password.
- **A stalled backup is stopped.** `BACKUP_STALL_HOURS` (2 by default) cancels a backup that makes no progress at all, so a run stuck on an unresponsive share ends in hours instead of days, while a slow but healthy multi-terabyte run carries on.
- **The exclusion assistant warns about app databases in another container**, such as Immich's and Nextcloud's, which a folder backup of the app does not contain.
- **The recovery kit covers dumps and ZFS datasets.** It has the restic commands to get either back without BombVault and warns against restoring the newest snapshot after data loss, since that can be the emptied or encrypted one.

### MCP server for AI assistants

- **An assistant can read how your backups are doing:** status per domain, coverage, the protected items with their last backup and what a backup of them stops, run history, restore points including database dumps and ZFS datasets, current activity, repository growth and the open anomalies.
- **With a key that allows it, it can start** a backup of one item, of one domain or Backup Everything, and cancel the backups its own key started. Restores, deletions, prune, acknowledging anomalies, settings, credentials and keys stay in the web interface.
- **A button per client.** 28 clients on your computer, among them Claude Code, Cursor, VS Code, Gemini CLI, LM Studio and n8n, and ChatGPT, Claude, Grok and Le Chat in the cloud. Each button opens a setup made for that client: a key named after it and its configuration in the client's own format, without putting the key on a command line, or the sign-in for the two that take no key. The dialog turns green once the client has connected. Anything else that speaks Streamable HTTP connects through Other client.
- **One key per client**, created under Settings, System, MCP server, shown once and stored as a fingerprint, with read-only keys for clients you trust less. Every key change sends a notification. Each key's tile shows the mark of the client it was made for.
- **Limits that protect your restore points:** 12 starts per hour per key, 15 minutes between starts of the same item, 4 per item a day, and a retention guard that keeps assistant backups from pushing your own restore points out of a "keep last N" policy.
- **You see what it did.** Every run it starts, and the prune and off-site copy that follow, reads "via MCP" with the key's name in the activity log, the error panel and the backup notification. **Log** on each key's tile in the MCP card shows what that key did over the last 30 days: the backups it started, each linked to its run, and its calls with their outcome, including why a call was refused.
- **Works on a plain Unraid install.** The card adds the address you use to the self-signed certificate with one click and hands you the certificate file for the client. A reverse proxy or Tailscale works as well. The endpoint `/mcp` answers 404 until a key exists or sign-in through OAuth is switched on.

### Sign-in through OAuth for cloud assistants

- **ChatGPT and Claude on claude.ai connect without a key.** BombVault is the OAuth authorization server of its own MCP endpoint. Switch on **Sign-in through OAuth** on the MCP card and enter the public https address BombVault is reachable at; the ChatGPT and Claude buttons then show the connector URL and where it goes.
- **You allow each client yourself.** The client sends you to a BombVault page where you sign in with your login password, and your second factor if you set one up. The page shows who asks and where your answer sends you back to, warns that a link from someone else could connect their account, and starts with **Allow starting backups** off. A request it refuses stays on that page instead of sending you anywhere.
- **Each signed-in client gets a tile beside the keys**, with its mark, its own log, Revoke and the start switch, and the same limits as a key. Revoking takes effect at once. Switching sign-in through OAuth off, or changing the public address, revokes every grant.
- **Built to the MCP authorization specification:** protected resource and server metadata, dynamic client registration, the authorization code flow with PKCE (S256) only, tokens bound to BombVault's own address, access tokens that last an hour and refresh tokens that are replaced on every use. A refresh token or code that turns up a second time revokes the grant it belongs to; a client that repeats a refresh within 30 seconds because the answer never reached it gets new tokens instead.
- **Only offered while a login password is set.** Tokens, codes and client secrets are stored as fingerprints, registrations are limited per address and capped, and restoring a configuration backup or changing `APP_KEY` affects sign-ins as it affects keys.
- **The recovery kit** says that restoring the settings backup revokes every MCP key and every OAuth sign-in, and **the support bundle** carries the number of MCP keys, signed-in clients and registered clients, never their names or the public address.

### More

- **SMB shares and WebDAV servers as off-site destinations**, from a form in the **Off-site (rclone)** card under **Settings, Off-site**, without mounting the share on the host.
- **The recovery kit can be sealed.** With export encryption on under **Settings, Paths & Storage**, the kit downloads as `bombvault-recovery-kit.md.age`, armored so it can still be pasted or printed.
- **Renamed containers, VMs and folder sets keep their backups** ([#233](https://github.com/junkerderprovinz/bombvault/issues/233)). The card recognises the old entry, names what the match rests on and takes it over once you agree. "Link to an entry…" does it by hand, and **Unlink** undoes it.
- **Disco mode and the Storm animation level**, both hidden until you find them.

## ⚡ Improved

- **A cancelled backup leaves nothing stopped.** Containers, their dependencies and VMs stopped for the backup start again, a live VM's overlay is committed back, and a hook hanging in the container no longer holds the run. A cancelled or interrupted backup is reported as such, not as failed, and the **Cancel backup** button goes away once the restore point is written.
- **`BOMBVAULT_SELF_CONTAINER` is optional.** BombVault finds its own container from the mount table, whatever its hostname.
- **Host SSH.** The template's SSH fields are called **Host SSH: Address, Port and User**, and so is the card under **Settings, System**, because VM and ZFS backups both use them. Its test passes when only libvirt is missing. Your values stay.
- **An address left at the template's `192.168.x.x`** no longer blocks the connection; BombVault tries the server through host.docker.internal.
- **Counts read the way each language forms them**, with three, four or six plural forms where a language has them.

## 🐛 Fixed

- **Settings saves no longer delete additional off-site targets.** An empty off-site field in Settings removed the domain's other targets on the next save, mesh targets included. Only sort order 0 is the primary now.
- **A renamed or removed entry can leave the schedule** ([#232](https://github.com/junkerderprovinz/bombvault/issues/232)) with its "Include in schedule" switch, and keeps its backups.
- **Test connection reports an unreachable server as unreachable** ([#246](https://github.com/junkerderprovinz/bombvault/issues/246)), with restic's own reason, instead of as an empty repository.
- **The sidebar scrolls on a short window** ([#247](https://github.com/junkerderprovinz/bombvault/issues/247)), and a tooltip no longer stays on screen after Prune ([#243](https://github.com/junkerderprovinz/bombvault/issues/243)).
- **A card's "Last backup" matches its backup list**, including entries rebuilt by Discover and folder sets.
- **A VM backup that gives up before it starts says why**, and a restore refuses a disk it cannot reach instead of leaving it out.
- **TrueNAS: SSH commands reach the right machine.** With `LIBVIRT_URI` set, a missing SSH host, user or port is taken from it.
- **VM backups with zvol disks** count the disks' new data, and **off-site copies from a named repository** include the dumps.
- **The Unraid template mounts Host Data as Read/Write - Slave**, so a share mounted after BombVault started is visible to it.

## 🔒 Security

- **A plain settings export no longer carries a primary repository's password.** A backup path that is itself a remote with credentials (`rest:https://user:pass@…`) was exported as is. It is redacted now, and importing such a file keeps the live value.
- **rclone 1.75.1**, which closes two vulnerabilities the image scanner flags as critical.

## Upgrading

- **Nothing has to be changed.** The database is upgraded on the first start, settings export files from older versions still import, and no setting or environment variable was removed or renamed. The MCP server stays off until you create a key or switch on sign-in through OAuth.
- **Database dumps start with the next backup** of every recognised database container. If your databases already dump themselves, switch it off under **Settings, General, Automatic database dumps**.
- **Anomaly detection is on**, and while an anomaly about lost data is open it keeps that item's old backups beyond your retention policy. Acknowledge the anomaly or mark it as expected to let retention run again.
- **Older Unraid installs keep Host Data on plain Read/Write.** In the Docker tab, edit BombVault, set Host Data's Access Mode to "Read/Write - Slave" and apply. ZFS datasets need it, together with Host Data mapped as `/mnt` and the Host SSH link VM backups use. On TrueNAS, set Host Data to a host path above the datasets, such as `/mnt/tank`.
- **An additional off-site target lost to a settings save** does not come back on its own. Add it again under **Settings, Off-site, Additional off-site targets**.
- **Sign-in through OAuth faces the internet.** It needs a login password and BombVault reachable at a public https address with a certificate browsers trust, usually through a reverse proxy. A proxy with a login of its own has to let `/mcp`, `/oauth/` and `/.well-known/` through to BombVault, and `TRUSTED_PROXY` has to name the proxy, or every client seems to come from its address and they share one limit.
- **Scripts that create off-site targets:** `POST /api/offsite/targets` refuses sort order 0, which belongs to the domain's off-site field, and places a target without one last.
