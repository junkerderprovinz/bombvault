Rename a container, a VM or a folder set and its backups come with it. BombVault recognises the entry, says what it recognised it by, and moves the old one over once you agree.

## ✨ Added

- **A renamed container or VM is recognised on its own card** ([#233](https://github.com/junkerderprovinz/bombvault/issues/233)). The card reads "Looks like radarr-old" and names what the match rests on: the same Docker container, the same appdata folders, the same compose service, a template Unraid renamed along with the container, or, for a VM, the same libvirt UUID. Beside it stands the number of backups waiting under the old name. "Not this one" puts the suggestion away for good.
- **Taking over moves the old entry here.** Its schedule membership, its folder selection and its exclusions come along, and its backups become this entry's history: they appear in the snapshot list, they restore into the entry under its new name, and retention counts the backups of both names together from then on.
- **Where nothing matched, the link is made by hand.** A card without backups of its own offers "Link to an entry…" and lists the entries that are no longer installed. Entries that are already another entry's former name are left out, because their backups have an owner.
- **The former name stays on the card.** An entry that took another one over reads "Formerly: radarr-old" and carries an Unlink button. Unlinking puts the entry back under that name together with the backups from before the link; whatever was backed up under the new name since then stays with the new name.
- **A former name that is in use again is called out.** If something else starts running under the old name, the card says so and says that the older backups stay where they are. Who owns which snapshot is decided by the time of the link: everything before it belongs to the entry that was renamed, everything from the link onwards to whoever carries the name now.
- **Discover brings the links back after a lost database.** Each link is written into the encrypted definition copy that travels with the backups, so rebuilding the entries from the repository restores the former names as well.
- **A folder set's name is fixed once it has backups**, because they are filed under it. The form says so and points at creating a new set for a new name.
- **Every refusal names its reason.** A takeover is refused while a backup is running, when the target already has backups of its own, when the old name is live again, and for BombVault's own container. Unlinking is refused while the old name is live, and when another entry has been backed up under that name since the link was made.

## 🎨 Design

- **The confirm dialog answers in the accent and repeats the verb that asked.** Deleting a backup is answered with Delete and the trash glyph instead of a neutral OK, and a plain confirm wears a check mark. The corner close button is gone: Cancel already answers, and the two wore the same cross.
- **The sign-out button wears a sign-out glyph.** It had the power glyph, which in this app means shutting a VM down. The directional glyphs mirror in a right-to-left layout.
- **Disco glides the colours round the wheel instead of stepping.** A palette move lands on the document root alone, and the registered colours travel over the same three seconds a step takes, each ink flipping halfway. Panels rendered outside the page follow the same references.
- **The Recovery page is titled Recovery**, the name its tab has carried all along. The heading said "Disaster recovery".
- **The sidebar rows press by the motion engine's number.** They scaled by a value written into the row, so they kept pressing at the motion level where a press is off. A guard keeps the next control from writing its own number instead of taking the token.

## 🐛 Fixed

- **A card's "Last backup" line and the list of backups under it no longer disagree.** The line came from the run history, the list from the repository. An entry rebuilt by Discover has no runs at all and read "Never" with a repository full of its snapshots; the stand-in written for that reached only entries whose container was gone, and the VM list had none. The line is the newest backup the entry owns, decided by the same rules that decide which backups it may restore. While the repository cannot be listed the run's own date stands in, so an unreachable repository still does not read as never backed up.
- **A folder set is dated from its backups too**, so a set rebuilt from the repository stops reading as never backed up and one whose backups were deleted stops keeping a date.
- **A snapshot list empties when its source fails to load.** Switching Flash to off-site left the local rows sitting under the off-site error, because a failed load kept the previous list. Flash, Config and the VM, folder-set and container panels clear the list on a failed load and drop answers that arrive for a source that is no longer selected, including the reload a finished delete starts.
- **A VM backup that gives up before it starts says so.** Its checks run before the first progress event, so a disk it cannot reach, a repository it cannot open or a host it cannot ask left the card turning until the page gave up hours later, with the reason only in the log. The failure is recorded as a run, the way a container backup already did, which is what the card waits for and what carries the reason to the error panel.
- **A restore refuses a disk it cannot reach instead of leaving it out.** A disk outside the Host Data mount was dropped, and the VM was then defined from a description that still listed it and started, with nothing said. The backup refuses such a VM whole, and the restore does the same now. A restore into another instance also refuses two disks whose file names would land on each other in the destination folder.
- **Counts read the way each language forms them.** Ten Slavic and Baltic languages have three or four forms where English has two, and sixteen of the twenty-one strings that carry a count had only one, so a card could say "1 containers". Each language's own rule picks the form, through the plural rules the browser already carries.

## 🌐 Translations

- The rename suggestion, the takeover and unlink dialogs, the former-name row, the link picker and the name-locked hint: 31 new strings in all 42 languages.
- Plural forms for the fifteen strings that carry a count, in all 42 languages: three forms in Czech, Lithuanian, Polish, Russian, Slovak and Ukrainian, four in Slovenian, six in Arabic, and one where a language needs one.
