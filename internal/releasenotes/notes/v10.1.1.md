A patch for keep rules and for ZimaOS: the copy in a section's Off-site field follows the How long to keep card of its storage location, like every other copy, and BombVault finds container data in ZimaOS's /DATA/AppData folder.

## ⚡ Improved

- **One place for how long backups are kept.** The copy from a section's Off-site field follows the How long to keep card of its storage location, like every other copy, and a section can have its own values there under Rules per section. The Off-site retention card under Settings, Storage locations is gone. The Retention tab there points to the storage locations and keeps the preview. The update changes no copy's rules: a copy whose values match its storage location follows it from then on, and any other keeps its values as its own rules for that section. ([#351](https://github.com/junkerderprovinz/bombvault/issues/351))

## 🐛 Fixed

- **Reset to the storage location asks before it keeps less.** On the How long to keep card it removed backups without the question that Ask before keeping less promises. It asks first, as the Rules per section window does.
- **Container data under /DATA/AppData was not found.** ZimaOS keeps app data in a folder called AppData, but BombVault only matched appdata in lower case, so a container backup there held its configuration and none of its folders. Setting DATA_ROOT_SEGMENTS=AppData did not help either. The folder name now matches in any case, though still only as a whole name, so a folder such as AppDataBackup does not count. A restore writes the data back under the folder's own spelling.
