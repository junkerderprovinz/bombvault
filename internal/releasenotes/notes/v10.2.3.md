BombVault 10.2.3 is a long list of fixes: ZFS replicas send faster, Replica only switches off cleanly, restores come back on the image they were backed up with, and backups, copies, checks and alerts that used to stop or vanish without a word now finish or tell you why.

## ✨ Added

- **Take over a replica folder from an earlier install.** After BombVault was set up again, the replica target refused the folder this BombVault had filled before, and only a new name and a full send got the replica going. The replica card offers **Take over the folder**, and the next replica carries on from the copies in it.
- **Start a new repository where one is gone.** A remote storage location that held backups and suddenly holds no repository, such as a rest-server whose disk did not mount, is no longer filled with a new, empty one on its own. Its page says so as soon as a backup or copy finds it gone, and **Start a new repository here** does it once you decide to, for every section of the location at once and for named repositories too.

## ⚡ Improved

- **ZFS replicas send faster.** Every ssh session prefers AES-GCM, which is several times faster than the default cipher on CPUs with AES-NI, and the stream passes a 32 MiB buffer between send and receive, the way mbuffer does in a hand-made pipeline, so a receive that pauses to write no longer stalls the send. How much faster it gets depends on the CPUs and disks at both ends, and the rate shown counts the compressed stream, so it reads lower than a tool that counts the data before compression. ([#359](https://github.com/junkerderprovinz/bombvault/discussions/359))
- **Checks and prunes of large repositories finish.** They were cut off after 15 or 30 minutes per repository, so a large remote repository never got its space back. They run as long as restic keeps reporting, and a prune is held to `BACKUP_MAX_HOURS` like a backup.
- **A check, trial restore, unlock or prune started by hand keeps going** when the tab closes or a proxy gives up waiting. The page says the run goes on, and its result shows up when it ends.
- **Deleting backups answers as soon as they are gone** and reclaims the space afterwards, so a delete on a large remote repository is no longer reported as failed after every snapshot was already removed.
- **Back up selected hands a selection of several kinds to the server.** The page started one kind after the other and stopped when you left, so the later kinds were never backed up. The server takes the whole selection now, and a kind that cannot go at all is named with its reason.
- **Alerts get through.** Each notification channel sends on its own with its own time limit, so one host that never answers no longer silences the rest, and an alert no channel took is tried again. With summary messages on, a frozen guest, a failed retention or a crossed budget still goes out right away.
- **Graceful VM backups wait up to ten minutes for the guest to shut down** and never force it off, so a Windows guest installing updates is not cut off halfway. A guest that still runs after that is left alone, and that backup fails with the reason.
- **Restores come back on the image the container ran when the restored backup was taken,** not on a newer one pulled since, also when later backups already ran on the new image. An image is pulled only when it is missing, private registries get their sign-in, and a locally built image restores on a host without internet.
- **A refusal because a section or batch is busy says so** in words, instead of the general sentence, also when a ZFS entry, its backups or a safety snapshot cannot be deleted while a run holds the section.

## 🐛 Fixed

- **Replicate all now stopped after the first ZFS entry** when you left the page during its first send. The server runs the whole batch now, one entry after the other, whether the page stays open or not, and the bar is back when you open the backups list again. An entry that cannot replicate is named and skipped, and the others still run. ([#359](https://github.com/junkerderprovinz/bombvault/discussions/359))
- **Use as own folder refused to move a folder on this server to an S3 location with its own sign-in** when Copy the backups already made was on and other locations use the default sign-in. It said both places sign in the same way with different credentials, although a folder on this server reads no cloud sign-in at all. The default sign-in no longer gets in the way there. ([#359](https://github.com/junkerderprovinz/bombvault/discussions/359))
- **The window showed nothing under What happens when its check failed,** apart from a small line that was easy to miss. The reason is now shown there in a box, and when only the copy of the backups already made is in the way, it says that switching off Copy the backups already made lets the own folder move. ([#359](https://github.com/junkerderprovinz/bombvault/discussions/359))
- **Switching Replica only, no backup off left the off-site copies of the ZFS section switched off** without a word, because only the own folder came back. It is a setting of its own now and leaves the switches of the storage locations alone. Off-site targets the old switch turned off stay off, so switch them on again on their storage location's page, and every ZFS entry's card shows the section's switch as it stands, so it can be switched off from any of them. ([#359](https://github.com/junkerderprovinz/bombvault/discussions/359))
- **ZFS entries that only replicate** now start their replica with Back up now, which the page offers as **Replicate now**, and the replica stops the entry's containers and runs its commands around its snapshot like a backup does. Their replicas count for an every-few-days schedule, the overdue alert and the coverage, so the schedule no longer fires every night and a green section is not called overdue. Back up all sends their replicas one after the other outside the backup, so the other backups and restores no longer wait hours behind them, and a replica that cannot start is named.
- **ZFS replicas on the overview and the entry's card.** A failed replica is named under what needs attention instead of reading as no off-site copy, current replicas no longer offer an off-site check or trial restore that could only fail, and after a switch of target, or a change of the server's address, pool or folder, the card shows only runs to the new place as the latest replica. A failing replica of one entry no longer hides that another entry has no off-site copy at all, and an entry whose last backup skipped datasets counts as not protected.
- **Deleting a ZFS entry's backups** also deletes them on the off-site targets while the section's own folder is off, instead of refusing or leaving them there. An entry inside the tree of another no longer shows up in the outer entry's timeline, delete or restore.
- **Back up everything also backs up compose project folders,** and a flash, config or folder backup that fails before it starts shows up as a failed run with an alert and a fail ping.
- **A VM a graceful backup shut down is started again at the next start** of BombVault when BombVault stopped in the middle of the backup. A container that does not come back after a backup is named on the run and no longer started at some later boot.
- **An every-few-days schedule counts only its scheduled runs,** so backing up one container by hand no longer pushes the run back for all the others. A section backed up only by its entries' own schedules gets its overdue alert and its window on the overview, and its row there says it runs on the entries' schedules instead of Not scheduled.
- **Container backups** refuse a folder whose disk did not mount, also an Unassigned Devices disk, and a folder emptied since its earlier backups, keep a container's own longer stop timeout, and start the containers it depends on in compose, or a database in its stop list, before it. A backup that could not read some files names them on the run and tells you in the notification. A database whose dumps fail or are switched off counts as not protected in the list and in the tally.
- **Containers come back whole after a recreate or restore:** entrypoint, hostname, working folder, stop settings, terminal flags, long-form volumes and mounts made with `--mount`. Containers that share another container's network are put back onto it, a database import also stops the apps that use the database, and the start test runs the copy on its real data.
- **A restore that fails after the container was removed** puts the container back, stopped, instead of leaving it gone, with the containers that share its network. When a restart cuts the restore off, the next start of BombVault puts it back and tells you. A latest restore from a place with no snapshot of the container is refused instead of bringing it back empty, and entries from a foreign repository that cannot be recreated say so before you confirm and restore their files into a folder instead.
- **Restores into a folder that is not on mounted storage are refused,** since on Unraid that folder lives in memory and is gone after a reboot. An in-place restore refuses unmounted pools and Unassigned Devices disks the same way before it touches the original, saving a database dump into a folder is checked too, and a VM restore stops a paused VM first and keeps its autostart setting.
- **The emergency restore offers entries that exist only in the off-site copies** and guards its run against leaving the page. Leaving it inside the app stops the queue after the entry that runs, and the Restore page names the rest.
- **A storage location that holds a section's own folder can no longer be removed or erased.** The removal window names the sections, and the location's rclone remote stays while a section uses it. Moving an own folder onto a copy keeps what that copy's keep rule kept, an old own folder that does not answer is not copied as if it were empty, a move with nothing to copy is refused when a backup landed in the old folder meanwhile, and the safety settings of a typed address open once the section points there. Add storage location says why it could not switch a section over, and an empty folder on mounted storage passes the connection test.
- **rclone storage locations recover from a failed backend list** instead of staying broken until a restart, a pasted rclone config adds its remotes instead of replacing the stored ones, and copies from an AWS bucket outside us-east-1 work, also when its storage location was set up without a region.
- **Off-site copies hold up better.** A bucket never written to no longer fails every pass, a copy cut off by a restart is closed as failed instead of hiding behind the last good one, and a cancelled copy is recorded as cancelled. Bandwidth limits apply to forget and prune too, Replicate now starts for a section whose own folder is off, and a target with a sign-in of its own no longer warns about it when its copy can read the section's folder anyway. A repository in the other encryption mode fails its connection test with a clear reason.
- **Delete protection and trial restores belong to the place they proved.** Only append-only targets are tested and judged, so a section with one plain target no longer stays unproven, and a target moved to another place starts unproven instead of wearing the old place's results. The trial restore is planned for sections that copy only to added targets, such as a group member, and one that cannot read its off-site copy, or finds it emptied after an earlier drill restored from it, is recorded as failed and alerts.
- **The overview reads the sections and the coverage again when a run ends,** and progress bars whose end was missed while the connection was down go away, also behind a reverse proxy that answered with an error while BombVault restarted.
- **Settings pages no longer write back stale values.** A save built on an older state is refused and laid on a fresh read, so a tab left open no longer brings back a removed storage location or an old folder. An edit typed just before leaving the page is saved, and a new line in the exclusions field stays.
- **A settings import** with a replica running is refused before anything is written, and the page reads everything again after an import. The flash zip made after a flash backup opens in the Unraid USB Creator.
- **A removed phone is locked out.** A phone removed or switched off on the Instances page can no longer use its session, and a removed phone that opens its app again comes back switched off, so paired phones sign in once more after the update.
- **Passwords and passkeys are harder to misuse.** Changing or clearing the password asks for the current one and the two-factor code, passkey sign-in can no longer be locked out from another address, and with two-factor on a passkey has to verify you or is followed by the code. A configuration restore ends every session and removes the passkeys, so a stolen cookie or a lost key stops working; set your passkeys up again afterwards.
- **A saved sign-in that a pull source uses can no longer be removed,** and a pull source whose sign-in is gone is refused instead of reaching the other member with this instance's default sign-in.
- **Pulled backups go into a repository of their own per source,** and what earlier pulls left in this box's own repository is moved out, so retention and the restore lists no longer take the other box's backups for this box's. Pull now and a received-repository check keep running past the request, and pulls between two S3 buckets or two rest-servers without a shared sign-in work.
- **A pull source or received repository the member offers can be saved before its first copy is there.** Opening another instance's repository says why it failed, and the received repositories no longer hold up the Instances page.
- **Removing a member that is away ends its requests,** its idle ZFS receive slots and its waiting key requests, so its card goes. A withdrawn role is told again until the member hears it.
- **Switching off a Receiver switches off its storage location** even while the member is away, and a Receiver on a share says that it copies only through a storage location you add. The receiver names the address its rest-server is reached at, and one opened by a name from the browser asks for Address for partners first.
- **An instance that enters another group's phrase** tells a member that missed the leave as soon as that member asks again, so it no longer stays listed as away there.
