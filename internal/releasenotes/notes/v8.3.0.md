Two reports that looked unrelated turned out to share a cause: a domain list or a backend check copied into several files, with the copies quietly drifting apart. Self-backup gets the off-site card every other domain already had, and an S3 destination can finally use credentials of its own.

## ✨ Added

- **Self-backup is a full off-site domain in the interface now.** It gets the same card as containers, VMs, flash and folders: the guided setup wizard, a connection test, replicate-now, additional destinations, append-only protection and per-destination credentials ([#176](https://github.com/junkerderprovinz/bombvault/issues/176)). Nothing about this was a deliberate limitation. The backend has carried the domain all along, with its own off-site setting, its own destination rows and its own remote-primary row. It was simply absent from the list this settings page builds, from four copies of the domain type in the frontend, and from four handlers that each kept their own inline list of valid domains. The plainer repository field on the self-backup page is gone, so one value no longer has two editors that can overwrite each other, which is the same reason the schedules moved out of that page earlier.
- **A destination's credential set can be chosen for S3 and rclone, not only for a rest-server.** The selector was hidden behind a check for the REST backend, on the reasoning that only REST needs a username and password in that step ([#182](https://github.com/junkerderprovinz/bombvault/issues/182)). That is true of the fields and wrong for the selector: a credential set carries S3 keys as well, and replication already resolved them per destination. A local path shows no credentials block at all.
- **A remote primary backup path can use its own credential set.** Until now only replication destinations could, so anyone whose main path was an S3 bucket with its own keys had nothing to select and ran on the shared set.

## 🎨 Design

- **The shared credentials card says that it is shared.** It is called "Shared cloud credentials" now, in all 42 languages. The selector elsewhere already offered "Shared (default)" as a choice, but the card that actually defines those credentials never used the word, so it was not obvious that the two were the same thing, or that picking a set overrides it. Suggested by kramttocs in [#176](https://github.com/junkerderprovinz/bombvault/issues/176).
- **The off-site wizard chooses credentials, it no longer edits them.** Its credentials step used to also offer the shared username and password inline whenever the destination was a rest-server, so one pair of values had two editors and "Shared" read like a property of that one destination rather than the list everything falls back to. The step now shows the selector and a line saying where the shared credentials live. Also asked for by kramttocs: "my preference would be to ONLY have a dropdown here and never see the Username or Password." Editing them stays under Settings → Shared cloud credentials and in each set's own row.

## 🐛 Fixed

- **A credential set chosen for a primary path would have been honoured by the connection test and ignored by every real backup.** The wire format deliberately left the field out while the test resolved it anyway, so simply exposing the field would have produced a green test in front of backups still running on the shared credentials, which looks verified and is not. The credentials are applied on the backup path itself, and all five domains build their restic mode through one function, so the bandwidth caps from [#152](https://github.com/junkerderprovinz/bombvault/issues/152) and the credentials can no longer drift apart per domain.
- **A weekly schedule was summarised one day early for anyone west of UTC.** A backup set to Wednesday showed as "weekly (Tue)" on the dashboard while the Schedules tab correctly showed Wed ([#183](https://github.com/junkerderprovinz/bombvault/issues/183)). The label is produced by formatting a reference date built in UTC, and the formatter was left on the viewer's own timezone, so midnight UTC moved back into the previous day across the Americas. It was right in Europe, which is why it lasted this long. Measured rather than argued: that reference date formats as "Tue" in `America/New_York` and "Wed" in UTC. The formatter asks for UTC explicitly now, and the test pins that property rather than the machine's own zone, so it fails everywhere instead of only on a westward laptop.
- **Self-backup's location is set where its credentials can be set.** Pointing self-backup at an S3 bucket from the field on its own page left nowhere to say which keys that bucket needs ([#182](https://github.com/junkerderprovinz/bombvault/issues/182)). That field was a plain text input, while Settings → Paths and storage has held the same value as a full path row all along: local or remote, and for a remote one the safety dialog with bandwidth limits, append-only and the credential set. Keeping both would also have repeated the mistake the schedules and the off-site repo were moved out for, two editors for one setting with the older snapshot able to overwrite the other. The weaker field is gone, with a line pointing at the path row, which also retires its caption: it promised a "relative subpath under the host mount root" for a value that had just been given an s3: URL.
- **An earlier v8.3.0 image blanked the page when the off-site wizard was opened for self-backup.** If you pulled that one, pull again. Adding self-backup to the off-site tab left the wizard's own four-domain copy of the domain type in place, along with a cast asserting that off-site mode never receives it, which made the assertion true for the compiler and false at runtime: the settings-key lookup returned nothing, so the repository URL was undefined and backend detection called `.trim()` on it during the first render. Both key maps carry the domain now and the cast is gone, so a domain missing from either map is a build error rather than a blank page.

## ⚡ Improved

- **The five-domain list has one definition instead of six.** It was re-declared per file, and several copies had dropped self-backup, which is precisely how one domain ended up with less of the interface than the others while its backend was complete. The credential resolution is likewise shared between the off-site and primary paths rather than duplicated, since a second copy is how the two would come to answer the same question differently.

## 🌐 Translations

- The credentials heading in the off-site wizard, the new "uses the shared credentials" note and the renamed shared-credentials card are translated in all 42 languages, along with a pointer on the self-backup page to where its off-site copy is configured now. Five translation keys left over from the removed fields were deleted everywhere.
