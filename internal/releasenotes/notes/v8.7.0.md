A folder set can carry its own schedule and says in one line what actually backs it up, a running backup can be stopped, there is a second way to give, and the interface moves to GlimStone 1.8.0.

## ✨ Added

- **A folder set can have its own schedule** ([#199](https://github.com/junkerderprovinz/bombvault/issues/199)). Containers and VMs have had per-item schedules since [#121](https://github.com/junkerderprovinz/bombvault/issues/121); folders never did, so a set was in the nightly run or excluded from scheduling altogether. If one large folder only needs backing up weekly, the only way to spare it was to switch it off and run it by hand. Turn on **Per-item schedules**, give that set a weekly cadence, and it leaves the Folders run and Backup Everything and gets its own entry instead. A set without a cadence keeps following the Folders schedule exactly as before, and nothing changes at all with the toggle off.

  Two details worth knowing. The due gate ignores a set on its own cadence, so one weekly set cannot hold the nightly schedule closed for the daily sets beside it. And `everyN` is refused for a folder set, as it already was for containers and VMs, because it would be stored and then silently ignored; use `off`, `daily HH:MM`, `weekly DOW HH:MM` or a cron expression.
- **Each folder set carries its resolved schedule as a sentence** ([#199](https://github.com/junkerderprovinz/bombvault/issues/199)), on the Schedules card and on the Folders tab. Five outcomes: it runs on the Folders schedule, it runs on its own, it runs with Backup Everything, it runs twice, or nothing backs it up at all. The last two are the reason this exists, and they are coloured as the warnings they are. **"Runs twice" names both schedules**, so the second one does not have to be hunted for on another card.
- **Stop a backup that is running.** A backup that has started could only be waited out; there is a Stop button beside the progress bar now, and the run it cancels is recorded as cancelled rather than failed. Only for backups: interrupting one is safe, because restic writes its snapshot last, so an aborted run leaves unreferenced data and no snapshot. A restore is a different matter and keeps its own control, with its own warning about a half-restored target.
- **A second way to give, in a window of its own.** Pick a coin, pick its chain, take the address as text or as a QR code. It works with no internet, sends nothing anywhere and shows no name. Every chain on offer carries its own address, so a network the recipient cannot receive on is unofferable rather than merely discouraged - and the chain is switched directly under the address it changes, because a picker one box away from its own effect makes somebody look twice to see whether the address moved.
- **A PayPal route on the About card**, beside the existing ones. Three ways to give, all in one row under the sentence that asks.
- **A sign-out row in the sidebar**, above the view toggle, and only when a login password is set. An instance without one has nothing to sign out of. It clears this browser's session and returns you to the login screen; Settings keeps the "sign out everywhere" variant that also invalidates other browsers.

## 🎨 Design

The interface is on **GlimStone 1.8.0**.

- **The rail is a card, not a wall.** It carries the same radius and the same ground margin as every other card, with the background showing on all four sides. The page gutter moved to the frame that holds the rail and the content, so one number now produces the gap around the rail, the gap around the content and the gap between them. **That number is the house's 1rem**, not this app's own: an earlier cut used 1.5rem, and beside the sibling app the rail then sat further from the window edge and, half a rem shorter at the top and the bottom each, read as a visibly smaller rail. Measured after the correction, both apps at the same window size: same position, same 224 by 868, same radius, same distance to the content. The content keeps its own 1.5rem of padding, which is a separate distance.
- **The rail's glyph-mode width is the house's 85px**, where it used to be worked out per app from the brand mark plus the row padding, which gave 96px here and 64px in the sibling. Two rails of different widths doing the same job is what a shared language exists to prevent, so the mark fits the rail now rather than setting it; the 48px mark still sits centred with room on both sides.
- **Hover moves up the surface ramp, all the way up.** A control filled with the raised surface had nowhere to hover to and reached back down to a tone below the one it was resting on, so it went four units darker under the pointer instead of lifting. There is a third tier now, lighter on dark and darker on light.
- **Every dropdown in the app is the app's own, not the operating system's.** Twenty-one native `<select>` elements are gone. The design language has said since 1.5.0 that a native control gets replaced rather than persuaded, and the reason it had not happened is worth naming: the app owned the panel but not the whole control, so converting one meant hand-rolling a trigger, an open/close state, a wheel handler and a list of options, which nobody does for a filter bar. There is one component for it now, and it keeps three things a hand conversion loses: the width does not move when the value does, the arrow is the house's own solid triangle, and the wheel steps the closed control past anything that cannot be picked. A test fails the build if a native one comes back.
- **The wheel steps a picker again.** A closed dropdown answers the mouse wheel, both the app's own listbox (on the language picker, where a list of 42 should not cost a click first) and every native one still standing. It clamps at both ends rather than wrapping: one notch too many should not land a value from the other end of the list.
- **A new button shape for the small row action**, square while the label setting paints no words and an ordinary labelled button while it does, with the glyph filling half the square rather than two thirds of it. The two reset controls beside the colour rows are deliberately unchanged.
- **The sidebar's sign-out row and the view toggle take a palette position**, like every other row in the rail. They were the last two rows still painting the one flat accent, so in rainbow mode the column ended in two grey-gold rows under a run of coloured ones. An earlier round had argued that was deliberate; it was not.
- **The bulk-action bars above the container, VM and folder lists are coloured too.** They sit outside the rows and so never inherited a position. The colour is keyed to the ACTION rather than the page, so "Back up selected" wears the same one on Containers, on VMs and on Folders, and a button hidden by the current selection never shifts the colour of the ones beside it.
- **List rows are no longer washed in their own colour.** A row still owns its palette position, so the controls inside it stay coloured. What is gone is the tint laid over the whole card, which was too much colour at once now that the bar above the list carries its own.
- **The About card moved to the end of the General tab.** It was under System, on the reading that a version number belongs with the host integration. General is the first tab anybody opens, so the card is now the last thing on the first thing they see - and the sibling apps already had it there, which ends a three-way disagreement about one standard card.
- **Every button on the About card wears its brand's mark**, including the mail button, which had none, and GitHub's own on the repository button. Each mark is passed at that one call site rather than through the symbol table: a pattern on "repo" would put a GitHub logo on repository settings that have nothing to do with GitHub. On hover the button becomes that brand's own colour.
- **The Folders tab reads like the Containers tab.** The action badges moved to the card's top-right corner, the last-backup date moved down beside the Backups trigger, and the row that held a switch plus two action tiles became a single flush-right switch. A snapshot row is two things now instead of three columns: a line saying which snapshot, and a row holding everything it can do.
- **"Backups" is one size in all three card kinds.** The Containers and VMs cards expressed their disclosure as a selector at 24px while the Folders card used a button at 32px. All of them take the button height now, and so does the restore row's destination strip, which stood beside a 32px button at 24px of its own.
- **The crypto window's coin tiles are square**, with the mark at half the tile, and the hover goes light on the dark theme. The marks carry their brands' own colours - a donor finds Bitcoin's orange faster than they read eight three-letter tickers.
- **The modal backdrop darkens further**, and the value now lives in one place instead of at nine call sites. Four of those nine never carried the shared class at all, so they had been darkening by a literal that nothing else could reach.
- **The rainbow-mode note on the accent row is an info bubble**, not a line of grey prose under the row. The picker itself is dimmed and inert while rainbow mode is on, and it is not hidden: the row still shows that an accent colour exists and is currently not the one in charge. The wording says "turn rainbow off to choose one again" rather than "the accent does nothing", because a handful of controls outside any coloured surround still read it. The bubble appears only while the rainbow actually owns the colours, and it stays readable while the row it explains is dimmed.
- **The What's New window loses its two rules and its top close button.** A line under the title and another above the footer is hierarchy drawn with a border, which this app's design language avoids, and the padding already separates the three regions; the confirmation window lost the same pair earlier. The header's close button went with them, because the footer already carries one and two controls doing the same thing read as a choice between two answers rather than one answer offered twice. Keyboard entry is unchanged: the window still opens with a close button focused, now the one that remains.
- **The Security card is called Password.** Once the second factor moved into a card of its own, the name promised more than the card contained. The 2FA card's enable button is the width of its own words, not the width of the card.
- **"Remove set" is "Delete folder set"**, and the card's own two badges say simply Edit and Delete - the set is named by the card they sit in.

## ⚡ Improved

- **A refused connection test says which two names disagree** ([#194](https://github.com/junkerderprovinz/bombvault/issues/194)). A rest-server started with `--private-repos` gives each user only the tree under its own name, so the first part of the repository URL has to be the htpasswd user. When a test is refused and those two differ, BombVault now says which name it signed in with and which name the URL begins with, rather than listing what usually goes wrong. Both values were in front of it all along; it had never compared them. In that report the difference was one character, an underscore in the credential set where the generated recipe writes a hyphen, and it survived three rounds of screenshots.
- **The off-site wizard says it before the test is run.** The same comparison sits under the repository URL while it is being filled in. It is a hint and not a refusal: a server running without `--private-repos` is free to disagree, and it stays quiet wherever it would be guessing, including a URL with a single path segment, where a 401 means a wrong password instead.
- **The off-site setup says that the password and the `htpasswd` line are one secret in two forms** ([#194](https://github.com/junkerderprovinz/bombvault/issues/194), and the other half of [#192](https://github.com/junkerderprovinz/bombvault/issues/192)). The wizard printed the generated password, then printed recipes containing a line that appends `user:hash` to `.htpasswd`, and never said the hash was that password. Both values on screen, neither labelled as the other's form, so it read as two secrets and people went looking for the second one. An info bubble beside the password now says which half goes on which box and that there is nothing to hash yourself. The same sentence is in the off-site documentation's worked example, in all twenty-six languages, because the person who asked was reading the documentation rather than the wizard.
- **And that the first path segment of the repository URL is the user, not a folder.** Every recipe the wizard prints turns on `--private-repos`, so a URL without the user answers `401` even when the password is right. That was the rest of the same two reports. The placeholder always showed the correct shape, but a placeholder is not a rule, so now it is stated beside the field.
- **The resolved-schedule sentence is computed on the server**, by the same function the scheduler consults, from the same four settings, so what the card promises and what the job does cannot drift apart. A hint text can describe the rules; it cannot say what the current combination does.
- **The Folders card says that a set can carry its own schedule** ([#199](https://github.com/junkerderprovinz/bombvault/issues/199)). The switch enabling it lives in another card, and until it is on the folder rows show no schedule editor at all, so the feature was invisible from exactly the screen where you would look for it.
- **Controls in a form row follow the Buttons labelling setting**, not the Tabs one. The source toggle, the VM method switch and the path-mode pair were reading a setting nobody had touched, so somebody who set Buttons to glyph-only watched the buttons change while these stayed put. Page-level tab strips are unaffected and still follow Tabs.
- **"Delete all backups" in the Folders and VMs cards is a full button with its glyph**, matching the identical action on the Containers card, instead of a small chip.
- **The QR code is larger**, and its white plate takes the card radius so it reads as a card rather than a slab. It stays black on white in both themes on purpose: an inverted code is outside the standard, and the scanners that refuse one are exactly the wallet apps a donor is holding.
- **The glyph generator can carry a multi-line note.** Two long explanations of why a symbol's frame is cropped had been written straight into the generated files, and regenerating deleted both without a word. The generated files say "do not hand-edit", so they were right and the edits were wrong, but a generator that could only carry a single line left nowhere else to put the reasoning. It lives with the generator now.
- **Five gosec findings in the secret package are closed**, so the lint gate runs clean again.

## 🐛 Fixed

- **A folder set could be left unprotected while looking configured.** The Folders card carries three controls that all read like scheduling, and the combination that looks most sensible is the one that protects nothing: "Include in schedule" reads as "part of the Folders schedule", but it gates the per-item entry, the Folders job **and** the Backup Everything pass, so switching it off takes the set out of every automatic backup. Nothing on screen said so. Now the set's own row does, in red.
- **Cancelling a folder-set backup did nothing.** Container and VM backups registered their cancel under the same key their progress used; folder sets registered theirs under the set's id while progress used its name, so the cancel never found the run it was meant to stop. Shutdown never noticed because it walks the whole map.
- **The 401 explanation for [#194](https://github.com/junkerderprovinz/bombvault/issues/194) never reached anyone.** It recognised an error only when the repository URL sat inside the message, and the message BombVault shows never carries one: restic prints the URL on its "Is there a repository at the following location?" line, which the error builder steps over as boilerplate to reach the line that names the cause. So the connection test went on showing a bare `401 Unauthorized` long after the explanation shipped. Every test case written for it had been composed by hand, each one with a URL in it, which is why nothing failed. It now also recognises restic's own REST-backend wording, and the case taken off a reporter's screen is in the test.
- **The About card's GlimStone link opened a 404.** It said 1.7.5, which was a changelog heading and never a release: the language folded 1.7.1 through 1.7.10 into 1.8.0. Every version on that card is a link to its own tag's release page, so the number was not merely stale. The number now travels with the files it describes rather than sitting in a constant beside the card, which is what let it drift in the first place.
- **A dropdown panel could be narrower than its own options.** The panel took the trigger's exact width, which was right for the two wide pickers the app had and wrong the moment a compact filter bar got one: every option truncated, because each row spends 24px of that width on its own padding. The trigger's width is a floor now and the content decides the rest. Found by looking at it running, not by a test.
- **The sign-out row and the view toggle kept their glyph in text mode**, where every navigation row above them shows words only. Both rows were in the labelling engine for hiding the words and outside it for dropping the symbol, so they were the only two in the rail wearing an icon in a text-only column.
- **A mark on a filled tile could be invisible.** The selected coin tile is filled with the accent, and a brand colour on a fill the engine chooses is a contrast nobody can predict - measured on the default accent, one coin's orange came out at 1.45:1 against the 3:1 a graphic needs. Every mark on a filled tile now takes that fill's contrast ink.
- **One mark on the About card kept the button's ink instead of its brand colour**, because a fill set on the parent `<svg>` never reaches a path that declares its own.
