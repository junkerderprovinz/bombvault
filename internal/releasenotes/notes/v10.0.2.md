A patch that puts every one-line setting beside its name, keeps number fields short, and stops BombVault from creating an off-site repository on a host that does not answer.

## 🎨 Design

- **Every one-line control stands beside its name.** In the cards and windows across BombVault, dropdowns, segmented choices and number and text fields sit at the end of their row instead of filling the width under their name. On a phone they move under the name when the row is too narrow for both.
- **Number fields are short again.** Days, weeks, retention counts and the other number fields had grown as wide as a line of text and are back to the width of a few digits.
- **Replicates to is a dropdown** on a ZFS entry, so long server names fit.
- **Replicate now shows once**, among the actions of a ZFS entry's page, and no longer also at the bottom of its Replica card.

## 🐛 Fixed

- **BombVault tried to create an off-site repository on a host that did not answer.** When the connection failed, for example with a timeout or a refused connection, it took the location for empty and ran restic init, which failed again with a message that read as if the location held nothing. It now stops with "could not reach the repository, so nothing was created there". ([#334](https://github.com/junkerderprovinz/bombvault/issues/334))

## 🌐 Translations

- **The documentation describes the current interface** in all 26 languages, including that the line to Local can be switched off for the flash drive, ZFS datasets and the self-backup.

## Upgrading

- **Nothing has to be changed.**
