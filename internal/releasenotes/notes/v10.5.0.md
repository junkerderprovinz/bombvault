BombVault 10.5.0 is a reliability release. A review of the whole app found ways in which backups could be lost, restored wrongly or reported as fine when they were not, and every confirmed case is fixed here and tested against a real server. It also backs up VMs with Unraid snapshots in full and prunes own folders by their storage location's card.

If you use a named repository, please check its backups. An earlier version could prune them by another location's card, and backups pruned that way can't be brought back.

## ✨ Added

- **A question instead of a pause.** When a section finds its own backups from before this database at a storage location, **Needs you** and the location's page ask whether to **Take them as this server's own** or **Check the rules first**. The run of each waiting backup links to that question.
- **A keep card for every folder.** A folder on this host and a typed remote folder have their own **How long to keep** card, which covers only the own folders in it.
- **Fetched copies on the Restore page.** **Fetched from** under **Other sources** opens what this server fetched from another instance, without a key to enter.
- **More in the recovery kit.** The kit carries every sign-in a storage location uses, and a new server reads them back with **Save sign-ins**. The self-backup also keeps the keys of the ZFS servers and the certificates.
- **Accept a storage location without delete protection.** A location that cannot refuse a delete, such as OneDrive, has a switch **Accept without delete protection** on its page, and the Protection Status panel then shows "Delete protection: none, risk accepted". Thanks to @2wheelsdown for the thoughtful request. ([#406](https://github.com/junkerderprovinz/bombvault/issues/406))

## ⚡ Improved

- **Own folders follow their storage location's card.** An own folder in a storage location is pruned by that location's **How long to keep** card, and **Rules per section** still wins. Moving an own folder to a place that keeps less asks first. Thanks to @manilx for the clear reports. ([#407](https://github.com/junkerderprovinz/bombvault/issues/407))
- **Balanced keeps two years.** Keeping one year only holds the newest backup of this year, so **Balanced** gets Years 2. A place on Balanced stays on it, and since it only keeps more, nothing is deleted.
- **Every entry offers its own plan on its Settings tab.** A plan stored while the old **Own plans per entry** switch was off never ran, so the update clears it and names it in the log. Thanks to @manilx for asking where it went. ([#405](https://github.com/junkerderprovinz/bombvault/issues/405))
- **Stacks are restored on the Restore page.** A Compose stack has its own **Stacks** card there, and the search finds it by its name or by any of its containers. Thanks to @manilx for pointing out where people look for it. ([#399](https://github.com/junkerderprovinz/bombvault/issues/399))
- **Notifications work on a fresh install.** A fresh install starts on **Only on failure**, so a channel you fill in tells you when a backup breaks. Healthchecks hears every backup whenever a URL is set, and **Never** stops only the messages.
- **A shared Healthchecks check stays red.** Once one section's backup failed, the good backups of the other sections on that URL ping `/fail` and name it, until it has a good backup again or the failure is acknowledged under **Needs you**.
- **A section's status goes by its slowest entry.** One entry that stopped is no longer hidden by a neighbour that runs, a new section says **No backup yet** until its first run was due, and the weekly digest names overdue sections instead of saying **All good**.
- **Containers keep their network.** Containers that share a network stop and start with its owner and start after it at boot, and a restore keeps `--volumes-from`. A definition stored by an earlier version gets its `--volumes-from` entry with the next backup.
- **Updates after a backup.** Only what you set carries over to the new image, and a failed update goes back to the image that ran and says so on the run.
- **The Emergency wizard finds more.** It reads every off-site location, lists what the copies hold when no self-backup is left, and starts the Settings step on the place the key opened. Sign-ins for rclone and remote places can be entered before the key is taken over.
- **VM runs say what they leave out**, such as read-only, network or volume disks and the state of an emulated TPM. A guest that shut down late after its backup is started again.
- **Signed requests between instances.** Group members sign role requests and storage offers, so a member on an older version sends them again once it is updated. Each storage offer has its own login and folder, with delete protection on.
- **Key-holding downloads need a password.** The flash ZIP and the exports of flash and self-backups hold the `APP_KEY`, so they need a login password like the recovery kit.
- **A host that is down gives up after 30 seconds** when a repository on it is opened, instead of the 15 minutes restic keeps retrying.

## 🐛 Fixed

- **Good backups no longer age out behind a green run.** A backup that read no files, missed a selected folder or could not read some files ends as a warning that names what is missing. Its older backups are kept until a complete backup comes through, for folder sets, flash and Compose project folders alike.
- **An emptied flash folder keeps the last good ZIP**, and the ZIP is written in one step, so a full disk or a sync tool never meets half a file.
- **A failed snapshot listing no longer reads as "no backups".** restic prints an empty list and exits with 0 in that case, and BombVault now treats it as the failure it is.
- **A named repository keeps what its page says.** It could be pruned by another location's **How long to keep** card while its page read Keep all, with nothing in the log.
- **A hidden rule of all zeros no longer outranks the card.** Moving own folders into a location with no keep values yet could leave such a rule on each section, and the update removes it with one log line per section. A rule of all zeros set by hand goes too, so give a section its own values under **Rules per section** before you update if it should keep more. ([#407](https://github.com/junkerderprovinz/bombvault/issues/407))
- **A section with a named repository keeps its rule of all zeros.** Without it the repository would start pruning by the shared rule, so the section's own folder keeps everything, and **Who prunes** and the Preview say so. ([#407](https://github.com/junkerderprovinz/bombvault/issues/407))
- **A storage location added again at an old address starts clean.** It no longer stops with a message about a repository that is gone, and the update frees locations already stuck that way. Thanks to @manilx for the report. ([#408](https://github.com/junkerderprovinz/bombvault/issues/408))
- **A missing bucket or a key that does not fit is named.** A copy or a location test against a bucket that does not exist says so within seconds instead of waiting up to an hour, and another instance's repository reads as such on the run and the page. ([#408](https://github.com/junkerderprovinz/bombvault/issues/408))
- **A switched-off storage location stays off.** With **Available** off it takes no backups and prunes nothing.
- **A pool that is down is refused.** First backups, flash ZIPs and every restore in place refuse a folder whose disk is not mounted, since it lies in the host's memory.
- **The local repository stays readable after a prune.** Files a prune, tag, pull, section move, delete or stack backup wrote are readable by other users right away instead of the next night. Thanks to @cpsmith516 for tracing the cause through the code. ([#398](https://github.com/junkerderprovinz/bombvault/issues/398))
- **A stack restore stops the containers before it writes.** A green stack restore could leave PostgreSQL unable to start. The restore now checks every member first, keeps members stopped when the project folder failed, and no longer starts a database that came back without its data.
- **A container is found by its exact name.** A removed container whose name matched the start of another container's id backed that container up and overwrote its definition.
- **A restore that did not write says so.** Files restic could not write no longer end green, and folders an older backup holds come back or are named before the restore.
- **VMs with Unraid snapshots are backed up in full.** BombVault follows each disk's chain and backs up every file in it, and a live backup no longer merges the snapshots into the bottom image. Thanks to @schwimmbadpirat for the careful report. ([#400](https://github.com/junkerderprovinz/bombvault/issues/400))
- **VM restores bring back the disk that was backed up.** A restore under a newer overlay, after a merged chain or from before the first snapshot no longer mixes two points in time or drops the newest data. A failed restore keeps the VM defined with its NVRAM.
- **The ZFS failover works.** The command in the sheet and the docs failed on real ZFS and left the copy unmounted, and the next run rolled back what was written to the copy. The command now leaves every dataset writable and mounted, and a run stops before it would throw writes away.
- **ZFS copies keep their history.** Deleting or running an entry with a received copy in its tree, or cleaning a parent entry, no longer removes snapshots that belong to others. With **Local** off, scheduled rounds prune at the storage locations too.
- **Off-site copies that never ran no longer read ok**, and the protection level stays below green until the first copy worked.
- **Overdue means overdue.** A section with nothing to back up reads Not scheduled instead of Overdue, and Home Assistant reads `ok` only when every section is current. ([#407](https://github.com/junkerderprovinz/bombvault/issues/407))
- **The Preview matches the prune** for copies added through a storage location, direct repositories and renamed entries. **Who prunes** and the protection window name the rule that applies, and a location without delete protection says "Delete protection: none". ([#406](https://github.com/junkerderprovinz/bombvault/issues/406), [#407](https://github.com/junkerderprovinz/bombvault/issues/407))
- **Saved means saved.** A cleared command under **Commands before and after** no longer keeps running, a location with a hidden password can be edited, and a refused value no longer stays on the page.
- **Schedules do what they show.** An entry's own plan runs right after it is switched on, a switched-off section runs nothing, and a section with nowhere to back up to fails instead of reporting success.
- **Pulls and received repositories.** A pull that read nothing counts as failed and alerts, schedules keep their time and weekday, a received repository can be added at the address the member offers, and **Integrity check FAILED** only fires when a check ran.
- **Passwords and paths are guarded.** A location's password is hidden for every caller, a location whose host starts with a dash is refused, a link above a stored path can't lead outside the mount, and a paired phone restores only into the restore folder.
