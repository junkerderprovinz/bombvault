BombVault 10.5.0 fixes two keep rule bugs. A named repository could lose backups, and own folders moved into a storage location could ignore its **How long to keep** card.

If you use a named repository on 10.4.2, please check its backups. Any that the wrong rule pruned can't be brought back.

## 🐛 Fixed

- **A named repository keeps what its page says.** On 10.4.2 it could be pruned by another location's **How long to keep** card while its page read Keep all, with nothing in the log. It follows the rule its page shows again.
- **A moved own folder follows its location's card.** Moving own folders into a location with no keep values yet could leave a hidden rule of all zeros on each section, and that rule won over the card. The update removes those rules with one log line per section, and the next backup prunes down to the card. ([#407](https://github.com/junkerderprovinz/bombvault/issues/407))
- **A rule of all zeros you set yourself goes too.** The update can't tell it from a hidden one, so a section whose location has a card starts following that card. To keep more, give the section its own values under **Rules per section** before you update, since rules with values stay. ([#407](https://github.com/junkerderprovinz/bombvault/issues/407))
- **A section with a named repository keeps its rule of all zeros.** Without it the repository would start pruning by the shared rule, so the section's own folder keeps everything. **Who prunes** and the Preview say so and point to **Rules per section**, and the log names the section. ([#407](https://github.com/junkerderprovinz/bombvault/issues/407))
