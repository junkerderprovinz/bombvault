BombVault 10.3.0 adds a memory limit per backup, keeps servers and phones that are switched off in the group, and sends ZFS replicas to a ZFS server a shorter way. It also fixes a long list of things: storage locations of almost every kind connect and stay connected, restores come back on the image they were backed up with, and backups, copies, checks and alerts that used to stop or vanish without a word now finish or tell you why.

## ✨ Added

- **Memory limit per backup.** Settings, System, Performance has a new field, **Memory limit per backup (MiB)**. It sets a soft limit for each backup process, so a large backup slows down instead of being killed for running out of memory. 0 sets none, which is how backups ran before.
- **Instances that are away stay in the group.** A server that is shut down or a phone with the app closed keeps its card on the Instances page and its row on the Pairing page, marked **Inactive** in grey with when it was last seen, and comes back as the same card. **Remove** works on such a card whichever modules are switched on, and ends the member's requests, idle ZFS receive slots and waiting key requests. Right after a restart a card says **Checking** in grey instead of Not connected in red. The Android app shows an instance that is away the same way and also lists the instances of the group it never met itself.
- **Put BombVault's SSH key on a Storage Box or an SFTP server with the account's password.** The password is used for that one sign-in and kept nowhere, and a wrong one is reported as a wrong password, also by servers that ask for it as a prompt. The command for doing it by hand is shown next to it, filled in with the host, user and port.
- **A bucket field for S3 keys that may open only one bucket,** such as a Cloudflare R2 object token or a scoped AWS key. These never passed the connection test, because the test listed every bucket. With the bucket typed in, the test and the folder browser open that bucket.
- **Choose the drive or workspace a sign-in opens.** A OneDrive sign-in with several drives, or a Zoho WorkDrive with several workspaces, asks which one to use instead of leaving the location unusable.
- **SFTP and Storage Box servers are held to their key.** The connection test shows the fingerprint of the server's key, and BombVault refuses the server if it later shows a different one. Until now no host key was checked at all.
- **Switches for yes-or-no settings** of FTP, SFTP and SMB servers instead of free-text fields. FTP asks for its encryption as one choice: none, explicit TLS, or implicit TLS on port 990.
- **A share field for SMB servers that do not list their shares.** The test opens that share, and a location can no longer be saved or get a new folder on the list of shares itself, where every backup failed later.
- **Take over a replica folder from an earlier install.** After BombVault was set up again, the replica target refused the folder this BombVault had filled before, and only a new name and a full send got the replica going. The replica card offers **Take over the folder**, and the next replica carries on from the copies in it.
- **Start a new repository where one is gone.** A remote storage location that held backups and suddenly holds no repository, such as a rest-server whose disk did not mount, is no longer filled with a new, empty one on its own. Its page says so as soon as a backup or copy finds it gone, and **Start a new repository here** does it once you decide to, for every section of the location at once and for named repositories too.

## 🎨 Design

- **Instance cards are all one size.** Every card of the grid is as wide and as tall as the tallest one, and the logo sits at the top beside the name, at one size on every card. In a single column a card is as tall as what it holds.
- **Names are shown in full.** A long name on a card wraps, the badges move below it, and the kind of instance has a line of its own. In the picture of the group, names wrap too instead of being cut short.
- **Every BombVault in the picture of the group shows the logo,** this server, the other instances and the phones, with a small round badge that says whether it is a server or a phone.

## ⚡ Improved

- **ZFS replicas to a ZFS server take a shorter way.** The host pipes zfs send straight into its own ssh to the server, with BombVault's replica key and the server's pinned host key, and falls back to the way through BombVault when it cannot. Every ssh session prefers AES-GCM, and a stream through BombVault gets a 32 MiB buffer, also on a BombVault that receives it. Nothing has been measured on real hardware yet, so any gain depends on both machines, and the rate shown counts the compressed stream. ([#359](https://github.com/junkerderprovinz/bombvault/discussions/359))
- **Closing an anomaly says what happens to the old backups.** The question before you acknowledge it or mark it as expected says that an open anomaly keeps every old backup of its item, and that once it is closed the next cleanup deletes old backups by the keep rules again. A bulk close names the held item, or counts them when several are held. ([#360](https://github.com/junkerderprovinz/bombvault/issues/360))
- **Checks and prunes of large repositories finish.** They were cut off after 15 or 30 minutes per repository, so a large remote repository never got its space back. They run as long as restic keeps reporting, and a prune is held to `BACKUP_MAX_HOURS` like a backup.
- **A check, trial restore, unlock or prune started by hand keeps going** when the tab closes or a proxy gives up waiting. The page says the run goes on, and its result shows up when it ends.
- **Deleting backups answers as soon as they are gone** and reclaims the space afterwards, so a delete on a large remote repository is no longer reported as failed after every snapshot was already removed.
- **Back up selected hands a selection of several kinds to the server.** The page started one kind after the other and stopped when you left, so the later kinds were never backed up. The server takes the whole selection now, and a kind that cannot go at all is named with its reason.
- **Alerts get through.** Each notification channel sends on its own with its own time limit, so one host that never answers no longer silences the rest, and an alert no channel took is tried again. With summary messages on, a frozen guest, a failed retention or a crossed budget still goes out right away.
- **Graceful VM backups wait up to ten minutes for the guest to shut down** and never force it off, so a Windows guest installing updates is not cut off halfway. A guest that still runs after that is left alone, and that backup fails with the reason.
- **Restores come back on the image the container ran when the restored backup was taken,** not on a newer one pulled later, also when later backups already ran on the new image. A copy restored next to the original starts on that image too, and Update after backup no longer puts the container back on the image the restore went away from; it waits for a newer one. An image is pulled only when it is missing, private registries get their sign-in, and a locally built image restores on a host without internet.
- **Errors say what to change.** A refusal because a section or batch is busy says so in words, also for a ZFS entry, its backups or a safety snapshot held by a run, and Replicate now, a replica that cannot start and a second check of a received repository say why too. A wrong rest-server password says to check the user name and password, a refused SFTP key says to add the key the form shows, an FTP server that wants encryption names the setting, a wrong Nextcloud address shows the form it needs, and a Garage region error names `s3_region`. A copy that fails behind rclone names rclone's own reason instead of a bare error 500.
- **rest-servers with a self-signed certificate can be reached.** Put the certificate into the `certs` folder of BombVault's data folder (`appdata/bombvault/certs` on Unraid), and backups, copies and the delete protection test trust it without a restart. The error for an untrusted certificate names that folder.
- **S3 locations need less typing.** The region is read from addresses that name it (AWS, Backblaze B2, Hetzner, Scaleway, OVH, Wasabi), Garage starts with its own default region, IDrive e2 asks for its endpoint, and an address pasted with the bucket on it, the way the R2 dashboard shows it, is used for the server and the bucket. A bucket made from the folder browser goes into the region the form names, also on AWS outside us-east-1.
- **The storage class picker offers what the service takes.** A class the service refused broke every upload after a save that went through. Setting a location back to the default class takes effect, also where it holds a section's own folder or a direct repository, and More settings shows only the options that shape a new bucket.
- **Pruned backups free their space on Google Drive and OneDrive.** Google Drive deleted pruned data into the trash and OneDrive Business into its recycle bin, where it still counted against the quota. A Google shared drive can be entered under More settings.

## 🐛 Fixed

- **Cloud sign-ins stay signed in.** A token rclone had refreshed was overwritten with the old one at every restart and every change to the rclone config, so Box, Jottacloud and other services whose refresh tokens work once lost their sign-in. The fresh token is kept, also in the recovery kit and in exports, and changing a location's connection or browsing its folders no longer uses it up. Browsing a location's folders signs in with that location's own current token, never with one an earlier browse of another location of the same service left behind.
- **Cloud services that could not be set up connect.** Jottacloud takes the login token from its security page, the Zoho WorkDrive command carries the region, ShareFile gets its address with the token, and Mega and Proton Drive with two-factor sign-in no longer fail on their first run with a code that was already used. iCloud Drive says how to bring the trust token and cookies of a sign-in done with rclone config, and that Apple asks for it again after 30 days. A sign-in that expired is reported as such instead of as a service that does not report its free space.
- **Changing a location's connection leaves the other locations alone.** It rewrote a saved sign-in, or the default one, that other locations, copies and pull sources use, without testing them. The location gets a sign-in of its own instead, and the window says when its sign-in is shared. A region the saved sign-in does not sign for is refused at the test instead of failing at the first run.
- **SFTP, Storage Box, SMB and FTP locations keep what you type.** A password typed for an SSH-key server is kept and tried after the key, passwords keep spaces at their ends, the key and ssh command fields that replaced BombVault's own key are gone, and the folder browser in the connection window works for these servers too.
- **rest-server addresses are read the way people type them.** An address typed with `rest:` in front or without `http://` works, one that leaves no room for the sections' folders is refused at the test instead of at the first copy, and a login or folder named like a repository's own folder (`data`, `keys`, `config` and so on) no longer cuts the address off. The self-backup recipe and offer put its repository where rest-server can serve it.
- **Replicate all stopped after the first ZFS entry** when you left the page during its first send. The server runs the whole batch now, one entry after the other, whether the page stays open or not, and the bar is back when you open the backups list again. An entry that cannot replicate is named and skipped, and the others still run. ([#359](https://github.com/junkerderprovinz/bombvault/discussions/359))
- **Use as own folder refused to move between places that sign in differently,** such as a folder on this server and an S3 location with its own sign-in, when Copy the backups already made was on. It said both places sign in the same way with different credentials. Each place is read with its own sign-in now, also between two S3 locations or two rest-servers with different logins. ([#359](https://github.com/junkerderprovinz/bombvault/discussions/359))
- **The window showed nothing under What happens when its check failed,** apart from a small line that was easy to miss. The reason is now shown there in a box, and when only the copy of the backups already made is in the way, it says that switching off Copy the backups already made lets the own folder move. ([#359](https://github.com/junkerderprovinz/bombvault/discussions/359))
- **Moving an own folder or a copy no longer fails at its last check on a stale lock** that an old run left in the new place, after the copy had already run. A second try switched without any check, because nothing was left to copy; a new place that holds every backup already is checked first, and the window says so.
- **ZFS entries set to Replica only, no backup** wait for their first replica instead of a backup that never comes, and their page shows the replica instead of the section's own folder with 0 backups. Back up now starts their replica, offered as **Replicate now**, and it stops the entry's containers and runs its commands around the snapshot like a backup does. Their replicas count for an every-few-days schedule, the overdue alert and the coverage, and Back up all sends them outside the backup, so other backups and restores no longer wait hours behind them. ([#359](https://github.com/junkerderprovinz/bombvault/discussions/359))
- **Switching Replica only, no backup off left the off-site copies of the ZFS section switched off** without a word, because only the own folder came back. It is a setting of its own now and leaves the switches of the storage locations alone. Off-site targets the old switch turned off stay off, so switch them on again on their storage location's page, and every ZFS entry's card shows the section's switch as it stands, so it can be switched off from any of them. ([#359](https://github.com/junkerderprovinz/bombvault/discussions/359))
- **ZFS replicas on the overview and the entry's card.** A failed replica is named under what needs attention, in plain words such as that the server has no zfs command, with the server's own output under View errors. Current replicas no longer offer an off-site check or trial restore that could only fail, and after a switch of target or a change of the server's address, pool or folder, the card shows only runs to the new place as the latest replica. A failing replica of one entry no longer hides that another entry has no off-site copy at all, and an entry whose last backup skipped datasets counts as not protected.
- **Deleting a ZFS entry's backups** also deletes them on the off-site targets while the section's own folder is off, instead of refusing or leaving them there. An entry inside the tree of another no longer shows up in the outer entry's timeline, delete or restore.
- **Back up everything also backs up compose project folders,** and a flash, config or folder backup that fails before it starts shows up as a failed run with an alert and a fail ping.
- **A VM a graceful backup shut down is started again at the next start** of BombVault when BombVault stopped in the middle of the backup. A container that does not come back after a backup is named on the run and no longer started at some later boot.
- **An every-few-days schedule counts only its scheduled runs,** so backing up one container by hand no longer pushes the run back for all the others. A section backed up only by its entries' own schedules gets its overdue alert and its window on the overview, and its row there says it runs on the entries' schedules instead of Not scheduled.
- **Container backups** refuse a folder whose disk did not mount, also an Unassigned Devices disk, and a folder that was emptied after its earlier backups. They keep a container's own longer stop timeout and start the containers it depends on in compose, or a database in its stop list, before it. A backup that could not read some files names them on the run and in the notification, also in the summary of scheduled runs, and a database whose dumps fail or are switched off counts as not protected.
- **Containers come back whole after a recreate or restore:** entrypoint, hostname, working folder, stop settings, terminal flags, long-form volumes and mounts made with `--mount`. Containers that share another container's network are put back onto it, a database import also stops the apps that use the database, and the start test runs the copy on its real data.
- **A restore that fails after the container was removed** puts the container back, stopped, with the containers that share its network, instead of leaving it gone. When a restart cuts the restore off, the next start of BombVault puts it back and tells you. A latest restore from a place with no snapshot of the container is refused instead of bringing it back empty, and entries from a foreign repository that cannot be recreated say so before you confirm and restore their files into a folder instead.
- **Restores into a folder that is not on mounted storage are refused,** because on Unraid that folder lives in memory and is gone after a reboot. An in-place restore refuses unmounted pools and Unassigned Devices disks the same way before it touches the original, saving a database dump into a folder is checked too, and a VM restore stops a paused VM first and keeps its autostart setting.
- **The emergency restore offers entries that exist only in the off-site copies** and guards its run against leaving the page. Leaving it inside the app stops the queue after the entry that runs, and the Restore page names the rest.
- **Storage locations in use stay.** A location that holds a section's own folder, or that a backup or copy is writing to, can no longer be removed or erased, and its rclone remote stays while a section uses it. Moving an own folder onto a copy keeps what that copy's keep rule kept, an old own folder that does not answer is not copied as if it were empty, and a move with nothing to copy is refused when a backup landed in the old folder meanwhile. Add storage location says why it could not switch a section over, and an empty folder on mounted storage passes the connection test.
- **A storage location's page fits a phone.** Its name wraps instead of being cut, its actions line up with it, and the dots of the keep picture no longer run into each other. A location that holds only own folders shows no copy picture, its card is called Bandwidth, and Who prunes says that each section's keep rules prune its own folder; a location with both describes its copies and its own folders apart.
- **rclone storage locations recover from a failed backend list** instead of staying broken until a restart, a pasted rclone config adds its remotes instead of replacing the stored ones, and copies from an AWS bucket work in any region, also when its storage location was set up without one or with a key in another region.
- **Own folders in a bucket that holds no backups yet are left alone.** When a section's own folder moved to an S3 or REST storage location before anything was written there, for example ZFS that only replicates, the prune after every round failed with "repository does not exist". Prune, verify, unlock and the restore check leave such a folder out, and an off-site copy into a bucket never written to no longer fails every pass. A bucket that held backups before and is empty now is still reported. ([#359](https://github.com/junkerderprovinz/bombvault/discussions/359))
- **Off-site copies hold up better.** A copy cut off by a restart is closed as failed instead of hiding behind the last good one, and a cancelled copy is recorded as cancelled. Bandwidth limits apply to forget and prune too, Replicate now starts for a section whose own folder is off, and a target with a sign-in of its own no longer warns about it when its copy can read the section's folder anyway. A repository in the other encryption mode fails its connection test with a clear reason.
- **A backup started while the one before it is still being copied off site says so.** It was refused with "a backup is already running" although that backup had finished. Now it says the off-site copy of the last backup is still running, and the buttons that start a backup say the same while they wait.
- **A tap on a greyed-out button says why.** On a phone the explanation shows on every tap and stays until you tap elsewhere, also while the list scrolls under it. The number of picked rows in the bar above a list stays on one line beside its buttons.
- **Delete protection and trial restores belong to the place they proved.** Only append-only targets are tested and judged, so a section with one plain target no longer stays unproven, and a target moved to another place starts unproven. A trial restore counts for the target it read, so a new target that takes over from an old one does not inherit its result. The trial restore is planned for sections that copy only to added targets, such as a group member, and one that cannot read its off-site copy, or finds it emptied after an earlier drill restored from it, is recorded as failed and alerts.
- **The overview reads the sections and the coverage again when a run ends,** and progress bars whose end was missed while the connection was down go away, also behind a reverse proxy that answered with an error while BombVault restarted.
- **Settings pages no longer write back stale values.** A save built on an older state is refused and laid on a fresh read, so a tab left open no longer brings back a removed storage location or an old folder. An edit typed just before leaving the page is saved, and a new line in the exclusions field stays.
- **A settings import** with a replica running is refused before anything is written, and the page reads everything again after an import. The flash zip made after a flash backup opens in the Unraid USB Creator.
- **A removed phone is locked out.** A phone removed or switched off on the Instances page can no longer use its session, and a removed phone that opens its app again comes back switched off, so paired phones sign in once more after the update.
- **Passwords and passkeys are harder to misuse.** Changing or clearing the password asks for the current one and the two-factor code, passkey sign-in can no longer be locked out from other addresses, however many there are, and with two-factor on a passkey has to verify you or is followed by the code. A configuration restore ends every session and removes the passkeys, so a stolen cookie or a lost key stops working; set your passkeys up again afterwards.
- **A saved sign-in that a pull source uses can no longer be removed,** and a pull source whose sign-in is gone is refused instead of reaching the other member with this instance's default sign-in.
- **Pulled backups go into a repository of their own per source,** and what earlier pulls left in this box's own repository is moved out, at start and before retention runs, also with Pull or the source switched off, so retention and the restore lists no longer take the other box's backups for this box's. Only backups that can be tied to the source move. One the other box has deleted in the meantime looks the same as a backup of this box whose entry was removed, so it stays where it is. Pull now and a received-repository check keep running past the request, and pulls between two S3 buckets or two rest-servers without a shared sign-in work.
- **A pull source or received repository the member offers can be saved before its first copy is there.** Opening another instance's repository says why it failed, and the received repositories no longer hold up the Instances page.
- **A member that missed a change hears it later.** A withdrawn role is told again until the member hears it, and an instance that enters another group's phrase tells a member that missed the leave as soon as that member asks again, so it no longer stays listed as away there.
- **Switching off a Receiver switches off its storage location** even while the member is away, and a Receiver on a share says that it copies only through a storage location you add. A Receiver with no storage location on it says so, also while its member is away or gives no address, and one allowed again after it was switched off says that its location is off and switches it back on with a fresh login from its details.
- **Partners get an address for the receiving server that works.** It is Address for partners, or else the IP address at which the receiver's own check reached its rest-server, never a reverse proxy's name or address or a Tailscale address a browser happened to use, and it no longer changes with whichever browser signed in last. Address for partners can be set on the Receiver tab after setup too, and a partner on an older BombVault gets an error instead of saving a wrong address.
