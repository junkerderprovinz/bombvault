## ✨ Added

- **Delete all backups of a VM in one click.** A new *Delete all backups* action in the VM panel removes every snapshot of a VM from the selected source (local or off-site) and prunes the repository, instead of deleting them one at a time. (requested by @manilx)

## 🐛 Fixed

- **Manual Prune no longer fails on a stale lock.** A lock left behind by an interrupted backup/prune made Prune report *"repository is already locked"* and never reclaim space. It now clears the stale lock first, like backups already do. (reported by @manilx)
- **Scheduled VM backups skip a VM that no longer exists.** A schedule entry for a deleted VM (or an undefined libvirt template) made the nightly `vms` job error every night. Such a VM is now skipped with an info log instead of failing the job. (reported by @manilx)
- **"Stop other containers" restarts in the right order.** When a backed-up container (for example a VPN gateway like gluetun) had dependents sharing its network namespace (`network_mode: container:<name>`), they were restarted before the target was back up and failed with *"cannot join network namespace of a non running container"*. The target is now started and confirmed running before its dependents restart. (reported by @manilx)
- **Restic encryption mode is reconciled with the existing repo.** Toggling the Encryption setting against an existing repo now fails fast with a clear, actionable message instead of cryptic per-backup errors.

Image: `ghcr.io/junkerderprovinz/bombvault:2.8.0` (also `:2`, `:2.8`, `:latest`) and `docker.io/junkerderprovinz/bombvault:2.8.0`, multi-arch (amd64 + arm64).

## Added

- **Remove a stale VM entry.** A VM that was deleted from the host but still shows under "Not installed" with no backups now has a **Remove entry** button (VMs tab) that clears the leftover entry. (A VM that still has backups is handled by "Delete all backups" in its Backups panel, as before.)

## Fixed

- **Maintenance "healthy" indicator no longer carries across repos.** In Settings → Integrity & maintenance, switching the Local/Off-site source now clears the per-action result indicators, so a green result from one repo doesn't stay shown for the other where nothing has run.

> Note: the recurring daily `dumpxml: failed to get domain` error for a deleted VM was already fixed in v2.8.x (the scheduler now skips a VM that's no longer defined on the host) — updating to this image and removing the stale entry clears it for good.
